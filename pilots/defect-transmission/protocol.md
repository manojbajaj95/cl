# CPU protocol: can a retrieved coding defect reproduce?

This is the one-generation gate in [the compute request](../../reviews/compute-requests.md), not a test of the law in [PR #4](https://github.com/manojbajaj95/cl/pull/4). Use Qwen2.5-Coder-1.5B-Instruct Q4_K_M, CPU only, with a known defective note planted into an otherwise empty memory. Tests, model settings and menus are fixed across the four arms. The paired sound note says the right thing, the defective note promotes one specific wrong edge-case implementation, and unrelated prose matches the full input token count at each decision. Use the same placement and match sound and defective notes in length too. The fourth arm retrieves no note.

## Coding stream and outcomes

- Each of 16 Python behavior families has a fixed source variant and three held-out variants, with separately permuted solve/write options, distinct contexts and hidden inputs. No prompts give away the hidden test inputs or expected outputs. Family specs do state the contract, so a note must compete with that contract. We test single-step transmission with **relevant** retrieval, not retrieval quality.
- The model first selects a Python patch, sees its patch and the smoke-test result, and selects a new reusable implementation for a separate wrapper. The three candidate bodies comprise a correct one, one reproducing the note's planted defect, and a different defect. The two wrong candidates have distinct wrong outputs on the hidden probe; smoke tests cannot distinguish the candidates (one family has no smoke test). Score the newly written helper, not the first patch.
- Execute only the prewritten expressions, not generated code. Use a three-letter decoder at \(T=0.8\), no top-k/p truncation within the menu. Evaluate one solve prompt and all three possible write histories for each arm. Marginalize those histories exactly: \(p(w)=\sum_s p(s)p(w\mid s)\). This removes rollout noise without switching to greedy decoding. No prompt filters, baseline-margin selection, or intermediate stopping based on outcomes.
- To match generic perturbation, fit no-lesson inverse temperature to defective-note entropy on source variants only, separately at solve and write. Weight write entropies by the fixed *source* no-lesson solve distribution at \(T=0.8\), so the fit cannot benefit from changed visitations. Apply both fitted temperatures unchanged to held-out variants. Show the held-out entropy match as a diagnostic, not a new fit. The nominal-temperature no-lesson arm is also reported.

## Estimates and decision

Report gross \(\tau=P(\text{new defective helper}\mid\text{defective note})\), the corresponding rates under all controls, and paired risk differences. Also report the PR #4-style background-adjusted \((p_{\rm bad}-p_{\rm filler})/(1-p_{\rm filler})\), which has a transmission-probability interpretation only if the note adds defects without preventing background defects. Break down any defect into planted-signature and other defects; report solve defect rates separately.

Use 10,000 paired percentile bootstrap draws of 16 **families**, equal weight, holding all variants and arms in a family together and refitting temperatures from resampled source variants. Intervals describe this challenge and model, not random checkpoints or a representative sample of software. Primary gate: kill if the lower 95% bound of gross defective-note minus filler is not strictly positive. Recommend the 5 GPU-h Stage 1 only if that gate passes and the gross contrast against matched temperature and the planted-signature contrast against filler also have strictly positive lower bounds. Passing says only that transmission is detectable here; Stage 1 must still test whether a verifier setting puts \(R\) in the informative range.
