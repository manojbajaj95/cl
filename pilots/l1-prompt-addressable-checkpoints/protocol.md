# L1 protocol: prompt-addressable checkpoints

[Flood triage](https://github.com/manojbajaj95/cl/blob/fb4bd9654b5981679090aaac21c32d459e47e67f/reviews/flood-triage.md#learning-primitives-pr-42-36-ideas) ranks L1; the [PR #6 ledger](https://github.com/manojbajaj95/cl/blob/fb4bd9654b5981679090aaac21c32d459e47e67f/reviews/idea-ledger.md) points to the operational test in [flood-top10](https://github.com/manojbajaj95/cl/blob/fb4bd9654b5981679090aaac21c32d459e47e67f/reviews/flood-top10.md#top-3-smallest-first-tests-each-with-a-retention-check).

> Setup: Qwen2.5-0.5B with one LoRA trained over 5 sequential tasks. Task k's data carries the tag `<v_k>`, plus an as-of loss: under `<v_j>` (j < k), match stored checkpoint j's logits on 64 probe prompts per past version.
>
> Metric: KL(model | `<v_j>`, checkpoint j) on held-out inputs (not the probes), and task-j accuracy under `<v_j>`.
>
> Stacked control at equal tokens and bytes: untagged sequential training with replay of the same probe logits, plus storing per-version LoRA deltas at matched bytes.
>
> Kill: held-out as-of KL is not below the replay control (CI), or only the probes are reproduced.
>
> **Retention:** with the current tag, all 5 tasks and WikiText-2 perplexity stay within 1 pp and 2% of plain sequential training plus replay.

The [PR #42 source card](https://github.com/manojbajaj95/cl/blob/a4ae445253154c235be84767a8304c690ad47974/ideas/flood/learning-primitives.md#l1-prompt-addressable-checkpoints-a-git-log-inside-one-set-of-weights) proposed GPT-2 small, a shuffled-tag arm, and a stricter quantitative floor: “Kill if as-of KL is not < 50% of untagged KL, or old-task accuracy under the past tag < 80% of checkpoint k's.” The later reviewer setup determines the base model and primary gate. Report the original quantitative checks as well.

## Smallest CPU implementation

- Use frozen Qwen2.5-0.5B in float32 with one rank-5 LoRA on the LM head. Cache exact frozen logits and final hidden states; this avoids repeating frozen work, not a change to the trainable forward pass. Teacher and student score the entire vocabulary. Distill teacher-to-student KL with weight 1 alongside task next-token cross-entropy.
- Five sequential domains use the same short two-choice prompt template, with alternating label polarity and disjoint nonce values. Each stage sees 48 balanced labeled training prompts for the new task; each task has 32 separate balanced held-out prompts. Use the same 64 unlabeled probes (covering all five domains, distinct from train and held-out) for every checkpoint so a version must distinguish different targets even on the identical probes. Trials share splits, vary LoRA initialization and example order, and pair those random draws across trained arms.
- Each stage has 48 AdamW updates (learning rate 0.001) with 16 labeled rows; from stage 2 each step also uses 16 old-version probe rows. Every past checkpoint's 64 probes are used at least once in each later stage. There are 3,840 labeled and 3,072 replay presentations per arm; their prompt lengths and pairing are identical. Keep full adapter snapshots and teacher distributions for training and scoring only; deploy just the final adapter.
- The tagged arm stores its own stage-j targets under literal `<v_j>`. Replay sees these exact same targets on the same batches under a fixed length-matched neutral prefix `<v_0>`, not targets generated by a different trajectory. Shuffled tag uses the same budget with independent random tags per presentation; at evaluation it receives the same version queries as the tagged arm.
- The storage control spends the same deployed incremental bytes on five rank-1 float32 deltas, SVD-compressed from the tagged arm's own snapshots with no additional training. It receives the matching tag. It is a weight-space reconstruction baseline, not a fitted output-KL quantizer. Exact full deltas are the zero-KL reference and would cost five times the incremental bytes. The wrong-tag reader queries the final tagged adapter using `<v_5>` instead of the old tag; the frozen reader uses the requested tag without an adapter. These diagnose gains from a prompt prefix alone rather than learned history.
- Compute full-vocabulary KL(final reader || exact tagged checkpoint) on the shared 160 held-out prompts for each old version (v1–v4, equal weight). Also report the reverse KL, probe KL and held-out task-j accuracy (forced choice A vs. B). Do not include trivially self-identical v5 in the primary mean. The held-out effect must be below replay with a paired 95% CI wholly below zero; an apparent probe advantage without that held-out advantage is a kill, not a keep. The source accuracy floor applies to each past version, not a pool that could conceal one forgotten task.
- Under the current tag, score the five held-out accuracies separately and compare the absolute per-task differences to 1 percentage point. Compare relative perplexity to 2% on a fixed first-512-next-token slice of the raw WikiText-2 test split, using eight consecutive 64-position windows prefixed with the reader's tag. This is a CPU screening slice, not a full-corpus perplexity estimate. WikiText-2 and accuracy thresholds use paired point differences, with uncertainty shown separately. Report the exact checkpoint's original accuracy against the 50% balanced-task chance level so retaining an unlearned task is not counted as a useful success.
- Report two-sided 95% percentile CIs from 10,000 paired seed-level bootstrap draws (RNG seed 797). Inference is conditional on the fixed test prompts and WikiText slice; CIs quantify between-training-seed variation, not corpus/task sampling or multiple comparisons.
