# Node: what is the smallest model-independent description of an edit?

Parent: [PR #76 edit-transfer](https://github.com/manojbajaj95/cl/pull/76), sub-question 1.

**Question:** What is the smallest model-independent description of an edit, and can each target compile its missing part from it?

## Root cause: a realized edit is not its specification

PR #76's transport approaches start with what the source *did*: a weight delta, an activation difference, or a collection of changed outputs. All three mix together at least three things: the behavior someone meant to change, the source's particular way of achieving it, and the damage the source happened not to suffer. Matching coordinates only addresses the second. Even an exact source behavior diff does not say which unchanged cases were deliberately protected, which changed cases were accidents, or which counterfactual cases the source never had to distinguish.

For example, a source only sees standard shipping and changes a fee from $5 to $6. “Add $1 to all shipping” and “set the standard-shipping fee to $6; leave express alone” can produce the same source observations and exactly the same write. On a target with express shipping at $9 and standard at $7, those instructions demand different results. Target probes can reveal the two current fees and how the target computes them; they cannot reveal which instruction was intended. Conversely, once the instruction is known, the source cannot tell the target which weights can implement it without disturbing an old discount rule. That is a target-local question. If the target's writable layer cannot distinguish standard from express, even a perfect description may be unimplementable at that layer.

The parent reports a concrete symptom: in [LoRA Superposition](https://arxiv.org/abs/2610.30691), the on-backbone gain is 30.21 pp and the leave-one-backbone-out gain is 0.06 pp. [Cross-lingual editing](https://arxiv.org/abs/2611.10646) identifies an orthogonal residual and bounds the gap of source-only corrections in its setting; [THESEUS](https://arxiv.org/abs/2602.12952) and [ARIADNE](https://arxiv.org/abs/2610.32581) recover part of the gap using matched behavior inside both models. These are evidence against treating source effects as sufficient coordinates for a target write, not proof that every edit has a large private residual. The shipping example is a separate, exact ambiguity: no better alignment resolves it. The parent's minimal witness, teaching set and probe-basis ideas help only when the observations they carry distinguish the relevant instructions. A tiny teaching set can be perfectly faithful to the source and still be ambiguous on the target.

### What “smallest” and “compile” would mean

Fix a family of targets, a shared observation language (e.g. decoded answers, tool events or decisions, not neuron indices or token IDs), an allowed persistent write family, and a budget for target-local queries. Before seeing a particular receiver, an encoder emits a message from an authoritative edit request or from source evidence. A compiler gets that message and authorized target-local observations, but no source weights or source teacher at installation. A verifier decides whether the result realizes the requested relation on affected cases and preserves target behavior on protected cases; the edit may explicitly leave some cases unrestricted. Old behavior is measured against the **target's** pre-edit behavior and retained-task ground truth, not copied from the source. Two requests can share a code on a target only if there is a single admissible output for both there (including a no-op where appropriate). Pairwise compatibility alone may not imply a common write for a whole code class.

There are three different failures to report: **ambiguous intent** (request more authoritative information), **infeasible write** (no allowed write under the stated constraints, if proved), and **unknown** (information, solver or verification budget exhausted). A checked no-op counts as success if the target already satisfies the relation. Compare the total description budget, including vocabulary/verifier setup and any per-target compilation data; report fixed setup amortized over edits separately from per-edit bytes, target queries and write/verification compute. Otherwise the “shortest edit” can be an index into a hidden dataset. Minimality is relative to these budgets and the range of targets; it is not a claim about absolute shortest programs.

## Raw ideas (no self-filtering)

These are paper-and-pencil or tiny synthetic first tests to consider later, not pilots. Start with finite tables, small linear/ReLU targets or short state machines where scope and write feasibility are independently knowable. Use disjoint compiler and verifier cases. At matched new-edit success, compare ordinary old-task scores and previous unrelated edit success separately to the pre-edit target; averages must not conceal the one old case a proposal claims to protect. Match source-message bits (including shared setup), receiver access/write budget and verification budget against the named control unless varying that resource is the point.

1. **Edit confusion graph.** *Mechanism:* join two requests when some receiver with the same available side information cannot safely use one shared result for both. A zero-error fixed-length code must color the graph; use incompatible request sets as hyperedges when every pair can share a write but the whole set cannot. *Why new:* PR #76's minimal witness asks what examples suffice, not for a lower bound over every encoding. *Cheapest first test:* exhaustively enumerate a three-request/two-receiver truth table and compare the optimal code with shortest teaching sets, including a pairwise-compatible triple with no common write. *Retention:* define incompatibility with an old-task constraint, then independently check its old-rule cases and a previously edited row after decoding.
2. **A semantic checksum from disputed cases.** *Mechanism:* emit an answer to a deliberately chosen case where two plausible edit meanings differ, even if that input does not occur in the source; the answer comes from the request author or simulator, not source logits. *Why new:* the parent mines changes the source realizes; this bit is selected because the source cannot settle it. *Cheapest first test:* construct matched-source pairs like set-vs-add, budget one bit, and compare the disputed-case answer with one more source paraphrase or a random authority query. *Retention:* check held-out out-of-scope cases and a neighboring pre-existing exception.
3. **Typed query exchange rates.** *Mechanism:* build a two-oracle description protocol: the receiver can buy a local response about what is possible, or buy a semantic answer from a separately priced authority. Derive the achievable triples of message bits, local queries and authority queries. *Why new:* feedback in HypoLoop revises writing plans; this asks when more execution feedback provably cannot substitute for one intent answer. *Cheapest first test:* enumerate optimal decision trees on a four-request table crossed with four target types; compare with always-solve-first and always-ask-first. *Retention:* test that low-cost paths still preserve old decisions and previously patched actions on held-out states.
4. **Object identity by intervention fingerprints.** *Mechanism:* replace a source entity name with a short sequence of role interventions whose joint observations identify the intended object under renaming; treat multiple matches as unresolved. *Why new:* unlike MindBridge retrieval or a fixed-schema probe basis, the description is invariant to label swaps and demands causal identification before writing. *Cheapest first test:* two renamed relational worlds with identical names/frequencies but different parent/child role structure; compare to name matching and passive relational examples. *Retention:* verify same-name distractors and old relations of the identified entity remain unchanged.
5. **Make the hold-fixed variables first-class.** *Mechanism:* describe a change by a structural equation and an explicit list of variables whose pre-edit values must be held fixed, not a list of example outputs. Receivers may recompute descendants consistently. *Why new:* AnyEdit's broad outputs and the trace compiler's input guards do not by themselves distinguish a mediated ripple from collateral damage. *Cheapest first test:* two billing DAGs with different decompositions into subtotal, fee and tax; compare to equal-byte edited-output labels on unseen baskets. *Retention:* protect discounts and unrelated tax classes, including previously corrected discount cases.
6. **Unit-free edit laws.** *Mechanism:* send constraints on dimensionless ratios or order rather than magnitudes; bind units and scale using receiver observations and reject inconsistent unit assignments. *Why new:* unlike PR #76's evidence-as-likelihood update, this is an invariance law over output transformations, not an override strength adjustment. *Cheapest first test:* convert a synthetic classifier's resource outputs between mixed units; compare a ratio instruction with absolute-output distillation and explicit unit conversion. *Retention:* check prior decisions at unchanged thresholds and an older override expressed in a different unit.
7. **Relational edit via paired executions.** *Mechanism:* specify a change by a relation between two runs under swapped context, with neither run's answer individually fixed; allow any target-native result satisfying the pair. *Why new:* sibling obligation compilation allows alternatives on a target; here the shared object identifies semantic equivalence across models with different per-input safe answers. *Cheapest first test:* require two mirrored maze starts to have mirrored actions under different native tie-breakers; compare to source action labels and independent per-state admissibility. *Retention:* preserve preferred actions on nonsymmetric starts and old obstacle detours.
8. **Difference between admissible and observed ripple.** *Mechanism:* ship a set of allowed propagation paths and a set of forbidden paths through a shared event graph, with all internal realizations unobserved. *Why new:* a trace program copies one execution path and ChainEdit supplies ripple constraints; this object allows different paths but forbids leakage through named intermediates. *Cheapest first test:* two state machines implement the same alert rule through different allowed routes; compare endpoint-only supervision and exact source-trace matching. *Retention:* run old workflows sharing the forbidden intermediates and recheck an older alert exception.
9. **A commutation law as content.** *Mechanism:* define the requested edit by how it must commute with named, already meaningful transformations (and where it must not), chosen before installing it. *Why new:* forward trace compile measures commutators after choosing writes; here a commutation requirement itself identifies the edit, without specifying its source output. *Cheapest first test:* a table remap that must commute with renaming but not with an established override; compare to compiling examples at the identity transformation. *Retention:* evaluate both orders on old overrides and unchanged keys.
10. **Quantified exceptions without rule-order leakage.** *Mechanism:* encode an exception by its dominance relation over named rule classes rather than by its position in a rule list; eliminate target order as an implementation detail. *Why new:* generic scoped retrieval (SERAC/GRACE) does not require equivalent precedence for independently ordered rule engines. *Cheapest first test:* insert the same scoped exception into two shuffled, partially overlapping rule lists; compare with a trigger/answer capsule and replay. *Retention:* exercise pre-existing higher-priority decisions and unrelated cases in both engines.
11. **Semantic bisection after a model swap.** *Mechanism:* specify edit intent on a hierarchy of task abstractions; descend only along a witnessed disagreement between admissible interpretations, requesting a semantic answer only when needed. *Why new:* contrasts with counterexample-guided repair (SpecRepair), which refines candidate writes to satisfy a known obligation; this protocol resolves the obligation itself. *Cheapest first test:* a depth-three ontology with target-specific alias intersections; compare against flat active selection at equal authority and target-query counts. *Retention:* check edits and ordinary labels in omitted sibling categories.
12. **Progressive edit descriptions with safe prefixes.** *Mechanism:* transmit a prefix whose realizations are safe under every still-possible meaning, with refinements expanding what can be committed, rather than sending a tentative update to roll back. *Why new:* unlike HypoLoop's plan revisions or the sibling's lazy disjunction over write choices, the prefix constrains an unresolved message's semantics across receivers. *Cheapest first test:* enumerate four nested policy requests and interrupt transmission at every bit; compare with a complete message or implementing the likeliest prefix interpretation. *Retention:* test old workflows and prior fixes after every prefix, not only after full decode.
13. **Multi-receiver semantic broadcast.** *Mechanism:* a single message exploits complementary side information held by different receivers: each solves for the part it cannot already infer, with correction data charged to the sender. *Why new:* PR #76's teaching set optimizes a common dataset; this borrows index coding to count missing semantic fields rather than to share examples. *Cheapest first test:* two toy site policies need two independent exception bits; each site has the other verified bit, so compare an XOR broadcast with sending both bits and with per-site messages. *Retention:* validate pre-existing local exemptions and old tasks, including a site with a stale side-information bit that must be rejected.
14. **Semantic diff against a public reference, not the source.** *Mechanism:* express the intent as a difference from a versioned reference policy with explicit rules for reconciling local deviations, instead of using either model's behavior as the reference. *Why new:* WeightCode's reusable program can implement this but does not make the reference choice part of the edit's identity; test reference semantics, not program reruns. *Cheapest first test:* three independently customized tables with the same known reference and one incompatible local deviation; compare with a direct source diff and a full intent specification. *Retention:* check old local deviations and a prior downstream override, including when reconciliation refuses the edit.
15. **Proof of semantic erasure by substitution.** *Mechanism:* delete one proposed description field only if varying it over all allowed values leaves a common receiver action; emit the receiver/input that breaks deletion otherwise. *Why new:* the sibling's inverse certificate decides feasibility of fixed obligations; this uses a receiver as a counterexample to compression. *Cheapest first test:* brute-force subsets of fields on small finite specs and compare with source-only delta compression and greedy example removal. *Retention:* include a field indispensable only to protecting one already edited case, and check all ordinary old cases independently.
16. **Compiler-independent edit identity by distinguishing futures.** *Mechanism:* define two edits as the same only if every continuation in a declared operation language yields equivalent decisions; store the shortest continuation that separates them. *Why new:* same-effect round trips in PR #76 and present-day probe signatures do not test whether two writes behave identically on a later update. *Cheapest first test:* two tiny persistent rule stores agree today but differ after the next named override; enumerate continuations of length two against one-step behavior matching. *Retention:* score unrelated old decisions and previously installed fixes along each continuation, excluding declared replacements.
17. **Ordinal prohibitions without a fixed target outcome.** *Mechanism:* transmit a partial ordering of violations, with forbidden tradeoffs, rather than a loss weight or one acceptable scalar objective. *Why new:* an inverse-optimized objective in PR #76 recovers source action; this object can rank target-only boundary cases without recovering source preferences over realizations. *Cheapest first test:* two small linear targets with swapped feasible compromises; compare a portable ordinal specification with one loss weight fitted on the source and a flat disjunction. *Retention:* make failure on one protected old class incomparable with new-edit gain and check older fixes at every admissible compromise.
18. **Edit rule over counterfactual user inputs, not factual outputs.** *Mechanism:* ship a policy about which user-controllable changes may change a decision and which must not; compile minimal behavior change outside the dependence relation. *Why new:* unlike role-intervention fingerprints, which find *where* to act, this specifies a dependency to remove without receiving the source's output or trace. *Cheapest first test:* edit a two-feature decision rule in targets with different shortcut correlations; compare with paired-label editing and source logit distillation at equal bytes. *Retention:* test old cases where the other feature legitimately predicts the decision and a previously corrected subgroup.
19. **Specify on shared events, privately certify realization.** *Mechanism:* freeze a verifier on public events and require each target to prove its new and old behavior within its own internal model; test whether the public spec remains valid when the private proof or write family changes. *Why new:* obligation compile's local certificate is tied to write feasibility; the proposed separation keeps the message identical while changing certificate language and receiver visibility. *Cheapest first test:* exact enumeration on one table target and interval bounds on one piecewise-linear target realizing the same event policy; compare with a proof that includes source addresses. *Retention:* score held-out old events and previous edits with an independent enumerator rather than trusting the certificates alone.
20. **One-sided semantic sketches for no-ops.** *Mechanism:* let a tiny public sketch certify that some targets need no write, but forbid it from generating a write; receivers outside the certified class request the full message. *Why new:* unlike the parent's transferability score, this measures satisfaction of the intent without estimating any update effect; it can save total transmitted bytes without changing installation. *Cheapest first test:* mix exact no-op and near-no-op toy targets and compare a conservative short certificate with a magnitude threshold and full broadcast. *Retention:* audit a near-no-op whose old exception would be damaged by an unnecessary write, and replay earlier fixes on actual installs.
21. **Install the smallest change to the decision boundary's topology.** *Mechanism:* name a component split/merge and which landmarks must remain connected, independent of either model's coordinates or distance metric. *Why new:* trace collision splitting introduces a local new address; this specifies a global invariant over observable inputs and admits different native addresses. *Cheapest first test:* two small grid classifiers with different boundaries but the same landmark partition; compare graph constraints with equal-byte pixel labels and scoped retraining. *Retention:* preserve prior landmark connections and an older carved-out region on a separately checked grid.
22. **Receiver-independent narrowing by expiration event.** *Mechanism:* make an edit contingent on a semantic event (e.g. a newly published policy taking effect), not a write count, wall clock, or checkpoint identity; compile the pre-event and post-event obligations together. *Why new:* sentinel half-lives in meta-editor and trace compile observe whether writes persist; here when an edit *should stop* is part of its meaning across targets with different internal clocks. *Cheapest first test:* two small state machines observe the same event via different action sequences; compare with fixed expiration time and permanent edit. *Retention:* run old tasks and prior patches both before and after expiration, including a legitimate exception that must outlive this edit.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can we characterize the minimum edit message by the requests a receiver cannot safely conflate?** Start with exact finite confusability bounds and look for a succinct construction that predicts when a source witness is enough. This has the clearest chance of producing a new object: a receiver-relative compatibility test and a lower bound independent of the editor algorithm. Cards 1–3, 13, 15.
2. **Which part of an edit is discoverable from receiver behavior, and which part needs an authoritative semantic answer?** Look for a boundary between useful local observations and ambiguity no local experiment can reduce, then a protocol that spends the right kind of query and makes safe partial commitments. Cards 2–4, 11–12.
3. **Can a causal or relational contract describe the same edit across structurally different models without standardizing their internals?** Find the weakest shared observable identities and relations that still make scope, intended ripples and protected behavior checkable. The payoff is a representation with native compilation, not a common adapter. Cards 4–8, 18–19, 21.
4. **Can edit identity survive composition and time without sending a history or a full policy?** Find a small continuation language whose distinguishing futures reveal differences hidden in a present-day effect, and determine whether precedence and expiry are closed under successive independent edits. Cards 9–10, 14, 16, 22.
