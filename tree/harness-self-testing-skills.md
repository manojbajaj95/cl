# Harness → can a skill carry its own experiment to re-validate itself?

Parent: [tree/agent-harness.md (PR #47)](https://github.com/manojbajaj95/cl/pull/47), next-node #4 and idea #10 (counterfactual perception port). This node asks what stops a skill from carrying a test that re-establishes *whether it still applies* when task cues alias, or after the reader model or a tool is swapped. Ideation only: no experiments were run.

## Root cause

**A skill stores the conclusion (the procedure) but not the discriminating evidence that licensed it, and validity is a three-way interaction (skill × reader model × environment) that current methods measure on one leg at a time, outside the skill, and indexed to the old reader.** Three sub-causes:

1. **Evidence lives in the library, not the skill, and is bound to the old reader.** Paired WITH/WITHOUT evidence is a router's property: [SkillApt (2609.26863)](https://arxiv.org/abs/2609.26863) raises success 81.9% → 91.3% while loading skills on 26.3% of states (vs 98.8% zero-shot), and [SkillDelta (2609.32274)](https://arxiv.org/abs/2609.32274) beats random activation in 15/15 settings (+4.3 pts), but both histories describe *that* agent. After a model swap they are void. [Beyond Gain (2610.32322)](https://arxiv.org/abs/2610.32322) finds per-skill verdicts reproduce across tasks (κ 0.42) but differ across models: a hub must read them per model.
2. **What is stored tests the environment, not the reader.** [When Agent Skills Go Stale (2611.22525)](https://arxiv.org/abs/2611.22525) is the nearest prior art: it records checks from successful runs and replays them without model calls, recovering up to +67 pp after environment change. Those checks compare observations against the saved state, so a swapped reader that now misreads or no longer needs the skill passes every check. [Memory portability (2609.05339)](https://arxiv.org/abs/2609.05339) shows the reader leg is large: compressed notes shift +9.91 / −13.28 pp by migration direction, store-only repair misses the 90% target in 48/48 cases, and keeping raw source evidence recovers 34/48. The *evidence* is what travels, not the conclusion.
3. **Gain is not identifying, and existing tests are not designed to discriminate.** Beyond Gain proves no criterion that vanishes at equal arms (gain, leave-one-out, Shapley) can separate an *internalized* skill from an *uncovered* one; nearly half of high unaided scores come from tasks no model benefits from. [SkillSandbox (2610.10088)](https://arxiv.org/abs/2610.10088) synthesizes scenarios once, at admission (Keep/Reject), and finds 17–32% of skills are never exercised after 500 tasks, so passive reuse never re-validates them. [Policy-update readouts (2610.39358)](https://arxiv.org/abs/2610.39358) predict utility decline (AUROC 0.525 → 0.802) but need white-box training rollouts, not a portable test. [SkillAligner (2608.06880)](https://arxiv.org/abs/2608.06880) rewrites skills to the current interface but never tests the assumption it rewrote.

So nobody stores, per skill, a **minimal experiment whose outcome distribution differs between the latent conditions under which the skill helps and those under which it hurts**, in a form a different reader can run. Tests in skill work today are regression checks (did the env change?) or utility estimates (did success go up?), never hypothesis tests about the skill's own licensing assumption. Adjacent work not read in full here (alphaXiv quota ran out): Skill-V (2610.11781), Skill Contracts (2610.05161), ACE-Skills continuous evaluation (2608.20614), executable task contracts (2610.14477), IBM process-level skill evaluation (2610.01833). The reviewer should check them before ranking ideas 1, 2 and 5.

**Not repeats:** PR #20 HK2 (edit-generated regression witnesses) and SAGE per-item tests protect *old tasks* from an edit; here the skill tests *itself* under a new reader. PR #47 #10 stores one learned experiment; ideas below give it semantics (what it identifies, how it updates, how it travels).

## Raw ideas (no self-filtering)

Each: mechanism · why new · cheapest first test (with retention check). Default testbed for first tests: the G1/A3 rotated-rule router (PRs #14, #29) with a reader swap Qwen2.5-0.5B ↔ 1.5B, plus a synthetic tool whose schema can be renamed or re-ordered. Every lesson arm keeps the temperature-matched and same-length filler controls from the ledger.

1. **Skill = claim + its crucial experiment.** Store with each skill a pair of rival hypotheses (H_apply, H_not) and the single cheapest action sequence whose predicted outcomes differ most between them (max expected KL). At read time run it, update a Beta over applicability, load iff posterior > threshold. *New:* the stored object is a discriminating experiment with predictions, not a replayed check (2611.22525) or a utility table (SkillApt). *Test:* 20 aliased rule lessons; compare to SkillApt-style paired history, recorded env-checks and always-load, at equal extra actions, before and after a 0.5B→1.5B swap. Retention: success on the 20 original states with the experiment run must stay within 1 pp of oracle loading.
2. **Internalization-vs-uncovered litmus inside the skill.** Each skill carries two micro-tasks: one solvable only with the capability (unaided probe) and one where the skill's text alone is insufficient unless the reader can follow it (follow probe). The 2×2 outcome reads internalized / works / uncovered / unfollowable. *New:* operationalizes Beyond Gain's identifiability result as a per-skill, model-agnostic artifact instead of a hub audit needing a second model. *Test:* SkillsBench subset or 40 synthetic skills, 2 readers; compare state labels to Beyond Gain's cross-model protocol at a fraction of the runs. Retention: retiring by litmus must not cost reward on held-out tasks (gate: ≤1 pp).
3. **Experiments indexed by the reader's own logit margin.** Store the experiment as a set of contrast states plus the expected directive shift (in logits) the skill should cause. After a swap, measure the new reader's shift on those states; a shift below the competing margin (cf. 2604.23750 margin competition) predicts the skill no longer controls behavior. *New:* a reader-side, forward-only validity test; uses the repo's own finding that directives shift ~0.6–1.0 logit. *Test:* PR #31 swap pairs; predict which lessons stop flipping actions under 1.5B from 0.5B-recorded contrasts. Retention: no lesson that still works gets dropped (precision ≥ 0.9).
4. **Skill as a falsifiable theory with a dead-man switch.** Each skill states a prediction about an observable the agent sees anyway (e.g. "the API returns field X before Y") and self-suspends after k consecutive falsified predictions, logging the falsifier. *New:* validity is checked continuously as a free side-effect of normal use, not by extra runs or a maintenance pass. *Test:* tool-schema rename mid-stream; time-to-suspend and false-suspension rate vs 2611.22525 replayed checks. Retention: false suspensions on an unchanged control tool < 2%.
5. **Counterfactual twin tasks generated by the skill itself.** The skill ships a generator that, given the current task, produces the minimally different twin on which the skill's assumption is violated; the agent runs both mentally (cheap rollout) and compares. Disagreement on the real task that matches the twin's predicted divergence signals non-applicability. *New:* SkillSandbox generates scenarios at admission; here the skill generates *its own boundary case at read time*, conditioned on the live task. *Test:* aliased workflows from 2610.25858-style ReasoningBank collision (cosine 0.835 vs 0.837); measure misloads. Retention: correct-load rate on non-aliased tasks unchanged.
6. **Transfer the experiment, re-fit the conclusion.** On a model swap, discard the procedure text, keep the experiment + recorded outcomes, and have the new reader re-derive the procedure from that evidence. *New:* inverts memory migration: migrate evidence, regenerate conclusions (2609.05339 says raw source helps; this makes the minimal sufficient evidence a first-class part of the skill). *Test:* 0.5B-written lessons re-derived by 1.5B from stored experiments vs re-reading old text vs re-learning from scratch at equal tokens. Retention: old-task success after migration ≥ old-reader success.
7. **Minimum description experiment (MDE).** Compress a skill's experience log to the smallest set of trajectories that still reproduces its Load/Abstain boundary under the writer (a coreset of decisive evidence); ship that, not all history. *New:* a sufficiency criterion for *what evidence to carry*, giving a bound on skill size. *Test:* coreset vs random subset vs full log at equal size, swap reader, measure boundary recovery. Retention: original reader's decisions agree ≥95% with full-log decisions.
8. **Experiment market across skills.** Skills compete to buy test time; a skill's price is its expected regret if wrong × uncertainty. Skills that have not been exercised (the 17–32% in SkillSandbox) bid highest after a swap. *New:* allocation of re-validation budget as a mechanism, not an audit schedule. *Test:* fixed probe budget after swap; regret vs uniform, recency and SkillApt-uncertainty allocation. Retention: frequently used skills keep ≥ baseline success.
9. **Self-testing via adversarial sibling.** Each skill is stored with an "anti-skill" (the procedure for the look-alike context where it is wrong). The experiment is a forced choice: which of the pair does the reader's execution trace match better on a 1-step probe? *New:* applicability as a learned contrast pair carried together, not a threshold on one skill's similarity. *Test:* 20 rule/anti-rule pairs in the router; compare to similarity threshold and precondition guard. Retention: rule-only accuracy unchanged when anti-skill is present but not chosen.
10. **Skill carries the gradient of its own utility.** Store d(success)/d(reader temperature or margin) measured at write time; after a swap, measure the new reader's entropy and predict new utility by extrapolation (lessons-as-temperature, PR #29: R² 0.916). *New:* uses the repo's surprising A3 finding as a portable re-validation law: if a lesson is mostly a temperature knob, its validity under a new reader is predictable from one entropy measurement. *Test:* predict 1.5B lesson effects from 0.5B gradient + 1.5B entropy; compare to re-running paired evaluations. Retention: rank correlation ≥ 0.7 on held-out lessons.
11. **Applicability certificates by interchange.** The experiment is an interchange intervention: patch the "skill-relevant variable" from a known applicable trajectory into the current one and check whether the reader's next action changes as predicted. *New:* causal-abstraction interchange used as a runtime applicability test, not interpretation (PR #47 #6 used it as an address; here as a test). *Test:* white-box 0.5B on router; compare with similarity routing on aliased states. Retention: no change to actions on states where the variable is absent.
12. **Skills with model-version unit tests compiled from failures.** Every time the skill was misapplied, the minimal failing state becomes a test with the expected abstain; the test suite travels with the skill. *New:* the skill's *misapplications* are its spec, so a new reader is tested on exactly the aliasing cases the old reader learned. *Test:* replay failure-tests after swap; does gating by them beat gating by success-checks? Retention: success-check pass rate unchanged.
13. **Probabilistic programs as skills.** Write each skill as a small probabilistic program over latent "mode" variables; the applicability experiment is posterior inference from a few observations, and the action is the posterior-weighted procedure. *New:* the skill is generative about its own context, so self-testing is inference, not a bolt-on check. *Test:* 3-mode API with aliased observations; compare to point procedures with precondition. Retention: single-mode accuracy unchanged.
14. **Cross-reader agreement as the experiment.** After a swap, run the skill's probe under both old and new readers (old one kept cheaply as a frozen judge for N steps); disagreement localizes which skills need repair. *New:* a temporary dual-reader overlap period as a mechanism for migration, like a database dual-write. *Test:* fraction of broken skills found with k probes vs random audit. Retention: skills where readers agree keep old success.
15. **Experiment-first skill writing.** Refuse to admit a skill until its writer has produced an experiment that, on held-out states, separates help from hurt with AUROC ≥ τ. Skills that cannot be tested are kept as "hypotheses" only loaded under exploration. *New:* testability as the admission criterion, not utility. *Test:* library of 40 lessons; compare admitted-by-testability vs admitted-by-gain on stream with later aliasing. Retention: old-family success vs gain-admitted library.
16. **Tool-swap invariants.** The experiment is a semantic invariant on tool I/O (e.g. "after create, list contains id") that holds under any faithful implementation; a tool swap that breaks the invariant flags the skill, one that renames fields does not. *New:* tests the *meaning* the skill depends on rather than recorded surface observations, so it survives benign renames that break 2611.22525-style replay. *Test:* synthetic tool with benign rename vs semantic change; false alarm vs miss rates vs replayed checks. Retention: zero suspensions under benign rename.
17. **Value-of-information gating.** Only run the skill's experiment when expected regret reduction exceeds its cost, computed from the skill's stored priors and the current reader's uncertainty. *New:* closes the cost gap that makes paired evaluation impractical online; makes self-testing cheap by default. *Test:* total actions and success vs always-test and never-test. Retention: old-task success ≥ never-test.
18. **Skill genealogy re-validation.** When a skill was derived from parents, its experiment includes parents' experiments; a failed parent test propagates suspicion to children (a dependency graph of evidence). *New:* evidence lineage across a library (cf. reversible execution tapes in PR #47 #8, but for validity not state). *Test:* tree of 15 derived lessons; break one root assumption; measure precision of propagated suspension. Retention: unrelated branches untouched.
19. **Calibration-carrying skills.** Each skill carries its own calibration curve (predicted vs realized benefit by context bin) and a one-number drift test (ECE on the last n uses). *New:* a portable, model-specific confidence object; recalibration is cheap on swap. *Test:* ECE detection latency of a swap vs SkillApt evidence reset. Retention: calibrated skills keep ≥ baseline success.
20. **Skill learns which questions to ask the user.** For ambiguous applicability, the experiment is a clarification question whose answer discriminates the latent condition; skills store the question and answer→decision map. *New:* human-in-loop experiment as a carried part of the skill (cf. 2610.25858 "when to ask" collision). *Test:* simulated user, aliased workflows; misloads vs asking always. Retention: question rate on unambiguous tasks < 5%.
21. **Weights-side self-test: canary probes for consolidated skills.** When a skill is distilled into LoRA, store canary inputs whose outputs certify the skill is present and unchanged; after base swap or further fine-tuning, the canaries detect silent loss. *New:* a portable presence test for weight-space skills, linking harness and model sides (cf. MX1 consolidation routes). *Test:* consolidate 10 lessons, fine-tune further; canary detection vs held-out task drop. Retention: canary false-alarm rate on untouched adapters < 5%.
22. **Self-testing ensembles of procedure variants.** A skill holds K procedure variants and an experiment that picks among them for the current reader; after a swap, the experiment re-selects without rewriting. *New:* re-validation as variant selection; avoids rewrite collapse (ACE / Dynamic Cheatsheet 18,282 → 122 tokens). *Test:* K=3 variants per lesson; post-swap selection vs single best-before. Retention: pre-swap success unchanged.
23. **Skill-to-skill cross-examination.** Skills test each other: skill A's experiment includes predictions about whether skill B should load; contradictions in the library's joint predictions after a swap localize the stale skill (sheaf-style global consistency, flood #31). *New:* collective re-validation without ground-truth rollouts. *Test:* plant one stale skill among 20; localization accuracy vs per-skill tests at equal probe count. Retention: no change to fresh skills.
24. **Experiment amortization into a learned applicability head.** Distill all skills' experiments into a small reader-specific head that predicts outcomes of experiments without running them; on swap, re-fit only the head from a few runs. *New:* a portable experiment set + cheap per-reader head as the migration unit. *Test:* head fit from 20 runs on 1.5B vs full re-evaluation. Retention: decision agreement with full paired evaluation ≥ 90%.

## Ranked sub-questions (by likelihood of a new primitive)

1. **What is the minimal sufficient evidence a skill must carry so that a different reader can re-derive both the procedure and its applicability boundary?** (ideas 6, 7, 24) A positive answer defines a new portable object (an "evidence capsule") and a size bound; the migration-portability results (2609.05339: raw source recovers 34/48, notes 0/48) say the gap is real.
2. **Can one carried experiment identify the skill's latent licensing condition, i.e. separate internalized / working / uncovered / misapplied under any reader, where gain provably cannot?** (ideas 1, 2, 9) Turns Beyond Gain's impossibility into a constructive per-skill test.
3. **Is reader-swap validity predictable from a single forward-only measurement of the new reader (entropy, directive shift vs margin)?** (ideas 3, 10, 21) If lessons are mostly temperature knobs (PR #29), validity might transfer by a law, making re-validation nearly free.
4. **Can a library re-validate itself collectively from mutual predictions, without ground-truth rollouts after a swap?** (ideas 14, 18, 23)
5. **When is self-testing worth its cost online?** (ideas 8, 17) Likely an improvement, not a primitive, but it gates whether any of the above is deployable.
