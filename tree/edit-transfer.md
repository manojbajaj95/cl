# Node: can an edit made in one model be moved to another?

Parent: [PR #49 model-guided edits](https://github.com/manojbajaj95/cl/pull/49), sub-question 5 ("Can an edit computed in one model be transported to another, so the big model learns once and writes many times?").

Question: a model learns something (a fact, a skill, a fix) through a weight edit. Can that edit be moved into a different model (another seed, a newer release, a bigger or smaller sibling, another family) so the target learns it without relearning from data?

## Root cause

**An edit is not an object; it is a difference between two beliefs, written in private coordinates against a private prior.** A ΔW only means something together with the source's key covariance C, its downstream Jacobian J, and the old belief it overrides. Every current transfer method moves one of these through a map fitted on shared structure. But the part of an edit that makes it *work* in the target lies mostly in the target's private subspace, which no map from source-side information can predict.

Three pieces of evidence point the same way:

1. **Updates are almost entirely backbone-private.** LoRAs trained for the same task on 7 CLIP backbones are nearly orthogonal. Summing all of them keeps 30.21 pp of gain on each backbone, but a leave-one-model-out sum gives 0.06 pp: an update written for model A does almost nothing in model B, even for the same task. The frozen backbone "selects its own component".
2. **The missing part is the target's private residual.** For cross-lingual ROME/MEMIT/AlphaEdit (a cross-"model" transfer inside one network), the gap is dominated by an orthogonal residual: source edits fail to span the target update directions, and any correction from source-side statistics has an expected gap lower-bounded by the private variance of the target residual.
3. **What is shared lives in activations, not weights.** Concept directions and steering vectors transfer across families above about 1.7B (47–49% of SAE feature pairs align, cross-model steering 71.0% vs native 68.0%), and late representations are linearly alignable. Weight-space transfer, by contrast, needs a linearly connected region (fine-tuning transfer between Llama 3.0 and 3.1) or a permutation/Procrustes alignment, and still leaves gaps.

A fourth, quieter point: edits suppress rather than erase (the original fact stays linearly decodable at 0.79–0.96 after ROME, constrained FT and even weight-free GRACE). An edit is therefore an *override calibrated to the source's own competing belief*. A target with a different prior strength needs a different override, so even a perfect coordinate map would move the wrong magnitude.

**Consequence:** the field has four families of workaround, and each pays for the root cause somewhere:

| Family | How it moves the edit | Where it pays |
|---|---|---|
| Parameter transport (Git Re-Basin, task-vector re-basin, gradient-sign masking, fine-tuning transfer, LoRA-X) | Align coordinates by permutations or subspaces, copy ΔW | Needs same architecture or a linearly connected region; misses the private residual |
| Functional transport (THESEUS, ARIADNE) | Match the activation change ΔW induces at matched blocks, then solve a native target update by Procrustes plus ridge regression | Needs calibration inputs and block correspondences; ARIADNE still trails the source-induced change by 8.14 points (width extension) and 3.66 (reduction) |
| Re-learning (Heirloom, Trans-LoRA, distillation) | Old model labels data, new model is trained on it | Works (within 1.7 pp of labelled retraining) but it is relearning: data, compute, and a copy of the old model |
| Moving the edit out of the weights (MindBridge memory modality, Universal Activation Bus, GRAFT bridge) | Store edits in a shared module or space with a small per-model adapter | The edit is no longer a weight edit; each model still needs a fitted adapter |

**What is missing is a model-independent description of an edit's content plus a per-model compiler that solves for the private residual inside the target.** Nobody has defined what "the same edit" means across two models in a way that can be checked, compressed, and recompiled. That object would be the primitive.

### Evidence from papers

| Paper | Finding used above |
|---|---|
| LoRA Superposition [2610.30691](https://arxiv.org/abs/2610.30691) | Exact sum of 7 backbone LoRAs: +30.21 pp, 0.28 pp below solo; leave-one-model-out sum: +0.06 pp. Cross-backbone responses concentrate on the diagonal. |
| Backbone-Specific LoRA Geometry [2611.27201](https://arxiv.org/abs/2611.27201) | Derives a cross-backbone correlation bound from attention symmetries; LoRA directions identify their source backbone by cosine. |
| Geometric Bottlenecks of Cross-Lingual KE [2611.10646](https://arxiv.org/abs/2611.10646) | Closed-form gap decomposition (key propagation, parallel and orthogonal residual mismatch); orthogonal residual dominates; source-only correction lower-bounded by target private variance; contrastive realignment fixes keys, not values. |
| Fine-tuning Transfer [2503.20110](https://arxiv.org/abs/2503.20110) | Llama 3.0 diff on 3.1: +46.9% IFEval; works best when source and target are linearly connected. |
| Re-Basin of Task Vectors [2505.22697](https://arxiv.org/abs/2505.22697), Gradient-Sign Masking [2510.09658](https://arxiv.org/abs/2510.09658) | Same-architecture release-to-release transport by head permutation or sign masks. |
| THESEUS [2602.12952](https://arxiv.org/abs/2602.12952) (ICML 2026), ARIADNE [2610.32581](https://arxiv.org/abs/2610.32581) | Task identity defined functionally (activation effects), transported across widths and depths; a gap to fine-tuning remains. |
| Heirloom [2611.00650](https://arxiv.org/abs/2611.00650) | Personal adapter migrated by distillation from the old model; a non-personal adapter loses 12.2 points. |
| MindBridge [2503.02701](https://arxiv.org/abs/2503.02701) | Cross-model knowledge editing by moving edits into an LLM-agnostic "memory modality". |
| Universal Activation Bus [2608.09521](https://arxiv.org/abs/2608.09521), GRAFT [2611.18638](https://arxiv.org/abs/2611.18638) | Shared activation space with one adapter pair per model; learned linear bridge for cross-backbone LoRA reuse. |
| Cross-Architecture Steering Transfer [2608.05164](https://arxiv.org/abs/2608.05164), LRT hypothesis [2506.00653](https://arxiv.org/abs/2506.00653), Universal Refusal Circuits [2601.16034](https://arxiv.org/abs/2601.16034) | Activation-level directions transfer (affine maps; above ~1.7B), weight-level edits do not come with them. |
| Suppressed, Not Erased [2609.18985](https://arxiv.org/abs/2609.18985) | Original fact stays decodable after successful edits (probe 0.96 ROME, 0.86 FT, 0.79 GRACE). |
| LatentPort [2609.25053](https://arxiv.org/abs/2609.25053) | Live recurrent state moved 4B→9B recovers 91.8% of context benefit: state transfer is feasible when the architecture matches. |
| Memory Portability [2609.05339](https://arxiv.org/abs/2609.05339) | For agents, fixed-schema memory moves across a model swap (+0.0004), compressed notes do not (+9.91 / −13.28 pp): portability comes from a fixed schema, not from the content. |

Already in the pool, so not repeated here as ideas: parent #11 cross-model transport by stitching, parent #12 portability score, P17 weight-space linker with symbol tables, B2-28 cross-model transfer by margin targets, B10 portable server-side learning state, B20 environment-version transport, and the task-vector transport / LoRA-to-text prior art in the shared memory.

## Raw ideas (no self-filtering)

Each entry: mechanism, why new, cheapest first test with a retention check. Default testbed unless stated: MLPs or GPT-2/Pythia pairs on CPU, CounterFact or synthetic key→value edits; "retention" = accuracy on the target's original task or neighborhood prompts before vs after. Every test should include the two baselines that bound it: naive copy (or Procrustes-transported ΔW) and distillation at the same number of target queries.

1. **Edit support set (an edit's minimal witness).** Mine, from the source pair (base, edited), the k inputs on which the edit changes behavior most and the k on which it must not (via gradient ascent on the base-vs-edited divergence). Ship only these 2k input/output-shift pairs; the target compiles them with a data-aware operator (ROME/AlphaEdit-style). *New:* functional transport uses generic calibration inputs at matched blocks; distillation uses many queries. This makes the witness part of the edit and asks how small it can be. *First test:* 50 MEMIT edits plus 10 LoRA behaviors on GPT-2 small → Pythia-160M; efficacy, paraphrase and neighborhood retention vs random-probe distillation at equal k ∈ {4, 16, 64}.
2. **Edit as an inverse-optimized objective.** Compress ΔW into the smallest loss term (a few weighted examples) whose one-step closed-form minimizer on the source reproduces ΔW (inverse optimization / dataset distillation of a single edit). The objective, not the weights, is the portable artifact. *New:* edits have never been represented as the objective that generates them. *First test:* MLP seeds A→B; optimize 8 synthetic examples so one O2 step on A gives ΔW_A; apply that step on B; compare with copying ΔW and with 8 real examples; retention on B's original task.
3. **Universal teaching set.** Optimize a tiny dataset so that one fine-tuning step installs the edit in *every* model of a population (4 seeds, 2 widths), then test on a held-out fifth model. *New:* dataset distillation targets one architecture; this targets "the edit as a family-level invariant". *First test:* 5 MLPs, rank-1 remap edits; held-out-model efficacy and retention vs per-model distillation at equal examples. *Risk:* cross-architecture distilled data is known to generalize partly.
4. **Edits as evidence, not conclusions.** Transmit the edit as a likelihood ratio (Δlog-odds over a candidate set, calibrated against the source's prior), so the target lands at *its own* posterior. Motivated by suppressed-not-erased: an override is sized to the source's competing belief. *New:* every transfer so far moves the final behavior. *First test:* GPT-2 small/medium, facts where the two models' prior strength differs; compare final-target vs Δlog-odds transfer on efficacy, over-confidence and neighborhood retention. *Risk:* near B2-28 margin targets; the new part is composing with the receiver's prior.
5. **Parallel transport along the lineage.** When the target descends from the source (continued pretraining, a new release), carry ΔW along the training path: at each saved checkpoint update ΔW by the linearized effect of that step (a JVP of the optimizer update, a discrete Lie derivative). *New:* all methods align endpoints; none uses the path. *First test:* MLP, edit at step t, continue training the base to t+k with saved checkpoints; transported vs copied vs re-based edit on efficacy and on the new model's task retention.
6. **Ghost-edit training (edit-aware continued training).** Train the new release while a "ghost" copy of each registered edit rides along: both base and base+edit get the same batch, and the edit's ΔW is updated so the edit's behavior is held fixed. The release ships with its edits already ported. *New:* turns edit migration into a training-time invariant. *First test:* MLP with 20 edits through 5k continued steps; ghost vs re-apply-at-end vs re-learn; cost in extra forward passes.
7. **Linear connectivity as a continual-learning invariant.** Fine-tuning transfer works inside linearly connected regions. Regularize every future update to stay linearly connected to a fixed ancestor, so every edit ever made in the family stays portable. *New:* LMC has been measured, never maintained as a portability guarantee. *First test:* continued training of an MLP with and without an LMC barrier penalty; transfer 20 old edits forward; also measure the plasticity cost.
8. **Shared edit ports trained from birth.** Reserve a small subspace in chosen layers that is aligned across a family during training (an alignment loss on port activations across models). Edits written only in ports move by copy. *New:* the ABI is enforced on independently trained models, not just declared. *First test:* two MLP seeds with a 16-d port; port edits copied A→B vs Procrustes-transported edits in unported models; retention and port capacity (edits before collapse). *Risk:* overlaps P9/P17 contracts; new if the port is learned by cross-model alignment.
9. **Shared developmental decoder.** Generate each model's weights from its own code through one frozen shared decoder (hypernetwork). An edit is a Δcode. Test whether a Δcode means the same thing on two different codes. *New:* asks whether a shared "genetic code" makes edits portable, rather than using hypernetworks for one model. *First test:* two MLPs decoded from different codes; edit as Δcode in A applied to B; efficacy and retention vs ΔW copy. *Risk:* near Universal Hypernetworks (2604.02215) and SM1.
10. **Edit code plus per-model decoder.** Learn a shared edit space z and one small decoder D_m(z)→ΔW per model, trained on many random edits made in all models. To transfer: encode A's edit to z, decode with D_B. A new model joins by fitting only its decoder. *New:* the Universal Activation Bus idea, applied to updates instead of activations. *First test:* 5 MLP seeds, 500 training edits; held-out edits transferred A→B; retention on B.
11. **Align models on their responses to edits, not on activations.** Fit the transport map T_AB by matching the behavioral effect of many random edits in both models (an edit-Jacobian alignment). *New:* stitching and Procrustes align representations; here the alignment target is "same edit, same effect". *First test:* MLP seeds; T fitted on 1k random rank-1 edits; test on structured edits vs activation-Procrustes transport.
12. **Cycle-consistent edit transport.** Learn T_AB and T_BA from unlabeled random edits with a cycle loss (A→B→A returns the same behavior change) plus a functional loss. *New:* CycleGAN-style self-supervision in edit space. *First test:* as 11; cycle error as a predictor of which edits will transfer.
13. **Transferability spectrum.** Decompose every edit into a shared and a private part using multi-model CCA on edit effects. Predict per edit how much will transfer, and report the shared fraction as a property of the edit. *New:* a measurement that turns "transfer works sometimes" into a per-edit quantity. *First test:* 200 edits across 3 seeds; does the shared fraction predict realized transfer efficacy better than edit norm or layer? Gate on target variance first.
14. **Target completes the private residual from context.** Move the shared part by alignment; then let the target fill its private residual by self-distillation from its own in-context version of the edit (fact in the prompt as teacher, OPSD-style), with a retention anchor. *New:* the private-variance bound says source information cannot predict the residual; the target's own ICL can. *First test:* GPT-2 medium/Pythia-410M facts; shared-only vs shared + ICL completion vs ICL-only distillation at equal steps; neighborhood retention.
15. **Edit compiled to a crosscoder.** Express the edit as a change in a crosscoder's shared dictionary (feature i → feature j association) and decode into each model through its own crosscoder decoder. *New:* crosscoders are used for model diffing, never as an edit carrier. *First test:* Pythia-70M/160M crosscoder on one layer pair; 20 feature-level edits; efficacy, and retention as change on unrelated feature activations.
16. **Universal editor over a model population.** Train one editor network (MEND-like) on many models, conditioned on a model descriptor computed from activations on a fixed probe set; at test it writes the same edit request into an unseen model. *New:* editors are per-model; this one learns the map from edit request to private coordinates. *First test:* 50 MLP seeds for training, 10 held out; edit efficacy and retention vs per-model ROME.
17. **Gated edit capsules with portable keys.** Ship an edit as (key detector, value) where the key is a text trigger set and the value a target-space direction recomputed by steering-vector transfer. *New:* combines GRACE-style gating with activation-level transfer, which already works above 1.7B. *First test:* 20 facts, Qwen2.5-0.5B → 1.5B; capsule vs MEMIT re-edit; retention on neighbors. *Risk:* MindBridge-like.
18. **Logit-space lowest common denominator.** Implement the edit purely in output space (a conditional logit processor keyed on the prompt), which is portable across any models sharing a tokenizer; then distill it into weights inside each target. *New:* use the portable form as the transfer medium and the weights as a per-model cache. *First test:* Qwen 0.5B → 1.5B; processor-then-distill vs direct distillation at equal steps; retention.
19. **Edit dictionary matching.** Each target keeps a library of its own past edits with behavioral signatures. Transfer becomes retrieval plus composition of target-native edits whose signatures sum to the source edit's signature. *New:* transport by recombining native parts, never by mapping coordinates. *First test:* MLP B with 500 native random edits; reconstruct 20 A-edits by sparse combination of B's library; efficacy and retention.
20. **Round-trip certificates.** Accept a transferred edit only if transferring it back reproduces the source behavior within ε. The round-trip error is a portable, label-free test of transfer fidelity. *New:* a verification primitive for transfer that needs no target labels. *First test:* in ideas 11/12, does round-trip error predict target efficacy (Spearman) better than activation-alignment error?
21. **Edit inheritance via the subliminal channel.** Subliminal learning transfers traits only between same-initialization models. Use that channel as an assay: an edit that transfers through unrelated generated text is a weight-tied edit; one that does not is semantic. *New:* uses the channel to classify edits by how tied they are to the substrate. *First test:* two GPT-2 small seeds (same vs different init); 20 edits; distill on unrelated outputs; measure inherited edits and retention. *Risk:* 2606.00831 says it is a LoRA artifact.
22. **Fleet consensus edit.** Transfer one edit to N targets with noisy methods, then average behavior across the fleet and distill the consensus back into each member. Private residual errors may average out where the shared part agrees. *New:* uses a population to estimate the private residual. *First test:* 5 MLP seeds; consensus vs single transport; retention per member.
23. **Edits as moves in a shared game.** Define the edit operationally as a change in the model's answers on a fixed, family-wide probe language (a "behavioral basis" of 1k probes), and require all models to expose the same basis. *New:* a fixed schema for weights, as fixed-schema memory is the only agent memory that survives a model swap (+0.0004). *First test:* express 20 edits as Δ on the probe basis; compile on target; compare with ARIADNE-style block matching at equal queries.
24. **Size-aware transport (small teaches big).** Steering transfers small→large via affine maps. Learn where in the large model a small model's edit should land by matching the *depth-normalized* effect profile (which layer fraction the edit's effect peaks at), then compile with a data-aware operator. *New:* treats depth correspondence as part of the edit's content. *First test:* Pythia 160M→410M; profile-matched vs fixed-layer-fraction placement; efficacy and retention.

## Deeper sub-questions, ranked by chance of a new primitive

1. **What is the minimal model-independent description of an edit, and can a per-model compiler rebuild the private residual from it?** This attacks the root cause directly: define "the same edit" as a checkable object (witness set, inverse objective, behavioral-basis delta) and let the target solve its own private part. Ideas 1, 2, 3, 14, 23.
2. **Can transport follow the path between models instead of aligning endpoints?** For release-to-release transfer, the training trajectory is a free, unused source of the private residual. Parallel transport and ghost edits would make edit migration part of training. Ideas 5, 6, 7.
3. **Should models be aligned in edit space rather than representation space?** Fitting maps on how models respond to edits (with cycle and round-trip checks) targets exactly the quantity transfer needs, and yields a label-free fidelity test. Ideas 10, 11, 12, 20.
4. **Can the substrate be built so edits are portable by construction?** Shared ports or a shared developmental decoder would turn transfer into copying, at some cost to capacity and plasticity that must be measured. Ideas 8, 9, 16.
5. **Is an edit better transferred as evidence than as a conclusion?** If overrides are sized to the source's own prior, a likelihood-ratio message that composes with the receiver's prior could fix magnitude errors no coordinate map can. Ideas 4, 13, 22.
