# Synchronizing consolidation: can an update sequence erase history without erasing skills?

Parent: [Minimal edit state, card 7 and deeper question 1 (PR #104)](https://github.com/manojbajaj95/cl/pull/104/files). **Node question:** Can a short sequence of updates collapse many past training histories into one edit class (a synchronizing word for the Nerode quotient of edits), and what does that give continual learning? These are raw research bets, not novelty verdicts or learning results.

## Root cause: quotienting does not make distinct states coalesce

PR #104 solves the **sufficiency** question for a fixed editor: equal classes have identical future observation and admission traces under every request suffix. It does not solve **reachability**: two genuinely distinct classes may have no short, legal, retention-preserving path to a common successor. The future-read distinction is real, not a classifier error. More probes can expose it but cannot remove it. In particular, every request can be injective **on the quotient**; then no word can reduce its rank, even if the learning trajectories visibly converge. Conversely, a destructive reset can give rank one at once but forget a live task or refuse future writes.

For the parent's exact affine oracle, write `q = Bz` (where the rows of `B` span the closure of the observations under all allowed edit matrices) and `q' = Fₐq + cₐ`. A common word `w` coalesces a cohort iff its induced matrix `F_w` annihilates the span of the pairwise differences `qᵢ − qⱼ`; the shared translations cancel. If the induced matrices are invertible, a finite word cannot coalesce distinct entries. For example, scalar gradient descent on a fixed quadratic preserves a nonzero initial difference after any finite number of steps if `0 < ηλ < 1`. A cooldown can contract the difference, but does not make it exactly zero. In exact arithmetic an appropriately chosen singular update can; its kernel has to contain the unwanted difference while the common successor and intermediate states satisfy the old-task guards.

**A separating toy.** State is `(r, v, x, y)`: `r` is a protected old skill, `v` is a visible editable score, and `x, y` are binary editor registers. Start with the same `r, v` and all four register pairs. Common updates `X: x ← 0` and `Y: y ← 0` leave `r, v` intact. Requests `R_x: v ← x` and `R_y: v ← y` distinguish the original histories; `T_b: v ← b` supports a fresh target. All requests are always admitted. Each of `X, Y` leaves two classes, and `XY` leaves one. No legal one-letter word suffices: every letter leaves at least one readable register. This is a hand-constructed positive control, not a CL result. If instead a still-live old task must return each history's original `x`, the two values cannot enter the same class under that protected readout. Test within compatible live contracts; do not silently replace distinct per-history targets by a shared label.

## What would count (and what it buys)

- **Exact contract.** Fix the deterministic full editor, a cohort `S` with compatible live targets, and a declared continuation alphabet including any subsequent consolidation calls. Quotient the reachable full states by PR #104's observation/admission traces. A *retained reset word* is one common open-loop sequence of allowed requests, with every prefix admitted from every entry and above pre-registered retention floors, such that its image of `S` has rank one (one quotient class). Reducing the rank but leaving it above one is partial consolidation, not synchronization. Distinct trajectories *during* the word are allowed; identical future traces are required only *after* it. Per-history replay or choosing requests from live observations is not a fixed word; compare and charge these as separate arms. Equal request strings whose executor secretly reads persisted history need not give equal successor classes.
- **Approximate contract.** Pre-register horizon, observation tolerances per group, and a suffix workload including adversarial distinguishing requests. Track worst-case pairwise trace diameter over the tested suffix set and admission mismatches, not connected components of “within epsilon.” Only an exact oracle or an inductive bound justifies an unbounded claim. With randomized edits, a shared externally supplied seed is a different contract from equality of future laws under adaptive requests; state which one is evaluated.
- **Payoff to test.** If two cohorts really coalesce under the declared interface, one tested continuation can stand in for both, and one canonical successor or transition table may replace multiple live editor states. That can make later updates less dependent on curriculum order and tests less redundant. Measure the compute or persistent bytes actually saved, including guards, checkpoints, generated examples, source branches and logs. A rank drop alone does not show a memory saving in a single learner, and physical weights need not become identical. A common class that cannot learn the next topic is not a useful destination.

### Controls and exclusions

Read PR #6's [ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md), [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md), and [top 10](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-top10.md). [PR #91](https://github.com/manojbajaj95/cl/pull/91) and [PR #104](https://github.com/manojbajaj95/cl/pull/104) already propose discovering/minimizing the quotient; [PR #95](https://github.com/manojbajaj95/cl/pull/95) and [PR #98](https://github.com/manojbajaj95/cl/pull/98) supply retention/definedness witnesses. Here the intervention is changing the set of *reachable successors*, not fitting a smaller predictor. No revival of execution-reward-matched effect-class distillation, Gramian/readiness ranking, cooldown-frequency effects, double-dosing removal, sparse-damage syndromes, or reflection in an exact training-equivariant symmetry.

Nearest common art: Černý's reset words and subset synchronization are the formal null, including careful synchronization for partial automata and adaptive homing as a different operation. A CL claim must add live task constraints and beat the appropriate automata search on a learned host; a new wrapper for subset search isn't enough. In weight space compare [SWA](https://arxiv.org/abs/1803.05407), [model soups](https://arxiv.org/abs/2203.05482), [Git Re-Basin](https://arxiv.org/abs/2209.04836), and [TIES-Merging](https://arxiv.org/abs/2306.01708); for stability compare [EWC](https://arxiv.org/abs/1612.00796), [GEM](https://arxiv.org/abs/1706.08840), replay and WSD-style cooldown/rewarm. These are nearest known controls, not a literature clearance.

**Shared first-test protocol.** All cards below are CPU-first. Use a finite editor or a width-8 learner; hold out whole entry histories, suffix families/combinations within the declared alphabet, and seeds. Construct hard twins matched on current accuracy and per-item margins. Compare at equal calls, data, persistent bytes and new-task efficacy as applicable; match elapsed steps, seen-example frequency and margin for any cooldown arm. Always log retention on untouched old tasks and still-live lessons using disjoint inputs after every real committed step and after suffixes. Use worst-group floors, record rejections and time-to-learn, and do not count intended supersession as forgetting. Abort a direction if it wins only against no-op, by matching immediate outputs, or by silently lowering coverage.

## Raw ideas

### A. Make a native word that actually removes a future distinction

1. **Annihilator compiler.** **Mechanism:** choose and order native rank-one gradient updates whose induced product kills the measured entry-disagreement span, not the whole editable parameter space. Search exact products first and label nonzero residuals approximate. **Why it might be new:** unlike switched-system observability, it compiles available *learning examples* into a reset for a chosen class cohort. **Cheapest test:** enumerate two-to-four-example words in a three-coordinate linear learner; compare random order, identical batches near zero LR, and constrained least squares. **Retention:** trace an overlapping old regression group at each step, then fit a new target using the spared direction.

2. **Momentum-and-weights deadbeat word.** **Mechanism:** choose steps and momentum settings jointly to kill disagreement in the augmented weight/velocity state; don't save or restore a seed checkpoint. **Why it might be new:** deadbeat control is known; the hypothesis is a reusable schedule that synchronizes the editor rather than just cooling loss or setting velocity to zero. **Cheapest test:** exhaust a small schedule grid for scalar heavy-ball regression with matched outputs but different velocities, against velocity reset plus matched cooling. **Retention:** score held-out old inputs throughout and after rewarming on a second loss.

3. **Safe detour reset.** **Mechanism:** when direct rank reduction violates an old-task guard, first add a temporary compensation update, contract the history-sensitive direction, then unwind compensation using the common word. **Why it might be new:** unlike GEM's one-step projection or careful automata search, the temporary learned compensation creates a legal reset path in a neural editor. **Cheapest test:** find a two-head linear or bilinear example whose unassisted alphabet has no safe coalescing path; add one charged compensation action, compare to GEM and reset-and-replay. **Retention:** check the tight old head at *every* step, including unwind, and after mixed-head edits.

4. **Synthetic reset lesson.** **Mechanism:** optimize a few shared synthetic minibatches through multiple sampled entry histories with a loss on paired *post-continuation* trajectories, not just terminal logits; forbid a history identifier. **Why it might be new:** dataset distillation learns short training sets; this one targets an edit-class attractor shared by multiple already competent learners. **Cheapest test:** two modular rules on a tiny MLP; compare to output-distilled examples and real replay at equal sample/gradient budgets on held-out third-rule scripts. **Retention:** run held-out queries from both original rules before and throughout consolidation and following third-rule commits.

5. **Force a quotient collision with an ordinary proximal step.** **Mechanism:** fit an editor with group-thresholded nuisance coordinates whose exact zero removes future-readable state differences while leaving an active set for subsequent learning. Count the optimizer's residuals in the null test. **Why it might be new:** proximal sparsification normally buys sparse weights, not future interchangeability across independently trained histories. **Cheapest test:** brute-force a sparse linear editor and compare to magnitude pruning, including a case where equal sparsity leaves different future traces. **Retention:** run old examples that rely on the surviving groups and test recurrence after reactivating a previously unused group.

6. **Edit-metric reconditioning.** **Mechanism:** design a short shared preconditioner-fit-and-step program to equalize how factorized twins respond to future task gradients; evaluate the optimizer as part of the reset. **Why it might be new:** Git Re-Basin aligns weights modulo permutations, but doesn't equalize future effective step geometry across genuinely edit-distinguishable factorizations. **Cheapest test:** use PR #104's bilinear twins extended to two products and mixed future targets; compare balanced factors alone, rebasin where applicable, and optimizer restart. **Retention:** check the original protected readout during reconditioning and after edits that mix the two products.

### B. Spend the smallest reset that the stream will support

7. **Reset portfolio with overlap.** **Mechanism:** store several short words with overlapping certified entry domains; solve a coverage-cost tradeoff for routing to canonical states, declaring routing information and its storage separately. **Why it might be new:** unlike task routing or subset synchronization in isolation, the library reuses costly future edit tests across histories with different curricula. **Cheapest test:** build a guarded editor with three overlapping basins; compare disjoint grouping, one universal word and per-entry replay at fixed coverage. **Retention:** retest old tasks on overlap boundaries and after cross-basin requests.

8. **Priced adaptive reset.** **Mechanism:** if no short word exists for the entire cohort, pick a paid observation and branch on its answer to select retained reset words whose destinations coincide. **Why it might be new:** adaptive homing diagnoses state; the candidate pays to drive a learner to one useful class, not simply to identify it. **Cheapest test:** enumerate a guarded six-state toy with no common admitted first move that can merge the cohort; compare best fixed word and exact adaptive strategy under a query budget. **Retention:** follow each branch, including wrong noisy responses in a separate arm; report old-task violations and rejected useful edits.

9. **Synchronizing slack auction.** **Mechanism:** allocate a fixed tolerance budget across old tasks to choose which *temporary* losses are worth permitting en route to a smaller rank; floors remain anchored to original references and can't be rolled forward. **Why it might be new:** EWC-like importance spends tolerance on present fit; the proposed curve prices a guaranteed reduction in future distinctions. **Cheapest test:** enumerate paths on a guarded grid with opposing task groups; compare fixed per-group margins and greedy min-loss, holding the original total slack and per-group minimum floors fixed. **Retention:** report each original group's largest transient loss, final loss and post-recurrence loss.

10. **Synchronize on paid return visits.** **Mechanism:** compile one word as a sequence of updates on regularly recurring data, inserting consolidation-only no-op gaps; intervening edits must be included in, or robustly bounded by, the word's contract. **Why it might be new:** spaced replay chooses what to rehearse; this exploits a regular stream's recurring requests as otherwise costly letters in a reset. **Cheapest test:** enumerate admissible subsequences in a toy recurring-regime stream with an interleaving that spoils naive selection; compare ordinary spaced replay at matched sample count and elapsed time. **Retention:** evaluate each group even while dormant and at unannounced recurrence before the word finishes.

11. **Reset with competing next tasks.** **Mechanism:** optimize the common destination under a worst-case budget of steps to learn any one of a specified set of mutually incompatible new targets, testing targets on separate forks. **Why it might be new:** unlike a generic plasticity/readiness score, future branching is a hard destination constraint that rules out absorbing or frozen states. **Cheapest test:** in a tiny editor with an easy frozen sink and harder reachable learnable sink, enumerate resets and compare shortest reset and matched-margin replay. **Retention:** after each branch learns its target, test all old groups and any still-live target on that branch.

12. **Buy fewer classes per extra kilobyte of replay.** **Mechanism:** select an indivisible retained replay packet jointly with a common word, and map the Pareto frontier of reachable rank versus packet size versus calls. Word is fixed after selection, with all retained evidence charged. **Why it might be new:** coreset selection usually buys old accuracy; here an example is valuable if it enables a specific previously impossible collision. **Cheapest test:** brute-force all subsets of a six-example buffer in a linear editor; compare herding and random coresets at matched retention, steps and bytes. **Retention:** score absent old examples and keep replay-free old groups in the test.

### C. Use coalescence to do something a soup cannot

13. **Continuation-test de-duplication.** **Mechanism:** consolidate multiple live instances of the same curriculum contract with a shared word and evaluate future edits once on a retained representative, with fallback when exact equivalence is unavailable. **Why it might be new:** cached training and model soups reuse computation or outputs, not a certificate that a future *commit trace* is interchangeable. **Cheapest test:** run parallel tiny continual learners, compare class-certified reuse with margin-cluster caching at equal future-call budgets under separating suffixes. **Retention:** independently audit old behavior and admission on every instance after applying the certified next edit.

14. **Merge by a rendezvous script, not a weight average.** **Mechanism:** parties that learned the same live targets in different orders execute one shared charged update script locally; only after coalescence can one future patch stand for every branch. **Why it might be new:** unlike a Model Soup, TIES or Re-Basin merge, the delivered artifact is a common executable prefix; no weight exchange is required in the script arm, and success is portable subsequent writes. **Cheapest test:** four width-8 branches; compare aligned averaging plus a matched optimizer-state restart and equal-budget local replay. **Retention:** keep every branch's predeclared common old tasks and test mixed future edits on each branch; no claim for conflicting contracts.

15. **Checkpoints that retire logs by construction.** **Mechanism:** establish exact coalescence through a common word before expiring edit logs; continue from the canonical editor state alone, not through implicit provenance reads. **Why it might be new:** event-log compaction normally retains point-in-time reconstruction semantics, whereas the retained reset can drop divergent provenance that is now irrelevant to *every allowed future edit*. **Cheapest test:** tiny rule editor with an optional later edit that reads provenance; audit which bytes survive versus snapshot-plus-log compaction at equal continuation coverage. **Retention:** check recurring lessons after logs are physically removed and verify admitted provenance-dependent behavior is neither silently lost nor excluded after the fact.

16. **Carry only the protected residual.** **Mechanism:** for distinct live contracts, split a minimal charged protected payload from a shared editor core; synchronize the core and prove an intertwining law conditional on payload, not full-state equality across differing targets. **Why it might be new:** parameter isolation protects skills but doesn't necessarily provide a single shared update transition with the smallest per-learner residual. **Cheapest test:** two users with one differing old bit and common modular learning tasks, compare independent small adapters and a shared head at equal bytes. **Retention:** check both user-specific old tasks, including later edits that interact with the retained bit.

17. **Portable edit patches with a reset preamble.** **Mechanism:** author a patch on one member, ship a common synchronizing preamble plus the same request payload to peers, and forbid member-specific recompilation. Unlike branch rendezvous, test the *total transfer cost* across many different patch issuers and charge the preamble every time it is needed. **Why it might be new:** adapter composition transfers weights; a preamble would make edit executability a portable property of a request/native-update bundle. **Cheapest test:** compile patches on one toy checkpoint each, compare Re-Basin-aligned delta transfer and per-host replay on unseen histories. **Retention:** check unmodified old rules at each preamble step and after each transferred patch, counting all refusals.

18. **Checkpoint handoff without copying the source.** **Mechanism:** a public curriculum of fixed tasks leads fresh and longtime learners to the same usable edit class; handoff consists of that curriculum, optionally with a small shared supplement charged as data. No source weights or instance history provided. **Why it might be new:** unlike dataset distillation for fresh initialization, a bootstrap class doubles as a live retention-preserving synchronization point for incumbents. **Cheapest test:** on a modular task with a canonical symbolic learner, compare a script to oldest-first replay and a compressed snapshot at matched bandwidth and local steps. **Retention:** incumbents must preserve old tasks at every step, while fresh replicas must acquire them by the join point and keep them through later edits.

### D. Design and break repeatable reset primitives

19. **Reset separators as an architectural interface.** **Mechanism:** build a small editor in which histories factor across modules and a targeted reset may touch a separator with shared mutable state but cannot consume module-owned task memory. Synchronize modules and separator in a certified order. **Why it might be new:** unlike independent adapter resets, the hypothesis is a compositional reset rule for dependent modules; local resets alone can fail when the separator is readable. **Cheapest test:** enumerate two finite toy modules with a shared parity channel, compare independent resets and monolithic solver search. **Retention:** evaluate the cross-module old rule as well as each module's local tasks after interleaved writes.

20. **Uniform reset interval.** **Mechanism:** design a learner plus a common word such that every stream of at most `k` admissible writes starting at the destination stays in the word's safe entry basin and returns to the destination under that word. Measure the maximum `k` (or find the shortest escape). **Why it might be new:** unlike periodic plasticity resets or cooldown, a bounded-history invariant would make the same reset reusable at a guaranteed cadence. **Cheapest test:** exhaust admitted words up to `k` in a finite two-task editor to prove or refute the one-cycle inclusion; compare periodic optimizer reset. **Retention:** check cumulative worst-group drift against the first cycle's references, including a late old-task return.

21. **A reset conjugate across backends.** **Mechanism:** learn a tied request compilation from native updates in two editor implementations; prove that each compiled word maps its input cohort into the same *interface* state under the shared request contract. Charge translators as memory. **Why it might be new:** PR #104's migration lens maps one backend's current state into another; this asks for a shared sequence that contracts *both* without reading instance state across the boundary. **Cheapest test:** small redundant linear editor and table editor with a shared rewrite API, compare backend-specific resets and direct state translation. **Retention:** after reset, run old scripts unchanged through both adapters and test original held-out behavior.

22. **Synchronize trace laws without tying the seeds.** **Mechanism:** use shared minibatch distributions in a noisy editor to erase dependence on entry state in the observable continuation law, testing policy-dependent requests and independent seeds. **Why it might be new:** Markov-chain coupling bounds mixing; a retained stochastic reset would target observable edit laws and maybe mix faster than the latent state. **Cheapest test:** compute transition matrices on a six-state noisy learner; compare to noise-only mixing and common-random-number alignment, testing exact laws before empirical distances. **Retention:** bound old-task failure probability during the word and after adaptive suffixes, not just expected accuracy.

23. **The shortest obstruction certificate.** **Mechanism:** compute reachable safe *pairs* and, for small cohorts, safe subsets backward from candidate destinations. Supply a minimal incompatible cohort or required new update, not a failed optimizer run. Include a case with pairwise safe paths but no shared safe word. **Why it might be new:** careful synchronization already gives obstruction machinery; the CL hypothesis is that a witness identifies a missing retention-safe update primitive versus irreducible live task information. **Cheapest test:** plant both failure types in an exact toy and see whether a permitted new action clears only the first, against adding random actions at equal coverage. **Retention:** retest old witness tasks throughout the repaired word, and show erasing the irreducible bit fails its old-task guard.

24. **Continual reset red team.** **Mechanism:** alternate training a word with finding a request suffix that maximally separates survivors, then lock the word and test suffix families searched by an independent challenger. The challenger cannot add a new port. **Why it might be new:** counterexample-guided quotient learning in PR #91 splits classes; here counterexamples change the *update program* to remove the separation without changing the alphabet. **Cheapest test:** plant a two-step read-after-write failure in a bilinear learner; compare to random suffix training and static immediate-effect matching at equal execution budget. **Retention:** every adversarially patched word must still preserve the original held-out tasks and admission coverage, including tests not used by the challenger.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can a few native learning updates erase procedural history under a fixed, useful edit interface?** Highest: an annihilator on the continuation-visible disagreement span, with retention and editability constraints, would be a reusable *action* (1–6, 11). Start with the exact toy, then hold out entry and suffix families on a width-8 learner; require a win over both reset-and-replay and aligned-weight/optimizer reset. If the only solution replaces the state with a stored answer or closes write ports, stop.
2. **Can reset words compose and be reused indefinitely?** A retention-safe basin invariant and separator rule would make repeated consolidation a bounded-memory protocol, rather than one impressive endpoint (19–21). Falsify with interleaved edits that break closure or cumulative drift; compare against periodic cooldown at matched time and old margins.
3. **What forces an irreducible rank, and what one new action breaks the right obstruction?** A witness that distinguishes preserved task information, unsafe paths, and injective dynamics could guide editor design (3, 7–9, 16, 23). Lower confidence: the witness could reduce to textbook careful synchronization unless it identifies and transfers a missing learning update.
4. **Can coalescence buy enough real amortization to justify the intervention?** Measure bytes, future tests and overall calls after the reset cost across long recurrent streams (13–18). Lower novelty by itself: if matched replay or rebasin plus optimizer reset yields the same portability, this is a consolidation improvement, not a new primitive.

## First discriminating CPU experiment (proposed)

Validate an exhaustive oracle on the register positive control and the protected-bit and invertible-affine negative controls. For a learned test, train two overlapping modular rules in different orders on a width-8 MLP with momentum; keep margin-matched twins. Freeze the native alphabet (minibatch updates, a small public LR grid, and a declared momentum reset) and a word budget of at most four updates. Train/select using whole discovery histories and shallow suffixes, then evaluate on held-out histories and unseen combinations including a third learnable rule. Compare no-op, momentum reset, matched cooldown, output-distilled and real replay, plus aligned averaging when both checkpoints are available (charge them). Require contraction of continuation trace diameter beyond the strongest matched control, no admission mismatches, old-task floors at every committed step, and comparable third-rule acquisition. If only a specially engineered toy coalesces or if matching margins/compute erases the gain, don't scale. **No learning experiment was run.**
