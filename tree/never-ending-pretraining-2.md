# Never-ending pretraining 2 · Transport the write, not just its result

Child of [the root](root-never-ending-pretraining.md) ([PR #389](https://github.com/manojbajaj95/cl/pull/389)); follows the [review](https://github.com/manojbajaj95/cl/blob/db8c8709d6947d01e95c61877892767fa201e181/reviews/flood-triage.md) of NP07 and NP28. Both were scored 3; no root card reached 4. The remaining question is what operation one model could perform that a better initialization, a date tag, or a new measurement cannot. The 26 candidates below change the actual write, its representation, or the rules for composing it. No experiments were run.

**Fixtures and fair comparisons.** Start with a finite autoregressive model on a tiny byte alphabet, or a two-layer decoder on a private synthetic chronology. For tokenizer cards, apply the same raw bytes and match cold next-byte distributions first; compare [exact byte pushforward](https://arxiv.org/abs/2410.09303), [approximate likelihood matching](https://arxiv.org/abs/2503.20083), [FOCUS](https://arxiv.org/abs/2305.14481)/[WECHSEL](https://arxiv.org/abs/2112.06598), and new-tokenizer retraining (same-budget and stronger full-budget reference). Include [MATT](https://arxiv.org/abs/2510.21954) where internal-state matching matters. Give ordinary optimizers a tuned LR and equal state or state a size advantage explicitly. For time cards, use **valid time** for when a claim holds, **knowledge horizon** for which publications are admissible, and **ingest step** for the order they reach training. Differentiate “was reported” from “was true.” Compare [TempLAMA](https://arxiv.org/abs/2106.15110), two-date conditioning, bitemporal retrieval through the same query language (an external-state oracle), [MEMIT](https://arxiv.org/abs/2210.07229), and [PRISM Edit](https://arxiv.org/abs/2607.11327) where temporal editing is relevant. Evaluation is cold without retrieval for the proposed learner; keep old stable tasks, old valid answers, and old as-known answers separate. Kill if a named control matches the claimed operation with the same held-out old/new performance at the relevant state/compute budget, or if a claimed invariant fails. Fix numerical tolerances before testing.

## A · Make a write independent of its tokenization

### NP2-01 · Lift a byte write back into the current tokenizer
- **Mechanism.** Store the desired update to log odds of a small set of byte-prefix events, not a token-row delta. Realize it in either tokenizer with a minimum-cost parameter step subject to those event changes and zero change on protected events. In an enumerable model use the byte-event Jacobian and its pseudoinverse; a target outside the image is explicitly unwritable, rather than silently projected into a different lesson.
- **Nearest art.** [Exact byte probabilities](https://arxiv.org/abs/2410.09303) transports reads, not parameter actions; [AlphaEdit](https://arxiv.org/abs/2410.02355) constrains weight updates in a knowledge null space. The candidate is a single executable write whose feasibility and meaning are defined without naming a tokenizer.
- **First test / kill.** Use three prefixes with attainable and unattainable requested changes. Apply the same write in two split/merge charts, then repeat with unseen contexts. Kill if likelihood matching plus ordinary training attains the same requests and rejection behavior, or if the claimed shared write disagrees beyond linearization error on held-out byte events.
- **Retention.** Keep old completions that share the edited byte prefix but diverge at the first byte inside a new merge.

### NP2-02 · Keep the smallest memory a merge cannot carry
- **Mechanism.** When old coordinates are quotiented out, retain only the missing training state that can alter a future *shared* read. In a linearized writer this is the observable component of the null-space state of the migration: span the successive responses to allowed batches and store coordinates in that span, not the whole old optimizer. Reconstruct the missing contribution when stepping the new chart.
- **Nearest art.** [Staged Training](https://arxiv.org/abs/2203.06211) passes optimizer state through growth, and [bidirectional lenses](https://doi.org/10.1145/1047659.1040325) retain information needed for round trips. Removing unobservable state is [classical realization theory](https://doi.org/10.1137/0301009); the candidate is taking that quotient of the *lost optimizer state across a tokenizer edit*, with minibatches as inputs and byte events as outputs.
- **First test / kill.** Build a merge where two lost directions share cold outputs, but only one can re-enter a shared read after two steps. Compare zero-fill, full old state and same-rank PCA. Kill if truncated response state cannot match the full-state trajectory on unseen batches more accurately than the same-rank control.
- **Retention.** Check old outputs that depend on the returning response and one skill carried by an unaffected state direction.

### NP2-03 · Compose migrations with a repair term
- **Mechanism.** For two elementary token rules, compose their transported writes and attach an executable correction when opposite orders reach the same vocabulary but disagree on behavior. Fit the correction in shared byte-effect coordinates; orient it to a canonical order. To be reusable, the same local correction must make an unseen three-rule sequence independent of the chosen order of adjacent swaps.
- **Nearest art.** [Composable Expansions](https://arxiv.org/abs/2308.06103) composes function-preserving surgeries; [An Equivariance Toolbox](https://arxiv.org/abs/2512.21447) characterizes learning-dynamics symmetries. The new obligation is an explicit local repair of an *observed noncommuting write*, not proving that parameter symmetries already commute.
- **First test / kill.** Use three compatible boundary rewrites in a finite LM. Learn a repair from each pair once and apply it in two decompositions of the third-order edit; compare canonical replay of the raw batches and a direct map. Kill if the pair repair has to be refit for each path or accumulates more disagreement than independent migration.
- **Retention.** Evaluate old phrases participating in each individual rule and a phrase at their overlapping boundary; matching terminal vocabulary IDs does not count.

### NP2-04 · A merge with two writable fibers
- **Mechanism.** A frequent span gets one forward token but its backward pass has a shared write and a contrast write keyed by raw context classes. The forward state may coincide before training, yet the contrast stays addressable until writes that need it factor through the shared channel. Compress both into one only if the contrast is unnecessary under a declared update family.
- **Nearest art.** [Dynamic Tokenization](https://arxiv.org/abs/2411.18553) predicts embeddings for temporary merges, and [Gradient Routing](https://arxiv.org/abs/2410.04332) masks gradients by example. Retaining two future write identities for *one* merged read, and releasing the second after factorization, is the narrower claim (not adding a new meaning vector).
- **First test / kill.** Construct two old uses with identical current predictions and opposite next-batch corrections. Compare a normal merge, subword dropout, and two ordinary embedding rows at matched active state/compute. Kill if the two-channel write gains neither future learning over the normal merge nor compression over keeping the two rows.
- **Retention.** Test both old meanings after learning a third context, including an old context with no branch cue except earlier raw bytes.

### NP2-05 · Roll back the coordinate change, keep the lessons
- **Mechanism.** Each migrated step emits a shared byte-effect delta and a residual outside the old chart. To remove a tokenizer change, invert the migration and re-realize the accumulated shared deltas in the old chart; keep genuinely unrepresentable residuals explicit. This is selective retraction of a coordinate change, not a return to a checkpoint that predates new training.
- **Nearest art.** [ZeTT](https://arxiv.org/abs/2405.07883) supports tokenizer swaps; [retroactive data structures](https://doi.org/10.1145/1240233.1240236) change historical operations. NP12 in the root uses reversal as an assay; the extra operation here retracts the change without rerunning the intervening raw stream.
- **First test / kill.** Interleave two transferable new rules with one known rank-deficient residual. Remove the middle tokenizer edit and compare checkpoint rollback, backward ZeTT, and retraining as an oracle. Kill if it drops transferable rules, silently invents an old-chart realization of the residual, or backward ZeTT already suffices at equal cost.
- **Retention.** Check ordinary original-tokenizer text and old true alternatives on contexts that also host one of the new rules.

### NP2-06 · End supervision inside a token
- **Mechanism.** Apply a write to a raw byte interval using a difference of differentiable log prefix masses at its endpoints. The denominator conditions on the preceding raw prefix and neither term observes later bytes. A partial token therefore need not be expanded into a separate training example or supervised in its entirety.
- **Nearest art.** [Exact Byte-Level Probabilities](https://arxiv.org/abs/2410.09303) and [Tokenization Bias](https://arxiv.org/abs/2406.16829) already recover or analyze byte/word probabilities under tokenization. This uses those marginals as a *scope restriction on training*: two realizations of the interval must apply the same supervised evidence without seeing the rest of a token.
- **First test / kill.** Use a merged token whose suffix would reveal a planted label. Compare canonical token cross-entropy, byte fallback, and interval writes at matched work. Kill if changing only the unobserved suffix changes the training gradient, or byte fallback has the same locality and efficiency.
- **Retention.** Score the previously learned suffix task and unaffected old continuations; the private-label cut must not damage them.

### NP2-07 · Make accumulation commute with splitting a training unit
- **Mechanism.** Define an update transaction over raw spans: accumulate *unpreconditioned* byte-event gradients for the whole transaction, then apply Adam or another nonlinear writer once. If retokenization changes the number of microbatches, carry the unfinished raw-span transaction across the boundary instead of advancing optimizer time. Include a counted mask for which raw targets were already charged.
- **Nearest art.** Gradient accumulation is standard; [Staged Training](https://arxiv.org/abs/2203.06211) carries a full training state, and [FLEXITOKENS](https://arxiv.org/abs/2507.12720) changes segmentation and compression. The candidate is a transaction with a conserved *unfinished* supervision set and one final commit across a migration; ordinary byte-normalization does not repair applying a nonlinear step twice.
- **First test / kill.** Split a raw passage midway through an accumulation window and migrate; compare completing the old window, flushing in both charts, and fixed byte batching. Kill if the mixed transaction cannot match the uninterrupted write without repeating bytes, or fixed byte grouping offers exactly the same capability at equal latency.
- **Retention.** Test a rare old continuation whose span straddles the switch and an old task sensitive to the optimizer's step count.

### NP2-08 · One shared optimizer across mixed tokenizer workers
- **Mechanism.** Let data-parallel workers temporarily use different tokenizers, but send gradients in agreed byte-writer coordinates. Reduce those cotangents and advance the single shared moment state once. Chart-local residuals live separately until they are realizable in a common chart; never average their Adam deltas as if the coordinates were identical.
- **Nearest art.** [Universal Cross-Tokenizer Distillation](https://arxiv.org/abs/2503.20083) lets separate models align predictions; [The Loss Does Not See the Basis, but Adam Does](https://arxiv.org/abs/2608.05136) demonstrates how coordinate choice changes updates. This is one synchronous lineage performing a collective *write* across charts, not an ensemble or continual transfer between models.
- **First test / kill.** Split a tiny batch across two charts, swap the charts without changing the batch, and reduce in byte-effect coordinates. Compare retokenizing all workers, averaging translated parameter gradients, and averaging translated optimizer deltas. Kill if worker assignment still changes retained behavior or all-worker retokenization wins at equal compute and transition interruption.
- **Retention.** Use old examples split and merged differently across the workers, including low-frequency spans absent from the reduction examples.

### NP2-09 · Transfer refusal, not a mismatched zero
- **Mechanism.** Give each byte-defined write a partial domain. If it is realizable in the old chart but conflicts with protected reads in the new chart, the migrated model may defer that exact write or undo the relevant local merge. It may not keep the same write name while silently replacing the requested effect by its least-squares projection.
- **Nearest art.** [AlphaEdit](https://arxiv.org/abs/2410.02355) already projects edits into a preservation null space; [The Foundations of Tokenization](https://arxiv.org/abs/2407.11606) formalizes statistical information loss. The proposed operation uses incompatibility to *selectively change the tokenizer* so a particular ordinary write becomes legal again.
- **First test / kill.** Plant two equally scored merges, one making a useful new write incompatible with a required old read; undo only that boundary. Compare unconstrained update, projected edit, and dropping both merges. Kill if projected editing gets the same useful new effect and old retention, or if selective unmerge cannot restore an admissible write.
- **Retention.** Protect the old rule that caused the conflict, plus continued compression and old reads for the unrelated merge.

### NP2-10 · Swap input and output representations without severing credit
- **Mechanism.** Keep a byte-indexed latent embedding for a tied vocabulary; read it through a tokenizer-dependent input aggregation and output marginal, but collect both gradients against the *same* latent variable. A migration changes those read maps, not which directions are allowed to receive joint input/output credit. Sum the gradients pulled back through the two adjoints, rather than averaging new rows.
- **Nearest art.** [FOCUS](https://arxiv.org/abs/2305.14481) initializes new rows from overlapping embeddings, and [MATT](https://arxiv.org/abs/2510.21954) transfers attention-influence behavior. The candidate is preserved coupling between the two uses of a row over future gradient steps, even when fixed embeddings and hidden reads already match.
- **First test / kill.** In a tied bigram model, make training an emitted spelling change how the spelling is interpreted later. Compare tied and untied transfer with matched cold predictions and parameter budget. Kill if the latent write does not recover both effects across a merge or ordinary tied transfer matches it.
- **Retention.** Test old input interpretations as well as old output spelling, so training one half cannot hide loss of the other.

### NP2-11 · Transport a prohibition on writing
- **Mechanism.** Migrate the set of *forbidden functional changes* before moving the optimizer. Derive legal target-chart steps by pulling those prohibitions back through its byte-event map. An old protected direction with no single new parameter counterpart remains forbidden, and unrelated new coordinates can stay writable.
- **Nearest art.** [AlphaEdit](https://arxiv.org/abs/2410.02355) constrains edits in one model's null space, and [Sculpting Subspaces](https://arxiv.org/abs/2504.07097) protects earlier tasks during fine-tuning. A transportable prohibition that survives changing what a logit means is the proposed primitive, not null-space projection itself.
- **First test / kill.** Represent one old constraint as a single row before a split and a combination of two rows afterward. Compare freezing likely rows, Jacobian transport of an old Fisher penalty, and pulling back the exact prohibition. Kill if the penalty matches both legal adaptation and protection on a second migration, or the prohibition prevents every useful update.
- **Retention.** Check nearby unprotected old behavior as well as the protected combination; exact preservation on one read still does not license collateral loss.

### NP2-12 · Carry a future write through an unfinished byte prefix
- **Mechanism.** Compile the suspended state of a prefix-conditioned update into a residual parse distribution and the corresponding gradient contributions. Resume under the new chart before the end of the word. Unlike completing the word first, future bytes cannot change the status of supervision already committed; unlike discarding the state, no earlier bytes are charged twice.
- **Nearest art.** [Exact Byte-Level Probabilities](https://arxiv.org/abs/2410.09303) handles reads ending mid-token, and [subword regularization](https://arxiv.org/abs/1804.10959) trains across segmentations. The remaining claim is an online transfer of an *open computation of a training gradient*, with fixed already-committed supervision.
- **First test / kill.** Pause a marginal-prefix training computation where two parses have unequal posterior mass, migrate and resume. Compare flushing, restarting from raw bytes, and keeping only the winning parse. Kill if the compact suspended state cannot reproduce the uninterrupted gradient or needs as much stored raw context/work as restarting.
- **Retention.** Check old mid-word completions and old short contexts that select the minority parse; a canonical-boundary-only result fails.

## B · Make a correction independent of its incidental dates

### NP2-13 · A rectangular overwrite, with a boundary that means something
- **Mechanism.** Write a fact into a rectangle of (valid time, knowledge horizon) using four signed corner updates to answer-score differences: recover its effect by summing corners at or before the queried coordinates. A correction published at horizon H for validity interval V initially writes V × [H, ∞); later overlapping corrections truncate the affected cells. Compose corner updates before realizing them in weights; shared cancelling boundaries disappear. The operation is a scoped overwrite, not training on four dated examples.
- **Nearest art.** [Temporal database terminology](https://doi.org/10.1145/140979.140996) supplies the two axes; [PRISM Edit](https://arxiv.org/abs/2607.11327) writes a polysemous subject vector modulated by one temporal context. The delta is a compact, composable bitemporal overwrite with enforced cancellation, not the fact that two dates can be supplied.
- **First test / kill.** Partition a tiny chronology into overlapping half-open intervals and write a correction crossing an old boundary. Compare two-date CPT, PRISM with both dates available, and unconstrained MEMIT. Kill if a rectangle cannot survive inserting a second overlapping rectangle without relearning enumerated cells or if a control already does this.
- **Retention.** Measure all four sides of the edit plus old adjacent boundaries and older as-known versions of the same fact.

### NP2-14 · Withdraw one correction but preserve its historical publication
- **Mechanism.** Make each correction an identified additive claim with a validity support. A withdrawal installs its negative contribution only after the withdrawal became knowable and only on still-supported cells; later independent repairs remain. The earlier publication remains answerable, even when its factual authority is withdrawn. Use support masks and signed residual writes in the tiny fixture.
- **Nearest art.** [DBSP](https://arxiv.org/abs/2203.16684) uses signed changes to maintain materialized views, and [time-sensitive knowledge editing](https://arxiv.org/abs/2406.04496) uses PEFT to inject and update temporal facts. The challenge is a targeted inverse in *one learned surface* that retains the prior belief trajectory, not a missing deletion operator in databases.
- **First test / kill.** Apply A, an overlapping independent B and a withdrawal of A. Compare global weight negation, new-data conditioning, and sequential MEMIT with retraction examples. Kill if withdrawing A changes B or old publication answers, or if a normal temporal edit can cancel A with no collateral damage at equal cost.
- **Retention.** Require what A originally reported, truth before A, and what B independently authorized.

### NP2-15 · Publish a multi-claim report as one write
- **Mechanism.** Stage payload writes behind an evidence-availability factor learned separately from their fact values. At publication, make the factor activate all claims from the report together and only in their listed validity scopes; a never-committed report provides no factual authority. No runtime reader fetches the staged material from a store.
- **Nearest art.** [Temporal databases](https://doi.org/10.1145/140979.140996) know recorded-time visibility; [Composable Unstructured Knowledge Editing](https://arxiv.org/abs/2608.11660) teaches a model to use several facts in one passage. The delta is a shared *learned publication operation* that makes partial application impossible on cold queries spanning claims.
- **First test / kill.** Feed a two-part report with a third claim interleaved from an unrelated publication. Compare a single batch at release, time-tagged per-claim edits, and gating. Charge staging bytes and compare release latency. Kill if commitment leaks one staged claim, activation is only partially coherent, or buffering the report and applying one write matches quality, state and latency.
- **Retention.** Read old cross-claim combinations before release and historical answers about unrelated multi-claim reports afterward.

### NP2-16 · Lift an asserted fact into a quotation without promoting it to truth
- **Mechanism.** Give a write a type: publishing “source S asserted P” changes a report channel, while making P authoritative changes a truth channel. Learn a one-way projection from authorized reports into truth; there is no inverse from truth into which source said it. A contradicted report can still be recalled verbatim as a report after its truth contribution is cancelled.
- **Nearest art.** [ConflictBank](https://arxiv.org/abs/2408.12076) separates intra-model conflict from conflict with retrieved context, and [EVEDIT](https://arxiv.org/abs/2402.11324) uses event descriptions to delimit deductive editing. The extra operation is a write whose type forbids a source report from changing the default factual answer without another admissible write.
- **First test / kill.** Train on matched reports, counterreports and one later adjudication, with held-out quoted paraphrases. Compare role prefixes and a temporal MEMIT/PRISM edit on the same payload. Kill if merely quoting a false report changes truth scores or explicit type separation adds no protection beyond the prefixes.
- **Retention.** Require earlier quotations, previously adjudicated facts, and the earlier truth interpretation for unrelated subjects.

### NP2-17 · Freeze only what was knowable before publication
- **Mechanism.** Compile an update as the difference of two states: an unchanged past-horizon reader plus a new term whose output is guaranteed zero before publication. Permit ordinary general skill deltas to reach both horizons only if they preserve the old evidence-supported answer set. This scopes the new information, not all improvement in the model.
- **Nearest art.** [Can Prompts Rewind Time?](https://arxiv.org/abs/2510.02340) tests prompt-driven suppression of later knowledge; [TempLAMA](https://arxiv.org/abs/2106.15110) conditions on a year; [AlphaEdit](https://arxiv.org/abs/2410.02355) preserves selected outputs. The new claim is a hard one-sided write restriction sharing general skill across cuts, not instruction-time behavior or freezing whole snapshots.
- **First test / kill.** Publish an unguessable outcome and also teach a generic logical transformation. Ask systematically older as-known questions in held-out paraphrases, including questions solvable from old evidence once the generic skill improves. Kill if later facts leak backward or if the bound suppresses legal old deductions that a time-conditioned control retains.
- **Retention.** Preserve old known answers, past answer sets with no settled truth, and old generic reasoning with no date tag.

### NP2-18 · Ingest out of order without rewriting history
- **Mechanism.** Resolve a write using its publication timestamp and intersecting validity cells, not optimizer ingest order. Keep only the current piecewise authority summary needed by the writer (including historical publication cuts); turn each arrival into the signed difference of that summary's old and new read surfaces, and realize it in a fixed score-coordinate chart. Swapping arrival order with author and publication dates kept fixed must produce the same readable history.
- **Nearest art.** [Retroactive Data Structures](https://doi.org/10.1145/1240233.1240236) supports historical insertions, and [Time-Incremental CPT](https://arxiv.org/abs/2609.23916) studies chronological web snapshots. The potentially reusable primitive is order-independent learned history with no replay of the sorted sequence and no external lookup during inference; sorting at an upstream queue is a control.
- **First test / kill.** Ingest a notice, a correction and an older notice that arrives late, in all arrival permutations. Compare timestamp conditioning, sort-then-train, and an external bitemporal oracle. Kill if the normalized write is path-dependent beyond tolerance or sort-then-train meets the same budget and retention despite an unbounded-delay fixture.
- **Retention.** Require the factual and as-known answers on both sides of the late notice and on a never-overlapping old fact.

### NP2-19 · Write the support of a rule, not every conclusion
- **Mechanism.** Represent a learned implication with its own validity and availability support. Compose it with a premise by intersecting support on *both* axes, and write the resulting operator on the rule rather than editing each derived answer individually. A rule that applied yesterday but was first published today cannot justify a prediction made yesterday.
- **Nearest art.** [TFLEX](https://arxiv.org/abs/2205.14307) embeds logical and temporal query operators for temporal graphs; [RippleEdits](https://arxiv.org/abs/2307.12976) checks consequences of edits; [EVEDIT](https://arxiv.org/abs/2402.11324) models deductive edit boundaries. The delta is a writable, independently time-scoped *inference rule* whose application survives further pretraining, not an external graph query or rehearsing its conclusions.
- **First test / kill.** Give a fictionally amended purchasing rule and a late-discovered qualifying premise with crossing support. Compare tagging the direct facts, teaching enumerated derivative edits, and a timed functional write. Kill if the latter cannot generalize its update to unenumerated compositions or the tagged control can already do so at matched data.
- **Retention.** Check old uses of the unamended rule, old true conclusions with different premises, and the earlier knowability of a conclusion that later became derivable.

### NP2-20 · Correct the meaning of a relation without rewriting its old facts
- **Mechanism.** Factor the mapping from phrasing to relation meaning from the factual assertions in that relation. A definition correction writes a new mapping over a bitemporal scope while preserving the old assertions and old mapping outside it. Teach one corrected meaning, then allow it to change interpretation of old records without rewriting every record.
- **Nearest art.** [Prompted Knowledge Cutoffs](https://arxiv.org/abs/2510.02340) probes semantic shifts as a separate category; [PRISM Edit](https://arxiv.org/abs/2607.11327) updates a subject representation across answer times. The delta is changing a *shared interpretation rule* after a late clarification, with explicit preservation of old facts rather than replacing a set of answers.
- **First test / kill.** Retroactively redefine a fictional regulation's “active” category for some validity dates. Train on one entity and test unseen old entities. Compare an edit per entity, a time-tagged definition, and a scoped interpretation write. Kill if the new meaning cannot transfer without contaminating old scopes or the tagged definition matches.
- **Retention.** Require old classification by the original wording and direct recall of all underlying old assertions, including revised entities.

### NP2-21 · Withdraw support once, not once per copy
- **Mechanism.** A claim contribution depends on distinct provenance roots, not on how many documents repeat it. Merge echoes idempotently, and remove the contribution only after all currently valid independent roots are withdrawn. Compile the small support formula into the learned write; neither an echo nor its retraction is an independent vote.
- **Nearest art.** [Provenance Semirings](https://doi.org/10.1145/1265530.1265535) distinguishes alternative and joint derivations; [ConflictBank](https://arxiv.org/abs/2408.12076) studies conflicting parametric and retrieved evidence. The delta is compiling idempotence and support withdrawal into a bitemporal weight update, not inventing provenance or deduplicating text.
- **First test / kill.** Use two sources and their syntactically different echoes; retract a root and then the other. Compare URL/content deduplication, source-tagged editing, and external provenance retrieval as oracle. Kill if an echo can keep a withdrawn claim alive or shared provenance wrongly cancels an independent valid claim.
- **Retention.** Preserve as-known answers from before either withdrawal and current answers supported by a root that never withdrew.

### NP2-22 · A correction can widen the set of admissible answers
- **Mechanism.** Make “insufficient evidence to distinguish A from B” a two-candidate support set in the writer. An adjudication narrows the set; a disclosed measurement failure can widen it without installing a replacement fact. Protect this issue from incidental edits by retaining which exclusions are licensed, not merely retaining high entropy.
- **Nearest art.** The repo's [deployment feedback DF32](https://github.com/manojbajaj95/cl/pull/352) protects unresolved comparisons; [RecencyQA](https://arxiv.org/abs/2603.16544) distinguishes recency requirements. The added operation is the inverse of time-scoped exclusion, reopening a *specific* answer previously ruled out while other exclusions remain effective.
- **First test / kill.** Start with three possible values, eliminate one through A and one through B, then invalidate only A. Compare plain abstention training, confidence regularization and timestamped editing. Kill if the operation cannot reopen exactly the associated answer on held-out questions, or an abstention baseline also retains exact support.
- **Retention.** Test historical answer sets before and after each exclusion, and facts that remain determinate throughout.

### NP2-23 · A correction delta you can apply to an answer surface
- **Mechanism.** Represent “what changing the horizon from H1 to H2 adds or retracts at valid date V” as a signed residual function. Apply it to the H1 answer surface to get H2; compose adjacent residuals without re-reading the raw reports. Require cancellation of an intermediate correction and its reversal, rather than relying on the model to describe the edits in prose.
- **Nearest art.** [DBSP](https://arxiv.org/abs/2203.16684) computes changes of views from input deltas; [TempLAMA](https://arxiv.org/abs/2106.15110) reads a fact at a time. The proposed object is an *executable learned difference* across knowability states, not two independent date-conditioned predictions or a diff over an external fact table.
- **First test / kill.** Teach only adjacent residuals in a three-horizon chronology; apply their sum between nonadjacent horizons to unseen facts sharing the rule. Compare independent timestamp-conditioned reads and weight-delta addition. Kill if composition does not carry to unseen horizons/scopes, or independently reading the endpoints yields the same control over intermediate cancellation and final outputs.
- **Retention.** Require older answers reconstructed from the inverse residual and stable facts whose residual should be identically zero.

### NP2-24 · Refine time granularity without invalidating an old write
- **Mechanism.** Write a fact over a time cell with declared semantics for every subcell, a subset, or unresolved. When finer evidence splits the cell, lift the old write only into children it logically covers. Continue supporting coarse questions via quantifier-consistent aggregation instead of training the month token to mean whichever day was seen last.
- **Nearest art.** [TimeStress](https://arxiv.org/abs/2502.01220) varies time granularity at evaluation; [TFLEX](https://arxiv.org/abs/2205.14307) offers temporal logical operators. The primitive is a *refinement of an existing parametric write* that preserves the semantics of old coarse queries without pretending their evidence fixed every new finer cell.
- **First test / kill.** Start with “some day” and “all days” old records, then expose a correction for one day. Compare hierarchical timestamps, fresh day-token training, and refinement. Kill if it treats the two old quantifiers alike or if time-tagged training without explicit refinement already preserves both coarse and fine query truth.
- **Retention.** Require old coarse conclusions with their original quantifiers and precise older days unaffected by the split.

### NP2-25 · A time-scoped exception meets its own authority
- **Mechanism.** Represent the publication and validity scope of a correction separately from the scope over which its source has authority. An exception may supersede the general claim only on the intersection of all three. Splitting a source's authority after a later audit reallocates the override to its remaining cells, not all occurrences of the exception.
- **Nearest art.** [EVEDIT](https://arxiv.org/abs/2402.11324) introduces deduction anchors for an edit's scope; [temporal databases](https://doi.org/10.1145/140979.140996) separate validity and transaction time. The candidate is a restrictive meet on *where a learned write may override another*, not a generic source priority, routing, or conflict count.
- **First test / kill.** Publish an early general rule and two later exceptions with narrower, overlapping authority. First fit their independent scopes, then change one audit and query unseen intersections. Compare latest-publication wins, source-tag-conditioned CPT, and a bitemporal retrieval oracle. Kill if the meet cannot recover the general rule outside the intersection or a fixed priority rule matches.
- **Retention.** Check old exceptions under their earlier authority and old defaults for a jurisdiction to which neither exception applies.

## C · Try to compose surviving primitives, not their machinery

### NP2-26 · A correction that commutes with a shared alphabet change
- **Mechanism.** Encode a bitemporal patch (NP2-13) as signed *byte-defined* answer effects plus protected sibling cells (NP2-01 and NP2-11). Realize the same patch before or after migrating the tokenizer, even when the new token consumes part of a date or a fact value. If either chart cannot express the patch, refusal should preserve the old fact rather than substituting a different scope.
- **Nearest art.** [Approximate Likelihood Matching](https://arxiv.org/abs/2503.20083) transfers prediction across tokenizers; [PRISM Edit](https://arxiv.org/abs/2607.11327) edits time-aware representations. The claimed operation is portable *scope and write effect* jointly; doing likelihood transfer and then a new temporal edit is the strongest simple stack.
- **First test / kill.** Merge the shared prefix of two values across a validity boundary and apply the same late correction in both orders. Match cold byte likelihood, edit success and parameter budget against separate transfer plus PRISM. Kill if protected cell responses depend on order or both controls compose without the common patch object.
- **Retention.** Require pre-publication as-known answers, older valid values, and ordinary old text affected by the merge but not by the correction.

## Ranked deeper questions

1. **Can an ordinary write factor through a new alphabet without taking its old optimizer with it?** Start with NP2-01 and NP2-02 on one safe and one lossy merge. Exhibit a minimal surviving state, then compose two migrations (NP2-03). Stop if that state is as large as the original or output distillation plus a tuned optimizer reproduces the same future trajectory.
2. **What is the smallest correction algebra that can undo one publication without rewriting time?** Combine scoped overwrite and withdrawal (NP2-13/14), then demand an arrival-order law (NP2-18). Beat PRISM with both dates available and external bitemporal retrieval at matched query semantics; the latter may win on correctness, in which case any parametric advantage must be explicit in state or latency.
3. **Can a fact writer share new reasoning while keeping evidence unavailable in the past?** Start with the report/truth split and the availability boundary (NP2-16/17), then try an old premise with a later learned rule (NP2-19). Stop if the proposed protection either leaks the later fact or blocks an old inference a simple time-conditioned model can make.
4. **Do the two invariances compose, or does a tokenizer migration change what counts as a temporal edit?** Run the small obstruction fixture in NP2-26 only after both component operators work. Require an old valid answer and an old as-known answer on opposite sides of the edit and use identical byte readouts; stop if the crossed failure is explained by ordinary cold tokenization drift.
