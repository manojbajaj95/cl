# Root: Learning from conflicting feedback after deployment

Root node (depth 0) · 32 candidate primitives · Ideas only; no experiments run

**Thesis.** A deployed learner chooses not just an answer but also which disagreement it can hear next. An edit that makes current ratings look better can eliminate the route by which a quiet user, a returning cohort, or a delayed consequence can correct that edit. Instead of carrying only a reward model and a policy, carry objects that specify what a feedback event licenses, which interventions could overturn the inference, and who retains an effective way to do so after later updates.

**Scope.** Informed by the [idea ledger](https://github.com/manojbajaj95/cl/blob/bc7efa8cd9ca0293a32a3f26993c90381fced844/reviews/idea-ledger.md), the [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md), and neighboring [sleep](https://github.com/manojbajaj95/cl/blob/devin/1795574658-root-sleep-and-dreaming/tree/root-sleep-and-dreaming.md) and [LoRA-learner](https://github.com/manojbajaj95/cl/blob/devin/1795578733-lora-learner-4/tree/root-lora-learner.md) roots/branches in the #344–#350 series. This root is about feedback acquisition, interpretation, shared decision rules, and retention through successive live updates, not a new adapter writer or skill-fork operator. It leaves aside the ledger's closed directions on self-sealing prohibitions, offline likelihood A/B of a lesson, soft endorsement pooling, and save-and-restore. A policy table, decoder, or tool-using agent can implement the same primitives; success must not depend on fitting a particular parameterization.

## Literature check

Used targeted scholarly web searches and inspected primary-source abstracts or relevant excerpts (arXiv, ACL Anthology, PMLR and publisher proceedings). Each card links the closest mechanism found in this pass; the gaps are hypotheses to check against full texts before any pilot, not priority claims.

**Shared first-test contract.** All tests below are proposals, primarily tiny enumerable streams; no collection, training, or simulation was performed. Predict or act *before* each event; log proposed and exposed actions, who could respond, feedback timing and update vintage. Compare at matched questions, exposure, state bytes and updates wherever they differ. In a simulator use an independent oracle for served utility and the correct scope of a change; don't use the training feedback as truth. Every card's retention clause uses untouched, held-out old tasks (including a quiet/minority slice when relevant), checked both before learning and after the indicated stream, with direct task success or old preference-choice accuracy. Revoked requirements are not old tasks; score them as successful changes. Reject a purported learning win if it trades away old-task retention beyond a predeclared tolerance, even if its pooled score improves. Claims about real users would require consented interventions and separate validation; no silent feedback is assumed to be assent.

## A · What did a feedback event measure?

### DF01 · Paired-world feedback certificate
- **Primitive:** Keep two observationally equivalent causal models with opposite recommended writes (e.g., a stable preference plus a biased response widget versus genuine drift). An update consumes a randomized, consented channel intervention only when its observation excludes one of the two models; otherwise commit only the part both worlds support.
- **Nearest prior / gap:** [Semantic Identifiability Frontier](https://arxiv.org/abs/2610.20450) characterizes a fixed comparison channel; [Causal Preference Learning](https://arxiv.org/abs/2506.05967) frames generalization causally. Here the witness is tied to an actual pending policy change in a changing channel, not to estimating persistent disagreement.
- **Cheapest first test:** Two actions, two matched log-generating worlds, and one randomized feedback-widget intervention. Compare action error to T-POP with the same interventions and a causal learner that commits to its most likely graph. Dead if deferring the disputed write doesn't help when the favored graph is wrong.
- **Old-task retention:** After five widget changes, test old formatting and tool-selection tasks, including a low-response cohort, with the original widget hidden.

### DF02 · Menus with transport conditions
- **Primitive:** Encode a choice as an edge indexed by the set of available alternatives. Learn the smallest context-dependent set of inclusion/exclusion conditions under which an edge transfers to another menu; a changed offer set can invalidate an edge without reversing it.
- **Nearest prior / gap:** [Choice Set Confounding in Discrete Choice](https://www.cs.cornell.edu/~kt/publication/2021-tomlinson-choice-set-confounding/2021-tomlinson-choice-set-confounding.pdf) addresses selection of the available set; [Recommendations as Treatments](https://arxiv.org/abs/1602.05352) corrects exposure bias. Neither is the proposed sparse, revisable map of which preference evidence transports when the alternatives *causally change* the choice.
- **Cheapest first test:** Three response options; introduce a third option that suppresses one otherwise stable comparison. Match random exposure across a propensity-weighted pair model and a full menu-conditioned choice model. Reject if the map gives no few-shot advantage on withheld menus.
- **Old-task retention:** Keep measuring the original two-way decision and an unrelated document-editing task after the third option is added and removed.

### DF03 · Split the recommendation effect from the survey effect
- **Primitive:** Factor an interaction into an answer and its feedback solicitation; maintain two estimates, one for the answer's effect on independent utility and one for the solicitation's effect on what gets reported. Learn a shared update only from the first; improve the feedback channel on the second.
- **Nearest prior / gap:** [Separable-effects inference](https://doi.org/10.1093/jrsssb/qkag051) separates treatment components under assumptions; [Learning from Implicit User Feedback](https://aclanthology.org/2021.emnlp-main.489/) treats response behavior as a dissatisfaction signal. The proposal uses separable control of a live interface to route learning to different actuators, even when both effects move the observed rating.
- **Cheapest first test:** Cross-randomize answer style and opt-in feedback placement in a four-cell simulator with a held-out task-success signal. Compare to a full-context preference model given both factors. Kill if the split doesn't reduce wrong-direction deployment writes at equal feedback burden.
- **Old-task retention:** Retest incumbent style choices and completion accuracy for users with the old solicitation layout after several layout swaps.

### DF04 · Release credit only when the source decision is identifiable
- **Primitive:** A late correction creates a set of feasible source decisions, plus effects common to every attribution. Update on the common implications immediately; keep disputed credit unspent until a repeat under a deliberately staggered action schedule distinguishes the sources.
- **Nearest prior / gap:** [Causal reward redistribution](https://proceedings.neurips.cc/paper_files/paper/2023/file/402e12102d6ec3ea3df40ce1b23d423a-Paper-Conference.pdf) identifies influential history for delayed rewards; [delayed dueling bandits](https://arxiv.org/abs/2605.26554) analyze delayed feedback. The proposed delayed item can have an unknown source decision, with an intervention to acquire the missing correspondence rather than forced redistribution.
- **Cheapest first test:** A two-step workflow with occasional delayed “that was wrong” notes; swap the timing of independent substeps, not the note. Compare to causal redistribution and a probabilistic attribution model with the same interventions; reject if staged credit doesn't improve wrong-step corrections.
- **Old-task retention:** After intermittent notes on new workflows, check old one-step tasks and unchanged second-step actions in unfamiliar workflows.

### DF05 · Learn a translation between feedback protocols
- **Primitive:** A calibration map between two feedback channels transports *sets of allowable decisions*, not numerical ratings. Fit it only through overlapping tasks shown in independently assigned channels; a new channel can transport the winning action but not strength of support.
- **Nearest prior / gap:** [Reward-rational implicit choice](https://proceedings.neurips.cc/paper_files/paper/2020/file/2f10c1578a0706e06b6d7db6f0b4a6af-Paper.pdf) grounds diverse feedback in a common reward by specifying choice sets. Here the system must learn which conclusions survive a channel migration without assuming a common reward scale or complete translation.
- **Cheapest first test:** Migrate from ranked alternatives to free-text edits with a handful of jointly covered cases; evaluate unseen disagreements with stage-dependent channel bias. Compare separate heads plus pooled calibration; kill if hard translation or total separation give the same migration regret.
- **Old-task retention:** Recheck old rankings, including uncommon multi-step tasks, after the rank interface stops collecting labels.

### DF06 · Carry bounds for silent users into the action selector
- **Primitive:** For every candidate action carry lower and upper utility under observationally indistinguishable nonresponse models. Spend one of a few randomly offered follow-up invitations on the stratum that can change the feasible action set, not the one with highest predicted response; retain wide bounds when the invitation cannot reach nonresponders.
- **Nearest prior / gap:** [Limited feedback and partial monitoring](https://proceedings.mlr.press/v83/ensign18a.html) finds proxy losses in a structured selective-observation problem; [Oracle-Robust Online Alignment](https://arxiv.org/abs/2602.20457) robustifies against oracle errors. Neither comparison supplies an action-specific identification region that the system can narrow by opening a feedback route.
- **Cheapest first test:** Two cohorts with identical observed approval but different unobserved error; permit an opt-in audit with known reach and bounded residual missingness. Compare robust online optimization with fixed uncertainty and standard active querying. Reject if decision-directed querying doesn't improve bound coverage or utility at equal burden.
- **Old-task retention:** After three dropout waves, test old task success in both cohorts via independent evaluation, not the responding subset.

### DF07 · Distinguish edits to today’s output from edits to tomorrow’s policy
- **Primitive:** Make “fix this output” and “learn this for me” separately elicitable actions, with a third choice to defer. Ambiguous text can improve the present outcome without granting any update. Learn when asking for persistence consent changes future treatment; never infer permission from the text alone.
- **Nearest prior / gap:** [Aligning from User Interactions](https://arxiv.org/abs/2603.12273) learns hindsight targets from continuations; [PLUS](https://arxiv.org/abs/2507.13579) supports editable profiles. The new observable is independent authorization to reuse feedback *before* construction of any training target, not another profile editor.
- **Cheapest first test:** Same correction string in one-off and durable intent worlds, with a sparse persistence-confirmation option. Against a confirm-everything arm and a hindsight learner with the same query budget, reject if the operation doesn't reduce both unwanted persistence and missed durable fixes at matched burden.
- **Old-task retention:** Test standing old preferences after a burst of authorized and unauthorized one-off corrections with identical wording.

### DF08 · Learn where a correction *stops* transporting
- **Primitive:** Store a paired witness: one near-identical case where a feedback rule applies and another where it does not, plus the context change that switches its validity. Use it to train a boundary operation that asks for the missing context variable on future near-boundary cases.
- **Nearest prior / gap:** [TRACE](https://arxiv.org/abs/2610.09107) tests refinements of latent intent constraints by generating actions that satisfy them. Here hold the action pair fixed and query whether a *previous event* applies when one context variable changes; learn when later cases require that variable, rather than just refining the candidate constraint.
- **Cheapest first test:** A formatting rule reverses only for an uncommon intended audience; contrast asking about applicability with asking for a preferred answer on the same cases. Kill if the witness doesn't transfer to held-out wording with the same audience distinction.
- **Old-task retention:** Recheck old usual-audience tasks and the original uncommon-audience tasks after adding a second scope boundary.

## B · When the deployed policy changes the teacher

### DF09 · Separate policy-induced taste from exogenous drift
- **Primitive:** Maintain two revision states: a component following change measured under an opt-in reference exposure and a component following the effect of recent advice. Do not promote the latter to an unconditional preference; expose it only in sessions with the matching exposure history.
- **Nearest prior / gap:** [Stateful Performative Prediction](https://proceedings.mlr.press/v151/brown22a.html) models state transitions; [Causal Estimation of User Learning](https://arxiv.org/abs/2306.00485) estimates user learning induced by personalization. The proposed operation moves evidence between two persistent update scopes rather than just estimating or penalizing a policy-induced shift.
- **Cheapest first test:** In two-arm streams with the same observed preference trend but opposite causes, randomize a brief reference exposure. Compare against a history-conditioned stateful learner and NS-DPO with identical samples; fail if the split cannot improve post-switch choices.
- **Old-task retention:** Check recurring older tasks when the user returns to reference exposure and unrelated skills after the novelty cycle ends.

### DF10 · Protect the chance to contradict a serving policy
- **Primitive:** Give a user-defined correction scope a reachability floor: from each protected starting context, a permitted interaction policy must elicit distinguishing evidence within a bounded horizon with at least a stated probability under the modeled response processes. A serving update that makes all such policies infeasible cannot advance.
- **Nearest prior / gap:** [Active Diagnosis](https://home.lmf.cnrs.fr/downloads/SergeHaddad/A15-CDC.pdf) already controls a partially observed system to ensure bounded detection of a fault; [Conservative Dueling Bandits](https://arxiv.org/abs/2610.36708) constrain service quality. The proposed constraint preserves the existence of an affordable diagnosis policy after *each* update, even though a separate serving policy acts in ordinary use and both user preferences and response support can change.
- **Cheapest first test:** A three-state agent can hide a user-visible setting without degrading immediate success. Compare fixed exploration, an old-utility constrained policy, and a controller with a fixed active-diagnosis policy. Kill if a reachability check cannot shorten detection of a later localized reversal at equal service loss.
- **Old-task retention:** Measure old protected and ordinary workflows under identical floor budgets before and after reopening the setting.

### DF11 · Learn a cohort-to-cohort interference footprint
- **Primitive:** A local write records which other cohorts' *future evidence streams* it changes via shared artifacts or tools. Use that footprint to decide which cross-cohort observations are descendants of the same intervention and which may justify independent promotion.
- **Nearest prior / gap:** [General Interference](https://arxiv.org/abs/1305.6156) uses exposure mappings for effect estimation; [Online Experimental Design Under Network Interference](https://arxiv.org/abs/2412.03727) allocates experiments under spillovers. The proposed footprint is a learned write-time object for deciding whether apparently independent feedback really corroborates a second policy change.
- **Cheapest first test:** Two teams use separate prompts but a shared editable template. Randomize a local change and mask propagation in a comparison arm. Reject if learned footprints don't prevent more false promotions than cluster-level updates with equal interventions.
- **Old-task retention:** Repeat old jobs in both teams with and without the shared template after a local correction propagates.

### DF12 · Supersede by event time, not arrival time
- **Primitive:** Store a partial order of decision and effective times for feedback, and compile competing revisions into a policy that is invariant to delivery order whenever their applicability windows do not overlap. For ambiguous windows, request the intended effective boundary rather than averaging the changes.
- **Nearest prior / gap:** [NS-DPO](https://arxiv.org/abs/2407.18676) reweights samples backward in time; [Delayed Dueling Bandits](https://arxiv.org/abs/2605.26554) account for delayed observations. The target is the semantics of overlapping revisions, not weighting old observations or reducing stale-feedback regret alone.
- **Cheapest first test:** Mix revision commands and ordinary preferences for recurring tasks; permute arrival times across identical effective histories. Compare with event-time sorting and piecewise drift models. Kill if explicitly eliciting the boundary provides no benefit in histories with overlapping times.
- **Old-task retention:** Revisit old recurring tasks whose window remains in force, plus ordinary tasks that never entered a revised window.

### DF13 · Learn which comparisons leave the preference unchanged
- **Primitive:** Store an intervention footprint for each query family, estimating its immediate evidence value and its delayed effect on what people prefer. Route repeated measurement through query families that retain information while shifting later independent choices least; do not treat stability of answers to the same question as neutrality.
- **Nearest prior / gap:** [Estimating and Penalizing Induced Preference Shifts](https://arxiv.org/abs/2204.11966) targets recommender-induced shifts; [Active Preference Learning](https://arxiv.org/abs/2602.01581) optimizes acquisition. Here query wording or contrast exposure is itself the intervention, and the learner chooses a substitute measurement instrument, holding the serving policy fixed.
- **Cheapest first test:** Two equally informative query families, one changes future choices through anchoring. Assign question families randomly, measure later choices through a common held-out task, compare with entropy querying plus a generic shift penalty. Kill if the reusable footprint fails under a new elicitation budget.
- **Old-task retention:** Check pre-existing style preferences and unqueried tool tasks after repeated elicitation.

### DF14 · Reference branches with explicit washout
- **Primitive:** Annotate feedback-backed updates with the shortest supported washout needed before a reference branch becomes informative. Distinguish a learner-state reset from a return to a reference user-exposure distribution; if the latter is unavailable, prohibit a long-horizon equivalence claim.
- **Nearest prior / gap:** [Design and Analysis of Switchback Experiments](https://doi.org/10.1287/mnsc.2022.4583) estimates effects under carryover; [Stateful Performative Prediction](https://proceedings.mlr.press/v151/brown22a.html) recognizes stateful deployment. Here carryover bounds control which live feedback counts toward retiring or reinstating a prior behavior, rather than just how a one-off experiment is analyzed.
- **Cheapest first test:** Subjects in a simulator recover after zero, two, or five baseline exposures; mix quick and slow groups. Compare against a fixed washout switchback and a stateful model with the same exposures. Reject if learned admission rules don't resolve more reinstatement decisions without false equivalences.
- **Old-task retention:** Test old baseline tasks after each reinstatement decision, separately from recovery of the simulated exposure state.

### DF15 · Distinguish an unavailable correction from a rejected one
- **Primitive:** Maintain a reachability map for the sequence “see behavior → reach correction surface → submit correction → learner receives it.” Intervention on one link produces a different uncertainty update than upstream silence, even if both yield zero complaints.
- **Nearest prior / gap:** [Implicit User Feedback](https://aclanthology.org/2021.emnlp-main.489/) uses abandonment and interruption as signals; [Recommendations as Treatments](https://arxiv.org/abs/1602.05352) corrects for exposure. The map represents serial failure of evidence delivery, enabling targeted repair before policy retraining.
- **Cheapest first test:** Toggle feedback access independently of task suitability in a two-surface stream with opt-in delivery confirmation. Compare to propensity correction on final ratings plus an abandonment classifier; fail if the map cannot localize which link to fix out of distribution.
- **Old-task retention:** Recheck old jobs through both surfaces, including jobs where the correction surface was already accessible, after targeted repairs.

### DF16 · Keep the ability to learn after an interface migration
- **Primitive:** Before changing an interface, certify that its collection of feasible interventions separates every currently identified pair of rival updates that matter to service; when it doesn't, carry forward a specific bridge intervention rather than generic legacy logging.
- **Nearest prior / gap:** [Partial monitoring](https://proceedings.mlr.press/v83/ensign18a.html) relates feedback observability to regret; [Semantic Identifiability Frontier](https://arxiv.org/abs/2610.20450) identifies what comparison channels reveal. The operation preserves decision-relevant observability *across a migration* rather than classifying one game or channel.
- **Cheapest first test:** Remove a feedback control while adding two replacements; only one separates the two corrections that matter. Compare utility-matched UI migration and preservation of the most-used signal. Reject if the certificate doesn't predict later revision latency on unseen changes.
- **Old-task retention:** Score old successful flows and old opt-in correction flows before and after migration; retain both task success and the ability to fix the longstanding task.

## C · How should different users' feedback combine?

### DF17 · Carry a minority counterexample across a global update
- **Primitive:** Let a scoped user objection bind a witnessed action/context pair to a counterexample that the next policy must still handle. Transfer the obligation to a new workflow only if a fresh witness shows the same failure mechanism; do not give the user a veto over unrelated behavior.
- **Nearest prior / gap:** [MaxMin-RLHF](https://arxiv.org/abs/2402.08925) protects worst-group reward and [representative social choice](https://www.jair.org/index.php/jair/article/view/17524) studies sampling people and issues. Here the carried object is a falsifiable, repairable claim about a behavior that can be inherited when its old surface disappears, not just weight or standing veto power.
- **Cheapest first test:** One rare critical workflow appears in two interfaces under different names. Compare equal-size rare-case replay plus MaxMin to witness transfer under one interface replacement. Kill if replay alone covers the held-out successor workflow equally well.
- **Old-task retention:** Recheck the original rare workflow, and ensure a majority task that legitimately uses the objected-to action still works.

### DF18 · Mark cycles that require the same people to be present
- **Primitive:** Attach each learned preference cycle to the co-presence conditions under which its edges can all be supported in the same decision population. If a cycle disappears when the edge-specific participation bias is removed, do not randomize the policy on the strength of that cycle.
- **Nearest prior / gap:** [HRC/DSPPO](https://arxiv.org/abs/2605.17342) explicitly separates transitive and cyclic preference components and optimizes a dynamic Nash game; [Nash Learning from Human Feedback](https://proceedings.mlr.press/v235/munos24a.html) already handles nontransitivity. The claim is about cross-edge support for the game induced from live feedback, not a better decomposition or Nash solver.
- **Cheapest first test:** Compare an authentic Condorcet cycle with a cycle made from edge-dependent response panels with the same marginals. Run a small shared-panel audit and compare to HRC plus edge propensity weights. Kill if the support check cannot avoid spurious mixing without discarding real cycles.
- **Old-task retention:** Check old transitive tasks and a genuine old cyclic coalition on independent shared-panel responses after the panel composition shifts.

### DF19 · Learn the boundary of a joint decision
- **Primitive:** Represent a learned rule as an assignment of decision rights to affected parties. A policy may personalize a private presentation, but a requested change to a shared artifact triggers a joint decision; learn the boundary from interventions that separate consumption from downstream exposure.
- **Nearest prior / gap:** [GateMem](https://arxiv.org/abs/2606.18829) evaluates given contextual authorization boundaries; [network interference](https://arxiv.org/abs/1305.6156) identifies spillovers. Given a fixed governance rule, the operator learns when a preference edit crosses the exposure boundary that triggers joint authorization, even if its author is allowed to edit the artifact.
- **Cheapest first test:** A two-user editor serves private views and a shared export; feedback becomes contradictory only for exported content. Compare against a scope-tagged mixture and an always-consult protocol, given identical observations. Reject if intervention-learned authority fails to improve consent violations at equal consultation burden.
- **Old-task retention:** Retest each user's old private formatting tasks and the team’s unchanged shared export requirements.

### DF20 · Reserve representation for users who return
- **Primitive:** Represent a quiet cohort by a time-indexed right to reopen specified decisions on its return, not by stale votes counted as perpetual approval. Spend tentative deployment scope in its absence; reclaim only the portion that would otherwise foreclose its later input.
- **Nearest prior / gap:** [Representative Social Choice](https://www.jair.org/index.php/jair/article/view/17524) samples individual–issue pairs; [sleeping-expert subgroup fairness](https://doi.org/10.4230/lipics.itcs.2020.55) activates comparators by subgroup. The new object is a future revision claim that persists even when the corresponding users and rewards are absent.
- **Cheapest first test:** Simulate alternating shifts in a shared workflow with a hard-to-undo default and matched exposure. Compare against recency weighting and fixed group weights. Kill if staged deployment doesn't improve worst-shift regret without delaying reversible improvements.
- **Old-task retention:** Measure returning users' routine work and stable always-present users' tasks on the first day of each return.

### DF21 · Learn which concessions actually remove conflict
- **Primitive:** Store conditional trade witnesses of the form “group A accepts B's choice on field x if A retains field y.” Test each witness under a paired change; compose only trades with no overlap in the concessions used as evidence.
- **Nearest prior / gap:** [Multi-objective preference optimization](https://arxiv.org/abs/2505.10892) learns across objective weights; [differentiable social choice](https://arxiv.org/abs/2602.03003) surveys learned decision and aggregation mechanisms. A trade witness is a reusable cross-party counterfactual on separately editable fields, not a learned utility vector or a pooled Pareto sweep.
- **Cheapest first test:** Two parties negotiate three independent fields in a shared report, then face a held-out combination with one overlapping concession. Compare to weight-conditioned optimization and joint-choice modeling at equal comparisons. Kill if isolated trades don't reduce queries or if composition violates accepted terms.
- **Old-task retention:** Repeat old report agreements and unrelated individual requests after several trade witnesses are composed.

### DF22 · Split support for a trial from support for a default
- **Primitive:** Keep separately elicited ballots for “try once” and “make this the standard.” A trial ballot opens evidence collection but cannot be counted as durable support; a default promotion requires its own observations from each affected scope.
- **Nearest prior / gap:** [Conservative Dueling Bandits](https://arxiv.org/abs/2610.36708) protect baseline exposure while exploring; [pairwise calibrated rewards](https://arxiv.org/abs/2506.06298) represent preference mixtures. Here exploration and permanent changes are different objects of preference even if the offered outputs are identical.
- **Cheapest first test:** Generate users who accept a novel answer format at trial but object to its repeated use. Compare repeated-rating and two-horizon utility models at equal prompts. Reject if explicitly eliciting promotion support fails to improve persistent-choice accuracy at the same experiment count.
- **Old-task retention:** Test retained default tasks after trials and after actual promotions, and score old one-off overrides separately.

### DF23 · Weight evidence without weighting the right to decide
- **Primitive:** An observation carries two independent quantities: reliability about an empirical outcome and authority over a collective preference. Use separate counterfactual tests to update one without silently changing the other.
- **Nearest prior / gap:** [MiCRo](https://aclanthology.org/2025.emnlp-main.882/) resolves ambiguity by online mixture routing, and [Social Choice Should Guide AI Alignment](https://arxiv.org/abs/2404.10271) makes aggregation normative. The proposed operator stops competence evidence (e.g., being good at detecting rendering errors) from leaking into whose preferences control the shared rule.
- **Cheapest first test:** Give a reliable evaluator a minority formatting preference and swap reliability midway without shifting tastes. Compare against a multi-head model using a shared evaluator weight and a hand-coded separation. Kill the learned operator if it can't transfer the distinction to a new skill at equal supervision.
- **Old-task retention:** Recheck both old error-detection and old collective-choice tasks after the swap. A rise in one can't compensate for loss in the other.

### DF24 · Feed disagreements about the rule back to a separate learner
- **Primitive:** Route explicit complaints about the aggregation rule to a revision state for that rule, not as new votes on the answer it happened to select. Use identical outcome pairs under alternate disclosed decision rules to distinguish outcome dislike from procedural objection.
- **Nearest prior / gap:** [Differentiable Social Choice](https://arxiv.org/abs/2602.03003) covers learning aggregation mechanisms; [Nash Learning](https://proceedings.mlr.press/v235/munos24a.html) turns comparative outcome preferences into a policy. The new feedback channel identifies a preference over *procedures at fixed outcomes* and cannot rewrite existing first-order votes.
- **Cheapest first test:** Simulate two panels that agree on action rewards, but one rejects a default set without its input. Compare a full-context outcome learner and a fixed procedure at the same consultation count. Reject if explicit rule feedback doesn't improve adoption of the right rule on fresh issues.
- **Old-task retention:** After a rule revision, measure old individual tasks and old joint tasks where the revision was not authorized.

## D · How can we keep learning without silently losing old capabilities?

### DF25 · Carry a conditional guarantee from an old task into a new one
- **Primitive:** Attach an old-task guarantee to a behavioral precondition and a failure witness, not a task label. Use a deliberately transformed pair of tasks to test whether the guarantee transfers before routing a new correction through the same shared policy.
- **Nearest prior / gap:** [Safe Policy Improvement in Constrained MDPs](https://arxiv.org/abs/2210.11259) constrains explicit safety costs; [Invariance and Partial Identifiability](https://proceedings.mlr.press/v202/skalse23a.html) studies what reward differences are policy-relevant. Here the learner tests where an old constraint remains meaningful on a novel workflow before it admits a write.
- **Cheapest first test:** An old workflow's confirmation step matters only for irreversible actions. Introduce a novel reversible action and an irreversible lookalike. Compare fixed canaries plus a generalized risk classifier; kill if a transferred conditional guarantee doesn't retain safety with less needless blocking.
- **Old-task retention:** Run held-out old irreversible and reversible tasks after the new behavior is learned, measuring confirmation and successful completion.

### DF26 · Charge repeated updates for the same untested skill exposure
- **Primitive:** Record the union of old decision regions that successive updates may perturb, together with the unresolved uncertainty of their *joint* effect. Route audits to distinguish cumulative drift from repeated harmless movement on the same probe before permitting another overlapping write.
- **Nearest prior / gap:** [Anytime-valid off-policy inference](https://arxiv.org/abs/2210.10768) supports sequential evaluation under adaptive logging; [Soft Baseline Bootstrapping](https://arxiv.org/abs/1907.05079) constrains actions with uncertain estimates. Here two changes can invalidate a prior approval only in their overlap; the object is the outstanding joint audit obligation across candidate vintages, not a confidence bound per vintage.
- **Cheapest first test:** Ten small updates near two old policy boundaries; inject matched pairs whose isolated changes look equally safe but whose composition differs. Compare fresh per-edit tests and cumulative endpoint checks with equal audits. Kill if overlap tracking cannot predict damage earlier without excessive false stops.
- **Old-task retention:** Evaluate both old boundary tasks and interior cases after the tenth update at a matched new-task improvement rate.

### DF27 · Test recovery of a preference without storing the old answer
- **Primitive:** Store a minimal, randomized *distinguishing query* between an old preference and its nearest rival. After a recurring context returns, use its answer to re-identify the active regime; score how much knowledge is recoverable with a fixed query budget rather than whether the old policy can be reloaded.
- **Nearest prior / gap:** [Recall or Relearn?](https://arxiv.org/abs/2610.36585) uses mixtures of in-context experts for recurring drift; [Strongly Adaptive Online Learning](https://arxiv.org/abs/1502.07073) competes on intervals. Here retention includes the ability to disambiguate an old behavior from a plausible new rival even when the old decoder or output is gone.
- **Cheapest first test:** Recurring preferences over action outcomes, with new paraphrases and action names after each return. Match state and query budgets for expert recall plus active querying. Kill if contrast-specific queries do not accelerate relearning under returns with altered surface forms.
- **Old-task retention:** Score ordinary old skills with no extra query, then old returning preference tasks after exactly one distinguishing query; report both.

### DF28 · Learn the failure boundary of a claimed retention proof
- **Primitive:** Alongside a probe suite, keep an adversarial pair of updates that pass the same probes but differ on an unseen old task. Learn to select a replacement probe that separates the pair; stop accepting proofs derived from the old suite until the witness is resolved.
- **Nearest prior / gap:** [Reusable Holdout](https://doi.org/10.1126/science.aaa9375) controls adaptive reuse of a fixed evaluation sample; [Invariance and Partial Identifiability](https://proceedings.mlr.press/v202/skalse23a.html) relates observations to policy equivalence. The probe change here targets the behavioral equivalence class that an audit cannot distinguish, even if its estimates are statistically perfect on the measured tasks.
- **Cheapest first test:** Enumerate small policy edits; construct pairs tied exactly on visible canaries but distinct on a hidden old-task partition. Compare independent random rotation and worst-loss probe selection at equal tests; kill if the witness selection fails to generalize to unseen edit families.
- **Old-task retention:** Use a third sealed old-task split, never used for finding the witness or the new probes, after successive live writes.

### DF29 · Retain both behaviors and their precedence
- **Primitive:** Treat precedence between two simultaneously applicable requirements as an independently auditable relation. A change to one requirement can preserve both rules in isolation but must revalidate their joint decision at the old intersection.
- **Nearest prior / gap:** [Objective-Conditioned Active Preference Learning](https://arxiv.org/abs/2611.05506) queries individual objectives, and [multi-objective preference optimization](https://arxiv.org/abs/2505.10892) conditions on tradeoffs. This object records which requirement prevails specifically at an old intersection and carries its audit obligation into subsequent online updates, rather than treating individual retention as joint retention.
- **Cheapest first test:** Independently teach “be concise” and “include all fees”; then revise only the length requirement. Compare to old-task replay with conjunctions and a lexicographic-rule learner at equal memory and audit budget. Reject if tracking touched intersections doesn't outperform uniform joint rehearsal.
- **Old-task retention:** Test old single-constraint and combined-constraint billing tasks separately, plus unrelated calculation accuracy.

### DF30 · Match a retention check to the user distribution before the edit
- **Primitive:** Maintain a protected evaluation target fixed to pre-edit task/cohort composition; track a second estimate for post-edit responders. If retention is not identified under changing participation, the learner reports a gap and invokes a separate audit, rather than substituting ratings from whoever stayed.
- **Nearest prior / gap:** [Covariate-shift robust off-policy evaluation](https://arxiv.org/abs/2401.11353) evaluates shifted context distributions, and [performative power](https://arxiv.org/abs/2203.17232) studies induced distribution change. Here disagreement between two targets controls a specific retention decision, with no guarantee claimed for unreachable old users.
- **Cheapest first test:** A new preference update raises observed approval by inducing dropout of low-approval users. Match independent outcome observations across rolling OPE, fixed stratified evaluation, and the dual-target audit allocator. Kill if adaptive separation offers no audit efficiency or fails with modest remaining nonresponse.
- **Old-task retention:** Evaluate direct success for a consented pre-edit task/cohort panel and report the live-cohort estimate separately after dropout.

### DF31 · Invalidate corroboration when its source is withdrawn
- **Primitive:** A deployed correction may change which users see the action and thus produces apparent new corroboration. After feedback is withdrawn, mark downstream corroboration by whether it could have been obtained under an admissible alternative exposure history; use only a fresh independent witness to close a gap.
- **Nearest prior / gap:** [Exact Unlearning in Reinforcement Learning](https://arxiv.org/abs/2606.04182) and [Counterfactual Certification for Sequential Unlearning](https://arxiv.org/abs/2610.17993) cover deletion and sequential guarantees. This is a narrower *evidence-admissibility* operation when exposure or user state cannot be reset, not exact deletion of real-world consequences or checkpoint replay.
- **Cheapest first test:** An early correction drives all later comparisons toward one action; revoke it and vary whether later support would survive reference exposure. Compare sample deletion and complete retraining from surviving logs with equal chances to recollect feedback. Kill if the admissibility rule cannot retire unsupported changes without discarding independent support.
- **Old-task retention:** Retest unrelated old tasks and one old decision with independent evidence after the withdrawal and reacquisition period.

### DF32 · Preserve the previously unanswered question
- **Primitive:** In a region where old evidence left two actions incomparable, carry a noncommitment constraint: no shared write may silently resolve the comparison without a new overlapping witness, even if scores on all labeled old tasks remain unchanged.
- **Nearest prior / gap:** [Partial Identifiability in Reward Learning](https://proceedings.mlr.press/v202/skalse23a.html) describes equivalent rewards under fixed feedback; [Semantic Identifiability Frontier](https://arxiv.org/abs/2610.20450) derives ambiguity within comparison channels. The proposed invariant tracks old *decision-relevant unknowns* through a stream of writes and permits unrelated evidence to resolve them only if it covers the old comparison.
- **Cheapest first test:** Train from disjoint conflicting contexts with two unlabeled old comparisons. Stream corrections for a third context; compare principled uncertainty masking and a static abstention rule at matched labeled-task accuracy. Reject if the invariant doesn't preserve calibration on the old unknowns or slows resolution after real overlap appears.
- **Old-task retention:** Test labeled old tasks normally, and check that old ambiguous tasks still elicit the appropriate choice or question on both genuinely unresolved and later-resolved cases.

## Ranked deeper questions

1. **Can a policy preserve reachability of disconfirming feedback without paying permanent exploration cost? (DF10, DF15, DF16)** Characterize the weakest reachability requirement that bounds time to detect a localized preference reversal under partial observability. Start with two indistinguishable feedback processes where static exploration maintains marginal choice support but loses the only accessible correction path. Drop the direction if a matched constrained bandit can guarantee the same detection time and old-task utility.
2. **When can we tell genuine preference drift from drift the learner caused? (DF01, DF03, DF09, DF13, DF14)** Derive identification and impossibility cases for the smallest separable answer/solicitation intervention with carryover and nonresponse. The prize is a decision about which updates are warranted under which interventions, with a test against a history-conditioned stateful learner. If interventions only work with unrealistic washout or universal participation, retain bounds, not point estimates.
3. **What should count as independent corroboration after deployment changed the evidence stream? (DF11, DF18, DF31)** Develop a test for when exposure-dependent feedback can authorize a shift in collective policy, or when fresh evidence is needed. Compare to interference-aware estimation and sequential retraining under matched fresh-feedback budgets; score preservation of independently supported old decisions after withdrawal.
4. **Can retention preserve the ability to disagree later, not just the old answers? (DF25, DF28, DF29, DF32)** Ask whether an old-task audit can distinguish preservation of current outputs from preservation of their conditional obligations and unresolved comparisons. Construct versions with identical visible old accuracy but different behavior after one conflicting update; require a small reusable witness set to predict which old duties break.
