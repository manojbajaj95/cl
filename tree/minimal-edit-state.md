# Node: what state predicts every future edit?

Parent: [Weights edit algebra, question 1](https://github.com/manojbajaj95/cl/pull/88). This develops [expanded top-10 #2](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-top10.md), not a second proposal for the quotient itself. Candidate primitive: a **live edit state** that a learner can update, erase from, or migrate without losing distinctions needed by future edits and old tasks.

## Root cause: a frame is not a state

PR #88 correctly rejects the additive-delta shortcut: fixed displacements can commute while the protected behavior depends jointly on them. Its replacement, a retention-closed action on \(q(s)\), still needs a way to determine and maintain \(q\). Matching current outputs, one-step edit efficacy, or even a sampled response matrix can merge checkpoints whose later edits read different information. Then the next compressed state is not a function of the current compressed state and request. More compute for that predictor cannot fix an aliased input. Conversely, carrying all weights and editor metadata avoids aliasing but establishes no useful compression.

Even identical functions with identical current loss and margins can diverge. Take two readouts \(\mathrm{new}=uv,\ \mathrm{old}=uv+b\), with \(b=0\) and \((u,v)=(1,1)\) or \((2,\tfrac12)\). Both readouts initially equal 1. One simultaneous gradient step at learning rate 0.1 on \(\tfrac12(uv-2)^2\) sends the old readout to 1.21 or 1.435, respectively. At an old-drift limit of 0.3, only the first passes. There is no optimizer history in this example. The difference comes from the implementation of the edit, not the task spec: a separate update to \(b\) could compensate. Thus output-equivalence of the host does not entail edit-equivalence, and minimizing a given implementation is different from designing an implementation with fewer future distinctions.

## What “smallest” means

Fix reachable full states \(s\), an edit vocabulary \(A\) (including optimizer steps if allowed), and observations \(O(s)\): protected and live readouts, with a separate reference for intentional supersessions. Record admission/rejection as a visible event; model rejected requests as explicit transitions rather than dropping them from the test. The full state includes any mutable guard, optimizer, data cursor, or editor memory consulted by these actions. The public task targets, initial state, and allowed action descriptors are declared side information, not free storage for the learner's history.

For a fixed deterministic implementation, two states are equivalent exactly when every finite request string, including the empty string, yields the same observation trace and admission events. This is a right congruence: prepending request \(a\) to every distinguishing suffix proves that two equivalent states remain equivalent after \(a\). Hence the class is sufficient and any exact recursively updatable summary must refine it. From a fixed start this also induces the Nerode equivalence on **prefix histories**; it is not automatically a two-sided algebra of reusable edit commands on every base. With randomized edits, choose between equality of observable laws under every allowed adaptive request policy and equality for shared externally supplied seeds; those are different contracts. In the law case, a quotient on *fully observed latent checkpoints* needs extra conditions for a class-to-class stochastic transition kernel; observable-history predictive states or belief states are the safe starting point.

**Exact CPU oracle.** For always-admitted affine edits \(E_a(z)=M_a z+b_a\) and linear observation \(Cz\), close the row span of \(C\) under right multiplication by every \(M_a\). Equivalently, take the span of all \(C M_w\) for suffixes \(w\). If \(B\) is a basis of this span, \(q=Bz\) is sufficient: \(BM_a=F_aB\), giving \(q'=F_aq+Bb_a\), and \(Cz\) is readable from \(q\). A difference outside \(\ker B\) is detected by at least one suffix because the generating rows span \(B\). This rank gives the smallest number of **linear** coordinates on an unrestricted real state domain, not the minimum bit rate of a nonlinear encoding on restricted reachable states. This is switched-system observability, a control, not a CL novelty claim. In an \(n\)-bit register with one visible bit and always-legal shift-and-load edits, the current readout sees one bit, while a long enough suffix reads any bit. If all configurations are reachable, the quotient needs \(n\) bits even though only one is visible now. A different alphabet, such as one that cannot expose the register tail, changes that answer.

**Useful is harder than exact.** Pairwise “within \(\epsilon\)” is not a partition: \(0, 0.75\epsilon, 1.5\epsilon\) form a chain but the endpoints disagree. Use certified cells or an explicit prediction-error envelope, report horizon and coverage, and check the floor against the original targets. For a real learner, ask for an incrementally maintainable rate–distortion tradeoff at equal current-task success, old-task retention, and accepted-request coverage. A positive finite-depth result is not evidence of unbounded closure without an invariant or a stated tail bound. Do not charge the baseline for full weights while letting a supposedly tiny candidate secretly read the same weights or replay the same edit history; report full-model-plus-index and standalone-summary regimes separately.

Treat those as inputs or controls. The cards below ask how to **change, maintain, or spend** edit state, not just discover its classes.

- Effect-class distillation lost to execution-reward replay; no endpoint hash or distillation-only win. Match replay and prefix memorization at equal bytes and actual executions.
- Gramian plasticity reserve and pre-edit capacity forecasts did not survive their strong controls. Use a closure oracle for the exact affine toy, not a Gramian scalar as a neural claim; match readiness, edit norm, and per-item margin where applicable.
- Functional syndromes failed when old damage was diffuse. No assumption of sparse damage; report worst-group differences as well as means.
- Finite-state test-string discovery, predictive state representations, and bisimulation are prior machinery, not novelty evidence. The deltas in the cards are hypotheses, not a literature clearance.

**Shared first-test rule.** All proposals are unranked and CPU-first. Hold out whole prefixes, suffix families, and seeds rather than random cells from the same history table. Recheck untouched base tasks and still-live edits on disjoint inputs after every actual committed step (and after delayed recurrence where named); never count a legitimate supersession as forgetting. Count all persistent bytes, including optimization state, side metadata and archived recovery material, and charge probes, resets and forks. Report false-safe rate, new-task efficacy/latency and admission coverage together so rejecting or skipping edits cannot win. Separate oracle diagnostics from experiments with a learned host.

## Raw ideas

### A. Change what counts as state when the edit vocabulary changes

1. **Alphabet upgrades with a minimum migration message.** **Mechanism:** before discarding the old representation, compute which old-class siblings a new request family separates. For one exact, known upgrade, send a residual class index within each old class; when several destinations can request different refinements and share a message, color a graph linking pairs that any destination must separate given its old summary. **Why it might be new:** a measurable information price for adding an edit capability, not another clustering pass. **First test:** enumerate 32 states and three upgrades; compare exact minimum messages against the union of per-upgrade indexes and an equal-byte edit log. **Old-task check:** run pre-upgrade old and live checks after mixed old/new requests, not just after migration.

2. **Upgradeable summaries with a fallback question.** **Mechanism:** when a new edit exposes a distinction the current summary cannot recover, use the cheapest authorized yes/no query to a surviving teacher or evidence source; maintain the answer in future state or return “unidentified” if no such source exists. Route queries by the number of future edit distinctions they resolve. **Why it might be new:** the question restores a missing state coordinate for repeated edits, not permission for one write. **First test:** add an edit family after compressing a toy learner with omitted latent task bits; compare adaptive questions with random questions and selective replay at the same budget. **Old-task check:** score all valid historic rules after later requests that reuse the recovered bit; charge unanswered cases to coverage.

3. **State erasure with a blocked re-entry.** **Mechanism:** retire a coordinate and remove every edit port that could reveal it until a new lesson explicitly reconstructs or re-specifies it; enforce the restriction in the executor, not in the evaluator. **Why it might be new:** retirement is a paired irreversible data operation and reversible capability change, not merely eviction or a proof that a coordinate will never be used. **First test:** alternate dormant and active rewrite families on a finite learner; compare byte-matched LRU/replay and a permanent ban at matched admission. **Old-task check:** exercise unrelated base tasks during the ban and old cross-family behavior after re-entry; a silently accepted stale response fails.

4. **Edit grammar as a compactness knob.** **Mechanism:** synthesize a request protocol that forbids only combinations responsible for blowing up state; choose the grammar jointly with the quotient under a minimum coverage constraint on useful requests. In the oracle, minimize the product of control state and learner state, then compare it with neural approximations. **Why it might be new:** it trades degrees of freedom in the API for state bits while preserving individual capabilities, rather than quantizing weight directions. **First test:** search tiny two-stage curricula where each individual edit is legal but certain interleavings expose a growing history; compare to a same-coverage static blacklist. **Old-task check:** check base and live tasks on each admitted sequence and count refused recurrences separately.

5. **Lens upgrades that preserve old edit scripts.** **Mechanism:** design an encoder migration \(T\) and a request translation \(\tau\) that satisfy \(T F_a=F'_{\tau(a)}T\) on reachable summary states for the older vocabulary, while newly added edits can use extra coordinates. The migration fails if the extra bits cannot be initialized from declared sources. **Why it might be new:** the compatibility unit is an executable edit interface, not just a checkpoint that matches old answers or a translated receipt. **First test:** move a 16-state editor between two redundant factorizations; hold out old edit words and compare output-matched and edit-intertwined migrations. **Old-task check:** evaluate original targets and older requests after both migrations and interleaved new edits (within their declared scopes).

6. **Counterfactual storage bills for advertised ports.** **Mechanism:** estimate the incremental state bits needed when each edit port is included or removed via recomputed exact quotients (toy) or held-out compression curves (learner). Charge ports for their joint growth, not the bytes of their own code. Select ports under the same useful-request coverage floor. **Why it might be new:** the price of an interface is memory it makes distinguishable even when the port is idle. **First test:** design two ports whose individual memory bills are low but whose alternating calls expose a latent register; compare joint port selection to a marginal-cost chooser. **Old-task check:** verify no protected outputs or still-live lessons are lost on common accepted scripts and report dropped valid requests.

### B. Design the learner to have a smaller state, not just a better predictor

7. **Synchronizing consolidation.** **Mechanism:** learn a short, legal sequence of updates that maps many post-learning histories to one edit class without deleting any live target. Require measurable contraction of classes or bytes, not just a lower output penalty; in a finite toy check the resulting class by exhaustive suffixes. **Why it might be new:** this is an edit program that actively removes future history dependence, unlike passive storage compression. **First test:** learn two overlapping tasks on a width-8 network, build margin-matched twins, and compare a learned synchronizer to reset-and-replay at equal calls and to output-distilled consolidation. **Old-task check:** retain both tasks throughout the allowed consolidation window and after unseen third-task edits.

8. **Choose the write by successor code length.** **Mechanism:** when multiple writes meet the same new/old contract, prefer the one whose successor can be maintained with the shortest verified live-state code; compare one-step and look-ahead versions. **Why it might be new:** the editor optimizes the compressibility of its *future action interface* rather than sparsity of the current delta or reserve rank. **First test:** select among equal-success writes to the same tiny nonlinear host; compare to smallest delta, optimizer readiness and replay at matched margins/norm. **Old-task check:** retest original and live targets through delayed random and separating edits, with the same edit coverage.

9. **Force forgotten coordinates to be unreadable.** **Mechanism:** train the edit compiler against randomized discarded latent coordinates and enforce with a sandbox that future requests can access them only through the live summary. In one arm also prevent indirect reads via activations the dropped coordinates influence. **Why it might be new:** creates enforceable unobservability instead of fitting a predictor that still relies on the host for hard cases; useful if a large inference model remains deployed. **First test:** mute a learned residual channel in a tiny two-head editor. Compare to a bottleneck with unrestricted compiler reads and to masking alone. **Old-task check:** use disjoint old examples after real held-out commits, including ones that rely on the residual for inference.

10. **Learn a stateless replacement for one hidden subsystem.** **Mechanism:** find where two identically observed states separate (e.g., momentum versus weight geometry), then replace just that subsystem with an editor derived from the current live state. Require continued learning to reproduce task-level effects, not bitwise optimizer updates. **Why it might be new:** the replacement is selected for how many continuation distinctions it removes, not improved optimizer speed. **First test:** replace momentum only in an interleaved two-task linear/MLP stream and compare to blanket resets and same-byte projected-moment sketches; measure remaining distinctions at matched gain. **Old-task check:** track earlier tasks after each update, especially a recurrence with reversed gradient sign.

11. **Coalescence as an extra action target.** **Mechanism:** offer a request “make these two independently trained histories exchangeable under this repertoire” with side constraints on their shared live behavior. Learn a symmetric repair that updates both rather than distilling either toward the other. **Why it might be new:** the target is a relation between two learners' future responses, not current output agreement or teaching a pre-existing simulator. **First test:** start three function-matched tiny networks in unlike parameterizations; train on paired repairs and test on the held-out pair under shared suffixes. Compare to independent canonicalization and one-way distillation. **Old-task check:** check both hosts on original and live examples before repair and throughout the common continuation.

12. **Minimum-state editor synthesis from nondeterministic specs.** **Mechanism:** specify each semantic request by the set of outcomes that satisfy its contract; synthesize a small deterministic machine that picks a valid effect for every reachable request rather than imitating a fixed optimizer. Train a dense host to realize that machine's transitions afterward. **Why it might be new:** separates necessary task memory from incidental differences between valid implementations; the target is a new compiler object, not a smaller copy of a particular optimizer. **First test:** brute-force a small finite multi-task spec with multiple permissible effects, then compare its oracle to compressing SGD and to an equal-state routed baseline. **Old-task check:** require every admitted oracle and learned transition to preserve all protected/live obligations on held-out inputs; report new-edit coverage against the larger editor.

### C. Make the state update itself a budgeted operation

13. **On-demand state materialization.** **Mechanism:** let the summary store handles for editable coordinates that can be reconstructed by a declared bounded query; explicitly choose between storing the coordinate and paying the query on future requests. Track information lost when the evidence source changes. **Why it might be new:** a random-access representation of future edit state with a latency–bytes frontier, not a store of prompts reused for ordinary inference. **First test:** split a tiny MLP's edits into hot and rare families; compare lazy reconstruction to dense summaries and same-byte replay under an unexpected hot/rare swap. **Old-task check:** measure rare historic tasks after the first materialization and after another unrelated committed edit.

14. **Shared state for separately operated editors.** **Mechanism:** each editor keeps private state but sends the minimum decision-relevant message when the next edit crosses a boundary. Distinguish communication needed on a particular request from any synopsis that must support all requests. **Why it might be new:** the object is an interactive handoff of a learner's state, not an interface that joins static edit certificates. **First test:** two modules hold separate halves of a feature permutation; compare query-conditioned messages with a one-shot equal-byte shared synopsis and full-state oracle. **Old-task check:** re-evaluate old cross-module combinations after alternating responsibility, including a previously repaired combination.

15. **A transaction that proves it did not touch edit state.** **Mechanism:** before a full-weight update, identify a reachable block of actions/variables closed under the observer; certify the update lies in its unobservable complement and leave the summary unchanged. Route unprovable updates to the normal state transition and test which fraction of ordinary training needs no state bookkeeping. **Why it might be new:** unlike a no-op on current outputs, this lets a genuine change outside the declared edit/retention interface bypass updating the summary. **First test:** use an exact affine oracle and then a two-head MLP in which one head can move with or without leaking into shared features; compare weight-norm and output-only bypasses. **Old-task check:** test boundaries on delayed cross-head requests and verify old targets after every bypass, with deliberately leaking controls.

16. **A patch language for changing the summary schema.** **Mechanism:** store a bounded decoder and transition rules per coordinate group. On a structural model edit, update only the rules that break, then recompose the unchanged groups and check behavior under mixed suffixes. **Why it might be new:** migration can be local in the *live-state implementation* even if the host representation moves globally; this is not rewriting proof fragments attached to edits. **First test:** take two weakly coupled task families and rotate the host representation while replacing one family's update rule. Compare local patching with full refitting and frozen rules at the same transition-execution budget. **Old-task check:** retest the unchanged family and shared old cases after alternating old/new rule calls.

17. **State failures with a repairable erasure flag.** **Mechanism:** give summary coordinates an explicit missing/corrupt state; restrict only actions whose futures depend on those coordinates and schedule a declared reset or reconstructing exercise. Never read missing data as a default. **Why it might be new:** converts compressed edit state into a fault-isolation interface for progress under partial loss, not an error-correcting code over protected facts. **First test:** erase one compressed coordinate block on a small modular learner; compare to unconditional fallback and equal-byte replicas under the same query budget. **Old-task check:** check unaffected old tasks while damaged, and affected tasks after recovery and a fresh suffix.

18. **Exchange state bits for edits to realign a host.** **Mechanism:** when loading a summary on a different host, either pay for more side bits or pay a small number of authorized preparatory edits that make the same old summary sufficient on that host. Search the tradeoff with the same observer, request vocabulary, and coverage. **Why it might be new:** a host modification can substitute for transmitting missing edit-state information, without requiring recovery of its checkpoint. **First test:** switch between two parameterized toy hosts, one with an extra coupling into the next gradient. Compare state-only translation, prep-only, and a hybrid. **Old-task check:** preserve original tasks during the prep and after actual edits in both hosts; reject prep that quietly changes the old contract.

### D. Challenge the quotient before it becomes another confounded score

19. **Query-priced basis of future distinctions.** **Mechanism:** choose distinguishing suffixes with explicit execution, rollback and read costs. Seek the cheapest basis that spans a held-out action grammar rather than the shortest witness for each pair. Mark a basis unverified if its span is supported only by samples. **Why it might be new:** turns edit-state extraction into a joint sensing problem where the cheapest sufficient measurements need not be the easiest one-step edits. **First test:** derive the optimum on a small affine toy with heterogeneous edit prices, then hide the matrices and compare against random suffixes, immediate-effect sketches, and an equal-query L* arm. **Old-task check:** use the recovered state to admit actual unseen edits without slipping on worst-group protected drift.

20. **Admitted coverage as a memory lower bound.** **Mechanism:** reduce a family's old-task obligation to random access: write \(n\) independent binary choices, then issue a uniform request whose success requires recovering one previously written choice. Under full admission and uniform inputs, average bit error \(\delta\leq \tfrac12\) requires at least \(n(1-h_2(\delta))\) summary bits, where \(h_2\) is binary entropy; for abstentions, derive or measure a separate coverage curve rather than claiming this bound at selective error. **Why it might be new:** seeks a bound for *feasible edit coverage versus bytes*, not just a class count on hidden bits. **First test:** implement a query-and-edit game atop a tiny network, with no copy of previous labels or hidden access to weights in the standalone arm; compare distribution-matched prefix memorization. **Old-task check:** require the queried change and intact independent historic tasks; plot failures and refusals separately.

21. **Worst-case and workload state that can disagree.** **Mechanism:** maintain a small workload-predictive state plus a priced, opt-in exact residual for rare authorized suffixes; invoke the residual using a known workload family or calibrated gate. Include the residual in total storage and compare the whole frontier. **Why it might be new:** the state contract distinguishes discounted average usefulness from exact promises instead of hiding rare drift in an aggregate error. **First test:** change the frequency of an old rare port while keeping single-step margins matched; compare a fixed worst-case sketch and a workload-only compressed state. **Old-task check:** report rare-group false-safe rates and actual old accuracy both before and after the frequency change.

22. **Correlation is edit state.** **Mechanism:** preserve the minimum joint latent state needed to predict future old-task failures under adaptive requests. Distinguish a contract over observable laws from a common-seed contract; do not keep a seed merely because it predicts a path on one arbitrary coupling. **Why it might be new:** measures how many history bits are needed to retain joint risks after observing outcomes, not just how well a simulator predicts marginal risks. **First test:** build two finite stochastic learners with the same one-step failure rates and different cross-edit correlation; compare joint predictive state with independent risk heads under a request policy that branches on the first outcome. **Old-task check:** score joint relapse and per-task retention under both fixed and branching continuations.

23. **Depth-budgeted edit state with certified refresh.** **Mechanism:** maintain a cheap short-horizon state until its remaining validity expires, then pay to refresh it from declared retained evidence. Study the amortized cost of updating depth-dependent projections rather than treating depth as a fixed evaluation hyperparameter. **Why it might be new:** usable depth becomes a resource that edits consume and refresh can replenish, without resetting the retention reference. **First test:** compare to a fixed-depth and a full-state simulator on a stream with rare long dependencies; include the cost of storing and reading refresh evidence. **Old-task check:** trigger those dependencies just before and after refresh and measure false-safe errors and old-task drift from the original baseline.

24. **A hiding benchmark with a switchable causal readout.** **Mechanism:** make existing, matched-history coordinates matter or not matter to edits by randomly switching which latent coordinate an authorized later request can read; keep current outputs and edit margin matched. Use the switch both to prove compression on the null arm and to test for hidden access on the informative arm. **Why it might be new:** a causal equivalence-switch benchmark can catch both under-compression and a purportedly small state leaking information from its host; a fixed memorization rival catches neither alone. **First test:** implement a masked/readable register and then a nonlinear MLP version; blind methods to the test suffix realizations. **Old-task check:** protected register-derived behavior must survive in the readable arm and ordinary old predictions must survive in both, including after recurrence.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can we synthesize a low-state *editor*, not merely compress an existing one?** Compare fixed-editor minimization with semantically valid coalescence, successor code length, and synthesis (7–12). The result would be an action that constructs interchangeability. Kill it if lower state cost comes from refusing valid requests, freezing the only useful learning path, or retaining fewer tasks.
2. **Can an edit vocabulary grow without keeping an unofficial checkpoint?** Characterize the bits or external evidence needed to refine a quotient, then make capability admission and retirement explicit operations (1–6, 18). The primitive is a live-state migration with a measurable information cost; the null is exact migration by hidden replay.
3. **Can the summary be the thing the editor actually operates on?** Train and evaluate a standalone transition, or a charged query/handoff protocol, with explicit recovery and independently held-out suffixes (9, 13–17, 19). Without an execution or byte advantage over an equally fast full-host path and equal-budget replay, the summary is just a diagnostic.
4. **Can we explain which old-task obligations force state to grow?** Use a controlled visibility switch and a coverage-sensitive lower bound to separate necessary task memory from incidental editor state (6, 20, 24). A useful result predicts bytes from task structure and coverage on held-out families, not just observed class counts.
5. **Which approximation can remain reliable through adaptive deployment?** Test joint failure state, priced residuals and refresh against workload shifts and adversarial suffixes (21–23). Report risk, refused requests, and cumulative damage; a discounted forecast that is accurate only on the training curriculum is insufficient.

## Smallest discriminating CPU test

First reproduce the exact affine closure oracle with a visible register, an unreadable tail, and an edit vocabulary that exposes the tail. This checks the evaluator, not the research claim. Then use one two-layer learner on modular rules with overlapping and disjoint protected groups; generate output/margin-matched histories and hold out families of request *combinations* and lengths within the declared vocabulary. Compare a fixed editor plus compressed predictors (immediate effects, a first-order response sketch, and a prefix/replay rival) against a summary-trained editor allowed to pick semantically valid successors. Also include a full-state oracle and a matched host allowed to change weights but not trained to coalesce. Freeze admissible requests, coverage floor, and per-group drift tolerance before measuring. The candidate has to attain the same new-task success and old-task retention at the same coverage, while using less state at matched calls or fewer real continuation calls at matched bytes. If only the exact oracle works, or the gain vanishes under those controls, stop before scaling. No pilot was run for these cards.
