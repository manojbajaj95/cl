# Conservative extension: learn something new without changing what old tasks mean

Parent: [Generator-side forgetting (PR #120), card 11](https://github.com/manojbajaj95/cl/blob/20a2506fac7f4375b77b6341ed7b60f4d21caa62/tree/generator-side-forgetting.md#L60), the score-3 conservative task-language extension idea. This node explores the admission rule for a model or agent's learned knowledge, not just its task generator. **Ideas only; no experiments were run.**

## Root cause: the namespace can survive while the interpretation changes

A learned update can leave the old prompts, weights, or tool names in place and still change their meaning. A new overload can change how an old expression resolves; a new fact can change an old default conclusion; a new skill can use up the shared budget before the old skill runs. Conversely, a solver can forget how to perform a task whose specification has not changed. Retention accuracy on a fixed suite conflates those cases and misses changes to valid answers that the current solver never produces. The hypothesis is that the right unit of learning is an **extension with a checked old-interface projection**, not a write with a good average retention score.

In logic, a theory extension is conservative over the old language if it entails exactly the same old-language sentences. For a monotone extension of a theory, only the absence of *new* old-language consequences needs proving. A learned update may also remove old consequences, so check both directions. Choose an old signature `Σ₀`, a declared set `C₀` of legal old contexts and reachable starting states, and an independently specified observation `Obs`. A context can ask a query, compose old calls, or drive an agent for several steps. For a candidate extension `E`, require

```text
for every c in C₀:
    Obs(run_new(embed(c))) projected to the old interface
        = Obs(run_old(c)).
```

Use a fixed, public embedding and projection; start with identity on old inputs and outputs. Depending on the contract, `Obs` is the set of acceptable answers, a transition relation including visible effects, or a distribution over public traces. A different valid action need not break the contract if what matters is the acceptable set; in that case test execution separately. If callers can distinguish timeout, denial, ambiguity or a new answer, the observation must not erase it. Where checking is approximate, name the metric, tolerance and scope; do not call it exact conservation. Old reference semantics comes from the accepted contract, not whatever mistakes a frozen model happens to make.

**Admission.** Require both the new obligation and preservation of *every* old task in scope. Return `ACCEPT(certificate, scope)` only when both are checked. For an interfering candidate, return `REJECT(old context, old observation, new observation)`, preferably a small reproducible witness; for failure to learn the new obligation, give a new-task witness instead. If no admissible write exists in a declared edit class, return an infeasibility proof (e.g. a set of old/new constraints no single write can satisfy), not a single failed candidate masquerading as a proof about the whole class. Return `UNKNOWN` without admission when the scope is underspecified or search is inconclusive. A bounded certificate proves only the stated scope; it must not authorize an unbounded contract. To correct a genuine old mistake, explicitly revise the contract, record what changed, and then check conservativity over the retained fragment. Never reward silent redefinition as new learning.

## Common first-test protocol

- Start with two CPU worlds: a tiny typed expression language with overloads, and a finite stateful agent with defaults, tools and a small shared budget. Fix independent executable contracts and exhaustive oracles within stated bounds (depth, horizon, inputs, states). Include extensions that are safe, ones that fail in one unusual composition, and ones that cannot fit the declared edit class. Also test ordinary candidate updates, not just planted faults. Keep longer compositions and alternate task families hidden for generalization tests; failures there identify scope limits, not false proofs.
- Every card's old-task check adds to two separately reported axes: exact old-interface disagreements in the enumerable scope, and worst-family live service (fresh task solve/pass rate, old-cue generation reachability within a fixed proposal budget when applicable, and failure/abstention/timeout rates). Measure at admission and after later updates. Report new-task coverage, false admissions, false rejections, unknowns, and witness/proof cost. Rejecting everything, hiding old failures behind abstention, and a frozen learner with no usable new skill are not successes.
- Match stored bytes (including tools, adapters, old checkpoints, proofs and monitors), model calls, oracle work and serving budget. Compare a versioned old namespace plus a new one, frozen routing plus append/retrieve, exact full rechecking in the small world, and replay/distillation at equal cost. Use the card-specific control in addition where applicable. A checker buys nothing if the best simple baseline serves the same old and new contracts at the same cost. Report proof guarantees separately from empirical service; compare Pareto fronts if budgets cannot all be matched.

## Research cards

### A. Preserve meaning while the language grows

1. **Learn conservative definitions before adding rules.** **Mechanism:** Fit a new symbol first as a typed, nonrecursive definition in the old language; certify elimination of that symbol by expansion and verify the proposed new-task examples. If only nondefinitional candidates fit, ask the full checker rather than assuming interference. **Why it might be new:** Definitional extension is standard; the candidate improvement is using elimination to choose what a bounded learner stores and checking whether it buys more new-task service per byte than an isolated skill. **Cheapest first test:** Infer macros for five small list operations with one planted contradictory requirement; compare an equally compact learned macro library with separate routing. **Old-task retention:** Exhaust old terms and check the old evaluator and live solver after subsequent macro additions, especially around shared parser/index limits.

2. **Export the smallest missing context bit.** **Mechanism:** When the old and new requirements demand different results at the same allowed input, find a minimal *available* field or caller capability that separates the conflicting regions; keep the old interpretation for callers that lack it. **Why it might be new:** PR #120's separability witness diagnoses whether a generator has an address; this turns the obstruction into a priced interface requirement for accepting knowledge without reallocating meaning. **Cheapest first test:** Enumerate feature subsets in two overlapping symbol dialects, including a case where no permissible feature separates them; compare a version tag with the same signaling budget. **Old-task retention:** Send all untagged old calls plus held-out old callers legitimately using the proposed field; reject any proposal that steals their interpretation.

3. **Certificate of safe overload resolution.** **Mechanism:** Use a paired type resolver to produce the smallest old expression whose meaning changes, then learn a restricted applicability rule for the new overload and recheck all old derivations. **Why it might be new:** Compatibility checking is not new; ask whether the typed critical cases from a failing extension can guide learning of an overload's extent better than explicit versioning or examples alone. **Cheapest first test:** Add numeric and list overloads to an enumerable grammar with coercions; compare the restricted overload to versioned namespaces and equal-cost replay of random old terms. **Old-task retention:** Exhaust old calls both in isolation and nested under coercions, including previously ambiguous or rejected expressions if those outcomes are contractual.

4. **Backward-compatible grammar pruning.** **Mechanism:** After accepting new productions, remove old productions only if an independently checked translation retains every old meaning and preserves declared bounds on derivation cost; return a context witnessing either semantic loss or excess cost. **Why it might be new:** Ordinary grammar minimization keeps a fixed language; the proposed consolidation spends new productions to replace old implementation paths while serving both old and new queries under live search budgets. **Cheapest first test:** Use two small transducer grammars with shared subexpressions and one misleading alias; compare versioned grammars and semantic deduplication. **Old-task retention:** Exhaust projected outputs, then ask the live generator for unseen old instances under the original proposal cap; valid but newly infeasible derivations count as loss.

### B. Make learning writes carry evidence

5. **Inductive retention for recurrent skills.** **Mechanism:** Learn a relation between pre- and post-update hidden states, and prove that it maps initial states, preserves old visible transitions, and closes under every legal old call. Check any new-call transitions allowed between old calls separately. **Why it might be new:** Bisimulation-style proofs are standard; the candidate is learning a reusable invariant as an admission artifact alongside a skill, rather than growing a fixed trace suite. **Cheapest first test:** Train table policies for a toy inventory agent whose hidden state changes encoding; compare invariant synthesis to bounded trace checking at equal oracle cost. **Old-task retention:** Check all reachable old state pairs and long unseen call chains, including the first old call after a legal new one.

6. **Charge each reusable proof for what it depends on.** **Mechanism:** Index a certificate by the definitions, reads and assumptions in its proof; when a new write touches them, reopen exactly the affected obligations, and treat unknown dependencies as invalidation. **Why it might be new:** Incremental build/verification already tracks dependencies; test whether learned write contracts make repeated semantic admissions affordable without hiding dynamic dependencies. **Cheapest first test:** Stream 20 tiny DSL rewrites through direct and data-dependent calls; compare full rechecking and static dependency invalidation, including the cost of maintaining the index. **Old-task retention:** Use the exhaustive oracle after every accepted write, with hidden late-bound calls designed to expose a missed dependency.

7. **Certified approximation with a declared drift budget.** **Mechanism:** For stochastic skills, bound changes in old public-trace distributions and debit the error against a fixed original contract, either directly or with sound composition bounds. Reset a budget only after re-proving against that contract. **Why it might be new:** A per-release locality threshold forgets its reference as the teacher drifts; the candidate is an admission currency with trace-level accounting, not another divergence loss. **Cheapest first test:** Update a toy stochastic dialogue policy repeatedly with small biases; compare to a fixed-reference replay gate and independent per-step thresholds at matched new utility. **Old-task retention:** Compute exact finite-horizon total variation per old family, including rare traces and long runs where one-step marginals agree.

8. **Joint admission for writes that fail alone or together.** **Mechanism:** Require a proof about the actual merged update; search for compensating pairs or isolate an incompatibility core when individually safe writes interact. Never infer the aggregate verdict from pairwise scores. **Why it might be new:** The object is an accepted *transaction against an old semantic contract*, including intermediate visibility rules, not a predictor of merge interference. **Cheapest first test:** Use a three-write table program with both cancellation and a third-order collision; compare proof-guided search to atomic bundles with exhaustive order search at equal calls. **Old-task retention:** Exhaust old queries after commit and during any intermediate state that old callers can observe; repeat with different valid commit orders.

### C. Turn failures into well-scoped counterexamples

9. **Sealed distinguishing contexts.** **Mechanism:** Construct old contexts in which old and new implementations predict different observations without letting the candidate train on the final witness bank; check candidate-produced witnesses against an independent evaluator. **Why it might be new:** Counterexample-guided repair is known; test whether searching the *old context language* for disagreements separates wrong semantics from low sampled retention under adaptive learning. **Cheapest first test:** Give two old-context grammars the same single-call outputs but different outputs on nested uses; compare syntax-guided distinguishing search with hard-negative replay and random contextual testing. **Old-task retention:** Exhaust held-out composition shapes after repair and compare witness coverage beyond already exposed failures.

10. **Counterexamples that price missing write access.** **Mechanism:** When the edit class is finite or tractable, extract a jointly unsatisfiable core and compute a cheapest extra write port or state bit that makes the core satisfiable; independently recheck the whole repair. **Why it might be new:** [PR #83](https://github.com/manojbajaj95/cl/pull/83) already asks for edit-indexed inverse certificates. The narrower bet is whether a priced change to the *learner's interface* actually transfers across later admission problems, not whether we can invert one write. **Cheapest first test:** With two shared linear heads, alternate requirements with known one-bit versus one-port repairs; compare the core-guided choice to trying every same-cost port in a fresh stream. **Old-task retention:** Exhaust all old contracts, including obligations not in the core, and check whether the purchased port still preserves them after later writes.

11. **Unknown meaning is not permission to write.** **Mechanism:** Carry alternative old contracts consistent with available evidence; accept only if the update is conservative for all of them, otherwise return the smallest discriminating old query to ask an authority. **Why it might be new:** [Carried identifiability (PR #80)](https://github.com/manojbajaj95/cl/pull/80) carries rival explanations to learn a rule; here unresolved semantics itself limits the set of legal extensions even when an old solver looks competent. **Cheapest first test:** Hide which of two default rules an old task used, then offer one safe and one interpretation-dependent new rule; compare active clarification to random clarification queries and a pessimistic frozen contract. **Old-task retention:** Score each latent old world separately, including one where the live model had already made the wrong guess before the extension.

12. **Refute observed service separately from the formal contract.** **Mechanism:** Pair a formal witness channel with a live execution witness channel. Attribute a failed old call by replaying its initial state through the specification and the executor; do not rewrite meaning to accommodate a routing or solver failure. **Why it might be new:** PR #120 separates generator from solver; this card asks whether typed failures at admission choose cheaper repairs than a single old-pass gate when specifications themselves can evolve. **Cheapest first test:** Inject matched parser, dispatch and solver faults in a toy agent, then add ordinary learned updates; compare to component ablations and one generic repair loop. **Old-task retention:** Check unseen old calls and their projected observations with the repaired live agent, plus exact old specification equivalence even when the live arm improves.

### D. Extend stateful and distributed agents

13. **Persistent-state migration with a retraction.** **Mechanism:** Learn a mapping of old states to new representations and a projection back. Verify that projecting immediately recovers each old state, that executing then projecting agrees with the old projected command semantics (including errors and side effects), and that allowed new commands respect the declared relation. **Why it might be new:** Database migrations and simulation relations already exist; ask whether the map can be the learned memory artifact, reducing the need to retain a duplicate runnable state. **Cheapest first test:** Extend a table-backed planner with a new grouping key and hidden history-dependent conflicts; compare a learned map to dual storage and a hand-coded migration. **Old-task retention:** Check all old reachable states, including states populated before migration, and alternating old/new sequences with declared visible effects.

14. **Conserve service under shared resource contention.** **Mechanism:** Include public service guarantees (deadline class, refusals, ordering if promised) in the old observation; admit a learned scheduler or skill only if old requests keep those guarantees under a specified envelope of mixed traffic. Return an offending old request and arrival sequence. **Why it might be new:** Scheduling isolation is standard; the learning bet is treating resources as part of the semantic admission witness so the learner can trade less wasteful dynamic sharing against static quotas. **Cheapest first test:** Exhaust short finite arrival traces with two old tools and a bursty new one; compare fixed reservations and quota sharing at equal utilization. **Old-task retention:** Check per-class deadlines and visible effects on mixed sequences, not just old-only traffic; report out-of-envelope behavior separately.

15. **Multi-client conservation at a shared update.** **Mechanism:** Give clients independent old observation maps; compose their extension certificates only under explicitly shared assumptions and request a distinguishing client context when a shared write violates one. **Why it might be new:** PR #115 already identifies shared-base interference; test whether compact negative/positive compatibility evidence substitutes for transferring each client's tests while protecting private compositions. **Cheapest first test:** Run three finite-state clients with private adapters and one shared interpreter; compare per-client freezing, sampled shared tests and accept-only-by-consensus at matched bytes and checks. **Old-task retention:** Exhaust the private old contexts independently and report worst-client failure, including simultaneous old traffic and a case where aggregate pass rate improves.

16. **Scoped corrections with a conserved remainder.** **Mechanism:** If new evidence contradicts an old contract, propose the smallest declared region to revise, give concrete old observations that change there, and prove equivalence outside it. Treat revision as a separate authorized operation, never an ordinary admission. **Why it might be new:** AGM revision already addresses conflicting information; the candidate is returning an executable boundary for what a learning system would revise and validating the unaffected old tasks. **Cheapest first test:** Correct one exception in a finite default-rule agent whose consequences cascade; compare AGM-style minimal change and a versioned override with identical evidence. **Old-task retention:** Check every old query outside the signed-off region, plus nearby default and downstream composition cases; report intentional changes separately from accidental loss.

### E. Learn when full checking is worth the cost

17. **Prove a partition, not a list of test cases.** **Mechanism:** Learn a cover of the old context space and attach a sound proof per region (e.g. a relational interval argument); split where the proof cannot close and never accept an uncovered region. **Why it might be new:** Abstract interpretation is established; the learning question is whether a cross-update partition learned from past extensions amortizes verification without the blind directions of a fixed footprint. **Cheapest first test:** Extend a small piecewise-linear controller and verify old actions by intervals; compare a fixed partition, direct solver queries and exhaustive checks. **Old-task retention:** Check all old inputs and boundary neighborhoods with an exact oracle; charge incorrect admission even if single-point accuracy rises.

18. **Keep a portable conservation contract, not a portable edit.** **Mechanism:** Compile the same public old observation contract and new obligation into different hosts, accepting each implementation only with its own proof; retain the smallest witness of host-dependent nonconservation. **Why it might be new:** Repo edit-transfer nodes already separate content from implementation. The test here is whether a reusable *old-language protection contract* makes continual admission portable when the new skill and the old behavior both have different internal encodings. **Cheapest first test:** Translate between a finite transducer and a table interpreter with overlapping old syntax; compare replay-based porting and a versioned adapter. **Old-task retention:** Exhaust old contexts against the same independent reference on both hosts after further unrelated edits; an implementation-specific proxy cannot define success.

19. **Conservativity under declared changes to the world.** **Mechanism:** Parameterize the old contract by independently varied legal environments, then check each original/extended pair under the *same* environment rather than demanding a constant answer across worlds. **Why it might be new:** Domain-randomized validation is familiar; the bet is an explicit relational admission contract that keeps adaptation to legitimate world changes without permitting the new knowledge to redefine an old policy. **Cheapest first test:** Learn a new route tool while the old delivery rule responds to changing road costs; compare a frozen policy, environment replay and direct robust verification. **Old-task retention:** Enumerate all declared small maps and compare old rule consequences per map, including ties, blocked routes and map changes after a new task.

20. **Budgeted escalation from audit to proof.** **Mechanism:** Let a learned triage policy choose the next proof action (type check, symbolic search, exhaustive slice, query for clarification), but keep it out of the final verdict; hard instances can still return `UNKNOWN`. **Why it might be new:** Solver portfolios are known; ask whether the counterexample history of a specific learner predicts which proof actions will pay for repeated safe admissions, beyond static scheduling. **Cheapest first test:** Stream finite grammar updates from alternating conflict modes; compare a fixed portfolio and per-instance cheap checks followed by one solver at equal time. **Old-task retention:** Enumerate all accepted updates independently and report old-family service and worst repeat failure; show false rejections and unknowns rather than evaluating only easy accepted cases.

21. **Reclaim space by forgetting the implementation, not the guarantee.** **Mechanism:** Synthesize one compact replacement for several retired implementations with a joint conservation proof; garbage-collect old artifacts only when the remaining checker and certificate still suffice to justify the contract. **Why it might be new:** Checkpoint compression normally measures predictive match; here checkability survives compaction and becomes part of the storage accounting. **Cheapest first test:** Merge repeated old table-policy variants into a shared decision graph under a byte cap; compare append/retrieve, exact table minimization and replay distillation. **Old-task retention:** Enumerate both direct and compositional old calls after deleting all retired objects and after a further learning cycle; independently verify retained evidence without fetching the deleted artifacts.

22. **Counterexample for an observation that is too weak.** **Mechanism:** Allow legacy callers drawn from a declared context language to challenge the observer itself: find two implementations the projection equates but a legal downstream consumer distinguishes; revise the scope explicitly before any new admission. **Why it might be new:** Contextual equivalence is classical, and [PR #107](https://github.com/manojbajaj95/cl/pull/107) covers fixed assay collisions. The candidate is an operational test of the *contract boundary*, not a better predictor fed the same observations. **Cheapest first test:** Let an old API return equal abstract answers with different error or ordering behavior; synthesize the smallest distinguishing downstream consumer and compare to schema diffing and larger end-to-end replay. **Old-task retention:** After observer refinement, recheck previous admissions against a hidden collection of legal consumers; count previously missed distinctions separately from checker errors under the old scope.

## Prior-art and ledger screen

This is a quick abstract-level screen (arXiv, Crossref, HF Papers keyword search), not novelty clearance. The mechanism borrowed from each field is not itself a novelty claim.

- [Model-theoretic inseparability and modularity of description logic ontologies](https://doi.org/10.1016/j.artint.2013.07.004) is direct prior art for preserving an old vocabulary across additions and for stronger model-based notions of preservation. [OWL 2 profiles](https://www.w3.org/TR/owl2-profiles/) illustrate why computational claims need a specified logical fragment. The transfer bet is on learned, bounded implementations with live service and priced updates, not on inventing conservativity or deciding it for an arbitrary model.
- Typed definitions, overload compatibility, simulation and contextual equivalence already provide precedents for language and interface preservation. [Alchourrón, Gärdenfors and Makinson](https://doi.org/10.2307/2274239) explicitly address contraction/revision, the control when a new claim is inconsistent with an old one. Do not quietly substitute minimal revision for conservative admission.
- [Learning without Forgetting](https://arxiv.org/abs/1606.09282) preserves sampled old responses by distillation; [Net2Net](https://arxiv.org/abs/1511.05641) preserves the function at growth time. Neither insertion-time equality nor replay agreement alone states which interactions later callers may observe. Match those controls where old inputs or architectural growth matter.
- [ROME](https://arxiv.org/abs/2202.05262) measures edit specificity, [AlphaEdit](https://arxiv.org/abs/2410.02355) constrains knowledge edits to a preservation null space, and [Certified Mechanistic Edits](https://arxiv.org/abs/2610.03502) is direct evidence that certificate-bearing skill preservation is not new by itself. Compare against fixed-interface protection and ask whether a changed task language, observer or composition boundary defeats it.
- [Provable Repair](https://arxiv.org/abs/2104.04413), [SpecRepair](https://arxiv.org/abs/2106.01917), and [Counterexamples as Feedback for Agent Self-Correction](https://arxiv.org/abs/2609.02892) cover verified repair or using failure feedback. A counterexample plus another prompt rewrite is not a distinct contribution.
- [Idea ledger (PR #6)](https://github.com/manojbajaj95/cl/pull/6/files): do not revive counterexample-guided lesson preconditions as feedback alone, composition contracts as identity-generated SFT labels, or fixed-set retention gating as proof. [PR #115](https://github.com/manojbajaj95/cl/pull/115) already treats vocabulary/architecture growth as retention events; the new question is how an admission checker detects changed meaning and produces a usable failure. If an isolated namespace wins at matched cost and utility, keep it.

## Deeper sub-questions, ranked

1. **What is the smallest old observation language that is adequate for all legal old callers?** Start with cards 3, 5 and 22: exhibit two extensions agreeing on standalone tasks but separated by an old composition; vary allowed contexts and look for a checkable, strictly smaller sufficient contract than full trace identity. If a versioned interface has the same utility and cost, there is no reason to replace it.
2. **When can a rejection identify the minimal extra information or write access worth buying?** Cards 2, 10 and 11 separate input aliasing, inadequate write capacity and unknown old meaning. Check whether the proposed purchase restores feasibility on held-out future extensions, versus equal-budget tags, ports or clarification.
3. **Can certificates compose through ordinary learning and consolidation without cheaper proof reuse hiding old failures?** Cards 6–8, 17 and 21 should find where dependency reuse or joint proof improves the safe-admission frontier over full rechecking. Require an exact finite oracle and a frozen-version baseline before claiming a gain.
4. **How much conservativity survives contact with live service?** Cards 4, 12–15 and 19 distinguish semantic compatibility from reachability, scheduling and plasticity after admission. A proof that protects the old grammar while no old task can be generated or solved is a successful semantic check and a failed continual learner.
