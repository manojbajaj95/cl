# Root: Self-Modifying Architecture for Continual Learning

Root node (depth 0) · 32 candidate primitives · Ideas only; no experiments run

**Thesis.** A lifelong learner should be able to change what it computes, how its parts communicate, and which experiences can change which parts. The hard case is not adding a bigger expert after a known task boundary. It is making an edit that survives the next edit: a split whose children can still learn together where required, a deletion that does not erase future uses, or a new learning rule that does not silently reinterpret old feedback. Treat the executable graph and the graph carrying learning signals as two mutable objects. An edit can affect one without changing the other.

**Scope.** The [idea ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md) asks for a new object or operation and old-task retention in the first test. This is not the [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md) path through optimizer-state inheritance, meters and observability, token retirement, or teaching markets. The [self-modifying flood (#43)](https://github.com/manojbajaj95/cl/pull/43) already has weight autobiographies, an edit ISA, neutral drift, and successor lineages. [Developmental growth (#127)](https://github.com/manojbajaj95/cl/pull/127) covers genome encodings, morphogenesis, trophic pruning, regeneration, and developmental clocks. [Cancelling-pair renewal](https://github.com/manojbajaj95/cl/blob/devin/1795562643-cancelling-pairs/tree/cancelling-pairs.md) reclaims jointly silent structures. The cards below do not need developmental schedules, cancellations, checkpoints masquerading as deletion, or an agent rewriting its own benchmark.

**Literature check.** Comparisons use web discovery and the linked original abstracts or paper sections. They identify the closest mechanisms found and a gap to test, not priority claims. [Progressive Nets](https://arxiv.org/abs/1606.04671), [DEN](https://arxiv.org/abs/1708.01547), [PackNet](https://arxiv.org/abs/1711.05769), [Net2Net](https://arxiv.org/abs/1511.05641), [Firefly](https://proceedings.neurips.cc/paper_files/paper/2020/hash/fdbe012e2e11314b96402b32c0df26b7-Abstract.html), [GradMax](https://arxiv.org/abs/2201.05125), [NEAT](https://doi.org/10.1162/106365602320169811), and [HyperNEAT](https://doi.org/10.1162/artl.2009.15.2.15202) already establish expansion, isolation, function-preserving growth, and topology evolution. More recent work narrows the gap: [MoSEs](https://arxiv.org/abs/2511.06237) composes reusable subexperts and expands selectively; [Autoplastic Networks](https://www.nature.com/articles/s44387-026-00169-0) learn depth, connectivity, and operator mixtures within a supernetwork; [SoftModel](https://arxiv.org/abs/2608.16409) already combines exact structural operators with governed in-service adoption. [Are Self-Evolving Agents Continual Learners?](https://arxiv.org/abs/2610.25858) finds that global harness edits interfere with old tasks on drifting streams. “The system edits itself,” or “the edit preserves predictions at insertion,” is not enough.

[Lottery tickets](https://arxiv.org/abs/1803.03635), [RigL](https://arxiv.org/abs/1911.11134), [continual backprop](https://arxiv.org/abs/2306.13812), and [ReDo](https://arxiv.org/abs/2302.12902) are reasons not to confuse finding, rewiring, or recycling sparse capacity with retaining the meaning of a live operation. [Growing Networks with Autonomous Pruning](https://arxiv.org/abs/2603.19759) already combines growth with differentiably gated pruning; [DIMoE-Adapters](https://arxiv.org/abs/2605.07494) evolves a pool of continual-learning adapters, and [C-LoRA](https://arxiv.org/abs/2502.17920) instead reuses low-rank directions inside one adapter. The tests below require more than a different allocation of expert slots or rank.

**Shared CPU-first protocol.** Use a finite-state agent, a typed toy graph, or a small NumPy learner. Start with ordinary tasks A and B (one rare), introduce C without an oracle task ID, then present a second shift D and returns to A/B. The running learner chooses edits using stream evidence only. Exact enumeration with hand-built parts can establish that the operation differs from a matched control; it does not establish that a learner can discover the edit. Follow a positive separation with the same toy using learned choices. Give controls the same candidates, data, side information, update opportunities, and budget where applicable. Charge rejected edits, migration work and peak memory as well as live parameters, stored recipes, and per-query compute. Use a fixed-graph learner with replay and a conventional add/freeze or prune-and-retrain arm alongside the named close control. Report adaptation at matched retention and retention at matched adaptation. If a static masked graph wins under the same real budget, or the claimed advantage is simply hiding copies in auxiliary state, reject the primitive as a CL bet.

**Old-task check for every card.** Run a hidden, fixed held-out mix of ordinary A/B queries or full episodes through the normal interface before the edit, immediately after it (including in-flight work when relevant), after C learning, and after the D edit. Report each task and worst-task drop, not only the pooled score. Set the acceptable drop against a no-new-learning arm before looking at results. The check on each card adds a particular old slice; the learner does not get that slice as a routing signal or as an edit acceptance set.

## A · Grow something other than capacity

### SMA01 · Split a component by counterexample continuations
- **Mechanism:** Grow a persistent context bit only when two prefixes that meet at the same internal state have different outputs under the same continuation. Attach the distinction at the first shared boundary that needs it, and pass the bit only downstream of that boundary. The new object is a continuation-defined state refinement.
- **Nearest prior / gap:** [Automaton extraction with queries and counterexamples](https://proceedings.mlr.press/v80/weiss18a.html) splits a partition while extracting an automaton from a fixed recurrent model. Here a bounded continuation witness changes the running learner's own state space and the bit survives into future learning; exact finite-state refinement itself is not new.
- **Cheapest first test:** Train a three-state door controller, then alternate worlds where the same visible door state needs different responses after reset. Give a wide recurrent learner and an input-cluster split the same counterexamples and one additional bit. Hold out continuation combinations.
- **Old-task retention:** Run both original door policies on old prefixes that share the revised state, including prefixes whose continuations do not need the bit.

### SMA02 · Grow the missing member of a composition
- **Mechanism:** When familiar operations fail only in combination, synthesize a middle module from the constraints imposed by the existing producer and consumer. Neither endpoint changes at birth; the new middle must also support a second caller before it counts as a reusable operation.
- **Nearest prior / gap:** [Lifelong Learning of Compositional Structures](https://arxiv.org/abs/2007.07732) searches structures over reusable components and adapts components. Test the narrower operation of synthesizing an intermediary jointly constrained by both ends, versus giving the same wiring search an unconstrained component slot.
- **Cheapest first test:** Compose finite transducers with incompatible boundary encodings. Infer a middle map from two partial compositions and predict a held-out third, versus an equal-size end-to-end bridge given identical executions.
- **Old-task retention:** Run the original producer and consumer tasks separately and in their old compositions; check old cases that use values never observed in C.

### SMA03 · Grow a loop from repeated evidence requests
- **Mechanism:** Replace a fixed chain of nearly repeated modules with a persistent recurrence whose exit depends on the state of the problem, not the unrolled step index. Keep the parts that must not repeat outside the loop; a loop can later be nested by the same edit.
- **Nearest prior / gap:** [SoftModel](https://arxiv.org/abs/2608.16409) already grows directed cycles with contraction certificates. The narrower operation here synthesizes a loop by identifying which transitions consume work and which are one-time effects, then replacing the old chain instead of attaching extra capacity.
- **Cheapest first test:** Fit a finite list-processing pipeline that sums items and emits one final receipt. Add longer lists; compare to an equally sized fixed loop and standard cycle insertion given the same traces and work limit. Require extrapolation without duplicate receipts.
- **Old-task retention:** Re-run short lists with empty and early-stop branches, checking emitted actions as well as the sum.

### SMA04 · Grow a port for information that arrived too late
- **Mechanism:** Make a provisional result into a persistent request/reply pair. Grow a typed return port and a continuation that consumes the late evidence; do not re-run the whole request or silently replace a decision already made. Future modules can reuse the port without replacing the original producer.
- **Nearest prior / gap:** [Interface Automata](https://luca.dealfaro.com/papers/01/FSE01.pdf) represent component assumptions and guarantees over input/output actions. The proposed CL operation is evidence-driven invention of a return port and a continuation from observed failures, not interface checking itself.
- **Cheapest first test:** In a tabular reservation agent, add delayed confirmation mixed with immediate approvals. Give an equal-state capped recurrent controller and a restart policy the same sequence and feedback. Count duplicate reservations and completion cost.
- **Old-task retention:** Keep immediate booking and cancellation working unchanged, including a pending old booking spanning surgery.

### SMA05 · Grow a lateral translation, not a new expert
- **Mechanism:** A learner adds an edge that converts between two established modules' coordinate systems, then tests whether the translator works for an unseen third composition. The conversion is bidirectional only on a learned overlap; neither module is copied or replaced.
- **Nearest prior / gap:** [Progressive Nets](https://arxiv.org/abs/1606.04671) use lateral connections into new columns. The candidate operation is making an independently trained pair of live modules mutually reusable through a scoped translation, rather than giving a new column access to old features.
- **Cheapest first test:** Learn two tiny table-valued controllers with independently permuted latent states. Use paired unlabeled transitions to infer a partial map; compare with an equal-size bridge trained on C labels and a one-way edge. Hold out a composition and an ambiguous overlap.
- **Old-task retention:** Check old tasks on both sides, including states outside the map's scope that must still take their original paths.

### SMA06 · Grow an explicit boundary inside a monolith
- **Mechanism:** Insert a new module boundary at a factor of the internal state by exposing *replaceable* inputs and outputs, not all activations. Infer where replacing the factor leaves unrelated behavior unchanged. A later module can implement the same factor independently.
- **Nearest prior / gap:** [Unsupervised Causal Abstractions Discovery](https://arxiv.org/abs/2606.19594) searches for causal abstractions. The candidate primitive uses such a factor as a new writable boundary in the continuing model; merely recovering the factor would tie prior art.
- **Cheapest first test:** Learn a tiny network for two independent arithmetic subroutines, introduce a new version of one, and compare causal-boundary insertion with a same-width activation split and a fixed learned router. Hold out input pairs and intervention values.
- **Old-task retention:** Score A/B before and after replacement, including combinations where the edited subroutine runs but must not affect the other answer.

### SMA07 · Grow a synchronization point from collisions
- **Mechanism:** When separately useful recurrent modules both write to a shared resource, grow a rendezvous that binds the two operations to a joint transition. It reconciles unfinished intents, not outputs after the fact. Other modules can attach to the new rendezvous.
- **Nearest prior / gap:** [Multiparty Session Types for Safe Runtime Adaptation](https://doi.org/10.4230/lipics.ecoop.2021.10) check adaptations against communication protocols. The new operation would infer *where to add* a joint transition from executions, then reuse it; checking a known protocol is a control.
- **Cheapest first test:** Combine two finite warehouse agents that rarely cross paths but can claim the same bin. Compare a learned rendezvous with a global lock and a joint policy at equal state and action budget. Hold out new arrival timing.
- **Old-task retention:** Run old solo and paired schedules away from the conflict, and check that the new joint transition does not cause a deadlock on an old schedule.

### SMA08 · Grow a common prefix without taking ownership of its tails
- **Mechanism:** Factor the beginnings of several live workflows into a shared prefix with resumable state; retain independently editable tails. Make the prefix return a continuation state, not a task label. Future tasks can start at that boundary from their own beginnings.
- **Nearest prior / gap:** [DreamCoder](https://arxiv.org/abs/2006.08381) adds reusable functions by compressing programs. Here the test is moving an execution boundary across *running stateful tasks* while making the tails independently resumable; a same-library refactor is the strongest simple control.
- **Cheapest first test:** Share the prefix of two tiny intake workflows with interleaved jobs, then learn a new tail and introduce a different prefix that legitimately enters an old tail. Compare ordinary common-subexpression factoring with the same runtime storage.
- **Old-task retention:** Resume old A/B jobs that paused before surgery as well as fresh jobs; score any collected inputs and emitted actions, not just final output.

## B · Prune without just discarding what looks idle

### SMA09 · Delete a module by distributing its state to its consumers
- **Mechanism:** Construct a different projection of a shared recurrent module's state for each consumer; push each projection and its transition into that consumer. Delete the producer only if every continuation in the permitted message grammar is still expressible. No central clone remains.
- **Nearest prior / gap:** [Neuron Merging](https://arxiv.org/abs/2010.13160) compensates for deleted units by moving their contribution into surviving weights. Here elimination factors a *transition system* across heterogeneous consumers; the hard case is new legal compositions, not a one-step output reconstruction.
- **Cheapest first test:** Eliminate a finite-state coordinator whose two consumers only need disjoint projections. Compare central automata minimization and whole-coordinator distillation under equal total state. Add a coupled case that should make the deletion inadmissible.
- **Old-task retention:** Execute held-out interleavings of both consumers, including a rare old request that distinguishes two states identical to the other consumer.

### SMA10 · Prune cross-talk rather than nodes
- **Mechanism:** Remove a directed dependency only in the contexts where replacing its message with any legal value leaves output and continuation unchanged. Retain the edge elsewhere, and compile separate execution slices that share the same modules. The edit is subtraction from an edge's domain.
- **Nearest prior / gap:** [GrapNet](https://arxiv.org/abs/2606.18923) already exposes relation-local deletion and attention routing. The gap is conditioning physical absence on invariance over legal interventions, rather than pruning a low-score relation or selecting a sparse path on each query.
- **Cheapest first test:** Fit a small rule graph with one sensory link irrelevant except in a narrow context. Compare learned slice pruning with top-k routing and whole-edge deletion at equal byte and execution budgets; inject shifted values into irrelevant messages.
- **Old-task retention:** Keep the rare old context that still depends on the link, and test old contexts where that edge is now absent against shifted nuisance values.

### SMA11 · Replace a pruned region with a generator of its obligations
- **Mechanism:** Delete many modules performing variants of one bounded operation. Retain a compact rule that instantiates a transient implementation from a request's structure; it cannot refer to old weights. The generator must also produce a working variant that did not exist before pruning.
- **Nearest prior / gap:** [HyperNEAT](https://doi.org/10.1162/artl.2009.15.2.15202) already generates connectivity from a compact encoding; [DreamCoder](https://arxiv.org/abs/2006.08381) already learns generative libraries. The CL hypothesis is conversion of independently learned live modules into one sufficient generator at deletion, not a new encoding family.
- **Cheapest first test:** Learn separate table transducers for several alphabet permutations, infer the generative rule, and delete all source tables. Compare equal-byte compression and size-conditioned hypernetwork distillation. Test an unseen permutation and include generation cost.
- **Old-task retention:** Re-run every old alphabet, including a rare one whose inverse map disagrees with the most frequent variants.

### SMA12 · Prune a decision without pruning its work
- **Mechanism:** Replace a router and several destinations by a factorized execution that performs shared work once and delays the one conflicting operation until its necessary condition arrives. Delete the old router itself, rather than distilling its choices.
- **Nearest prior / gap:** [MoSEs](https://arxiv.org/abs/2511.06237) sparsely selects and composes subexperts. Here the primitive is removal of an early choice from the architecture when computation can be legally postponed, not better choice among reusable experts.
- **Cheapest first test:** Two tiny agents preprocess packages identically but differ in final dispatch according to late evidence. Compare router distillation, ordinary prefix sharing, and the delayed-choice graph, matched in total work. Hold out reversals of early cues.
- **Old-task retention:** Verify old dispatches with and without early cues, including an old customer that needs a valid preliminary response before dispatch.

### SMA13 · Delete an update path but keep its forward path
- **Mechanism:** Expose a learned relation as two directed edges: one carries the value, the other lets feedback change the producer. Remove only the latter and introduce a separate local correction destination. Later callers can still read and other sources can still teach the producer.
- **Nearest prior / gap:** [Progressive Nets](https://arxiv.org/abs/1606.04671) freeze old columns and [Synthetic Gradients](https://proceedings.mlr.press/v70/jaderberg17a/jaderberg17a.pdf) decouple feedback via local estimates. Test caller-specific deletion and redirection in a multi-consumer graph, against stop-gradient plus a matched adapter; if that implements the same future learnability, this is not a new primitive.
- **Cheapest first test:** Use two tiny heads with shared features, add a third with incompatible evidence, and then give new legitimate evidence through an old head. Compare global freezing, a fixed stop-gradient adapter, and live rewiring with the same writable parameters.
- **Old-task retention:** Hold out old examples from both old heads after C and after the legitimate update, including rare cases dependent on the feature that remains writable.

### SMA14 · Prune the distinction between two histories, not the histories
- **Mechanism:** Quotient two branches of an executable graph only on the subset of states whose *future action traces* agree under the allowed requests. Keep a minimal refining branch for the rest; the same operational rule can quotient a newly learned third branch.
- **Nearest prior / gap:** [Angluin's active automata learning](https://homepages.math.uic.edu/~lreyzin/papers/angluin87.pdf) and automaton minimization already merge continuation-equivalent states. The candidate is partial, live quotienting of independently editable modules with a retained state-lifting map for still-distinct continuations, not finite-state minimization by another name.
- **Cheapest first test:** Merge two small inventory controllers with a common replenishment subgraph but incompatible backorder rules. Compare whole-program DFA minimization and module distillation at matched bytes; then introduce a third controller and count refit work.
- **Old-task retention:** Re-run both old controllers, including rare transitions out of their shared states into different backorder actions.

### SMA15 · Remove a redundant protocol round by commuting its effects
- **Mechanism:** Fuse two messages and eliminate the intermediate processing node if its action can move across every admitted concurrent operation without changing either result. Carry the derived atomic operation into later compositions, not a record of messages to replay.
- **Nearest prior / gap:** [Partial evaluation](https://doi.org/10.1145/243439.243447) and [runtime architecture graph transformation](https://oro.open.ac.uk/1165/1/wermelinger02scp.pdf) already reduce and reconfigure known programs. The candidate is learning the conditions for fusing rounds from repeated workloads and declining to fuse when newly learned operations break commutation.
- **Cheapest first test:** Simulate a reservation then commit protocol with commuting reads and one competing reserve. Compare batched calls and inlining; hold out legal schedules, including one where fusion must not take effect.
- **Old-task retention:** Compare old receipts, errors, and final ledger values for both conflict-free and contested old jobs after fusion and after a new concurrent action is introduced.

### SMA16 · Peel off a learned behavior through its inverse
- **Mechanism:** If a module holds a reversible canonicalization followed by a policy, move the canonicalization to the input boundary and delete its implementation inside the module. Use an explicit inverse to migrate mid-execution state only where the transform is invertible, freeing the policy to serve another boundary.
- **Nearest prior / gap:** [Network Morphism](https://arxiv.org/abs/1603.01670) preserves the function of a network during structural change, and [Kitsune](https://dl.acm.org/doi/10.1145/2398857.2384635) migrates live program state. The narrower bet is learned separation of coordinate convention from behavior, evaluated by reuse and real deletion, not by exact transfer alone.
- **Cheapest first test:** Infer a permutation/sign map for two tiny game controllers that differ in coordinates but share a policy. Compare joint distillation and alignment plus a fixed wrapper. Count duplicate state; a noninvertible boundary should reject the edit.
- **Old-task retention:** Continue pre-edit game episodes and start new ones in both old coordinate conventions, including states on the edge of the learned inverse domain.

## C · Rewire live computation and retain its commitments

### SMA17 · Move an edge across a queue without deciding by arrival time
- **Mechanism:** Learn a map on unfinished messages when replacing a producer–consumer connection. The cut belongs to a logical step of each job: messages sent before the cut must be translatable into the new continuation, even if delivered after it. Retire the old edge while the system runs.
- **Nearest prior / gap:** [Naiad](https://sigops.org/s/conferences/sosp/2013/papers/p439-murray.pdf) tracks logical progress in cyclic dataflow; [Kitsune](https://dl.acm.org/doi/10.1145/2398857.2384635) supports explicit state transformation. The bet is inferring a small transition-preserving message map from execution, and using it to switch without draining or keeping two whole pipelines.
- **Cheapest first test:** Switch units in a two-stage event processor with reordered messages. Compare drain-and-switch, versioned dual serving, and a learned message map under equal storage and pause budgets; hold out delay schedules.
- **Old-task retention:** Score old jobs interleaved with new jobs through the cut, including old messages that were queued but never consumed before surgery.

### SMA18 · Transfer an unfinished commitment, not just hidden state
- **Mechanism:** Remove a planner from a live task by handing its successor only the residual obligations: completed effects, outstanding effects, and effects still compensable. Require a new plan to discharge those obligations, not to reconstruct the former planner's latent vector.
- **Nearest prior / gap:** [ReCaml](https://dl.acm.org/doi/10.1145/1932681.1863550) makes execution state central to reconfiguration. The CL bet is a learned, policy-independent residual task that can cross controllers with incompatible state representations; hand-written migration and a recipe interpreter with the same effects are controls.
- **Cheapest first test:** Swap a greedy pickup planner for a batching planner while deliveries are part-complete. Infer obligations from observable actions and use no saved old planner. Compare trace replay and a learned hidden-state adapter.
- **Old-task retention:** Finish partially complete A/B jobs with no duplicate pickups or lost cancellations, and run untouched old job variants after the swap.

### SMA19 · Add a link whose output can be challenged by its recipient
- **Mechanism:** Replace a bare output edge with a request plus a bounded counterexample channel: the learner attaches a second edge on which a downstream component can demand a distinction the upstream representation erased. Plug that distinction into the next execution and future callers, rather than merely reporting uncertainty.
- **Nearest prior / gap:** [Learning to divide and conquer](https://dl.acm.org/doi/10.1007/s10703-008-0049-6) learns component assumptions from counterexamples in compositional verification. Here the counterexample can change what the running upstream component exposes; an assumption learned over a fixed interface is a control.
- **Cheapest first test:** Teach a tiny packing agent a new client whose boxes share an upstream weight tag but require a new fragile/nonfragile distinction. Compare fixed feedback plus retraining and sending the full raw input under a strict bandwidth cap; hold out a second client needing the same new distinction.
- **Old-task retention:** Check the old packers, including jobs where the new distinction should have no effect and the recipient never requests it.

### SMA20 · Switch architecture by translating legal operations, not coordinates
- **Mechanism:** When two subgraphs overlap in behavior, learn a map from *sequences of operations* on the first to sequences on the second, and use it as the reroute. The source and destination can have different internal state dimensions and a one-to-many operation correspondence.
- **Nearest prior / gap:** [Option Transfer and SMDP Abstraction](https://arxiv.org/abs/2110.09196) studies transfer via successor features and temporal abstractions. Test a learned operation translator that replaces a live subgraph and preserves the ordering of old sequences, beyond sharing a basis of individual options.
- **Cheapest first test:** Route a toy courier from a primitive-step controller to a macro controller. Learn translations with paired endpoints, compare macro policies and one-step action adapters at equal samples, then test novel action orderings with the same endpoints but different effects.
- **Old-task retention:** Check old courier loops including sequences where taking the same final action via a different path invalidates the job.

### SMA21 · Wire a relation with jointly assigned roles
- **Mechanism:** Create a jointly resolved connection between three or more live modules so that the identity of each caller changes what the other callers mean. Keep one shared relation in place of several pairwise adapters; new role assignments reuse the relation without new weights.
- **Nearest prior / gap:** [Modular Lifelong RL via Neural Composition](https://arxiv.org/abs/2207.00429) composes reusable modules for tasks. The narrow bet is inferring and installing a multi-party binding operation from sparse examples rather than composing a sequence of already meaningful independent module calls.
- **Cheapest first test:** Infer a three-party exchange relation on small symbolic inventories from a few assignments of buyer, seller and guarantor. Compare equal-size pairwise links and a matched monolithic module; predict unseen permutations. Include a task with only pairwise effects where the relation should not help.
- **Old-task retention:** Run old two-party exchanges and existing three-party combinations, including one where an entity is allowed in one role but not another.

### SMA22 · Move a recurrent boundary across a clock change
- **Mechanism:** Rewire execution so a component receives one event per meaningful transition instead of one per observation. Learn how to split or combine events together with the state map that carries unfinished computation across the change. Undoing the batching does not require the old graph.
- **Nearest prior / gap:** [GrapNet](https://arxiv.org/abs/2606.18923) separates graph structure from execution policy; [Naiad](https://sigops.org/s/conferences/sosp/2013/papers/p439-murray.pdf) gives dataflow logical time. The novel candidate is a learned change of *what counts as a step* on a particular recurrence, not faster scheduling of identical steps.
- **Cheapest first test:** Replace per-sample counting with event-counting in two finite control loops fed at variable rates. Compare fixed downsampling and an event-driven architecture with the same observation budget. Use old burst patterns and a new signal for which batching must stop early.
- **Old-task retention:** Verify old traces during rate changes, including events straddling the edit and old timeouts that depend on elapsed time rather than event count.

### SMA23 · Move credit with the edge that earned it
- **Mechanism:** When a connection disappears before delayed feedback arrives, route that feedback to the successor that can still implement the original operation. If the operation was split, use the issued action's provenance to split the correction; do not train whichever component now occupies the old name.
- **Nearest prior / gap:** [RUDDER](https://arxiv.org/abs/1806.07857) redistributes delayed returns across timesteps. This edit transports an already attributed learning signal across *module identity changes*, preserving where it should teach after the move.
- **Cheapest first test:** Split a finite policy with pending delayed outcomes. Compare teaching the current actor and replaying completed trajectories with an equally sized provenance map; introduce delays crossing two splits. Count pending records in every arm.
- **Old-task retention:** Return to A/B after the backlog clears, including archived action classes that share a destination but should receive opposite corrections.

### SMA24 · Move a shared dependency as one cut with several destinations
- **Mechanism:** Rewrite a producer and the consumers that share its latent convention as one joint graph move. Search for a cut whose affected consumers can all be retargeted under a *single* convention change; a second edit may operate on any resulting branch without retaining the cut's old endpoints.
- **Nearest prior / gap:** [Weaves, Wires, and Morphisms](https://arxiv.org/abs/2604.07242) formalizes graph wiring and morphisms for learning systems. The candidate is inference of a minimal joint cut from streaming examples and the availability of subsequent edits, not the algebraic fact that diagrams compose.
- **Cheapest first test:** Change a shared representation used by three partially overlapping symbolic tasks. Compare single-edge retargeting and simultaneous independent fits with the same candidates and cost, including a case where no common map exists. Hold out a later task that reconnects two consumers.
- **Old-task retention:** Evaluate all old consumers, especially uncommon branches where a locally valid retargeted edge uses a convention inconsistent with its peer.

## D · Change the language of learning, not its step size

[Backpropamine](https://arxiv.org/abs/2002.10585), [VSML](https://arxiv.org/abs/2012.14905), [Irie et al.'s self-referential weight matrix](https://arxiv.org/abs/2202.05780) and [Automated Continual Learning](https://arxiv.org/abs/2312.00276), and [AutoHebb](https://arxiv.org/abs/2610.40757) already put part of the update rule inside the model. [Gödel Machines](https://arxiv.org/abs/cs/0309048) formalizes proof-based self-rewrites; the [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) empirically tests code changes in an evolving agent archive. The bets here give learning rules new composable inputs, outputs or semantics. They do not introduce optimizer buffers, schedules, or a general benchmark-driven self-editor.

### SMA25 · Teach a learning rule a new kind of evidence
- **Mechanism:** Attach a typed interpreter for a new feedback message (for example, “this example compares two outcomes,” not “this is the right label”). The interpreter emits an update expressed in the consumer's existing local semantics. Leave the rule for old messages intact.
- **Nearest prior / gap:** [AutoHebb](https://arxiv.org/abs/2610.40757) lets a neuromodulator combine external feedback with internal activity to gate a local Hebbian rule. The candidate is extending the rule's *message algebra* and composing interpreters without retraining the meaning of every feedback source.
- **Cheapest first test:** Start a tabular preference learner with exact labels, then introduce paired comparisons and later abstentions. Compare a fixed concatenated-feedback learner and a single rescoring model under identical message data and capacity. Hold out mixed message sequences.
- **Old-task retention:** Check old classifications after comparison training and query the old label channel again to ensure it still teaches subsequent old examples as intended.

### SMA26 · Grow a new teaching edge by changing who predicts what
- **Mechanism:** A downstream component turns an intermediate consequence it can predict into a named local target for its producer. The producer learns to predict this consequence in addition to its existing output; only downstream consumers that use the consequence teach it.
- **Nearest prior / gap:** [Difference Target Propagation](https://arxiv.org/abs/1412.7525) sends targets to hidden layers. The proposed separation is inventing an auxiliary prediction *with a new consumer and independent learning lifetime* from repeated failures, not using a different gradient surrogate for a fixed objective.
- **Cheapest first test:** A tabular delivery controller gets delayed failures from depleted capacity. Let a component invent a pre-delivery capacity prediction; compare full return learning, ordinary target propagation, and a preallocated auxiliary set with equal labels and writable state. Test transfer to a second route.
- **Old-task retention:** Run old routes where the consequence is irrelevant and an old constrained route where it matters under a different input distribution.

### SMA27 · Peel a learning clause out of a learned updater
- **Mechanism:** Extract a small executable rule for a recurring class of updates, then replace the original update path on that class with the extracted clause. Allow a later learner to alter that clause without changing the behavior of the updater elsewhere.
- **Nearest prior / gap:** [AutoML-Zero](https://proceedings.mlr.press/v119/real20a/real20a.pdf) searches executable learning algorithms from elementary operations. Here a clause is derived *from the live updater*, installed in one domain, then tested on whether it can be revised independently. Pure rule distillation and symbolic search are controls.
- **Cheapest first test:** Extract a bounded rule from a tiny learned updater that handles both noisy labels and exceptions. Compare equal-size whole-rule distillation and a symbolic learner given the same traces. Introduce new exceptions and revise only the extracted clause.
- **Old-task retention:** Score old noisy examples and old exceptions after both surgeries; test held-out old updates as well as the predictions before feedback.

### SMA28 · Make edit authority follow the source of evidence
- **Mechanism:** Give an event a subset of the learning graph it may modify, inferred from which components generated and consumed its consequences. On a graph split, transport and subdivide that authority with the operation, not with a frozen node ID. A newly attached consumer can ask for a new path without gaining implicit authority over the old producer.
- **Nearest prior / gap:** [Reward Tampering Problems and Solutions](https://arxiv.org/abs/1908.04734) analyzes causal paths by which agents can influence reward. [PackNet](https://arxiv.org/abs/1711.05769) freezes selected parameters. The candidate is movable, source-specific authority over legitimate updates, not a new tampering detector or global write mask.
- **Cheapest first test:** Supply contradictory annotations from two independent components of a toy sorter, then split a producer both used. Compare fixed-source update masks and an unrestricted learner with matched writable slots. Introduce a legitimate correction through only one source post-split.
- **Old-task retention:** Re-evaluate old decisions supported by both sources, including examples for which one source should still be able to correct the shared behavior.

### SMA29 · Compile a joint update only when separate rules conflict
- **Mechanism:** When two local rule applications produce incompatible shared states, synthesize one joint rule that consumes the pair of evidence messages and reconciles their semantic constraints before either write. Keep the individual rules on non-overlapping cases. This is a new arity of update, not a priority order over updates.
- **Nearest prior / gap:** [VSML](https://arxiv.org/abs/2012.14905) learns local recurrent computations that communicate to implement a learning algorithm. The proposed operation creates a particular multi-source update node *because* the independently supported constraints cannot be satisfied by serial rule application; no novelty if ordinary joint loss ties.
- **Cheapest first test:** Use a tiny model with a shared integer slot updated by two rules whose individual choices are order-sensitive. Give the joint node and a joint-loss control the same constraint language; require held-out message pairs where the joint node is not simply majority vote or serial application.
- **Old-task retention:** Maintain old single-source behavior after fusion and old pairs where either ordering used to be correct.

### SMA30 · Learn a relation that tells another module how to generalize
- **Mechanism:** One module can emit an executable equivalence condition on examples for another module's update rule. Revise that condition when a new pair breaks it, without modifying the learned predictor directly. The result changes which future examples are treated as the same evidence.
- **Nearest prior / gap:** [Learning Algebraic Recombination](https://arxiv.org/abs/2107.06516) learns operations to make synthetic training examples. The proposed object is a revisable equivalence attached to the recipient's learning graph, not a generated batch; equivalent augmentation and metric learning are controls.
- **Cheapest first test:** A symbolic learner ties counts across mirrored symbols until a new context breaks a subset of those symmetries. Compare replay with augmentation, a learned embedding for tying, and an explicit update equivalence with the same examples and bytes. Test a later split of the equivalence.
- **Old-task retention:** Check old mirror variants after the split, including old coincidences that must remain tied and rare exceptions that never should have been tied.

### SMA31 · Grow a rule that learns from incompatible corrections without averaging them
- **Mechanism:** Give a correction a conditional scope discovered from its conflict with another correction. Compile the discovered distinguishing condition into the learning rule so the next correction may apply to either scope without fitting or overwriting the other. Prediction alone need not bifurcate when the scopes differ only in *what evidence would change it*.
- **Nearest prior / gap:** [Irie et al.'s Automated Continual Learning](https://arxiv.org/abs/2312.00276) metalearns in-context adaptation and retention in a self-referential matrix. Here the primitive exposes the learned scope as an addressable executable part of the rule; a fixed-size context-conditioned self-referential learner with the same observations is a control.
- **Cheapest first test:** Give two finite learners identical outputs but different valid correction conditions in successive contexts. Compare putting the distinction in the predictor, the update rule, or a recurrent shared learner at matched total state. Infer scope from delayed context evidence, not labels revealing the generating task.
- **Old-task retention:** Test old predictions and briefly branch the evaluation to replay valid and invalid old corrections, then score held-out old episodes; don't use these branches for edit selection.

### SMA32 · Rewrite the editor by handing it less authority
- **Mechanism:** The agent can replace one broad graph-edit operator with narrower, composable operators that govern disjoint kinds of subsequent edits. The running system ceases to have the broad operator. One narrower operator can be redesigned without restoring its sibling's authority or copying a predecessor.
- **Nearest prior / gap:** [Gödel Machines](https://arxiv.org/abs/cs/0309048) already rewrite the mechanism for finding rewrites; [RSIFlow](https://arxiv.org/abs/2610.21791) evolves a meta-agent that selects component-specific improvement workflows. The test here is a lasting decomposition of the *operation language* that trades reachability for localized adaptation under a fixed toy evaluator, not recursive self-improvement or component-specific workflow selection in general.
- **Cheapest first test:** Give a finite workflow learner an editor that can initially touch feature and action subgraphs. Let experience suggest splitting those edit languages, then teach a new action. Compare a fixed typed editor with the same grammar, full-edit filtering, and archive-and-restore at equal search and storage budgets. Include a shift that really needs a cross-boundary edit.
- **Old-task retention:** Re-run old feature-dependent jobs after each rule change and check that ordinary old task updates remain expressible without regaining the retired broad editor.

## Ranked deeper questions

1. **What is the smallest architectural edit that preserves both old behavior and the ways old behavior can still be taught?** Start with SMA13, SMA23, and SMA31. Construct two graphs that agree on every old query at the edit but disagree after one ordinary old feedback sequence. Ask whether a representation of that feedback interface predicts which edits survive later shifts better than replay on the same budget. An exhaustive finite witness can kill equivalence-by-prediction; it cannot by itself show that the interface is learnable.
2. **When does a structural change produce capacity that an equally sized static supergraph cannot buy?** Pair SMA01 and SMA09: split on a witnessed continuation, later remove the shared component by distributing its necessary state. Count peak state, edit descriptions, and execution work across several reversals. Drop the capacity claim if a fixed sparse supergraph with the same data and budget ties across shifts.
3. **Can unfinished work be migrated from behavioral evidence without carrying a predecessor?** Compare SMA17's queued messages and SMA18's partially discharged obligations. Find a stream on which the missing distinction can be inferred from ordinary execution, and a paired stream whose hidden commitments make it impossible. The primitive is only useful if the learner can separate the two without a privileged state dump.
4. **Can changing which evidence means what beat changing which module is selected?** Compare SMA25, SMA29, and SMA30 against a router with the same candidate rules and observations. Look for transfer to a held-out combination of evidence sources without new modules or a supervision oracle. If a fixed rule interpreter over the same messages buys the same adaptation and old-task retention, don't escalate to a self-rewriting editor.
