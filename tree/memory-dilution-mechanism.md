# Node: memory dilution — when adding correct lessons breaks old ones

Parent: [agent memory, PR #89](https://github.com/manojbajaj95/cl/pull/89). Question: which part of the reader erases a valid rule, and what would let a reader keep learning without erasing old effects?

## Root cause

**Separate keys isolate the facts in the store, not their effects in the reader.** The parent puts the whole store in one causal prefix and scores the next token of a frozen model. Adding a rule neither overwrites old data nor changes weights, but it changes the computation that binds a query to a value and turns that value into a decision. The old rule has no protected read or execution path. This is a demonstrated architectural failure mode; the mediator (attention competition, position, or downstream deference) is not yet identified. An escape needs **non-interference for unrelated writes and explicit composition for jointly relevant writes**; guaranteed additivity of every effect would rule out useful interactions too.

### What the parent data support

Recomputed from [the probe and its JSON results](https://github.com/manojbajaj95/cl/tree/631025a6f17bd4142eca36e7aaa91f123f85d7d6/tree/probes). The distractors assign correct queues to *other* keys; for each probed item at each store size the script shuffles the rules once. Scores are restricted to the six queue tokens; margin is the target logit minus the highest competing queue logit (which need not be the same competitor in different conditions).

|---|---:|---:|---:|---:|---:|---:|---:|
| 0.5B | 24 (4 seeds) | −2.98 | +4.19 | +1.32 | +0.12 | +0.05 | 100% → 54% |
| 1.5B | 18 (3 seeds) | −0.97 | +8.37 | +7.13 | +4.91 | +3.09 | 100% → 83% |

- The headline **99% / 63%** is the fraction of *positive solo margin* lost, not the fraction of memory uplift over no memory. Subtracting the empty-store mean first gives about **58% / 56%** of measured uplift lost. At 48, the rule still helps compared with empty; the empty arm also differs in length and content, so neither percentage isolates the rule's causal contribution at fixed load.
- **Check against a simple recency story:** at 48 rules, split the logged normalized line position into thirds. Mean paired changes from solo (early / middle / late) are −3.93 / −4.09 / −4.42 logits on 0.5B (7 / 10 / 7 items) and −3.17 / −6.00 / −6.65 on 1.5B (6 each). The late bin is not spared and does not beat the early bin. This argues against a simple “closer always rescues” account, not against positional effects in general. The bins contain different items, lack exact token positions, and do not hold load fixed *across* store sizes.
- **Check against “the override gets pushed away”:** with zero unrelated rules the explicit UPDATE remains last, with the same suffix. From one old copy to eight, constrained P(new) goes .384 → .299 (0.5B) and .973 → .810 (1.5B); P(old) rises .345 → .406 and .024 → .165. This refutes distance *from the final update to the query* changing in that arm. The update's absolute position, repeated-key competition, and the apparent amount of old evidence still change together. This is a separate, deliberately conflicting experiment; it does not prove authority weighting causes the non-conflicting result.

### Cheapest discriminating follow-up (proposed, not run)

Use a subset of the parent's items and all variants of each item. Replace the target rule with an equal-token inert span to measure its incremental effect at fixed load; record target versus each fixed rival, six-way accuracy, and the unrelated distractors' queue histogram. Hold that histogram balanced or rotate it (otherwise repeated queue values can bias the output without any loss of target attention).

| Candidate and reachable path | Intervention and what would distinguish it |
|---|---|
| **Attention competition.** Every late query token can attend to the memory prefix. Even if the target score stays fixed, its softmax mass falls if other spans add to the denominator; incorrect bindings or competing values are alternatives. | Freeze target/query token positions and switch equal-token slots from inert text to syntax-matched wrong-key rules. Inspect target score, denominator, and target-value contribution in candidate binding heads selected on separate items. In the loaded forward pass restore just the target contribution to its fixed-position low-load value while leaving other contributions intact; compare norm-matched wrong-span patches and rival-value patches. A target-specific recovery with stable raw target scores favors normalization loss; recovery only by swapping the value implicates misbinding. Attention mass alone is not causal evidence. |
| **Position/propagation.** Shuffling changes where the rule is encoded and its distance to the query; relative positions and intervening tokens can affect copying even without similar keys. | In fixed-length templates rotate the same target and equal-token distractor blocks through beginning/middle/end across the *same* items; separately vary rule-to-query gap using non-rule tokens and shift rule and query together. If insertion of unrelated active slots hurts similarly at matched positions, position alone fails; if moving blocks predicts loss with distractors held fixed, position contributes. Check that the tokenized spans really match. |
| **Deference after binding.** A reader may know which value a record says yet not execute it, e.g. treat a repeated instruction as more authoritative than a later correction. | Cross raw vs explicitly authoritative source tags with slot-matched repeated vs unique episodes. Use paired forced-choice “what does this record say?” and “which queue should be used?” queries, and check the bound value in the original action prompt with a value-swap intervention learned/tested on separate items. If binding survives and authority changes action but not bound value, test a downstream arbitration mediator against random directions. An extraction prompt alone is not evidence that the action prompt computed the binding. |

Measure all interventions on held-out items and report uncertainty across store seeds, not pooled variants as independent. A factorial control is useful because release of attention competition could also change apparent authority. Do not rank the three mediators by the raw position bins: the code establishes the shared read is reached, but the logged outputs do not identify a circuit.

### Where write-skew starts, and where the analogy stops

[Expanded top-10 #3](https://github.com/manojbajaj95/cl/blob/3d72df549945f5aa243baa399c954ee9628374db/reviews/flood-top10.md) extends [SD3 in PR #58](https://github.com/manojbajaj95/cl/pull/58): writes that pass retention separately can break it together. Here a “write” appends to the store; it is not a gradient update. PR #89 motivates the anomaly but did not check each singleton or pair at a fixed retention tolerance and cannot establish a genuinely three-way effect. Several small additive losses can cross a retention threshold and look like write-skew.

Keep an old rule A fixed. Pre-register a floor on held-out old-task margins and correctness. For a fixed new triple B,C,D, evaluate all eight subsets of it over A, using matched placeholders in unused slots and the same positions, query, and rival for each contrast. A strict triple witness keeps A above the floor for *all* proper subsets and drops it below for BCD. Separately compute the interaction contrast `m(BCD) − m(BC) − m(BD) − m(CD) + m(B) + m(C) + m(D) − m(∅)` on continuous fixed-rival margins (the store always contains A). Compare it with matched disjoint filler triples and a count-only curve fitted on other stores; a nonlinear count effect can also give a nonzero contrast. If filler/count explains it, target generic load sensitivity; if identity matters, compare an interaction-aware write against pairwise guard and serialized re-derivation at equal new-task success. Test LoRA separately only after establishing the context result; similarity across substrates is not assumed.

## Guardrails for the idea pool

Read the [idea ledger](https://github.com/manojbajaj95/cl/blob/3d72df549945f5aa243baa399c954ee9628374db/reviews/idea-ledger.md), [flood triage](https://github.com/manojbajaj95/cl/blob/3d72df549945f5aa243baa399c954ee9628374db/reviews/flood-triage.md), and expanded top-10. Do not revive learned per-lesson attention bias (M2), layer-local KV visibility (ledger N1), static lesson valuation (G1/Q2), implicit edit cosine (B3), double dosing, sparse syndromes, or private shorthand. Attention changes above diagnose mechanisms, not a new salience method. Also do not claim the parent's additive reader, solo logit sum, or scope gate as new. Closest reference points: [Lost in the Middle](https://arxiv.org/abs/2307.03172) already measures position effects, [Focused Transformer](https://arxiv.org/abs/2307.03170) tackles external-memory key distraction, [PCED](https://arxiv.org/abs/2601.08670) separates documents and aggregates at decoding, and [LatentSkill](https://arxiv.org/abs/2606.06087) already compiles text skills into adapters. These are proximity checks, not exhaustive novelty claims.

All cards are raw hypotheses for future work, not results. Default CPU world: a sequential stream of small routing/permission rules, including joins (type → region → service → queue), exceptions, independent tasks, and scoped revisions. Hide the complete join key until execution where appropriate. Keep old paraphrases, old multi-hop tasks, and out-of-scope tasks disjoint from writing/verification data. A valid scoped revision changes the intended users only; a method gets no retention credit for suppressing a correct revision. Match bytes (including indices and side state), input tokens, reader calls, and new-task success; report the compute/retention frontier when all cannot be matched. Baselines include append-all, keyed top-1 on unary lookup, exact-key multi-hop and strong top-k retrieval on joins, raw replay, and isolated solo-effect sum. When attributing language-model gains to lesson content, also match entropy with a no-lesson temperature arm. An exact symbolic table is an oracle on literal rules and the relevant baseline whenever the structure is given.

## Raw ambitious ideas

1. **Write a retention debit, not a relevance score.** Mechanism: each accepted write spends a one-sided bound on *lost margin* in a class of previously learned queries, including interaction allowances; the reader publishes how much slack remains and may re-express both writes to recover it. Why it might be new: an explicit consumable read guarantee rather than serializing observed conflict pairs (SD3) or predicting whether a write is safe in isolation. First test: enumerate small three-write bundles; compare retention and acceptance to a pairwise guard and full bundle checks at equal audits. Retention: minimum held-out old margin and violations after bursts of accepted writes.
2. **Split only at a demonstrated collision.** Mechanism: when an old action flips, try to split the *query state* into two independently read states using a distinguishing continuation; allocate a new state only if the continuation also predicts unseen spillover. Why it might be new: subdivisions reflect measured non-interference of executable states, not novelty of keys, edits, or activation clusters. First test: stream compact permission machines with homonymous roles; compare learned splits to exact-key tries and supervised clustering at equal states. Retention: old trajectories across a split, including unseen aliases on both branches.
3. **Separate binding from authority with a constrained interface.** Mechanism: a reader emits an evidence-indexed binding plus a provenance event ID; a separately trained resolver can decide applicability but cannot replace the bound value. Why it might be new: authority is testable conditional on a frozen binding, not a learned trust multiplier on an opaque note. First test: tiny model on identically worded synthetic rules and contradictory histories; swap bindings while holding sources fixed, versus an end-to-end role-tagged reader. Retention: old action margins on valid unchanged sources after many authority changes elsewhere.
4. **Evidence ancestry as a quotient.** Mechanism: aggregate independent events, not repeated mentions; split an ancestry class when later evidence shows two mentions had independent origins. Why it might be new: evolving independence classes give semantics to repetition that provenance-only deduplication and fixed Bayes factors do not. First test: scatter paraphrases and independent corroborations through a revision stream and compare with text dedup and known-source counting under noisy IDs. Retention: old correct decisions whose true corroboration must not be washed out by duplicate reports elsewhere.
5. **Memory calls with an effect return channel.** Mechanism: each called rule returns a value *and* a typed residual query about what could change it; the caller executes that query only when a future write matches it. Why it might be new: storage is indexed by open semantic dependencies produced at execution, not just an input key or a fixed dependency graph. First test: route through default and exception edges inserted out of order; compare against a dependency-indexed incremental executor with fixed signatures. Retention: disjoint old join outputs after filling many residual queries.
6. **Join by projection, not by extra text.** Mechanism: learn an operator that projects a pair of returned values into the minimum state needed for the next lookup, dropping distinctions irrelevant to *all known continuations* and reopening the class when a new continuation distinguishes it. Why it might be new: quotienting intermediate meaning rather than an edit's endpoint effect or text length. First test: a finite protocol with long redundant descriptions; compare to a fixed bottleneck and learned dense retrieval at equal bytes. Retention: old multi-hop paths through both the collapsed and subsequently reopened states.
7. **Retention via two-sided output bounds.** Mechanism: each rule emits action-score intervals, and the reader only resolves an action once its lower bound beats every other upper bound; uncertainty can be refined by reading further rules. Why it might be new: it is the *unread relevant set* that gets an explicit residual bound, not an item confidence used for gating. First test: bounded-score joins with an unknown number of remaining exceptions; compare against fixed top-k and deterministic branch-and-bound with the same bound information. Retention: false old-action flips and unresolved old reads at a fixed coverage and read budget.
8. **Derived clauses with a writable validity separator.** Mechanism: a compressed clause is a pair of shared effect and a minimal separator describing the situations where the effect must stay separate; when it fails, rewrite the separator before the effect. Why it might be new: compaction preserves distinctions needed for future reads, rather than compressing text or matching fixed behavioural fingerprints. First test: learn regions of a tiny decision table under delayed exceptions; compare to decision-tree updates and recompiling the compressed rule from scratch. Retention: previous exception boundaries on cases not used to fit the separator.
9. **Probe-to-protocol escalation.** Mechanism: two mutually inconsistent read traces cause the memory to save the shortest *state intervention* that disambiguates them and insert its result as a new dependency of both reads. Why it might be new: an experiment becomes a reusable composition operand, not a pre-write check or learning example. First test: hidden service states where several policies look equivalent until one targeted toggle; compare with entropy-selected extra observations and oracle probe selection without a reusable result. Retention: old tasks sharing only a subset of affected states after the experiment.
10. **Local repair via rejected parses.** Mechanism: persist what interpretation lost against each stored rule and under which observation; on a later update, reconsider only rejected interpretations that the new observation discriminates. Why it might be new: a ruled-out parse is executable read state with a revival condition, not a rival label kept as replay. First test: a tiny grammar with intermittent aliases and changed defaults; compare to maintaining an n-best parse beam and replay. Retention: previous unambiguous commands and other ambiguous families after a partial reinterpretation.
11. **Decision-invariant boundary transport.** Mechanism: when updating a shared predicate, learn how its boundary moves and carry forward old downstream decisions for points proven not to cross; rewrite only the crossing units. Why it might be new: transport is of a read dependency under changing predicates, not adapter alignment or fixed probes. First test: half-space scopes feeding Boolean rules, including cases where small shifts move many points; compare to full recomposition and point replay. Retention: held-out old decisions on both sides and near the moving boundary.
12. **Counterfactual access costs.** Mechanism: charge a write for how many extra reads an old decision needs to remain provable, not only for wrong decisions; choose between changing representation and paying the extra cost. Why it might be new: deterioration of the *minimal old computation* becomes a write constraint even if accuracy is still perfect. First test: progressively add correct exceptions to short permission proofs; compare against utility/latency re-ranking and cached proofs. Retention: old success under the original call cap after repeated writes, and uncapped success separately.
13. **One-of-many semantics instead of a soft average.** Mechanism: store sets of acceptable next actions and resolve their intersection across independently read obligations before using an actor's prior to pick among survivors. Why it might be new: ambiguity survives intermediate joins and can be narrowed by later evidence, rather than selecting one teaching label or adding logit vectors. First test: sequential partial constraints with held-out intersections; compare to a set-valued critic and an exact constraint solver given the same extracted facts. Retention: old feasible intersections remain reachable and old forbidden actions remain excluded.
14. **Memory holes as explicit no-effect sentinels.** Mechanism: train the reader to emit an out-of-band “no binding” result for genuinely irrelevant records; test it by intervening on the value behind a no-binding result and checking invariance. Why it might be new: non-applicability has an interventional semantics rather than a calibrated relevance score. First test: train a tiny reader on matched positive and near-miss rules, compare with hard retrieval and null-token supervision without swaps. Retention: old positive bindings and old no-effect queries as near-miss writes accumulate.
15. **Re-executable state transformers.** Mechanism: write small transition fragments with explicit pre/post read state; compose a fragment by applying it to the state produced by a prior fragment rather than reinjecting both demonstrations. Why it might be new: an operator extracted from a lesson must work on states reachable only after *later* learning, not just its local train support (or additive output nudges). First test: learn fragment descriptions from partial demonstrations in a finite workflow with unseen orderings; compare to tool execution with hand-written schemas and equal-budget sequential reader calls. Retention: original workflows and old fragments embedded in novel sequences after extra writes.
16. **Binding checkpoints scoped to one decision.** Mechanism: memoize commitments only inside the current read; a later hop must explicitly invalidate a binding and give the evidence that justifies recomputing it before it can change the action. Why it might be new: transactional semantic stability within inference, not model checkpoint addressing or a cache keyed on prompt identity. First test: route multi-step queries where unrelated later hops repeat the key, plus real overrides; compare to invariant prompting and a per-query immutable cache. Retention: old paths with legitimate overrides and those with only lookalike repetitions.
17. **Scope refinement by symmetric differences.** Mechanism: partition the query space into old only, new only, both, and neither; learn a separate rewrite for the overlap while preserving old-only behavior and installing the new behavior on new-only cases. Why it might be new: a learned rewrite is decomposed into independently testable effects on scope partitions, not ranked by average spill. First test: compositional synthetic attributes with intersecting exceptions and held-out combinations; compare to independent edits plus oracle filtering and learned scope gates. Retention: worst-region old accuracy, not just pooled accuracy.
18. **Compaction with a disagreement oracle.** Mechanism: replace a substore only if an independently generated distinguishing continuation fails to separate old and compact representations; store the found distinction as a live read split when one exists. Why it might be new: compactness concerns future *read composition*, not one-step outputs or equivalence of weight edits under future optimizer updates. First test: exhaustively check finite workflows against a bounded continuation generator; compare to fixed probe signatures and raw store at equal verification calls. Retention: old behavior under withheld continuations as later lessons extend workflows.
19. **Memory as scoped substitutions.** Mechanism: compile each lesson into a substitution on an identified variable in a partial reasoning trace; only occurrences in its scope are bound, and conflicting substitutions leave a residual query rather than globally rewriting tokens. Why it might be new: existing weights-as-program work doesn't make variable capture in a changing external memory a measurable failure. First test: nested permission inheritance with two variables sharing a name; compare to static alpha-renaming in a symbolic executor and an LM with unique IDs. Retention: held-out older nested cases after adding same-name bindings in a different scope.
20. **Compose through minimal separators.** Mechanism: learn which intermediate variables actually mediate interaction among lesson families; serialize only summaries at learned separators and query the full local record on a failed separator check. Why it might be new: budgeting semantic cross-family communication, not partitioning a KV cache or clustering similar items. First test: graph-generated tasks with known separators and spurious text overlap; compare to graph retrieval and factor-graph inference at matched calls. Retention: older cross-family joins (including rare bridge cases) when irrelevant families expand.
21. **Write a reversible partial operation, not its undo text.** Mechanism: discover an operation together with a domain-restricted inverse, using the inverse to detect which older intermediate decisions a change *cannot* be safely unwound through and which need a fresh read. Why it might be new: inversion exposes loss of information at multi-hop joins; restoration is neither exact by construction nor a parameter save/restore stack. First test: mixtures of bijective and many-to-one rule transforms; compare against dependency replay and a full trace log at equal bytes. Retention: which old branches actually return after selective revision and reversal.
22. **Grow independent lanes only on proven coupling.** Mechanism: start one cheap read lane; for a confirmed identity-sensitive collision, split execution state, then expose only an explicit join variable between lanes. Collapse lanes if a held-out composition test cannot distinguish isolation from sharing. Why it might be new: the learner changes the topology of *semantic communication* on a causal collision, not a per-layer visibility mask or MoE task router. First test: tiny executor with disjoint casts followed by necessary cross-lane joins; compare against static lanes, retrieval, and independent experts plus a join model. Retention: old within-lane and cross-lane success as load grows and lanes are merged.
23. **Learn to read a requirement before a value exists.** Mechanism: emit a deferred binding with a type and admissible values, update it when later evidence arrives, and have unresolved reads abstain rather than inherit a distractor's value. Why it might be new: the persistent object is an executable partial read with explicit unresolved obligations, not a group of candidate policies or fixed uncertainty tag. First test: stream initially missing edges into a small routing graph; compare to ordinary missing-value handling and delayed retrieval with typed keys. Retention: old resolved joins remain resolved, and old unresolved joins get resolved only by valid bindings.
24. **Require independent witnesses for learned alias transport.** Mechanism: separate a semantic alias assertion from the rule it transports; allow propagation only after an intervention makes alias and lookalike hypotheses predict different continuation states. Why it might be new: it taxes *cross-rule evidence reuse* rather than gating arbitrary lessons by confidence, and makes false transfer countable. First test: matched routing ontologies with intentionally confusable synonyms, versus embedding nearest-neighbor plus the same intervention budget. Retention: previous alias-dependent joins and protected non-alias joins after learning later names.

## Deeper sub-questions, ranked by chance of yielding a primitive

1. **Can a store make old effects composably safe under a sequence of accepted writes, without checking all subsets or declining useful writes?** Start with the fixed-load triple contrast; if identity effects transfer, test spent retention slack (1) and separating read state (2, 20, 22). If a count model or greedy serialization ties at equal acceptance and compute, there is no evidence for a new interaction primitive.
2. **Can binding, applicability, and action authority be learned as independently intervenable parts of one read?** The factorial diagnostic decides what interface to protect; test (3, 4, 14, 16). The differentiator is intact causal binding with correct action under irrelevant writes and scoped revisions, not higher confidence or better extraction alone.
3. **What information must the result of one read carry to compose with later, previously unseen lessons?** Compare value-only exact multi-hop against explicit unresolved obligations or execution states (5, 6, 15, 23). If the same join can be carried by a value or program at equal cost, the extra object is unnecessary.
4. **Can a learner discover the boundaries across which compaction, scope change, or aliasing is unsafe?** Try (8, 11, 18, 24) only where static scopes and fixed witnesses fail on future compositions. Measure retained old boundary cases and new coverage; replay or recompute is the control, not append-all text.
