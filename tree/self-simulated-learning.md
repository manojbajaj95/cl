# Node: can a model simulate its own learning, and can edit effects be grouped into finite behaviour classes?

Parent: [PR #63, edit simulator](https://github.com/manojbajaj95/cl/pull/63) (`tree/edit-simulator.md`), sub-questions 3 (small twin or self-prediction) and 4 (quotient into finite behaviour classes).

Question: can a model simulate its own learning, with a small shadow twin or by predicting its own post-edit outputs? Can edit effects be grouped into a finite set of behaviour classes so that editors search over effects instead of weights?

Ideation only. No experiments were run for this node.

## Root cause

**Every current simulator, whether twin, self-predictor or effect cluster, models one map: edit → change in outputs at the endpoint. Learning is a second map: edit → change in how the model will respond to the *next* edit. Endpoint outputs do not identify the second map, so nothing trained or clustered on them can carry it. Forgetting lives in that second map. This is the parent's "response drift", seen from the simulator's side.**

Three parts:

1. **An output twin is not a learning twin.** How a model responds to an update is set by its gradient geometry (the empirical NTK between new and keep inputs, and how that kernel moves), not by its outputs. Two models with identical outputs can have different kernels, and distillation matches outputs only. In the kernel regime, fine-tuning is kernel regression ([2210.05643](https://arxiv.org/abs/2210.05643)). Per-example learning dynamics decompose into exactly this kernel term plus a residual, including the "squeezing" effect that pure output views miss ([2407.10490](https://arxiv.org/abs/2407.10490)). Small proxies also differ from large models in what makes them forget: capacity and interference decide which rare tasks survive ([2605.29548](https://arxiv.org/abs/2605.29548)), and proxy-run decisions transfer unreliably to full scale ([2512.24503](https://arxiv.org/abs/2512.24503)). So a small twin is most wrong exactly on rare old behaviours, which is the retention question.
2. **Self-prediction today is post-hoc and not covariant with edits.** Models can describe behaviours they *already* learned (behavioural self-awareness [2501.11120](https://arxiv.org/abs/2501.11120); introspection adapters [2604.16812](https://arxiv.org/abs/2604.16812); self-awareness shifting with realignment [2602.14777](https://arxiv.org/abs/2602.14777)). They predict their own current behaviour better than other models can ([2410.13787](https://arxiv.org/abs/2410.13787)). That is a readout of the present weights, not a forward model of the update operator. A self-simulator also has a self-reference problem: the edit it forecasts changes the forecaster too. Nothing requires the forecast to stay calibrated after the model applies the edit, so its accuracy is valid for one step at most.
3. **Static effect classes are not closed under composition.** Clustering edits by their measured effect on a probe set (datamodels [2202.00622](https://arxiv.org/abs/2202.00622); latent-trait decompositions of dataset interactions [2509.13624](https://arxiv.org/abs/2509.13624); behavioural couplings [2610.23847](https://arxiv.org/abs/2610.23847); the parent's edit-effect hash) gives a partition that is only valid *now*. Two edits with the same immediate effect can leave different kernels, so a later third edit separates them. For a class to be a valid search unit, it must be a **congruence**: equivalent edits must stay equivalent after any continuation (the Myhill–Nerode condition). The ledger already shows the failure. In Fleet Q2/Q3, exact outcome scores did not give classes that were stable across task halves (nine sign flips), and A3 showed that the same margin need not mean the same editability. Narrow fine-tunes generalising broadly (emergent misalignment [2502.17424](https://arxiv.org/abs/2502.17424)) is the same fact at the behaviour level: the current effect understates the reach of the class.

So the missing object is a **learning state**: the smallest description of a model that predicts both its current outputs and its responses to future edits. Twins, self-predictors and effect classes each approximate the output half. The primitive this node is after is a representation (twin, head or quotient) whose equivalence is defined by *future* behaviour under learning, with retention as the observable.

### Evidence from papers

| Paper | Finding relevant to the root cause |
|---|---|
| Kernel view of LM fine-tuning [2210.05643](https://arxiv.org/abs/2210.05643) | Prompt-based fine-tuning is often well described by the eNTK, so learning response is a kernel property, not an output property. |
| Learning dynamics of LLM fine-tuning [2407.10490](https://arxiv.org/abs/2407.10490) | Decomposes the effect of learning one example on others into kernel × residual terms; explains squeezing and hallucination drift that endpoint views miss. |
| Why larger models learn more [2605.29548](https://arxiv.org/abs/2605.29548) | Capacity and interference set rare-task retention, so small twins diverge from big models where forgetting matters. |
| Rethinking proxy-model practice [2512.24503](https://arxiv.org/abs/2512.24503) | Small-run proxies can misguide full-scale data decisions; scale changes the learning response. |
| Looking Inward [2410.13787](https://arxiv.org/abs/2410.13787) | Models predict their own behaviour better than other models trained on that behaviour; a readout of present weights. |
| Tell me about yourself [2501.11120](https://arxiv.org/abs/2501.11120), Introspection Adapters [2604.16812](https://arxiv.org/abs/2604.16812) | Models can report behaviours already learned by fine-tuning; post-hoc, not prospective. |
| EM self-awareness shifts [2602.14777](https://arxiv.org/abs/2602.14777) | Self-report tracks realignment, so the self-model is re-read after each change rather than forecasting it. |

| Emergent misalignment [2502.17424](https://arxiv.org/abs/2502.17424), trait-space monitoring [2606.07631](https://arxiv.org/abs/2606.07631) | Narrow edits land in broad behaviour classes; the class reaches beyond its measured immediate effect. |

## Raw ideas (no self-filtering)

Each entry gives a mechanism, why it is new, and the cheapest first test, which always includes a retention check. Do not re-pitch the PR #6/#63 neighbours: hypothetical fine-tuning query (PR #42 D3), body double (W6), verbal self-forecast (SM30), counterfactual twin (SM34), the parent's shadow twin (#7), self-simulation of post-edit outputs (#18) and edit-effect hash (#21). Where an idea is close to one of them, it says what differs. Shared baselines for every test: a constant forecast, the first-order response model, a static probe-effect hash, and real short branches at equal verifier cost.

1. **Nerode edit quotient.** Two edits are equivalent iff, for every continuation edit in a test family, the resulting probe behaviour matches within tolerance ε. Classes are refined by splitting whenever some continuation separates them (partition refinement). *New:* classes are defined by future response, not by immediate effect, which makes them a congruence that editors can safely compose. Static hashes (#21) are the coarser, non-congruent version. *First test:* GPT-2 small with ROME edits on 200 CounterFact facts. Build static-effect clusters and Nerode classes, using a family of 20 second edits as continuations. Compare how well each predicts the second edit's effect on 500 held-out old facts (retention) and on rare-relation facts.

2. **L\* for the learning automaton.** Treat model + editor as a black-box automaton whose alphabet is edit classes and whose output is the probe vector. Run Angluin's L\* with membership queries (real edits) and equivalence queries (random edit sequences) to learn a finite automaton of learning states. *New:* this is active automata learning applied to a network's own learning process, and the state count is a measurable "learning complexity". *First test:* a toy MLP on 5 sequential tasks with 8 edit classes. Learn the automaton, then predict old-task accuracy after held-out sequences of length 6 against a first-order rollout.

3. **Kernel-matched learning twin.** Distil a small twin to match the big model's eNTK Gram matrix on (new ∪ keep) probes, using random-projection gradient sketches, instead of matching outputs. Edits are then trialled on the twin. *New:* it distils the *learning operator*, not the function. W6 matched observed per-update changes; this matches the generator of all of them. *First test:* Pythia-70M twin of Pythia-410M with three twins: output-distilled, kernel-distilled and both. Compare the Spearman correlation of predicted versus real forgetting on 30 held-out LoRA fine-tunes, scored on rare-task probes.

4. **Drift twin.** Also match the kernel's first derivative along likely update directions (how K changes per step), measured by finite differences of gradient sketches across one real step. *New:* this directly targets the parent's missing quantity R inside a twin. *First test:* as in idea 3, adding a fourth arm. The pass bar is that the drift-matched twin forecasts which facts cross the margin (R > a) better than the plain kernel twin.

5. **Edit-covariant self-simulator.** A self-forecast head predicts post-edit probe outputs. It is trained with a covariance loss: after the real edit is applied, the head, which is itself edited, must still forecast the *next* edit correctly. Its calibration becomes a fixed point under its own updates. *New:* it addresses the self-reference failure; D3/#18 self-predictors are trained for one step and never asked to survive their own edit. *First test:* Qwen2.5-0.5B with a LoRA forecast head and 10 sequential fact edits. Plot forecast error versus edit index with and without the covariance loss, and track retention of the first 5 edits plus WikiText PPL.

6. **Kernel-as-attention self-model.** Add a module whose attention score between a pending context X and a query Y is trained to equal the true eNTK entry K(X,Y). The model then carries its own learning kernel in its forward pass and can say which outputs a lesson will move. *New:* this is an in-weights, per-pair, prospective sensitivity map; introspection work only reads already-learned behaviour. *First test:* GPT-2 small, with the module trained on 10k (X,Y) pairs. Report held-out correlation with the true kernel, and test whether gating updates by predicted K on keep probes cuts forgetting versus a random gate.

7. **Effect dictionary with learned interaction table.** Train a sparse autoencoder over Δ-probe-output vectors from many real edits to get "effect atoms". Fit a pairwise interaction table for atoms that are not additive, then compile atom combinations to weights with a data-aware operator. *New:* this is a compositional basis for effects with explicit non-additivity; #21 hashes whole effects. *First test:* GPT-2 small with 2k ROME/LoRA edits and 64 atoms. Test whether atom-sum plus the interaction table predicts held-out two-edit compositions, including old-fact retention, better than effect addition.

8. **Kernel-signature class key.** Key each edit by its immediate effect *plus* the change it causes in the keep-probe gradient Gram matrix. *New:* the key includes the second map, so it is a cheap approximation of idea 1 without continuations. *First test:* the same setup as idea 1. Compare how well each key predicts the interference of a later edit on old facts.

9. **Reachability atlas over classes.** Using a class quotient, build a graph where nodes are classes and edges are edits that stay within the retention tolerance. Editors plan with A\* in class space and only compile to weights at the end. *New:* the search space is classes with retention-safe transitions rather than weights. *First test:* a toy MLP with 6 tasks. Compare A\* plans with random weight search at equal verifier calls on target success and old-task retention.

10. **Edit bisimulation metric.** Define a distance between edits as d(e1,e2) = |immediate effect difference| + γ·W1(distribution of continuation effects), learned by TD-style fixed-point iteration over logged edit sequences, as with RL bisimulation metrics. *New:* a metric version of the Nerode quotient that gives graded similarity for search. *First test:* PR #63-style toy. Check whether the metric's nearest neighbour predicts the second-edit retention loss better than ΔW cosine and immediate-effect cosine.

11. **Successor-effect representation.** For each edit, estimate the expected discounted future change of keep probes under the editor's own policy, analogous to successor features. Editors pick edits whose successor effect on keep probes is small. *New:* it forecasts the cumulative forgetting that this edit makes more likely later, not the edit's own damage. *First test:* toy MLP stream of 50 edits, fitted by TD. Measure retention at step 50 when edits are chosen by SR versus by immediate damage.

12. **Train to be simulable.** During pretraining or fine-tuning, add a penalty on the residual of a cheap simulator's forecast (first-order or low-rank) of the model's own next-update effects, so that the learner becomes predictable. *New:* it changes the learner to fit the simulator rather than the other way round; 2407.10188 regularises self-*state* prediction, not update prediction (flag as adjacent). *First test:* split-MNIST MLP and a 2-layer transformer on 5 tasks. Measure forecast error of forgetting and final retention against a no-penalty baseline and an L2 baseline at matched accuracy.

13. **Quantised learning.** Restrict every update to a codeword from a learned finite codebook of function-space update directions (VQ over projected gradients), so learning *is* class choice. Simulation becomes a codeword × codeword lookup table. *New:* it makes the class set finite by construction. *First test:* 5-task CL on a small MLP with 32 codewords. Report accuracy and retention versus SGD, and test whether the lookup table predicts forgetting of held-out sequences.

14. **Koopman learning operator.** Lift probe-logit vectors into observables in which fine-tuning on a data class acts linearly, then fit DMD/Koopman operators per data class from training trajectories. Forgetting is then read from the operator's eigenvalues and modes. *New:* system identification of the learning dynamics in function space; distinct from the parent's Jacobian/covariance state-space model (#24), which works in weight-derived statistics. *First test:* Pythia-70M with 5 task fine-tunes. Fit DMD on 4, predict the probe trajectory and old-task forgetting on the fifth, and compare with first-order.

15. **Twin ladder extrapolation.** Use twins at several scales (14M/31M/70M), fit how each forgetting statistic scales with twin size, and extrapolate to the target model (Richardson-style). *New:* it uses the scale *trend* of learning response, which addresses the fact that a single small twin is wrong on rare tasks. *First test:* Pythia 14M–160M as the ladder and 410M as the target, on 20 fine-tunes. Measure rank correlation of predicted forgetting on rare-task probes against the best single twin.

16. **Relaxation basins as classes.** After an edit, continue briefly on generic data (relaxation) and classify edits by where they end up: survived, reverted, or mutated into an attractor class. *New:* classes are defined by the fate of an edit under ordinary continued learning, which is the CL-relevant continuation. *First test:* GPT-2 small with ROME edits followed by 200 steps of generic LM. Test whether the basin label predicts survival under later unrelated edits better than immediate efficacy.

17. **Optimizer-state-aware learning state.** Include projected Adam moments and data-order position in the class key and twin state. Two models with identical outputs but different momentum then count as different learning states. *New:* it names hidden learning state that output-based simulators cannot see. *First test:* clone a model, then create two copies with identical outputs and different Adam moments, apply the same next edit, and measure the divergence in retention. This shows whether the effect is non-trivial.

18. **Internal fast-weight twin.** Keep a fast-weight copy of the top blocks inside the model that receives the same gradients at k× LR. The gap between fast and slow internal copies gives a running look-ahead of where learning is heading on keep probes. *New:* the twin shares representations with the model, so it is not a separate network that can diverge in kernel. *First test:* Qwen2.5-0.5B LoRA fine-tune with k=4. Test whether the fast–slow gap on keep probes predicts forgetting 50 steps ahead, versus loss-curvature baselines.

19. **Edit monoid presentation discovery.** Learn generators and relations of the class monoid from observed compositions: which class pairs commute, cancel or saturate. Editors then rewrite edit plans with these relations, like a word problem. *New:* it *discovers* algebraic laws, where PR #42 O1/O2 *enforce* them (flag adjacency). *First test:* toy MLP with 8 classes. Test whether the discovered relations predict retention for held-out words of length 4.

20. **Planned-curriculum self-forecast.** The model forecasts its own outputs k steps ahead on a *planned* curriculum and reorders the curriculum to minimise forecast keep-probe loss. *New:* it forecasts across a horizon for curriculum control; distinct from training a simulator on past SGD history (parent #10) because the forecast is used counterfactually over orderings. *First test:* 5-task CL. Use forecast-chosen order versus random order and compare final retention, with a reverse-forecast control.

21. **Counterexample-guided class refinement with twin and real model.** Keep a twin's class partition and query the real model only on representatives. Whenever the real outcome disagrees, split the class (CEGAR loop), so the twin is corrected exactly where it is wrong. *New:* a twin with a quotient and a refinement rule, where cost is spent only at class boundaries. *First test:* compare against the idea 3 twin alone and against real branches at equal real-edit budget, on retention-forecast accuracy for rare facts.

22. **Retention-tolerant class granularity curve.** Measure the number of Nerode classes as a function of the retention tolerance ε and continuation depth d. The curve itself is the object: if it saturates, finite classes exist; if it keeps growing, effect search is hopeless at that tolerance. *New:* a measurable answer to "can effects be finite?". *First test:* idea 1's setup with ε ∈ {1, 3, 10} pp and d ∈ {1, 2, 3}, plotting class count.

23. **Cross-model class transfer.** Learn classes on model A, then check whether the same edit families fall into the same classes on model B, a sibling scale or an updated version. *New:* if classes transfer, a "behaviour class" is a property of the data and edit, not of the weights, which is a portable primitive. *First test:* Pythia-160M versus 410M on 200 edits. Report the adjusted Rand index of the Nerode partitions and whether B's retention is predicted by A's classes.

24. **Self-simulation through imagined replay.** Before applying an update, the model generates samples from its *predicted* post-update self (via the forecast head) on keep prompts and uses them as replay targets during the real update. *New:* replay data comes from the forecast of its future self, not from its current self (SDFT/self-generated replay [2605.26097](https://arxiv.org/abs/2605.26097)). *First test:* 5-task CL on Qwen2.5-0.5B, comparing current-self replay, forecast-self replay and no replay on retention, with a temperature-matched control as in the A3 lesson.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Does a finite congruence exist? How many edit classes are there under continuation, at a useful retention tolerance, for a real edit family?** If the count saturates, an "effect space" editors can search is real and Nerode classes become the primitive. If it does not, finite effect search is ruled out. Ideas 1, 2, 10, 22.
2. **Is the learning kernel (eNTK plus its drift) a portable state that a small twin can carry better than outputs?** If kernel-matched twins forecast rare-task forgetting where output twins fail, "distil the learner, not the function" is new. Ideas 3, 4, 15, 18, 21.
3. **Can a self-forecast be edit-covariant, staying calibrated through its own updates?** This decides whether self-simulation is possible at all, beyond introspection on the present. Ideas 5, 6, 24.
4. **Can a learner be trained or constrained to be simulable at small cost in accuracy?** Quantised learning or a simulability penalty would make the class set finite by construction. Ideas 12, 13, 19.
5. **Which hidden learning state (optimizer moments, data order, relaxation fate) must a class key include?** This is the cheapest falsification route for all output-based simulators. Ideas 8, 16, 17.
