# Repair-reveal IV: read through drift, then clear by doing owed work

**Status:** Ideas only. Exact paper check and proposed paper/CPU first tests; no learner or GPU runs. **Parent:** [Repair-reveal III](repair-reveal-3.md) ([PR #303][parent]). **Review seeds:** [Flood triage, row 421][triage] on [PR #6][review] scores **#03** (cancel an unknown offset with two opposite-signed native reports) and **#06** (erase a diagnostic carrier with the next genuinely owed update) at 3. Both are baselines, not new cards.

**Ledger read first:** [Idea ledger][ledger]. **P** marks a candidate new reusable object or operation; **I** marks an improvement or audit. Neither offset cancellation nor a reset is new. The claim to test is whether the due workload can produce an actionable observation and then retire its footprint, more cheaply than buying those two functions separately.

## Contract and controls

- A is original work; B is installed work, including the repaired route and pinned borrowers; C is installed and incoming successor work. Fix lawful due menus, normal reports, optimizer (including slots and clipping), precision, nuisance support, old-task floors, and arrival/deadline support before blind runs. The proposer cannot choose labels or insert records. Price displaced records and measure progress by queue; do not count an update as owed just because it clears a coordinate.
- Decide on the full public history before the last useful cut. A grant needs a single causal dispatch policy for all consistent histories and joint calls; no backing is released or secretly booked on an incomplete observation. Keep every promise executable after clearing without reconstructing a private erased value. Test held-out A, B and C before, at exposed cuts (including refusal), and after a later mandatory write; test promised old arrivals, not just final average score.
- Rival stack: [#303 #03/#06][parent], best same-order differencer, a paid matched-time reference or audit, [OGD][ogd]/[GEM][gem] and a dedicated clear or snapshot/restore, followed by exact same-information dispatch. Give that stack the same lawful actions and reports, including the chosen order. An unrestricted exact stack can emulate the candidate; a practical gain must be in actual checks, carried bytes, planning cost, or completed work under a binding clock. Match per-queue progress, precision, compute, initial margins and timing or report the tradeoff. Include a report collision, a missed clear, and a later write that re-exposes a hidden slot as separate negatives.

## Exact paper check: a usable contrast and a timely clear

Take unit-step SGD, `v=x=z=0`, and a fixed private feature `h∈{−1,+1}` of the due examples. It is not in the public queue metadata. The first two already-due C records have losses `(v−h)²/2` and `(v+h)²/2`. The native post-update report is `floor(b+v)` at each of those cuts for an unknown shared `b∈{−2,−3/2,−1,−1/2,0,1/2,1,3/2,2}`. Thus `v=h,−h`; each report alone has overlapping supports, but `r₁−r₂=2h` even at ties. With two same-sign reads, the contrast is zero and some full report pairs coincide. If the offset can instead jump by `+4` between reads, `(1,3)` arises both from `h=+1, b₁=0, b₂=4` and from `h=−1, b₁=b₂=2`. Under that expanded drift support the pair must refuse.

Between the second and third updates, a blind job needs two of three service units to finish by deadline. In `h=+1` exactly one pinned B caller requests a unit; in `h=−1` both do. No arrivals are visible at grant time. There is a common policy in the first cell: hold one unit and serve whichever old call arrives. Grant nothing on the first report or in the two-caller cell. All B calls before the grant cut use original backing. A separate audit delivered after the window cannot finish the job; an exact scheduler given the same contrast can.

The third, already-owed A batch has loss `((x−1)²+v²)/2`. It moves `x` to 1 while clearing `v` before an old read requiring `|v|≤1/2`; the read is not due in the diagnostic window. Moving the read earlier fails, as does a different owed batch `((x−1)²+(z−1)²)/2` that pays the same local loss decrease but leaves `v` exposed. An unaffected old A/C read (`|x−z|≤1`) passes at all cuts; already completed B service requires no erased value. Exact served-record loss drops in the positive arm are `1/2, 2, 1`. The workload and liability support are illustrative, not learned: this checks information and timing, not an advantage over a same-report planner or retention on a learned host.

## A. Recover a decision from native reports without buying a reference

### 01. Cancel drift with a due second difference (P; #03)
- **Mechanism:** Select among three naturally due records so the signed response has a nonzero second difference while a common affine drift does not. Certify disjoint sets of rounded contrasts, with timestamps fixed before choosing the records.
- **Novelty vs nearest prior art:** [Correlated sampling and chopper stabilization][chop] already remove offsets; polynomial detrending already removes affine drift. The candidate is a due-record sequence that supplies the contrast while paying all three learning debts. Compare the best affine estimator on the same native stream.
- **Cheapest first test:** Enumerate three timestamps, two response signs, bounded slopes and all rounding breakpoints. Compare the parent pair and a priced reference; include quadratic drift whose rounded contrast aliases.
- **Old-task retention:** Run pinned B between all reads, and score A and installed C at each of the three writes, including the alias case.

### 02. Make the contrast survive different report grids (P; #03)
- **Mechanism:** Maintain the feasible shared-offset set from each rounded bin on its own grid. Select an owed pair to make those sets incompatible for histories that disagree on the admissible load, without rescaling the actual reports.
- **Novelty vs nearest prior art:** [Set-based active diagnosis][diagnosis] separates uncertain output sets. Here the due action chooses *which native grids interact*, not the encoder precision; compare exact diagnosis with the same grid menu and a common finer grid priced in bits.
- **Cheapest first test:** Enumerate two odd/even grid spacings plus an origin shift. Find a pair whose raw integer difference collides but whose joint feasible-offset intervals separate; then let one origin drift until a false grant would occur.
- **Old-task retention:** Serve both grids' normal C workloads at native precision, preserve A margins and run old B requests on every ambiguous bin pair.

### 03. Use a compulsory record as a gain reference (P; #03)
- **Mechanism:** When native reports have both unknown offset and positive gain, pick a lawful sequence containing a reference response gap known from a public ordinary record. Admit by the interval for the ratio of two differences, not by estimating gain on a hidden coordinate.
- **Novelty vs nearest prior art:** Two-point calibration already removes affine sensor error. The candidate is a reference from existing task work with a certified nonzero gap under the *executed* optimizer; compare paid calibration and a native-report set estimator.
- **Cheapest first test:** Three rounded reads, two possible liability amplitudes and a finite gain menu; add clipping that makes the denominator interval touch zero and require refusal.
- **Old-task retention:** Run the reference record's normal old C task with B still backed, then exercise A and old B again on both sides of the clipping knee.

### 04. Certify one good contrast when the nuisance can jump once (P; #03)
- **Mechanism:** Lay out two disjoint native pairs. Enumerate all placements of a single jump and grant only if every compatible interpretation of the four reports backs the same policy; conflicting pair votes do not suffice.
- **Novelty vs nearest prior art:** Change-point detection and [set-based diagnosis][diagnosis] already model abrupt shifts. The candidate is a grant certificate robust to uncertainty about *which* contrast is valid without requiring a fifth measurement. Compare exact jump inference and two dedicated repeat probes.
- **Cheapest first test:** Use four due records, all three inter-read jump positions and two liability modes. Seek safe early grants in a subset of traces, and add a second admissible jump as a falsifier.
- **Old-task retention:** Exercise each normal owed record, and replay old A/B/C traffic on conflicting traces where the decision stays provisional or refuses.

### 05. Use saturation as a bound, not a missing reading (P; #03)
- **Mechanism:** Treat clipped reports as one-sided constraints. Choose a second compulsory response so that the clipped half-line and the other finite bin force a safe load bound, even when the raw difference is not meaningful.
- **Novelty vs nearest prior art:** Censored estimation uses saturation inequalities; [#297 #02][next] guards clip knees. The candidate deliberately chooses an ordinary write that makes a target release identifiable *with* censoring. Compare exact censored inference on fixed order and a paid unsaturated reference.
- **Cheapest first test:** Enumerate offset intervals at both rails and a two-record menu; look for an admissible cell with exactly one clipped read. Force both rails to alias as a negative.
- **Old-task retention:** Check old C with the original report rails unchanged and execute A and B for the single-clip grant and double-clip refusal.

### 06. Use public times to weight an interleaved contrast (P; #03)
- **Mechanism:** Precompile a timestamp-indexed combination of ordinary reports that cancels affine nuisance despite unequal spacing imposed by other jobs. Refuse if a legal time gap widens the rounded contrast into an unsafe cell.
- **Novelty vs nearest prior art:** Irregularly sampled regression handles nonuniform times; [#303 #02][parent] encodes threshold-crossing time. Here timestamps compensate nuisance instead of encoding the hidden state. Compare actual-time regression and paid resampling with identical report latency.
- **Cheapest first test:** Interleave one pinned job that can slip by a tick between three reads; enumerate schedules and compare equal-time coefficients. Include a delay that pushes the contrast past deadline.
- **Old-task retention:** Execute the interleaved B job to its original deadline; exercise A/C in the longest permitted gap and the late refusal.

### 07. Transfer a contrast between two ordinary report channels (P; #03)
- **Mechanism:** Use a due record seen by both established channels as a shared endpoint, so within-channel differences can be chained without knowing either channel's constant offset. The endpoints of interest need not ever be read by the same channel.
- **Novelty vs nearest prior art:** Differential metrology already chains relative readings. The candidate is an overlap supplied by dual-use owed work under fixed visibility, with complete quantized trace certification. Compare an equal-byte channel calibration and an exact graph of difference constraints.
- **Cheapest first test:** Three records with visibility `{R}`, `{R,S}`, `{S}` and two offsets. Enumerate endpoint separation with and without the overlap; add an independent drift after the shared endpoint.
- **Old-task retention:** Run both channels' original C users including the shared record; run A and both pinned B groups even when the chain breaks.

### 08. Audit the smallest legal transcript (I; #03)
- **Mechanism:** Minimize carried state by computing which prefix summaries induce the same set of future safe actions. A one-bit cached sign is justified only if it is sufficient before all allowed rounding, drift and arrival branches.
- **Novelty vs nearest prior art:** Sufficient statistics and finite-state minimization already quotient histories. This is a memory-cost audit of the parent contrast, not a new coding method.
- **Cheapest first test:** Build the finite prefix/suffix table for an offset menu where two equal signs require different decisions after the same next report. Compare raw report buffering, exact partition refinement and a one-bit cache.
- **Old-task retention:** Exercise old B in all merged prefix classes and verify all old A/C reads even if the cache forces additional refusals.

## B. End the carrier's influence by paying an actual obligation

### 09. Clear the slot that would re-create a cleared carrier (P; #06)
- **Mechanism:** Require the owed clear to put the cleared state into a set that stays safe through the next compulsory write, including optimizer slots. A zero weight alone cannot certify the original reader.
- **Novelty vs nearest prior art:** [Deadbeat control][deadbeat] drives finite-horizon state to a target; [#303 #06][parent] clears the current read. The candidate certifies stability through a bounded due-word menu without clearing unused directions or editing slots.
- **Cheapest first test:** Two clipped heavy-ball histories land at the same zero weight with different momentum. Execute the next zero-gradient tick and compare a weight-only clear, a slot reset, and an owed partner selected over the two-tick horizon.
- **Old-task retention:** Serve A at both the clear and rebound cuts and run old B/C with unchanged optimizer dynamics.

### 10. Clear influence when the coordinate itself cannot be restored (P; #06)
- **Mechanism:** Select an owed update that maps the set of possible carrier values into a single safe output class for the actual A reader, leaving distinguishable weights for useful C work. Verify it under all declared later reads.
- **Novelty vs nearest prior art:** [OGD][ogd] protects outputs locally and [deadbeat control][deadbeat] includes terminal targets. The candidate uses a due write to collapse only a *post-diagnosis* reader equivalence class, not to restore parameters.
- **Cheapest first test:** Two possible carrier values remain nonzero after a genuine record; compare a fixed gate made insensitive by that update to exact parameter restore at equal C progress. Include a later mandated gate reopening as a negative.
- **Old-task retention:** Run the sensitive A slice and unchanged B/C routes after the output merge and on the attempted reopening branch.

### 11. Pick a due clear without knowing what was diagnosed (P; #06)
- **Mechanism:** Before seeing the contrast, commit to one legal clearing record that works for every public cell including refusal. Grant only where that same record also leaves the post-grant service policy feasible.
- **Novelty vs nearest prior art:** Robust input shaping chooses commands under parameter uncertainty. Here a queue cannot reschedule on private evidence; the object is a common payment covering all cells with the same obligation identity, not a cell-specific reset.
- **Cheapest first test:** Two carrier signs and three owed records: two sign-specific clears and one common clear with less surplus C gain. Remove the common record and compare adaptive legal scheduling and a priced reset.
- **Old-task retention:** Exercise old A at its sensitive cut in both signs and the refusal cell; keep all original B and the displaced C obligations due.

### 12. Prove two carriers are discharged by one owed update (P; #06)
- **Mechanism:** Allow two pending diagnostics to coexist only if one truthful due batch clears their *joint* influence before either sensitive cut. Compute the condition on reachable combinations, including clipping shared by both.
- **Novelty vs nearest prior art:** [Command shaping][shaping] can cancel multiple modes and [#289 #09][steps] certifies shared admissions. The candidate is a common clearing payment for two independent observations; pairwise clearing success on isolated copies is not a certificate.
- **Cheapest first test:** Two signed carriers and one clipped gradient budget. Find a combination where each isolation run clears but the simultaneous run fails; compare separate clears charged at equal progress and an exact joint scheduler.
- **Old-task retention:** Exercise both original A readers, and all B and C work on joint and singleton traces, including refusal of a second diagnostic.

### 13. Absorb the carrier into an owed task's useful direction (P; #06)
- **Mechanism:** Use a due example to move variation from an A-sensitive direction into one that pays C without contaminating B. Require A invariance and stronger held-out C performance than clears that destroy the variation outright.
- **Novelty vs nearest prior art:** [Task arithmetic][arith] subtracts or combines learned directions and [OGD][ogd] projects updates. Here the carrier is redirected by an ordinary due gradient, not by storing and applying a task vector; compare vector-based redirection with its bytes charged.
- **Cheapest first test:** Search a two-direction quadratic map for a truthful batch that annihilates A-visible variance and reduces independently specified C validation loss for both signs. Compare pure clear and a sign-shuffled carrier.
- **Old-task retention:** Test held-out A including the original carrier reader, earlier B without a route switch, and independently held-out old C to catch harmful transfer.

### 14. Clear by a mixed batch when none of its owed items can clear alone (P; #06)
- **Mechanism:** If the existing batching rules permit it, settle multiple owed examples in one ordinary update whose gradient interaction clears a carrier before deadline. Verify the real aggregation and optimizer, not the sum of independently executed updates.
- **Novelty vs nearest prior art:** Batch gradient selection and input shaping already combine directions; [#303 #06][parent] uses one owed update. The candidate is a clearing action that exists only under lawful joint execution at equal coverage.
- **Cheapest first test:** Enumerate two owed losses and a clipped optimizer where the ordinary joint update clears but both serial orders fail. Compare best exact batch selection with the same actions; reverse the clipping order as a model-mismatch negative.
- **Old-task retention:** Run A at the first sensitive cut, replay B while both records are batched, and check separate held-out C slices rather than aggregate batch loss.

### 15. Make a clear survive a blind substitution of owed work (P; #06)
- **Mechanism:** Admit a diagnostic only when every allowed replacement for a later owed record takes the full state into the same safe reader class, possibly by distinct mechanisms. Do not reserve a specific record the scheduler is allowed to substitute.
- **Novelty vs nearest prior art:** [Robust command shaping][shaping] tolerates plant uncertainty; here uncertainty is the identity of future legitimate learning work. Compare a robust scheduler, a locked record, and a paid contingent clear.
- **Cheapest first test:** Two backup C records, one clears the carrier itself and one disables its downstream influence. Swap in a same-loss record that does neither; enumerate the public policy before any substitution is known.
- **Old-task retention:** Exercise A's sensitive route with either replacement and run B/C when the diagnostic is refused instead of blocking the substitute.

### 16. Price the earliest old read that makes temporary borrowing impossible (I; #06)
- **Mechanism:** Sweep independently fixed old-read positions against the first available owed clear. This separates a genuine timing overlap from an experiment that just never asks an old question at a difficult cut.
- **Novelty vs nearest prior art:** Release scheduling and [#297 #15][next] already budget expiry. This is an audit of reader deadlines, not a new restoration operation.
- **Cheapest first test:** Shift one ordinary A arrival across three cuts without changing the learning records. Compare live projection or a priced dedicated clear on the earliest read.
- **Old-task retention:** Actually serve the shifted original A request and hold all B/C traffic fixed; a skipped request is a failure, not a refusal that can be averaged away.

## C. Co-design the read and the clearance without speculative backing

### 17. Let an owed record deliver the second report and clear the old reader (P; #03 + #06)
- **Mechanism:** Use a naturally published **pre-update** statistic of an owed record as the second signed read, then let that same record's ordinary update clear the carrier. A grant requires the standard report and successful payment at the legal cut, not just the pre-update sample.
- **Novelty vs nearest prior art:** [Chopper stabilization][chop] and [command shaping][shaping] separately cover observation and settling; [#303 #03/#06][parent] use them in sequence. The candidate reuses one record boundary where a distinct clear or probe would miss the cut. Compare the same-report differencer + selector + scheduler stack with that boundary fully exposed.
- **Cheapest first test:** After the first report `floor(b+v)` in the paper fixture, try an already-owed record whose native pre-update prediction is `−v`, whose true target is zero, and whose unit-step quadratic update therefore clears `v`. Use carrier amplitudes `±3/4` and include offsets `0` and `3/4`: the pre-update pair separates the signs, but both signs can give `(0,0)` if the second report instead uses the post-update prediction. Charge any extra probe needed before the immediate A request.
- **Old-task retention:** Run the immediate sensitive A request and a first-wave B request still backed before commit, and run old C after the record on both commit and refusal.

### 18. Match two observations to their physical exit states (P; #03 + #06)
- **Mechanism:** Partition report cells by which owed clear is feasible, not just by B load. Prefer a contrast that distinguishes two cells with identical current load but disjoint safe clears, since no public plan can rely on a hidden choice once the job is granted.
- **Novelty vs nearest prior art:** [#303 #17][parent] encodes feasible continuations and [set-based diagnosis][diagnosis] separates modes. Here the difference is a required clear on the *same optimizer trace* that generated the observation, even when immediate dispatch is identical.
- **Cheapest first test:** Three equal-progress read orders, two histories with the same B load but different hidden moment signs, and two owed clears. Compare a load-only contrast, the exact joint planner, and a paid slot audit.
- **Old-task retention:** Exercise both latent A readers with the chosen clear, old B during dispatch, and held-out C under both exit paths.

### 19. Hand off a service promise across an erased contrast (P; #03 + #06)
- **Mechanism:** After grant, retain only a bounded dispatch entitlement whose executable continuation does not depend on the diagnostic reports or carrier. Choose the contrast partly by whether the set of resulting promises has a compact, sufficient handoff to an existing downstream reader.
- **Novelty vs nearest prior art:** [#303 #15/#17][parent] cover downstream queues and continuation selection. This targets eliminating diagnostic history *while* a B promise is outstanding; compare a priced transcript, a scheduler token and an exact minimally sufficient quotient.
- **Cheapest first test:** Two public contrasts authorize the same initial stage but different post-clear reserve needs. Search for one shared policy token that preserves both; add a late old call that makes the proposed token insufficient.
- **Old-task retention:** Execute the late B call and the promised next stage after erasure, then run sensitive A and old C without reopening the carrier.

### 20. Close a diagnostic cycle without paying the same record twice (P; #03 + #06)
- **Mechanism:** Use one owed write to discharge the first carrier while opening a second, distinct one. Count the write's single queue payment once, certify old-reader safety between cycles, and start the second contrast only if future owed work clears it too.
- **Novelty vs nearest prior art:** [#297 #21][next] reinvests capacity in the next margin and [command shaping][shaping] composes shaped moves. This is a rolling handoff of the *carrier* with an independently checkable debt after each cycle, not extra capacity from accounting.
- **Cheapest first test:** Two carriers and three owed periods. Compare serial diagnose/clear, joint planning and a trace whose last clear slips; count only complete cycles with all exits paid.
- **Old-task retention:** Run both A reader deadlines, B at the cycle handoff and after the second refusal, and each ordinary C obligation exactly once.

### 21. Choose a contrast and clear with one common nuisance model (P; #03 + #06)
- **Mechanism:** Track joint nuisance assignments across the paired reads and the clear. A report can narrow the nuisance range enough to justify a clear only if the optimizer sees that same nuisance and the coupling survives the declared drift; otherwise require unconditional clearance.
- **Novelty vs nearest prior art:** [Set-based diagnosis][diagnosis] and robust control propagate common uncertainty. The candidate is a due-write certificate that is less conservative than independently robust read and clear when both depend on one physical disturbance; compare exact joint reachability and the independently robust stack.
- **Cheapest first test:** One nuisance affects both report offset and effective update gain; search for a public cell where the same due update is safe on every jointly consistent trace but not under the independent box. Break the shared nuisance after the second report as a negative.
- **Old-task retention:** Execute old A at the clear, B through the grant and any refusal, and old C at both gain extremes and on the broken-coupling branch.

### 22. Cross evidence availability with clearing availability (I; #03 + #06)
- **Mechanism:** Factor the read and the exit: equal learning work with contrast present/absent, and safe owed clear on time/late. Hand the resulting *same* observations and actions to the best modular stack; account for missed old work, report carry and separate checks before crediting a deadline win.
- **Novelty vs nearest prior art:** [#303 #22][parent] factors report delivery and bridge feasibility; this is an audit for a timely *restoration* constraint after evidence has already been used. No new scheduler is claimed.
- **Cheapest first test:** Exhaust the four cells with one paid reference, one paid clear, and an oracle schedule as ceiling. Reject the coupling if the best matched stack reproduces the cost and on-time service.
- **Old-task retention:** Run original A, B and C in all four cells, including the deliberately unsafe attempted old read and the safe policy that must refuse the diagnostic before exposing it.

## Ranked deeper questions

1. **Can one genuinely owed record both deliver the decisive contrast and retire its footprint before the first sensitive old read?** Start with 17 and 22. Independently move report delivery and the old-read deadline; price both components against the best combined reference + clear + scheduler. If identical native actions tie, name the resource the joint selection saves against the best separate implementation, or drop the primitive claim.
2. **When is an observed clear stable under the writes that must follow it?** Use 09–12 and 15. Match starting margins, vary optimizer slots and blind due substitutions, and seek a reader-safe forward set that survives a real later write rather than only a zero intermediate weight.
3. **Which contrasts remain actionable under jointly plausible drift, clipping and delivery time?** Start with 01–07. Enumerate rounded outputs before approximating; find the first honest shared-nuisance relaxation that makes the unsafe and safe traces collide and identify the cheapest competing reference.
4. **Can repeated read/clear cycles avoid accumulating either diagnostic history or unpaid restoration?** Use 18–21. Require a public policy after every erasure and run later old requests across every handoff. Compare a priced transcript and exact scheduler; a role switch that strands an old reader fails even if all final weights match.
