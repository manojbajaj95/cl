# Discrete backpropagation through a learned tool loop

Parent: [`tree/agent-harness.md`, PR #47](https://github.com/manojbajaj95/cl/pull/47/files) · Depth 2

**Root cause: a failure identifies a set of possible repairs, not a write address.** In the parent's shared prompt/retrieval interface, we often cannot even intervene on a single decision mechanism. But separating the mechanisms and replaying the *entire* state does not solve the inverse problem either. An upstream misroute and a downstream compensation can both turn the same failed trace into a pass. More accurate credit for the observed action only values that action under a replay policy. It does not specify which *persistent component edit* will change the right decisions on subsequent calls while leaving old behavior intact. At a branch or retry, that edit changes which states and tool effects the verifier ever sees; fixing each logged call independently can prescribe inconsistent writes to the same component.

**Disconfirmation and nearest classical baseline.** A deterministic bounded loop already has a [weakest precondition](https://doi.org/10.1145/360933.360975) if the program and state are complete. CEGIS can put a shared repair variable into that program and search for a satisfying assignment. Thus neither backward predicates nor conjunction with old tests are novel. With an oracle trace, a complete candidate menu and sufficient calls, forward replay should also match any exact inverse. The research claim worth testing is stronger: *can partially learned local models exchange smaller reusable certificates about what a component may change, and refine those certificates from checked failures, such that they remain predictive across tools, iterations and old goals?* Disconfirm it if bounded model checking / CEGIS over the same learned state, or equal-cost closed-loop replay with the same candidates and preservation evidence, matches certificate reuse, query cost and retention on a second environment. A hidden tool bit that produces identical logged prefixes but makes opposite edits correct is an explicit counterexample to sound localization without further information: return both possibilities, request an observation, or abstain. No finite test panel certifies arbitrary unobserved effects.

### An exact finite obligation

Let `e` name a persistent edit (or a shared repair variable), and let `s` contain the tool, router and relevant memory state. For deterministic edited transition `F_e`, a success predicate `B_0(s,e)` pulls back as `B_(k+1)(s,e) = B_k(F_e(s),e)`. With absorbing completion this means “succeeds within the remaining budget.” Pull back through each component and tool transition in reverse order; keep the *same* `e` across call sites and conjoin protected endpoints before picking a write. Discharging means implementing the edit and checking the induced closed-loop behavior, not predicting an agreeable intermediate string. Alternative passing edits are a disjunction, not an averaged target. Under partial observability the quantifier is part of the obligation: “some compatible state,” “all compatible states” and “passes with probability ≥ p under this stated law” are different contracts. A result should say which one it checked.

### CPU probe: exact preimages do not select a repair by themselves

Run [the NumPy probe](probes/discrete_backprop_probe.py) with `python tree/probes/discrete_backprop_probe.py`. Three width-six tables represent frozen discrete learners, `retrieve → plan → act`. The tool has two phases: a correct action advances, a wrong action retries the same phase, and the rollout has three calls to the pipeline. The baseline tables compose to the identity. At one port, make the target symbol's row return the output for an old symbol (the alias). The failed rollout repeats the first wrong action and never reaches phase two; a repair must pass the previously unvisited suffix. The ideal table and planted address are bookkeeping, not inputs to either selector. The repair menu is all 90 one-cell overwrites plus no-op. The loop and each goal's action checker are white-box to the preimage calculation.

The backward masks pull terminal acceptance through the finite tool state and the tables, indexing every predicate by the *same* candidate edit through all calls. Independent forward replay checks every target and protection bit. The **terminal-only replay oracle** gives every target-passing edit equal weight: it sees exact counterfactual success, a stronger baseline than blaming a random port from the single failure. **Protected** intersects that same target success set with five old repeated-symbol anchors. **Alias hidden** removes exactly the distinguishing old anchor, leaving the other four. Retention is measured on all 20 ordered pairs of distinct old symbols, never supplied to the selector; the no-op retains 100% of them but fails the new task.

| Planted port | Minimal target edits (both methods) | After old anchors | After hiding alias | Terminal-only planted-cell localization | Terminal-only old success | Protected old success |
|---|---:|---:|---:|---:|---:|---:|
| Retrieve | 3 | 1 | 3 | 33.3% | 73.3% | 100% |
| Plan | 2 | 1 | 2 | 50.0% | 80.0% | 100% |
| Act | 1 | 1 | 1 | 100% | 100% | 100% |
| Balanced mean | — | — | — | 61.1% | 84.4% | 100% |

Over NumPy seeds 0–15 at each port (48 planted instances), the summary is invariant to the relabelings, and the protected singleton always restores the planted cell. Percentages are exact finite-menu/held-out averages, rounded to one decimal; no sampling CI or estimate of LM performance. For a retrieve defect, restoring the retrieve row preserves the alias; compensating in plan or act overwrites the path the alias still needs. Each such compensation breaks 8 of 20 old pairs. An edit upstream of the corrupt table cannot restore the missing output of that table, so there are fewer compensations for later defects. Removing the alias anchor restores the entire terminal-only ambiguity, despite still protecting four old skills. **The distinguishing information, not the backward pass, buys localization here.** An exhaustive forward check with the same anchors selects the same edit. This is an identifiability probe, not a sample-efficiency result, a learned preimage model, or evidence of robust localization from terminal failures alone.

## Raw mechanisms for the reviewer

These are hypotheses, not novelty verdicts. Compare with equal-cost replay and symbolic search where applicable. Charge new tool calls, verifier queries, model calls and stored bytes; report a frontier when they cannot be matched. Keep old evaluation separate from the preservation evidence used to select edits.

1. **Repair variables as first-class wires.** Mechanism: put the *persistent editable cell* on a wire that can fan out to many invocations; compile one unification constraint for all its uses, emitting an unsatisfiable core if no shared write works. Why new: [Sparo (2609.32492)](https://arxiv.org/abs/2609.32492) chooses a component, not a shared edit value that is coupled across all its uses; the candidate primitive is a reusable update wire with a certificate of where sharing must end. First test: compare to per-call backward targets and a whole-program SMT repair on a retry loop where each call alone is satisfiable but their one-cell conjunction is not; check old single-call and shared-write episodes with both invocation orders.
2. **Versioned continuation quotients.** Mechanism: merge two tool states only if every allowed future edit has the same effect on a finite protected goal language; cache one inverse certificate for the equivalence class and split it on a separating counterexample. Why new: [C3 (2603.06859)](https://arxiv.org/abs/2603.06859) reuses a trace prefix for alternative continuation values; this shares the inverse across distinct prefixes, including edits the current policy never executes. First test: add redundant and secretly relevant state to a toy tool, compare new verifier calls to trace memoization and partition refinement, and check previously merged old goals after each split.
3. **A rejection algebra for backward messages.** Mechanism: define messages with separate sets of proved feasible, refuted and unobserved edits. Composition propagates “unknown” instead of projecting it to failure or success; attach witnesses to either proof so new evidence can retract just that fact. Why new: [Trace/OPTO (2406.16218)](https://arxiv.org/abs/2406.16218) gives a generative optimizer structured execution context; here uncertainty has executable semantics under composition. First test: blind a random subset of table/tool state and compare false commitments vs budget-matched trace feedback and symbolic interval bounds; measure both old-task success and abstention on the old cohort.
4. **Replay-cost dual variables.** Mechanism: propagate a vector of minimum evidence costs indexed by the unresolved edit equivalence class; the backward pass returns the next cheapest distinguishing operation as well as the admissible edits. Why new: [C3 (2603.06859)](https://arxiv.org/abs/2603.06859) budgets alternatives and continuations to estimate values; the proposed dual prices evidence that would collapse a *version space* and uses that price across goal contexts. First test: give a finite tool two alternative observations with different prices and different separating power; compare to greedy information gain and exact diagnosis, then measure held-out old outcomes of each write at equal query spend.
5. **Tail certificates for unbounded retries.** Mechanism: pair a reverse obligation with a ranking function or a proof of possible nontermination; summarize all future invocations of one learned component by a fixed-point contract. Why new: [TEP (2601.21064)](https://arxiv.org/abs/2601.21064) seeks local prompt refinement equilibrium; this is a termination obligation for the deployed program, not convergence of the optimizer. First test: hide a retry cycle beyond the training unroll and compare against bounded CEGIS and classical ranking synthesis; check both solve rate and latency on old terminating episodes with unseen retry delays.
6. **Backward credit under private state.** Mechanism: send a belief set and an acceptance risk bound across each port; return the smallest missing state predicate that would make the write safe, or a certificate of unresolved ambiguity. Why new: [C3 (2603.06859)](https://arxiv.org/abs/2603.06859) states trace-completeness or resampling requirements for value; here incomplete state is the first-class output of inverse reasoning. First test: flip an unlogged tool mode that reverses safe repairs, compare to full-state and POMDP-belief baselines, then score old retention on both modes and new success at matched abstention.
7. **One proof for multiple verifier vocabularies.** Mechanism: factor obligations into a latent transition predicate plus an adapter with paired inclusion claims in each verifier's language; transfer the predicate, not the labels or prompt patch. Why new: [DSPy Assertions (2312.13382)](https://arxiv.org/abs/2312.13382) uses constraints inside LM pipelines; the proposed object is a transportable inverse whose obligation semantics have to survive a verifier swap. First test: port a Boolean verifier obligation to a rubric and then to a structured tool response; compare to transfer of demonstrations and a typed adapter alone, and test old exceptions in both vocabularies.
8. **Which-copy credit for coupled writes.** Mechanism: express a repair as a witness over the identity of the learner used at each call: same learner with an edit, two learners with one parameter split, or a proof neither suffices. Why new: [TextResNet (2602.08306)](https://arxiv.org/abs/2602.08306) routes feedback to existing components; this lets reverse credit *choose a parameter-sharing pattern*, not just route a signal. First test: solve two old/new task families with conflicting uses of a single learner and a strict one-copy budget, against hand splits and generic routing; check old cross-family compositions at every permitted split.
9. **Obligations as differentiable projections, not labels.** Mechanism: ask a small network optimizer for the minimum weight displacement whose discrete predictions enter the allowed *relation* while maintaining protected margins; if infeasible, return a dual witness tied to examples and the edit subspace rather than a forced label. Why new: [ABL explanation selection (2611.30970)](https://arxiv.org/abs/2611.30970) shows that compatible concept explanations and training dynamics can disagree; the proposed bridge retains the disjunction until the weight-space realizability check. First test: train a CPU linear classifier on allowed label pairs where the individually easiest labels conflict; compare to pseudo-label SGD and direct constrained optimization, then check old classes on fresh noisy features.
10. **Refutation-carrying compilation.** Mechanism: lower a port obligation to a table override, prompt edit or small weight write and ship a counterexample generator for mismatches between the abstract edit and the compiled learner. A mismatch leads to a smaller guaranteed domain, not a global rewrite. Why new: [A-CEGIS (2609.02892)](https://arxiv.org/abs/2609.02892) refines a single concrete artifact against its oracle; here counterexamples refine an abstract/concrete *correspondence* that other ports can reuse. First test: lower the same parity-style router obligation to a table and tiny classifier; compare to training against counterexamples alone, and measure old-route failure on hidden domain boundaries.
11. **Distributional residuals instead of scalar rewards.** Mechanism: propagate bounds on the joint vector of new success and named old effects, using the same noise draw or admissible coupling for each candidate. Allow opposing effects to cancel only when their joint law is checked. Why new: [C3 (2603.06859)](https://arxiv.org/abs/2603.06859) estimates scalar continuation value; this transports a joint feasible set that can forbid tail regressions even when mean credits agree. First test: construct two equally scoring policies that fail together or on disjoint tool modes; compare to variance penalties and vector-reward search and check the worst old-mode retention.
12. **Credit escrow for irreversible effects.** Mechanism: real tool execution receives an edit only after its backward certificate proves a sufficient reversible sandbox effect; otherwise release a conditional repair whose writer cannot act outside the checked saving boundary. Why new: [RECAP (2606.06698)](https://arxiv.org/abs/2606.06698) scores immediate compliance under new constraints; this binds write authority to a compositional proof over persistent effects. First test: simulate a workflow with a shared inventory and a nonrefundable reservation, compare to safe-action masks plus replay, and check old inventory and completion invariants under interrupted execution.
13. **A counterfactual state join.** Mechanism: when two branches pull different requirements back to the same write, carry a joint relation over branch state and shared edit rather than intersecting marginal acceptable outputs. Preserve dependencies through late branch merges. Why new: [Trace/OPTO (2406.16218)](https://arxiv.org/abs/2406.16218) exposes data dependencies to a generative optimizer; this join explicitly rules out locally valid but jointly impossible outputs under a shared update. First test: use a two-branch shared-symbol verifier with identical local pass rates and different joint pass conditions; compare to independent preimages and whole-graph CEGIS, with old crossed-branch assignments held out.
14. **A library of failed inverses.** Mechanism: store certified *impossibility under a write language*, with the structural reason that would invalidate the proof; use it to avoid retrying futile adaptations and choose when to expose a new port. Why new: [Sparo (2609.32492)](https://arxiv.org/abs/2609.32492) carries evidence across optimization rounds; a reusable impossibility proof can strike out an entire edit family before proposing a mutation. First test: permute tool names across repeated infeasible instances, compare to caching failed candidates and SAT-core reuse, then check old feasible tasks for false pruning and retention after port changes.
15. **Time-bounded credit leases.** Mechanism: attach tool/memory version and an explicit validity interval to an obligation; renew it with the cheapest compositional certificate, or replace it by a narrower scoped write instead of retraining everything when one dependency drifts. Why new: [RECAP (2606.06698)](https://arxiv.org/abs/2606.06698) evaluates changing constraints; the lease is an update object that separates expired premises from invalid learner behavior. First test: interleave schema swaps, harmless version bumps and recurrences; compare to version-triggered replay and TTLs, and check old-schema retention plus recurrence recovery without test-time updates.
16. **Inverse synthesis from successful trajectories with incompatible goals.** Mechanism: pass one trace backward against two verifiers simultaneously and synthesize a state variable that explains why a write is allowed for one and forbidden for the other; treat this separating variable as a new port parameter. Why new: [AgentHER (2603.21357)](https://arxiv.org/abs/2603.21357) relabels trajectories to generate goal-conditioned experience; this uses opposed obligations to infer a missing input to the writable interface, not to relabel success. First test: use two task intents aliased at the router and opposing acceptable actions; compare to hindsight relabeling and supervised feature discovery, audit both old intents under fresh phrasings and held-out goal combinations.
17. **Composable reserve of future repairs.** Mechanism: among edits that satisfy today's obligation, prefer one accompanied by a certificate that a named menu of tomorrow's transformations still has independent writable degrees of freedom. Record a finite reachable repair set, not a plasticity score. Why new: [ABL (2611.30970)](https://arxiv.org/abs/2611.30970) studies capture into a selected explanation; here choices within the same semantics are distinguished by *provable future reachability*, not a Gramian proxy (closed in the [idea ledger](https://github.com/manojbajaj95/cl/pull/6)). First test: enumerate all legal repairs on a capacity-limited rule table where today's optimum can strand future writes; compare to slack heuristics and two-step search, with old pairwise task retention measured after the future edit.
18. **Counterexample channels for uncertified adjoints.** Mechanism: learn a fast local inverse and propagate its claims along with a recipe for constructing a falsifying forward trace at that port. Spend checking budget on claimed reusable relations whose violation would invalidate the most downstream obligations. Why new: [A-CEGIS (2609.02892)](https://arxiv.org/abs/2609.02892) uses diagnostic examples about a candidate artifact; this applies adversarial checks to the *credit operator itself*, an object reused on new goals. First test: train inverse predictors on short loops, introduce a long-loop alias, and compare to random checking and candidate-level CEGIS under equal calls; measure certification error and held-out old retention as the inverse is repaired.

## Ranked next nodes

1. **Can a learned port expose an edit-indexed inverse certificate that composes around a loop without enumerating its candidate writes?** This is the closest route to an update algebra rather than symbolic replay: show the same compact object survives sharing, unseen continuations and fresh goals.
2. **What is the smallest additional observation that makes a retention-safe write identifiable, and can the inverse itself request it?** A credit operator that returns a discriminating intervention or an impossibility certificate would remain useful in the partial-state regime where passive exact credit cannot.
3. **Can a disjunctive behavior obligation be compiled to a weight edit, with a certificate of realizability or a counterexample naming the missing write direction?** This would turn checked tool effects into weight-space instructions without choosing arbitrary pseudo-labels.
4. **When does a backward obligation have to change the learner's sharing structure rather than its current behavior?** A proof that the same write must satisfy incompatible calls could make splitting or tying learned cells part of the learning rule, not hand-designed modularity.
