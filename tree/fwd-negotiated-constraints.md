# Can old behaviours negotiate an edit constraint without replay or old-model gradients?

Parent: [`tree/model-forward-only.md`](https://github.com/manojbajaj95/cl/pull/50) (sub-question #2, idea #4 "write-nullspace negotiation").
Mode: ideation only. No experiments were run for this node.

**Short answer: not with any current method.** Every replay-free protection scheme fixes the constraint *before* it sees the edit. Old behaviour is turned into a frozen summary (a feature subspace, a covariance, a Fisher diagonal, a weight null space, a stored prototype). The edit is then projected or penalised against that summary. Nothing on the old side ever *answers* a specific proposed edit. Negotiation needs an old side that can be asked "does this particular edit hurt you, and what would you accept instead?" and can answer with forward passes only. Today that old side does not exist as an object.

**Definitions.**
- *Negotiated constraint*: the set of admissible edits is produced edit by edit, in an exchange between a proposer (the new task) and one or more old behaviours that each return a counteroffer, veto or price.
- *No replay*: no stored old inputs, outputs, or generator trained on them, **for the editor**. If anything old-derived is used to form a counteroffer, the doc says what and charges for it, in bytes, as the parent asked.
- *No old-model gradients*: no backward pass through the old model, no stored Jacobians or Fisher matrices built from old data.

## Why current approaches can't do it

### Root cause (three parts)

1. **Old behaviour has no forward-callable interface.** In a network an old skill exists only as a disposition: it shows up when an input arrives. Without stored inputs there is nothing to call. So every method replaces the skill with a proxy computed once (subspace, covariance, spectrum), and a proxy cannot be asked a new question.
2. **The constraint is edit-independent.** Projection, null-space editing and regularisers all compute admissibility *before* the edit, as a property of the old point. The parent node's own toy shows the cost: the right mask depended on hidden old coordinates, which a new-task score never reveals. A frozen summary either over-protects (plasticity loss, span saturation) or under-protects (large edits leave the quadratic region).
3. **No currency.** Even where several parties exist (multi-objective bargaining), they trade in gradients, which need data and backward passes. A forward-only edit loop only has scalar scores. There is no agreed unit in which an old behaviour can say "this much, and no more" or accept a side payment.

**Working hypothesis (falsifiable).** A model can host *self-addressing old behaviours*: small forward-only objects that, given a proposed weight delta and nothing else, regenerate their own probe inputs from the current weights and return a signed counteroffer. If this works, the constraint becomes a *protocol* rather than a *projector*, and its byte cost is the size of those objects, not a replay buffer. It fails if every such object either (a) needs as many bytes as replay to reach the same retention, or (b) can be beaten by LOKI-style weight-only null space at equal compute.

## Ledger constraints honoured

- Not re-proposed: gradient projection, AlphaEdit/LOKI null space, sparse-write certificates, plasticity-reserve Gramians, functional syndromes, e-value gating, median-of-means/social-choice gates, Vickrey MoE auctions, futures markets on forgetting, double-entry weights (PR #6 ledger, PR #45 source). Ideas below that look adjacent say how they differ.
- Edit-site choice has little headroom once a data-aware operator is used (PR #49). Ideas here are about *who admits an edit*, not where to put it.
- Self-WSP and ES baselines (Self-WSP 2611.28833, EGGROLL 2511.16652) and a matched random-search control are required in every pilot.
- Memory-value pilots need a temperature-matched no-memory arm and a same-length filler arm (A3 lesson).

## Raw ideas (no self-filtering)

Every first test uses the same cheap testbed unless noted: a 2-layer MLP or 4-layer transformer trained on task A (old), then edited forward-only (antithetic ES, 64 directions) toward task B. **Retention check (common)**: A accuracy/loss on a held-out A set the editor never sees, compared against (i) unconstrained ES, (ii) ES + LOKI weight-spectrum null space, (iii) ES + 1% replay of A at equal byte budget, (iv) ES + random constraint of equal rank, (v) oracle OGD. Report B gain and A retention together, and the bytes each arm keeps.

1. **Counteroffer oracles from weight-derived probes.** Before an edit, the model synthesises probe inputs by maximising its own *output confidence* with a forward-only search (ES on inputs), giving an "old voice" with no data. For each proposed delta, the voice reports the KL shift on its probes and the antithetic direction that cancels most of it. *New:* inversion is used to *answer an edit*, not to replay; forward-only throughout. *Test:* bytes = 0 old data; compare to (iii) at matched retention.
2. **Behaviour contracts as fixed points.** Each old behaviour stores itself as a small set of (seed, output-hash) pairs where the seed is regenerated deterministically from the weights (hash of a layer slice). An edit is admissible if the hashes of the regenerated seeds still match within tolerance. *New:* the probe set is a function of the weights it protects, so it moves with them and costs only the hash bytes. *Test:* measure probe drift under benign edits (false vetoes) and under harmful edits (missed harm).
3. **Edit-conditioned probe sampling.** Given delta Δ, generate probes *aimed at Δ*: inputs that maximise ‖f(x; W+Δ) − f(x; W)‖ by forward-only search. If the maximal disagreement lands on inputs the old model is confident on, veto or shrink. *New:* the old side's question depends on the edit (fixes root cause 2). *Test:* the adversarial probe search budget needed to catch harm, vs random probes.
4. **Signed counteroffer (parent idea #4, made concrete).** Old side returns not pass/fail but a second delta Δ′ drawn from its own antithetic pair that cancels its loss; the editor applies Δ + λΔ′ and λ is bargained (Nash product of new gain and old retention, both forward-measured). *New:* Nash bargaining with scalar forward utilities only. *Test:* Pareto front vs MUNBa-style bargaining with real gradients.
5. **Old behaviours as frozen low-rank "ghost" copies that vote.** At consolidation, compress the old model into a tiny forward-only surrogate (e.g. a 1% student trained from self-generated probes, then frozen). The surrogate votes on edits by comparing its outputs with the edited model on the surrogate's own generated inputs. *New:* the surrogate is a negotiator, not a teacher. *Test:* surrogate size vs retention curve; charge surrogate bytes.
6. **Price signals in a shared budget of KL.** Every old behaviour is given a fixed KL allowance. The editor spends from allowances; when one runs out, that behaviour's probes become a hard constraint. Allowances regenerate slowly (forgetting is allowed but rate-limited). *New:* explicit forgetting budget per behaviour, measured forward-only. *Test:* retention vs allowance schedule; does rate-limited forgetting beat a hard null space on long streams?
7. **Counterfactual tokens: each behaviour holds an input key it can regenerate.** Store per behaviour a 16-byte seed for a tiny input generator shared by all behaviours. *New:* replay of a seed, not data; "is a seed replay?" is answered by charging bytes. *Test:* bytes vs retention against (iii).
8. **Disagreement-weighted ES.** Run ES with two populations: one maximises new reward, one (the "old guild") maximises agreement with the pre-edit model on self-generated probes. Recombine only offspring both accept. *New:* co-evolutionary negotiation, both sides forward-only. *Test:* compare to single-population ES with a fixed penalty of tuned weight.
9. **Edit escrow.** Apply edits into a shadow delta that only becomes permanent after N later steps in which no old probe has flagged it; flagged edits are refunded (reverted) automatically. *New:* time-delayed acceptance with refund, forward-only. Different from delay-compensated gating (ledger), which predicts harm; escrow observes it. *Test:* harm caught vs escrow length.
10. **Old behaviour as an energy over activations, read forward.** Fit (forward-only, from self-probes) a density model over each layer's activations. An edit's cost is the energy increase of the edited activations on the same probes. *New:* a constraint in activation-density space, not weight space; no old data. *Test:* compare to SAE-activation regularisation (2606.26629) at equal compute.
11. **Hash-chain of behaviours.** Each consolidation appends a Merkle root of output hashes over self-probes; an edit must keep earlier roots within Hamming distance d. *New:* tamper-evident retention log costing only roots. *Test:* how often roots catch real harm vs false alarms.
12. **Gauge negotiation.** Many weight changes are function-preserving (neuron permutations, rescalings). The old side proposes a *gauge move* that relocates its behaviour away from the edit's support before the edit lands. *New:* old behaviours relocate instead of blocking. Differs from memory relocation S1 by being edit-triggered and forward-only. *Test:* gauge search budget; retention after edit.
13. **Behaviours that bid with capacity they release.** An old behaviour can pay for keeping its directions by releasing others it no longer uses (its least-sensitive directions under self-probe perturbation). *New:* a swap market in directions; old side is both seller and buyer. *Test:* plasticity on a 10-task stream vs GPM span saturation.
14. **Sensitivity sketches by random forward perturbations.** Each old behaviour stores a sketch S = Σ_i r_i · score(W + σ r_i) over self-probes, i.e. an ES-estimated gradient of its own retention, compressed by count-sketch. An edit is projected away from S. *New:* old-gradient proxy built without any backward pass and without data. *Test:* sketch bytes vs retention, vs LOKI.
15. **Old behaviour writes its own guard rule in text/program.** For agents: an old skill, prompted with the proposed harness/lesson edit, writes a test it would fail on. The edit is admitted if the test passes. *New:* the protected behaviour authors the retention test at edit time. *Test:* on the G1 router, compare to random prior-task test sampling; retention = old-route success.
16. **Majority of self-checks under input noise.** Old behaviour = the set of inputs whose outputs are stable under small noise (robust regions), found forward-only. Edits must keep each robust region robust. *New:* uses the model's own stability as a free label of "what it knows". *Test:* compare region-preservation to random probes.
17. **Bilevel ES with a learned old-side critic that never sees old data.** A small critic network learns to predict "edit harms old behaviour" from (Δ statistics, self-probe output shifts), trained across many synthetic task pairs in a meta-phase. *New:* a transferable veto learned on synthetic streams. *Test:* train critic on synthetic MLP tasks; apply to a new stream; retention vs no critic.
18. **Time-reversed negotiation.** Run the edit, then run a short forward-only "undo" search that restores self-probe outputs while preserving new-task score; keep whatever survives both. *New:* constraint applied after the fact by a reconciling search, not a projector. *Test:* undo budget vs final retention/gain.
19. **Old behaviours as stochastic resonance.** Inject structured noise into the edit; old behaviours that are robust to it absorb it, fragile ones amplify. Detect amplification forward-only, then shrink the edit along that noise pattern. *New:* identifies fragile old behaviour by its response to probing noise during the edit. *Test:* correlation of amplification with actual old-loss increase.
20. **Edit as a contract signed by k random sub-networks.** Split the model into k random masks; each masked model is an "old witness". An edit is admitted only if each witness's self-probe outputs move less than τ. *New:* witnesses are cheap sub-views of the model itself, no extra memory. *Test:* k and τ sweep; retention vs unmasked probe check.
21. **Negotiation over a shared rank budget in LoRA.** New task and each old LoRA bid for rank in a shared adapter with forward-measured marginal utility per rank; allocation by VCG. Differs from Vickrey MoE capacity (PR #45) because bids are made by *old* behaviours defending their rank. *Test:* 5-task LoRA stream; retention vs O-LoRA-style fixed allocation.
22. **Output-space treaties.** Old and new agree on a partition of the output simplex (e.g. logits of some classes/tokens are "old territory"). Edits that move old-territory logits on self-probes are clipped. *New:* the treaty is in output space, cheap to check, no input data. *Test:* class-incremental MLP; compare to decision-invariance regularisation (2611.20619).
23. **Self-play red team for the old side.** A forward-only generator searches for inputs where edited and old models disagree *and* the old model was right by its own consistency (e.g. agreement with its augmented views). Those inputs become the old side's bargaining evidence. *New:* evidence of harm is produced adversarially from the model alone. *Test:* harm recall vs random self-probes.
24. **Forgetting insurance.** The editor must post a "premium": a reversible delta (seed log, as in PR #50's seed-log autobiography) stored until old behaviours certify no harm; if harm appears later, the premium is used to roll back that edit only. *New:* combines escrow with paid insurance and per-edit rollback. *Test:* bytes of premium vs retention on a 10-edit stream.
25. **Self-consistency as the universal old currency.** Use the old model's agreement with itself under augmentation/paraphrase as the only old-side utility. Every behaviour can be priced in the same unit, without labels or inputs from the past. *New:* gives root cause 3 a currency. *Test:* does preserving self-consistency on self-probes predict A retention (R²) better than weight-spectrum null space?
26. **Behaviour quorum via weight hashing of attention heads.** Each head carries a tiny signature of its typical attention entropy on self-probes. An edit that changes too many signatures at once is split into smaller edits applied sequentially. *New:* negotiation by edit splitting rather than vetoing. *Test:* retention vs one-shot edit at equal total delta.

## Deeper sub-questions (ranked by how likely they lead to a new primitive)

1. **Can a model generate, from its weights alone, probe inputs whose output shifts predict old-task harm as well as held-out old data does?** (Ideas 1, 3, 16, 23, 25.) This is the gate for the whole node: if self-probes reach, say, R² ≥ 0.7 against true old-loss change across edits, the old side gains a forward-callable interface (root cause 1) and every negotiation scheme becomes possible. Decisive test: rank-correlate self-probe KL with held-out A loss change over 200 random ES edits, vs LOKI spectrum and 1% replay.
2. **What is the minimum byte cost of an edit-conditioned old-side oracle, and does it scale sub-linearly with the number of old behaviours?** (Ideas 2, 7, 11, 14.) A primitive exists if retention-per-byte beats replay by an order of magnitude and stays flat as behaviours accumulate.
3. **Is there a forward-only currency in which old and new behaviours can trade, such that bargaining beats a tuned fixed penalty?** (Ideas 4, 6, 13, 21, 25.) If Nash or VCG allocation over forward utilities dominates a fixed λ on the Pareto front, constraints become protocols.
4. **Can old behaviours move instead of block (gauge or capacity relocation triggered by the edit)?** (Ideas 12, 13, 18.) If relocation recovers plasticity that projection loses on long streams, it answers span saturation.
5. **Does delayed acceptance (escrow, insurance, undo) catch harm that immediate checks miss, at lower cost?** (Ideas 9, 18, 24.) Least likely to be a new primitive (close to rollback ideas), but cheapest to test.

## Shared decisive test

Sub-question 1 decides most of the tree. If self-probes cannot predict old harm better than the weight spectrum, ideas 1–3, 8, 10, 14, 16, 19, 23 and 25 all fall back to replay or to LOKI, and the node should be closed with that negative result.
