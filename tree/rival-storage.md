# Rival storage: can a refuted shortcut become a reusable repair?

**Parents:** [Carried identifiability (PR #80)](https://github.com/manojbajaj95/cl/pull/80/files), which carries *unresolved* alternatives; [witness sets (PR #81)](https://github.com/manojbajaj95/cl/pull/81/files), which carries the experiments that distinguish an alternative from the rule.

**Question:** If we keep the *refuted rival* instead of just `f(x) = y`—as a margin, twin pair, or rival adapter—can data from a later task help fix the old shortcut without access to the old task's data?

**Status:** Idea generation only. The tests below are sketches; none were run.

## Why the parent approach fails

**What was observed.** In [PR #57's cue-vs-rule probe](https://github.com/manojbajaj95/cl/pull/57/files), the oracle-conflict arm went from 95.5% flipped / 95.0% aligned A accuracy before B to 54.2% / 53.1% after B-only training. The drop on *both* splits rules out a simple return to the original cue-copying behavior as the complete explanation: pure cue-copying would ace aligned A. The result does not distinguish overwritten features from a broken readout. Neither parent measured whether witness or rival memory reverses that drop.

**Structural root cause:** A refutation is scoped evidence against a mechanism; a label is a constraint at a point. In the binary case, where the rival disagrees, its prediction is already the other class. Adding that prediction to a saved label or changing cross-entropy to a point margin doesn't say which input change makes the rival flip, or what should stay invariant. A lookup can pass all the saved margins. Twins add an intervention, but finitely many twins still don't specify when it is valid. An adapter can encode the rival's behavior off-support, but a delta in A's feature coordinates may enact a different behavior after B.

**Where delayed repair breaks:** Even a faithfully stored rival doesn't specify why evidence from B bears on A. Showing that a bit is spurious for B's label says nothing about A unless a shared mechanism or an intervention with the same meaning links them. And knowing what *not* to use doesn't recover what *to* use if A's rule is gone: two old rules that fit all retained constraints and all B observations can still disagree on unseen A inputs. A negative-only store can't decide between them. Keep a positive carrier (e.g. a frozen readout **and** a usable representation, or a compact rule fragment), and treat an unmatched rival as uninformative rather than as permission to edit.

The candidate primitive is therefore **a transportable refutation**: the rival's failure expressed as a scoped intervention, an operation for checking whether later evidence applies, and an edit backed by a surviving positive carrier. Test whether any sparse version of this object buys more than simply keeping the carrier or replaying the same witnesses.

## Nearest prior art

Light screen: Hugging Face Papers searches for counterfactual replay, counterfactual pairs, and contrastive explanation memory in continual learning; checked the linked arXiv abstracts. The distinctions below are candidate deltas, not claims of exhaustive novelty.

| Checked | Already covers | Open delta for this node |
| --- | --- | --- |
| [DivDis](https://arxiv.org/abs/2202.03418), [Learning from Failure](https://arxiv.org/abs/2007.02561) | Diverse off-support hypotheses selected with extra supervision; a biased network used to find examples to debias against | Persist the scoped refutation, then bind an intervention from a different task to a repair of an earlier mechanism. A spare biased head alone is not new. |
| [Dark Experience Replay](https://arxiv.org/abs/2004.07211), [Proxy-based Contrastive Replay](https://arxiv.org/abs/2304.04408) | Old logits attached to replay examples; class contrast through proxies | Neither abstract describes a refuted mechanism with a scope that can be checked on later tasks. Storing logits or adding contrast alone is a control. |
| [Counterfactually Augmented Data](https://arxiv.org/abs/1909.12434), [Counterfactual Alignment](https://arxiv.org/abs/2312.02186) | Paired edits to reduce spurious sensitivity; sharing counterfactuals across classifiers to diagnose spurious behavior | A reusable *scope and update rule*, not just more pairs or evidence that classifiers share a shortcut. |
| [Temporal Logic Counterfactual Experience Replay](https://arxiv.org/abs/2303.02135), [COUNTERMEM](https://arxiv.org/abs/2609.31874), [MemAdapter](https://arxiv.org/abs/2610.05162) | Off-policy experience from counterfactual rollouts; verified bad/good action records retrieved across tasks with a fixed base LLM; context-sensitive calibration of retrieved memory | COUNTERMEM already stores the wrong action, correction and reuse conditions. The proposed delta is later evidence *rewriting the old decision mechanism*, not retrieving a better action or changing how strongly to heed a memory. |
| [CUBER](https://arxiv.org/abs/2211.00789) | Use gradient alignment to decide when new data should update old tasks | Test alignment of *interventions with matched semantics*, including a gradient-matched task where the same feature is causal and transfer would be wrong. |
| [Idea ledger and flood triage (PR #6)](https://github.com/manojbajaj95/cl/pull/6/files) | C1 contrastive-pair memory was killed as CAD/contrastive ICL; functional syndromes were falsified on diffuse damage; verifier twins and negative-dependency invalidation already appeared in the flood | No raw logit subtraction as a primitive, no assumption of sparse damage, and no novelty credit just for using twins or invalidating dependencies. |

## Shared paper testbed

A learns a rule with a correlated cue. During A, limited verification refutes the named cue rival but A can still rely on it in other regions. Then discard raw A data. Give B one of three matched treatments: an intervention on a mechanism shared with A, ordinary observations with similar predictive statistics but no intervention, or an intervention on an apparent match with different semantics. Use synthetic variables so evaluation knows which is which; show algorithms only the metadata their memory budget buys. Evaluate both an intact-carrier setting and one where ordinary A forgetting is allowed. Measure A immediately before and after B: report flipped-A gain, A's normal aligned accuracy, an unrelated earlier task U's normal accuracy, and B accuracy. A repair must improve *unseen* flipped A over controls without trading away aligned A, U or B; false repairs on the mismatched B arm count against it. A eval sets never enter matching, selection, training or stopping.

Charge all added bits (including frozen feature copies, constants, IDs, adapters and generator state), and match update work and access to B interventions. Compare carrier-only, carrier plus B, equal-byte oracle-conflict replay, same-witness replay or OGD as separate baselines, and the closest margin/twin/adapter baseline. Replay arms are benchmarks allowed a saved A buffer; proposed no-old-data arms cannot consume saved A inputs or labels after A. A literal twin buffer is thus a comparison, not a valid solution; a twin *operator* can act on new B inputs. Each retention check below adds to, rather than replaces, the aligned-A and U check.

## Raw ideas (unfiltered)

### What to store

1. **A repair receipt with a frame condition.** **Mechanism:** Store a cue intervention, one invariant that falsified the rival, and a list of variables the intervention must leave unchanged. Make the compiler reject B interventions that violate that list. **Why new:** Unlike a witness margin or COUNTERMEM's retrieval conditions, the frame condition determines whether a proposed *edit* is allowed. **Cheapest first test:** Add one hidden-by-default collateral bit to the toy B intervention; compare with a scope-free twin operator. **Retention:** Check A and U particularly when flipping the same named cue also changes a rule input.
2. **Derivative stencil instead of a margin.** **Mechanism:** Keep the desired response along a cue flip together with a nonzero response along a matched rule flip; evaluate both on B examples after coordinate matching. **Why new:** Counterfactual Alignment uses shared counterfactuals diagnostically; this stencil constrains the old readout and rejects the trivial constant solution. **Cheapest first test:** Two binary differences, versus an equal-byte rival margin on matched synthetic probes. **Retention:** On normal A and U, verify that legitimate rule flips still change decisions.
3. **The rival's algebra, not its weights.** **Mechanism:** Fit a tiny transition table of how a rival's prediction changes under generators (flip, swap); keep the table and a scoped assertion of which transitions A forbids. **Why new:** Unlike the fork adapter in PR #80, it can recognize the same behavior under a permutation without transferring a weight delta. **Cheapest first test:** Reorder feature channels before B; compare a two-generator table with an equal-byte adapter. **Retention:** Check A and U through the permutation, including a legitimate cue user that shares one transition.
4. **Two-sided equivalence classes.** **Mechanism:** Store a quotient that says which transformations must identify A inputs, plus a minimal separating set of transformations that must *not*. Carry the quotient via B's transformation system, not any labeled points. **Why new:** PR #80's partition refinement groups candidate features the evidence can't distinguish; this groups *inputs under scoped transformations* and retains required separations. **Cheapest first test:** On a two-bit toy, distinguish an invariant direction from an XOR interaction using two transformation generators. **Retention:** Measure normal A and U on distinct classes at risk of accidental merging.
5. **A refutation's nearest valid boundary.** **Mechanism:** Store a short predicate for where the rival failed *and* an adjacent regime where the same mechanism was legitimate. Attach the resulting piecewise restriction to the A readout. **Why new:** A disagreement-region sampler in PR #81 says where rivals split, not where an otherwise successful removal must stop. **Cheapest first test:** Give A one context where cue copying really is the rule and compare to a global cue penalty at equal bytes. **Retention:** Split normal A by context and report U separately.
6. **A residual decoder that only repairs disagreements.** **Mechanism:** Encode a small positive patch in the basis induced by the rival's intervention, with an explicit null output outside that basis. B estimates the new basis, then the old patch is decoded in it. **Why new:** DER preserves old logits and PR #80 carries a fork direction; here B supplies coordinates for a fixed, scoped correction rather than choosing a stored head. **Cheapest first test:** Rotate two latent components between A and B; compare to an equal-rank old residual adapter. **Retention:** Check that normal A and U predictions outside the patch's support stay intact.

### How later evidence binds

7. **Intervention handshake.** **Mechanism:** Match A and B via two probes: one that should reproduce the rival's response, one it should leave unchanged. Require both before routing B's evidence to A. **Why new:** CUBER's alignment comparator can match correlated gradients; the handshake demands distinct positive and negative signatures. **Cheapest first test:** Build two B candidates with the same gradient at initialization but different response to the second probe. **Retention:** Wrong-handshake B must leave normal A and U at their carrier-only levels.
8. **Commuting-square transport.** **Mechanism:** Infer a feature map on B and accept a rival binding only when mapping then intervening agrees with intervening then mapping on held-out B probes. **Why new:** DivDis selects hypotheses; this tests whether a change of coordinates has preserved the *meaning of a refutation*. **Cheapest first test:** Enumerate permutations on four bits; include two with identical observational fit where only one preserves the intervention. **Retention:** Track aligned A and U when multiple maps pass and the system abstains.
9. **Composition-only evidence.** **Mechanism:** Store a refuted interaction rather than independent cue names; permit a fix only if measurements of B's joint intervention minus its single-factor effects reproduce the interaction. **Why new:** A feature-trust ledger would mark the individual features; the stored object targets an interaction without outlawing its parts. **Cheapest first test:** Use a two-bit XOR shortcut where both singleton effects vanish under balanced sampling; compare singleton trust scores. **Retention:** U uses one of the bits legitimately; check it alongside normal A.
10. **A matched but disqualifying example.** **Mechanism:** Archive a compact *predicate* for a failure-to-transfer case alongside each refutation. If B matches the signature of both the refutation and the disqualifier, withhold the edit until a second intervention separates them. **Why new:** Unlike LfF's biased scorer, this is negative evidence about *the mapping*, not about B's labels. **Cheapest first test:** Use a same-cue-name A/B pair with different causal roles and no extra twin budget. **Retention:** Verify normal A and U after the false match as well as after the genuine match.
11. **Competing bindings, agreement-only surgery.** **Mechanism:** Keep all A↔B maps that pass the intervention checks and implement only the A edit on which those maps agree. Defer the rest. **Why new:** PR #80 carries ambiguity about the rule; this carries ambiguity about the *translation*, without maintaining several whole old policies. **Cheapest first test:** Two symmetric B channels identify one safe component of a two-component edit; compare to choosing the highest-scoring map. **Retention:** Check normal A and U that legitimately use the ambiguous component.
12. **Reversed-sign transfer.** **Mechanism:** Store which changes in context turn a rival from a bug into a useful feature, so B evidence can authorize opposite readout edits in different scopes. **Why new:** A global trust dial or OGD mask cannot express signed obligations for the same mechanism. **Cheapest first test:** Cue causal in one B context and spuriously predictive in another; compare with a per-cue scalar under a matched budget. **Retention:** Report worst-context normal A and U accuracy, not just means.

### How the old task is repaired

13. **Counterfactual adapter as a measuring instrument.** **Mechanism:** Use a small rival adapter only to amplify shortcut behavior in a shadow pass, identify the readout term that changes on new B twins, then subtract that term from A only. Do not merge or deploy the rival adapter. **Why new:** PR #81 uses rival resurrection to trigger replay; here the rival's controlled reintroduction measures a removable component without A replay. **Cheapest first test:** Compare with direct rival-delta subtraction after a known hidden-basis rotation. **Retention:** Measure normal A and U before and after the subtraction, including cases when the rival adapter drifts.
14. **Repair by cancellation only in a product model.** **Mechanism:** Run the current old readout twice with B-derived cue components of opposite sign; cancel the odd component only when the scoped twin operator is valid. **Why new:** Unlike killed C1's good-minus-bad context logits, the cancellation enforces an intervention symmetry on the old readout; nonlinear even-order leakage is an explicit failure mode. **Cheapest first test:** Linear cue term plus quadratic leakage; compare with a same-compute single-pass cue clamp. **Retention:** Check normal A in scopes where cancellation must be off and check U at the same inference budget.
15. **Local inverse with a drift cutoff.** **Mechanism:** Store the action of a rival perturbation and its inverse on small A readout statistics. Re-estimate that action on B and allow inversion only if it remains well conditioned and preserves the positive carrier. **Why new:** It inverts a measured *behavioral component*, not historical SGD as in reversible-update ideas. **Cheapest first test:** Two-channel linear model with progressively collinear cue and rule channels; compare to fixed delta rollback. **Retention:** Check normal A and U around the cutoff where inversion would otherwise amplify noise.
16. **Refutation transactions.** **Mechanism:** Compile two independent scoped repairs into a joint edit only if both orders satisfy both intervention contracts. Otherwise search for a joint solution, or apply neither. **Why new:** Flood O2 imposes commutative learning generally; this uses competing negative obligations to decide when separate edits cannot be composed. **Cheapest first test:** Two low-rank repairs sharing one feature where order changes the answer; compare to additive adapter merge. **Retention:** Score A after each edit order and U under the joint edit, keeping B learning matched.
17. **Counterfactual gradient substitution.** **Mechanism:** Replace just the cue-mediated term of the B update into shared features with the corresponding term from a matched B intervention. Keep evidence-dependent changes to A's readout distinct from feature maintenance. **Why new:** PR #81 anti-projects gradients using an A disagreement set; this estimates a *replacement gradient* from B, allowing legitimate shared learning instead of deleting an entire direction. **Cheapest first test:** Use correlated linear features where projection also removes the useful B component. **Retention:** Check normal A and U through B; reject a flipped-A win that comes from suppressing B learning.
18. **Refutation-scoped feature splitting.** **Mechanism:** If A needs cue invariance but B demonstrably needs the cue, duplicate only the contested feature channel and give the old and new readouts different bindings. **Why new:** PR #60 already splits colliding features; the proposed distinction is an intervention-based criterion for *semantic* incompatibility, not gradient collision. **Cheapest first test:** Compare to a gradient-conflict split at equal channel count with B arms that have the same gradient but different legitimate cue roles. **Retention:** U must still receive its original semantics, and normal A must survive the split.

### What stays valid as tasks accumulate

19. **Refutation dictionaries with task-specific polarity.** **Mechanism:** Store one intervention operator for a class of rivals, with short per-task signed constraints and exceptions. Learn how B binds to the operator once, not separately for each old task. **Why new:** PR #80's feature-trust ledger shares a scalar; this shares an executable operation while allowing different old tasks to disagree about it. **Cheapest first test:** Three old tasks using the same cue, one legitimately; compare with independent operators and scalar trust at matched bytes. **Retention:** Report normal accuracy for every old task, especially the exception.
20. **Closure under rival replacement.** **Mechanism:** After repairing A, describe transformations under which a surrogate rival would count as the same failure, and use B environments to test the closure before retiring the receipt. **Why new:** PR #81's re-refutation refits a current rival on demand; an explicit closure covers a family of replacements before one becomes dominant. **Cheapest first test:** Replace a banned cue with its complement or an exact proxy; compare to checking only the stored rival. **Retention:** Check normal A and U that use nearby but non-equivalent features.
21. **Parity checks over intervention identities.** **Mechanism:** Keep redundant composition equations among refutations; when scopes drift, test the equations on B to find a consistent set of bindings, or abstain if not identifiable. **Why new:** Functional syndromes tried to locate sparse damage to weights; this checks the consistency of a known graph of interventions with no sparse-weight premise. **Cheapest first test:** Three interventions with one composition identity; misbind two across the stream and see whether the check abstains rather than blaming one. **Retention:** Normal A and U must not regress after an ambiguous diagnosis.
22. **Positive-carrier insufficiency certificate.** **Mechanism:** Search a tiny symbolic rival class for two rules consistent with the surviving carrier, receipt and B evidence that imply different A repairs. Return the distinguishing intervention still required rather than guessing. **Why new:** PR #80 carries plausible hypotheses before resolution; this produces a concrete *post-refutation non-repairability witness* after carrier damage. **Cheapest first test:** Erase one old parity factor, then enumerate compatible two-bit rules; compare to confidence-thresholded repair. **Retention:** On ambiguous B, measure whether abstention preserves normal A and U relative to doing nothing, not whether it masks existing forgetting.
23. **Evidence that expires on a change of semantics, not time.** **Mechanism:** Keep a receipt active only while its intervention laws are reproducible on new tasks; retire the binding, not the refutation, when a later B violates those laws. **Why new:** Negative-dependency invalidation in PR #68 already withdraws conclusions; here the trigger is a failed executable equality, and the negative evidence survives for reuse with a fresh map. **Cheapest first test:** A→B→C→D with one deceptive remap in C and a valid remap in D; compare permanent and time-decayed bindings. **Retention:** Check normal A, U and B after each task, including recovery in D without A data.
24. **Bits spent on disambiguating the repair.** **Mechanism:** Store only those parts of the rival whose removal would allow two different *safe edits* on the same B intervention. Keep unresolved ambiguity where every candidate implies the same edit. **Why new:** Teaching-dimension witnesses distinguish hypotheses; this compresses by the action needed later, not by naming every rival correctly or finding sparse damage. **Cheapest first test:** Enumerate rival truth tables and two edit operators, then compare edit disagreement under equal-byte witness selection and action-based compression. **Retention:** Include normal A and U in the safe-edit definition using predeclared toy constraints, and verify both on independent evaluation sets.

## Ranked deeper sub-questions

Ranked by chance of yielding a reusable primitive, not by ease of the next test.

1. **Can we check that a refutation means the same thing in two tasks?** (1, 7–11) Best primitive bet: a transport test with positive and negative controls, composable independently of the repair method. First distinguish two observationally matched B interventions where only one preserves A's mechanism. If a name match or gradient alignment ties it, there is no reason to store a richer binding.
2. **What is the smallest positive carrier for a negative-memory repair?** (6, 13, 15, 22, 24) Seek a pair: a sufficient repair state and an impossibility witness when it is missing. An exact enumeration of compatible rules can separate missing information from optimizer failure before any network work. A frozen carrier that already solves A with no rival is the key null.
3. **Can we define edits by their intervention effects rather than their parameter addresses?** (2–4, 13–18) A portable edit would enact the same scoped repair through permutations or rotations of the representation without touching unrelated old behaviors. If only the original coordinate system works, this is another adapter regularizer.
4. **Can a negative memory survive changes of scope and composition without becoming a ban list?** (5, 12, 16, 19–21, 23) Seek a refutation language with explicit exceptions and invalidation of bindings, not unconditional prohibitions. It earns primitive status only if many receipts reuse those operations and beat per-task storage at matched bytes while preserving all normal old tasks.
