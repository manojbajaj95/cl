# Merger certificates: what must a continual learner store, and what can it just replay?

Parent: [Training-invariant edit content, card 19 (PR #106)](https://github.com/manojbajaj95/cl/pull/106). **Node question:** If legal later training can send two incompatible edit targets to the same learning state, can the witness tell a bounded continual learner what to save, when to replay it, and when replay cannot help?

## Root cause: an installed edit cannot be read back from information training destroys

The parent tries to install an edit by finding a readout that training preserves and a write that can selectively change it. That works in the parent's linear positive control because future gradients never touch the protected complement. It fails when every admissible way of installing two incompatible targets admits a legal continuation that makes their **full learning states** identical. Better directions, larger initial margins, and a cleverer decoder of that state cannot separate the two afterward. This is a conditional obstruction, not evidence that arbitrary SGD trajectories hit exact collisions. A single merged pair rules out those specific lifts; it rules out a class of editors only when each admissible joint choice of lifts is covered. An uneditable invariant or lack of install feasibility is a different obstruction.

**What the certificate says.** Fix a base, admissible edits and continuations, a retention contract, and a deadline. Give two runs the same later batches, public metadata, and final query, varying only the earlier target. Exhibit legal installs of both requests, a common suffix, and a prefix at which their states agree but the sets of acceptable answers are disjoint. Include weights, optimizer registers, precision, counters, persistent caches, and retrieval keys in the state of the system being tested. Check legality and untargeted retention floors in both arms at every prefix; a contradictory revision or an illegal reset is not a witness. If an earlier checkpoint already breaks the target obligation, report that failure separately: the merger certifies loss of distinguishability, not the first time a miss occurred. An identical public suffix suffices; different suffixes can only be used if whatever suffix information the decoder actually sees also agrees. With exact equality, any target-blind deterministic replay from that state with the same inputs takes the same path. A randomized decoder with identical inputs cannot guarantee either answer on both runs; with equal priors, its average success on the pair is at most one half. Equal predictions today, nearby weights, or two sampled runs with different optimizer moments are not this witness. For non-exact stochastic mergers, a verified bound on total variation of the decoder's transcript laws gives a separate equal-prior binary success bound of `(1 + TV)/2`; a distance in weight space does not.

### From an obstruction to a planning object

Record each witness as a **deadline, a pair of live contracts, a common continuation, and the actions still available**. A plan can (i) prevent the merge by selecting a legal lift or updating differently, (ii) carry a discriminator in protected state or through a target-dependent replay source, or (iii) pay for a new observation that can actually tell the targets apart. Include abstention or a declared relaxation only if the contract allows it. Distinguish recovering the answer through read-through memory from reinstalling it into the learner: a bit can select the right answer and still be useless if no legal replay sequence can restore it by the deadline without harming old tasks. Replaying more target-blind data after a full merger cannot create the missing distinction.

For a finite host with a fixed update policy, make a graph on admissible installed instances: connect two if a common continuation leaves the same decoder observation at a required checkpoint and incompatible obligations then apply. Any fixed-length protected message assigned before that continuation must assign different messages to adjacent instances, so it needs at least `ceil(log₂ χ)` bits for this graph. For single-valued answer obligations, fixed public checkpoints, and an unrestricted decoder, coloring the graph of **all** conflicts under that decoder's observation suffices for read-through. Include conflicts across different suffixes if the decoder cannot tell those suffixes apart. General sets of acceptable answers may require a higher-order constraint (pairwise intersections need not have a common element). A graph built from a subset of witnesses gives a lower bound for that host and interface, not a universal exact rate. Replaying before a merger, changing the host's transition, or buying a new observation changes the graph; legal repair and wall-clock deadlines add constraints beyond coloring. This is the classical side-information coding floor already touched by PR #105. The candidate primitive is a **choice over actions that prevent edges or pay for them**, with memory bits, replay calls and floors accounted for on the same plan. In a finite oracle, enumerate policy choices at each observable prefix before enumerating legal continuations; two runs with the same available information must get the same action, so a cut that requires seeing tomorrow's batch does not count.

**Exact CPU-sized example (by construction, not an SGD result).** Let a past edit install two independent bits `(a,b)` in a register, with a separate old skill `r` that always stays fixed. The next window allows exactly one publicly named batch type: `A` erases `a` to zero, `B` erases `b` to zero; the deadline is immediately afterward, when the learner must answer both bits. No alternative installs, outside queries or early repairs are allowed. Every possible input pair has an erasing suffix that makes it collide with a partner. Saving either raw bit alone fails one of the two branches. Saving just `a XOR b` works on both: the named batch identifies the surviving bit, which together with the saved parity decodes the other. Zero bits fail on the pair `(0,0),(1,0)` under `A`. If legal replay can set the erased register after the batch, the same bit selects the one required replay action; if the register is now locked, read-through still works but reinstalling is impossible. If both erasures may occur before any decoding or repair, all four targets collide and two bits are needed. Nothing about this calculation says natural training has these kernels or exposes which distinction it lost.

### Prior art and experimental rules

- Read [PR #6's ledger, triage and top 10](https://github.com/manojbajaj95/cl/pull/6/files). Do not repackage sparse-damage syndromes, weight-statistic conservation, Gramian/readiness forecasting or half-life ranking. [PR #105](https://github.com/manojbajaj95/cl/pull/105) counts description bits with receiver side information; its 76–94% is the loss of *description savings*, not the fraction of installed edits erased. [PR #104](https://github.com/manojbajaj95/cl/pull/104) asks when editor states are already equivalent for all continuations. [PR #108](https://github.com/manojbajaj95/cl/pull/108) searches for safe coalescence of compatible histories; here a legal coalescence between **incompatible** live obligations is something to pay for or avoid. No new coding theorem, quotient algorithm, or synchronizing word by itself is a CL novelty claim.
- Nearest empirical controls: [knowledge-edit decay under fine-tuning](https://arxiv.org/abs/2511.05852), [small episodic buffers](https://arxiv.org/abs/1902.10486), [maximally interfered retrieval (MIR)](https://arxiv.org/abs/1908.04742), [Dark Experience Replay](https://arxiv.org/abs/2004.07211), and [learned replay scheduling](https://arxiv.org/abs/2209.08660). Strong nulls are a same-byte intent buffer with a rewrite API, exact graph coloring plus a fixed replay rule on a finite host, and prevention-only regularization or projection. The cited titles/abstracts are a nearest-neighbor screen, not novelty clearance.
- All first tests below are CPU proposals. In learned hosts, use exact equality of the actual quantized or discrete state, not quantized measurements of a higher-precision host. Include an injective control (e.g. exact scalar quadratic SGD with `0 < ηλ < 1`), a matched-margin nonmerging twin, and held-out batch orders/target families. First establish variation in the necessary memory or repair deadline across branches. Compare at matched install success, new-task progress, total persistent bytes (including memory code, routing and optimizer state) and replay, inference and observation budgets. Report the live targets and independent old tasks on disjoint examples after each commit and at deadlines, including worst groups and legitimate revisions separately. Do not give any arm tomorrow's batches for free.

## Raw ideas

### A. Make the certificate decide what earns a byte

1. **Cut-or-carry planner.** **Mechanism:** label each detected collision by the legal actions that prevent it and the protected messages that distinguish it otherwise; jointly choose cuts and messages under separate update and memory budgets. **Why it might be new:** a write changes which distinctions must be stored, rather than memory ranking following a fixed write policy. **Cheapest test:** enumerate a four-state editor with competing cuts; compare projection plus a separately optimized buffer and graph coloring plus fixed replay. **Retention:** check a shared untouched skill and both conflicting targets after all permitted suffixes.
2. **Deadline parity.** **Mechanism:** store a shared parity over obligations whose distinct loss modes are mutually exclusive until an announced deadline; decode just in time from whichever witnesses survive. **Why it might be new:** classical erasure coding is the null; the CL bet is that a learner can reuse surviving internal behavior as code side information without dedicating a full slot to each task. **Cheapest test:** implement the two-bit oracle, then allow the double-erasure control; compare raw retained labels and a static code with the same host side information (which should tie in the toy). **Retention:** check each task's held-out variants and a readout sharing the replayed register.
3. **One representative, several repairs.** **Mechanism:** store a prototype example only when replay of it yields acceptable outcomes for every target assigned to it, possibly acting differently on different surviving state; split groups on legal-repair counterexamples rather than semantic distance. **Why it might be new:** defines interchangeability by what can still be repaired after training, not prototype similarity or installation gradients. **Cheapest test:** brute-force single-example repairs for quantized linear classifiers; pit against k-center and gradient matching at equal bytes. **Retention:** trace untouched classes before and after the common repair.
4. **Incompatibility hyperedges.** **Mechanism:** find a set of set-valued contracts with no common post-merger answer even though every pair overlaps; assign memory by ruling out these sets, not just pairs. **Why it might be new:** a CL buffer can exploit interchangeable skills without missing higher-order losses invisible to pair checks; constraint hypergraphs alone are known. **Cheapest test:** use acceptable output sets `{A,B}, {B,C}, {A,C}` at one endpoint and compare to pair-only selection. **Retention:** test unseen inputs for the three contracts and an unrelated literal answer that must remain unchanged.
5. **Multi-query memory toll.** **Mechanism:** attach the price of retaining each distinction to the smallest set of future queries for which its absence matters; release or reassign it only when an explicit interface change removes all such queries. **Why it might be new:** contracts retire bits by removing distinguishing behavior, not because examples have aged or been retrieved less often. **Cheapest test:** toggle query families in a finite text transducer with old equally frequent distractors; compare FIFO and frequency-based retirement. **Retention:** evaluate unrevised old query families and test that authorized retirement does not damage their answers.
6. **A code over allowed lifts.** **Mechanism:** when installing the same task admits several equally usable states, allocate lifts jointly across tasks to reduce the required external code; charge restrictions on future writes. **Why it might be new:** the internal codewords are chosen for *post-training* repair equivalence, not nearest weight alignment or install-time precision. **Cheapest test:** exhaust two lifts per target and two suffixes; compare independently chosen lifts plus optimal coloring. **Retention:** check unseen old examples that share writable coordinates, including after a second edit.

### B. Price exactly when replay is useful

7. **Replay option with a last exercise time.** **Mechanism:** quote the last checkpoint at which a stored item can still be legally used to prevent a collision, then spend replay just before that window closes. **Why it might be new:** protects a repair opportunity rather than scoring a predicted loss by magnitude. **Cheapest test:** one stream where a quantizer closes a repair path and another with equal immediate loss but no closure; compare MIR and a learned scheduler given the same lookahead. **Retention:** measure unrelated old tasks at every checkpoint and verify the repaired targets on unseen examples after the window.
8. **Two-part repairs without two labels.** **Mechanism:** store a short discriminator and replay a target-blind shared carrier to reopen a writable path; use the bit to pick the final action. **Why it might be new:** separates replay that restores reachability from evidence that identifies what to restore; neither part alone can work. **Cheapest test:** a finite gated learner with a common unlock action; ablate each part and compare equal-budget full-intent replay. **Retention:** test old functions through the unlock and after relocking, where side effects could hide.
9. **Replay only the XOR of repairs.** **Mechanism:** when the survivor identifies which direct repair operators are still applicable, store a composition of repair operators rather than their targets; cancel known factors to obtain the missing action. **Why it might be new:** attempts to exploit shared update algebra for executable repairs, beyond encoding their output labels; fails if legal updates do not support cancellation. **Cheapest test:** use reversible bit-flip edits with one lost effect, then a noncommuting negative control; compare parity over labels and a stored edit log. **Retention:** check unrelated readouts affected by the operators after each commit and a follow-on task.
10. **Learn a replay action by covering witnesses.** **Mechanism:** distill one minibatch whose *pre-merger* update prevents several otherwise certified pairs from colliding, subject to new-task and retention guards. **Why it might be new:** a replay item is judged on which incompatible branches it keeps repairable, not on matching losses or gradients on one trajectory; standard distillation is the null. **Cheapest test:** optimize or enumerate a one-example replay set on a tiny quantized two-head model and compare to gradient-matched replay. **Retention:** check both old heads on disjoint samples and their worst checkpoint after an unseen batch order.
11. **Target restoration with a temporary loan.** **Mechanism:** borrow a shared scratch slot only long enough to unpack a protected discriminator and commit a durable repair, then lend that slot to the next expiring obligation. **Why it might be new:** schedules workspace and durable bits separately, using deadlines at which distinguishability is actually lost. **Cheapest test:** interleave two finite repair sequences using one scratch slot; compare persistent slots, greedy expiry, and joint deadline scheduling as the formal null. **Retention:** query the old task whose scratch is reclaimed at each handoff and after the next training window.
12. **Route to evidence, not to an old answer.** **Mechanism:** keep a key to an independently available example source only if a certificate shows the source can deliver target-identifying evidence on time; carry an actual residual if the source can disappear. **Why it might be new:** provenance is priced by whether it can defeat a specific collision under source failure, unlike frequency-based retrieval. **Cheapest test:** simulated source outages with identical answer popularity and different witness coverage; compare full labels and uniform key caching. **Retention:** test old tasks both during and after source outages; charge all per-target information in the source or restrict every arm to the same public source.

### C. Plan under uncertainty without treating a predictor as a proof

13. **Counterexample-priced branching.** **Mechanism:** start with an optimistic store/replay plan, search legal common suffixes for an uncovered edge, and replan only on a demonstrated counterexample. **Why it might be new:** synthesizes a memory policy against forgetting, not just a certificate of an edit or a failure predictor; counterexample-guided synthesis is the algorithmic baseline. **Cheapest test:** enumerate a finite host with order effects, then compare this search to random suffix probing under equal calls. **Retention:** audit all old contracts on held-out suffix orders plus guards along training.
14. **A paid observation that substitutes for a bit.** **Mechanism:** before the deadline, choose between storing a discriminator now and paying later to query an external source with an explicitly modeled response partition. **Why it might be new:** treats fresh information and replay compute as different currencies; repeat evaluation of the merged host cannot substitute for a bit. **Cheapest test:** a finite rule learner with intermittent, noisy, task-dependent evidence; compare always-store and always-query under the same source budget. **Retention:** score untouched rules when the paid query is unavailable and during learning from the response.
15. **Interval of obligations, interval of memory.** **Mechanism:** maintain a lower bound from witnessed collisions and an upper bound from a constructed, checked repair policy; spend discovery compute only if closing the gap would change a store/replay decision. **Why it might be new:** uncertainty is expressed in a decision-specific byte/call gap, not as confidence in a forgetting score. **Cheapest test:** hide some edges of an exhaustible finite learner, then compare decision-guided audits with uniform sampling. **Retention:** use the exact held-out oracle to test worst old-group failures at matched new-task gain.
16. **Collision risk traded for latency.** **Mechanism:** allow a short noisy discriminator only for tasks with a declared error/latency allowance, buying exact backup repair if checks detect ambiguity. **Why it might be new:** prices approximate merges using distinguishability of full transcripts and the actual time to repair, rather than distance in weights. **Cheapest test:** stochastic rounded SGD on a tiny linear model; enumerate transcript distributions and compare calibrated MIR plus the same backup buffer. **Retention:** check worst old-group loss, silent error and recovery time after each noise regime switch.
17. **Revocable certificate scope.** **Mechanism:** keep an explicit assumption ledger on the continuation types used in each memory plan; revoke the plan when the stream permits a new combination and preserve a backup until a revised plan is checked. **Why it might be new:** policy migration is initiated by an expanded reachable set, not by an accuracy drop that may come too late. **Cheapest test:** reveal double-erasure continuations after single erasures; compare reserve bits and a generic distribution-shift alarm, and include a surprise switch where no recovery is possible without a preheld backup. **Retention:** check original tasks during migration and immediately after novel combinations.
18. **Hidden optimizer channel audit.** **Mechanism:** test apparently merged weights with shared follow-up edits that could decode residual target information from optimizer registers; save a discriminator only if no allowed cheap recovery can use that channel under a verified finite model. **Why it might be new:** makes optimizer memory compete with a buffer as a priced recovery resource, not as a proxy for edit persistence. **Cheapest test:** enumerate a quantized momentum learner and compare preserved versus reset moments, with equal total bits. **Retention:** score held-out old tasks during the decoding steps and on the first real update afterward.

### D. Make this useful across many windows

19. **Residual handoff without a full refresh.** **Mechanism:** as the likely erasure partition changes, recode protected bits using the current surviving distinctions and the old code, without reloading all old examples. **Why it might be new:** continual memory migration may pay only for new ambiguity; static rate–drift coding is the null. **Cheapest test:** rotate which one of three registers is erased with supervised repair opportunities, then remove a required handoff; compare full rewrite and an optimal fixed code. **Retention:** query each previously learned rule at the handoff and after rotation.
20. **Federated repair split.** **Mechanism:** place discriminators at sites where local training cannot erase them, and send them only when a shared certificate predicts a site will need them before its next merge. **Why it might be new:** changes which site holds missing distinguishability under different update laws; neither parameter averaging nor multi-user memory is the proposal. **Cheapest test:** two small learners with alternating complementary overwrite tasks; compare central replay and local buffers at equal total bytes and communication. **Retention:** directly test each site's old groups and require recovery during a held-out offline interval only if the contract promised it.
21. **Separate disposable history from live ambiguity.** **Mechanism:** compress compatible histories aggressively but protect separators for only the incompatible pairs incident to the proposed compression; release them when obligations legitimately coincide. **Why it might be new:** combines destructive consolidation with a precise liability, rather than merely optimizing for a safe reset word or a smaller quotient. **Cheapest test:** finite cohort with two distinct live contracts and several nuisance histories; compare keeping all histories and retained reset plus a fixed intent log. **Retention:** audit old queries before consolidation, after it, and under a held-out distinguishing suffix.
22. **Nested replay under memory pressure.** **Mechanism:** satisfy the earliest uncovered merger by replaying a stored item, but admit that replay only after testing whether it creates a later uncovered merger for another live task. **Why it might be new:** replay itself spends future distinguishability, so it is not merely a protection term added to a buffer scheduler. **Cheapest test:** three-register learner where replay of task A erases a separator for task B; compare greedy earliest-deadline, MIR and joint exhaustive planning. **Retention:** record task B after both the first and last replay, and include an independent old group.
23. **Design a host with cheap local antidotes.** **Mechanism:** meta-learn an update architecture so common unavoidable mergers leave a small, reusable family of legal restorative moves, trained to work from the shared destination with an explicitly charged discriminator. **Why it might be new:** trains for low conditional repair cost rather than zero forgetting or fastest average relearning; full-intent repair at the same complexity is the strong null. **Cheapest test:** co-train a quantized two-head learner and a tiny action dictionary on synthetic tasks; test new target families and remove the discriminator. **Retention:** check original and unrelated heads after repair and after a new edit, matching acquisition rates.
24. **Persistent replay impossibility receipt.** **Mechanism:** if a target discriminator is available but every allowed repair path breaches a retention floor or misses a deadline, preserve the obstruction and escalate to read-through, a permitted extra action, or an honest failure instead of repeatedly replaying. **Why it might be new:** separates memory capacity failures from actuation failures with an action-specific receipt; finite reachability is the formal null. **Cheapest test:** exhaustive search on a learner with a lock that can be opened only at a cost to an old head; compare failure-triggered replay and a fixed no-retry policy. **Retention:** audit the blocking old task along rejected candidate paths and on the chosen fallback.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can one certificate price the choice between preventing a collision and retaining information that survives it?** (1, 6, 13, 15, 22.) Highest chance: a certificate that can be acted on, not a more accurate forgetting alarm. Solve the finite joint problem, then require a strictly better byte/replay frontier than strongest separate protection and buffer policies on held-out orders of an actual small discrete learner. A win only on constructed reset tables is not evidence for ordinary CL.
2. **When is a bit enough to direct repair, and when is repair provably out of reach?** (3, 7–8, 11, 23–24.) A two-stage repair contract could distinguish evidence acquisition from legal actuation and specify the last usable repair window. Look for same-merger twins with equal information budget but different legal repair paths. Kill if a same-budget intent buffer and rewrite API always ties.
3. **Can a learner keep only a moving residual without repeatedly accessing the original examples?** (2, 4–5, 9, 19, 21.) The bet is an online recoder that reuses surviving internal distinctions under a priced schedule of repair opportunities. Compare to the best static code, recoding with full intent, and ordinary replay under alternation and held-out combinations, not just single erasures. If all the savings are classical coding on a known erasure channel, keep it as a control.
4. **Can useful merger scopes be certified on an actual small learned host in time to act?** (14, 16–18.) Use the full finite state of quantized SGD with momentum, then test if cheap certificates transfer across unseen starts and orders. Exact state equality or a defensible transcript-law bound is the gate. If coverage or lead time is too low, the object may remain a lower-bound tool rather than an online primitive.
