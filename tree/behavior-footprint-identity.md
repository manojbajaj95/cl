# Can a behavior have a substrate-independent footprint?

Parent: [Harness shared ISA (PR #100)](https://github.com/manojbajaj95/cl/pull/100). **Question:** Can measurements made with one behavior active at a time predict whether a subsequent text, code, or weight write will hurt it? More strongly, can the same measurements say which parts of a behavior survive a substrate swap?

## Root cause: the null contract does not cover the instruction's read path

PR #100 uses Qwen2.5-0.5B-Instruct, greedy decoding, three seeds, and 32 held-out capital questions per seed. A is “write the entire answer in uppercase,” B is “end with DONE.” Text is a system instruction before decoding; code runs on the emitted string; weights are rank-8 adapters trained on 50 questions to imitate the corresponding code transform of base-model answers. The **null adapter N is the same training procedure with the identity transform**, not a zero update: it learns to imitate greedy base answers on prompts without either instruction, with prompt tokens masked from the loss. The critical comparison is plain base + text A versus the same text A with N **active**. This is not just loading an inactive adapter: the script calls `set_adapter("N")` before generation.

| Condition | A compliance | Capital retention |
|---|---:|---:|
| Base, no A | 0% | 98% |
| Null adapter, no A | 0% | 90% |
| Base + text A | 54% | 54% |
| Null adapter + text A | 9% (0–28% across seeds) | 80% |
| DONE adapter + text A | 0% | 91% |
| Null adapter + code A | 100% | 90% |

The root cause at the **contract** level is missing counterfactuals. Matching an answer on the unedited prompt is not matching how the model responds when an instruction is added. The adapter optimizes only the first quantity, while text A relies on the second; both use the same decoder. The observed drop cannot be explained solely by a semantic conflict between “uppercase” and “DONE,” since N has no DONE target. And downstream uppercase code still works with N active, so the text failure is not a general impossibility of producing an uppercase answer in this harness. But “behavior-preserving” describes the training target, not an observed equivalence: even without A, capital retention moves by 8 points and the probe did not measure exact held-out answer or logit agreement. Retention here is only a case-insensitive substring match on the first word of the reference capital, not full semantic correctness.

The **mechanistic** hypothesis is that N rewrites part of a context-conditioned computation that A reads or depends on. The current data do **not** localize that computation or distinguish lost instruction routing from an intact instruction signal overridden by a stronger default completion, an EOS/length change, or a small margin change amplified by greedy decoding. The rise in capital retention with N + text A is compatible with a return toward ordinary answer trajectories, not evidence that a specific circuit was repaired or broken. To try to disprove the read-path account, compare fixed-prefix instruction-on minus instruction-off margins with N on and off, and separately match the instruction-off margins, entropy and EOS preference. If the instruction contrast is stable and the damage is explained by the changed default trajectory, do not call it a routing failure. An active zero-update adapter and a same-norm random adapter distinguish runtime effects and generic perturbation from effects of distillation. Only a selective instruction-path patch that restores the contrast and free-running A without restoring all base activations would support the narrower read-path claim.

## Candidate object and first gate

Freeze a small **basis of paired interventions**, not a basis of raw neurons. Each port specifies a controlled change, its execution stage, and a standardized observable: e.g., replace an instruction with a length-matched placebo; substitute the question entity; vary the case or final word on a fixed candidate string; substitute a tool result; shift the EOS margin at a matched prefix. Keep the pairs, units, stage order, and output scorers fixed across measured implementations. Include applicability masks: a tool-result port is not evidence about a postprocessor that never receives it. Use semantic candidate answers and matched prefixes where possible; a code wrapper can be queried with a forced candidate string, not assumed to have logits or to intervene inside the model.

- **Read** `R_A[k,j]`: change in A's *incremental* effect on observable `k` under intervention `j`. Difference out the change under the same intervention with A absent. This is a finite causal contrast under a specified intervention, not proof that A uses a particular neuron.
- **Write** `W_B[j]`: signed displacement under B alone in the observable state manipulated by port `j`, in units set by the port's calibration intervention. Keep protected observables (e.g., reference entity, content, existing skills) alongside target effects. Do not equate an output suffix change with a prefix-logit change just because both produce DONE.
- Predict the interaction in `A ← B` with the signed contraction `R_A W_B` restricted to ports B can reach before A's relevant read. For old-task score `s_A`, report both the total score change `s_A(A+B)-s_A(A)` (negative is harm) and the four-cell interaction `[s_A(A+B)-s_A(B)]-[s_A(A)-s_A(base)]`. To predict total change, add B's isolated effect `s_A(B)-s_A(base)` measured on the fixed calibration basis: a direct write can matter without a nonadditive interaction. Use no pair outcomes to construct either footprint. The contraction is a local approximation whose missing-port, threshold and feedback failures are part of the question.

A single descriptor that asserts identical footprints for *all* implementations of A and predicts the same interference from B is already contradicted by text A versus code A under N. Separate a **contract core** (which semantic obligations co-vary under standardized counterfactuals at equal standalone competence) from a **realization envelope** (where the implementation reads and writes, and under what order and context). Coordinates and measurement protocol are substrate-independent; envelope equality is an empirical and scoped claim, not required by semantic equivalence. First ask if this separation is identifiable at all. If it needs substrate labels or per-pair exceptions to work, it is not the proposed primitive.

**Cheap first gate (proposed, not run).** Start with a tiny CPU model that follows format instructions on synthetic key/value recall plus exact string wrappers; retain the capital example as a regression target, not as the dataset for learning a predictor. Use six or more behaviors (format, entity selection, conditional format, content transformation), several independent realizations of each, and only behaviors with meaningful standalone lift (predeclare ≥15 pp above base on independent eligibility items; PR #100's text B is not a valid positive). Include the untrained null, the trained null, and output-matched twins. Freeze a calibration basis on disjoint tasks/templates; reserve whole behavior families, adapter seeds and a mixed pairing (e.g., weight writer → text reader) for testing. Match standalone lift where feasible, but also report unmatched cells and abstentions. Measure (1) cross-substrate retrieval of the same contract among strength-matched distractors, (2) held-out directional drop/error and rank correlation, and (3) worst old-task retention and new-task lift in a short write-and-swap stream. Use exact normalized entity correctness and track format separately; report means plus per-family failures and uncertainty resampled over behavior families/seeds, not over correlated pair cells. Check split-half reliability before interpreting rank correlations.

At equal calibration calls/bytes, compare with raw output margins/single-task gain, length-matched placebo and entropy/EOS controls, instruction NLI, function-vector cosine and CKA where available, and delta/gradient geometry for weight-only cells; accept that some baselines cannot address every pair. Include a same-budget direct mixed-pair audit as a practical competitor (trained only on different pairs). Require a prospective ≥0.15 rank-correlation gain over the strongest applicable single-read baseline on held-out pairs with reliable labels, and a gain in the worst retained task at matched new-task lift versus same-budget auditing before claiming a useful primitive. If the identity clusters by substrate or the envelope cannot distinguish output-matched twins, keep the collision examples, not the identity claim.

## Prior art and boundaries

Read [idea ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md), [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md), and [flood top 10](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-top10.md) from [PR #6](https://github.com/manojbajaj95/cl/pull/6). Treat B3's failed implicit-ΔW cosine as a baseline with a weak standalone signal, not a demonstration that all footprint predictors fail. F1/E1 already cover shared gradient geometry; effect-class distillation lost to execution reward. P21/SM2's learned weight ISA is already done; PR #89's behavioral fingerprints and PR #100's footprint types are direct precursors, so hashing a response vector is not a new proposal. Distinguishing *all* future continuations is the existing Nerode quotient (PRs #91/#92/#95/#98), and finding bad triples is existing write-skew (SD3). Neither alone earns novelty here.

The alphaXiv search was quota-limited; the following are arXiv abstract checks, not reproductions or an exhaustive novelty claim:

## Raw ideas (unfiltered)

All first tests below are CPU-scale proposals. Unless otherwise noted, freeze probes before measuring a candidate; check retention on disjoint, previously working examples with the new behavior active and standalone lift matched.

1. **Causal socket.** **Mechanism:** couple the signed response of an old behavior to an isolated writer's movement at the same observable port. **Why possibly new:** unlike MergeProbe or B3, the read and write are measurable without a shared parameterization or training domain. **First test:** predict N → text A using an instruction/placebo contrast and candidate margins, then test a held-out weight → text family with no pair calibration. **Retention:** exact entity recall and the old instruction's compliance under the writer.
2. **Substitution core plus realization envelope.** **Mechanism:** compare standardized semantic contrasts for identity; store stage-specific dependencies separately to predict swap risk. **Why possibly new:** extends #89's fingerprint and #100's type with a falsifiable split between stable obligations and nonportable dependencies. **First test:** retrieve A across text/code/LoRA while correctly distinguishing their vulnerability to N. **Retention:** check all older readers after replacing A in a three-behavior stack.
3. **The null that leaves a trace.** **Mechanism:** make an adapter match baseline answers on neutral prompts while letting its instruction susceptibility vary; use these twins to identify which read coordinates carry missing information. **Why possibly new:** turns the parent null from a one-off control into a controlled basis challenge, not a null-edit search in weight space. **First test:** train twins with and without a small instruction-contrast loss, match their neutral outputs, and blind the predictor to the objective. **Retention:** protect held-out unrelated instructions, not just the contrast used in training.
4. **Read elasticity curves.** **Mechanism:** store responses to calibrated perturbation magnitudes rather than one local derivative; a write consumes a measured margin before it crosses a failure threshold. **Why possibly new:** the same dose units can be queried in text, model state and code rather than optimizing an adapter-specific coefficient. **First test:** compare responses to three EOS or case-margin doses, predicting a held-out dose in another substrate. **Retention:** measure the weakest prior behavior at each dose and exact answer content.
5. **Timed access rights.** **Mechanism:** attach a stage/availability interval to each port and allow interference only if a write can reach a later read; distinguish postprocessing from changes visible during decoding. **Why possibly new:** tests a portable temporal type, not an empirical commutator table for each ordered pair. **First test:** move the same suffix edit from postprocessing to constrained decoding, and add a later parser that either can or cannot observe the edit. **Retention:** old entity and parser accuracy under both placements.
6. **Common-path rescue.** **Mechanism:** record the smallest shared semantic patch that restores a read after two different writers break it. **Why possibly new:** causal tracing is known; a repair identified under one writer substrate and applied at the same observable under another is the proposed shared handle. **First test:** derive a case-margin rescue from adapter N, then test a length-matched text distractor and an unrelated patch control. **Retention:** recover old A without losing capital recall or the new writer's own effect.
7. **Directional collision triangle.** **Mechanism:** use asymmetric readers of the same port to infer conflicting writes that symmetric similarity cannot rank. **Why possibly new:** directional weight retention exists; a cross-substrate collision assembled from separately measured factors is the bet. **First test:** make P read a field Q writes, Q read a different field R writes, and R read neither; predict all six directions. **Retention:** score each old reader after each addition, not just pair mean.
8. **Redundant reads as a set-valued footprint.** **Mechanism:** represent alternative sufficient read paths as clauses, with separately measured losses of each path; predict failure only when no clause survives. **Why possibly new:** SD3 identifies bad sets; this tries to predict an unseen bad set from single-writer measurements and a reader redundancy map. **First test:** gate a rule on either a context flag or a tool bit, then independently remove each and predict the joint failure. **Retention:** both rule accuracy and factual accuracy after singles and pairs.
9. **Causal fingerprint counterfeit.** **Mechanism:** construct implementations with identical measured footprints but a reachable held-out retention difference; use the cheapest witness to bound what any predictor on the old basis could know. **Why possibly new:** a finite-basis impossibility result, not another continuation quotient. **First test:** build string wrappers that agree on all assay strings but disagree after a legitimate delimiter change, then repeat with model twins. **Retention:** measure how much old-task failure can be hidden at each probe budget.
10. **Versioned basis without remeasuring the library.** **Mechanism:** keep old coordinates fixed, append a new port only after a collision, and infer missing coordinates as intervals until the old behavior can be cheaply checked. **Why possibly new:** the unit of migration is measurement coverage rather than weights or a syntactic ABI. **First test:** introduce a tool-state behavior after four text/weight writes and compare selective remeasurement against full refresh at equal calls. **Retention:** count missed old-task drops as well as preserved behavior after refresh.
11. **Port equivalence under mediation.** **Mechanism:** merge two candidate ports only when clamping one removes the other's contribution to the old behavior in both directions across held-out realizations. **Why possibly new:** compresses by counterfactual redundancy, not CKA correlation. **First test:** contrast duplicated casing cues with two correlated but independently causal cues in a tiny network. **Retention:** deploy compressed sketches and compare worst old-task loss against full sketches.
12. **Cancellation is a negative control.** **Mechanism:** find two writers with opposite signed displacements and use their predicted cancellation to validate units and expose nonlinear residuals. **Why possibly new:** calibrates a cross-substrate signed axis by cancellation rather than fitting a pair residual or rediscovering commutators. **First test:** combine a text cue that raises a case margin with an adapter that lowers it, matching their standalone magnitudes on calibration items. **Retention:** check restoration of old case behavior and unchanged entity accuracy on new items.
13. **Read-preserving distillation.** **Mechanism:** distill the contrasts of independently chosen old readers, not only their answers, while moving a new behavior from text or code to weights. **Why possibly new:** NCA asks about the original context returning; this asks whether preserving selected counterfactual reads transfers to unrelated old readers at equal replay bytes. **First test:** compare contrast distillation against plain replay and logit distillation on equal examples. **Retention:** measure old instructions and recall on untrained paraphrases and reader families.
14. **Silent-write bank.** **Mechanism:** store a small library of target-null writes that deliberately move different shared observables; use it as a set of calibration instruments for future readers. **Why possibly new:** the instruments are reusable across substrates and characterize a reader, rather than forecasting a particular weight edit. **First test:** compare neutral-capital adapters, neutral text distractors and identity-on-assay code against equally many random probes. **Retention:** predict which old instruction fails under a newly synthesized null instrument.
15. **Invariant unit, moving model.** **Mechanism:** re-anchor port units using fixed reference interventions after base fine-tuning, but measure drift in which readers share a coordinate separately from magnitude drift. **Why possibly new:** E2 already reindexes logits; the extra claim is detecting when a previously shared causal coordinate splits. **First test:** compare a temperature change to a fine-tune that changes the instruction contrast after temperature matching. **Retention:** compare no refresh, unit-only refresh and split-aware refresh on old tasks at equal budget.
16. **Boundary twins.** **Mechanism:** measure a behavior on minimal pairs where the intended rule flips at a domain boundary but the output string need not change. **Why possibly new:** PR #57's witness sets target identifiability; this tests whether such contrasts are interchangeable read ports for predicting unrelated mixed writes. **First test:** use “capitalize only country names” versus “capitalize everything” with inputs on which they usually agree. **Retention:** count both old-task correct firings and protected non-firings after swaps.
17. **Side-effect-only identification.** **Mechanism:** mask the target score and ask whether the signature of protected invariants under controlled perturbations identifies a behavior family. **Why possibly new:** tests whether identity contains reusable information beyond matching target outputs or expected task gain. **First test:** compare same-accuracy formatting realizations to different semantic rules with matching string lengths. **Retention:** use the signature to predict which old invariant is lost under an unseen writer; failure is informative.
18. **Feedback lifting.** **Mechanism:** distinguish a terminal output write from an otherwise identical write whose output is read into the next turn; compose footprints across the visible boundary. **Why possibly new:** exposes when apparent postprocessor isolation disappears without training a new sequence-effect predictor. **First test:** append DONE with code, then feed or suppress the transformed result on the next turn. **Retention:** old second-turn tool selection and multi-turn entity consistency.
19. **Scratchpad and answer double dissociation.** **Mechanism:** offset a downstream formatting write with an upstream generation write so final outputs match, then test old readers that inspect intermediate versus final channels. **Why possibly new:** operationally separates equal answers from equal access paths while holding static probes fixed. **First test:** use a two-stage CPU agent with a typed scratch field and answer renderer; make two output-matched realizations. **Retention:** score the old scratch-based decision and final answer independently.
20. **Local operating-region certificate.** **Mechanism:** store a safe region in joint port units; estimate uncertainty outside the sampled region and abstain instead of reporting zero overlap. **Why possibly new:** unlike generic proof-carrying adapters, a reader's region is reusable for writers not considered when it was measured. **First test:** infer the region from single interventions, challenge it with two-stage compositions including out-of-range contexts, and compare equal-coverage abstention. **Retention:** false-safe rate on old tasks, plus retained lift at matched acceptance.
21. **Many readers, one writer constraint.** **Mechanism:** compile the worst old readers' port margins into a constraint on a new writer and offer alternative realizations that satisfy the same constraints. **Why possibly new:** only if one region measured from old readers constrains both a prompt change and an adapter without learning a substrate router; projection alone is known. **First test:** offer several prompt variants and adapter strengths; compare a port-constrained choice against equal-cost replay and direct evaluation. **Retention:** worst old-task score across sequential writes at matched gain.
22. **Missing-port residual as a new coordinate.** **Mechanism:** use correlated prediction residuals across unrelated pairs to locate a missing controllable observable, then add one measured port, not a pair-specific parameter. **Why possibly new:** differs from PR #97's out-of-span credit by minting a shared measurement that must transfer to combinations not used to locate it. **First test:** hide the EOS port from the initial basis, use a few discovery pairs, then test whether recovering length/EOS explains new pair failures. **Retention:** reduction in false-safe calls for old tasks in unseen pairs.
23. **Order as a test of causality.** **Mechanism:** permute only reachable stage order while holding standalone distributions constant, and predict the sign of changed interference from the individual read/write records. **Why possibly new:** unlike parent #8, order predictions are out of sample and no measured pair commutator is stored. **First test:** swap a parser and normalizer, or move a tool result from before a model read to after it. **Retention:** old parser and rule quality in each order plus factual content.
24. **Budget lower bound via indistinguishable readers.** **Mechanism:** plant independent binary dependencies in old behaviors, then estimate minimum assay size needed to detect writers that collide on the least-measured dependencies. **Why possibly new:** a retention-versus-port-budget law, not a count of future edit classes or inaccessible bits. **First test:** a synthetic family with known dependency support; compare random, structured and direct pair audits at the same calls. **Retention:** report worst-case missed old-task loss as the number of dependencies and accumulated writes grows.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can a directed factorization predict a mixed pair that has never been composed?** This is the highest-upside test: independently measurable reads and writes would be a composable object, not just a compatibility score. Start with #1/#5/#7/#12 and compare against output deltas, MergeProbe-style features and matched-cost pair audits. Demote if new substrate pairings require retraining or a lookup table.
2. **Can we identify an invariant core without discarding the mechanisms that govern interference?** Use #2/#3/#16/#19: same contract, matched lift, distinct access paths, plus different contracts with coincident outputs. A measurable core/envelope split would give a swap operator something precise to preserve; abandon it if identity is mostly substrate or compliance clustering.
3. **What can no fixed probe basis certify, and can one extra coordinate eliminate a whole family of collisions?** Use #9/#10/#22/#24 to measure the cost of indistinguishability and test residual-driven extension. The primitive would be a reusable witness-plus-coordinate operation, not active selection on each pair separately. Judge by held-out retention per additional assay.
4. **When do footprints compose across stages, feedback and redundant paths?** Use #5/#8/#18/#23 to test whether reachability plus alternative reads predicts unseen cascades and bad sets. Rank lower because write-skew and order effects are already known; a win means predicting them without enumerating them.
5. **Can preserving a footprint preserve old behavior better than preserving outputs?** Test #6/#13/#20/#21 at equal replay and compute. A useful intervention would repair the same old reader across multiple writers while keeping new-task lift, not just add a regularizer that works for the capital example.
