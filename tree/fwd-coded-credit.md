# Can intervention-coded questions separate credit in one forward batch?

**Yes if the batch observes distinguishable effects of interventions that can actually be written. No if “one batch” just means scoring more mixed edits with one judge.** The primitive to look for is an experimental interface that returns *which realizable write changes which behavior*, with a way to detect aliasing and test whether that answer survives when the diagnostic machinery is removed. Orthogonal perturbations and heterogeneous batching already exist.

This extends the [forward-only node (PR #50), idea #3 and branch #4](https://github.com/manojbajaj95/cl/pull/50). Forward-only here means ordinary evaluations, optionally with explicit software hooks, not JVPs, reverse-mode AD, or an editor with uncharged offline training. A **credit channel** is a signed, decision-relevant effect on a named behavior (or an explicit interaction) attributable to a writable intervention. Extra tokens, logits, heads, labels, and calls are observations, not automatically independent credit channels. This is a literature and ideation node; no experiments were run.

## Root cause: orthogonal assignments do not make effects separable

Fix a checkpoint and candidate edits `u₁…uₖ`. Let `fⱼ(z)` be behavior-view `j`'s expected score when edits are assigned signed doses `z`. For a local additive approximation, `fⱼ(z) − fⱼ(0) ≈ zᵀgⱼ`, where `gⱼ` contains the effects of the candidate directions on that view. Each scalar read provides a row of a measurement operator. For unrestricted edit effects the relevant columns must have full rank after accounting for question/seed baselines and nuisance terms. With noise, they also need to be well-conditioned at the perturbation scale used for writing.

- **A batch is not a measurement.** For `m` assignments repeated across `q` views, the local model is `Y = ZG`, with `Z` of size `m × k` and `G` of size `k × q`. If `rank(Z) < k`, adding identical-assignment views does not identify any unrestricted column of `G`: each has the same blind subspace. A shared support, tied coefficients, or a genuinely new intervention/readout can change that conclusion. For example, with *known* diagonal support for two views and two edits, one antithetic pair with both edits on can recover both local effects from two separate deltas; averaging the deltas loses the distinction. Without that support assumption both deltas are sums, even with noiseless scores. The diagonal case is a control, not a novelty claim.
- **Orthogonal code columns are not orthogonal to interactions.** In a four-row sign design with `z₃ = z₁z₂`, the three main columns are balanced and pairwise orthogonal. A pure interaction `f(z) = az₁z₂` gives exactly the same transcript as a pure edit effect `f(z) = az₃`, yet the edit-3-only write has different effects. Repeating those rows never helps. Adding the full sign-reversed block separates this even-order alias, but a cubic can still alias a main effect in a design with `z₄ = z₁z₂z₃`, even after sign reversal. Full factorial recovery is possible but exponential for unrestricted interactions. Sparse recovery, low-order truncation and small doses are assumptions with failure cases, not ways around the bound.
- **Questions and gates can change the estimand.** If each code row also changes wording, content, target, eligible tools or the grader, algebraic orthogonality does not remove baseline differences or edit-by-question interactions. Randomly cross assignments with matched question families and hold verifier definitions fixed. Pairing the exact question estimates its own contrast; randomizing over exchangeable variants estimates an average, not instance-level credit. A prompt tag may leak an answer, and a token-local gate may change a different computation than a merged weight edit. For deployment, compare the diagnostic effect against the actual write on untouched gate-free questions. Post-write retention needs a separate old-behavior readout; not detecting a regression on queried anchors is not a guarantee elsewhere.
- **This is a write-identification problem, not necessarily full recovery.** In a noiseless linear model with measurement map `A` and a linear target contrast `T`, the target is identifiable iff `ker(A) ⊆ ker(T)`. With bounded noise the useful analogue is agreement on the decision across all compatible effects to the required tolerance. If two compatible worlds call for opposite edits or disagree on unacceptable old damage, probe again, make a directly verifiable joint write, or abstain. If every allowed query leaves them indistinguishable, there is no score-only fix. A well-conditioned diagnostic matrix is also not enough if every realizable write that acquires the new rule breaks old rules.

**Candidate interface:** `probe(checkpoint, edits, assignments, behavior_views) → effect estimates + ambiguity witnesses`; `commit(proposed_write) → gate-free acquisition and retention audit`. Probe claims are conditional on the domain, dose, repeatability, and interventions actually made; a witness is an alternative effect model consistent with the scores but calling for a different commit, not just a low confidence number. For a model, an ordinary commit could be a merged tensor update. For an agent, it could be a single revised executable policy with probe-only selectors removed. A permanent router is an allowed comparison, not evidence for a successful ungated write.

## Where current methods already get partway

Search (2026-11-24): alphaXiv and arXiv across “multiplexed SPSA,” orthogonal finite differences/Jacobians, grouped causal interventions, low-rank heterogeneous batching, nonlinear model merging, and causal/agent credit. This maps the parent claim and closest controls; it is not a novelty certification for each raw card.

None of these interfaces identifies which constituent of a mixed edit caused each response and transports that attribution into an ungated persistent write. ## Common cheapest-test contract

The interesting claim is **more correctly identified, actionable effects per unit cost at matched acquisition and retention**, not more output dimensions per call. Compare (1) isolated candidate and joint-write audits in the **same** hardware batch, with the same prefix/cache optimization, (2) global Hadamard and tuned random/antithetic perturbations with the **same vector** of readouts, (3) the parent question-gated barcode plus an equivalent permanent-router arm, and (4) the best simpler mechanism for the particular card. Use exhaustive untagged interventions only as a tiny offline audit oracle; charge any oracle access used by the learner. Stronger supervision goes to all arms or is disclosed separately.

Start with explicit clean, low-order, and dense/high-order interference regimes, matching realized perturbation norms and scoring final writes at matched acquisition. Fit on current nonce rules and permitted old anchors; audit on untouched nonce compositions, delayed old-task recurrences and invariant tasks under the normal interface. Report signed-effect error and actionable coverage (including abstentions), gated-to-ungated sign flips, and worst old-family regression. Check old loss against the unedited checkpoint: an antithetic difference can be zero while both signs do equal damage. Include no-write and single-task controls. Charge token prefill/decode, judge and label calls, rollout transitions, FLOPs/wall time and retained state; sharing a prefix may save compute, but divergent prefixes and side effects cannot be treated as shared for free.

The [ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md) and [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md) set four traps: no sparse-forgetting assumption (functional syndromes failed under diffuse damage), no self-written questions for their own sake (self-QA tied teacher QA), no claim from pairwise grouping alone (function-space group testing and quartet audits were already triaged), and no apparent prompt effect without same-length filler and entropy/margin controls. The parent barcode, parent score-vector tomography, and RL-on-OOD verifier twins are controls, not cards below.

## Raw cards for the reviewer

No cards are filtered or ranked here. **P** means a candidate reusable object or operation, not established novelty; **I** means an improvement to an existing operation. Every first test is proposed, not run, and includes a normal-interface retention check.

### Create an observation operator

1. **C01 · Counterfactual fork bytecode (P).** Compile an edit assignment into an inference DAG that shares state only up to the earliest affected operation, then branches with explicit read/write scopes. **New bet:** tree decoding shares token prefixes; this would define legal *weight-policy counterfactuals* and enforce where sharing ends. **First test:** late adapters on a tiny decoder vs same-cache heterogeneous batching; demand exact branch-score agreement and after a commit recheck old syntax without fork instructions. Early edits may erase all savings.
2. **C02 · Executable dual questions (P).** Synthesize parsers of the same answer whose score contrasts each respond to one candidate edit while canceling known nuisance edits; emit a null test alongside every parser. **New bet:** active learning picks examples; these questions define a dual measurement basis tied to writable candidates and reuse one response. **First test:** choose readouts for a two-field nonce transducer with cross-talk; compare independent field losses and random contrasts, then recheck old field combinations after a gate-free commit. The parser may simply encode a known decomposition.
3. **C03 · Probe slots with challenge-response (P).** Let a question request anonymous intervention slots; a verifier inserts random no-op/permutation challenges after the prompt is fixed and checks whether effects follow the actual slot rather than its textual name. **New bet:** an intervention API that tests its own exclusion failure, not a better visible barcode. **First test:** plant a prompt shortcut in two rule probes; compare blind assignment and prompt-only shuffling, then check old instructions after committing without slots. Hiding names may already do all the work.
4. **C04 · Instrumented tool receipts (P).** For each sandbox action return an answer plus scope-matched signed receipts from independent state observers; pair receipts with known no-op switches to separate action credit from narration credit. **New bet:** instead of a reward-shaping sum or self-reported reasoning, a reusable external readout can disagree with the action's own account. **First test:** two tools on a toy document editor, score content and preserved metadata from one run; compare terminal reward and direct state diff, then retest old edit/undo routines under normal execution. Rich logging might tie.
5. **C05 · Edit shutters (P).** Expose observation-only switches that temporarily block a plausible mediator after a candidate write, without editing the upstream weights; infer which credit follows the path rather than the candidate's side effect. **New bet:** intervention-on-intervention as a standard unit for learning, rather than a one-off activation patch for explanation. **First test:** two latent paths in a small parity model with a shortcut, compare knockout and interchange on equal queries; write the chosen fix and check old parity rules with shutters removed. A shutter can introduce off-manifold effects.
6. **C06 · Shared-prefix, independent-suffix judges (I).** Generate a neutral procedural state once and score several cheap verifiable continuations against it; permit diagnostic edits only downstream of the shared state. **New bet:** save evidence tokens by placing the edit boundary jointly with the verifier, not just prefill caching arbitrary questions. **First test:** a long toy program followed by short queries for different new operators, vs identical-prefix scoring with independent edits; check old operator chains after merging. The downstream restriction may exclude the right write.

### Recover what mixing hides

7. **C07 · Aliased-write witness (P).** Decode two transcript-consistent effect models that imply different safe writes, then emit the missing assignment with the largest predicted disagreement; stop as soon as all admissible models agree on the commit. **New bet:** experimental design targets a certificate of *write sufficiency*, not parameter reconstruction or generic posterior uncertainty. **First test:** force a three-way main/interaction alias with one bad old-task commit; compare D-optimal design and isolated audits, then revisit that old family after the selected write. An unrestricted ambiguity class could force full enumeration.
8. **C08 · Interaction packets (P).** Bind several candidate edits into an atomic write only when a held-out joint contrast shows that credit belongs to the group, not its members; carry both enabling and disqualifying assignments with the packet. **New bet:** transform an interaction estimate into an executable write unit with an applicability contract, not just a quadratic merge coefficient. **First test:** a rule requiring paired feature/readout changes; compare SLIM-style pair scoring plus greedy merging, and check two old rules that share one member after the joint commit. A simple joint candidate may tie.
9. **C09 · Dense leakage budget (P).** Ask an old-behavior panel for randomized signed contrasts, estimating an upper-tail risk proxy for damage across *combinations* of writes, not which individual facts were broken. **New bet:** a sketched dense interference budget consumed when composing writes, rather than sparse syndrome repair. **First test:** old losses with rotated diffuse response, compare same-byte replay, dense sketch and global vector ZO; check worst-family and recurrent old loss after matching new-rule gain. Tail unseen by the panel can dominate.
10. **C10 · Score parity cross-exam (P).** Reserve balanced parity columns that should be empty under the fitted effect model; when they light up, use their alias classes to nominate *which commit forecast* to falsify. **New bet:** low-resolution factorial diagnosis is standard; use contradictions to invalidate a specific portable write claim and route its next probe. **First test:** add a cubic contaminant invisible in the original sign design; compare a fixed higher-resolution design and random held-out mixtures, then measure protected old arithmetic after commit. A fixed design may be cheaper.
11. **C11 · Dose continuation as credit (P).** Treat each channel as a curve from infinitesimal test dose to deployable step, with a measured interval where its sign and old-behavior limits persist. **New bet:** continuation across multiple scored views determines whether the *same* credit is writable at useful gain, not a scalar line search on aggregate reward. **First test:** a saturating two-feature model whose best tangent flips at write scale, vs scalar line search and direct finite-scale audits; check old threshold decisions at matched gain. Curves may change after every write.
12. **C12 · Occluded responses (P).** Evaluate partial outputs in which a specified slot is unscored or clamped to a valid oracle value. Compare intact, unscored and clamped contrasts to distinguish scoring leakage from failure mediated by the slot. **New bet:** separates “credit vanished when the judge ignored it” from “credit vanished when downstream state changed.” **First test:** two-stage grammar with one output reused downstream; compare plain multitask scores and causal patching; retest old compositions with neither masks nor clamps. Valid oracle clamps may cost more than isolated tests.

### Transport credit into a persistent write

13. **C13 · Gate-erasure certificate (P).** For a question-gated score claim, attach a paired global-write check with identical inputs and scorer, then find the smallest counterexample set on which gate and commit effects disagree. Treat that residual as a veto or a target for a different commit. **New bet:** behavioral equivalence of the diagnostic *effect*, not the parent trace-to-weight compiler or routing at deployment. **First test:** overlapping adapters with a token-mask-only win, versus direct merged validation; retest held-out old prompts after removal of all gates. Direct validation may fully subsume it.
14. **C14 · Credit coordinates from interventional pivots (P).** Define effect coordinates by a few witnessed interventions and their measured cross-responses rather than layer/parameter names; before reusing a probe, demand that a fresh pivot reproduces the old coordinate within bounds. **New bet:** transport the semantics of measurements after drift, without transporting edits or prescribing a weight address. **First test:** hidden-unit rescale/permutation followed by a real interference change; compare fixed behavior probes and parameter-based alignment; check old rules not used as pivots after the new write. Coordinates may lose rank under drift.
15. **C15 · Editable audit checksum (P).** Make each adopted rule emit a *counterfactual* signature on procedural witness questions, and require new writes to predict how that signature should change when the old rule is intentionally corrected. **New bet:** preserve a rule's ability to be corrected, not raw outputs or self-description of its weights. **First test:** correct a nonce dictionary entry after two unrelated writes, compare replay plus corrected labels; check old unaffected entries and held-out uses of the corrected one. Exact key-value memory can tie on trivial tasks.
16. **C16 · Conditional equivalence compaction (P).** Collapse two candidate writes into one only if a new-context probe cannot distinguish their acquisition or retention effects in a declared episode family; keep a recorded distinguishing witness when a later episode splits them. **New bet:** store a revisable quotient of intervention effects, not clusters of weight vectors or task IDs. **First test:** four rules with initially equivalent edits and a delayed breaking composition, compare adapter similarity and direct coalescing; check both old families after re-splitting. Finite probes may authorize false merges.
17. **C17 · Inkless crossover (P).** Dry-run two incoming writes in opposite overlapping regions of the same shared model, and use a deliberately retained negative/positive control pair to demand that the same decoded credit remains under both backgrounds. **New bet:** measure background invariance of a credit claim before commit, rather than require commutation of final patches. **First test:** three nonce rules with one shared feature reused across backgrounds, vs order-randomized merge tuning; revisit old isolated and composed behaviors without the fork code. True interactions may be rejected rather than resolved.
18. **C18 · Probe-to-commit envelope (P).** Compile into the admissible write family by fitting predicted signed effects instead of copying outputs; give the compiler a set of acceptable effect vectors rather than one teacher solution. **New bet:** a behavioral effect specification with freedom to choose the physical update, distinct from transporting a task vector or mimicking a trace. **First test:** two implementations of a toy language where the same answer is realized in different hidden states; compare output distillation and rank-one regression at equal data, then recheck old translations. The inverse problem may be as costly as training.

### Extend the interface to agents and streams

19. **C19 · Private retention envelopes (P).** Have isolated old-task evaluators return signed safety bounds on exactly the mixed writes they tested, with declared scope and expiry; intersect the envelopes without sharing old examples or aggregating away dissent. **New bet:** a composable *measured constraint on probes*, not a single critic, reward or old-gradient vote. **First test:** two synthetic agents with private old workflows, vs shared summary, simple reject-only feedback and pooled replay oracle at equal information where possible; audit both private workflows after the new procedure is installed. Bounds may be too conservative without shared anchors.
20. **C20 · Event-addressed randomness (I).** Allocate randomness by stable semantic event ID across counterfactual rollouts; flag unmatched events rather than pretend identical seeds pair traces after a branch changes the call order. **New bet:** valid common-random-number contrasts under reordered tool actions become a probe output. **First test:** a toy stochastic scheduler with insertion/reorder edits vs identical RNG seeds and independent rollouts; retain old scheduler success after shipping the chosen change. Matching IDs can itself encode privileged state.
21. **C21 · Counterfactual side-effect quarantine (P).** Express multi-step probe edits as transactions over forkable environment state; give each branch's tentative actions an independently checkable resource delta before allowing one branch to write back. **New bet:** assign credit for safe durable changes, not merely roll out alternative actions or freeze all tools. **First test:** two candidate agent procedures on a versioned toy filesystem, compare cloned sandboxes and COMA-style critic credit; run old create/edit/undo tasks after patching the normal policy. Nonforkable external effects remain outside scope.
22. **C22 · Uncertainty exchange (P).** Let the model expose two unresolved credit allocations and let the environment return the cheapest discriminating observation it actually supports, with the price; allow the environment to say that no permissible observation separates them. **New bet:** a negotiated experiment API for a missing *write-relevant* observation, not a teacher that invents new questions or a verifier that scores the same answer. **First test:** toy API workflows with equivalent success screens and different hidden mutations; compare ordinary active learning plus a fixed tool menu, then retest previous workflows after commit. A well-designed static API may already expose the answer.
23. **C23 · Transported sign constraints (P).** Carry only sign constraints confirmed across interventions on nuisance context; drop or rescope a constraint when a new environment gives a sign reversal under the same executable change. **New bet:** invariance is a tracked property of credit for an intervention, not domain-general accuracy or confidence gating. **First test:** learn a tool schema from two environments with deliberately inverted superficial cues, compare domain reweighting and verifier twins; check earlier workflows, including deliberate exceptions, after an ungated policy update. Shared confounding can survive all environments.
24. **C24 · Delayed credit joins (P).** Log small, branch-tagged intermediate predictions and control assignments during one forward batch; later join independent outcomes to those predictions, invalidating credits if assignment or policy semantics changed in the interim. **New bet:** late evidence resolves an explicit cross-readout ambiguity about *joint* durable changes rather than multiplying eligibilities by a later reward. **First test:** interleave two delayed tool outcomes with an intervening policy update; compare e-prop-style eligibility and replay, then audit old tasks whose evidence arrived out of order. Missing or correlated late outcomes can leave every join ambiguous.

## Ranked deeper questions

1. **Can we design observables that make edits identifiable on a genuinely shared model?** Search for a learnable *interventional interface*: a small set of writable perturbations and independently validated views that trades neither representation sharing nor answer leakage for separation. Highest upside because it creates experimental access that optimizers cannot get by reweighting rewards. First fork: executable dual questions vs fixed heads and batched isolated perturbations on novel held-out compositions.
2. **Can credit measured through a temporary gate be certified for an ordinary write?** Search for *gate erasure*: a transferable equivalence check, or a compiler with a falsifiable effect contract. This would let experimental access remain richer than the deployed learner. First fork: plant same-sign and sign-flipping gate/commit pairs; require healthy old-task performance without the gate.
3. **Can learners identify the safe decision without recovering the full nonlinear interaction table?** Search for *write-sufficiency witnesses*: small transcripts that exclude every materially different commit, or supply a concrete extra intervention. Upside is cheap, auditable credit under dense interference; risk is worst-case recovery or a narrow decision class. First fork: equal-budget alias breaking vs SLIM, stronger factorial designs and direct candidate audits.
4. **Can separately observed credit remain meaningful as the reader and policy drift?** Search for *rebindable credit coordinates*: interventional meanings that can be repaired or explicitly retired after new writes without retaining all old examples. First fork: hide checkpoint symmetries and real rule changes in the same recurring stream, then test whether rebinding distinguishes them and improves old retention over fixed anchors at equal bytes.

The decisive negative result would be that batched isolated edits with the same readouts and shared-prefix budget match every multiplexed scheme once the writes are ungated and old tasks are tested. That leaves useful serving engineering, not a new continual-learning primitive.
