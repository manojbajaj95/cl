# Breadth outside edit theory: continual learning when the learner's interface changes

Parent: the edit-theory region of the tree (Nerode quotient of edits, [PR #104](https://github.com/manojbajaj95/cl/pull/104); rate–drift law, [PR #105](https://github.com/manojbajaj95/cl/pull/105); relearning as a read head; merger certificates, [PR #110](https://github.com/manojbajaj95/cl/pull/110); replay deadlines, [PR #113](https://github.com/manojbajaj95/cl/pull/113)). **Node question:** recent nodes keep converging on edit equivalence, rate–drift and relearning reads. Leave that region on purpose: find continual-learning failures the pool has barely touched (vocabulary growth, architecture growth mid-life, populations sharing weights, learning from the model's own deployment traffic) and propose primitives there.

**Short answer.** Every edit-theory node assumes the same four things: a fixed parameter set, a fixed input/output alphabet, one learner, and a data stream the learner does not cause. A real model's lifetime breaks all four. When the interface changes, "freeze the old weights" stops implying "keep the old behaviour", and the retention metric itself can become undefined. The CPU probe below shows three clean cases: adding 5 output tokens with every old weight frozen still costs 14 points of old-task accuracy; an exactly function-preserving widening still makes the old task drift faster than not growing (0.39 vs 0.16 at step 1); and a deployment loop where only predicted-positive users return leaves 90% of input bins with no labels at all. These are separate failure modes from interference between edits, and each suggests a conserved quantity to hold fixed at the interface change.

## Root cause: the parent theory is defined relative to a fixed interface

Pool coverage check (PR #6 ledger, triage and top 10, plus `ideas/flood/multiagent.md`): the only prior entries here are B2 "vocabulary-grown skills" (killed as L2P/ToolkenGPT prompt pools), growth variants inside tree nodes (#35 spectral domain growth, Hebbian growth), the PR #4 self-contamination law (collapse onset from the model's own defects), and the 61-idea multi-agent flood, which is about markets and institutions for write rights between task proxies, not about a fleet of deployed copies. Nothing in the pool treats the interface change itself as the forgetting event.

1. **The alphabet is not fixed (vocabulary/tokenizer growth).** A softmax shares one normalizer across all tokens. Adding output rows changes log Z on every old context, so with every old parameter frozen the old task still degrades; the whole old-task loss increase is the shared normalizer by construction. Input-side growth is worse: re-tokenizing old text changes the sequence the model sees, so "the same old test set" is a different input. Vocabulary-expansion work ([2407.05841](https://arxiv.org/abs/2407.05841), OFA [2311.08849](https://arxiv.org/abs/2311.08849), HyperOFA [2504.21018](https://arxiv.org/abs/2504.21018), AweDist [2505.20133](https://arxiv.org/abs/2505.20133), zero-shot tokenizer transfer [2405.07883](https://arxiv.org/abs/2405.07883), in-place expansion [2607.15232](https://arxiv.org/abs/2607.15232), old tokenizers new words [2512.03989](https://arxiv.org/abs/2512.03989)) studies initialization and target-language gain, and reports source-language loss as a side effect; none states a conservation constraint at insertion.
2. **The parameter set is not fixed (architecture growth).** Net2Net-style growth preserves the function at insertion but not the gradient field or the curvature on old inputs. The new units change how the next step moves old outputs, so a function-preserving growth is not a retention-preserving growth. Growth-induced forgetting is documented ([2408.10566](https://arxiv.org/abs/2408.10566); Grow, Don't Overwrite [2603.08647](https://arxiv.org/abs/2603.08647); staged training [2203.06211](https://arxiv.org/abs/2203.06211); masked structural growth [2305.02869](https://arxiv.org/abs/2305.02869); MIDUS depth up-scaling [2512.13751](https://arxiv.org/abs/2512.13751)) but treated as an initialization problem, not as which learning-dynamics invariants the growth must preserve.
3. **There is not one learner (populations sharing weights).** Deployed systems run a shared base with many private adapters, agents or replicas. A base update that is retention-safe for the base can break every client adapter's interface, and replicas that diverge hold different memories. Federated CL ([2309.01289](https://arxiv.org/abs/2309.01289), TARGET [2303.06937](https://arxiv.org/abs/2303.06937), FedDAA [2506.21054](https://arxiv.org/abs/2506.21054)) averages clients toward one model; it does not treat retention as a property of the population, where one copy may forget what another keeps.
4. **The stream is not exogenous (learning from deployment traffic).** The deployed model decides which users come back, what they ask and which labels arrive. Forgetting can then come from absence of evidence that the model itself caused, and drift detectors cannot tell it from real drift. Performative prediction (Perdomo et al. 2002.06673), self-consuming loops (Shumailov et al. 2305.17493; 2307.01850), in-context feedback-loop reward hacking ([2402.06627](https://arxiv.org/abs/2402.06627)) and data flywheels (e.g. [2610.09228](https://arxiv.org/abs/2610.09228), [2412.08467](https://arxiv.org/abs/2412.08467)) study equilibria, collapse or gains, not retention of old capabilities under self-selected traffic.

**What survives.** In each case there is a quantity the interface change should conserve and usually does not: the old contexts' log-partition (vocabulary), the old inputs' gradient/NTK field (growth), each client's activation interface (shared base), and the exposure propensity of each input region (traffic). These are the candidate primitives below.

### CPU probe ([`tree/probes/interface_change_probe.py`](probes/interface_change_probe.py), numpy, about 1.4 CPU-s, 5 seeds, mean ± SD)

**Vocabulary growth.** Softmax regression over 20 tokens trained on task A; add 5 output rows and train only those rows on task B (every old weight frozen).

| Arm | A NLL | A acc | Δ A NLL | B acc |
|---|---:|---:|---:|---:|
| Before growth | 0.257 ± 0.064 | 95.6 ± 2.0% | 0 | — |
| Shared softmax, old rows frozen | 0.574 ± 0.112 | 81.8 ± 4.4% | 0.317 ± 0.063 | 98.9 ± 0.5% |
| **Shared + log-Z conservation on unlabeled A anchors** | **0.309 ± 0.077** | **94.1 ± 2.4%** | **0.052 ± 0.013** | 98.0 ± 0.7% |
| Separate softmax + head selector | 0.607 ± 0.080 | 82.3 ± 2.6% | 0.350 ± 0.020 | 97.0 ± 0.8% |

With frozen old logits, 100% of A's NLL increase is the shared log Z (an identity, not a finding). Conserving log Z on unlabeled old contexts removes 84% of the damage for 0.9 points of B accuracy. A separate head just moves the cost into the selector.

**Architecture growth.** 2-layer MLP trained on A, widened with cancelling clone pairs (outputs equal to 1e-12 at insertion), then trained on B.

| Arm | A drift step 1 | step 5 | step 10 | A RMSE step 100 | B RMSE step 100 |
|---|---:|---:|---:|---:|---:|
| No growth | 0.157 ± 0.037 | 0.530 ± 0.097 | 0.763 ± 0.113 | 1.257 ± 0.295 | 0.391 ± 0.098 |
| Widen, train all | 0.391 ± 0.083 | 0.931 ± 0.155 | 1.108 ± 0.242 | 1.260 ± 0.288 | 0.371 ± 0.098 |
| Widen, train new units only | 0.235 ± 0.048 | 0.744 ± 0.121 | 1.003 ± 0.217 | 1.257 ± 0.288 | 0.375 ± 0.105 |

Even with every original weight frozen, the function-preserving widening moves A faster than no growth in the first 10 steps (1.5× at step 1). By step 100 all arms meet, so the effect is early drift at equal steps, not a final retention gap; it shows that function preservation does not preserve the update dynamics on old inputs.

**Endogenous stream.** Linear classifier deployed for 200 rounds; which users return depends on its own predictions; 1,600 labels in every arm.

| Arm | Fixed A acc | Unlabeled bins, last 50 rounds | Zero-support bins |
|---|---:|---:|---:|
| Before deployment | 60.6 ± 2.6% | — | — |
| Exogenous stream | 63.1 ± 4.4% | 4.2 ± 1.7% | 0% |
| Predicted-positive users return 3× | 63.3 ± 10.0% | 9.5 ± 3.3% | 0% |
| Only predicted-positive users return | 52.7 ± 0.5% | 81.4 ± 6.0% | 90.2 ± 12.3% |

The 3× arm only thins coverage (and widens seed variance); the hard gate is a structural counterexample where the model's own decisions remove the evidence for 90% of input bins and fixed-set accuracy falls 8 points below the pre-deployment model.

**Caveats.** Toy hosts only; the log-Z gate uses unlabeled A anchors that a real system must store or regenerate; no compute-matched comparison for growth.

## Rules for ideas in this node

- Do not re-propose B2 (per-skill tokens on a frozen backbone), the PR #4 self-contamination law, or the multi-agent flood's market/auction/insurance mechanisms (M1–M61). Do not drift back into edit equivalence, rate–drift or relearning reads.
- Required controls: for vocabulary ideas, OFA/mean-embedding initialization plus replay of old text at equal tokens; for growth ideas, Net2Net and zero-init LoRA-style growth at equal parameters and steps; for population ideas, plain FedAvg/model soup and a single model with equal total compute; for traffic ideas, an exogenous-stream learner at equal labels and an inverse-propensity-weighted learner.
- Every first test reports old-task retention on a fixed set, plus new-task gain.

## Raw ideas

### A. Vocabulary and tokenizer growth

1. **Partition-function conservation at vocabulary insertion.** **Mechanism:** when output tokens are added, constrain log Z on unlabeled old contexts to its pre-insertion value (a penalty or an exact per-context bias that absorbs new mass), so old rankings and calibrated probabilities are unchanged unless the new token is genuinely the answer. **Why it might be new:** expansion papers optimize new-row initialization; none treat the normalizer as the conserved quantity. **Cheapest first test:** the probe above (done in a toy: 84% of damage removed); next, add 500 tokens to GPT-2 small for a code domain. **Retention check:** WikiText-2 NLL and top-1 agreement with the pre-insertion model on old contexts.
2. **Segmentation-consistency anchors (free replay from re-tokenization).** **Mechanism:** after a new merge, the same old text exists in two segmentations; train the model to give the same next-byte distribution under both. The old segmentation is a replay generator that needs no stored data, only old text the model sees anyway. **Why it might be new:** BPE-dropout ([2605.13436](https://arxiv.org/abs/2605.13436)) regularizes pretraining; using the pre-merge segmentation as a retention anchor at expansion time is not in the pool. **Cheapest first test:** char-level vs merged tokenizer on a tiny LM, add 50 merges mid-training, compare bits-per-byte on old text with and without the consistency loss. **Retention check:** bits-per-byte (tokenizer-invariant) on held-out old text.
3. **Tokens as memoized computation.** **Mechanism:** train with byte fallback always available and a constraint that a merged token's embedding reproduces the hidden state the model reaches after reading its bytes. Vocabulary growth is then a cache insertion with no semantic change; a token can be evicted without forgetting anything. **Why it might be new:** zero-shot tokenizer transfer uses hypernetworks to guess embeddings; an exact cache-equivalence contract makes vocabulary changes retention-neutral by design. **Cheapest first test:** tiny byte-level transformer, insert 100 cache tokens, measure next-byte KL between byte path and token path. **Retention check:** old-text bits-per-byte before vs after insertion and after eviction.
4. **Token mitosis by context bimodality.** **Mechanism:** track each token's output-gradient directions; when they become bimodal (a token's usage forks, e.g. a new product name reusing a word), split it into two children that inherit the parent embedding, routed by a small context gate. Vocabulary grows where credit conflicts, not where frequency is high. **Why it might be new:** BPE grows by frequency; credit-driven mid-life splitting of an existing token is not in the pool (cf. collision-triggered feature split in PR #60, which splits hidden features, not alphabet symbols). **Cheapest first test:** synthetic LM where one token acquires a second meaning in phase 2. **Retention check:** old-meaning accuracy for that token and NLL on unrelated old contexts.
5. **Retired-token recycling with tombstones.** **Mechanism:** tokens that stop appearing are not deleted; their rows are frozen as tombstones that still answer for old text, while their gradient capacity in shared layers is reclaimed. **Why it might be new:** vocabulary is append-only in practice; recycling needs a rule for what old text containing a dead token should still produce. **Cheapest first test:** swap 10% of a toy vocabulary mid-life and compare tombstone vs delete vs keep-training. **Retention check:** old-text NLL on documents that still contain retired tokens.

### B. Architecture growth mid-life

6. **Gradient-preserving growth.** **Mechanism:** choose new units so that, at insertion, both the function and the old-task gradient/NTK on old probe inputs are unchanged (e.g. new units in the null space of the old-input Jacobian, or with a compensating learning-rate mask). **Why it might be new:** Net2Net, LiGO and staged training preserve f only; the probe shows f-preservation still speeds old-task drift (0.39 vs 0.16 at step 1). **Cheapest first test:** add a gradient-preservation arm to the probe's widening experiment. **Retention check:** A drift at steps 1–10 and A RMSE at 100, at equal B progress.
7. **Probationary one-way coupling.** **Mechanism:** new units may read old units but old units cannot read new ones for a probation window; the back-connection opens only when a retention test on old probes passes. **Why it might be new:** progressive nets keep the isolation forever and pay in parameters; a time-limited, test-gated quarantine is a growth protocol, not an architecture. **Cheapest first test:** MLP on split-MNIST-like tasks, compare permanent column, immediate merge and probation. **Retention check:** old-task accuracy at the end of each task.
8. **Depth equals age.** **Mechanism:** grow depth by inserting identity-initialized layers on top; each skill exits at the depth that existed when it was learned (its birth depth). Older skills live in shallower sub-networks that later growth never sits between. **Why it might be new:** early exit is used for compute; tying exit depth to skill age makes later growth structurally unable to change old skills' paths. **Cheapest first test:** 4-task stream on a small transformer with layer insertion per task. **Retention check:** each task evaluated through its birth-depth exit vs the full stack.
9. **Growth triggered by protected-span saturation.** **Mechanism:** grow only when the new-task gradient projected off the protected old-task directions falls below a threshold, i.e. when the learner literally has no retention-safe direction left. **Why it might be new:** dynamic expansion (DEN, 2408.10566) triggers on loss or schedule; a capacity signal defined by retention is different. Risk: plasticity reserve was killed (ledger), so this must beat a loss-plateau trigger. **Cheapest first test:** slowly-changing regression with OGD, compare trigger rules at equal final size. **Retention check:** average old-task loss at equal parameter count.
10. **Succession contract across architectures.** **Mechanism:** when a model is replaced by a new architecture, the predecessor actively searches its own deployment logs for behaviours users depend on (inputs where the user accepted the output and returned) and emits them as the contract the successor must pass. **Why it might be new:** backward-compatible updates (BCT, MUSCLE [2407.09435](https://arxiv.org/abs/2407.09435), negative flips [2105.03048](https://arxiv.org/abs/2105.03048), [2511.08322](https://arxiv.org/abs/2511.08322)) match on generic data; a contract selected from traffic evidence of reliance is not in the pool. **Cheapest first test:** logged-interaction simulator with two model generations, contract vs random-sample distillation at equal size. **Retention check:** negative-flip rate on relied-on inputs and on a fixed old benchmark.

### C. Populations sharing weights

11. **Adapter ABI for shared-base updates.** **Mechanism:** each client adapter registers the activations at its insertion points on a few of its own inputs; a base update must keep those activations within tolerance for every registered client (multi-client backward compatibility). **Why it might be new:** Trans-LoRA and version-transfer methods port adapters after the fact; constraining the base update by its clients' interfaces is prevention. Overlap risk with base-invariant edits (PR #92), which ports edits, not client interfaces. **Cheapest first test:** small LM base with 8 LoRA clients, update base on a new domain, compare ABI constraint vs re-fitting adapters. **Retention check:** each client's task accuracy with its frozen adapter.
12. **Population erasure code for skills.** **Mechanism:** a fleet sharing a trunk keeps each skill in r of n agents and lets the rest forget it; queries route to a holder. Retention becomes a population property with a redundancy factor, and each agent's capacity is freed for new skills. **Why it might be new:** federated CL averages to one model; deliberately non-uniform forgetting with a coverage code is not in the pool or the multi-agent flood. **Cheapest first test:** 8 small MLPs, 32 tasks, compare everyone-learns-everything vs r = 2 assignment at equal per-agent capacity. **Retention check:** fleet-level accuracy on all 32 tasks and worst-task accuracy.
13. **Staggered-lag replicas as living memory.** **Mechanism:** K serving replicas are updated round-robin, so at any time they lag the newest data by 0..K−1 rounds. Old tasks are served (or distilled) from the replica that has trained least since the task was last seen. **Why it might be new:** EMA and snapshot teachers are offline copies; using the serving fleet's natural lag as a time-indexed memory costs no extra storage. **Cheapest first test:** 4 replicas on a 10-task stream vs one model + EMA teacher at equal compute. **Retention check:** old-task accuracy when routed by lag vs the newest replica.
14. **Diversity reservoir from outlier agents.** **Mechanism:** weight sharing homogenizes agents; old skills survive longest in the most divergent agents. Track per-agent divergence from the consensus and, on a detected regression, distill from the most divergent agent that still passes the old test. **Why it might be new:** population methods maximize diversity for exploration; using divergence as a retention reservoir is different. **Cheapest first test:** gossip-averaged population of 8 learners on a task stream, compare repair from consensus vs from the outlier. **Retention check:** old-task accuracy after repair and new-task accuracy cost.
15. **Base-update contagion tracing.** **Mechanism:** when agent A's experience is merged into the shared base, record which other agents' private behaviours changed most; quarantine A's update in those directions until those agents confirm. **Why it might be new:** turns one agent's write into a fleet-wide side-effect audit; federated CL measures global forgetting, not per-agent contagion. **Cheapest first test:** 8 agents, one agent trains on a conflicting task, measure contagion map vs ground-truth damage. **Retention check:** per-agent old accuracy before/after merge.

### D. Learning from the model's own deployment traffic

16. **Exposure-propensity ledger.** **Mechanism:** log, per input region, the probability that the model's own outputs caused that region to be seen again (return, follow-up, label). Weight updates by inverse propensity and flag regions whose evidence vanished because of the model. **Why it might be new:** IPS is standard in recommender learning; using it to separate self-caused absence of evidence from real drift in a CL retention guarantee is not in the pool. **Cheapest first test:** the probe's hard-gate deployment arm with IPS and exploration arms. **Retention check:** fixed-set accuracy and zero-support bin share.
17. **Silence as a regression detector.** **Mechanism:** after an update, a drop in traffic or follow-up rate for a region is evidence of a regression there (users stopped asking). Use it as a label-free trigger for replay or rollback on that region. **Why it might be new:** drift detectors watch input distribution changes as exogenous; reading traffic loss as the model's own forgetting signal inverts it. **Cheapest first test:** user simulator with region-wise abandonment after errors; compare silence-triggered replay vs periodic replay. **Retention check:** accuracy on a fixed old set per region.
18. **Retention exploration budget.** **Mechanism:** reserve ε of live responses to exercise old capabilities in context (canary answers that the user still gets value from), so retention is measured in situ and labels keep flowing for regions the model would otherwise starve. **Why it might be new:** bandit exploration targets reward; exploring for coverage of old capabilities is a different objective. **Cheapest first test:** probe deployment arm with ε ∈ {0, 0.05, 0.1}. **Retention check:** fixed-set accuracy vs ε, and current-task loss cost.
19. **Seasonal anticipatory replay.** **Mechanism:** forecast when an old task's traffic will return (weekly, yearly, product launches) from the traffic history and pre-warm it with replay just before the return. **Why it might be new:** replay schedules react to interference (MIR) or spacing; forecasting the task's return from deployment traffic is not in the pool. **Cheapest first test:** periodic 5-task stream; anticipatory vs uniform replay at equal replay budget. **Retention check:** first-batch accuracy when an old task returns.
20. **Echo accounting for self-quoted traffic.** **Mechanism:** users paste or lightly edit the model's own outputs back in. Detect the model's earlier text (exact-match or watermark), train only on the user's diff and give zero weight to the echoed part. **Why it might be new:** model-collapse work filters synthetic data globally; per-turn diff training on one's own echoed outputs is narrower. Risk: learning from user edits exists (PRELUDE, 2404.15269) and the PR #4 self-contamination law covers collapse onset. **Cheapest first test:** simulator where 30% of inputs are echoes; compare diff-only vs full training. **Retention check:** output diversity and accuracy on a fixed old set.

### E. Other interface changes

21. **Length-indexed retention for context extension.** **Mechanism:** extending the context window (position interpolation, new RoPE base) is an interface change; conserve short-context logits on unlabeled short prompts during extension, the positional analogue of idea 1. **Why it might be new:** extension papers ([2308.10882](https://arxiv.org/abs/2308.10882), [2605.14589](https://arxiv.org/abs/2605.14589)) report short-context loss as a side effect. **Cheapest first test:** tiny transformer extended 4×, with and without short-context conservation. **Retention check:** short-context perplexity and task accuracy.
22. **Precision as a consolidation knob.** **Mechanism:** keep learning on a quantized deployed model; protected weights get a coarse grid so small updates round away (a per-weight barrier), while plastic weights get fine precision or stochastic rounding. **Why it might be new:** Ada-QPacknet uses bit-width for packing; using rounding as the forgetting barrier itself is not in the pool (PR #113 idea 8 uses precision only as a deadline clock). **Cheapest first test:** int8 MLP with a split grid on a 5-task stream vs EWC at equal compute. **Retention check:** old-task accuracy.
23. **Modality insertion with interface conservation.** **Mechanism:** when a new encoder (vision, audio) is attached, conserve the text model's next-token distribution on text-only inputs and its log Z on mixed inputs where the image is uninformative. **Why it might be new:** multimodal CL measures text degradation; conservation of the old modality's distribution at attachment is the same primitive as idea 1 applied to inputs. **Cheapest first test:** toy LM with a synthetic second modality. **Retention check:** text-only perplexity.
24. **Interface-change budget.** **Mechanism:** treat each interface change (new tokens, new units, new modality, replica merge) as spending a retention budget measured by the conserved quantity it disturbs (Δ log Z, Δ NTK on old probes, Δ client activations); schedule interface changes to stay within it. **Why it might be new:** unifies A–D around one conserved-quantity accounting; growth and expansion are scheduled by capacity or data today. **Cheapest first test:** combine the probe's three experiments and check whether each conserved-quantity change predicts old-task loss better than parameter-change norm. **Retention check:** the old-task loss each change predicts.

## Deeper sub-questions (ranked by chance of a new primitive)

1. **What must an interface change conserve so that frozen old parameters imply unchanged old behaviour?** The probe gives two answers (log Z on old contexts for outputs; the gradient field on old inputs for growth). Is there one general condition (old-input outputs *and* their first-order dynamics invariant) that covers tokens, units, modalities and positions? Best chance: it is a clean, testable primitive with a strong toy result already.
2. **Can a learner separate forgetting it caused through its own traffic from exogenous drift?** Needs a propensity ledger and a retention guarantee that holds under self-selected labels; no CL work states this.
3. **When retention is a property of a population, what is the minimal redundancy and routing?** A fleet sharing a trunk could forget per agent and still retain as a whole; open is whether a coding view gives capacity gains over one model at equal compute.
4. **Can vocabulary growth be made semantics-free (tokens as memoized computation)?** If a token is a cache entry with an equivalence check, tokenizer changes stop being a CL event at all.
