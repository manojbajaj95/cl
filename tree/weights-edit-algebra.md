# Node: can training make weight edits compose without forgetting?

Parent: [Self-describing weights](https://github.com/manojbajaj95/cl/blob/devin/1795538897-self-describing-weights/tree/self-describing-weights.md) ([PR #53](https://github.com/manojbajaj95/cl/pull/53)). This is the parent's second branch. Literature and ideation only; no experiments were run for this node.

## Root cause: the old-behavior constraint moves when the state changes

The parent supplies an important negative control. Its fixed vectors **commute exactly in real arithmetic**, but the shared-random-frame arm's first lesson gain drops from `0.740` to `0.693` after the second write and old-task MSE rises from `0.03907` to `0.07034`. Teacher-aligned coordinates keep both edit gains near target yet also raise old-task MSE (`0.00057 → 0.00257`). That is evidence of behavioral interference in one toy, **not** evidence of order dependence. Better addresses made a write portable; they did not make the write preserve what was already learned. The probe does not identify which mechanism caused its measured loss.

Let `s` be the whole mutable checkpoint state (including any optimizer or editor metadata), `P(s)` its protected outputs, and `E_a(s)` the checkpoint after semantic instruction `a`. Past lessons are not all protected forever: the contract says what an instruction is allowed to replace, which earlier promises it must retain, and on which inputs. The key distinction is between:

- **Single-step locality:** `P(E_a(s₀)) ≈ P(s₀)` on the starting checkpoint and sampled old inputs.
- **Retention under composition:** the same condition holds whenever `a` is legal at a *reachable* state `s`, including states with earlier live promises not present at `s₀`.
- **Behavioral algebra:** equal legal scripts remain interchangeable after legal continuations, not just in their immediate predictions. Composition of state maps is already associative; the research goal is semantic composition with observable retention and coverage. Compatible **independent** edits may exchange order, dependent edits get an ordered meaning, and inconsistent promises must be rejected or explicitly superseded.

For a fixed dense displacement `a`, a first-order constraint `J_P(s₀) a = 0` need not hold at `s₀+b`. Near a smooth point the new leakage includes a mixed term `bᵀ H_P(s₀) a` for each protected output, in addition to single-step curvature; nonlinear key movement or activation switches may not even admit a useful common local linear approximation. In a state-dependent editor the effective displacement can change as well. A null space large enough today might be empty of useful directions tomorrow: if the new target sensitivity lies in the span of the protected sensitivities, **no infinitesimal first-order-neutral move can hit the target to first order**. This is an obstruction to local movement, not a proof that no finite or architectural repair exists.

Even exhaustive *pairs from the base* do not prove closure. Consider three edits that set `a`, `b`, or `c` from zero to one. The intended lesson readouts are the three bits and the protected output is `P(a,b,c) = abc`. Each edit and every two-edit order succeeds and retains `P=0`, but all three together flip it. This is a shared-representation counterexample, not an impossibility for the lesson specs: a different model could decouple `P`. A second failure is hidden state: two implementations with the same current readout but different hidden `h` can diverge when the next edit copies `h` into a visible bit. Thus observational equivalence at one step is not necessarily a **congruence** for editing.

**Candidate primitive: a retention-closed action on an edit-aware behavioral state.** Train the model to expose a bounded state on which legal semantic instructions act; equal scripts should lead to states equivalent under future legal instructions, with a declared, testable retention scope. More concretely, if `C_l` is the set of checkpoints meeting protected behavior and live lessons `l`, require `E_a(C_l) ⊆ C_{a(l)}` over the supported reachable states. That inclusion gives retention by induction for exact contracts. With a per-step implementation error `ε` and an `L`-Lipschitz ideal action in a metric that controls protected outputs, error can obey `e_next ≤ L e + ε`; even nonexpansive actions (`L ≤ 1`) allow linear accumulation at `L = 1`. Measure drift against the original protected targets, not just the previous step.

A frozen linear readout on fixed features can already admit such an action when targets are jointly feasible. The open problem is doing it with **shared nonlinear features that also keep learning**, without a snapshot, adapter, or retained example set per edit. Making `n` independent binary lessons retrievable exactly in arbitrary combinations requires at least `n` persistent bits somewhere: there are `2ⁿ` distinguishable combinations. Capacity, admissible edit families, and retention scope are part of the claim.

## What the nearest papers already solve

Read on arXiv; “composition” below distinguishes applying a script of edits from answering questions that combine edited facts.

| Work | What works; what does not establish the closure claim |
| --- | --- |
| [Editable Neural Networks](https://arxiv.org/abs/2004.00345), [MEND](https://arxiv.org/abs/2110.11309), [Edit-Ready Training](https://arxiv.org/abs/2611.26408) | Learn a host that tolerates gradient or simulated edits, or learn an auxiliary editor. ERT rehearses a particular rank-one classifier-head edit with support, query, and reference images; its agent may make several calls *on one request*. Sequences of distinct requests to one network are explicitly future work. Episode-level success and locality don't impose laws on states reached by other requests. |
| [MEMIT](https://arxiv.org/abs/2210.07229) and [Model Editing at Scale](https://arxiv.org/abs/2401.07453) | MEMIT jointly solves for many associations in an edit batch. The follow-up finds progressive loss of previously edited facts/downstream ability and abrupt collapse in tested sequential ROME/MEMIT runs. Jointly fitting a batch does not make the next batch respect the old one. [Better Regularization](https://arxiv.org/abs/2502.01636) isolates activation over-optimization and matrix norm growth in locate-then-edit methods and mitigates them; this does not address feasibility or higher-order leakage for arbitrary admitted edits. |
| [AlphaEdit](https://arxiv.org/abs/2410.02355) | Null-space projection improves sequential editing. The exact algebra in §3 is `(W+Δ)K₀ = WK₀` when `ΔK₀=0`. It composes for any sequence with the same exact protected keys and null space. The implementation thresholds eigenvalues and adds a soft drift penalty for earlier edited keys. A finite key set at one interface isn't an invariant for arbitrary old end-to-end paths or changing keys. |
| [Soft Recursive Least-Squares](https://arxiv.org/abs/2601.15686) | Maintains sufficient statistics and recovers the joint regularized least-squares solution for the supplied key/value pairs. Holding that multiset of pairs fixed, the optimum is order-independent in exact arithmetic. It is a soft fit, not exact feasibility; the guarantee is on the supplied regression problem, not agreement on keys or outputs when layer inputs or target extraction depend on preceding edits. This is the strongest simple control for a learned set of edit statistics. |
| [Task Arithmetic](https://arxiv.org/abs/2212.04089), [Tangent-Space Task Arithmetic](https://arxiv.org/abs/2305.12827), [Nonlinear Task Vector Analysis](https://arxiv.org/abs/2504.10957) | Fixed deltas can be added/subtracted, and task-disentangled support or a fixed tangent model makes functional additivity better justified. The nonlinear analysis gives positive results under explicit task relations and a simplified transformer. These are constructive special cases, not a method for closing semantic edit actions while features, protection scopes, and subsequent edit meanings change. |
| [GRACE](https://arxiv.org/abs/2211.11031), [WISE](https://arxiv.org/abs/2405.14768), [MemEIC](https://arxiv.org/abs/2510.25798) | A growing discrete codebook, a routed side memory with sharding, and external evidence plus dual LoRA/knowledge connector respectively are credible sequential retention controls. MemEIC also reasons across edited visual/textual facts. Isolation and retrieval help, but do not demonstrate closure in a shared dense substrate with bounded auxiliary state and no per-edit inventory. |
| [HPSE](https://arxiv.org/abs/2608.11660), [Learning to Edit](https://arxiv.org/abs/2402.11905), [Reversible Model Merging](https://arxiv.org/abs/2510.14163) | HPSE teaches atomic/multi-hop use of an injected passage. LTE trains a model to apply retrieved updates at inference, including in sequential settings. RMM preserves a basis to reconstruct source models after merging. None of these demonstrations requires equal edit paths to withstand future writes, or selective removal to leave other live edits intact on a changing dense host without retaining the old model basis. |
| [μKE](https://arxiv.org/abs/2504.01196) and [EtCon](https://arxiv.org/abs/2512.04753) | μKE explicitly protects dependencies between parts of a long-form edit via nested objectives and adaptive weighting. EtCon consolidates a targeted edit by training on autoregressive trajectories. These address genuine dependencies and distribution shifts, but neither establishes a reusable retention law for unseen sequences of distinct semantic requests. |
| [WikiBigEdit](https://arxiv.org/abs/2503.05683) | Tests the practical limits of lifelong factual editing on large streams of real changes and includes retrieval and continual fine-tuning comparisons. It is a useful scale check *after* controlled algebra tests; retention curves alone cannot distinguish a semantics-preserving composition law from a successful memory system. |

The gap is not “no sequential editor works.” It is the absence, in the reviewed work, of a learned, reusable **closure law** for nontrivial edit families on a moving shared representation, tested on novel histories at matched edit success and resource cost.

## Raw ideas (unranked)

These are candidate distinctions, not novelty verdicts or a shortlist. The [idea ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md) and [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md) already cover O1/O2/L4/X3 and Lie closure, fixed patches/homomorphisms, and rebasing by measured noncommutation. Hence the cards change the mechanism or contract, not just add inverse, idempotence, or commutator losses. They also do not re-propose predicting a capacity horizon from delta norms, forecasting a plasticity reserve, or detecting damaged facts with a sketch.

**Shared first-test discipline.** Start on a tiny dense MLP or transformer with independently generated old, edit, and held-out composition inputs and an oracle for which scripts are legal. Include valid overlap, intentional supersession, genuine conflicts, and held-out edit combinations/depths. At every prefix report efficacy, worst protected old and still-live lesson error, and admission rate on feasible requests; declaring everything unsafe or doing nothing is not success. For equal scripts check immediate and continuation behavior, and for deletions score the new intended target separately. Match base quality, bytes (including persistent edit state), training/update compute, supervision, and probe calls; disclose any temporary lookahead/search. Keep matched history rehearsal without the proposed structural change, a simple fixed-feature solver, and an appropriate isolation/retrieval control. All tests below are proposals.

### Make preservation structural

1. **Predictive edit quotient.** *Mechanism:* train a bottleneck `q(s)` with a successor model `q(E_a(s)) = T_a(q(s))`; pull together states only if both protected readouts and successors under randomly chosen continuations agree, including their admission decisions. *Why new:* unlike a weight header describing a current write, this makes behavioral equivalence predictive of future edits and a target for compression. *First test:* deliberately plant checkpoint twins that agree now but diverge on a third write; hold out that third instruction family and compare to one-step effect embeddings. Score all original and live lessons after the witness and after safe merges of twins.

2. **Protected factor with editable coordinates.** *Mechanism:* learn an invertible, input-conditioned coupling on shared hidden channels whose quotient feeds protected readouts; the editable fiber can depend on the quotient but cannot feed back into it within an edit epoch. Learn the factor jointly so its responsibilities are not given as task IDs. *Why new:* exact invariance comes from a learned computational factor, not distance from a key span or keeping one module per task. *First test:* on mixed tasks with overlapping input features and an explicit protected head, edit the fiber through unseen overlapping requests. Compare to a frozen-head adapter and a static-width split; test protected readouts on held-out shifts and the earlier editable targets after each write.

3. **Square-zero edit ideal.** *Mechanism:* learn a dense change of basis so accepted operator perturbations map a shared source into a destination and annihilate every possible edit destination: `Δ_a Δ_b = 0`. Project the destination out of declared protected readouts. Single-interface products then have no edit-by-edit terms even for finite operations. *Why new:* this builds an exact vanishing-product law into a learned operator family instead of penalizing observed commutators; it constrains a different failure than Lie closure. *First test:* fit an editable linear residual stack to a teacher with compositional but separable lessons; try withheld triples and repeat the exercise with nonlinearities between interfaces as a limit case. Compare to rank-matched subspace arithmetic; check all original and live outputs.

4. **Curvature-canceling edit paths.** *Mechanism:* train a small predictor of a second correction direction from edit strength and current state, explicitly targeting the protected Hessian-vector leakage of a finite write. Integrate the corrected path through a handful of substeps, refreshing the tangent. *Why new:* first-order projection protects one tangent; this learns a finite trajectory that follows a retention level set without storing its old samples at deployment. *First test:* use a bilinear protected readout with known curvature and two new outputs; compare strength sweeps against finite repeated AlphaEdit-like projection using the same probes. Check previous edits and the worst old MSE at intermediate points as well as endpoints.

5. **Nonexpansive effect transport.** *Mechanism:* learn a metric on protected output and edit-sufficient state, and constrain legal successor maps to be nonexpansive in it on supported states. Optionally contract nuisance error for irreversible stabilization but not along reversible semantic degrees of freedom. *Why new:* this asks for a law bounding amplification of approximation errors, even when individual writes are imperfect; it is not a scalar Lyapunov forecast. *First test:* fork a toy host with controlled hidden drift, apply the same held-out stream to both, and compare error amplification to spectral normalization plus rehearsal. Measure absolute old/live errors against targets as well as fork distance so both branches cannot forget together unnoticed.

6. **Retention-faithful feature migration.** *Mechanism:* constrain selected backbone updates to carry the edit interface through an invertible transform `k' = A k`; migrate key covariance by `A C Aᵀ`, key–target moments by left multiplication by `A`, and the readout by `W A⁻¹`. Transport any ridge metric too rather than imposing a fresh isotropic one. Learn when a representation change is expressible this way; otherwise treat it as out of contract, not a proved migration. *Why new:* change the statistics underlying the entire editable interface exactly, without rebasing individual deltas, replaying old keys, or identifying individual units. *First test:* interleave synthetic invertible hidden shifts and a learned noninvertible drift with new lessons. Compare to frozen features and equal-budget RLS refresh; test old and live outputs on keys excluded from migration fitting.

### Infer conflict structure and higher-order effects

7. **Interaction-spectrum editor.** *Mechanism:* train a low-order factorization of protected leakage over edit subsets using signed inclusion–exclusion probes. Learn sparse, reusable ternary compensators indexed by lesson features, rather than separate patches for particular triples. *Why new:* decomposes edit-set interference into actual mixed effects; a loss on pair order sees zero on `P=abc`. *First test:* hide the leaking triple and some safe triples in the product toy, then transfer to a small nonlinear MLP. Compare to pairwise-only and matched full-history rehearsal; after correction check prior lessons and protected outputs on unseen triple variants.

8. **Minimal jointly inconsistent set as an edit result.** *Mechanism:* train the edit interface to output a checkable infeasible subset of promised behaviors, using dual witnesses in a learned constrained subspace and a distinct “unresolved” result when only the subspace is ruled out. *Why new:* unlike a binary write-type gate or pairwise similarity estimate, the returned object identifies exactly which promises must be relaxed together in the solver's scope. *First test:* use a linear constraint toy containing pairwise-feasible but jointly inconsistent triples, with hidden feasible overlaps. Compare to an equal-cost conflict classifier; freeze state on rejections and check old/live retention and coverage on all admitted cases.

9. **Critical-pair corrective rewriting.** *Mechanism:* compile a learned operator alphabet together with oriented local repair rewrites, and impose a decreasing symbolic cost to terminate. Train overlaps of rewrite rules, not just observed pairs of edit commands, against a reference normal form. *Why new:* retains deliberately noncommuting semantics where needed; attempts local-to-global confluence on a restricted script language rather than learning that operators should exchange. *First test:* synthesize a tiny action vocabulary with two competing reductions of the same three-command script; withhold whole longer strings and compare to deterministic canonical sorting plus rehearsal. Verify the destination, all live lessons, and old outputs along every executed prefix.

10. **Overlap-only negotiation.** *Mechanism:* have commands expose a compact representation of their intended effects on shared latent factors; solve only the intersecting constraints, then splice the untouched actions back. Train the summary to be sufficient for declaring when an intersection is harmless and when a joint correction is needed. *Why new:* edits are not simply assigned disjoint addresses or rejected for overlap; the object is a portable partial constraint allowing local repair without seeing either full dataset. *First test:* generate coupled toy skills with overlapping supports but vary whether their effects agree. Compare to fixed disjoint routing and full batch solving at matched bytes; check old and prior lessons before and after admitted overlaps.

11. **Certifiable composition of retention bounds.** *Mechanism:* let each operator emit a small transfer function on abstract bounds for protected hidden states; compose the transfer functions and train them to be informative, using interval or zonotope propagation as the sound checker rather than trusting a learned score. *Why new:* enables preflight guarantees over an entire script with no execution on the whole protected set; an effect header usually predicts a specific write. *First test:* on a small ReLU net with analytically enclosed input boxes, hold out long merge scripts. Compare to post-hoc bound propagation at matched accepted-edit coverage; verify soundness against exact optima over activation regions where tractable and retest old/live data after commits.

12. **Null-edit witnesses.** *Mechanism:* train admissible no-op transformations which preserve current outputs but vary otherwise hidden coordinates; use them as adversarial states for learning successor invariance. Require no-ops to be certified relative to the current declared outputs, not assumed from small deltas. *Why new:* trains against hidden path dependence, rather than against another random semantic edit or a symmetry known to preserve the whole model. *First test:* perturb dense directions invisible on a toy's entire current output domain, then apply a fresh edit whose compiler reads those directions. Compare to random same-norm augmentation; check agreement after the edit and retained original/live outputs for both arms.

### Make removal and replacement composable

13. **Discarded-fiber receipts.** *Mechanism:* a lossy replacement produces a compact latent receipt for only the degrees of freedom it destroyed. Train a receipt decoder to remove the replacement in arbitrary admissible contexts while retaining later independent edits. *Why new:* seeks conditional information needed for selective undo, not a checkpoint stack, reconstructible source model basis, or compressed chronological delta log. *First test:* overwrite a shared low-rank factor, insert a second edit, then remove the first without replay. Sweep receipt bits versus saved residuals and RMM-style bases; check the second lesson, restored target, and all original tasks.

14. **Deletion by marginal constraint subtraction.** *Mechanism:* train a shared nonlinear feature model to read a compact signed sum of edit statistics; allow subtraction of the target instruction's sufficient statistic when that instruction is supplied again. Optimize for the remove-one counterfactual, not reconstruction of checkpoints. *Why new:* RLS already admits fixed-key downdates; the bet is that learned statistics support selective deletion after nonlinear feature learning without retaining individual keys or replaying surviving lessons. *First test:* train on pairs in a drifting toy and delete one member of an unseen triple; compare to RLS downdate with fixed keys and equal-byte deltas. Retest surviving lessons, unrelated old behavior, and the removed target.

15. **Declared dependency cuts.** *Mechanism:* represent edited behavior by alternative minimal derivations rather than one dependency list; when deleting a premise, recompute only derivations that lose their last valid support, while preserving outputs with redundant support. Learn the derivations by interventions, not correlation. *Why new:* the algebra distinguishes removing a dependency from removing the conclusion; a patch log or simple descendants rollback cannot do this when independent proofs overlap. *First test:* train tiny rule reasoning with two proofs of one answer, delete a premise from each in turn, and compare to single-parent rollback and full recompilation. Check previously corrected answers with live alternative proofs and unrelated old queries.

16. **Lexicographic supersession.** *Mechanism:* attach explicit priority as part of a semantic replacement command. Train a learned shared optimizer to return the lexicographically feasible set of effects, with fixed protections ahead of revisable lessons, and emit which lower-ranked obligations were displaced. *Why new:* ordinary merge weighting trades all errors against one another; this makes deliberate supersession composable and prevents it being counted as incidental forgetting. *First test:* stream contradictory toy rule changes in different arrival orders with the same specified priorities. Compare to weighted RLS and last-write-wins; check cases requiring a lower-priority premise to survive on the nonoverlapping domain and retest protected old outputs.

17. **Compensators rather than time reversal.** *Mechanism:* learn a forward action that cancels only the declared effect of an earlier edit, treating downstream actions as fixed constraints. Ask for a witness of unavoidable side effects when a compensator is infeasible. *Why new:* a mathematical inverse erases a transition; this is a new legal edit with its own scope, so it can cancel an effect without reconstructing the earlier state or resurrecting stale semantics. *First test:* apply a rule change, then a related but still valid refinement, then cancel the first rule's contribution on only one domain. Compare to inverse delta and receipt-based undo; preserve the refinement and all old outputs outside the cancellation scope.

18. **Undo-stable code finetuning.** *Mechanism:* use discrete editable bottlenecks with two update channels: ordinary training may change the shared real-valued decoder, but must preserve the decoded contrast between each admissible code and its deletion code, not just their current reconstructions. *Why new:* an editable quantizer or ABI can preserve current reads; here the specific invariant is a counterfactual remove-one effect after consolidation. *First test:* alternate few-bit overwrite/delete on a dense toy with new-feature training, then delete an early lesson using the old code. Compare to output/reconstruction distillation plus the same quantizer; measure old behavior and every surviving edit after removal.

### Compose across training and model use

19. **SGD–edit exchange rules.** *Mechanism:* treat a block of ordinary learning as a second action and train an exchange rule `learn; edit ↔ adapted-edit; adapted-learn` only where the semantics specifies independence. Include momentum in the state so a successful immediate exchange cannot conceal next-step damage. *Why new:* targets interchange between *different kinds* of updates, not commuting edits or keeping a fixed address ABI. *First test:* cross one learned edit with an actual optimizer step on independently labeled data, then continue with fresh gradient steps. Compare to joint rehearsal without an exchange map; require both the intended edit and the learning gain, and check protected tasks and the earlier sequential lessons after the continuation.

20. **Self-distill the continuation, not the checkpoint.** *Mechanism:* periodically consolidate old editing states into a small dense host by distilling both current outputs and the law for a sampled legal next write, with a large teacher available only in training. Distill equality or inequality of branch outcomes that matter to retention, not raw deltas. *Why new:* a consolidation can preserve predictions while deleting the capacity to apply or remove a lesson later; the supervised object is successor behavior. *First test:* consolidate a growing toy editor to fixed bytes, then use withheld multi-step scripts the teacher can still handle. Compare to output-only distillation and replay with the same teacher calls; score old base tasks and all still-live lessons after each later step.

21. **Rollout-closed locality.** *Mechanism:* train edit invariants over protected state-transition distributions of a policy, not merely logits on old prompts. Use short checked macro-transitions and compose their bounds on a declared subset; allow a write to affect trajectories only after the intervention boundary. *Why new:* accounts for the edit changing which states are subsequently seen; same-input KL and fact-based locality miss that failure, while EtCon uses rollout alignment for the intended edit. *First test:* edit one move in a tiny maze policy where an old route's prefix is preserved but another task can enter a new state. Compare to prompt KL and equal-rollout distillation; check old-route success, state visitation and earlier lessons under free rollouts.

22. **Transport edited inferences, not individual facts.** *Mechanism:* learn how an edit transforms a typed derivation step, then apply the same transformation at any depth where its precondition holds; certify unaffected steps with a finite toy proof checker. *Why new:* rather than merely training on generated multi-hop questions, this aims for a rewrite that composes on derivations the editor never saw and distinguishes intended consequences from forgetting. *First test:* change two relations in a small logic learner, then hold out depth-four queries and apply the edits in admissible orders. Compare with HPSE-style rollout distillation at matched data; test protected proofs, old unrelated facts, and the first edit's valid consequences.

23. **An edit action that can split and rejoin context.** *Mechanism:* learn a checkpoint transition whose effect is indexed by a latent context partition. For independent contexts train `split; edit each side; rejoin` to agree with their unsplit history, with bounded interaction state at the shared boundary. *Why new:* a router selects among stored adapters; this requires split/join identities when contexts overlap and later recombine in one dense model rather than leaving two adapters deployed. *First test:* split overlapping two-feature domains, do two local writes, then rejoin and apply a third cross-domain write. Compare to WISE-style routing plus merging and dense rehearsal; check old examples in the overlap and each branch's earlier fixes.

24. **Edit-sufficient envelope expansion.** *Mechanism:* train a bounded applicability envelope defining which future actions a representation can currently support, then learn a transformation that enlarges that set *while preserving every existing contract*. Score it on newly feasible requests, not a proxy for spare capacity. *Why new:* a feasibility gate predicts failure and a reserve score ranks writes; expansion is a constructive operation over the repertoire of legal edits. *First test:* give a fixed-width dense toy a deliberately aliased feature preventing two jointly feasible semantic edits; allow an equal-capacity re-encoding step. Compare to static gating and extra rehearsal; after unlocking both writes, repeat prior scripts and check old/live retention and admission on unaffected scopes.

## Deeper sub-questions, ranked by chance of a new primitive

1. **What state is sufficient to predict future edit behavior?** Seek the smallest state on which current agreement is a congruence under later edits. Use checkpoint twins and held-out continuations (cards 1, 12, 20); a positive result creates an interface for composition, compression, and auditing, not another editor score.
2. **Can training make protected behavior an invariant of a shared nonlinear edit action?** Compare learned invariant factors or square-zero interfaces against fixed-feature RLS and equal-budget adapters, then let the features move (cards 2–6). The critical result is retention at matched edit success and admission on held-out depths without one slot per lesson.
3. **What higher-order conflicts cannot be detected pairwise, and can an editor return a repair or a witness?** Hold out interacting triples whose pairs all pass and separate repairable interference from incompatible promises (cards 7–11). Success would change what an edit returns, beyond a delta or scalar safety score.
4. **How much information does selective undo require after shared learning?** Compare a minimal lost-state receipt with signed statistics and compensating actions under a hard byte cap, holding the surviving lessons fixed (cards 13–18). A lower bound or constructive encoding would clarify when rollback is a primitive rather than stored history.
5. **When can ordinary learning and certified edits exchange order?** Test on interleaved accepted edits and optimizer steps, then evaluate old functions and unseen edit continuations (cards 6, 19–20). An exchange law would let ongoing training and editing share a checkpoint without freezing the representation or invalidating every previous contract.
