# Carried identifiability: unresolved ambiguity as continual-learning state

**Parent:** [tree/rl-discriminating-experiments.md, PR #57](https://github.com/manojbajaj95/cl/pull/57), sub-question 5 and idea 11 ("identifiability-debt ledger"). There a NumPy probe showed that even oracle cue-conflict queries leave rule A at chance after rule B is learned, and that the "rival" (cue shortcut) exists only as a blend inside one function.

**Question:** Can what the data could not tell apart (the set of hypotheses equally consistent with task A) be carried across tasks as state, and be resolved later by evidence that arrives in a *different* task?

**Short answer from the literature:** no current method does this. Every family either commits to one function at the end of a task, carries uncertainty of the wrong kind (local parameter noise, not discrete rival explanations), protects behaviour only where the rivals agree, or resolves ambiguity only with labels for the same data. Ideation only; no experiments were run for this node.

## Why current approaches can't do this

| Family | What it carries across tasks | Why it cannot carry or resolve identifiability |
| --- | --- | --- |
| Point-estimate CL: replay, EWC/SI, OGD/GPM, task vectors | One weight vector plus protection of old outputs or old gradient subspaces | SGD returns one member of the Rashomon set ([Semenova et al. 1908.01755](https://arxiv.org/abs/1908.01755); underspecification, [D'Amour et al. 2011.03395](https://arxiv.org/abs/2011.03395)). Which member is decided by simplicity bias ([Shah et al. 2006.07710](https://arxiv.org/abs/2006.07710); [Hermann et al. 2310.16228](https://arxiv.org/abs/2310.16228)), not by evidence, and the alternatives are discarded when the task ends. |
| Bayesian CL: VCL, sequential HMC, neural tangent ensemble | A posterior used as the next prior | Gaussian / Laplace posteriors are unimodal around the chosen basin; rule-vs-cue are different basins, so the rival has ~zero mass. Even HMC samples propagated through a density estimator fail to stop forgetting, and misspecification breaks sequential updating ([Kessler et al. 2301.01828](https://arxiv.org/abs/2301.01828)). The NTE view ([2408.17394](https://arxiv.org/abs/2408.17394)) is a posterior over fixed lazy-regime experts, not over feature-level explanations. |
| Ensembles in CL ([2202.09826](https://arxiv.org/abs/2202.09826)) | K models | Diversity comes from seeds; in the parent probe no ensemble member was rule-like or a pure cue follower. Members are diverse on-support noise, not distinct off-support hypotheses. |
| Diverse-hypothesis methods: DivDis [2202.03418](https://arxiv.org/abs/2202.03418), D-BAT [2202.04414](https://arxiv.org/abs/2202.04414), CAML [2605.20771](https://arxiv.org/abs/2605.20771) | Within one task: K heads that disagree off-support | Disambiguation needs labels from the *same* task's distribution, and the losing heads are thrown away. Nothing persists across a stream. |
| Backward-transfer CL, e.g. CUBER [2211.00789](https://arxiv.org/abs/2211.00789) | Gradient-projection conditions under which a new task may update old ones | Improves old tasks where gradients align in the input subspace of old data. That subspace is the *on-support* region where rule and cue agree, so it cannot repair off-support errors. |
| Stratified retention for world models [2610.03713](https://arxiv.org/abs/2610.03713) | Retention keyed by invariance timescale | Assumes it is known which knowledge is invariant; the question here is how to carry *not knowing* that. |
| Label-delay / partial-label learning; our D1 deferred-commitment weights and D2 gradient IOUs (ideas/flood/learning-primitives.md) | Candidate labels or K branches per ambiguous *example* | Resolution arrives as a label for the same example. Nothing links task A's ambiguity to task B's evidence through shared features. |
| Agent memory with falsification gates: FGSE [2611.14326](https://arxiv.org/abs/2611.14326), EvoBelief [2610.12789](https://arxiv.org/abs/2610.12789) | Lessons written after tests pass | Stores what was concluded, never what is still open; a lesson cannot be retroactively rewritten when a later task decides an earlier ambiguity. |
| Shortcut-in-CL studies, e.g. continual LEGO [2605.05495](https://arxiv.org/abs/2605.05495) | — | Shows shortcuts learned early impair later learning; the reverse direction (later tasks repairing earlier shortcuts) is not targeted. |

### Root cause

Carrying identifiability needs three things, and current CL has none of them:

1. **The ambiguity is not a state variable.** Training ends with one function; the equivalence class of functions that fit A equally well is never written down. Bayesian CL writes down a *local* parameter uncertainty, which is the wrong object: identifiability is functional and usually discrete (rule vs cue are different basins).
2. **Retention is defined on-support, but identifiability lives off-support.** Replay, EWC, OGD and backward-transfer methods all protect or improve outputs on A's data distribution. On that distribution the rivals agree (98% in the parent probe), so these methods are blind to whether the ambiguity is kept, collapsed by evidence, or collapsed by drift. Nothing distinguishes "resolved by evidence" from "resolved by interference".
3. **No cross-task binding variable.** For task B to answer task A's open question, both must be stated over a shared variable (e.g. "is feature c a cue or a cause?"). Tasks are treated as independent likelihood factors over raw weights, so B's evidence about c has no route back to A's readout.

A minimal object that has all three: an **open question** = (the rival functions or the fork direction separating them, the shared features they disagree on, the off-support region where they split), stored per task, kept alive by a spread-preserving constraint, and closed only by evidence that projects onto it.

One caveat from the parent probe: there A's *aligned* split also fell to ~54% after B, so plain forgetting dominated. Tests below therefore keep A's on-support behaviour fixed (task-id heads or a frozen A readout) to isolate identifiability from ordinary forgetting.

### Shared first-test world: the carried-identifiability stream (CIS)

Extend `tree/probes/discriminating_experiments.py`: 16 input bits; core bits K and cue-capable bits C are fixed across tasks. Tasks T1..T5 each have a rule over a subset of K plus one cue bit in C that matches the label 98% of the time, except T4, where its cue is decorrelated (evidence that "C-bits are not causal"). **Delayed-resolution gain (DRG)** = T1 cue-flipped accuracy after T4 minus before T4, with no T1 data used after T1. **Retention check** in every test: T1 aligned accuracy, T2–T3 accuracy, and T5 plasticity, against equal-byte replay, EWC, and plain SGD.

## Raw ideas (unfiltered)

Each: mechanism / why new / cheapest first test (all on CIS unless noted, all with the retention check above).

1. **Rashomon slice as state.** At the end of each task, keep K members of its Rashomon set that are forced to disagree off-support (D-BAT objective on generated bit-flip inputs) and carry all of them; later tasks reweight members by evidence. **New:** the ambiguity set, not a point, is the unit carried between tasks. **Test:** K=4 members for T1; DRG after T4 vs a seed ensemble of the same size.
2. **Disagreement-region certificate.** Store per task a consensus model plus a tiny classifier g_A(x) predicting where the rivals split. Any later labelled data that falls in g_A's region is routed to resolve A. **New:** carries *where we don't know* as a learned region, at far fewer bytes than the rivals. **Test:** bytes and DRG vs idea 1.
3. **Feature-trust ledger.** Summarize each hypothesis by its attribution profile over shared input features; keep a per-feature trust score updated by every task; A's posterior over its hypotheses is recomputed from current trust. **New:** CL state is a per-feature reliability vector shared across tasks, so evidence anywhere re-scores every past task. **Test:** oracle attributions first, then integrated gradients; DRG and number of tasks re-scored.
4. **Open-question tokens (LLM).** Write each unresolved ambiguity as a text question with two candidate adapters ("does the label follow length or sentiment?"); on every new task, a resolver checks whether its data discriminates. **New:** questions, not answers, as memory entries. **Test:** Qwen2.5-0.5B, two text tasks sharing a length cue; DRG on task 1's cue-flipped split, with the temperature-matched no-memory arm required by the A3 finding.
5. **Spread-preserving regularizer.** While learning B, penalize collapse of the rivals' disagreement on A's off-support probes (preserve the spread, not the outputs). **New:** "don't forget your uncertainty", the dual of EWC. **Test:** spread after T2–T3 and DRG after T4 vs EWC with the same coefficient budget.
6. **Fork-direction Fisher.** Compute EWC importance along the weight direction separating the rivals, so the representation keeps both the cue feature and the rule feature decodable. Resolution then needs only a readout change. **New:** protects the capacity to change one's mind, not a decision. **Test:** linear-probe decodability of rule bits after T3 and DRG with readout-only resolution.
7. **Hierarchical meta-hypotheses.** Keep an explicit tiny posterior over meta-hypotheses ("C-type features are spurious"), with tasks as exchangeable draws; the network's per-task rivals are its likelihood terms. **New:** identifiability resolved by pooling across tasks, retroactively. **Test:** DRG vs feature-trust ledger (idea 3); vary how many tasks are ambiguous.
8. **Lazy commitment.** Freeze A's representation and keep two readouts (rule-reliant, cue-reliant); choose at query time from the current meta-posterior. **New:** resolution costs zero gradient steps and is reversible. **Test:** DRG and storage vs retraining A's head on stored data.
9. **Hypothesis IOUs.** Store generated unlabeled off-support inputs where A's rivals disagree. When a later task settles the question, pseudo-label them with the winner and train. **New:** unlike D2 (an IOU per candidate label of one example, redeemed by its label), these are redeemed by *cross-task* evidence. **Test:** 32 IOUs vs 32 replay points; DRG and T1 aligned retention.
10. **Identifiability-debt accounting.** Track debt = rival disagreement mass on a canonical probe set. An update may reduce debt only if it is justified by evidence (gradient projects onto the fork); unjustified reductions (drift) are penalized or reverted. **New:** separates "resolved by evidence" from "resolved by forgetting", which no CL metric does. **Test:** fraction of debt reduction attributed to evidence vs drift under plain SGD; DRG with the penalty on.
11. **Evidence-vs-drift attribution.** For each change in which rival A favours, use influence estimates on B's examples: keep the change if the influential examples bear on shared features, revert it otherwise. **New:** an audit of *why* the model changed its mind on an old question. **Test:** precision of the evidence/drift label against CIS ground truth.
12. **Partition refinement over features.** CL state = a partition of features into classes the data so far cannot tell apart (union-find). Each task can only split classes; every past task whose decision depended on a split class is re-resolved. **New:** monotone partition refinement as the learning state, like version spaces but over features and shared across tasks. **Test:** partition recovered from rival attributions vs ground truth; DRG for all tasks after each split.
13. **Honest-ambiguity outputs.** Train A to predict confidently only where its rivals agree and to abstain (or output the mixture) elsewhere; narrow abstention as classes split. **New:** nothing wrong is committed, so nothing has to be forgotten. **Test:** selective accuracy and coverage on T1 cue-flipped before/after T4.
14. **Online retroactive inductive bias.** Learn from resolved tasks which kind of hypothesis tends to win (cue vs rule, short vs long program), and re-apply it to past still-unresolved tasks. **New:** CAML meta-learns the bias offline per benchmark; here it is learned along the stream and applied backwards. **Test:** DRG on T1–T3 when only T4 is informative.
15. **Fork adapter: a scalar per open question.** Store the top-r singular directions of the weight difference between rivals as a rank-r adapter; resolution sets one coefficient. **New:** an open question becomes one addressable knob in weight space. **Test:** set the coefficient from T4 evidence (idea 16) and measure DRG; bytes vs storing both rivals.
16. **Gradient-alignment routing.** B's data answers A's open question if ⟨∇L_B, fork_A⟩ is significantly non-zero; its sign gives the answer. **New:** evidence is routed to old questions without anyone naming the shared feature. **Test:** routing precision/recall on CIS (T4 should route to T1–T3, T5 should not).
17. **Debt-driven task selection.** Given carried debt, pick the next task or data source from a pool by expected debt resolved per cost. **New:** active selection of *future tasks* by questions old tasks left open. **Test:** pool of 6 candidate tasks; debt remaining after 2 picks vs random and vs entropy on the current task.
18. **Sequential IRM with carried rivals.** Treat tasks as environments that arrive one at a time; past environments are present only as their rival summaries, and invariance is enforced against those. **New:** IRM needs simultaneous environments; this replaces old environments by carried hypotheses. **Risk:** online IRM variants may exist. **Test:** DRG vs IRM with replayed old data at matched bytes.
19. **Abduction memory for agents.** The agent stores "unexplained regularities" per task with both explanations; each new task's trajectories are checked for discrimination, and resolved items rewrite earlier lessons. **New:** memory of what is unknown, rewritten retroactively. **Test:** CL-Bench-style text tasks; lesson accuracy before/after a discriminating task, with temperature-matched and filler controls.
20. **Assumption-based truth maintenance for CL.** Every lesson, adapter, or skill records which open questions it assumed an answer to; when a question resolves, all dependents on the losing side are dropped or flipped. **New:** ATMS-style dependency labels on neural updates, with unresolved identifiability as the assumptions. **Test:** 5-task stream where T2–T3 adapters were trained assuming T1's cue; accuracy of T2–T3 after T4 with and without dependency flips.
21. **Hypothesis-code distillation.** Distill a task's rivals into one network conditioned on a hypothesis code h, where the same h means the same thing across tasks ("trust C-features"). Later evidence sets h once for all tasks. **New:** D1 branch codes are per delayed label; here the code is a shared cross-task assumption. **Test:** DRG for T1–T3 after setting h from T4; aligned retention vs separate rivals.
22. **Rate–distortion of ambiguity.** Choose B's update to minimize bits of information about A's open questions destroyed per bit learned on B (estimated from rival disagreement). **New:** a budget on lost *uncertainty*, not lost accuracy. **Test:** Pareto curve of B accuracy vs remaining spread, vs EWC's curve.
23. **Disagreement witnesses without labels.** Synthesize (by input optimization) the inputs on which A's rivals disagree most and store only those, unlabeled. Any later labeller (a later task's verifier, a stronger model, a human) labels just those. **New:** stores the question, not the answer; parent idea 2 stores labelled witnesses after resolution. **Test:** labels needed to fix T1-flipped vs replaying random T1 points.
24. **Measure natural delayed resolution.** Does plain SGD on a shared network already show DRG > 0 when T4 decorrelates a cue that T1 relied on? Check in the MLP probe and in a 0.5B LLM with a shared-cue task sequence. **New:** nobody reports backward transfer *of shortcut repair*; it fixes the headroom for every idea above. **Test:** DRG for SGD, replay, EWC, and a multi-head model, 5 seeds.
25. **Evidence escrow.** Keep a tiny buffer of later-task examples that routed onto an old question (idea 16), applied only when that old task is next queried or consolidated. **New:** evidence is stored next to the question it answers, not mixed into the current task. **Test:** DRG and T5 plasticity vs applying the evidence immediately.

## Ranked deeper sub-questions

1. **Does delayed resolution happen at all without help, and how much headroom is there?** Build CIS; measure DRG for SGD, replay, EWC and multi-head (idea 24). Everything below depends on this number. Dead end for the node if plain multi-head SGD already reaches oracle-level DRG; promising if DRG ≈ 0.
2. **Can a rival be kept as a weight-space fork (a rank-r adapter with one coefficient) and closed by gradient alignment from a later task, without any old-task data?** Ideas 15, 16, 8, 21. Dead if fork-adapter DRG is not ≥ 10 pp above equal-byte replay, or routing confuses T4 with T5.
3. **Should continual learning protect the spread off-support instead of the outputs on-support?** Ideas 5, 6, 10, 11, 22. Test whether a spread-preserving regularizer keeps the ambiguity alive until T4 without hurting T5 plasticity more than EWC.
4. **Can identifiability be carried as a feature-level state shared across tasks (trust ledger or partition refinement), so one piece of evidence re-resolves every past task?** Ideas 3, 7, 12, 14, 18. Needs feature attributions that are faithful enough; start with oracle attributions to bound the gain.
5. **For LLM agents, can a truth-maintenance memory carry open questions and retroactively rewrite the lessons that depended on them?** Ideas 4, 19, 20. Must beat the temperature-matched and same-length filler arms from the A3 pilots.
