# Can a payload be separated from its selector, and can compiled writes link?

Depth 3, below forward-trace-compile (`tree/forward-trace-compile.md`) ([PR #60](https://github.com/manojbajaj95/cl/pull/60)). That node found a trace says *what value to write* but not *where the write fires* or *which later layers read it*. This node asks two follow-ups: can a reusable **payload** (the value) be inferred separately from the **selector** (the key condition that delivers it), and can two independently compiled writes be **linked** without re-reading either one's examples? Ideation only; no experiments were run.

## Root cause: payload and selector are only identified as a product, and both live in someone else's coordinates

For a rank-one write ΔW = v aᵀ, the evidence (traces on fitted keys k_i) pins down only the products v·(aᵀk_i). Three facts make the factors non-identifiable and non-portable:

1. **Gauge of the factorization.** (v, a) and (cv + n, a/c) with n in the null space of everything downstream produce the same fitted behavior. The trace contrast v = h(fact) − h(no fact) contains position, copying and template components that are part of *this* selector's context, not the value. Nothing in the data separates "what" from "this-way-of-asking". The parent probe showed the consequence: least-squares selectors fired at coefficient 0.95 on a wrong subject (+34.7 pp leakage).
2. **The payload is in the consumer's code, not a shared one.** Function vectors steer in cases where the logit lens cannot decode the answer at any layer ([2604.02608](https://arxiv.org/abs/2604.02608)), so a working payload is a direction that *particular downstream circuits* happen to read, not a portable "value". A payload's meaning is set by its reader's Jacobian, and that Jacobian is never recorded with the write.
3. **Linking needs the other write's keys, which neither write carries.** Write A changes the residual at layer L_A. Write B's selector reads keys at L_B produced by layers between them. Whether B fires on A's output depends on J_{L_A→L_B} evaluated at A's output, applied to a_B. That is a cross-term of the two writes; it is not in A's examples or B's examples separately. The 2-hop failure is the visible symptom: the bridge entity is resolved early and the second hop reads early layers ([Hopping Too Late, 2406.12775](https://arxiv.org/abs/2406.12775)), so a late write's payload is never read by the next hop ([2601.04600](https://arxiv.org/abs/2601.04600)). Edits propagate to dependent facts only when the representation already has bilinear relational structure ([2509.21993](https://arxiv.org/abs/2509.21993)).

**So:** current writes carry no interface. The selector is stated in the producer layer's key coordinates, the payload in an unnamed consumer's coordinates, and both are implicit in the fitting examples. Every existing way to compose writes therefore re-derives the interface from data: joint MEMIT over all examples, meta-learned propagation (PropMEND [2506.08920](https://arxiv.org/abs/2506.08920)), redundant multi-layer copies (2601.04600), or ICL distillation of the joint context.

## Raw ideas (unfiltered)

Each: mechanism; why new (closest prior art); cheapest first test; retention check. Repeats checked against [PR #60](https://github.com/manojbajaj95/cl/pull/60) ideas and `reviews/idea-ledger.md` / `reviews/flood-triage.md` on [PR #6](https://github.com/manojbajaj95/cl/pull/6) (notably P17 linker with symbol tables, P19 ABI, P21 weight ISA); where an idea is near one, the difference is named.

1. **Reader-pullback payload.** Define the payload as the minimum-norm vector in the row space of the downstream reader Jacobian J_R (layer L+1 → logits, averaged over generic contexts) that reproduces the trace's logit effect; everything in null(J_R) is declared selector residue and dropped. The payload is then fixed in reader units and has a canonical gauge. **New:** gauge-fixing a payload by its consumer, not by covariance of keys (ROME) or ICL averaging (FV). **First test:** GPT-2 small, 20 nonce facts; plug each pullback payload under a *different* subject's selector; transfer accuracy vs raw trace vector and FV. **Retention:** WikiText KL; wrong-subject leakage.
2. **Answer-addressed payload codebook.** Precompute, once, a payload p_y for every output token y at layer L: the residual direction that most raises y across a large random-context bank (closed-form least squares on forward activations). Any future write is selector × p_y; facts need no payload fitting at all, only a selector. **New:** payloads independent of any fact or trace, amortized over the vocabulary; FV/ICV extract per task. **First test:** for held-out nonce facts with unseen answer tokens, compile selector from 1 trace and payload from the codebook; vs ROME. **Retention:** WikiText KL, top-1 flips on unrelated text.
3. **Payload swap matrix as a separability diagnostic.** For N compiled writes, build the N×N matrix M_ij = success when payload i is delivered by selector j. If payloads and selectors are separable, M is near "payload identity × selector-independent"; its rank-1 residual measures entanglement. A new primitive: a number that says whether a compiler factored a write. **New:** no editing paper measures cross-delivery of payloads. **First test:** 10 ROME writes, 10 LS writes, 10 pullback writes; compare residuals. **Retention:** each write's own efficacy unchanged (sanity).
4. **Multiplicative AND-selectors in SwiGLU units.** Compile atomic selectors once per subject (gate projection) and once per relation (up projection); a fact (S, R → O) is one GLU unit with gate = sel_S, up = sel_R, down = payload O. The product fires only when both hold, directly targeting the parent's wrong-subject-same-wording leakage. Atomic selectors are reused by every later fact. **New:** reuse of pre-compiled atomic selectors combined by the model's own multiplicative gate; ROME/MEMIT use one additive key. **First test:** Qwen2.5-0.5B, 5 subjects × 4 relations nonce grid; compile from 40% of cells, test unseen (S,R) combos and wrong-subject leakage vs ROME. **Retention:** WikiText KL; real facts for the same relations.
5. **ICL-gated selector learning (payload frozen first).** Fix the payload from one trace. Learn the selector from unlabeled prompts by asking the model *with the fact in context* whether the fact is relevant (does the in-context answer change when the fact is removed). The model's ICL is the oracle for where to fire; answers are never needed. **New:** selector labels from context-ablation effects on new prompts, payload untouched; differs from paraphrase augmentation because negatives come free. **First test:** 200 unlabeled prompts per fact; held-out wording and wrong-subject leakage vs LS-on-6-paraphrases. **Retention:** WikiText KL.
6. **Softmax-competing virtual KV writes.** Install each write as a virtual key/value pair inside one attention head's weights (key = selector, value = payload, via a bias-like always-present slot). Writes sharing a head compete through softmax, so conflicting writes resolve by match strength instead of adding. **New:** conflict resolution as the linker; closest is PR #60 idea 31 (trace programs into heads) and GRACE, which do not use softmax competition between writes. **First test:** 2–20 conflicting writes; second-write cost on the first (parent: −8.9 pp) vs ROME. **Retention:** attention KL on unrelated text.
7. **Jacobian key transport (first-order linker).** Given A's exported (payload u_A, layer L_A) and B's exported (selector a_B, layer L_B), compute ā = J_{L_A→L_B}ᵀ a_B on generic text and update B's selector with the transported component so B fires on A's output. Uses only the two exported vectors plus forward/JVP passes on unrelated text. **New:** a closed-form link step; ledger P17 posits symbol tables but no rule for resolving them. **First test:** two-hop nonce chains (A's object is B's subject) in GPT-2 medium; linked vs unlinked vs joint MEMIT. **Retention:** single-hop A and B accuracy, WikiText KL.
8. **Depth transport of a compiled payload.** Instead of re-fitting redundant copies from examples (2601.04600), solve for an early-layer write whose effect at L_A matches u_A (forward-only least squares through the frozen block stack). The payload becomes available to readers that run before L_A, i.e., the next hop. **New:** transport of the payload object only, no examples. **First test:** two-hop accuracy vs redundant editing at equal parameters. **Retention:** specificity drop vs redundant editing.
9. **Wire units.** A link is an explicit new MLP unit between L_A and L_B with input weights = u_A and output = B's key direction k_B; compiled from two exported vectors. **New:** the link is a separate, countable, removable object; parent idea 32 (glue writes) fits glue from joint traces. **First test:** chains of 2 and 3 hops; wire vs glue vs no link. **Retention:** fire rate of wires on WikiText (should be ~0).
10. **Token-embedding ABI.** A writes payload "emit the embedding direction of a reserved rare token σ"; B's selector keys on σ's embedding. Two writes compiled by different sessions link by name, with the model's own circuitry carrying σ forward like any token. **New vs ACE identifiers / P19 ABI:** the symbol is a native token representation the model already propagates, used as the medium between writes rather than a prompt-time ID. **First test:** pairs compiled separately with a shared σ; two-hop success vs unlinked. **Retention:** behavior on text containing σ naturally (leakage).
11. **Closed-form interference forecast from interfaces.** Predict the A/B cross-talk from exported quantities only: (a_Aᵀk_B, a_Bᵀk_A, u_Aᵀ J a_B, u_Aᵀu_B). Forecast before installing; only conflicting pairs get repaired. **New vs PR #60 idea 25 (commutator traces):** no forward traces on the facts' examples; forecast from interfaces. **First test:** 50 writes, AUROC of forecast for >5 pp drop vs key-cosine. **Retention:** efficacy of all 50 after install.
12. **Binding-ID addressed writes.** Use discovered binding-ID vectors (2310.17191) as the selector space: a payload is bound to a binding vector, and a weight-level "binder" maps entity → binding ID. Moving a fact to another entity swaps one binder entry, not the payload. **New vs PR #60 idea 4 (slot-relocatable):** the address space is the model's own binding-ID subspace. **First test:** extract binding IDs on GPT-2 medium entity-attribute tasks; relocate 10 payloads; relocation accuracy vs refitting. **Retention:** old entity-attribute pairs.
13. **Prompted selectors.** Compile the selector from the model's activation on a *description* of the domain ("questions about the capital of Zarnia"), not from examples; payload from the trace. Selectors become writable in text and reusable across payloads. **New:** selector derived from a domain description; CAST conditions are fitted from examples. **First test:** held-out wording and wrong-subject leakage vs LS selector. **Retention:** WikiText KL; prompts that mention the description words in another sense.
14. **Relation payloads as operators; link by matrix product.** Compile a relation override as an LRE-style operator correction (W_r, b_r) at the subject position; a two-hop link is W_{r2}W_{r1} computed algebraically and installed once. **New:** linking by operator composition; LRE (2308.09124) only reads relations. **First test:** GPT-2 medium relations with decent LRE faithfulness; composed operator vs measured two-hop. **Retention:** single-relation faithfulness after install.
15. **Reverse writes for free.** With a bilinear payload⊗selector write, the transpose gives the reverse fact (O → S). Install both from one compile. **New:** 2509.21993 shows bilinear structure helps reversal when trained in; here it is a compile-time transpose on a pretrained model. **First test:** 20 nonce facts; reverse-query accuracy vs ROME + reverse-ROME on a reverse template. **Retention:** WikiText KL, leakage onto other subjects with the object.
16. **SAE features as the link namespace.** Express payloads and selectors in a shared SAE basis; a link exists when A's payload features intersect B's selector features; linking adds missing feature edges. **New:** SAE features as linker symbols (2411.08790 decomposes steering vectors, does not link). **First test:** GPT-2 small public SAE; two-hop success of feature-linked vs unlinked writes. **Retention:** SAE reconstruction loss on WikiText.
17. **DAS-factored write coordinates.** Fit, once, a distributed-alignment rotation that separates a "which entity" variable from a "what attribute" variable at layer L. All future writes target the attribute subspace conditioned on the entity subspace. **New:** a causal-abstraction factorization used as the coordinate system for every write, not just for analysis. **First test:** DAS on 50 entity-attribute facts; new nonce writes in DAS coordinates vs ROME on leakage. **Retention:** WikiText KL, DAS interchange accuracy on old facts.
18. **Layer scheduling as a compiler pass.** Treat writes as instructions with read and write sets; assign layers by topological sort so producers precede consumers, with slack for later links. **New vs PR #60 idea 20 (type check):** placement is solved globally over a set of writes, including writes not yet compiled (reserved slack). **First test:** 3-hop nonce chains; scheduled placement vs causal-trace placement vs redundant editing. **Retention:** single-hop accuracy of each write.
19. **One selector, many payloads (relation multiplexing).** One subject selector carries several payloads, demultiplexed by which relation reader is active (payload set in disjoint reader subspaces). **New vs PR #60 idea 13 (demultiplexer):** demux keyed by the reader identity, not by transient direction. **First test:** 1 subject × 4 nonce relations in one write vs 4 ROME writes at equal bytes. **Retention:** cross-relation leakage.
20. **Payload interning.** Facts with the same answer share one payload vector; only selectors differ. Summed writes then add identical payloads, so cross-firing between same-answer facts is harmless and capacity rises. **New:** deduplication of payloads across writes; MEMIT stores one value per fact. **First test:** 50 facts over 5 answers; interned vs separate at 50 writes; efficacy curve vs #writes. **Retention:** WikiText KL, efficacy of earlier writes.
21. **Online selector refinement from deployment.** After installing, log forward passes on unlabeled traffic where the selector fires; re-run with the fact in context and drop the firing where the in-context answer is unaffected. Selector narrows without re-reading training examples. **New:** deployment traffic as negative evidence for a weight selector. **First test:** simulated stream of 2k prompts; leakage over time vs static LS. **Retention:** efficacy on true-domain prompts.
22. **Curried writes.** Compile (S, R) → O as a subject write producing a handle h_S, and a relation reader mapping (h_S, R) → O. Any later relation for S reuses h_S; any later subject for R reuses the reader. **New:** currying as the factorization rule, so linking reduces to shared handles. **First test:** 5×4 nonce grid compiled from 60% of cells; unseen cells. **Retention:** real facts for those relations.
23. **Cross-model payload transport.** Payloads move between model sizes through a stitching map fitted on generic text; selectors are re-derived locally on the target model. If payloads are portable and selectors are not, that is direct evidence for separation. **New vs PR #60 idea 34 (consensus keys):** transports payloads, not keys. **First test:** GPT-2 small → medium, 20 facts. **Retention:** target model WikiText KL.
24. **Inverse writes as a link check.** Every write ships its exact inverse (−payload under the same selector). Linking is validated by applying B, then A⁻¹: if B still fires on A's output, the link is wrong. A forward-only regression test for links. **New:** inverse writes as a link test, not for unlearning. **First test:** 10 two-hop links; does the inverse test predict which links fail? **Retention:** base behavior after write + inverse (should return to base).

## Ranked deeper sub-questions

1. **Is there a reader-defined gauge that makes payloads identifiable and portable?** (ideas 1, 2, 3, 17, 23) Decisive test: payload swap matrix on held-out selectors; a payload fixed by reader Jacobian, a token codebook, or DAS coordinates must transfer to a new subject's selector, beating FV, ICV and raw trace vectors at equal leakage. Everything below depends on this.
2. **Can atomic selectors be compiled once and combined multiplicatively so a new fact needs no selector fit?** (4, 13, 22) Decisive: on an unseen (subject, relation) grid, GLU AND-selectors cut wrong-subject leakage (+34.7 pp in the parent) to near zero without losing held-out wording, vs ROME, CAST-style conditions and GRACE.
3. **Can a link be computed from exported vectors alone, and how far does the first-order approximation hold across depth?** (7, 8, 9, 10, 18) Decisive: two- and three-hop nonce chains, linked from interfaces only, vs joint MEMIT, PropMEND and redundant editing that see examples; measure link accuracy vs layer gap.
4. **Can relation payloads be operators so that linking is algebra?** (14, 15) Decisive: composed LRE corrections reproduce two-hop and reverse answers on relations where LREs are faithful; report where faithfulness breaks.
5. **Does payload interning or reader-keyed multiplexing raise sequential-write capacity?** (19, 20) Decisive: efficacy vs number of writes against MEMIT batch at equal bytes.
