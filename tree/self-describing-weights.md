# Node: can weights be trained to describe themselves?

Question: can we train a dense model so an editor can read what a weight-space address does, write to it on another checkpoint, and predict what the write will preserve? Parent: [model-guided edits (PR #49)](https://github.com/manojbajaj95/cl/pull/49).

## Root cause

**A weight vector is a coordinate representation of a function, not a stable address book for that function.** For hidden permutations and paired sign flips in our tanh network, both the initialization distribution and the loss are invariant, and gradient descent is equivariant. Nothing in the objective prefers one representative of a function's symmetry orbit; independent trainings need not give corresponding units the same address. Not every functional symmetry is an optimizer symmetry: ordinary Euclidean gradient descent need not be equivariant to non-orthogonal ReLU rescalings.

**A unique structural address still doesn't establish what it means on data.** W-Asym breaks structural permutation symmetry, but neuron-identifiability work finds large approximate equivalence families even in structurally asymmetric models. For an exact example, if layer inputs lie in a proper linear subspace, any perturbation to a weight row orthogonal to that subspace leaves its preactivation unchanged there. Under low-rank or concentrated inputs this ambiguity is exact or approximate, respectively. Key covariance `C` characterizes second-order input coverage; the downstream Jacobian `J` specifies where a local change goes at a given input. Neither the relevant deployment distribution nor its retention scope is specified by a checkpoint alone. One can compute a Jacobian at a chosen input from the model; the weights do not tell you which inputs to choose, or which old behaviors deserve protection.

Existing wins buy legibility by **restricting the substrate** (crisp operators, sparse circuits, explicit fact tables) or **rehearsing a narrow write family** (Edit-Ready Training). In the work below, no dense model demonstrated an address-and-effect map carried in its own weights that stayed calibrated through ordinary continued training. The relevant documentation—basis, distribution, and downstream effect—is typically supplied externally, inferred from current activations, or built into the architecture. A one-off map can go stale as representations or the input mix change. The proposed primitive is a **versioned read/write contract**: given a checkpoint and a declared retention scope, resolve a semantic address, predict the effects of writing there, and report when the prediction is no longer supported.

### CPU probe ([script](probes/self-describing-weights/probe.py), [results](probes/self-describing-weights/results.json))

40 width-32 tanh MLP hosts fit sparse additive teachers; 28 hosts train the readers and writers, and 12 are held out. Two input features are reserved for new lessons. READ is pooled held-out ridge R² for the six original teacher coefficients, using flattened weights only. Each WRITE is the mean paired parameter difference between the base task and a separately trained single-feature variant, fit from the same per-host initialization. The writer applies these fixed deltas to held-out weights without host activations, fitting, or accept/reject search. The sequential check applies feature 0, then feature 1; each delta was learned from unedited hosts. Gain is the output-change projection onto the specified teacher feature (target +1); final gains are relative to the original unedited host. Retention MSE uses fresh old-task inputs where both new features are zero. Ordinary held-out task MSE before editing is measured on unrestricted inputs.

- **Removing a known symmetry helps reading but is not enough to align writes.** In the one-write [initial pilot](https://github.com/manojbajaj95/cl/blob/98472a3/tree/probes/self-describing-weights/results.json), canonicalization raised R² from −0.13 to +0.29, with write gain still +0.03. In the two-reserved-feature rerun above it raises R² from −0.14 to +0.38, with the same +0.03 write gain. Its predictions agree with raw to within `1.0e-15`; canonical weights are identical after an artificial permutation/sign scramble. The sort gives a consistent ordering for an equivalent checkpoint, not consistent meanings across different trained functions.
- **A shared frame helps even without supplied feature directions.** Random frames have the same row norms and penalty as teacher-aligned anchors. Sharing one across hosts gives +0.74 versus effectively zero for independently drawn frames, even though the unshared arm's per-host retrained oracle gains +0.90. Shared random anchors do not match teacher-aligned anchors: their base MSE is about 8× raw, and the first gain falls from +0.740 to +0.693 after the second write. The second write adds +0.764 relative to the first-only host. Teacher-aligned anchors instead improve base MSE by .00609, an advantage expected from a prior that encodes the true basis, not a generic cost saving.
- **Two successful writes aren't retention.** The teacher-aligned gains stay near +1, yet old MSE rises ~4.5× from a small baseline. The shared-random old MSE also rises, from .03907 to .07034. Adding two fixed deltas commutes in parameter space by construction; this test measures behavioral interference, not whether state-dependent edits commute or whether the frame survives SGD. One experiment seed, one shared random draw, one penalty strength, additive teachers, and no baseline-quality matching: the finding supports portability in this toy, not general dense-model legibility or continual retention.

## Prior art

| Work | What it establishes; what it leaves open |
|---|---|
| Lim et al., W-Asym ([2405.20231](https://arxiv.org/abs/2405.20231)) | Fixed weights remove structural permutation symmetry and improve unaligned mode connectivity in tested models. Scale-symmetry removal is not proved for W-Asym; no semantic address or retention contract. |
| Neuron identifiability ([2606.04754](https://arxiv.org/abs/2606.04754)) | Effective function classes depend on input support; approximate equivalence remains even in structurally asymmetric nets. Identifiability helps merging, not necessarily portable interventions. |
| Legible Transformers ([2607.08946](https://arxiv.org/abs/2607.08946)) | Bounded crisp operators give 50–184× more local edits in deep layers. Detection is easier than naming decoded output, and interpretation uses a rotated per-layer frame. |
| WSP Doesn't Need Transformers ([2611.22055](https://arxiv.org/abs/2611.22055)) | LLMs choose sparse fact tables with fixed lookup; roughly one row per answer. An explicit store is legible by construction, not an address map for arbitrary dense computation. |
| Weight-sparse transformers ([2511.13653](https://arxiv.org/abs/2511.13653), [2607.02964](https://arxiv.org/abs/2607.02964)) | Sparse structure aids circuit recovery and parameter-level descriptions; 12–31% of sparse weights received a short verified use description in the latter study. A description of where a weight matters is not a predictive write contract. |
| Edit-Ready Training ([2611.26408](https://arxiv.org/abs/2611.26408)) | Rehearses closed-form classification-head contrast edits. Astra's net score rose 0.46→0.79 on the hard Entity-30 confusion fix; gains were not uniform. The rehearsal doesn't establish a persistent whole-model write interface. |
| WeightCode ([2611.25476](https://arxiv.org/abs/2611.25476)) | Reusable programs install and accumulate capabilities; ported programs retained 83–110% of source gains on average while copying their fixed deltas did little. Strong control: recompile a program per checkpoint versus use a portable address directly. |
| Self-WSP ([2611.28833](https://arxiv.org/abs/2611.28833)) | Large gains from verified self-edits (GSM8K 11.8%→62.2%); equal-budget random search can match them. It does not establish self-knowledge of edit effects. |
| [Weight-Space Reading](https://www.alphaxiv.org/abs/2611.weight-space-reading-language-models.pdf) | 0.730 balanced accuracy predicting direction of subtle edits; readers falsely predicted changes on 53–88% of 40 behaviorally null edits. No conclusive self-reading advantage. |
| Weight Oracles ([2610.07334](https://arxiv.org/abs/2610.07334)) | A trained external reader can simulate small transformers with deterministic helper code and diagnose unseen anomalies. Neither an embedded map nor a general writer. |
| Weights Read and Write Features ([2609.37731](https://arxiv.org/abs/2609.37731)) | Activation-Supported Parameter Decomposition grounds editable weight components in read/write features in a dense pretrained model. A strong external, activation-dependent baseline; does not maintain the decomposition through continued learning. |
| Fast-weight PKM ([2601.00671](https://arxiv.org/abs/2601.00671)) | Sparse product-key slots support rapid episodic writes via local gradient updates; does not name or preserve dense semantic computation. |
| NeuMeta ([2410.11878](https://arxiv.org/abs/2410.11878)) | A hypernetwork learns a continuous weight manifold and generates weights across model sizes. That manifold is not exposed as semantics-preserving, addressable interventions. |
| Permutation-equivariant metanets ([2302.14040](https://arxiv.org/abs/2302.14040)) | An external neural functional learns to process and edit weights without depending on unit order. Invariance/equivariance removes a nuisance but does not impose shared meanings on the hosts. |
| [Weight Space Misfolding](https://www.alphaxiv.org/abs/2611.weight-space-misfolding) | Unauthorized edits can disrupt behavior; legibility making edits easier to audit *or* easier to misuse is a hypothesis, not an established result. |
| [Ledger: Noether memory, W-ISA/WeightCode, gauge preconditioning, functional syndromes](https://github.com/manojbajaj95/cl/blob/fed652d3b609b1e3ac461a21524c6184cfe44065/reviews/idea-ledger.md) | Noether payloads were erased by SGD/momentum or rebalancing; gauge preconditioning reduced to effective LR; learned weight ISA was killed as already done. Functional-syndrome recovery failed because fact damage was diffuse (~19% of damage in the worst 10%), so do not assume sparse functional corruption. |

## Raw ideas (no self-filtering)

These are candidate distinctions from the prior art above, not novelty verdicts. Charge retained bytes (including metadata), update compute, examples, and verification calls to both sides; score retention on held-out old inputs not used to fit the edit or choose a winner.

1. **Executable weight header.** *Mechanism:* reserve checkpoint parameters for per-layer low-rank sketches of `C` and output-facing `J`; train a consistency loss against live activations and edit secants. *New:* ASPD fits an external decomposition; the checkpoint would carry a refreshable effect predictor. *First test:* drift a dense MLP over three lessons and predict unseen rank-one effects, including no-ops, without target-model queries at edit time; apply the best write and score all old lessons. *Control:* same-byte external EMA activation/Jacobian sketch refreshed with the same batches.
2. **Content-blind fixed frame.** *Mechanism:* use one seeded random incoming-weight frame across a model family, with a schedule that eventually relaxes the anchor penalty. *New:* W-Asym removes symmetry; the claim here is that the same delta works across seeds and versions without semantic labels or fresh compilation. *First test:* repeat the CPU probe with >1 frame and a base-loss-matched strength sweep, freeze the editor across a short curriculum, and measure old-task MSE after each write. *Control:* per-host alignment followed by delta transport, using the same parameter observations and editor budget.
3. **ABI-stable continual training.** *Mechanism:* penalize changes in the responses and finite-write effects of previously published addresses, not arbitrary activations or weights. *New:* the thing being distilled is the effect of a future intervention, not the current function or one rehearsed ERT edit. *First test:* publish four MLP addresses, train on two tasks, use the original writer on held-out edit directions, and retest past tasks. *Control:* output and representation distillation using the same old examples and update compute.
4. **Units that write their own names.** *Mechanism:* learn a small per-unit key that predicts both what activates the unit and its downstream effect; train on ablations as well as observations. *New:* activation-grounded features acquire an in-checkpoint identity that can be queried before running a fresh decomposition. *First test:* name/select units in independently trained MLPs for a known concept, edit once, and retest the other concepts. *Control:* equally sized post-hoc activation prototypes regenerated at the same observation cost.
5. **Localization syndromes, not fact recovery.** *Mechanism:* keep parity/block sketches over address-level parameter changes to locate a few changed storage regions, then rerun local contract probes. *New:* the sparsity hypothesis is about a logged edit's parameter support, not about which facts are damaged; dense functional failures can still be detected by probes. *First test:* audit planted block changes, including overlaps and no-ops, then retest all old associations after rejecting or repairing flagged changes. *Control:* same-byte block hashes plus a dense random functional sketch; include dense changes as a failure case.
6. **Edit algebra training.** *Mechanism:* train learned add/delete operators with behavioral commutator, inverse, and locality losses on randomized edit histories. *New:* ERT rehearses single edits; the target here is an algebra on checkpoint states, including operator pairs never rehearsed together. *First test:* apply two state-dependent edits in both orders, then invert one; score both lessons and original tasks after every step. *Control:* same single-edit and pair samples with a matched ERT-style rehearsal loss but no commutator or inverse constraint.
7. **Quine regularizer.** *Mechanism:* learn a short per-layer code from which a shared decoder reconstructs the layer; train the same code to support local writes. *New:* NeuMeta decodes model coordinates; here each deployed layer ships an editable representation of itself with an enforceable round-trip contract. *First test:* train a 3-layer teacher/student pair, round-trip and edit one code, and test original functions before/after decoding. *Control:* same-rate weight autoencoder plus a learned latent editor, trained on the same edits without a contract.
8. **Gauge-orbit metadata.** *Mechanism:* encode checksummed symbols in exactly function-preserving signs, permutations, or rescalings; test whether an optimizer can preserve the symbols without continual rewriting. *New:* the target is an edit address map in a redundant gauge, not Noether's assumption that the optimizer conserves an analog payload. *First test:* measure bit error and prediction invariance through matched SGD, momentum, and a deliberate rebalance, then run an edit and check retention of old behavior. *Control:* a same-bit explicit header and an equal-power non-gauge channel on the same optimizer. Report any updater cost; zero immediate function cost is not zero maintenance cost.
9. **Canonical by gradient.** *Mechanism:* project into a key-ordered gauge after every optimizer step, transporting momentum with the permutation, and measure address swaps. *New:* the optimizer maintains a visible coordinate convention throughout the trajectory rather than aligning finished checkpoints. *First test:* compare address churn, transported-delta success, and original-task loss after a second lesson. *Control:* canonicalize only when editing, using the same ordering rule, with compute matched to the projection arm.
10. **A type system for weight writes.** *Mechanism:* attach learned input-support and output-effect types to blocks; reject or coerce a write whose predicted effect violates the declared contract. *New:* adds a preflight compatibility check over semantics and retention, rather than just a weight instruction set. *First test:* make legal, distribution-mismatched, and no-op writes in a two-domain dense MLP; measure false accepts and old-domain loss after approved writes. *Control:* an equal-byte/compute held-out probe classifier over edit proposals.
11. **The model reads itself.** *Mechanism:* train an introspective head attached to the host to answer questions about edit effects and uncertainty from internal weight summaries, refreshing supervision during normal training. *New:* Weight Oracles is external; self-reading must stay calibrated as its own checkpoints change. *First test:* predict sign or no effect on unfamiliar edits before and after continued training, then check the old-task MSE of edits it approves. *Control:* an equally sized external oracle with exactly the same summaries and update budget.
12. **Write-through-language.** *Mechanism:* bind tokens to stable parameter addresses and compile a sentence into a typed sequence of row writes with explicit scope. *New:* test whether ordinary language can resolve and compose persistent addresses inside a dense computation, not whether an LLM can emit a weight program. *First test:* withheld paraphrases and two-clause corrections in a tiny text transformer; retest original clauses and unrelated text. *Control:* a same-size edit schema parser feeding WeightCode-style per-host compilation at the same call budget.
13. **Nested-dropout addresses.** *Mechanism:* train on prefixes of an ordered unit set, using rank within a prefix as an address intended to survive width changes. *New:* reuse importance ordering for writes across widths, not merely as a pruning or compression schedule. *First test:* learn a delta on width 32, apply it to the corresponding prefix at width 64, and measure old-task MSE. *Control:* matched nested-width training followed by output-probe-based permutation alignment at edit time.
14. **Content-addressable dense FFN.** *Mechanism:* use a frozen hash of self-supervised concepts to choose stable read/write addresses for overlapping FFN rows; surrounding layers remain trainable. *New:* PKM addresses episodic slots; the bet is that the same address can govern dense transformations, not only retrieve a value. *First test:* learn two consecutive concept remaps and then test earlier concepts and hash collisions. *Control:* FwPKM with an identical stored-byte, activated-parameter, and write budget on top of the same backbone.
15. **Holographic editable layers.** *Mechanism:* superpose bound key–value operators in dense weights and unbind from a supplied key to read or delete the corresponding contribution. *New:* vector binding itself is known; the bet is a dense computing layer whose superposed operators remain readable after unrelated learning. *First test:* add/delete associations at several loads, fine-tune on a new mapping, and retest surviving associations and original non-memory behavior. *Control:* same-byte outer-product fast memory with matched local updates.
16. **Differential weight versioning.** *Mechanism:* carry a finite low-rank delta log and learn to rebase it when the dense layer changes, so intervention effects remain attributable to versions. *New:* unlike a seed log or save/restore stack, estimate how an old edit would behave if reapplied or removed on today's base. *First test:* insert two overlapping edits, train on a third task, remove only the first, and retest both remaining lessons and pre-edit tasks. *Control:* same-byte compressed external edit log with the same recompile/rollback budget.
17. **Adversarially robust legibility.** *Mechanism:* a checkpoint records predicted effects of authorized writes and rejects logged-versus-observed discrepancies; audit on benign toy corruptions and valid competing updates. *New:* in-checkpoint effect contracts augment the path-control defenses discussed in Misfolding; neither raw legibility nor a signature measures behavioral damage. *First test:* blind the auditor to harmless/no-op, legitimate, and randomly corrupted toy edits; measure rejection accuracy and old-task loss after accepted changes. *Control:* signed change log plus a matched set of old-task probes under the same verification budget.
18. **Cross-model Rosetta.** *Mechanism:* train several model families to expose a common semantic edit vocabulary, each with a native compiler from that vocabulary to its internal frame. *New:* shared random anchors align equal shapes; this asks whether a single frozen reader and spec survive different widths or activations without per-target examples. *First test:* train on tanh width 32/64, hold out another architecture, and test interpreted addresses, writes, and old-task MSE. *Control:* permutation-equivariant metanet plus per-family adapters with identical train hosts and inference budget.
19. **Address uncertainty and abstention.** *Mechanism:* each address reports a support estimate and the interval of predicted write effects; outside the certified scope, ask for evidence instead of guessing. *New:* separates missing deployment support from uncertain coordinates, and turns reliable no-op recognition into an interface requirement. *First test:* train on low-rank mixtures, shift into unseen directions, and compare abstention at matched coverage with retention MSE of accepted writes. *Control:* an ensemble or conformal editor with identical calibration examples and output bytes.
20. **Self-refresh by counterfactual rewind.** *Mechanism:* briefly fork a virtual address edit during training and use the discrepancy between predicted and observed effects to refresh the checkpoint header. *New:* ongoing synthetic recalibration of a compact map, including no-ops and stale-map detection, rather than behavioral rehearsal of the edited model. *First test:* shift the input mix twice with the writer frozen, use synthetic forks to recalibrate the header, then assess new writes and old-task MSE. *Control:* spend the same virtual-forward budget fitting an external edit predictor using the same sampled forks.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can a dense checkpoint maintain a calibrated header for its own write effects?** This adds a portable object usable by editors, debuggers, and auditors, not just a better edit selector. *First experiment:* train a compact `C/J` plus secant header through three data shifts; freeze the decoder, predict no-ops and actual write effects on an unseen edit family, and compare efficacy at matched retention with an equal-byte external sketch and live-probe oracle.
2. **Can training create an edit algebra that preserves old behavior under composition?** The random-frame arm is already readable and writable, yet loses first-feature gain and old-task retention on the second write. This makes behavioral composition the unfilled primitive, not addition of fixed vectors. *First experiment:* teach add/delete on randomized histories, hold out edit pairs, test both orders and a selective inverse, and score old lessons after each step against equal-cost single-edit rehearsal.
3. **What is the weakest shared frame that survives cross-seed and cross-version writes at matched task quality?** The shared-versus-unshared result establishes why this is worth pursuing, while the shared arm's 8× raw base MSE makes a frozen penalty an inadequate general solution. *First experiment:* sweep shared, unshared, and post-hoc frames with matched base loss, train one writer, then test it without refresh after several ordinary training phases; report both write gains and all past-task losses.
4. **Can an optimizer preserve usable metadata in an exact symmetry orbit?** A genuinely zero-function-cost channel would change how checkpoints store edit metadata, but a rebalance can erase it by construction and the ledger's SGD/momentum kill sets a high bar. *First experiment:* encode a short header in paired signs or permutations, measure bit survival and old-task retention after ordinary SGD, momentum, and gauge normalization, and compare with an equal-bit sidecar including maintenance cost.
