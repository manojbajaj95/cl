# Node: what makes an edit the same edit after the base changes?

Parent: [PR #77 meta-editor](https://github.com/manojbajaj95/cl/pull/77), sub-question 1. Sibling: [PR #76 edit-transfer](https://github.com/manojbajaj95/cl/pull/76).

Question: what can an editor store today that is still an identifiable, executable lesson when tomorrow's model has a different prior, different circuits, or different available writes?

## Root cause

**The parent logs what a write did here, but needs to remember what it was supposed to do elsewhere.** A raw update ΔW is tied to both the parameterization and the current model's response to a write. Even exact function-preserving permutations or rescalings can change the meaning of its numeric entries. A true capability change is harder: the same request can need less work, more work, a different write, or no write at all. The [model-guided edits node](https://github.com/manojbajaj95/cl/pull/49) found that a function-preserving rescale flips raw-weight choosers in its toy MLP; [self-describing weights](https://github.com/manojbajaj95/cl/pull/53) found that canonicalization helped readout but barely helped writing. Shared anchors helped writes in that toy setup, at a cost to base loss and second-write retention. A stable frame is not the same thing as stable edit semantics.

The parent's better candidate, the probe-effect vector `e = J_probe ΔW`, removes the coordinate problem for a matched infinitesimal intervention, but not the **identification** or **execution** problems:

1. **The trace does not identify the intent.** Suppose two writes both change `Paris → France` on every stored prompt. One is supposed to repair a single city lookup; the other is supposed to replace a stale gazetteer for all cities. A finite effect vector can be identical for both. The difference matters as soon as a new base answers an unprobed city differently. Nonzero effects can also be incidental damage, and zero effects can hide obligations the source already satisfied. No number of replays of that same trace recovers the distinction.
2. **The old difference is not the new obligation.** A source move from 0.2 to 0.8 on a correct answer is not a `+0.6` instruction to a target already at 0.9. Conversely, a move with no visible negative effects on the source may break a target's newly shared circuit. Numeric effects should be stored as observations with their base and test scope, not reused as unconditional targets.
3. **An identifiable edit need not be feasible.** Even if its intent is known, the target may have no legal write that achieves it within the allowed budget while preserving unrelated tasks. Source data alone cannot in general predict the target-private update direction (see the cross-lingual result below). A compiler has to inspect the target and sometimes decline. Distinguish **ambiguous** (need a witness), **already satisfied** (no write), and **infeasible under this write budget** (need another substrate or budget); none is a generic failed edit.

This is a structural failure of treating logs as portable labels, not evidence that PR #77's proposed editor was run or that online editing is impossible. The candidate primitive is an **outcome-labelled edit record** with a portable obligation and a separately versioned realization: what must change, what must stay, how to distinguish rival interpretations, and trial evidence scoped to a base, compiler and budget. Keep failures too, but don't teach a later editor that the same obligation is impossible everywhere. The goal is to reuse editing experience while recompiling the native write, not necessarily to transport the source delta or preserve every incidental source behavior.

## Where the bar already is

| Nearest line | What it already buys; what this node still has to show |
|---|---|
| [Fine-tuning Transfer](https://arxiv.org/abs/2503.20110), [GradFix](https://arxiv.org/abs/2510.09658), [Cross-LoRA](https://arxiv.org/abs/2508.05232) | Direct diff transfer works on some release pairs; target-gradient sign masking and data-free subspace alignment strengthen the controls. Use the strongest applicable one when weights are comparable. None of these makes a recorded acceptance label independent of the target. |
| [LoRA Superposition](https://arxiv.org/abs/2610.30691) and [Geometric Bottlenecks of Cross-Lingual KE](https://arxiv.org/abs/2611.10646), as reported in PR #76 | The former's leave-one-backbone-out sum gained only 0.06 pp in its CLIP experiment; the latter isolates a target-private residual for cross-lingual editing. Neither proves a universal impossibility result. Both make native target work an explicit cost, not something to hide in an alignment step. |
| [THESEUS](https://arxiv.org/abs/2602.12952), [ARIADNE](https://arxiv.org/abs/2610.32581), [Universal Activation Bus](https://arxiv.org/abs/2608.09521) | PR #76 already covers transporting activation effects and fitting shared interfaces. A new coordinate system or a portable activation port alone is not the contribution. |
| [Trans-LoRA](https://arxiv.org/abs/2405.17258), [Heirloom](https://arxiv.org/abs/2611.00650), [Text-to-LoRA](https://arxiv.org/abs/2506.06105) | Synthetic-data transfer, distillation, and generating a LoRA from a task description are existing routes. Beat same-byte examples plus a fresh native fit, or buy something they don't give (e.g. a verified distinction between intents). Charge access to the old model and synthetic generation if used. |
| [Task Vector Bases](https://arxiv.org/abs/2502.01015), [Recycling LoRAs](https://arxiv.org/abs/2602.12323) | Compressed arithmetic on task vectors exists. Recycling finds that random adapters can perform similarly to recycled ones in its setting; compare against randomly initialized carriers when claiming reusable edit *content*. |
| [MUSCLE](https://arxiv.org/abs/2407.09435), [RLSEdit](https://arxiv.org/abs/2601.15686), [CaKE](https://arxiv.org/abs/2503.16356), [postEdit](https://arxiv.org/abs/2402.08631) | Negative flips across releases, sequential preservation, multi-hop circuit integration, and black-box response correction already have baselines. Measure old-instance regressions, and don't call a wrapper a native write. |

[Idea ledger and flood triage (PR #6)](https://github.com/manojbajaj95/cl/pull/6): functional syndromes failed because damage was diffuse; sparse structural certificates don't show impossibility; L1 lost to equal-byte stored deltas and hurt retention in its tested form; effect-class distillation beat canonicalized token KL but did not beat execution-reward-only replay. Don't repackage any of these. P17/P19 already cover a linker and stable ABI; PR #76 already has witness sets, objective inversion, universal teaching sets, evidence rather than conclusions, lineage transport, and round-trip checks. The ideas below state what would have to be new, not claims of novelty or results.

## Raw ideas (no pilots)

**Shared paper test design.** Unless noted, use a tiny classifier or fact/relational learner with tractable legal writes and two sequential bases. Separate an exact gauge clone (null test), same-lineage functional drift, and a new seed or width (stress test). Cross these with cases where the target knows the edit already, needs it, or cannot execute it with the specified write budget. No old model at deployment unless its access is charged. Put the same bytes, target queries/gradients and write steps on the budget sheet for same-byte replay + native fit, source delta where compatible, and the parent's fixed probe-effect recompilation; add the relevant control below. Keep held-out old tasks outside compile-time constraints; report instance-level negative flips against the *unedited target* as well as absolute old-task success (which can expose pre-existing drift), at matched new-task attainment. Where a proposal updates the editor itself, also rerun a panel of old edit problems on fresh bases: a base can retain its skills while the editor forgets how to make old kinds of edits. All tests here are proposals, not runs.

1. **An edit comes with its closest rival.** *Mechanism:* store a small set of candidate obligations consistent with the observed edit, and a decision tree of labelled queries that separates them only when the target makes their difference matter. *Why new:* PR #76's minimum witness describes one edit; this record explicitly preserves unresolved alternatives and spends labels on distinguishing them, not reproducing averages (cf. [PR #73 obligation identifiability](https://github.com/manojbajaj95/cl/pull/73)). *First test:* two intents share all source examples; compare target-side scope errors to fixed equal-label teaching sets. *Retention:* old neighbouring lookups, especially ones the wider rival would overwrite.

2. **An edit that preserves a relation, not a number.** *Mechanism:* encode an ordering or conditional equality across paired semantic inputs, normalized to a target-side comparator, instead of source logit differences. *Why new:* unlike the parent's probe vector or PR #76's logit-space common denominator, the object is a predicate unchanged by order-preserving score recalibration, not an update to the scores. *First test:* flip one wrong ordering in two differently calibrated teachers using identical write budgets. *Retention:* untouched rank orderings plus old thresholded decisions, since preserving ranks alone can still break those.

3. **No-op as a positive label.** *Mechanism:* store successful discharges with and without a write as distinct outcomes under the same obligation; train the editor to recognize when nothing should be done. *Why new:* beyond [PR #59's re-derivability memory](https://github.com/manojbajaj95/cl/pull/59), don't delete the record when a base solves it; retain verified non-action as a training example and reuse the obligation if it later resurfaces. *First test:* alternate bases that do and don't know a rule; compare to target-accuracy gating at matched accepted edits and query cost. *Retention:* track wrong negative flips from gratuitous edits and whether earlier edit types are still executed when needed.

4. **A typed refusal with a minimal conflict.** *Mechanism:* emit a small jointly infeasible subset of goal and keep constraints under the target's declared legal write set, not just a reject bit. Recheck the subset after a base change. *Why new:* unlike the ledger's killed structural rank certificates, the certificate is about actual constraints and is transportable as a claim to retest, not a guarantee that refusal survives. *First test:* enumerate rank-one candidates in a finite matrix toy and compare cross-base diagnosis to a generic rejection log and local SVD. *Retention:* measure the old constraints implicated in refusals and disjoint old tasks if a relaxed edit is tried.

5. **Edit applicability by counterfactual switches.** *Mechanism:* carry paired inputs that reflect a semantic intervention (e.g. change a date but not an entity), a hold-fixed condition, and whether the write should follow that switch. *Why new:* compared with the ledger's failed effect-class distillation or CaKE's curated circuit-guided samples, store the intervention boundary as the label, not one class of observed outputs. *First test:* train two rule learners with opposite spurious cues; compare boundary generalization to matched paired-example replay. *Retention:* old rules using the held-fixed feature in a genuinely relevant context.

6. **Bridge-free edit tests.** *Mechanism:* a generator yields equivalent tasks in different input encodings plus a common evaluator; it supplies new witnesses when a version changes format without requiring layer alignment. *Why new:* not a Universal Activation Bus or postEdit wrapper; the invariant is between evaluator outcomes, and successes require native weights to change when called for. *First test:* swap token encodings for a finite grammar and compare to Trans-LoRA-style synthetic replay under the same generation budget. *Retention:* old grammar tasks in both encodings, including unrelated parses.

7. **A keep rule learned from what was already correct.** *Mechanism:* freeze a per-target pre-write snapshot only long enough to form eligible keep instances from a portable task generator; store the generator and eligibility rule, not the old model's responses. *Why new:* MUSCLE measures instance regression; here the retained set is a target-dependent operation, so it can protect capabilities the source didn't have without copying their answers from the source. *First test:* introduce a new target-only skill that shares a feature with the edit and compare to source-locality masks and equal-budget target distillation. *Retention:* held-out instances of the target-only skill and original shared tasks.

8. **Edit identity by substitution in later edits.** *Mechanism:* regard two realizations as equivalent only if they can replace each other before specified follow-up edits without changing reachable outcomes. Store a small set of distinguishing continuations. *Why new:* PR #76's round-trip checks test recovery; substitution tests the fate of a third edit, not the ability to undo the first. *First test:* compile two first writes with equal immediate efficacy but different effects on the reachable second write; compare to one-step effect matching and RLSEdit. *Retention:* old-task scores before and after each continuation, not just the final scores.

9. **Write-skew signatures as portable edit outcomes.** *Mechanism:* record which joint obligations make two individually valid edits fail together, with the triple of interventions used to establish it. Reverify the triple on a new base rather than carrying over an interference scalar. *Why new:* extends SD3 in [PR #58](https://github.com/manojbajaj95/cl/pull/58) from counting write skew to transporting a falsifiable, higher-order interaction record. *First test:* coupled three-rule toy; compare prediction of new-base breakage to pairwise cosine and individual keep tests at equal probe cost. *Retention:* test the endangered old rule after A, after B, and after A+B; include untouched old rules.

10. **An edit with a safe hole.** *Mechanism:* let the record carry a deliberately unspecified region with an explicit do-not-commit rule; only fill it when a semantic discriminator becomes available. *Why new:* unlike generic confidence-gated routing or the fleet paraphrase portability kill, the hole is attached to rival edit scopes, not model entropy. *First test:* present two observationally equivalent worlds until the relevant discriminator arrives; compare to calibrated abstention at matched scope error and coverage. *Retention:* old ambiguous cases default to untouched; check legitimate old behavior in the part of the domain where the write does commit.

11. **Conformance tests that look for inheritance errors.** *Mechanism:* generate adversarial target bases that agree on edit-training outputs but differ on selected latent rules; store the counterexample family that separated good recompilers from bad ones. *Why new:* [PR #62](https://github.com/manojbajaj95/cl/pull/62) already proposed refutation over futures and function-preserving reparameterizations; here counterexamples are functionally different bases used to test the meaning of a specific archived obligation. *First test:* enumerate rival truth tables; compare to random base perturbations and fixed OOD examples. *Retention:* old behaviors shared by every generated base plus the variants' old-only behaviors.

12. **Record the weakest edit that beats its nearest non-edit.** *Mechanism:* store how far a no-write calibration or a simple retrieval step can get, together with a counterexample that forces a native write. *Why new:* turns the ledger's entropy-matched control into an explicit negative witness attached to the record; avoid interpreting arbitrary margin moves as skill. *First test:* design balanced true rule changes and pure temperature changes; compare record-guided recompilation to a fixed effect vector at matched native-write frequency. *Retention:* old calibration and task accuracy, stratified by source margin.

13. **A recipient-side menu of equivalent realizations.** *Mechanism:* archive the obligation and a set of qualitatively different realizations (e.g. change a lookup versus alter downstream integration), each paired with a cheap condition under which it did work. The recipient selects or rejects after checking those conditions. *Why new:* CaKE finds circuit-informed edits, and the model-guided node already lowers site-selection regret; the claim here is that *conditional evidence about alternatives* travels when individual recipes don't. *First test:* swap which circuit is redundant and compare to a random edit menu and a fresh covariance-aware site chooser. *Retention:* probe old tasks that depend on each alternative circuit.

14. **Local proof obligations with replaceable implementations.** *Mechanism:* factor a write into scoped claims about observable intermediate roles (e.g. select a record, then resolve it), allowing different modules to discharge them on each base. *Why new:* rather than P17 symbol relocation or CaKE layer localization, name no module in the portable record; require each role to pass an independently executable test. *First test:* switch from one-hop to factored two-hop implementations and compare to end-to-end training examples plus circuit-guided sample selection. *Retention:* old chains sharing each role individually and old chains crossing both.

15. **Transfer a failure boundary, not a write bound.** *Mechanism:* record which pairs of allowed operations and keep rules made the edit unreachable; use those cases to search the current base where feasibility disagrees, not to predict a numeric capacity. *Why new:* the ledger's edit-capacity law tied a constant; this object is a contrast between feasible sets at the same task and budget, not a global capacity scalar. Unlike idea 4 it records how refusal changes across write sets. *First test:* enumerate a toy ladder of ranks and allowable submodules, and compare search steps to a fixed rank/escalation schedule. *Retention:* measure held-out old-task negative flips at the first feasible step, not overall rank.

16. **Evidence with a duplicate check.** *Mechanism:* represent a correction as a verified evidence item with an identity; apply it to the target's existing support only if that evidence has not already contributed. *Why new:* PR #76 proposes evidence rather than conclusions; the added operation is preventing double-counting when two bases have seen overlapping provenance, not estimating a better universal likelihood ratio. *First test:* tiny Bayesian classifier with partial overlap in evidence sources; compare to an evidence-only update and direct target replay. *Retention:* old calibration and decisions on related classes exposed to the same sources.

17. **An inverse that preserves all later independent edits.** *Mechanism:* define cancellation by withdrawing one named behavioural obligation and asking the target to realize the remaining obligations plus explicit restoration requirements, not by subtracting a delta. *Why new:* Task Vector Bases supports negation, and the ledger's L1 had to beat stored versions; here no historic checkpoint is the required output when later independent obligations were added. *First test:* apply A then B, change base, withdraw A; compare to subtracting A, undo/redo, and refitting B from stored examples at equal budgets. *Retention:* B, old A-related behavior explicitly restored, and unrelated old tasks.

18. **A portable separation test for split versus merged concepts.** *Mechanism:* if a source edit binds two inputs to one concept, keep a witness pair and an answer to whether the correction should follow both when a later base separates them. *Why new:* distinct from the C47/C48 concept differentiation flood: no need to force a concept split, only to preserve the legal interpretation of an edit through one. *First test:* merge two input aliases in a source then give the target a meaningful distinction between them; compare to semantic feature matching and same-byte curated replay. *Retention:* old tasks involving the unedited half and transfer of old edits whose concepts really did remain merged.

19. **Interchangeable witnesses with cross-examination.** *Mechanism:* allow the target to replace an obsolete witness (e.g. a retired API call) only by passing independently generated counterexamples with a common verifier. Log the replacement and its unresolved alternatives. *Why new:* [PR #65](https://github.com/manojbajaj95/cl/pull/65) proposed transferring an experiment and refitting its conclusion; this is a rule for replacing the experiment itself without silently changing the edit's definition. *First test:* two equivalent API migrations and one plausible but semantically narrower migration; compare to direct canonicalization and same-budget execution replay. *Retention:* old common behavior and previously valid edge cases absent from the replacement witness.

20. **Edit records that predict where their own labels stop working.** *Mechanism:* attach a compact applicability test to each past outcome (e.g. conditions under which the successful write had a competing path); revise the test when a later version breaks the prediction. *Why new:* unlike a stale weight header ([PR #69](https://github.com/manojbajaj95/cl/pull/69)) or the edit simulator's effect-domain idea ([PR #63](https://github.com/manojbajaj95/cl/pull/63)), the prediction is about whether an *old lesson for the editor* can be reused, not whether one fixed delta will work. *First test:* with an online editor, compare applicability-labelled replay to recency and target-verified replay at the same label budget. *Retention:* earliest edit types on late bases, as well as base-task negative flips.

21. **A bound on reuse, priced in clarifications.** *Mechanism:* for an edit family, maintain equivalence classes induced by the allowed observations; compute a lower bound on how many additional labelled questions a target needs before it can choose safely. *Why new:* [PR #73](https://github.com/manojbajaj95/cl/pull/73) already proposes keep-bit scaling and non-identifiability witnesses; the increment is pricing how much an archived record reduces clarification relative to having the target alone, across base changes. *First test:* enumerate finite rule families and compare exact query costs to target-only active learning, equal-byte teaching sets, and trivial entropy bounds. *Retention:* count old-task violations among strategies that stop below the bound, and verify old tasks above it.

22. **Learn an editor from same obligation, different realizations.** *Mechanism:* train on pairs of verified native writes for one obligation in different bases, but force the shared part to predict which test would distinguish that obligation from its rival; keep the write heads local. *Why new:* the parent's universal edit prior and Text-to-LoRA predict effects or adapters; here the shared prediction is a falsifier, so a new viable implementation need not look like a previous one. *First test:* withhold one base and one family of ambiguous edits; compare to pooled probe-vector conditioning and random adapter carriers given equal target feedback. *Retention:* old editor problems on withheld bases and held-out old classifier tasks after every accepted write.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can an edit be stored as a set of rival obligations plus a discriminator that runs only when they disagree on the recipient?** Strongest candidate: a record that can carry known ambiguity, resolve it with a new label, and distinguish ambiguity from lack of a legal write. The gate is whether a stored discriminator cuts clarification or false transfers on unseen bases versus equal-budget replay and target-only active learning (1, 4, 10, 21).
2. **What equivalence of edits is closed under later learning?** Immediate effects can agree while follow-up edits and reversions disagree. A finite language of substitution, composition and withdrawal tests would define when two realizations are operationally interchangeable, rather than just similarly shaped updates (8, 9, 17).
3. **Can a record keep the old lesson but require a new proof when the base changes?** Versioned, replaceable witnesses could let an editor reuse evidence without inheriting its old model's calibration or circuit assumptions. Check whether the witness language stays smaller than saving replay examples or re-labelling everything (5, 14, 18, 19).
4. **Can we measure the recipient's obligation-to-write gap separately from its misunderstanding of the obligation?** Separating no-op, missed scope, and constrained infeasibility would turn outcome logs into useful teaching data. It ranks below the others until diagnostic labels improve an editor beyond fresh native optimization and simple gating (3, 12, 15, 20, 22).
