# Universal openers: diagnose one history, give the same write a window on all of them

**Status:** Ideas only; one exact paper fixture, no learner runs or GPU work. **Parent:** [Carried coverage](carried-coverage.md) ([PR #275][parent]), cards **13** and **15**. **Review seed:** [Flood triage, row 392][triage] scores both 3: one useful C batch reveals which hidden alias is present but opens the same later write for every sealed alias; one useful diagnostic step creates a finite learning window that the later editor can miss. The [idea ledger][ledger] requires ordinary old-task retention, matched margins and a win over the strongest stack of the parts. Do not revive dead Gramian forecasts, replay-deadline scheduling or confidence-gated lesson visibility.

**Verdict:** A diagnosis can narrow what the verifier knows, but it must not be what makes the advertised write safe. A universal opener changes the learner so the *unchanged* write works even in the counterfactual aliases that would have produced a different report. The strongest bet is an opening whose remaining lifetime is certified from live shared geometry, not the report, a reservation or a clock-only schedule. Neither robust feasibility nor a finite deadline is new alone. Look first for a strict gain over conformant search, per-alias openers and the best stacked diagnostic plus ordinary training policy before promoting either seed.

## Contract

- **Seal the alternatives before the opener.** A = original tasks, B = installed writes (including defaulter B_d), C = installed and successor work, W = paired service, R_d = the defaulter's receipt. Inherit the parent's lawful state/backing seal, fresh draw, trusted ordinary report, named threat, conditional detection accounting and independent clearing. Freeze the reachable alias set H, useful C menu, serving precision, scheduler, intervention bounds, old floors and later editor interface. Include slots, clocks and legally reachable nuisance states. Fix the later write or its blind selection rule before seeing the opener report; reveal its actual truthful batch only afterward. No audit-only batches, rare labels, slot resets or fabricated gradients.
- **Universal means a common action, not a policy that reads the answer.** For each advertised opener action, take its counterfactual image over the entire sealed H, not just histories compatible with its realized report. For each advertised opportunity the same later batch, optimizer and action parameters must be legal and effective across that image under every covered intervening word. Native updates may differ; the interface cannot pass a target, route, alias tag or choice of hyperparameters. If the report tells the verifier to clear rather than act, keep the cleared and no-result branches in coverage accounting; do not use them to remove incompatible aliases from the opener's test. Separate truthful alias separation, safe-and-effective opening and the rule for spending the opening.
- **Prove a window, not a confident timestamp.** For a proposed number of intervening legal updates, check all eligible prefixes through that number and exhibit an admissible missed-window suffix where the unchanged write no longer works. A lower bound on readiness is not a proof that expiry is inevitable: if expiry is claimed on every suffix, bound it separately. If a word ends the opportunity early, declare it before the seal and route to clearing. Scope the certificate to the declared action and workload; charge monitoring, time, bytes, proof refreshes and any pinned capacity. Expiry confers no authority, and a no-result branch is not detection.
- **Keep old service live.** Measure per-slice floors from acquisition, including common and rare B_d, all A/B/installed C, and actual W by its deadline on every prefix, failed opening, refusal and fallback. After lawful retirement actually reuse R_d's backing and run a blind suffix. Match initial item margins, clocks, C gain, compute, queue access and peak and live byte-ticks. The stacked control gets the same legitimate reports, scheduler and native updates; if it implements the same contract at equal cost, the joint mechanism ties. Mask the report and disable the opened path in separate offline interventions, without adding a new online capability.

## One exact paper fixture: report bins are not write permissions

Take two sealed aliases h = ±1, a carrier g = 0 and a downstream weight x = 0. One due C example has an ordinary two-head loss L = ((h−1)² + (g−1)²)/2. Here h is an immutable input to the report head, not a trainable coordinate or an editor input. The trusted pre-update loss reports 1/2 or 5/2, which remain distinct even when rounded to the nearest integer. Ordinary unit-step SGD on g sets g = 1 in both aliases. The blind later C example has loss (max(g−5/8, 0)·x−1)²/2; its native unit-step SGD at x = 0 leaves g unchanged and moves x by max(g−5/8, 0). Require 1/8 ≤ x ≤ 1/2 for a successful write, with x ≤ 1/2 also the illustrative old-service bound. The numerical threshold is an interface in this fixture, not a real retention measurement.

Between the two batches, allow any number k of due steps on g²/8 with unit-step SGD on g: g is multiplied by 3/4 per step. At k = 0, 1, 2 the unchanged later move is respectively 3/8, 1/8, 0 for both aliases, and remains zero thereafter. Before the opener it is zero. Masking the report does not change these moves. Removing the g movement while leaving the diagnostic read intact yields zero on both branches. For a per-alias contrast, consider a different due example with loss ((h−1)² + (g−h)²)/2. It has the same report bins but sets g = h after SGD. It enables the write for h = +1 only, despite reporting the alias exactly. If that is the sole opener, an oracle can identify when not to spend but cannot make the common write work. Independent clearing must still cover h = −1.

This separates report precision, common readiness and expiry. The factorized diagnostic and training heads deliberately do **not** establish a coupled mechanism or a resource win: a stack that gets the same ordinary batch ties, and a dedicated read plus a different native update may also tie. A real test must show an old reader using the new path after backing reuse; an illustrative interval for x does not establish that.

## A. Open the same write without telling it which history it got

### 01. Certify the pre-report intersection — primitive candidate
**Mechanism.** Compile the intersection of safe-and-effective native write menus over the full opener image of H, including images with incompatible report bins. Expose only actions in that intersection to an independent editor; report bins stay with the verifier. **Novelty vs nearest prior art.** [Compiling Uncertainty Away in Conformant Planning][conformant] already finds common plans; the candidate is a learnable transition that turns an empty common native-write menu into a nonempty one while separately diagnosing the pre-state. This is the reference implementation of parent 13, not novelty on top of it. **Cheapest first test.** Enumerate two-slot SGD menus before and after a due batch; compare the report-masked batch, per-alias openers at equal compute, rare-slice [GEM][gem], [DER replay][der] and a menu with empty intersection after every opener. **Old-task retention check.** Force the same update on both aliases offline and score rare B_d after reuse as well as A/B/C and W on both legal fallbacks.

### 02. Cross the cones before identifying their signs — primitive candidate
**Mechanism.** Let a truthful opener rotate a shared feature so native later gradients from opposite momentum aliases cross into the same old-safe descent cone without coalescing the slots. Certify intersection membership for each realized optimizer delta, not for the nominal gradient alone. **Novelty vs nearest prior art.** [GEM][gem] projects the present gradient against remembered tasks; this uses an earlier native gradient to change the geometry encountered by a later, unprojected gradient. **Cheapest first test.** Search two-dimensional momentum SGD with a shared linear feature and ±m; compare a one-off GEM projection and equal-work feature warm-up, with momentum sign held out of editor inputs. **Old-task retention check.** Check a rare B_d direction opposed to the common slice, including post-update overshoot and post-reuse behavior.

### 03. Open a route by negating a dependency — primitive candidate
**Mechanism.** Make a due step put the two paths of a shared reader into opposite sensitivities to the hidden alias, so their sum stays within the old tolerance when the later editor perturbs either shared input in a declared range. Require sensitivity cancellation at the later write, not equality of opener endpoints. **Novelty vs nearest prior art.** [Learning without Forgetting][lwf] protects old predictions by distillation; the new object is a trainable interval of safe *future* edits earned without old targets. **Cheapest first test.** Use a two-path linear reader with unequal slots and enumerate a grid of blind writes; compare output distillation plus a standalone diagnostic, including an equal-output control with unequal edit sensitivity. **Old-task retention check.** Re-read both old input families after reuse and after both extremes of the admitted write range.

### 04. Route-neutral by permutation, not averaging — primitive candidate
**Mechanism.** Train an ordinary C objective on a symmetric feature pair so each alias may keep a different feature order, but a later permutation-invariant native write updates a common readout without aligning features or seeing the alias. **Novelty vs nearest prior art.** [Deep Sets][sets] supplies permutation invariance; here an opener must create a usable common *optimizer action* while the hidden order remains diagnosable and relevant to other installed readers. **Cheapest first test.** Enumerate swapped two-unit networks under a shared symmetric loss, and compare fixed symmetric architecture, per-alias alignment and the best split stack. **Old-task retention check.** Include an asymmetric old reader that would expose unintended alignment or channel swapping after actual reuse.

### 05. Spend a packet of native gradient directions — primitive candidate
**Mechanism.** Open a set of future write directions indexed only by the truthful downstream input, so a new C editor can choose its own native example after the seal without reopening or receiving a route from the verifier. Certify the set at the level of effective optimizer deltas. **Novelty vs nearest prior art.** [Dataset Distillation by Matching Training Trajectories][mtt] matches a training trajectory with synthetic data; the transfer claim is readiness for a frozen family of independently supplied truthful batches, not one fitted trajectory or hand-picked held-out head. **Cheapest first test.** Freeze a small polygon of admissible input gradients, fit only with two training directions, then enumerate its held-out extremes and find an optimizer where checking only extreme nominal gradients is unsound. Compare normal warm-up and exact menu enumeration. **Old-task retention check.** Exercise every extreme through a normal old-task suffix, including the boundary reader's rare slice.

### 06. Make alias breadth buy rather than consume options — primitive candidate
**Mechanism.** For structured nuisance families, let counter-signed native updates operate on complementary hidden coordinates but land in the same shared feature range. Add a third alias at seal time that defeats the first opener; search for a broader opener without increasing C steps or changing the editor. **Novelty vs nearest prior art.** [Invariant Risk Minimization][irm] seeks a stable predictor across environments; the claim here is that native updates exploit, rather than merely ignore, nuisance-dependent dynamics to obtain a uniform future write. **Cheapest first test.** Enumerate sign triples in bilinear regression and compare ordinary invariant C training and a shared-opening baseline; include a symmetric triple with no common opener. **Old-task retention check.** Test against each sign separately, not their mean, and verify installed C on the no-opener clearing branch.

### 07. Make the surviving option insensitive to report corruption — improvement
**Mechanism.** Prove one native update contract under arbitrary corruption of the diagnostic report, while certifying detection only under the parent's declared precision/noise model. Never grant an authority that still needs a trustworthy diagnosis. **Novelty vs nearest prior art.** [Provably Efficient UCB-type Algorithms For Learning Predictive State Representations][psr] uses observation histories for action selection; this is an operational stress test of the strict report-independent contract, not a better belief estimator. **Cheapest first test.** Substitute every attainable report or a dropped packet in a two-alias branch table; compare report-conditioned routing and a conformant executor without diagnostic access. **Old-task retention check.** Force fallback for bad authority reports while measuring all old floors, and test the already-authorized common write offline under the same corruptions.

### 08. Prove there is no common opener by dual prices — improvement
**Mechanism.** Use a small infeasibility certificate for the intersection of later native-write constraints, with an independent witness for each pre-opener or post-opener exclusion. For a discrete menu enumerate actions; use a separating hyperplane only when the relaxation itself is infeasible. **Novelty vs nearest prior art.** [Conformant compilation][conformant] already resolves universal feasibility; the addition is an interpretable lower bound on the extra work or backing needed to admit the fixed later editor, not a new learning operation. **Cheapest first test.** Build a three-alias affine toy where pairwise intersections are nonempty but the full one is empty; find the smallest lawful additional batch that changes the bound. **Old-task retention check.** Trace the forced independent clearing through W and every old slice; do not relax old floors to make the intersection nonempty.

## B. Make the useful diagnostic buy a finite learning window

### 09. Hand off readiness in legal updates, not elapsed time — primitive candidate
**Mechanism.** After an ordinary diagnostic gradient moves a live shared gate, bound how quickly readiness can decrease under any allowed intervening optimizer transition. Hand off the supported number of legal updates, not an expiration from a wall clock. **Novelty vs nearest prior art.** [Horizon-Dependent Tube MPC][tube] already varies horizon-dependent constraint tubes; the proposed learning operation makes a useful diagnostic step create the tube through which a separate native edit can later land. This is parent 15's reference, not a new claim beyond it. **Cheapest first test.** Enumerate the fixture and a two-reducer extension; compare a permanent #263 card 18 opening, coverage carry without an opening, a fixed gate schedule and a separate opener at equal steps. Try the same editor one step after expiry. **Old-task retention check.** Audit early, latest permitted and expired fallbacks through actual reuse, including independent clearing on the late branch.

### 10. Turn the separating gradient into a decay budget — primitive candidate
**Mechanism.** Seek a head where report separation and opening gain depend on a shared feature slope, so moving that feature with the reported loss both reveals the alias and increases a calculable worst-case budget for later legal interference. Use separation for verification, not as a route or sole proxy for the budget. **Novelty vs nearest prior art.** [FLEX][flex] already chooses informative excitation in nonlinear dynamics; the difference to test is whether the *same native gradient* causally buys uniform retention-safe editability after the informative output. **Cheapest first test.** Couple the fixture heads with one shared scalar, sweep its slope and intervene on the shared gradient while preserving the report; compare separate excitation plus matched C work and equal-report heads without the slope path. **Old-task retention check.** Match starting old margins and score worst-alias B_d at latest useful arrival, not only the head with the larger diagnostic margin.

### 11. Drain the window by the work actually done — primitive candidate
**Mechanism.** Use a live charge bound on cumulative contraction or drift consumed by intervening native batches; certify future opportunity under a remaining budget rather than a count of steps alone. Forbid charging nominally cheap updates that are expensive in an unobserved reachable alias. **Novelty vs nearest prior art.** [Control Barrier Functions: Theory and Applications][barrier] certifies safe sets; this is a disposable bound on efficacy created by a diagnostic gradient, with safety checked independently even after the opportunity is gone. **Cheapest first test.** Compare interleaved large and small SGD steps with identical wall-clock and step count; check whether a live contraction bound beats count-only scheduling, exact recomputation and the best split opener. **Old-task retention check.** Include the high-contraction order that consumes the budget early and execute its safe clearing path on the oldest B_d slice.

### 12. Certify an opening that closes and opens again on schedule — primitive candidate
**Mechanism.** When signed momentum makes editability enter, leave and re-enter a safe-and-effective set, advertise a finite union of guaranteed spend intervals with forbidden gaps, each valid for the identical editor on all aliases. Reject aliases with disjoint re-entry phases. **Novelty vs nearest prior art.** [Signal Temporal Logic Neural Predictive Control][stl] expresses time-indexed safety and recurrence; the candidate is a useful diagnostic that creates synchronized native write opportunities in otherwise unsynchronized optimizer histories. **Cheapest first test.** Enumerate underdamped quadratic SGD on two aliases, comparing a monotone first-window bound, fixed calendar and exact native planner. Hold a C editor arrival in a gap and at re-entry. **Old-task retention check.** Serve A/B/C and W during the gap; verify the late-window write after reuse as well as refusals just outside it.

### 13. Use expiry to return capacity to an incompatible native edit — primitive candidate
**Mechanism.** The opened regime admits an early editor and excludes a second real native write; ordinary gate decay restores admission for the second without undoing the first's learned service. Certify both admissions in advance and lose the first right if it misses. **Novelty vs nearest prior art.** [Signal Temporal Logic Neural Predictive Control][stl] and [rolling escrow](rolling-escrow.md) already express timed sequencing and release; the bet is that useful training dynamics implement release without pinned backup or a scheduled reset. **Cheapest first test.** Two truthful linear tasks with antagonistic update regimes, one expiring common gate and a held-out second arrival. Compare permanent opening plus explicit release, a fixed-time gate and a separate diagnostic plus planner. **Old-task retention check.** Test the first installed C skill and rare B_d after the incompatible write; include missed first arrival with W still served.

### 14. Spend a short window in two pieces without borrowing from the future — primitive candidate
**Mechanism.** Certify two independently useful microbatches of one later C editor as a word, with arbitrary covered interleavings; the first partial write must remain useful and old-safe if expiry prevents the second. **Novelty vs nearest prior art.** [Tube-based MPC][tube] already plans safe prefixes; this is a test of partial consumption of native write capacity that the diagnostic step created, with no speculative partial skill loss or rollback. **Cheapest first test.** Enumerate a two-coordinate regression where one microbatch alone is effective, and a negative host where success depends on the second coordinate. Compare indivisible scheduling, best separate opener and saving/restoring the partial state at equal bytes. **Old-task retention check.** Drop the second microbatch at every allowed cut; the first acquired service and every old floor must persist through clearing.

### 15. Certify that two windows cannot simply be added — improvement
**Mechanism.** Compute composition on actual joint gate and slot trajectories rather than adding published lifetimes from two legal diagnostic steps. Look for a useful second step that cancels the first window before its advertised terminal point; if both steps are in scope, cap the original guarantee accordingly. **Novelty vs nearest prior art.** [Learning-Based Shrinking Disturbance-Invariant Tubes][shrinking] already tracks state-dependent uncertainty; here the output is an audit of compositional claims over native useful writes, not an assumption of additive credit. **Cheapest first test.** Take two native scalar gradients with opposing signs and compare exact word enumeration to min, max and sum of isolated budgets. **Old-task retention check.** Check combined-state old floors and exercise a dropout immediately after cancellation before using or releasing R_d.

## C. Make diagnosis, universality and timing earn their coupling

### 16. Make the same feature explain the report and the later gradient — primitive candidate
**Mechanism.** Require one shared feature path to mediate both diagnostic separation and the extra native gradient reach. Block it with a matched offline intervention, then restore only the report or only the feature. Do not count independent heads as a mechanism. **Novelty vs nearest prior art.** [FLEX][flex] uses actions to explore and reduce model error; parent 18 separates causal effects. The harder hypothesis here is that shared-feature coupling creates a feasible point unavailable to any two head-specific actions at equal budget, even with joint scheduling. **Cheapest first test.** Compare shared versus factorized two-head regressors under the same due batches and all four intervention cells; give the stack the legal shared model and allow it to tie. **Old-task retention check.** Test both rare and common B_d after reuse, including a control where the shared diagnostic increases margin while damaging an unrelated installed C task.

### 17. Randomize the reveal, not the meaning of the right — primitive candidate
**Mechanism.** Select a sealed draw law over ordinary batch types whose post-images admit the same later native action over H, but whose trusted reports catch complementary false claims. Omit nondiagnostic draw types from detection credit, not from worst-branch service. **Novelty vs nearest prior art.** [Conformant planning][conformant] finds common actions and [sealed random checks](sealed-random-checks.md) already average detection over draws. The stronger test is whether one repeatable common write interface can remain identical across draws that need different diagnostic directions without a separate opener. **Cheapest first test.** Two useful draws with disjoint catch masks and identical common write reach; compare a separate randomized audit plus exact common warm-up, and add a cheap draw that preserves the diagnostic but breaks a single alias's route. **Old-task retention check.** Execute the same later editor on both draw images for every alias, then verify W also on timeouts with no detection.

### 18. Admit on worst effect, stop on observed nuisance — primitive candidate
**Mechanism.** Split the public handoff into a report-independent common action guarantee and a verifier-only stop rule. The diagnosis can redirect independent clearing sooner but can never enlarge the certified action or its lifetime. Test whether this avoids holding backing through an otherwise legal idle window. **Novelty vs nearest prior art.** [Control Barrier Functions][barrier] provide safety filters and parent coverage carry separates safety from detection. The incremental claim is a reusable two-channel interface where a stopping decision changes paid backing duration without changing counterfactual editability. **Cheapest first test.** Solve a two-window queue with a detected false claim and a missed claim; compare a common opener with clock-only clearing plus a separately optimized diagnostic stop rule at equal work. **Old-task retention check.** Verify the faster clearing actually serves W and leaves rare B_d usable on diagnosed, undiagnosed and missing-report paths.

### 19. Train for the last common editor, not the best average arrival — primitive candidate
**Mechanism.** Among fixed useful batches with equal current C utility, choose an opener whose terminal guaranteed efficacy is highest across multiple blind editors and lawful intervening words, subject to the same detection floor. Its choice may sacrifice an early peak to preserve a later common direction. **Novelty vs nearest prior art.** [Trajectory matching][mtt] optimizes against particular training paths and [horizon-dependent tube MPC][tube] gives a worst-path baseline; the CL hypothesis is a stronger late gain solely from selecting lawful native diagnostic work, not a fitted gate or synthetic batch. **Cheapest first test.** Enumerate two terminal editors with distinct gradient directions, including a candidate selected by mean arrival that fails the last common slot. Compare exact robust planning and the best stacked early diagnostic plus late warm-up. **Old-task retention check.** Require the worst-arrival write to preserve the weakest old slice and independently clear arrivals beyond the window.

### 20. Compute the price of making one opening universal — improvement
**Mechanism.** Vary the sealed alias class and measure the marginal lawful work or live backing needed to turn a report-conditioned opening into a universal one. Compare a universal editor/frontier to oracle routing as a price benchmark, not as an admissible deployment baseline. **Novelty vs nearest prior art.** [Conformant planning][conformant] already distinguishes knowing the state from planning without it; the addition is a controlled account of when trained universality is worth more than report-based specialization. **Cheapest first test.** Enumerate the full action frontier for two- and three-alias exact hosts at fixed diagnosis and horizon; mark instances where the best ordinary stack ties and ones where adding a single alias rules out any universal opener. **Old-task retention check.** Compare at equal rare/common floors and include the resource and W cost of clearing the hardest unserved alias.

### 21. Close the proof without closing the learned path — primitive candidate
**Mechanism.** At expiry erase the live diagnosis and capability proof using the parent's cut; the spent editor's retained effect must keep serving without restoring either. Reseal on a new episode and require a new opening even if a useful old feature persists. **Novelty vs nearest prior art.** [Learning without Forgetting][lwf] and [verified renewal](verified-renewal.md) protect old behavior or verify record release; the extra test is separating a persistent learned service effect from a short-lived proof of permission to make further writes. **Cheapest first test.** Two paper episodes with overlapping blind arrivals; compare a permanent open gate, fresh exact recomputation and a stored-tag baseline. Let one late editor try to reuse the expired guarantee. **Old-task retention check.** Reuse the oldest R_d backing for real and check both old slices and W after a normal blind suffix, without looking up either episode's diagnosis.

### 22. Require the interaction to pay for a delayed report — improvement
**Mechanism.** Make report time and physical opening time observable separately. Compare learning windows when the ordinary trusted report arrives before the latest safe spend, at the cut and afterward; a late check cannot retroactively authorize the write. **Novelty vs nearest prior art.** [Signal Temporal Logic Neural Predictive Control][stl] already handles timing constraints; this audit discriminates a true coupling from parallel work that completes too late to be usable. **Cheapest first test.** Enumerate all orderings of diagnostic delivery, gate decline, blind editor arrival and W deadline. Compare a faster independent check at equal total work, physical gating only and best fixed scheduling. **Old-task retention check.** Verify the report-late branch's timely independent clearing, and score rare B_d only after a legally spent opener and actual backing reuse.

## Ranked deeper questions

1. **Can useful training create a common native write that neither diagnosis nor a resource-matched warm-up can buy separately?** Start with 01, 02, 05, 16 and 20. Demand the same unchanged write on the full pre-report alias set, independent blind editor selection, and a strict advantage over per-alias/oracle controls, GEM, replay, exact native planning and the strongest feasible stack. If the successful stack uses the same action at the same cost, report the tie.
2. **Can the diagnostic gradient buy a provable, nontrivial duration through ordinary optimizer work?** Start with 09–13. Find a margin-to-duration bound that predicts an intervention on the gradient and an independently supplied schedule, not confidence on the observed alias. A clock-matched fixed gate, permanent opener, and an editor exactly one step late are the quickest disconfirmations.
3. **Which alias and continuation descriptions make universality go from feasible to impossible?** Use 06, 08, 15, 17 and 19 to separate failures of the native batch menu, report precision and horizon robustness. Name zero-detection branches and unserved aliases instead of projecting them out of the proof; test whether clearing is cheaper than widening the opener.
4. **Can a later editor keep the earned capability without keeping the history that authorized it?** Start with 14, 18, 21 and 22. Exercise expired, partially spent and delayed-report branches, then run repeated sealed episodes with actual backing reuse. A route tag, saved report or queue reservation that survives the cut is charged as backing, not counted as learned retention.
