# Edit language: what should compile into a weight change?

Parent: [model-guided edits](https://github.com/manojbajaj95/cl/pull/49). This node is ideation only; no experiments were run.

**Write a relation between the old and new behavior, not a recipe for producing a tensor.** A lesson should name the contexts or trajectories it changes, the observations that must stay equivalent, and what happens when a later lesson overlaps. The compiler should emit a weight patch and evidence for its claim, ask for a distinguishing observation, or explain why the request cannot be met under the declared assumptions.

## Root cause: the source of an edit is incomplete

The parent found that on a four-hidden-layer toy MLP, replacing a min-norm rank-one operator with a covariance-aware one cut random-layer regret from **16.71 to 0.38 utility points**; a function-preserving rescale moved the weight-only chooser on all five seeds. This argues for treating placement as a backend choice **in that setting**, not for assuming all layers are interchangeable on LLMs or for arbitrary edits. The next question is what information the better backend still cannot infer.

1. **Intent is not identified by successes.** “Route this fragile parcel to inspection” fits a fragile-goods rule, a special rule for this sender, or a rule about one destination. Those intentions agree on the example and disagree on future parcels. No choice of layer, optimizer, or verifier that sees only the original example can decide which untouched behaviors count as retention. “Preserve the rest” is not an implementation of a scope predicate.
2. **Specified intent may not be realizable in the given host.** At an edited linear layer, let the columns of `K_R` be protected activation keys and those of `K_A` be target keys. Exact preservation there and a requested displacement `D` ask for `ΔW K_R = 0` and `ΔW K_A = D`. For any `a` with `K_A a` in the column span of `K_R`, necessarily `D a = 0`. If a target key equals a protected key but their required displacements disagree, no patch to that layer works. If the same obstruction holds at every allowed single site, choosing a different single site does not help. This is an obstruction for that backend, not proof that the edit is semantically contradictory or impossible elsewhere. For output-level constraints, a local analogue uses the target Jacobian restricted to the null space of the protected-output Jacobian; requesting change along a weakly controllable output direction can force a large local update, where linearization may cease to be useful.
3. **Retention is a law of the sequence, not a one-edit score.** Two edits can pass every single-edit test yet jointly break a claim: e.g., one patch sends parcels to a newly reachable inspection queue, the next changes queue priority, and neither was checked on fragile parcels in that queue. In an agent, the edited policy changes its own evaluation distribution by visiting different states. An unchanged output on old logged prefixes does not establish that an earlier task still succeeds. Pairwise order, explicit supersession, and old and new reachable states belong in the semantics.

These are separate failures: **ambiguous source**, **incompatible clauses or insufficient backend capacity**, and **invalid composition/insufficient coverage**. They call for different responses: ask an intent question, request a changed clause or backend, or retain an obligation and test it where the new system can reach it. Lack of evidence or solver timeout is not impossibility.

### What current approaches already do

Literature checked via alphaXiv and arXiv, 2026-11-24. The gap below is about the interfaces these papers demonstrate, not a claim that none of their methods could serve as a backend.

| Approach | What it already handles | What remains to be written or decided |
|---|---|---|
| [WeightCode](https://arxiv.org/abs/2611.25476), closest | An LLM authors executable programs that inspect trained weights and install a new computation from a grammar, demonstrations, or examples. Programs re-run on independently trained ViTs; separately authored second writes retain a first noise-robustness gain while adding contrast robustness. | The executable program specifies **how** to operate on the host. The clean/old-task check is supplied for the task; the demonstrated two-stage installs are not a source-language law for arbitrary overlap, precedence, or failure. Reusing a Python patch or getting two additive capabilities is already done. |
| [Tracr](https://arxiv.org/abs/2301.05062) and [WSP replication](https://arxiv.org/abs/2611.21449) | Construct networks from symbolic programs, or have a frontier model implement new toy programs as weights. | Construction starts with a program for the function. Editing a pretrained system also needs a relation to its partially unknown old function, including what the program must leave alone. |
| [Program-as-Weights](https://arxiv.org/abs/2607.02512), [Compile by Training](https://arxiv.org/abs/2609.04199), [Text-to-LoRA](https://arxiv.org/abs/2506.06105) | Text can already produce adapters; fuzzy functions can already be stored and composed, including by generating teacher examples and training a reusable local adapter. | Function composition or predicting an adapter is not the same as reconciling *changes to a shared host* with inherited promises on their overlap. A text front end and a generated adapter are not new primitives by themselves. |
| [Adaptation compilation](https://arxiv.org/abs/2609.37371) | Predicts acquisition, transfer, boundedness, and preservation for candidate update programs and selects before adaptation. | The compilation target is an adaptation recipe selected by predicted metrics. The source here would define observations whose relation to the previous system must hold, including interaction with other source clauses and when to refuse. |
| [ROME](https://arxiv.org/abs/2202.05262), [MEMIT](https://arxiv.org/abs/2210.07229), [AlphaEdit](https://arxiv.org/abs/2410.02355), [MEND](https://arxiv.org/abs/2110.11309) | Analytic rank-one and multi-association writes, preservation by projecting away from protected keys, and a trained editor that transforms gradients from examples. | They give ways to satisfy a supplied target and reduce interference. AlphaEdit's null-space guarantee is conditioned on the preserved activations represented by its key space; it does not identify which future inputs are in the source-level frame. An editor cannot recover missing intent from a gradient. |
| [Self-WSP](https://arxiv.org/abs/2611.28833) and [WSP writes ICL](https://arxiv.org/abs/2611.26841) | Learn through test-filtered edits or turn demonstrations into interventions keyed to prompt activations. Self-WSP reports some comparable random-search results; the ICL study reports weak generalization to wording changes despite usually stable perplexity. | Passing a test split does not define what other wordings, old lessons, or future histories must preserve. The outer check is not a semantics for the update. |
| [SERAC](https://arxiv.org/abs/2206.06520), [RippleEdits](https://arxiv.org/abs/2307.12976), [MQuAKE](https://arxiv.org/abs/2305.14795), [the limits of parameter editing](https://arxiv.org/abs/2606.00570) | Learn an edit's scope at inference time, audit logical and multi-hop consequences, and show retrieval can beat parametric editing under substantial interference. | Scope detection and ripple tests are useful references and strong controls. They do not give a weight compiler a specification of *which* ripples are intended, which are forbidden, and which need an answer before writing. |

### One concrete starting language

```text
edit E17 against W0:
  scope     parcel.fragile && hub == H
  require   P(inspect before dispatch | scope) >= 0.95
  frame     on !scope: couple terminal actions to W0 with mismatch <= 0.01
  inherit   E09: never dispatch an unscanned parcel
  resolve   E17 may replace E04.priority only inside scope
  evidence  use finite hub simulator; check both policies' reachable prefixes
  backend   weight patch only; rank <= 4; no runtime checker
```

The language is **relational and versioned**: a clause denotes a set of acceptable pairs of old and new systems under its observer, scope, and evidence assumptions. A later write must meet still-active clauses against their named references, not just the latest checkpoint; otherwise small stepwise deviations can silently accumulate. A coupling is a specified joint comparison of stochastic behaviors, not merely matching their averages. The example is illustrative; the simulator, observations, reference coupling, and scope must be defined before certification. Different inventions below could replace this syntax entirely.

A minimal compilation contract is `compile(spec, host, evidence, budget) → patch + scoped claim | question + separating cases | conflict/limit + witness | unknown`. An interpreter that applies the spec directly is a reference oracle, not the deployed artifact. A compiler can use WSP, constrained optimization, synthesis, or gradients; it wins if source semantics predict behavior on held-out combinations where an equally budgeted baseline fails, not because it avoids gradients. Exact claims apply only under stated proof assumptions; statistical claims need held-out risk and coverage estimates.

## Raw ideas

Unranked hypotheses, not novelty verdicts. The [ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md) and [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md) already cover a weight ISA, linker/ABI, generic effect types and certified contracts, transporting deltas, exact undo, and compiling observations or traces. Conflict cores, lenses, and coupled trajectories also have precedents outside CL. The claims below hinge on what each source object would let a continual learner do, not on inventing those underlying tools.

The cheapest tests are future proposals. For all of them, separate compile and evaluation cases by factors or histories, not shuffled examples. Check acquisition on held-out intended effects, and retention both on the fixed pre-edit invariant cohort and on **nonsuperseded** earlier lessons after each write. Keep replaced targets in a separate revision cohort. Match evidence, compiler calls, persisted bytes, and patch budget; compare to covariance-aware editing at a fixed or random site, supervised adaptation with retention when applicable, and a direct interpreter/retriever when it can implement the same intent. A toy result only licenses the mechanism, not scale.

### A. Make the compiler understand what it does not know

1. **Two denotations and a question.** **Mechanism:** maintain source-level interpretations consistent with demonstrations; find an input on which two plausible interpretations demand opposite changes and ask for its intended effect. **New angle:** the question is about intended scope, not uncertainty about a weight address or an optimizer's forecast. **First test + retention:** fit fragile/sender/destination rules that alias on two examples in a parcel table; give editors one equal-cost label query. Score scope accuracy and preservation on unseen non-fragile parcels and the previous delivery rule versus uncertainty sampling from one learned editor.
2. **Editable conflict cores.** **Mechanism:** return a minimal set of *named source clauses* with no common behavioral solution, along with incomparable repairs the author may choose. Keep backend failures separate. **New angle:** a rejection can name an earlier promise that must be retracted, not just report that a verified edit failed; the repair edits the language, not the model. **First test + retention:** create three overlapping threshold rules in a finite classifier, with planted minimal conflicts and feasible-but-rank-limited controls. Compare reported cores to exhaustive truth, then resolve one clause and verify every non-retracted old rule on hidden combinations.
3. **Alias witnesses for the backend.** **Mechanism:** expose a target/protected pair, or linear combination, with identical accessible features but incompatible requested effects; return the smallest additional observable tested to break the alias. **New angle:** operators can share a semantic diagnostic that distinguishes “cannot see the distinction” from “must change your intent”; unlike the ledger's sparse-write graph certificates, the witness uses measured features or exact finite behavior. **First test + retention:** plant an alias in a frozen two-layer encoder; compare a witness-guided one-bit feature addition to a same-size random feature and a bigger-rank patch. Check new target accuracy, protected twins and previous edits after recompiling.
4. **Retention currencies with explicit exchange bans.** **Mechanism:** declare separate, nonfungible tolerances for cohorts or observables, and compile against a feasible vector rather than a single weighted loss. On failure, return the incompatible budget face, not a tuned trade-off. **New angle:** the source can forbid compensating a rare regression with a common gain; the compiler exposes which coexistence guarantee costs capacity. **First test + retention:** edit a linear classifier with one rare protected region and one abundant region; compare Pareto feasibility and acquired accuracy to tuned weighted losses at equal rank, reporting worst-cohort and historical retention separately.
5. **Open-world holes.** **Mechanism:** distinguish explicit exceptions from unanswered scope (three values: change, preserve, unsigned); on an unsigned case, compilation must agree with the old behavior for every retained interpretation or abstain from installing that portion. A later answer replaces just the hole. **New angle:** an incrementally authored edit carries unfinished semantic decisions, not deferred weight hypotheses. **First test + retention:** leave a novel class of parcels unsigned, then reveal exceptions in opposite orders. Compare to retraining from positive/negative examples; check old outputs on still-unsigned cases and unaffected earlier rules.

### B. Make the delta, not the host, express a law

6. **Transformation rules for the delta.** **Mechanism:** define how the change must transform under renaming, rotation, or reversal, without requiring those symmetries of the base function. Compile a generating set into constrained weights; check unseen transformations. **New angle:** equivariance of the *difference* preserves useful asymmetries of the old host; it is not model equivariance or transport of a delta between hosts. **First test + retention:** add a direction-dependent correction to a biased grid classifier; hold out whole rotations and check the original directional bias and old obstacle rule outside the correction region.
7. **Behavioral lenses.** **Mechanism:** give each lesson a `get` view and a `put` operation over policy behavior; synthesize the complement that a put must not modify. Require get-after-put, no-op for a redundant put, and replacement in the same view. **New angle:** lens laws make one editable behavioral view with a preserved complement, stronger than idempotence or invertible learning operators alone. **First test + retention:** set and unset delivery cutoff in a toy dispatcher while independently editing zone prices. Compare to constrained fine-tuning on alternate cutoff values; check restored cutoff behavior, unrelated prices, and old zone boundaries after each operation.
8. **Nonlocal edit identities.** **Mechanism:** specify identities of the *delta*, such as “raise the rush premium by one, but opposite changes to other items must keep every valid basket's total fixed.” Lower the relation to a null-space basis over outputs, not a new set of absolute labels. **New angle:** global conservation determines acceptable ripple effects without providing labels for the affected cases; the old composition-contract idea targets identities of the function itself. **First test + retention:** use an affine pricing model with withheld baskets and underdetermined compensations; compare to same-budget generated labels and check basket conservation plus frozen standalone prices.
9. **Move probability mass by name.** **Mechanism:** specify a sparse transport plan from old actions to new actions: e.g., convert one third of deferrals to inspections, with approvals untouched. Compile against a reference joint distribution, not just new action frequencies. **New angle:** policies with identical new marginals can rewrite different old decisions; a directional flow matrix makes them distinguishable and composes by its own rules. **First test + retention:** expose common random draws on a three-action policy and test whether only the requested flow changes on unseen draws. Compare to marginal KL plus target-rate matching; check approvals and earlier conditional rules.
10. **Retention by conditional independence.** **Mechanism:** change one decision factor while preserving the conditional distribution of a separate factor (e.g., change when to inspect while preserving the distribution of inspection stations given reason and region). **New angle:** the frame is a conditional law, not examplewise unchanged logits or unconditional accuracy; even intentionally changed outputs can satisfy it. **First test + retention:** use a factorized categorical policy under a held-out region mix; check requested dispatch changes and station-distribution drift conditional on region, plus retention on a previous reason class. Compare to marginal and pointwise KL constraints.

### C. Specify trajectories, not just prompts

11. **Path-specific edits.** **Mechanism:** target a causal path defined in a known environment model: a revised caution rule may affect route through hazard estimates but not through sender identity. Compile using paired edge interventions, including counterfactuals where the two mediators disagree. **New angle:** the edge names an allowed *effect of an edit* on a measured process, not a rank-one address per causal edge or a trace containing the edit's implementation. **First test + retention:** construct two observationally tied toy policies with different mediator paths. Compile against a few distinguishing interventions and check path effects plus old route choices on the forbidden path and no-shift missions.
12. **Reachability frames.** **Mechanism:** compile against a relation between old and new reachable states, allowing a detour but requiring a known old behavior once the policies reach matched states. Synthesize the relation alongside the patch. **New angle:** retention can be invariant to trajectory realignment and still catch an old promise broken only by a new state; a static regression suite cannot define that comparison. **First test + retention:** teach a grid agent a detour that enters a previously unreachable queue; exhaustively check old terminal behaviors and matched-state decisions, plus the new detour. Compare to distillation on old rollouts and equally sampled new rollouts.
13. **Edit the route, preserve the occupancy.** **Mechanism:** allow new paths while specifying what must stay unchanged about long-run resource usage, e.g., station occupancy per parcel type. Compile occupancy flow constraints into a stationary policy, then into weights. **New angle:** users can declare retention on a deployment distribution generated by the edited agent, instead of preserving the host's next action at fixed states. **First test + retention:** change short-path preference in a tiny ergodic Markov chain with identical-return policies. Check new route frequency and exact stationary occupancies after a second edit, plus previous rare-terminal success, against a return- and logit-matched policy update.
14. **Temporal write with an observation barrier.** **Mechanism:** require prefix equivalence until a named observation disambiguates the rule; compile the pending mode into the policy's recurrent state and forbid dependence on the unseen future. **New angle:** the lesson specifies the earliest allowed behavioral divergence; it is not a timestamped weight patch or a trace used as training data. **First test + retention:** use paired POMDP histories sharing a prefix whose regimes require opposite choices after a cue. Check pre-cue action distributions and success on old cue-free episodes plus acquisition after the cue. Compare to trajectory distillation and a hand-written monitor.
15. **Consumable permissions.** **Mechanism:** a lesson grants a behavior exactly once per episode or per typed resource; compile the resource accounting into state transitions expressible by fixed-size recurrent weights. **New angle:** the unit of an edit is a right with use semantics; logit suppression, gating, and stateless guard checks cannot enforce conservation across reordered trajectories. **First test + retention:** grant one extra handoff in a toy workflow and test repeated requests at unseen positions. Check ordinary handoffs and a prior independent permission remain unchanged; compare to per-turn supervision and an equal-state reference automaton.

### D. Make overlap and later edits first-class

16. **Patch precedence by intersection only.** **Mechanism:** attach an explicit override to an overlap of two semantic scopes; compile the priority rule there while leaving each rule's exclusive region intact. Disallow implicit last-write-wins. **New angle:** precedence is resolved over behavioral regions, not over adapter order, version order, or a CRDT's tensor merge. **First test + retention:** overlap three guards in a miniature router; recompile declarations in all orders with one priority fixed. Score agreed overlap plus earlier behavior in every exclusive cell, including held-out examples near boundaries.
17. **Future-edit quantifiers.** **Mechanism:** a lesson can grant an extension point and quantify over every future addition of a specified kind, e.g., “new parcel categories may refine cost, never change how a fragile parcel is routed.” Reject a backend that cannot support the declared family, even if the immediate edit works. **New angle:** the source denotes guarantees about future legal learner states, not a checkpoint ABI or a scalar plasticity reserve. **First test + retention:** enumerate later class splits in a symbolic linear router and test an unseen one; compare to ordinary per-edit constraints, checking protected routing after every allowed extension and rejection of a forbidden one.
18. **The update law is the lesson.** **Mechanism:** instead of writing today's answer, write how an answer should change when a named evidence channel changes. Compile a fixed-size neural state update that can consume later observations without consulting the author. **New angle:** the patch installs the semantics of a particular class of future revisions, not a new optimizer globally or a learned register ISA. **First test + retention:** teach a toy inventory policy to interpret counted corrections as cumulative for one product line and replacements for another. Hold out event orders; check both revised policies and earlier unaffected stock rules after every event.
19. **Supersession with a negative space.** **Mechanism:** retraction of a source rule specifies what must cease to follow *because of it*, while independent reasons for the same behavior stay live. Maintain derivations for the source clauses and compile the surviving consequence relation. **New angle:** this is reason-selective retraction despite overdetermination, not undoing a tensor diff or exact removal of training examples. **First test + retention:** plant two independent reasons for approval and one unique consequence of each, then revoke one reason. Check common outcomes remain, unique outcomes disappear, and old unrelated rules retain against rollback and matched-data unlearning.
20. **Rewrite the frame itself.** **Mechanism:** an edit can change the equivalence relation used for retention, with both an old and a new observer during a named transition. Require a commuting diagram from old observations into the deliberately coarsened new observations. **New angle:** the preserved observable is a revisable source object; neither cross-version weight transport nor finer label preservation alone can express this change. **First test + retention:** merge two delivery service labels, preserve cost and routing in the quotient, and add a new label within the merged class later. Test old tasks under the declared coarsening and retain unchanged service distinctions, against relabel/retrain and same-budget distillation.

### E. Learn or compute the source objects

21. **Minimal teaching basis of an edit family.** **Mechanism:** recover a finite family of distinct desired edit operators, then solve for the smallest set of old/new queries that distinguishes every pair. Use that set as a lesson alphabet; make non-separation detectable. **New angle:** compression targets intent identifiability, not reconstruction of lessons or weight diffs. **First test + retention:** build a family of routing rules, assign the teacher the same bit budget for a distinguishing basis or random examples, and check novel edits, out-of-family rejection, and historical/unaffected traffic.
22. **Inverse compilation of the source frame.** **Mechanism:** infer the weakly stated retention relation a user applies to paired before/after outputs, not the edit or its explanation. Propose a frame on which different users' accept/reject judgments can be separated. **New angle:** learns what fixed means (e.g., ranking vs score vs action) independently of the weight change; not edit decompilation. **First test + retention:** train on judge labels that alternately care about rank and calibrated probability; infer the observer for an unseen lesson. Compile equal-size patches and test both that inferred invariant and earlier unrelated invariants on unseen inputs.
23. **Worst-case edit under interpretation ambiguity.** **Mechanism:** all consistent intent interpretations define an uncertainty set; compile the largest useful change in their behavioral intersection and expose the residual as an unresolved decision. **New angle:** partial compilation has a denotation even with unresolved intent; unlike a question-only system, it delivers a monotone fragment without assuming a winning interpretation. **First test + retention:** use interval scopes with hidden endpoints; compare useful immediate writes to either abstaining or fitting the most likely scope. Check no leakage outside the intersection and old rules after successive clarifications.
24. **Resource-normalized obstruction frontier.** **Mechanism:** derive a lower bound or constructive witness for the least permitted rank, precision, or state needed to satisfy source clauses. Represent the claim in behavior coordinates so rescaling weights does not alter it. **New angle:** the edit has a measurable implementability boundary as a function of its promises, not a predictor of how many sequential edits a model survives. **First test + retention:** solve rank-constrained tabular linear edits with planted ranks and one quantization boundary. Compare analytic bounds and emitted patches to exhaustive search; check exact retention on protected keys and hidden linear combinations at and below the claimed budget.
25. **Proof by alternate compilation.** **Mechanism:** ask independent backends to implement the same spec; seek disagreements after checking each backend, and classify them as an unsigned case, a compiler bug under the spec, or sensitivity of a claimed bound. Use finite enumeration as ground truth where possible. **New angle:** disagreement audits the *source specification*, not just post-edit behavior; success means fewer unintentional legal divergences after the author answers, not merely finding regressions. **First test + retention:** compile underspecified rules to exact tables, low-rank weights, and a distilled model. Compare disagreement-directed questions to random probes, then recompile and test acquisition, original frames, and two historical lessons on held-out cross-scope cases.

## Deeper sub-questions, ranked by chance of yielding a new primitive

1. **What is the smallest observational language that identifies an intended change and its frame?** A *teaching interface for edits* would be reusable across models, compilers, and agents. Look for edits with identical examples that become distinguishable with one scope-, observer-, or counterfactual query; report how many bits are actually needed. Ideas 1, 5, 21–23, 25.
2. **Can retention survive composition as an algebra on behavioral observations, rather than on weights?** A composable frame or lens would give later learners something actionable to inherit, including explicit local supersession. Require the same nonconflicting result across equivalent declarations and find the smallest counterexample when the law fails. Ideas 7, 16, 17, 19, 20.
3. **Can a compiler produce actionable, gauge-invariant witnesses of what cannot be written?** An abstraction barrier is useful only if it can distinguish bad intent, hidden feature aliasing, and the cost of realizing a feasible change. Seek a dual certificate or exact counterexample that predicts the minimal intervention the author must make. Ideas 2–4, 24.
4. **What should “unchanged” mean when an edit changes the states an agent visits?** A first-class relation between trajectories, not a testcase set, could transfer to policy editing, monitoring, and CL. Start with two policies that agree on every archived prefix but disagree on a protected behavior after entering a new state. Ideas 9–15.
5. **Can a lesson write a future learning law, not a present answer?** A compiler for bounded update laws would install recurring revision without another edit call. The hard discriminator is generalization to unseen evidence order with finite state and protection of unrelated old lessons, not just runtime rule execution. Ideas 15, 17, 18.
