# Can a learned port expose an edit-indexed inverse certificate that composes around a loop without enumerating candidate writes?

Tree path: [agent harness (PR #47)](https://github.com/manojbajaj95/cl/pull/47/files) → [discrete backprop through a learned tool loop (PR #52)](https://github.com/manojbajaj95/cl/pull/52/files) → **obligation inverse certificates** (depth 3). Ideation only: no experiments were run for this node.

## Terms (from the parent)

- **Port**: the write interface of a component (table cell, prompt unit, adapter or weight block) plus its inputs, outputs and effects.
- **Edit index e**: the persistent write (address and change). The same e acts at every call of the port, on every loop iteration and branch.
- **Obligation**: a predicate on (state, e) that must hold for success; pulled back through edited transitions, B_{k+1}(s,e) = B_k(F_e(s), e).
- **Repair set**: all e that satisfy the obligation and the protected (old-skill) predicates. The parent found that a failure yields a repair set, not a write address, and that retention anchors, not the backward pass, made the safe write identifiable.
- **Inverse certificate**: a compact, independently checkable object that maps an obligation to (a sound description of) its repair set, without listing candidate writes.

## Root cause

**Every current approach has only two of three properties: learned (amortized), set-valued, and closed under composition with a shared edit variable. The loop requires all three at once.** Around a loop the same e appears in every unrolled copy of the port, so the backward step is not function composition (what backprop and lenses give) but an *intersection* of preimages over copies that share one variable. A learned inverse that returns one point cannot represent that intersection. A certificate that checks one candidate has to be given the candidates. An exact symbolic preimage is set-valued and intersects correctly, but it is not learned and its cost grows with unrolling.

Two structural obstacles follow, and any new primitive has to remove them:

1. **Disjunction.** Repair sets are unions (an upstream fix *or* a downstream compensation). A regression-trained inverse averages the branches and lands outside every one of them.
2. **Shared-variable intersection.** The copies of e across loop iterations must be intersected, so the certificate representation has to be closed under (a) pullback through one port and (b) intersection, and it has to reach a fixed point in a bounded number of iterations. Boxes, polytopes, BDDs and automata have these closures but are not learned. Neural sets (classifiers, embeddings) are learned but have no closure.

**Disconfirmation baseline for every card.** A shared repair variable plus bounded model checking, SMT or CEGIS on the same white-box loop, and equal-cost forward replay over the candidate menu, both given the same retention anchors. A certificate earns the name only if it matches their repair-set recall and old-task retention with fewer verifier or model calls *and* is reused across obligations or loop lengths it was not built for.

## Raw ideas (unfiltered)

Default testbed: the parent's three width-six tables (retrieve → plan → act) with retries, where all 90 one-cell edits plus no-op can be enumerated for ground truth. The enumeration is used only to *score* a certificate, never to build one. Retention check (always): success on the 20 ordered distinct-symbol old pairs that are not used by the selector, and the separate anchor set is never used for evaluation.

1. **Box-embedding edit sets.** *Mechanism:* each port learns a map obligation → axis-aligned box in a learned edit-coordinate space. Intersection is exact (box ∩ box), and loop composition is iterated pullback plus intersection until the box stops shrinking. *Why new:* box embeddings exist for knowledge-graph entailment, not as edit-space preimages. They give learned sets with exact closure under intersection. *First test:* recall of true repair edits inside the box versus box volume, on held-out fault sites; retention = old-pair success for an edit sampled from the box.
2. **Product-of-experts edit energies.** *Mechanism:* port exposes E(e | obligation); a loop's certificate is the sum of the energies of the unrolled copies (an intersection in probability); repairs are sampled by Langevin or Gibbs sampling over e, never enumerated. *Why new:* compositional EBMs have been used for images, not for persistent writes shared across a trace. *First test:* top-1 sampled edit success versus replay at equal call budgets; retention as above.
3. **Tropical certificates for piecewise-linear ports.** *Mechanism:* for ReLU/max ports, the edit-to-output map is tropical-rational, so the repair set is a tropical-polyhedral region. Compose certificates by tropical composition, and close the loop by a Kleene star in the max-plus semiring. *Why new:* tropical geometry has been used to analyze networks, not to invert edits around feedback. *First test:* a 2-layer ReLU port in a retry loop: exact region size versus SMT, in calls; retention on old inputs.
4. **Sketched affine certificate for linear memory.** *Mechanism:* in a linear associative memory, obligations and protections are affine in ΔW. Each loop copy adds rows; a learned sketch (a running Schur complement) keeps an O(r²) certificate whose size does not grow with loop length. *Why new:* MEMIT solves one batch closed-form; nobody keeps a composable, loop-length-independent summary of the admissible ΔW set. *First test:* GPT-2-small layer-subset edits as a toy loop (edited fact re-read k times); sketch-feasible edits versus the full stacked solve; retention on CounterFact neighborhood prompts.
5. **Contracting certificate operator (DEQ on certificates).** *Mechanism:* learn a backward operator T on certificate space and train it to be contractive (spectral-norm bound), so the loop certificate is fix(T), found by iteration with a uniqueness guarantee. *Why new:* deep equilibrium models solve for fixed points of states, never of preimage sets. *First test:* loops with 1 to 6 retries; error of fix(T) versus exact repair set when trained only on ≤3 retries; retention.
6. **Hypernetwork-amortized CEGIS.** *Mechanism:* a hypernetwork maps an obligation to a classifier over edits. A verifier returns counterexample edits, which are folded back into training, so the hypernetwork amortizes CEGIS across obligations. *Why new:* CEGIS restarts per spec; here the per-obligation inverse is learned once and reused. *First test:* verifier calls per solved obligation over a stream of 50 obligations (it should fall); retention on old pairs for accepted edits.
7. **Fourier repair-set algebra.** *Mechanism:* encode edits as bit vectors. The certificate is the low-degree Fourier spectrum of the repair-set indicator; intersection of shared copies is multiplication of indicators (convolution of spectra), truncated back to low degree. *Why new:* analysis of Boolean functions applied to edit sets, with a learnable truncation. *First test:* recall at degree 2 and 3 on the 90-cell space; retention.
8. **Attention-as-membership certificate.** *Mechanism:* port holds learned edit keys; an obligation query attends over them; membership = attention weight; loop composition = elementwise product of attention maps across copies, renormalized. *Why new:* uses a forward pass to return a soft repair set, not a single edit. *First test:* precision@k of attended edits versus replay@k; retention.
9. **Certificates that carry their splitting query.** *Mechanism:* the certificate returns the set plus the cheapest observation (anchor) that would halve it. Composition propagates both, so the loop emits one question instead of many replays. *Why new:* fuses version-space inversion with active anchor design, the parent's observed bottleneck. *First test:* number of anchors queried to reach a unique safe write versus random anchors and the parent's fixed five anchors; retention.
10. **Hyperdimensional edit superposition.** *Mechanism:* bind each edit's address and value into a hypervector; a certificate is a superposition; intersection is thresholded elementwise product; loop iteration i is a permutation binding. *Why new:* uses VSA as a composable set algebra over writes. *First test:* capacity (set size before recall < 90%); retention.
11. **Closed-loop implicit ellipsoid.** *Mechanism:* the admissible set is approximated by {Δ: Jᵀ_loop Δ ≥ margin, Δᵀ H_old Δ ≤ budget}, where J_loop = (I − ∂F/∂s)⁻¹ ∂F/∂e is the implicit closed-loop Jacobian of the shared edit (no unrolling). *Why new:* EWC/Fisher ellipsoids ignore the loop; implicit-function credit ignores the protection set. This joins them into one certificate. *First test:* a soft-table version of the parent loop; feasibility of edits sampled in the ellipsoid; retention measured on held-out old pairs, not on H_old's data.
12. **Composable diffusion over edits.** *Mechanism:* a conditional diffusion model over LoRA or cell edits; each port contributes a score conditioned on its obligation, and the loop sums the scores (compositional diffusion ≈ intersection). *Why new:* weight diffusion generates checkpoints; nobody composes per-port obligation scores into a repair-set sampler. *First test:* success of 8 samples versus 8 replays; retention.
13. **Edit-invertible ports.** *Mechanism:* architect the port so the edit → behavior map is a bijection on a chart (invertible residual in parameter space), making preimages exact by construction. The loop becomes a fixed-point solve in behavior coordinates. *Why new:* invertible networks invert inputs; this inverts *writes*. *First test:* expressivity cost (base task loss) versus exactness of inversion; retention of old pairs after an inverted write.
14. **Set-valued loopy belief propagation on the trace.** *Mechanism:* factor graph with e as a shared variable node tied to every call site; messages are learned compressed sets; the certificate is the BP fixed point. *Why new:* treats a persistent write as a variable in message passing over the computation trace. *First test:* marginal recall of true repairs; convergence iterations versus loop length; retention.
15. **Conformal inverse sets.** *Mechanism:* calibrate a learned edit scorer to output an edit set with coverage ≥ 1−α for the true repair; compose across loop copies with a union bound or a joint calibration. *Why new:* conformal prediction over writes, giving an explicit soundness statement that checkers can audit. *First test:* empirical coverage and set size at α = 0.1 on held-out faults; retention for edits chosen from the set.
16. **Gauge-quotiented certificates.** *Mechanism:* define certificates on edits modulo function-preserving symmetries (permutation, rescale), so composition does not double-count equivalent writes. *Why new:* the model-guided-edits node found raw choosers gauge-dependent; a certificate on the quotient removes that. *First test:* certificate stability under random rescaling; retention.
17. **Amortized dual certificates.** *Mechanism:* the certificate is the vector of Lagrange multipliers over obligation and protection constraints; a network predicts the duals; the loop sums dual-weighted constraints over copies; the admissible set is the argmin face. *Why new:* learning-to-optimize predicts primal solutions; here the dual is the reusable object and the protection duals are explicit retention prices. *First test:* duality gap of predicted duals on new obligations; retention.
18. **Retention receipts stacked over time.** *Mechanism:* every committed write stores the certificate it discharged; a later write must lie in the intersection of all stored receipts. The "loop" is the task sequence. *Why new:* GPM/OGD store linear subspaces; this is the nonlinear, obligation-indexed generalization, and conflict detection is just an empty intersection. *First test:* 10-task stream on the table world; forgetting versus GPM-style projection and replay at equal memory.
19. **Learned widening for edit summaries.** *Mechanism:* borrow interprocedural dataflow summaries (IFDS): a port's certificate is a summary relation from exit obligation to entry obligation, parameterized by e. Unbounded retries are handled by a learned widening operator that guarantees termination. *Why new:* widening is hand-designed in abstract interpretation; learning it for edit domains is new. *First test:* loops with unbounded retries; soundness rate of the widened summaries; retention.
20. **Edit-sheaf obstruction.** *Mechanism:* local certificates on ports are glued into a global section; a nonzero first cohomology means no safe single write exists (a proof of a missing write direction). *Why new:* the flood's sheaf idea was over lesson stores; this is over edit sets, and it produces the parent's "failed inverse" library automatically. *First test:* detection of planted unrepairable faults versus SMT unsat; retention not applicable (write is refused), so measure false refusals.
21. **LLM-emitted automaton certificates.** *Mechanism:* for prompt-unit ports, an LLM maps a failure trace to a regular expression or grammar over admissible prompt edits; loop composition is automaton intersection, which is exact. *Why new:* the LLM writes a set description, not a candidate, and symbolic closure does the composition. *First test:* the harness world with Qwen2.5-1.5B; fraction of intersection-sampled edits that pass versus TextGrad-style single proposals at equal calls; retention on old tasks.
22. **Length-generalizing distilled inverses.** *Mechanism:* get exact repair sets from SMT on loops of ≤3 iterations, distill them into a neural set model, and test it on 6 to 10 iterations. *Why new:* the claim is length generalization of inverses (no solver at test time). *First test:* recall and verifier-call savings at length 8; retention.
23. **Koopman-lifted edits.** *Mechanism:* lift port dynamics so the edit enters linearly in a Koopman space; the loop is a matrix power, and the repair set is a linear preimage in the lifted space. *Why new:* Koopman methods target states, not parameter edits shared over iterations. *First test:* smooth control-loop toy with a parameter edit; preimage accuracy versus unrolled gradient search; retention on old setpoints.
24. **Monotone ports with interval certificates.** *Mechanism:* constrain each port to be monotone in a lattice order on edits. Repair sets are then intervals, composition of monotone maps preserves intervals, and the loop fixed point exists by Tarski. The certificate is two endpoints computed by two passes. *Why new:* "editability by monotonicity" as a design constraint for learned modules. *First test:* cost of monotonicity in base accuracy; exactness of the interval; retention.
25. **Certificate falsification markets.** *Mechanism:* multiple learned inverse ports propose certificates, and a falsifier earns reward for finding an edit in the set that breaks an old skill or the obligation. Certificates that survive are cached and reused. *Why new:* unlike the parent's counterexample channel, it prices soundness per certificate, so reuse is gated by survival. *First test:* reuse rate and post-reuse failure rate over a 50-obligation stream; retention.
26. **Edit-indexed tokens in the KV cache.** *Mechanism:* an LLM agent writes into a reserved KV slot; the model is trained to emit, alongside the output, a "certificate token" whose embedding predicts which slot writes would flip the outcome. Loops reuse the slot, so tokens across turns are intersected by product. *Why new:* a self-reported inverse at inference time, without gradient computation. *First test:* AUC of the predicted flip set versus true slot ablations; retention on old prompts.

## Deeper sub-questions (ranked by how likely they lead to a new primitive)

1. **Is there a learned edit-set representation closed under port pullback and shared-variable intersection, with size independent of loop length?** This is the core algebra (cards 1, 4, 5, 7, 24). If one exists with sound outer approximation, it is a new update primitive: a learned "preimage type". If none exists, the obstruction itself is a result.
2. **Can ports be built so that their inverse is cheap by construction (monotone, edit-invertible, affine in a lift), and what does that cost in expressivity?** Weight-space programming made writes direct by choosing the representation. This asks the same for inverses (cards 13, 23, 24).
3. **When the certificate fixed point is not unique, what minimal observation restores uniqueness, and can the certificate emit that query itself?** This continues the parent's finding that anchors, not the backward pass, bought localization (cards 9, 15, 20).
4. **Do certificates distilled from exact solvers on short loops generalize to longer loops and new obligations at lower verifier cost than SMT or bounded model checking?** This is the amortization claim the parent could not show (cards 6, 22, 25).
5. **Can certificates stack across a task stream so that retention is enforced as an intersection of stored receipts, as a nonlinear generalization of GPM?** This is the bridge from loops within a task to continual learning across tasks (cards 17, 18).
