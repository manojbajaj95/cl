# Redundant skill populations: what must survive when individual copies can forget?

Parent: [PR #115, Breadth outside edit theory](https://github.com/manojbajaj95/cl/pull/115), card 12 and deeper question 3.

**Node question.** A fleet has one shared trunk and `n` agents with bounded private writable state. A newly learned skill is assigned to only `r` agents; the rest are free to forget it. Can the fleet keep serving old skills through later learning, outages, and handoffs without paying to keep every skill in every model? What, besides replication and routing, would make this a new continual-learning primitive?

## Root cause: holder count is not recoverable behavior

The parent is right that forgetting need not be measured per model. Its card 12, however, calls “put it on `r` agents and route to a holder” an erasure code. That's replication, and the proposed comparison against everyone learning everything cannot tell a benefit of *selective writes* from a benefit of *redundancy*. More importantly, a storage replica owns its copy of the bytes; a skill holder does not own the trunk features it needs. The common trunk and selector can remove the same capability from every nominal holder in one update, even with all private states frozen. And “route to a holder” presupposes both that one still works and that the router can find one on a task-unlabeled request. The parent's NumPy experiments cover vocabulary, widening, and deployment traffic, not fleets. There is no observed population result to explain yet.

Two counterexamples isolate the gaps. Write the old inputs as `x=(u,v)` with independent fair signs and the target as `u`. The trunk exposes `z=u` and each of `r` frozen holders predicts `sign(z)`. A legal new-task write changes the shared representation to `z=v` to learn target `v`. Now each old holder gets 50%, including the one chosen by an oracle. No number of heads seeing only `v` can beat chance on `u`; even allowing a raw-input router does not help **if its only allowed action is to select among these identical outputs**. Hold the trunk fixed and the old skill survives, but this one-coordinate host cannot then learn `v` at the head; a second coordinate or an old-version path can solve it, at a cost to count. Conversely, with the trunk fixed and mutually disagreeing experts, an overwritten selector can send every old query to the wrong expert while oracle routing stays perfect. This second failure does not require representation loss.

For independent known holder outages of probability `p`, the all-outage probability is `p^r`. With a trunk event of probability `q` that makes every holder fall below the old accuracy floor, and conditional independent outages of probability `p` outside that event, the probability that no qualifying holder can be called is at least `q + (1−q)p^r`. Routing can fail even outside those events. With no trunk writes, perfect task IDs and isolated private slots, that extra shared failure vanishes and the engineering baseline may already win. Count *functions reachable by a legal read under specified updates*, not placement slots. A proposed repair cannot reconstruct distinctions that the surviving observations have erased; a byte snapshot and a behavioral witness are different resources.

## Common first-test protocol

- Start with a CPU stream of 32 small synthetic skills, eight agents, and fixed-size private heads or bottleneck adapters on one small trunk. Fit each skill to a common minimum initial accuracy before counting it. Include (i) task IDs for a storage-only diagnostic, (ii) learnable but overlapping task cues with no IDs at inference, and (iii) an indistinguishable-input negative control with incompatible targets, where no routing rule should solve both without extra context. Use paired stream seeds, and hold out skill inputs, update orders, and trunk shifts rather than only probing the install stream. Separate frozen-trunk, local-write, shared-write, and coupled trunk/router-write arms. Inject private outages independently in one arm and common feature or version failures in another; never tune on the held-out failure trace.
- Compare fixed `r=1`, random and interference-aware `r=2`, and all-agent assignment; a single shared-trunk adapter bank with the same slots; single-model replay at the same byte budget; SEED-style one-expert updates and learned MoE routing; FedAvg and soups on compatible states (not on arbitrarily permuted heads). Add exact checkpoint/restore, fixed-trunk adapters, and coded adapter bytes wherever applicable. An equally budgeted central bank with the same inputs, update interleavings, and read access **can simulate the fleet**. A claim of irreducible population benefit has to name a real constraint (e.g. no shared mutable state, independent local update/access domains or a deadline), enforce it for both arms, and price the synchronization or extra bytes needed to emulate it.
- Match total stored bytes (including optimizer state, old trunks, router, anchors, teacher signals and metadata), training examples and update FLOPs, and billed inference/repair calls or a tail-latency cap. If these can't all be matched, report a Pareto curve, not a victory at equal per-agent width. Count every abstention, timeout or unroutable request as a failure in served accuracy. Log isolated-holder scores, hindsight-oracle score (diagnostic, never served accuracy), actual served accuracy and mean/worst old-task drop on fixed held-out data, with new-task gain at equal steps. For repair, report pre-damage, immediately post-damage, and after repair **and one further update**. Expose per-task tails and failure overlap; control for install margin and accuracy rather than equating diversity with survival.

## Raw ideas

These are proposals, not novelty verdicts. Each test is CPU-sized and inherits the common controls above; the extra control names the most direct way that card could tie.

### A. Learn which writes a population can afford

1. **Survivor-set update rule.** **Mechanism:** protect the best remaining *feasible set* of witnesses rather than regularizing every holder: take a new-task gradient subject to every allowed deletion in a small failure family leaving a passing old read. The protected witness can change after each step. **Why it might be new:** GEM protects individual loss constraints; here the feasible region is a set-dependent union of constraints, and feasibility can be passed between agents. **Cheapest first test:** enumerate deletion sets for three linear heads; compare to static quorum, SEED and GEM with dynamic worst-loss weighting at equal probe cost. **Old-task retention check:** worst old loss after the previously selected witness disappears, along with new loss at matched retention.
2. **Train for different failure directions, not different predictions.** **Mechanism:** give agreeing holders different response signs to anticipated legal trunk updates, using paired gradients as a training target; a step that hurts one should spare another. **Why it might be new:** PBT and the killed fleet bagging card vary trajectories or outputs; this targets the joint *derivative of retention* under a shared write and requires the same initial predictions. **Cheapest first test:** fit three linear adapters to equal margins, tune response covariance on train shifts, compare random placements and activation-orthogonal experts on held-out nonlinear trunk steps. **Old-task retention check:** simultaneous failure rate and routed old accuracy at equal marginal holder accuracy, including two-step shifts.
3. **Handoff as a differentiable write.** **Mechanism:** when admitting a new skill, train its gradient to leave a displaced old skill cheap to transfer from its current holder into a spare slot. Differentiate through one budgeted handoff step, not through the donor's old loss alone. **Why it might be new:** FedWeIT selects knowledge to transfer, but the proposed object is the change in *another* learner's handoff cost caused by a write. **Cheapest first test:** two-step unrolling on three small heads with rotating full slots; compare ordinary distillation and first-order transfer-gradient matching. **Old-task retention check:** remove the donor and score old requests at handoff time and after the next admission.
4. **Use a slot's previous occupant as an interference control.** **Mechanism:** choose among equally good placements by learning an inexpensive predictor of whether the new gradient will overwrite the previous occupant's still-useful features or make them reusable for its remaining holders. Train on swap counterfactuals, not task labels. **Why it might be new:** SEED selects by class-distribution similarity; the proposal predicts *cross-holder* gain from deliberate eviction, not expert fit or lesson popularity. **Cheapest first test:** exhaustively swap occupants of four tiny adapters and compare prediction against similarity and direct cheap trial writes. **Old-task retention check:** measure net old-task losses including evicted and causally affected skills, not just the recipient.
5. **Trunk writes that barter live feature directions.** **Mechanism:** learn a coupled step where one trunk feature becomes available for new learning only after its dependent old tasks get alternative private feature directions from the same update. **Why it might be new:** EWC or a backward-compatible ABI constrains old representations; this operation swaps which paths implement a trusted skill and frees a trunk direction, rather than preserving all paths. **Cheapest first test:** a three-feature linear bottleneck, with exact constrained optimization versus freeze, expansion and alternating refit. **Old-task retention check:** remove the vacated feature, check each old obligation on held-out inputs, and re-test after another trunk update.
6. **Leave behind an executable inverse for only the victims.** **Mechanism:** optimize each shared update to admit a small input-conditioned correction on the agents it would break, with corrections expiring once the old skill migrates. **Why it might be new:** BCT and the parent ABI conserve interfaces; this instead trades persistent private “undo” bytes for particular shared steps and still requires a measurable advantage over retaining an old trunk. **Cheapest first test:** train low-rank corrections for two MLP trunk steps versus residual adapters, full backfill and a compressed previous version. **Old-task retention check:** verify both corrected old service and the other holders' old scores after correction expiration and next update.

### B. Repair behavior, not serialized weights

7. **Functional repair escrow.** **Mechanism:** train a small auxiliary head *at admission time* to make a fresh agent repair a skill using only its outputs on shared unlabeled queries plus a few answers from surviving specialists. Optimize the escrow for update-and-repair loss, not teacher fit at admission. **Why it might be new:** regenerating codes repair symbols and coded inference repairs predictions; this repairs a writable learner under future trunk versions. PR #113's label escrow, saved adapters, and standard distillation are hard nulls. **Cheapest first test:** teacher MLP skills on shared inputs; delete one adapter and shift the trunk; compare equal-byte labels, quantized adapter, teacher logits and meta-trained escrow. **Old-task retention check:** repair previously unseen skills and keep them after an unseen next write; measure failure on other old skills too.
8. **Exchange behavioral constraints rather than whole teachers.** **Mechanism:** discover which inequalities over public inputs each survivor can still certify and train a replacement under their intersection. No survivor need know the full skill; contradictions are abstentions unless adjudicated by budgeted evidence. **Why it might be new:** ensemble CL usually combines complete predictors; PR #86's parity cross-exam gives a close witness precedent, but here partial constraints must build a usable new holder after heterogeneous forgetting. **Cheapest first test:** regress piecewise monotone functions using incomplete constraints versus pooling survivor logits and coded checkpoints. **Old-task retention check:** serve both the incomplete regions and held-out regions after the repair, counting contradictions as failures.
9. **Repair an agent from its upstream and downstream neighbors.** **Mechanism:** on compositional jobs teach a missing intermediate module from live predecessor/successor behavior, with deliberately trained interventions making two otherwise equivalent internal implementations distinguishable. **Why it might be new:** ordinary composition contracts were killed because atomic outputs generate labels for free; here the missing atom cannot label anything, and the claim is that interventions select a repair that works with unseen neighboring modules. **Cheapest first test:** tiny chains of learned permutations with one deleted stage; compare to end-to-end imitation on exactly the same interventions, plus saved mid-layer bytes. **Old-task retention check:** score held-out chains, individual stage tests when available, and behavior after a neighboring stage is replaced.
10. **Train the parity, then let the operands drift.** **Mechanism:** allow an auxiliary reader to change its reference alignment using only unlabeled traffic so that a jointly trained relation between independently plastic specialists remains useful after one disappears. **Why it might be new:** static parity is already covered and coded fragments are killed; only correction through independently learned drift, with no serializable common coordinates or hidden labels, is a claim. **Cheapest first test:** XOR or output sums as a sanity check, then nonlinear specialists with independent feature drift; compare exact byte coding and fixed parity with equal alignment FLOPs. **Old-task retention check:** leave one expert out on new inputs after multiple shifts and test a rebuilt holder after an additional write.
11. **Failure-time prompts as a transfer language.** **Mechanism:** train private adapters to respond to a small common vocabulary of learned synthetic queries with outputs suitable for repairing other adapters; optimize for transferred skill rather than information about donor temperature. **Why it might be new:** unlike H1/H1b lesson voting, the questions are an interface for writing a replacement, and must beat dataset distillation on the same queries. **Cheapest first test:** meta-train a 16-query set on some synthetic skills and transfer unseen skills to a changed trunk with and without query learning. **Old-task retention check:** compare both repair slope and delayed served accuracy with direct targets, raw-logit distillation and entropy-matched responses.
12. **Repair sets with incompatible donors.** **Mechanism:** choose a repair set whose members share enough behavior to identify the target, but differ enough under known shifts to avoid giving the same erroneous repair signal; explicitly seek counterexamples to agreement. **Why it might be new:** vote diversity and dependence-aware truth discovery are known; the bet is that diversity of *repair gradients* predicts replacement quality when votes agree, not a new trust score. **Cheapest first test:** degree-limited repair from five heads with controlled same-vote/different-gradient cases, against equal-cost leave-one-out donor testing and stacked reliability controls. **Old-task retention check:** remove the originals; evaluate replaced skills and other tasks after shared trunk writes.

### C. Read and compose skills without privileged task identity

13. **Exchange witnesses across stages of a job.** **Mechanism:** each old end-to-end skill has a small set of tested cross-agent execution paths; admit a stage write only if some complete path still passes, and learn new compatible paths from cross-boundary failures. **Why it might be new:** bi-level MoE routes within one pass; the proposed invariant is *whole path survival* through local writes even when every stage still has a healthy marginal replica. Ordinary service-chain redundancy is a strong engineering null. **Cheapest first test:** route two-stage maps with independently changing intermediate representations; compare per-stage routing and direct end-to-end test-and-reroute. **Old-task retention check:** score fixed old end-to-end jobs and worst-case single holder withdrawal, not just atomic stage accuracy.
14. **A read that asks the disagreement-resolving question.** **Mechanism:** learn a cheap interaction with the environment or caller to recover missing task context *exactly where later updates caused routing ambiguity*, and let the response select a live holder. **Why it might be new:** active classification is known; the candidate CL signal is change in witness coverage per additional observation, rather than uncertainty or margin (ledger's margin-routing kill). **Cheapest first test:** two nearly indistinguishable old jobs with several optional binary observations; compare active information gain and direct router retraining at equal calls. **Old-task retention check:** blind served old accuracy, failures where no observation can disambiguate, and query burden before and after late writes.
15. **Reassign addresses by overlapping competence.** **Mechanism:** move a skill between agents only through a small shared input region where both are competent; use it to train routing outside that region without reopening the old label set. **Why it might be new:** redirect tables were enough for stale IDs in the ledger; this tests task-unlabeled inputs with no persistent address and a bounded compatibility region. PASs-MoE is a close alternative. **Cheapest first test:** a drifting selector over two overlapping synthetic distributions versus router logit distillation and a direct probe-trained selector. **Old-task retention check:** old queries far from the handoff region and incorrect cross-routing of non-target skills after handoff.
16. **Make fallback behavior non-competing.** **Mechanism:** a rare old specialist can reject a request and hand off with a structured diagnostic saying where its input no longer fits, rather than adding its logit to a joint vote. Train that diagnostic on future simulated churn. **Why it might be new:** cascades and abstention are known; whether a previously transferred rejection diagnostic survives changes in the receiving agents, unlike a calibrated scalar, is the primitive candidate. **Cheapest first test:** small multi-expert classifier with rotating holders; compare calibrated rejection, two-pass MoE and same-size direct routing features. **Old-task retention check:** rare old held-out requests, false acceptance costs, and inference tail latency after both head and router updates.
17. **Quorum over sub-outcomes, not over whole answers.** **Mechanism:** for long jobs train holders with differently placed competence boundaries; after one fails, stitch locally verified sub-outcomes under an explicit compatibility test to avoid resetting the job. **Why it might be new:** ensemble voting and coded inference cannot directly recover a partially completed trajectory; ordinary checkpointing and skill composition can, so a gain must come from learned continuation across previously incompatible internal states. **Cheapest first test:** short finite-state paths with partial observations, fixed handoff budget, and independently learned policies; compare shared checkpoints and a robust single policy. **Old-task retention check:** old completion and constraint violations on fixed initial states with failure injected mid-trajectory.
18. **Compete for unlabelled routing only where there are no backup witnesses.** **Mechanism:** allocate incoming router updates to resolve examples most likely to lose *their last accessible competent path*, even if router confidence is high; estimate competence by reserved silent evaluations. **Why it might be new:** prioritization alone is an improvement; a local write coupled to an independently shifting set of rescue reads could yield a different training signal from loss, entropy or expert load. **Cheapest first test:** replay a fixed mix of rare- and common-task queries with equal label/probe budget; compare entropy sampling, direct routing-error replay and known-ID routing. **Old-task retention check:** post-update rare-task availability including wrong-but-confident routing and equal held-out oracle performance.

### D. Change the operating constraints, not just the ensemble size

19. **Mixed-version surgery at a trunk cut.** **Mechanism:** retain old trunk slices only on selected private routes and learn a boundary translator so one request can cross from an old prefix to a new suffix, or vice versa, without keeping a full old trunk. **Why it might be new:** BCT and versioned adapters are close; the hypothesis is that different skill failure domains can be isolated at different cuts with fewer bytes than either full snapshots or one uniform ABI. **Cheapest first test:** two-layer MLP with different layer-specific shifts; compare storage-matched versioned low-rank deltas and shared activation alignment. **Old-task retention check:** old service after each slice is independently withdrawn and under unseen combinations of surviving versions.
20. **Repair with disconnected update domains.** **Mechanism:** train local update operators that leave a small transferable behavior residual for reconciliation after a partition, then combine residuals into a usable holder without re-executing either learning history. **Why it might be new:** personalized federated CL and merging cover delayed aggregation; the target is preservation of per-skill rescue paths under concurrent writes, not building a single reconciled averaged model. **Cheapest first test:** two partitions receive conflicting tasks and exchange a fixed number of bytes on reconnection; compare sparse task arithmetic, FedWeIT and independent adapter transfer. **Old-task retention check:** serve old tasks in each partition during the split and from the fleet immediately after reconnecting.
21. **Learn where a shared feature needs a private escape lane.** **Mechanism:** train the trunk to predict which feature collision a legal local write will suffer, and allocate a width-limited raw-input bypass to the affected holder at write time. No trunk clone is needed per holder. **Why it might be new:** progressive networks and PMoE add paths; this is conditional acquisition of an independent sensing path to remove a specific common failure, tested against the same bypass in a central adapter bank. **Cheapest first test:** planted shared bottleneck with misleading correlations; compare learned versus random bypass placement and adding equal shared width. **Old-task retention check:** measure old service under feature removal, including tasks never granted bypass, at equal new-task gain.
22. **Sparsify synchronization by skill dependence.** **Mechanism:** attempt to learn an update boundary: agents independently accept local writes unless their write/read dependencies predict that the combined writes will remove the last witness for a skill. Coordinate only across that boundary. **Why it might be new:** PR #58 already poses write-skew; this card is only distinct if it learns which cross-agent communications are necessary, not merely detects non-additivity. **Cheapest first test:** concurrently apply pairs/triples of cheap writes with all subsets checked, against exact conflict checking, pairwise checks and synchronous transactions. **Old-task retention check:** fixed old suite immediately after mixed writes plus new-task progress and bytes sent.
23. **Move evidence before moving weights.** **Mechanism:** if old labels can be accessed only by their original agent, transmit a small set of adjudication queries learned to distinguish safe competing successor models; postpone moving their weights until the successor can pass locally. **Why it might be new:** active distillation and certified anchors are close, and group testing was killed as no cheaper than direct checks. The claim needs a genuine bandwidth advantage under label locality and must not rely on retaining a hidden global oracle. **Cheapest first test:** partitioned synthetic old inputs, equal communication for random queries, direct validation, active teaching and learned certificates. **Old-task retention check:** score after permanently dropping the original label-owning agent and after a new local update.
24. **Redundancy of revisions, not copies of one answer.** **Mechanism:** overlap prior and current skill versions across agents only while a caller-visible context splits their validity regions; train a version-aware read before retiring any old capacity. **Why it might be new:** model versioning and SkillApt cover revision and applicability; an ambitious claim is a retirement criterion learned from *joint* access patterns that preserves still-valid old uses at equal bytes to simple version-tag retrieval. **Cheapest first test:** streams that flip some rules globally and others only in a visible context, comparing timestamped replay, explicit versions and blind merging. **Old-task retention check:** separate still-valid old contexts, genuinely revised contexts, and contexts where the revision is unobservable; don't count preserving now-wrong answers as retention.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Can an optimizer write into the space of surviving sets instead of protecting fixed holders?** Cards 1–3. Search for a transition rule that hands off witness responsibility during learning, beats the best fixed placement plus single-model replay at matched resources, and holds on untrained trunk shifts and outage combinations. Start by enumerating the tiny feasible sets, then test whether a learned surrogate keeps the effect. If ordinary dynamic MoE or worst-loss constraints give the same frontier, it is allocation, not a primitive.
2. **Can a fleet train a repair operator that preserves a *future learning capability*, not just an immediate output?** Cards 7–12. Measure post-repair and post-next-write performance on unseen deleted skills under a shifted trunk, with fixed label access. Exact restoration under a frozen trunk is the sanity check, not the result. If quantized checkpoints, byte coding, or dataset distillation plus routing tie, drop the “functional code” claim.
3. **What is the smallest obligation that keeps a composite job executable during churn?** Cards 9, 13 and 17. Separate stage health from path success by crossing two independently updated boundaries. Look for a small learnable witness that works on unseen compositions at fewer tests than direct end-to-end rerouting and can guide a new write. Exact finite-state reachability alone is not novelty.
4. **When is a fleet more than a centrally simulated adapter bank?** Cards 19–23. Search for a separation under explicit restricted access, bandwidth or latency; without one, the bank is an exact null when it can reproduce the same state and operations. The useful object would be a write rule whose recoverability degrades gracefully under independent local progress, not an unpriced parameter-count advantage.

## Prior-art and kill screen

- **Direct nulls, not novelty claims:** [SEED](https://arxiv.org/abs/2401.10191) selectively trains one expert per task; [Continual Learning Beyond a Single Model](https://arxiv.org/abs/2202.09826) already studies CL with ensembles; [Theory on MoE in CL](https://arxiv.org/abs/2406.16437) already analyzes specialization, routing and forgetting; [CaRE](https://arxiv.org/abs/2602.03473) uses bi-level routing; [PASs-MoE](https://arxiv.org/abs/2601.13020) explicitly addresses router/expert co-drift. [MoE-Pruner](https://arxiv.org/abs/2410.12013) is a related expert-sparsification control, not a CL guarantee. Selective experts, learned routing, and router decay are not the proposed contribution.
- **Coordination and interference:** [TARGET](https://arxiv.org/abs/2303.06937) and [Federated Orthogonal Training](https://arxiv.org/abs/2309.01289) target global forgetting; [FedWeIT](https://proceedings.mlr.press/v139/yoon21b.html) selectively transfers sparse task knowledge, so not all federated CL reduces to a single averaged payload. [PBT](https://arxiv.org/abs/1711.09846) selects and copies training states; [model soups](https://arxiv.org/abs/2203.05482) and [task arithmetic](https://arxiv.org/abs/2212.04089) consolidate compatible weights. [GEM](https://arxiv.org/abs/1706.08840) is the gradient-constraint null; [backward-compatible training](https://arxiv.org/abs/2003.11942) is a representation-compatibility null.
- **Storage and fault tolerance:** RAID-style mirroring is already `r` identical copies, [regenerating codes](https://arxiv.org/abs/0803.0632) repair encoded symbols with a bandwidth tradeoff, and [ParM, Parity Models: Erasure-Coded Resilience for Prediction Serving Systems](https://jackkosaian.github.io/files/papers/sosp2019parity-models.pdf) learns parity models for prediction recovery when workers fail. Fault-aware placement, coded inference, and exact adapter checkpoint repair are prior art; a residual claim must handle learned state that changes between encode, serve and repair.
- **Internal exclusions:** screened [PR #6's ledger, triage and top 10](https://github.com/manojbajaj95/cl/pull/6/files) before drafting. Do not resurrect coded/redundant memory fragments, bootstrap writers (bagging), H1/H1b popularity and soft endorsement, paraphrase portability, confidence-only pull, stale-ID redirects, or the already-triaged fleet market, phylogeny and critical-size analogies. [PR #56](https://github.com/manojbajaj95/cl/pull/56) already has parity layers and coded adapters; top-10 #3/#4 and PR #113 already cover write-skew, drifting side information and timing-dependent replay. Where a card uses one, the extra prediction above is the only novelty claim.
- Screen scope: Hugging Face Papers searches for ensemble, federated and mixture-of-experts CL, PBT, model merging, population skill retention and distributed coding, plus targeted abstract checks. This is a nearest-neighbor screen, not an exhaustive review or proof of novelty. No fleet training or GPU experiments were run for this node; the root-cause examples are analytic counterexamples to the holder-count guarantee, not measurements of its prevalence.
