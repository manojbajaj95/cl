# Set-valued edit certificates: can one learned representation survive shared-edit composition?

Tree path: [discrete backprop through a learned tool loop (PR #52)](https://github.com/manojbajaj95/cl/pull/52/files) → [obligation inverse certificates (PR #83)](https://github.com/manojbajaj95/cl/pull/83/files) → **set-valued edit certificates** (depth 4).

**Scope:** Raw ideas and proposed first tests, not experiments or novelty verdicts. Read against the [idea ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md) and [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md): the bar is a reusable learning operation, not a renamed solver, stronger score, or bigger candidate menu.

## Root cause: there is one write, not one write per copy

The parent identified the right object but did not construct a learned, compact carrier for it. A persistent edit `e` changes both what a port does and which state its next copy sees. The backward message is a **relation between entering state and the same edit**, not just the marginal set of good edits for a nominal trace. A point inverse may choose a different valid mode at each call. An edit-only summary at an intermediate boundary may keep all the right marginal values while losing which values go together. An exact solver keeps those correlations, but may pay for the whole trace again. The missing operation is **reusing a checked summary without losing the correlations a later obligation can distinguish**.

For deterministic ports, lift the transition to `F̃ᵢ(s,e) = (Fᵢ(s,e), e)`. For a terminal obligation `G_T` and intermediate guards `Gᵢ` on the lifted space:

```text
R_T = G_T
R_i = G_i ∩ F̃_i⁻¹(R_{i+1})
repairs(s₀) = {e | (s₀,e) ∈ R_0} ∩ old_task_safe_edits
```

Pullback composes through the edited transitions; the meet incorporates the separate guards on that *same* trajectory. A terminal-only obligation needs no additional meet at each copy. For stochastic or adversarial ports, the obligation must also say which outcomes are quantified and in what order; old tasks must be rerun on the committed edit, not on an unedited trace.

- **Mode loss:** call 1 admits `{a,b}`, call 2 admits `{b,c}`. Two individually valid point predictions `a,c` miss the shared solution `b`.
- **Correlation loss:** over bit-pair edits, two copies admit `{00,11}` and `{01,10}`. Both coordinate marginals are full and both sets are nonempty, but their shared-edit intersection is empty. A box, marginal product, or separate existential edit per copy cannot distinguish this contradiction.
- **Size barrier:** let the edit select one of `N` addresses. A fixed loop increments a counter and emits whether it equals the edit address. At step `i` the guard can be unconstrained or forbid a match. The `N` guards can describe any subset of edits. An exact, self-contained summary that answers arbitrary membership queries must distinguish `2^N` subsets and so needs at least `N` bits in the worst case, even though the edit address needs only `log₂ N` bits. A pointer to the guard log is not compression if the log or its later read cost is excluded. This does not rule out structured families, partial certificates, or amortization.

Semantic closure is easy: store the formulas, substitute the transition and conjoin. **Compact closure is the research question.** Boxes close under intersection, not arbitrary pullback (even a shear takes an axis-aligned box to a slanted region). Monotonicity alone does not make arbitrary repair sets intervals. A shared-symbol BDD can represent the exact finite answer, but its width can blow up. A score or a sample can guide search; neither warrants a soundness claim by itself.

One constructive target: learn a finite type map `q(s,e)` such that each lifted transition factors through it, `q ∘ F̃ᵢ = fᵢ ∘ q`, and every permitted guard (including protections in scope) is constant on its fibers. Then certificates over the types close exactly under finite preimage and meet, with size governed by the number of types, not the horizon. The difficult parts are checking the factoring, keeping the number of types small on unseen recombinations, and finding a real edit of a feasible type without enumerating edits. This is a restricted target, not a claim that all ports have such a quotient.

**Prior-art floor:** [knowledge compilation](https://arxiv.org/abs/1106.1819) already studies succinct carriers and efficient transformations; [active automata learning](https://doi.org/10.1016/0890-5401(87)90052-6) already learns finite types from distinguishing suffixes. Neither operation on its own is the claim. The proposal is a checked, reusable edit interface that survives shared-write composition and produces affordable witnesses in a continually changing model. The parent's survey covers point editors and fixed-candidate certifiers; neither a better point proposal nor rebranding symbolic preimages would meet this bar.

## What would count

- **Certificate contract.** Declare the port version, edit family, state scope, and outcome semantics. Return a checked inner set `L` and/or outer set `U` with `L ⊆ repairs ⊆ U`, plus a way to extract a concrete shared write from `L`. An empty checked `U` proves infeasibility in scope; an empty `L` or a failed search means unknown. Test acceptance and rejection separately. A final old-task check on unseen inputs is still necessary; a proof on the anchor subset does not cover them.
- **Small common world.** Start with the parent's width-six retrieve → plan → act retry loop and single-cell writes. Add a two-bit correlation trap and paired examples with different retry counts and guard order, controlling for initial margin and edit size. Train on short traces and hold out whole guard combinations and longer traces. Enumerate only as the tiny-world truth oracle, not as part of test-time certificate construction. Continuous cards can use a two-dimensional edit plane with an exact oracle where available.
- **Controls and readouts.** Compare with incremental SMT/BMC over one shared edit, cached symbolic summaries, and equal-budget replay or point proposals plus the same forward verifier. Match edit family, old anchors, bytes and verifier calls; charge training and index construction, then report break-even reuse. Track false accepts, false exclusions, unknowns, recovery at matched retention, proof size/check time, and cost to extract a real write. On impossible cases report rejection accuracy and unchanged old-task scores; score repair on feasible cases at matched coverage so refusal cannot masquerade as retention.
- **Old tasks.** Keep the parent's held-out old-pair suite separate from anchors, including ordinary non-retry pairs, and measure held-out old retry tasks where applicable. Compare pre/post write and with controls; for streams report per-task retention after later writes as well. Treat the ledger's same-byte replay, constant/margin baselines, and write-skew cases as floors.

## Raw ideas

**P** = candidate primitive if the proposed operation works beyond its toy; **I** = improvement or diagnostic. “New” below means the proposed delta relative to the parent and nearby mechanisms, not a literature verdict. Nothing below was run.

### Learn what each copy must preserve

1. **Guard-complete edit types (P).** **Mechanism:** learn a partition of joint state–edit pairs by predicting which suffixes distinguish them. Export a finite transition table on types, with checked transition and guard maps and an edit decoder for feasible types. **New:** a port exports a reusable preimage type, not a point inverse or a box in a learned metric. **First test:** on a parity retry loop, demand the minimum sufficient partition up to redundant types; compare type count and extraction cost with exact partition refinement and a learned invariant state encoder on held-out suffixes. **Retention:** decode and apply one repair; run held-out ordinary pairs and old parity-triggering retries.

2. **Proof-guided edit separators (P).** **Mechanism:** carry a small set of shared edit symbols and state bits across each call boundary; infer separators from repeated trace structure and check the factorization before eliminating anything. Store a proof of how to reconstruct a witness for eliminated symbols. **New:** a learned cut exposes which edit correlations must cross a port, not which layer to update; it can be composed with certificates from other ports. **First test:** interleave two parity chains with one shared bit; compare maximum certificate width and witness cost against min-fill elimination and BDD reordering on unseen interleavings. **Retention:** apply the reconstructed shared edit and run held-out old pairs from both chains.

3. **Inverse bytecode with a small checker (P).** **Mechanism:** a learned compiler emits case split, substitution, equality and meet operations over named write binders; frozen rules check each emitted step against port semantics. Intern the proof fragments so later obligations call them instead of regenerating them. **New:** the model learns to emit and reuse *pullback programs*, not sets encoded in activations or candidate edits; plain proof search is the floor. **First test:** synthesize a fragment once for a branch-and-retry table and reuse it under an unseen guard; compare proof size and checked wall time to cached SMT lemmas. **Retention:** execute the resulting repair on unseen normal read/plan/act calls, including branches absent from compiler training.

4. **Suffix-rank certificate coordinates (I).** **Mechanism:** build a truth matrix with rows of prefix-produced state–edit pairs and columns of suffix obligations. Learn a candidate set of distinguishing suffixes, then check that agreeing on these suffixes implies agreement on all permitted suffixes via transition closure. **New:** the chosen probes *coordinate certificates*; unlike the parent's splitting query, they summarize many loops rather than identify one write. **First test:** hide half the suffix combinations of a small automaton; compare the resulting row classes and proof cost to fixed length-`k` suffixes and exact partition refinement. **Retention:** include old guards when fitting the interface, then test committed edits on held-out old traces differing beyond `k`.

5. **Certified edit garbage collection (P).** **Mechanism:** when an address becomes unobservable to all remaining ports and guards, replace it with an existential relation plus a reconstruction function. A learned liveness predictor proposes when to forget; a check rules out hidden reads and requires a common witness on the currently live symbols. **New:** drops dimensions from an *uncommitted repair set* without changing the edits it can witness on the surviving interface; not reachability GC of stored lessons. **First test:** create a retry that appears to release a write bit but reads it after a rare branch; compare peak symbol count and false witness rate against syntactic liveness and quantifier elimination. **Retention:** reconstruct and apply the full edit; test both routine old tasks and held-out old tasks on the late read.

6. **Lossless edit joins (P).** **Mechanism:** learn a decomposition of a certificate into small relations over overlapping edit fields. Export it only if a proof establishes that their natural join reconstructs the original relation; switch representation if a guard breaks that property. **New:** the compression unit is a checkable dependency between edit fields, rather than a low-rank score or the independence assumption of marginal message passing. **First test:** plant a two-field dependency that decomposes and a three-field parity one that defeats pairwise projection; compare against fixed pairwise factors and generic symbolic factorization at equal bytes. **Retention:** run held-out old tasks on the decoded edit, including an old task affected by the three-way interaction.

### Compress time without changing the write

7. **Proof-carrying retry powers (I).** **Mechanism:** learn which repeated port blocks recur, cache their certified binary powers as relations that retain the write binder, and assemble unseen horizons by checked composition. **New:** the reusable unit is an edit-parametric jump, not a short-loop sampler, learned fixed point, or cached rollout at one candidate edit. **First test:** reuse a cache from retries of length 2 and 4 at lengths 7 and 11; compare against exact repeated squaring and DAG-shared BMC with warm caches charged. **Retention:** commit one decoded edit and test both short old loops and old tasks held out at a different retry length.

8. **Refactoring-stable edit certificates (P).** **Mechanism:** learn a normalizer for trace segments and check an edit-preserving relation between the original and normalized interfaces. Allow a certificate proved for one segment to substitute for another only on matched boundary variables, including the same edit. **New:** the equivalence is of admissible *writes*, not just unedited outputs or equivalent port code. **First test:** compare a fused retry body with a split one and a decoy rewrite that agrees only at no-op; compare reuse and counterexamples to syntactic caching plus semantic equivalence checking. **Retention:** apply the same recovered edit in both versions and run held-out old tasks on both.

9. **Edit-conditioned induction (P).** **Mechanism:** predict an inductive invariant and well-founded termination ranking whose hypotheses are predicates on the write; check initialization, guarded preservation, and strict rank decrease once for the whole edit region. **New:** standard invariant/ranking synthesis is the control; the deliverable here is the reusable *domain of edits* that shares a proof, rather than a bound or a proof for one configured loop. **First test:** on a three-state retry loop, separate the terminating repair region from an edit that is safe for every prefix but never exits; compare cached invariant synthesis. **Retention:** run the committed edit on ordinary old tasks and measure termination and success on held-out old retry tasks.

10. **Closure under structured branch quantifiers (P).** **Mechanism:** use separate types for persistent edits, environment outcomes and ephemeral actions; check proof obligations under `∃edit ∀outcome ∃action` only where the policy is allowed to observe the outcome before acting. **New:** the certificate describes what a fixed learned write enables under observable contingencies, without accidentally allowing the write itself to adapt. **First test:** use two branches that are each repairable only with different writes, plus a version where a legal ephemeral action really can compensate; compare with QBF synthesis and an untied editor. **Retention:** commit feasible writes and run old tasks under familiar and held-out outcome sequences; for infeasible cases verify unchanged old behavior.

11. **Budget over joint failure traces (I).** **Mechanism:** carry the union of bad seed regions indexed by the same edit, then bound its measure under a declared joint seed law. Learn which event intersections merit exact checking; do not multiply per-copy success probabilities. **New:** estimates compositional risk for a persistent write through correlated outcomes, not conformal coverage of a candidate set. **First test:** use two retries sharing a coin whose per-copy failure rates coincide but whose joint risk differs; compare to exact finite-seed model checking and a union bound. **Retention:** compare old-task success and observed failure rates on independent held-out seeds after applying a budget-feasible edit.

12. **Write-skew proof probes (P).** **Mechanism:** generate a minimal edit *tuple* for which solo writes satisfy the old guards but their composition fails. Store the checked counterexample as a relation on the joint edit variables, including order where it matters, and let later compilers use it as a negative obligation. **New:** extends the flood's write-skew measurement into a reusable counterexample object that intersects with future edit sets. **First test:** plant an order-sensitive two-write interaction invisible to solo tests; compare against pairwise score filters and symbolic nogood caching at equal bytes and forward calls. **Retention:** commit a feasible pair and test old behavior after each prefix as well as after both writes.

### Make uncertainty useful without certifying guesses

13. **Two-sided closure sandwiches (I).** **Mechanism:** learn where to spend refinement budget in a paired domain. Prove safe regions in the inner carrier and ruled-out regions via the outer carrier; after pullback and meet, retain sound inclusions even when the carriers are rounded. **New:** uses the *gap* as an explicitly budgeted control surface, rather than mistaking a tight-looking box or energy score for a set of safe writes. **First test:** create two disjoint curved regions with identical axis bounds, plus a feasible near-touching control; compare inner-witness and outer-refutation rates to fixed paired domains and adaptive CEGAR. **Retention:** execute an inner witness in feasible episodes and measure old-task success; keep refusal and unchanged retention separate on infeasible episodes.

14. **Ambiguity that prices future meets (P).** **Mechanism:** choose a check by how much it resolves whether unresolved regions survive *later conjunctions*, not by marginal entropy of the current edit set. Keep the collection of unresolved distinguishing contexts as part of the certificate. **New:** the parent asked for an anchor that splits today's repair set; this buys information about tomorrow's ability to reuse a certificate. **First test:** design a high-entropy current split irrelevant to every remaining guard and a smaller split that decides feasibility; compare to active anchors, solver counterexamples and random checks. **Retention:** reserve equal old anchors across arms and check held-out ordinary and retry tasks on writes accepted after the queries.

15. **Certified minimum write budget (I).** **Mechanism:** lift budget axes such as number of editable cells and maximum norm to certificate parameters. Store proof-backed lower and upper antichains of budgets, rather than collapsing feasibility to one weighted objective. **New:** says *which capability is missing* with a scoped proof and not just an edit-capacity forecast. **First test:** plant a case where one large write or two smaller writes repairs the loop; recover the breakpoints against incremental multiobjective SAT at equal checks. **Retention:** choose a feasible write from each minimal regime and compare old-task performance at matched new-task success.

16. **Relational refutations of lossy types (P).** **Mechanism:** a checker returns two concrete state–edit pairs merged by the proposed type and a suffix that distinguishes them. Feed this triple into a split operation, rechecking only summaries depending on that type. **New:** the proof failure edits the learned certificate vocabulary, not the write candidate or the current anchor set. **First test:** introduce a suffix guard that distinguishes edit choices previously equivalent; compare incremental repair to rebuilding the quotient and to ordinary CEGAR with the same counterexamples. **Retention:** retest edits issued under the repaired type on old tasks in both the split class and unrelated classes.

17. **Refutation-directed write-family expansion (P).** **Mechanism:** when a proof shows the edit set empty, learn a proposed extra persistent handle from its conflicting obligations. Accept the expanded family only if a new checked feasible set appears, with that handle still shared across every copy. **New:** adjacent to [obligation compilation](https://github.com/manojbajaj95/cl/blob/devin/1795539325-obligation-compile/tree/obligation-compile.md); this version asks whether the *same set certificate's refutation* can guide enlargement and subsequent reuse, not whether a new direction repairs one case. **First test:** plant a one-handle impossibility resolved by a second degree of freedom and compare to randomized and exhaustive handle augmentation at the same expanded budget. **Retention:** test the expanded write on unseen old pairs before and after a second certified edit.

18. **Equality skeletons for thin intersections (I).** **Mechanism:** propose exact shared affine equalities separately from inequalities, prove those equalities where possible, and restrict the inner witness search to the certified affine hull. **New:** the target is usable extraction when a valid intersection has zero ambient volume; it is not the parent's loop Jacobian for local search. **First test:** two guards trap repairs on a diagonal line in a two-dimensional edit plane. Compare certificate-plus-witness recovery to equality-aware linear solving, interval sampling, and norm-matched gradient search. **Retention:** compare old-task scores for witnesses on the line and check a held-out boundary-sensitive old task.

### Keep the set valid across actual learning

19. **Translate receipts after commits (P).** **Mechanism:** rebase old certificates through a committed write, for example by pulling back an absolute weight constraint along `e ↦ W_after + e`; for non-additive writes require a checked composition map or invalidate the receipt. **New:** parent receipt stacking assumes a shared coordinate system; this proposal gives the receipts an explicit transport operation so their intersection still means something after a commit. **First test:** run a two-write stream in which naive receipt intersection rejects a safe next write or admits an unsafe one; compare to exact rebuilding from old anchors and cheap Jacobian transport. **Retention:** evaluate both old task groups after the first and second commits.

20. **Proof-capped receipt retirement (P).** **Mechanism:** drop an old receipt from the active meet only if a check proves that the survivors imply it for all edits in the declared future edit family. Retain and charge a way to reconstruct it if the family or port version invalidates the proof. **New:** shrinks the active certificate by verified implication, not by replay salience, forgetting insurance, or the model re-deriving a lesson. **First test:** induce two initially redundant old guards, then enlarge the edit family so one becomes essential; compare to unsat-core pruning and same-byte old-example eviction. **Retention:** issue one more edit after the enlargement and test the old task whose receipt was retired, plus other old tasks.

21. **Migration by a checked edit relation (P).** **Mechanism:** learn a relation between edits of two port versions, possibly one-to-many. Prove whichever direction of prevention or witness transfer is used, and expose unmatched regions rather than transferring a point by default. **New:** [edit transfer (PR #76)](https://github.com/manojbajaj95/cl/pull/76/files) asks whether an edit transfers; this asks whether whole feasible *and impossible* regions can be transported with correctly oriented proofs. **First test:** split one table address into two under a base upgrade, with a decoy target that matches only the unedited output; compare with point transfer plus verification and re-solving. **Retention:** run unseen pre-upgrade tasks on the upgraded port after the transported edit.

22. **Commit without spending the last option (P).** **Mechanism:** maintain a checked residual relation `(current edit, possible next edit)` for declared future obligations. Project onto current writes only after reserving at least one verified continuation where required. **New:** not a Gramian plasticity forecast or generic deferred commitment; the current write is committed, and a witness for a remaining option is part of its certificate. **First test:** plant two equally good current repairs where only one leaves a solution after a later guard; compare to exact two-stage planning and matched-retention projected updates. **Retention:** test held-out old tasks both at commitment and after exercising the continuation.

23. **Certificates over traversable edit paths (P).** **Mechanism:** represent the safe connected components of an edit domain and verify bridges in a write schedule, as well as checking the endpoint. Drop the connectivity assertion if the verifier cannot establish it. **New:** a set can tell you that two endpoints are safe without telling you whether a process that exposes intermediate weights may move between them. **First test:** in a two-dimensional plane with a barrier of old-task failure, compare a learned bridge plus checker to grid connectivity and endpoint-only certification. **Retention:** test held-out old tasks at intermediate snapshots and at the final committed edit.

24. **Certificate repair after schema changes (P).** **Mechanism:** attach dependency slices to certificate steps and learn how to substitute proof fragments when a guard or port is replaced. Retain untouched fragments only after checking their scope; compare the repaired edit set with a full rebuild. **New:** not migration of writes or generic cache invalidation; the target is a patch operation on a proof that preserves correlations with unchanged guards. **First test:** change one of three retry guards with a small semantic effect but a large syntactic diff; compare proof churn and cost to local incremental SMT and rebuilding the same carrier. **Retention:** apply a replacement write from the repaired certificate and retest old tasks for both touched and untouched guards.

## Deeper questions, ranked by chance of a new primitive

1. **Can a port learn a small, guard-complete type system for joint state and edit?** Highest: this enables pullback, meet and witness extraction on a single object. Find the minimal types using distinguishing suffixes; reject the idea if new guard combinations force nearly every state–edit pair into its own type, or if decoding costs as much as the shared-variable solve. (1, 4, 16)
2. **Can independently learned ports agree on a lossless edit interface?** High: a checked interface would let one swap or compose ports without training a global inverse. Test whether independently produced interfaces can be aligned at bounded cost, or whether join width tracks the full shared edit dimension. (2, 3, 5, 6, 8)
3. **Can a certificate survive the learner moving its own base?** Medium-high: checked rebase, retire and migrate operations would turn old-task retention into a persistent edit-set interface rather than a fresh verification problem. The hard test is an edit family's expansion invalidating an old proof that had looked redundant. (19–21, 24)
4. **Can impossibility expose the missing write interface, not just reject an edit?** Medium: a refutation that regularly proposes useful new handles would be a learning primitive, but a refutation may contain too little causal information or tie generic search. Require transfer to a new loop and no old-task regressions. (12, 15–17)
5. **Can a partial certificate preserve enough future editability to justify committing now?** Lower: useful if a reusable residual relation predicts safe continuations better than a same-budget planner, but it may amount to bounded lookahead. Test a held-out change to future obligations, not the forecast already encoded in the solver. (13, 14, 22, 23)
