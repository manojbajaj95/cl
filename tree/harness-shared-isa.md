# Agent harness → one instruction set across text, code and weights?

Parent: [tree/agent-harness.md](https://github.com/manojbajaj95/cl/pull/47) (root cause: every harness edit writes into one shared prompt and retrieval interface, so fixes interfere and credit is unassignable). Its top-ranked next node is this question: **can two learned behaviours be written, swapped and combined independently across text, executable code and weights under one behavioural contract?**

## Root cause

**A behaviour has no identity outside the substrate that implements it.** Each substrate defines "the same behaviour" with a different equivalence and a different composition operator:

| Substrate | What a behaviour *is* there | How two behaviours combine | What is left undefined |
|---|---|---|---|
| Text | A token string whose effect is decided by attention competition with everything else in context | Concatenation, then softmax renormalization | How much of the model's capacity the string takes from other strings |
| Weights | A ΔW in an arbitrary gauge, ΔW = BA = (BR)(R⁻¹A); its effect is input- and format-conditioned | Parameter addition through a nonlinear network | Which outputs the ΔW writes besides the target |
| Code | An extensional function on inputs/outputs or tool state | Function composition (order is explicit) | Nothing, but it can only express behaviours with a clean interface |

The only cross-substrate equivalence current methods check is **aggregate task gain on the training input distribution**. So compilation (text → weights, text → code) and decompilation (weights → text) preserve the gain, not the behaviour's footprint: what it reads, what it writes, and what it must leave alone. Without a footprint there is nothing a contract can say, so "swap A from text to weights while B stays in text" has no defined meaning, and composition is only as good as the luck of the two footprints not overlapping. This is the parent's shared-write-surface problem restated one level down: substrates do not share an address space, so there is no place to declare which part of behaviour space each edit owns.

## Evidence

| Observation | What it establishes |
|---|---|
| [SKILL2STEER (2611.04497)](https://arxiv.org/abs/2611.04497): a compiled skill shift carries a domain-general prior, not skill content. A wrong skill document performs on par with the correct one, an averaged bundle matches per-skill routing under an equivalence test, and a same-norm random direction falls to the no-injection baseline. | Text → weight compilation preserves gain but not identity: two compiled skills are mostly the *same* object. |
| [From LoRA to Language (2611.09454)](https://arxiv.org/abs/2611.09454): weight updates of two different skills have cosine 0.88; only 11.6% of their energy is skill-specific. Writers recover 39–44% of key instructions from adapters that stored the document, but only 1–2% from adapters trained on behaviour alone. | Weights → text decompilation cannot recover a behaviour that was never given a substrate-independent description. |
| [READ (2609.31600)](https://arxiv.org/abs/2609.31600): a LoRA's factorization is a free gauge that is invisible while the adapter serves alone but decides what a learned interaction between adapters can see; one-directional read-only coupling (new reads old, never writes old) keeps old skills intact and beats published merge baselines by 20+ points on SuperGLUE. | Weight composition needs an explicit read/write direction; READ supplies it *within* weights only. |
| [When Do Task Vectors Interfere? (2608.09490)](https://arxiv.org/abs/2608.09490): non-additivity between two task vectors is input-conditioned. The same merge shows a +6.9-point interaction on code prompts, +0.3 when wrapped in the adapters' training template, and +12.5 in an untrained chat template. | A weight behaviour's footprint depends on the text around it, so text and weights are not independent channels. |
| [CSPD (2611.27376)](https://arxiv.org/abs/2611.27376): RL experts distilled into soft prompts compose by concatenation; the full composition matches MOPD (67.83 vs 67.79) and beats it out of domain (56.6 vs 53.5). [Skill-to-LoRA (2606.16769)](https://arxiv.org/abs/2606.16769) matches full skill text on 18/21 skills; wrong-LoRA and shared-LoRA controls drop. [First-Order Steering (2610.04283)](https://arxiv.org/abs/2610.04283) translates weight deltas into composable activation directions with a Hessian error bound. | Single-substrate composition can work, and single conversions exist. None of them tests a *mixed* library (one behaviour in text, one in weights, one in code) or swapping one behaviour's substrate while another is active. |
| [Are Self-Evolving Agents Continual Learners? (2610.25858)](https://arxiv.org/abs/2610.25858), via parent: GEPA / Meta-Harness global prompts carry SQLite exploration rules from BIRD onto BFCL-Miss rollouts (−6.8 / −4.8 points before any BFCL-Miss training task). | In a real harness the shared write surface is text, so a text behaviour has no declared scope. |

### CPU probe: the 3×3 substrate swap matrix

`probes/shared-isa/probe.py` (Qwen2.5-0.5B-Instruct, CPU, greedy). Two behaviours, one contract each, written as an executable checker: **A** = answer entirely in uppercase; **B** = end the answer with the word DONE. Each is implemented three ways: **text** (a system-prompt instruction), **code** (a post-processor), **weights** (a rank-8 LoRA distilled from the *code* implementation's outputs on 50 training questions, so text, code and weights share one contract). Protected behaviour: the answer still names the right capital (held-out countries). Weight pairs combine by exact LoRA concatenation; the `nullw` control is a LoRA trained on unchanged base outputs (identity contract). Every (A substrate, B substrate) pair is run on 32 held-out questions; mean over 3 seeds (train/test splits), seed range in parentheses.

| A substrate | B substrate | A ok | B ok | retention |
|---|---|---|---|---|
| none | none | 0 (0-0) | 0 (0-0) | 98 (97-100) |
| none | text | 0 (0-0) | 0 (0-0) | 97 (94-100) |
| none | weight | 0 (0-0) | 100 (100-100) | 91 (88-97) |
| none | code | 0 (0-0) | 100 (100-100) | 98 (97-100) |
| text | none | 54 (50-59) | 0 (0-0) | 54 (50-59) |
| text | text | 90 (84-94) | 44 (41-47) | 14 (9-22) |
| text | weight | 0 (0-0) | 100 (100-100) | 91 (88-97) |
| text | code | 54 (50-59) | 100 (100-100) | 54 (50-59) |
| weight | none | 91 (88-97) | 0 (0-0) | 18 (16-22) |
| weight | text | 92 (84-100) | 0 (0-0) | 16 (12-19) |
| weight | weight | 88 (75-100) | 100 (100-100) | 22 (16-28) |
| weight | code | 91 (88-97) | 100 (100-100) | 18 (16-22) |
| code | none | 100 (100-100) | 0 (0-0) | 98 (97-100) |
| code | text | 100 (100-100) | 0 (0-0) | 97 (94-100) |
| code | weight | 100 (100-100) | 100 (100-100) | 91 (88-97) |
| code | code | 100 (100-100) | 100 (100-100) | 98 (97-100) |
| text | nullw | 9 (0-28) | 0 (0-0) | 80 (62-91) |
| code | nullw | 100 (100-100) | 0 (0-0) | 90 (88-91) |
| none | nullw | 0 (0-0) | 0 (0-0) | 90 (88-91) |

Readings (n is small; treat as a probe, not a result):

- **Any weight write erases a text behaviour.** Text-A compliance is 54% alone and 0% once LoRA B is loaded. The null LoRA, trained only to reproduce base outputs on instruction-free prompts, still drops text-A to 9% (0–28) while retention stays near base. A weight implementation's contract is defined only on the prompts it was trained on, and a prompt carrying another substrate's behaviour is outside them.
- **Text behaviours are not independent even in sign.** Text-B alone never fires on this model (0%), but fires 44% next to text-A, while retention falls to 14%.
- **One contract, three retention prices.** Behaviour A costs nothing in code (98%), 44 points in text (54%) and 80 points in weights (18%), even though the LoRA was distilled from code's own outputs. The weight version learns the format and breaks recall ("THE CAPITAL OF NETHERLANDS IS BRUSSELS"): format and fact share the answer tokens, and nothing in the contract says which one A may write.
- **Composition works inside a substrate and fails across them.** Weight A + weight B by exact LoRA concatenation keeps both (88% / 100%); code + code is perfect; the failures are in the mixed cells.
- **Code wins here only because A and B are pure output transforms.** It cannot implement behaviours that need the model's internals, so "move everything to code" is not a shared ISA.

## Raw ideas (no self-filtering)

Each idea: mechanism / why new / cheapest first test, with a retention check. Ledger overlaps are named so the reviewer can merge or kill.

1. **Behavioural footprint types.** Mechanism: give every behaviour a measured type: its write-set and read-set over a fixed, public probe basis (output features such as case, length, final token, tool-argument binding, fact recall), estimated by intervention in each substrate. The contract is the footprint; any implementation must stay inside it; two behaviours may be linked only when write-sets are disjoint or one reads the other. Why new: READ fixes read/write direction inside one LoRA bank; footprint types are substrate-independent and observable, so text, code and weights become comparable. First test: estimate footprints of A and B in all three substrates of the probe; predict each of the 9 mixed-pair cells' interference from footprint overlap vs from within-substrate similarity (LoRA cosine, instruction NLI). Retention: fact recall is one probe-basis coordinate, so the footprint must predict the weight-A recall loss.
2. **Swap-consistency loss.** Mechanism: train the weight implementation of B not to match B's output alone but to keep every other library behaviour's checker unchanged when those behaviours are realized in each of their substrates (text, code, weights) at the same time. Why new: S2L / LatentSkill / SKILL2STEER train one skill in isolation against a no-skill prompt; this trains against the cross-product of substrates. First test: retrain LoRA B with A-text present in half of training prompts and the A checker as an auxiliary target; check whether text-A compliance survives B-weights (the probe's text|weight cell) at equal steps. Retention: capital accuracy.
3. **Instruction tokens as pointers into weight bodies (dual-key adapters).** Mechanism: a behaviour's call site is a reserved token in context; its body lives either in context (a text definition after the token) or in a LoRA that fires only when an attention head reads that token. Swapping substrate moves the body; the call site and its scope stay put. Why new: Doc-to-LoRA and hypernetworks emit unconditional adapters; prompt-conditioned LoRA exists for tasks but not as a call/definition split shared with text. First test: train LoRA B conditional on token `<B>` (negatives without it); measure B with and without `<B>`, text-A survival when `<B>` is absent and present, and swap to a text definition of `<B>`. Retention: capitals with no tokens.
4. **Log-ratio IR with exact product-of-experts composition.** Mechanism: lower every behaviour, whatever its substrate, to a per-token log-ratio r(x, y) = log q_behaviour − log p_base (text: difference of logits with and without the instruction; weights: adapter on vs off; code: a constrained-decoding mask), then compose at decode time by summing log-ratios. Swap changes how r is computed, not the composition algebra. Why new: proxy-tuning and contrastive decoding use one ratio; here the ratio is the ISA's instruction format across all three substrates, and interference becomes a measurable cross term. First test: implement A and B as ratios from each substrate; compose all 9 pairs by PoE; compare with stacking (the probe). Retention: capitals; check that PoE of text-A and text-B avoids the text|text collapse.
5. **Token-level transducers as a fourth substrate.** Mechanism: compile output-transform behaviours into finite-state transducers over the tokenizer's vocabulary (code that runs inside decoding, not after it), so composition is FST composition with an exact algebra and nothing is written into the model. Why new: constrained decoding uses grammars for format, not as a learned CL storage substrate that weights hand behaviours off to. First test: learn transducers for A and B from weight-A / weight-B outputs, compose, and compare to LoRA A+B. Retention: capitals must match base by construction; measure what fraction of the library's behaviours a transducer can express.
6. **Substrate lattice with lowering and raising passes.** Mechanism: order substrates by compositional exactness (code > transducer > text > weights) and run a consolidation pass that moves each behaviour to the *most exact* substrate that can still express it: synthesize code from a weight behaviour's I/O pairs, raise a code fragment into weights only when its interface leaks. Why new: Program Distillation ([2611.19461](https://arxiv.org/abs/2611.19461)) goes one way (LLM → program); the lattice is a general two-way pass with a cost model. First test: synthesize `upper()` from weight-A outputs and delete LoRA A; retention should recover from the weight-A drop. Overlap: NOOA N1 round-trip consolidation.
7. **Side-effect bill (retention priced per substrate).** Mechanism: before writing, estimate each substrate's retention cost for this behaviour from a small calibration run and write where the bill is lowest; store the bill with the behaviour so a later swap can be priced. Why new: the probe shows the same contract with three very different protected-behaviour costs; parent idea #15 (policy duals) prices tokens and tools, not retention. First test: predict per-substrate recall cost for 10 behaviours from 8 calibration questions, check rank correlation against 32 held-out. Retention is the target itself.
8. **Cross-substrate commutators as stored objects.** Mechanism: for each behaviour pair measure the commutator [X_s, Y_t] = effect(X_s then Y_t) − effect(Y_t then X_s) and the cross term effect(X_s+Y_t) − effect(X_s) − effect(Y_t) across substrates s, t; store a small correction object in code for the nonzero ones. Why new: parent idea #7 rebases by order residuals within one substrate; here the residual is indexed by substrate pair, the object that makes a swap safe. First test: in the probe, store a correction for text-A × weight-B and test whether it transfers to text-A × weight-C for a third behaviour. Retention: capitals.
9. **Substrate dropout.** Mechanism: during any write, randomly realize each existing library behaviour in a random substrate so the new implementation learns to coexist with all realizations; the analogue of dropout across substrates. Why new: CL replay keeps old behaviours in one substrate; swap invariance is never a training target. First test: train LoRA C with A and B drawn randomly from text/code/weights; measure variance of A's and B's compliance across C's substrate. Retention: capitals.
10. **Attention budget accounting for text behaviours.** Mechanism: each text instruction declares a budget (attention mass or logit margin it may take from the answer); a runtime meter enforces the sum and evicts or compiles the excess to another substrate. Why new: text composition failures are treated as prompt engineering; a budgeted resource makes text behaviours linkable. First test: measure attention mass and margin on answer tokens under text-A, text-B and text-A+B; check whether the budget sum predicts the text|text collapse. Retention: capitals. Risk: margin competition is published for adapters ([2604.23750](https://arxiv.org/abs/2604.23750)).
11. **N-version behaviours (cross-substrate differential fuzzing).** Mechanism: keep two or three implementations of each behaviour alive; inputs where they disagree define the behaviour's semantic boundary and become its training and test set; the contract is the agreed region. Why new: N-version programming is a reliability tool; here disagreement between substrates is the learning signal for the contract itself. First test: fuzz capital prompts with odd formats (lists, code blocks, non-English), find code/weight/text disagreements on A, retrain weights on them. Retention: capitals and base outputs on non-disagreement inputs.
12. **Proof-carrying adapters.** Mechanism: every LoRA ships a certificate: probe inputs plus bounds on off-target KL against the public probe basis, under a stated range of context lengths and templates; a linker verifies certificates for every combination before loading. Why new: adapter sharing today ships weights and a model card, not checkable behavioural bounds under composition. First test: certify LoRA B against A-text; the linker should reject the text|weight pair the probe shows breaks. Retention: certificate includes recall.
13. **Holographic behaviour binding.** Mechanism: store many behaviours in one ΔW as a superposition key ⊗ body (holographic reduced representations), where the key is a text token or a code-written activation; unbinding by the key selects the behaviour, and swapping changes which substrate carries the key. Why new: LoRA merging sums adapters without keys; key binding, with the key carried by any substrate, is different. First test: bind 4 format behaviours into one rank-16 LoRA with 4 keys; measure cross-talk vs 4 separate LoRAs. Retention: capitals with no key.
14. **Prefix-to-weight exact transcription as the swap operator.** Mechanism: use the ICL-as-implicit-ΔW identity (a context's effect on one layer equals a low-rank update for that input) to transcribe a text behaviour into weights *at the token positions it would have occupied*, and the reverse; swap is then lossless for that layer, and the error elsewhere is measured, not trained away. Why new: Doc-to-LoRA / SHINE learn a map; this uses the closed-form identity as the instruction format. First test: transcribe text-B at one layer of the 0.5B model and compare to text-B and LoRA-B on all 9 cells. Retention: capitals. Ledger: B3 (implicit ΔW interference prediction) failed; this is a write operator, not a predictor.
15. **Behaviour content addresses for version control.** Mechanism: hash a behaviour by its footprint (idea 1) rather than its text or weights, so the harness can diff, revert and bisect behaviours across substrates (a weight behaviour and its code port share a hash). Why new: L1 prompt-addressable checkpoints address whole model states; this addresses single behaviours across substrates. First test: check that text, code and weight A hash equal within tolerance while A and B differ, on 3 seeds. Retention: n/a (identity test).
16. **Contract inference from substrate disagreement at matched gain.** Mechanism: when two implementations reach the same target compliance but differ on protected probes (e.g. weight-A keeps uppercase but loses recall), induce the missing contract clause automatically ("must preserve answer entity") and add it to all implementations. Why new: skill contracts and checkers are hand-written today; here clauses are learned from substrate disagreement. First test: induce the clause from weight-A vs code-A disagreements and retrain LoRA A with it; recall should recover while compliance stays. Retention: capitals.
17. **Read-only cross-substrate coupling.** Mechanism: extend READ's read-but-never-write rule across substrates: a new weight behaviour may read text-behaviour activations (the instruction's KV) but its ΔW is projected out of the subspace those text instructions write. Why new: READ is weights-only and needs canonical LoRA factors; the text side has no factors, so the protected subspace must be estimated from instruction activations. First test: project LoRA B out of the residual directions that text-A writes and rerun the text|weight cell. Retention: capitals.
18. **Behaviour-scoped tokenization.** Mechanism: let a behaviour own a private vocabulary slice (uppercase tokens are new embeddings tied to lowercase ones), so a format behaviour cannot reach fact-recall circuits that live on the original tokens. Why new: the probe suggests weight-A's recall loss comes from moving the answer to a different token sequence; vocabulary scoping is a substrate-level isolation tool, not a merge trick. First test: tie uppercase-token embeddings to lowercase ones during LoRA A training and measure recall. Retention is the target.
19. **Learned substrate router with a falsifiable contract.** Mechanism: a meta-learner maps a new behaviour's footprint to its substrate and a projected footprint, and is scored on the 3×3 matrix of each new behaviour against the library. Why new: harness routers pick skills, not substrates under a contract. First test: 6 behaviours, leave-one-out choice of substrate; compare against always-code-when-possible and always-weights. Retention: capitals.

## Ranked sub-questions (by chance of a new primitive)

1. **Does a measured footprint (read/write set over a fixed probe basis) give a behaviour a substrate-independent identity that predicts mixed-substrate interference?** If text, code and weight A share a footprint and the 9-cell interference is predicted by footprint overlap better than LoRA cosine or instruction NLI, the footprint *is* the instruction format of a shared ISA (ideas 1, 15, 16, 12). Primitive if yes.
2. **Can all three substrates be lowered to one composition algebra (per-token log-ratios or token transducers) in which combination is exact, and what share of real harness behaviours fit?** This makes composition a property of the IR, not of luck (ideas 4, 5, 6). Primitive if a real library mostly fits.
3. **Can a text token serve as the call site of a behaviour whose body moves freely between context and weights, without erasing other text behaviours?** The probe's text-A × weight-B erasure is the test; a positive answer gives the harness a pointer/definition split that is substrate-agnostic (ideas 3, 13, 14, 17). Primitive if the call site survives the swap.
4. **Is swap invariance learnable by training against substrate cross-products (substrate dropout, swap-consistency), or does it need a structural constraint like READ?** Answers whether the ISA is a training objective or an architecture (ideas 2, 9, 17). Likely an improvement unless training alone suffices across held-out behaviours.
5. **Can each substrate's retention cost for a behaviour be predicted before writing?** Useful for routing (ideas 7, 19), but an improvement on its own.
