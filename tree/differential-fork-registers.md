# Differential fork registers: can training itself be the read instruction?

Parent: [PR #112, survival-probability memory](https://github.com/manojbajaj95/cl/pull/112), especially cards 1, 23–24 and deeper question 1.

**Question:** Two fixed fine-tuning runs see no stored content, but one write makes run L succeed and another makes run R succeed. Can a learner write and read old-task content purely through which future training fork succeeds? How many bits remain readable after later training?

## Root cause: a contrast exposes state, but does not create or protect it

PR #112's two writes have success probabilities `(3/4, 1/4)` and `(1/4, 3/4)`. Pooling across equally likely forks maps both to `1/2`; that read has thrown away the fork identity. Keeping the signed contrast restores discrimination in the example, but its hand-specified transition table already branches on the hidden state. Nothing in the committor equation gives a legal writer a way to reach those states, makes the states survive later training, or shows that training is needed to read the difference. If a common continuation merges the **full** learner states, every subsequent payload-blind fork has the same law for both writes ([PR #110](https://github.com/manojbajaj95/cl/pull/110)). Exact coalescence is not necessary for failure: two states that remain distinct can give the same thresholded transcript, or noisy transcripts that cannot be separated at the available budget.

There are two distinct controls. **Leakage:** fix the fork data, success test, decoder, step budget, and seed law before seeing held-out writes. No old targets, message-dependent fork choices, retained labels, or per-write thresholds on the read side. A public task address is allowed but cannot tell the reader its value. **Shortcut:** allow the no-update control to score the *same public inputs used to train and test the forks*. Also compare raw logits, first gradients, equally expensive direct measurements, and equal-byte replay or a direct register with the same access privileges. An output match only on a smaller support set does not establish a training-only read. Use shadow copies; discarded read events do not count as progress on the live learner. Demonstrate direct old service and decoded old service separately, including non-target old tasks and matched new learning.

## What counts as a bit?

Let the payload be a uniform draw from a codebook of size `M`. Apply a legal write, then a common payload-independent distribution of continuation streams for `H` steps. The decoder gets just the ordered vector `Y` of `K` success flags, one per execution, and public protocol information. An operational capacity at error `ε` is the largest `log₂ M` that can be decoded with block error at most `ε` under declared write, storage, old-task retention, new-task progress, and read-compute budgets. Report both average and worst-codeword error; budget seeds, copies, and extra rollout repetitions. A bank trained on other histories may be shared, but its size and the writer/decoder cost still count.

- One transcript has at most `2^K` patterns; complementary L/R pairs have at most `2^(K/2)`; a known exactly-one-winner bank has only `K`. These are zero-error ceilings, not achievable rates. For nonzero error use, e.g., `(1−ε) log₂ M ≤ I(payload;Y) + h₂(ε) ≤ K + h₂(ε)`. Reporting exact oracle probabilities or real-valued terminal scores silently changes the read channel. Repeated measurements count against `K`.
- In a linear model, a fixed sequence of squared-loss SGD updates is an affine map of its initial weights. A terminal threshold on one logit is therefore one affine halfspace. With deterministic reads and writes varying in a `d`-dimensional affine fiber of the matched visible predictions, `K` such hyperplanes yield at most `Σ_{i=0}^d binom(K,i)` full-dimensional sign regions. This bound is for positive-margin codes, fixed batches and one terminal inequality per fork, not arbitrary first-passage rules. Repeated steps can change which halfspaces are reachable, but do not undo the bottleneck. If the full public-data logits determine all projections used in the gradients and terminal tests, those logits suffice even when a smaller no-fork test is constant.

### CPU witness: writable and readable, but neither exclusive nor durable

Run `python3 tree/probes/differential_fork_probe.py` (NumPy only). For a `d`-bit payload `m ∈ {−1,+1}^d`, install `w=(0, 0.8 m, 0)`. The shared public inference query `e₀` is always zero. Each of `2d` independent forks takes one half-squared-error SGD step at learning rate 0.5 on `e₀ ± eⱼ`, with the same target 1 for every fork and write. The fixed success criterion is a terminal `e₀` logit greater than 0.5. L wins for negative `wⱼ`, R for positive `wⱼ`; an erased weight vector makes neither fork win. The **live** learner never takes these fork updates. Later training moves each payload coordinate toward independent standard-normal distractor labels and moves one extra coordinate toward 1 (batch SGD, step size 0.15). No fork sees either the old answers or anything from the continuation stream.

Each row summarizes 4,096 independently sampled payloads and continuations. “Bits” estimates the information lower bound `d−Σⱼ h₂(pⱼ)` for the uniform independent message, using observed per-coordinate decode error `pⱼ` (not a finite-sample confidence bound or a reliable block rate). New MSE is measured only on the shared fixed target, not on unpredictable distractor labels. The raw pre-update fork logits already read the signs, so this is a **negative** result for training-exclusive access, not a new CL mechanism. Decay has a concrete cause: the code's signed mean shrinks as `0.8(0.85)^H` while payload-independent update noise accumulates, driving the sign read toward chance without any finite-step deterministic reset. This probe deliberately allocates one payload coordinate per bit and says nothing about capacity in a pretrained model.

### Prior art and triage

The [PR #6 ledger](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/idea-ledger.md), [flood triage](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-triage.md), and [flood top 10](https://github.com/manojbajaj95/cl/blob/devin/1795531716-reviewer-verdicts/reviews/flood-top10.md) already place differential committors under #5, **relearning as the read head**. Treat the basic register as a baseline, not a new card. Scope checks against #2 (Nerode quotient / observability), #3 (write-skew), #4 (rate–drift), and #7 (gauge metadata) matter: a new equivalence partition, a higher-order damage witness, a generic drift curve, or a hidden permutation tag is not the requested read/write primitive. Don't revive Noether-keyed restore (keep the key directly), Gramian plasticity reserve (signal collapsed after retention matching), sparse functional syndromes (diffuse damage), or threshold-only simulators. Compare absolute progress and itemwise old margins, not relative gain or calibration.

[Benign relearning](https://arxiv.org/abs/2406.13356) recovers ostensibly unlearned behavior, [MAML](https://arxiv.org/abs/1703.03400) writes an initialization for fast adaptation, [dataset distillation](https://arxiv.org/abs/1811.10959) can put content in the update examples, and [DeepSigns](https://arxiv.org/abs/1804.00750) reads designed codes from network responses. They make fast relearning, trained challenges, or deliberate latent codes insufficient novelty claims on their own. The tighter bet is **selectively writable old content that remains identifiable through a public success-only training interface where the matching forward or simple adaptation controls fail**. The analogues below are nearest starting points for falsification, not exhaustive novelty clearance.

## Raw ideas (24)

### A. Isolate what a training read can observe

1. **Depth-selective write.** *Mechanism:* optimize two installs to match public logits and all success flags through step `t−1`, but swap which legal curriculum succeeds at step `t`. *Why it might be new:* [PR #104](https://github.com/manojbajaj95/cl/pull/104) identifies distinctions exposed by edits; this asks for a writable separation by minimum training depth on fixed real batches, not a new equivalence relation. *Cheapest first test:* enumerate depth-1 versus depth-2 protocols in a two-layer linear net; compare raw public logits, parameter gradients where accessible, and one-step forks. *Old-task retention:* decode a held-out old rule after an unrelated suffix; measure all unrelated old losses at the same new gain.
2. **Midpoint splice read.** *Mechanism:* run two public warm-ups; apply the same terminal batch to each warm-up state, then on a spare copy swap weights or optimizer buffers between warm-ups to locate which intermediate state carries the read distinction. *Why it might be new:* [model stitching](https://arxiv.org/abs/2106.07682) splices representations for prediction; a causal splice here tests which evolving state is necessary for a writable content channel. *Cheapest first test:* two-block MLP with and without optimizer reset; match terminal gains before ablation. *Old-task retention:* require the decoded held-out old labels to follow the implicated carrier after unrelated adaptation, while untargeted tasks survive.
3. **Train-versus-apply challenge.** *Mechanism:* pair a live-gradient fork with a control that applies a cached first update of identical size on the same public batch, and write a bit into only their later divergence. *Why it might be new:* [linearized training](https://arxiv.org/abs/1902.06720) predicts trajectories; this uses a controlled departure from linearization as the readable object. *Cheapest first test:* two steps on a tiny factorized network, with gradient norm and initial logits matched; compare to direct Hessian-vector reads. *Old-task retention:* require discrimination to predict the old rule, not just curvature, on unseen queries and after fresh distractors.
4. **Multi-basin coalescent read.** *Mechanism:* target two stable public minima with similar scores on the training batch but different scores on a common fixed public exam; use the complementary curriculum to swap the favored basin. *Why it might be new:* [MAML](https://arxiv.org/abs/1703.03400) accelerates fitting; here information survives in a basin assignment even when allowed both fixed long reads and a fast-reader rival. *Cheapest first test:* use a tiny nonlinear regression with two minima and initial public margins matched, then run both forks to a convergence tolerance and compare early scores. *Old-task retention:* measure whether unrelated live training changes basin votes before or after old held-out service is lost.
5. **Forward identifiability as a compiler limit.** *Mechanism:* build the smallest same-input forward transcript that reconstructs the declared fork success flags, and exclude those flags from claims of fork exclusivity. *Why it might be new:* observability closure in [PR #104](https://github.com/manojbajaj95/cl/pull/104) is about future edits; the compiler here asks how many content bits genuinely require training relative to an implementable forward API. *Cheapest first test:* solve the linear SGD recurrence and compare reconstructed flags against the probe; seek a failure on a factorized net with identical public functions. *Old-task retention:* measure when the reconstructed and real flags predict different held-out old losses after the same continuation.
6. **Public-example substitution.** *Mechanism:* write for an equivalence class of public batches that share a declared task relation but not examples, and generate the actual fork batches after installation. *Why it might be new:* [dataset distillation](https://arxiv.org/abs/1811.10959) permits optimized examples carrying the answer; successful substitution would locate information in the write rather than in a particular challenge sheet. *Cheapest first test:* use fresh examples from two arithmetic tasks with input bases randomized independently of the message; compare canonical batches and generic fast adaptation. *Old-task retention:* decode old functions on unseen inputs after swapping the basis and a distractor stream.

### B. Make registers writable, not just detectable

7. **Overwrite without read-before-write.** *Mechanism:* find two fixed update procedures for setting one addressed slot to 0 or 1, working across all initial values of that slot and its neighbors. *Why it might be new:* [Nerode synchronization](https://github.com/manojbajaj95/cl/pull/108) merges histories; a successful fork-register setter merges histories only in the addressed bit while preserving the others and using a public reader. *Cheapest first test:* enumerate all eight initial states and both setters in a three-slot nonlinear learner. *Old-task retention:* evaluate all non-addressed old rules after each set and report stale-slot errors, not just target success.
8. **Write-once soft registers.** *Mechanism:* restrict writes to nonnegative updates or strictly increasing training exposure, then choose distributed codewords so multiple new values can be written without reversing that physical quantity. *Why it might be new:* write-once memory codes are classical (and in PR #6's next tier); the live constraint here is monotone learner updates with a success-only read, not direct cell visibility. *Cheapest first test:* enumerate two-write codebooks for four monotone coefficients and public threshold forks; compare to direct cell coding. *Old-task retention:* leave a separate old task live, test its loss after each overwrite, and test other slots between writes.
9. **Fork-addressed compare-and-set.** *Mechanism:* make a public updater commit only if its paired success flags identify the expected old value; derive a new candidate on a copy and reject it on an ambiguous read. *Why it might be new:* compare-and-swap and PR #6's MVCC proposals are prior; this asks whether the compare and the update can be implemented without materializing a separately stored value. *Cheapest first test:* interleave two writers on a two-rule MLP and include stale expected values; compare to an explicit bit with a lock. *Old-task retention:* audit false commits, non-target rule accuracy and correct old behavior whenever the write is rejected.
10. **Logical complements with different physical footprints.** *Mechanism:* allow several installations for each bit, chosen based on the interference they cause to the live learner, while demanding identical decoded old content from all of them. *Why it might be new:* classic [DPC](https://arxiv.org/abs/2507.17427) pre-cancels known interference; here the selectable variants must stay equivalent under the same deployed read after future writes. *Cheapest first test:* enumerate norm-matched variants for four messages on MLPs with a shared bottleneck; choose by held-out non-target loss, compare to equally many direct edit variants. *Old-task retention:* track the last and first rules independently under later writes never used for variant selection.
11. **Copy by training response.** *Mechanism:* feed a recipient only the donor's success flags on public challenges, then seek a recipient write giving the same useful read under a structurally different challenge bank. *Why it might be new:* distillation and the [executable header](https://github.com/manojbajaj95/cl/pull/53) transfer predictions or self-descriptions; this is transport of a newly written old computation across different read interfaces. *Cheapest first test:* transfer a Boolean rule from a linear-in-features donor to a small MLP; compare to sending the decoded bit string and training on matched public tokens. *Old-task retention:* test recipient's prior rules and donor-rule generalization after separate unrelated suffixes.
12. **Reversible training instruction.** *Mechanism:* encode a bit in whether a public sequence and its approximate inverse restore a public exam floor; constrain the live writer so ordinary predictions and single directions are matched. *Why it might be new:* reverse-edit compensation in [PR #88](https://github.com/manojbajaj95/cl/pull/88) targets undo; here failure of restoration is intentionally writable content, not unintended damage. *Cheapest first test:* match standalone updates on a small bilinear host and compare a round-trip success flag against direct order effects and raw update products. *Old-task retention:* test the read after unrelated live steps, and verify that the live learner's old tasks were never subject to the round trip.

### C. Spend the finite read budget on useful distinctions

13. **Class-specific erasure flags.** *Mechanism:* use L-only/R-only for data, neither for common degradation, and both as an explicit invalid outcome; refuse to decode rather than forcing a sign. *Why it might be new:* erasure codes are classical, but the question is whether a writable fork interface can transform otherwise undetectable old-answer errors into useful abstentions without payload labels. *Cheapest first test:* add common threshold drift and true sign reversals to the linear host; compare against a margin-abstaining direct read and replicated forks. *Old-task retention:* report selective risk, coverage, and non-target old accuracy at fixed service coverage.
14. **Noise-balanced physical placement.** *Mechanism:* choose code directions to decorrelate errors across forks under later training, even when the individual payload bits are equally accurate. *Why it might be new:* [functional syndromes](https://github.com/manojbajaj95/cl/pull/24) assumed sparse damage; this uses dense, measured cross-fork noise to improve block decoding, not sparse damage recovery. *Cheapest first test:* compare initially equal-margin codebooks under shared low-rank and isotropic distractor SGD, at equal compute and code bytes. *Old-task retention:* require more fully recovered old rule sets, not only better marginal bit accuracy.
15. **Counterfactual precision swap.** *Mechanism:* give one fork multiple resamples while the rival gets one; choose the resampled coordinate using estimated disagreement from prior public runs, never a per-write hint. *Why it might be new:* best-arm identification is classical; the research question is whether sampling effort can be shared across many old tasks given common training-induced uncertainty. *Cheapest first test:* shared-noise toy with one nuisance variable per live state; compare static allocation and standard pure-exploration policies. *Old-task retention:* report taskwise worst-case error and abstentions at identical fork execution count after new training.
16. **One old answer, many bits never read.** *Mechanism:* write a compressed representation of an old function so a public query address selects a few fork success flags sufficient to answer it without recovering the whole payload. *Why it might be new:* locally decodable codes are prior; a successful instance needs local *training* addresses despite dense shared-parameter drift and must beat a direct sparse read. *Cheapest first test:* four old linear rules, coordinate versus randomly mixed public tasks, a two-fork budget per query. *Old-task retention:* score worst-address held-out accuracy and repeat after each new write, not only the mean over easy addresses.
17. **Certified absence without reading contents.** *Mechanism:* distinguish “slot never written” from “written slot now below decode confidence” using a public third fork that detects write presence but does not encode the value. *Why it might be new:* membership filters or explicit validity tags already solve absence; the stronger claim is a joint write/read interface where the detectable presence survives failure of the value channel. *Cheapest first test:* mix blank, live, and drifted installs blinded to the decoder; compare to a budget-matched tag plus replay. *Old-task retention:* count false erasures and false old answers separately, including histories with similar new progress.
18. **Progress-invariant differential read.** *Mechanism:* place bits in fork success patterns unchanged as a common new-task feature improves, without demanding fixed individual fork scores. *Why it might be new:* continual invariance in [OGD](https://arxiv.org/abs/1910.07104) protects predictions; here the write protects the equivalence class of a coarse test under controlled progress. *Cheapest first test:* balance two public success thresholds against a common nuisance direction in an MLP and compare projected writes and forward-rank controls. *Old-task retention:* audit old service at several matched new loss levels, and under an out-of-family drift that should break the code.

### D. Stress the notion of a useful training-only carrier

19. **Cross-write calibration transplant.** *Mechanism:* evaluate or calibrate hard success thresholds only on other writers' states; constrain writers to agree on public continuous score summaries while exchanging the bit-bearing outcomes on held-out challenges. *Why it might be new:* [counterfeit footprints](https://github.com/manojbajaj95/cl/pull/107) show assay insufficiency; transplanting calibration tests whether a code is genuinely shared across independently trained writers. *Cheapest first test:* learn on some initializations and task orders, freeze the public exams, and try two unscreened initializations. *Old-task retention:* verify that unseen installed old rules decode after training without per-initialization calibration and preserve untouched rules.
20. **Semantic collision benchmark.** *Mechanism:* deliberately choose old rules that a public fork bank confuses despite equal install quality, then test whether a permitted rewrite can split their codes without adding a new probe. *Why it might be new:* [PR #110](https://github.com/manojbajaj95/cl/pull/110) certifies full-state merges; this asks for an actionable recoding test for reversible assay collisions, not another merge classifier. *Cheapest first test:* select two rules in a linear assay nullspace and retarget a nonlinear writer with a fixed bank; include a true merge as the impossible control. *Old-task retention:* test discriminating unseen old queries and check the rewrite does not displace other rules.
21. **Forward-to-fork handoff.** *Mechanism:* write a rule to be served ordinarily in-distribution and make the same write recoverable by success flags when a public, payload-free test detects that its normal read fails. *Why it might be new:* failure-triggered retrieval lost in the ledger; the new claim requires useful later recovery without retrieving a copy of the old answer. *Cheapest first test:* induce a representation shift in a two-view learner, compare no-fork adaptation, stored labels and an always-on fork reader at equal total budget. *Old-task retention:* measure ordinary and authorized recovery separately across shifts, including false triggers and non-target old losses.
22. **Canary intervention as a capacity adversary.** *Mechanism:* seek a legal new batch that keeps forward old margins and new-task progress matched but changes which distinct messages the fork bank can resolve. *Why it might be new:* [PR #105](https://github.com/manojbajaj95/cl/pull/105) prices drifting side information; this targets the split between content availability under ordinary inference and success-only availability at a fixed experimental budget. *Cheapest first test:* optimize a non-payload-conditioned nuisance batch over a public distribution of mock messages; validate on new message draws versus random batches. *Old-task retention:* report direct old, fork-recovered old and untouched-old accuracy, and distinguish assay failure from actual forgetting.
23. **Collateral capacity of natural installs.** *Mechanism:* first measure whether ordinary supervised old-task training makes several independently varied old rule values appear in fixed public fork transcripts; only then attempt constrained writes to amplify remaining distinctions. *Why it might be new:* benign relearning asks what can recover with more examples; this isolates a *joint*, bounded old-rule read using data that never disambiguate those rules. *Cheapest first test:* factorial old functions sharing an ambiguous public support in a two-layer net, with full public logits and gradient-matched rivals. *Old-task retention:* track unattended old rules as well as the decoded ones under an independent same-budget stream.
24. **Use a fork code to arbitrate an incompatible revision.** *Mechanism:* write which of two valid historical rules applies under a public context transition into paired success events, then ask a downstream learner to select a reusable subroutine from those events alone. *Why it might be new:* [successor features](https://arxiv.org/abs/1606.05312) transfer reward functions under fixed dynamics; this asks whether a learner can transfer the *old contextual distinction itself* without receiving it as a reward or exam label. *Cheapest first test:* use two composable Boolean modules, a public context bit that gives no old answer, and a held-out composition; compare to explicit context routing and stored answers. *Old-task retention:* require retention under the old context, correct revision under the new one, and stable untargeted rules after switching back.

## Deeper sub-questions, ranked by chance of a new primitive

1. **Is there a switchable distinction that needs more than a matched forward or one-gradient transcript?** (1–6, 19, 23.) Start with factorized learners and ordinary old installs; fix the public data and give baseline decoders access to every public logit and first-step gradient they can legally obtain. If multiple-step success still distinguishes held-out swaps and predicts unseen old behavior after later training, try training-depth-selective writes. Kill the exclusivity claim if a matched observation-only read suffices; an analytic affine witness is not enough.
2. **Can a single address support selective overwrite with no separately retained answer?** (7–12, 16.) Exhaustively cross at least three independently written rules, all old states and both overwrite values. Require correct post-drift decoding of the target and untouched slots, as well as no worse old service or new progress than direct edits. A useful setter would make the read interface composable; otherwise a discriminable whole-history fingerprint is not a register.
3. **Does the success-only read enable old service where the forward path fails?** (13, 17, 20–24.) Blindly mix absent, intact and drifted rules. Compare coverage and old-task error against direct reads, target-blind recovery, and stored labels at matched bytes and update compute. Reject improvements explained by a better drift detector or extra side information; the decoded response must change actual old decisions.
4. **What geometry limits reliable bits per fork after independent training?** (5, 10, 14–16, 18, 22.) Measure a block-error rate curve in a shared-parameter nonlinear host, not just the sum of marginal bit scores. Contrast low-rank common-mode interference with independent drift and test the linear sign-region ceiling in its valid regime. A useful new result would predict which *write constraints* buy more durable bits at matched old service and new progress; a curve showing generic decay is already anticipated by top-10 #4/#5.
