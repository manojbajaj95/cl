# Witness sets: can the experiments that refuted a shortcut keep the rule alive?

**Parent:** `tree/rl-discriminating-experiments.md` (PR #57). In its NumPy cue-vs-rule probe, every acquisition arm, oracle queries included, reached high flipped-A accuracy and then fell to chance (50-55%) on rule A after B-only fine-tuning.

**Question:** Can a *witness set* (the few experiments that refuted a shortcut) keep a rule through later learning better than equal-size replay or OGD?

**Working diagnosis (short):** A witness is a relational object: "on x, rule says y, rival says y', and the world said y". Every current memory method strips off the rival and stores only (x, y) or grad f(x). A few points pin a rule only *relative to a small hypothesis class*. A network's class is huge, so it can fit 8 stored points by memorizing them while the rule-computing features drift. Point-level anchoring is not rule-level anchoring.

Ideation only. No experiments were run for this node. The alphaXiv quota ran out on the first call, so papers were found through the Hugging Face papers API and from known arXiv ids.

## Why current approaches can't do this

| Approach | What it keeps | Why it misses the witness's content |
|---|---|---|
| Experience replay / reservoir; GDumb (Prabhu et al., ECCV 2020) | Random (x, y) | Witnesses are ~10% of the pool, so random replay of 8 points almost never holds one. Even when it does, the loss on 8 points can be fit by memorization. |
| Coreset / selection: GSS 1903.08671, bilevel coresets 2006.03875, MIR 1908.04742, forgetting events 1812.05159 | Points chosen for gradient diversity, interference, or forgettability | They select for *loss* coverage of the old task, not for *discrimination* against a named rival. No method stores which hypothesis a point rules out. |
| GEM 1706.08840 / A-GEM 1812.00420 | Inequality constraints: loss on memory may not rise | Constraints are on memory points' loss at first order. Any update that keeps those 8 losses flat is allowed, including one that rewires the rule into a lookup on those 8 inputs. |
| OGD 1910.07104 / GPM 2103.09762 / NTK overlap 2010.04003 | Gradient or activation subspace at stored points | Protects f at the stored inputs (locally, linearized). It keeps outputs at points, not the margin between rule and rival on unseen inputs. For a small MLP, B's update mostly lies outside the span of 8 gradients, and the linearization breaks over a long run. |
| Group-robust last-layer refit: DFR 2204.02937, JTT 2107.09044 | Minority (cue-conflicting) examples to reweight or refit a head | Works only if the rule features still exist. The parent's probe shows both A splits fall to ~chance (flipped and aligned), so the features are gone, not just the head. These methods are also single-task, not sequential. |
| Ideal Continual Learner 2305.00316 | The old task as a hard constraint set (all old optima) | The constraint set is the full data. It gives no account of which *small* subset carries the identifying information. |
| Spurious forgetting 2501.13453; Unforgettable generalization 2409.02228 | Diagnoses: alignment loss vs knowledge loss; some generalizations resist forgetting | They observe *which* behaviors survive and do not propose a certificate that makes a rule survive. |
| Machine teaching / teaching dimension (Goldman & Kearns 1995; nonparametric teaching 2405.10531) | Minimal sets that identify a target *within a fixed class* | This is the theory witness sets come from. It assumes a fixed, small hypothesis class. The network's class keeps changing during later training, which is exactly the continual-learning case. |
| Ledger: functional syndromes, contrastive-pair memory, self-quizzing replay (falsified/killed in PR #6) | Coded checks or paired contexts | Same-byte raw replay tied them. Any witness idea must beat same-byte replay of the same points. |

### Root cause

1. **A witness's information is relational, and memory stores it as unary.** The refutation means "hypothesis R beats hypothesis S on x". Replay, GEM and OGD keep "f(x) = y". They lose the rival S and the region of input space where R and S disagree.
2. **Identification is relative to a hypothesis class the network doesn't keep.** k witnesses identify R only among {R, S, a few others}. Later training enlarges the class the network effectively moves through (memorize-the-points, task-ID lookups), so the same k points no longer identify R.
3. **The constraint is on outputs, the damage is on features.** The probe's forgetting is feature-level (both A splits at chance). Output- or loss-level constraints at k points can't stop features being repurposed for B, because a k-point fit stays reachable from many feature configurations.

So the gap is a memory object that stores *a discrimination* (rule vs named rival over a region) and is enforced on the *mechanism*, not on k outputs.

## Raw ideas (unfiltered)

Each idea: **mechanism**; *why new*; **cheapest first test** (parent's NumPy probe unless stated: 5 seeds, B-only phase replaced by B + memory arm; retention = flipped-A and aligned-A accuracy after B, against 8 random replay points, 8 oracle-conflict replay points, and 8-point OGD, all at equal bytes and equal steps).

1. **Rival-carrying witness (x, y, S).** Store the refuted rival as a frozen small model S (here: "copy the cue"). During B, the loss is not CE on x but a margin: log p(y|x) - log p(S(x)|x) must stay above its pre-B value. *Why new:* replay stores no rival, so it can't tell "kept the rule" from "kept the label by memorization". **Test:** 8 witnesses + rival margin vs 8-point replay; gate ≥10 pp flipped-A gain.
2. **Witness amplification by rival-disagreement sampling.** Use witnesses to fit R's and S's *disagreement region* (here: inputs with cue ≠ majority), then replay fresh synthetic points from that region labeled by a frozen pre-B copy. *Why new:* turns 8 points into a generator of the discrimination, not a fixed set. **Test:** 8 witnesses → region sampler → 8 fresh points per step vs 8 fixed replay points; equal per-step bytes.
3. **Witness-as-unit-test on held-out generalization.** Accept a B step only if a *perturbed* witness set (fresh inputs that keep the witness's discriminating features, change the rest) still passes. *Why new:* GEM checks the stored points. This checks the rule the points certify, so memorization doesn't pass. **Test:** rejection-sampled B steps vs GEM on the same 8 points.
4. **Mechanism pinning: protect the witness's attribution path.** At learn-time, compute which hidden units carry the R-vs-S logit difference on the witnesses (integrated gradients of the margin). During B, apply OGD/EWC only to those units' input weights. *Why new:* OGD protects output gradients at points. This protects the feature path that makes the discrimination. **Test:** path-masked projection vs full 8-point OGD at equal projected rank.
5. **Witness margin in feature space (linear probe as certificate).** Store a linear probe w on hidden features that separates R from S on witnesses plus their perturbations. During B, penalize drift of w·h(x) on perturbations. *Why new:* the probe certifies that features still encode the rule, which output constraints can't see. **Test:** probe-drift penalty vs output distillation on the same points.
6. **Adversarial resurrection check.** Periodically fine-tune a copy of the model for m steps toward S on unlabeled data. If S comes back within m steps, the rule is "loose": replay the witnesses with higher weight. *Why new:* it measures how close the rival is in weight space, not current accuracy. **Test:** resurrection-triggered replay vs fixed-schedule replay at equal replay count.
7. **Witness-induced version space in weight space.** Keep the set of weights consistent with all witnesses (approximated by an ensemble of K heads trained to agree on witnesses but differ elsewhere). Learn B only in directions where all K heads agree on A. *Why new:* projects onto the version space witnesses define, not onto the stored points. **Test:** K=4 ensemble-agreement projection vs 8-point OGD.
8. **Teaching-dimension-aware witness budget.** Pick the next witness to shrink the rival set {S1..Sn} (cue, single bits, task-ID lookup) the most, as in machine teaching, then store that set. *Why new:* witnesses are chosen against a *list of rivals*, including the "memorize these points" rival. **Test:** greedy teaching set of 8 vs oracle-conflict 8, with the same replay protocol.
9. **Memorization rival as a first-class rival.** Add a k-NN "lookup on stored inputs" model as a named rival. A witness counts only if the rule beats the lookup on a held-out perturbation. *Why new:* explicitly kills root-cause 2. **Test:** witnesses re-selected against lookup vs plain conflict witnesses.
10. **Counterfactual twin witnesses.** Store each witness as a pair (x, x') that differ only in the cue and must get the same label. Replay the *pair constraint* f(x) = f(x'), not the labels. *Why new:* an invariance that is explicitly an intervention on the shortcut variable. Contrastive-pair memory was killed for *context*. This is a weight-update constraint. **Test:** 4 pairs (8 points) invariance loss vs 8 labeled replay points.
11. **Witness-conditioned low-rank slot.** Compile witnesses into a separate rank-1 adapter that is the only parameter set allowed to change the R-vs-S margin. B training freezes that adapter and can't reach the margin direction. *Why new:* a write-protected parameter slot whose content is defined by a discrimination, not a task. **Test:** rank-1 margin slot + B vs B with LoRA on all params.
12. **Rule distillation into a symbolic shadow.** From witnesses + rival, fit a tiny program (here: majority of bits 0:3) and keep it outside the net. During B, distill from it on the disagreement region. *Why new:* the witness set is the program's certificate, so the shadow is grounded, not hallucinated. **Test:** shadow-distilled B vs replay. Also log how often the program fit is wrong.
13. **Witness entanglement with B (shared-feature test).** Before learning B, find witness-like points for B against A's rule. Train B so its own witnesses don't need A's features. *Why new:* preventive feature allocation guided by the two tasks' disagreement regions. **Test:** A-retention after B with B-witness-guided allocation vs standard.
14. **Refutation-strength weighting.** Weight each witness's replay by how strongly the pre-B model's rival margin depended on it (leave-one-witness-out margin drop). *Why new:* weights by information about the rival, not loss or gradient norm. **Test:** weighted vs uniform witness replay at equal steps.
15. **Witness "half-life" scheduling.** Track each witness's rival margin during B. Replay a witness only when its margin decays below a threshold (spaced repetition on a discrimination). *Why new:* the trigger is the rival margin, not the loss (the ledger's forecast-weighted selection used loss). **Test:** margin-triggered vs uniform replay at equal replay count.
16. **Rival-gradient anti-projection.** During B, remove the component of the B gradient that *increases* S's agreement with the model on the disagreement region (projection against a rival direction, not onto a protected subspace). *Why new:* OGD protects A outputs. This blocks movement toward a named wrong hypothesis while leaving A's other outputs free. **Test:** anti-rival projection vs OGD at equal compute.
17. **Witness ensembles across seeds as a test of identity.** If witnesses truly identify R, models trained from different inits on witnesses + B should agree on A. Use cross-seed disagreement on A as a training signal during B (co-distill only on A's disagreement region). *Why new:* agreement among independent learners as a stand-in for "the rule is pinned". **Test:** 2-seed co-distillation on the region vs single-model replay.
18. **Witness-preserving merge.** Train B in a separate copy, then merge (task arithmetic) and pick the merge coefficient by the witness rival margin, not A accuracy. *Why new:* witnesses as the model-selection criterion for merging. **Test:** witness-margin-selected merge vs replay-selected merge with 8 points each.
19. **Rule-level KL on a witness-defined manifold.** Fit a density over witness perturbations (keep discriminating bits, randomize the rest). During B, minimize KL to the frozen pre-B model on samples from it. *Why new:* function-space regularization (as in FROMP / functional EWC) restricted to the discrimination manifold that witnesses define. **Test:** manifold-KL vs random-input KL at equal sample counts.
20. **Witness compression into a "why" token.** For an LLM: keep witnesses as a short in-context trace ("on x the cue said y', the answer was y") and train with it as a frozen prefix (context distillation) during B. *Why new:* stores the refutation trace, not the label. **Test (LLM, GPU):** Qwen-scale cue-vs-rule synthetic task; prefix-distilled B vs equal-token replay. Must include the ledger's temperature-matched and same-length filler arms.
21. **Witness-guided pruning of the shortcut feature.** Use witnesses to locate the cue feature (where S's prediction is read out) and zero or freeze it before B, so B can't re-recruit it for A. *Why new:* deletes the rival's mechanism, where other methods protect the rule's. **Test:** ablate top-k cue units vs no ablation, with replay held fixed.
22. **Two-timescale witness slow weights.** Witness replay updates only slow weights. B updates fast weights that decay toward the slow weights. *Why new:* the slow pathway's content comes from refutations only. **Test:** slow-witness/fast-B vs single-timescale + replay.
23. **Witness margin as a reward for B's own data selection.** Choose B training batches (from B's pool) that least shrink A's rival margin. *Why new:* the old task's witness set steers curriculum selection for the new task. **Test:** margin-aware B batch selection vs random B batches, equal steps, check B accuracy too.
24. **Certified witness radius.** Compute a Lipschitz/IBP bound on how far weights can move before any witness margin flips. Clip B's steps to stay inside that ball in the subspace that matters for the margins. *Why new:* certified retention defined by discriminations rather than losses. **Test:** clipped B vs unconstrained B: B accuracy cost and flipped-A retention.
25. **Witness-set transfer across tasks (meta-witness).** Train a small net to predict, from a task's witnesses, which parameters to protect. Train it on many cue-vs-rule pairs. *Why new:* learns a witness → protection map. **Test:** held-out rule family; predicted mask vs 8-point OGD mask.
26. **Re-refutation on wake.** After B, spend k queries re-running the stored experiments against the current model's *current* rival (refit S on the model's errors). Store new witnesses only where the rival changed. *Why new:* the witness set is maintained against a moving rival. **Test:** k=8 re-queries after B vs 8 extra replay points; retention after a third task C.

## Ranked deeper sub-questions

1. **Does adding the rival to the memory (ideas 1, 10, 16) beat equal-size replay and OGD on flipped-A after B?** This is the cheapest direct test of root cause 1 (relational vs unary). Gate: ≥10 pp over 8-point oracle-conflict replay, 5 seeds.
2. **Is forgetting in the probe feature-level, and does protecting the witness's attribution path (ideas 4, 5, 21) fix what output constraints can't?** First run a linear probe on hidden features after B to check whether A's rule bits are still decodable. If they are, the problem is only the readout, DFR-style refitting already solves it, and the node shrinks.
3. **Can witnesses be amplified into a generator of the disagreement region (ideas 2, 19) so that k stored points do the work of many fresh conflict points?** Test against fresh oracle-conflict sampling at the same per-step budget.
4. **Does including the "memorize the stored points" rival when selecting witnesses (ideas 8, 9) change which witnesses are kept and whether they last?** A teaching-dimension view of continual learning with a changing hypothesis class.
5. **Do witnesses need to be maintained against a moving rival over several tasks (ideas 6, 26)?** Retention over A→B→C with re-refutation vs static witnesses.
