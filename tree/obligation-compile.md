# Can a disjunctive behavior obligation compile to a weight edit?

Parent: [PR #52 harness-discrete-backprop](https://github.com/manojbajaj95/cl/pull/52) · Depth 3

**Root cause: a behavior refutation is not a write instruction.** The verifier says which outcomes would pass; the model's writable parameters determine which combinations of outcomes can actually change together.

## Question

Given a finite behavior obligation with alternative ways to pass, a set of old behaviors to protect, and a declared edit family, can a compiler return either a checked weight edit or a checked refutation that tells us what new write access would help? The same persistent edit must work across all inputs and calls in scope. The useful failure is not “try another layer”; it is “here is what the current write family cannot move, and here is an extension that demonstrably can,” or an honest `UNKNOWN` about the extension.

Pointwise SFT enforces per-input constraints with a Lagrangian; its multipliers are not a diagnostic specifying an extension to the writable family. |

## Root cause

There are two different losses of information. **Target selection** replaces a union of passing behaviors with one selected target. Rejecting that target, or fitting a compromise across targets, cannot refute the union. Symbolic repair need not select prematurely; enumeration or MILP already fixes this part on suitable models. **Write diagnosis** is the open part: even a complete refutation identifies conflicts among constraints, not a writable change that relieves them without breaking old behavior. The edit-to-behavior map may bend across activation patterns or change which rollout is executed. A missing first-order direction may not suffice on the real model, and a first-order zero need not imply nonlinear impossibility.

## An exact formulation

Let `Δ` be one shared weight edit, `E` its declared family and budget, `f(Δ)` the measured behavior on a finite obligation panel, and `P(Δ)` the protected behavior changes. Use exact preservation here for clarity; margin-based retention can instead be imposed as inequalities. The obligation is:

> Find `Δ ∈ E` with `P(Δ) = 0` and `f(Δ) ∈ ⋃ₖ Cₖ`.

Each `Cₖ` is a jointly passing branch, not necessarily a single target. For a stream of obligations the logic is **AND over instances, OR over each instance's passing alternatives**, all under the same `Δ` when a joint write is required. In the exact affine case (e.g. a frozen feature map with an editable linear readout), write `f(Δ) = f(0) + JΔ`, `P(Δ) = HΔ`, and let `B` span the intersection of the writable subspace and `ker H`. With `Δ = Bz`, each polyhedral branch gives `Mₖz ≥ bₖ`, including any linear edit-budget inequalities. A passing pair `(k,z)` is a primal certificate. A complete refutation gives a checked tuple of Farkas witnesses: for **each** branch, `yₖ ≥ 0`, `Mₖᵀyₖ = 0`, and `bₖᵀyₖ > 0`. Use exact arithmetic or certified bounds for the checker. Missing a branch means `UNKNOWN`, not `INFEASIBLE`.

**From dual to write request.** For a pure span failure with branch constraints `AₖJΔ ≥ bₖ`, pull the conflict back as `qₖ = JᵀAₖᵀyₖ`. It is orthogonal to `span(B)`. In a declared reference write space `U` containing `span(B)`, project `qₖ` into `(U ∩ ker H) ∩ span(B)⊥` (Euclidean coordinates here). A nonzero projection breaks that dual's annihilation and ranks directions to try; it does **not** break every possible dual or prove feasibility. If the refutation uses budget constraints, separate their contribution: the conflict may call for more budget, not another direction. In a rank-one or adapter dictionary, score only admissible atoms and then **re-solve with the enlarged family**; claim minimality only against an explicit cost and a matching lower bound. For a single obligation, an extension need only enable one disjunct. Across a family, a shared extension may use different disjuncts for different obligations; merely hitting the current duals does not prove that it works.

**Analytical sanity check.** Take `Δ = (x,y,z)`, protect `z = 0`, and allow only the `x`-axis initially. One branch needs `y ≥ 1`, the other `z ≥ 1`. Both are refuted in the original family. Only the first has nonzero pullback in the retention-safe extension space; adding the `y`-axis and checking `(0,1,0)` suffices. Conversely, if a target and protected input share exactly the same frozen feature and demand different outputs, every linear readout changes them together. No readout direction can fix the alias; a feature split or changed contract would need its own witness. A local Jacobian alias, unlike this exact feature alias, is not a global impossibility proof.

For nonlinear models report which result is certified: feasibility can be checked on the edited model; refutation needs an exact model or a **sound outer bound** on reachable behavior (with all relevant activation/trace regions covered). A single local linearization only diagnoses its own surrogate unless exactness there is proved. The null space can also be a poor proxy when old behavior is defined by an inequality or a closed-loop effect. **Disconfirmation:** if full re-solving with plain branch LP/MILP/SMT, CEGIS, or equal-budget direction search matches extension quality, proof reuse, and held-out retention, the compiler is a solver wrapper, not a new learning primitive.

## Ledger constraints

- [PR #52](https://github.com/manojbajaj95/cl/pull/52) already proposes shared repair wires, feasible/refuted/unknown messages, minimum-displacement relational projection with duals, and a library of failed inverses. Its exact replay gets the same result from the same anchors. The new claim must concern **using** a checked refutation to extend, transport, or allocate write access, not producing a backward predicate or an UNSAT core alone.
- [PR #6's ledger and triage](https://github.com/manojbajaj95/cl/pull/6/files) already cover weight IR/ISA, linking, ABI, abstract interpretation, deferred-commitment weights, certified retention ([2610.40740](https://arxiv.org/abs/2610.40740)), and trace-to-weight compilation. WSP repair alone was closed; graph-matching structural rank cannot certify numeric infeasibility. Don't revive falsified key-covariance capacity or Gramian reserve as certificates.
- The guided-edits node found little upside in picking **where** to edit. Compare to random-site plus a strong data-aware operator as well as exhaustive/budget-matched direction search. Keep held-out old behavior separate from anchors used to construct the edit or certificate; price solver calls, old data, and new parameters.

## Raw ideas (no self-filtering)

Primitive/improvement labels describe the proposed operation, not novelty verdicts. All first tests below are proposals; none were run.

1. **Deficit vector — ambitious but doable · primitive:** a failed obligation issues a write-access request. Pull back branch duals, remove already reachable and protected directions, and score rank-one `(output, key)` atoms against the remainder. Unlike AlphaEdit, this outputs a proposed change to the write family, not just an update in it. **First test:** mask one necessary adapter atom in a tiny nonlinear MLP; compare rank-one additions against random and direct gradient search; audit held-out old anchors. **Likely tie:** adjoint sensitivity or column generation.
2. **Disjunct tuple and cheapest shared extension — ambitious but doable · primitive:** several refutations jointly allocate write access. Use per-branch duals to propose a minimal atom set, re-solve the AND-of-OR obligations, and certify any claimed optimum. Unlike a single-branch IIS, the extension can satisfy different disjuncts on different instances. **First test:** affine head with a three-atom dictionary and competing obligations; compare exact enumeration and greedy dual hitting, and score held-out old anchor accuracy. **Likely tie:** bilevel MILP or branch-and-price.
3. **Softmax-mass sandwich — ambitious but doable · improvement:** faster feasibility bounds, same write operation. Bound `logsumexp(allowed) − logsumexp(disallowed)` from both sides on each logit region; certify an edit or impossibility only where the bounds close the required gap. Unlike SoftEdit, no fixed proportions within the allowed set are required. **First test:** three-class affine head with dominant and competing allowed classes; compare to exact low-dimensional search and check old held-out top-1 and probability floors. **Likely tie:** ordinary DC/convex-envelope optimization; dominant branch alone need not close the gap.
4. **Lazy disjunction across updates — ambitious but doable · primitive:** store unresolved *behavior choices*, not postponed gradients. Maintain feasible regions for the remaining alternatives across versions, publish only currently certified behavior, and recompile when a later obligation eliminates a branch. Unlike deferred-commitment weights, defer semantic commitment under explicit old contracts. **First test:** affine head where a later obligation invalidates the cheapest first choice; compare eager and deferred-weight baselines and audit old disjunctive accuracy after each write. **Likely tie:** incremental SMT or just-in-time recompilation.
5. **Dual retention ledger — moonshot · primitive:** make a proof-derived cut, rather than an old example, a unit of retained memory. Eliminate old nuisance variables into valid Benders cuts over future writable coordinates; invalidate cuts when their premises change, and never equate an incomplete cut set with a retention proof. **First test:** fixed-feature stream, byte-match stored cuts against replay and test old held-out margins and accuracy after every write. **Likely tie:** exact constraint caching or replay with cheaper sufficient statistics.
6. **Realizability depth — ambitious but doable · primitive:** classify a requirement by the smallest coupled set of writable layers, with refutations of shallower families. Compare joint writes with per-layer reachable sets to separate nonlinear interaction from simply adding two independent directions. **First test:** construct a two-layer MLP with neither single-layer family sufficient under matched bounds; compare brute-force depth enumeration and check unseen old inputs after the joint write. **Likely tie:** sparse block optimization; depth might just measure parameter count.
7. **Per-branch activation pinning — ambitious but doable · improvement:** tighten solver regions without changing the update interface. For editable configurations where pinning actually makes the map affine, attach a branch-specific region guard; enumerate or soundly bound unpinned regions before declaring UNSAT. Unlike one global PRDNN-style pattern, the proof can choose a different valid guard for each alternative. **First test:** one editable ReLU block where valid branches use different patterns; compare exact MILP, then check retained accuracy on old inputs near activation boundaries. **Likely tie:** standard activation-region splitting.
8. **Proof-carrying edits with revocable premises — ambitious but doable · primitive:** deploy a write as a proof-carrying artifact with independently checkable dependencies. Ship a primal branch witness for success, duals for any claimed exclusions, and the base version and guards needed to replay those proofs; recheck only affected premises. **First test:** tiny fixed-feature model with benign and invalidating base changes; compare full re-verification and check untouched old anchors after each change. **Likely tie:** proof-carrying code and certified mechanistic edits, unless selective rechecking works across writes.
9. **Weight/tool residual compiler — moonshot · primitive:** a failed weight write can purchase a typed write in a different store. Preserve the unresolved disjunction and prove that a routed context/tool operation and the weight portion jointly satisfy it. Unlike fallback prompting, choose the store from a refutation and check cross-store effects. **First test:** aliased toy router with a versioned memory/tool flag; compare prompt fallback and pooled CEGIS; check old goals in both routing modes. **Likely tie:** orchestrated CEGIS over a larger repair menu.
10. **Counterexample-grown adapter — ambitious but doable · primitive:** turn a plantable write deficit into a new parameter slot. Instantiate a rank-one atom from the pulled-back deficit only after re-solving certifies that it buys a branch; charge rank and carry old guards. Unlike fixed-rank LoRA it grows in response to a checked obstruction. **First test:** two-task stream with planted missing direction; compare equal-rank LoRA and greedy growth and check unseen old examples after the next update too. **Likely tie:** gradient-based adapter growth or column generation.
11. **Obligation algebra for separate writes — moonshot · primitive:** combine proof objects rather than blindly adding deltas. Intersect/union preimages for AND/OR and compose writes only with a transport or noninterference proof for the second write's premises. Unlike a generic weight linker, refusal identifies the behavioral premise that failed. **First test:** two affine head edits that pass alone but conflict when merged; compare joint solving and delta addition, checking protected single-task and cross-task holdouts. **Likely tie:** rely–guarantee reasoning or contract linking.
12. **Ripple edges as constraints — ambitious but doable · improvement:** give an existing chain editor a diagnostic. Compile implications as branch constraints over shared edits; report whether a reachable change can propagate an edge without violating old edges, rather than only expanding a target list as in ChainEdit. **First test:** synthetic fact triples and a two-hop query; compare ChainEdit-style expanded targets, and test held-out paraphrases, unrelated neighbors, and old chains. **Likely tie:** standard logical repair with stronger specifications.
13. **Dual-guided layer search — ambitious but doable · improvement:** improve the search schedule, not the writer. Reuse refutations to prune provably inadequate layer spans and prioritize extensions whose pullbacks align with unmet constraints. Unlike a causal salience score, the refutation is the deliverable; the ledger reports little headroom in site choice alone. **First test:** shallow model with equivalent sites and one planted blocked site; compare random-site plus data-aware fitting at equal cost, and check old held-out margins. **Likely tie:** active-set or block-coordinate search.
14. **Adversarial obligation completion — ambitious but doable · improvement:** adversarially refine the protected set and keep all new alternatives alive. A verifier cuts edits that pass via a branch but regress an old behavior; unlike candidate-only replay, reuse a sound cut across branches where its premises hold. **First test:** toy ReLU classifier with a small hidden failure region; compare ordinary CEGIS over the same domain and audit remaining old regions plus disjoint anchors. **Likely tie:** incremental CEGIS already caches equivalent cuts.
15. **Chance-constrained disjuncts — moonshot · primitive:** a write request names the failure mode blocking a joint probability contract. Compare moment bounds (e.g. Cantelli where moments are valid) with scenario bounds under stated sampling assumptions; preserve dependence between new success and old harm. **First test:** stochastic finite router with equal mean scores and opposite tail regressions; compare expected-reward and scenario optimization, then check old-mode tail retention on independent samples. **Likely tie:** plain joint chance-constrained programming.
16. **Degree-indexed refutations — moonshot · improvement:** use certificate degree to budget solver effort. Encode a bounded polynomial/ReLU surrogate and record the lowest discovered Positivstellensatz relaxation degree (or prove a lower bound before claiming minimality). Unlike raw Jacobian rank, degree can reflect nonlinear coupling. **First test:** tiny jointly editable polynomial head; compare SOS degree to enumeration effort and check held-out old outcomes under the least-cost certified relaxations. **Likely tie:** standard SOS hierarchy diagnostics; degree may reflect encoding more than behavior.
17. **Exact alias-to-split witness — ambitious but doable · primitive:** request a particular new input or sharing split, not a weight direction, when an exact feature alias makes every shared write contradictory. Prove both the alias and feasibility after the proposed split. Unlike parent #8's generic split search, force the request to name the indistinguishable pair and the missing discriminator. **First test:** frozen head with aliased old/new inputs and one observed separator; compare feature search and head expansion, then check old variants on both sides of the separator. **Likely tie:** partition refinement or decision-tree synthesis.
18. **Router disjunction compiler — ambitious but doable · improvement:** apply the weight compiler to closed-loop tool choices. Pull `search OR ask user` backward through a finite transition spec, then fit one persistent router edit and verify its alternate continuations. Unlike independent per-call labels, both options remain alive until the joint solve. **First test:** finite tool simulator with a retry and two successful paths; compare closed-loop MILP and per-call supervision, and audit old workflows using both routes. **Likely tie:** #52 preimages plus ordinary controller synthesis.
19. **Gauge-invariant deficit — ambitious but doable · primitive:** make a write request identify an attainable *behavior* direction and lift it under an explicit metric. Compare residuals in quotient function space under function-preserving rescalings that transport the edit family, rather than comparing raw pulled-back vectors. **First test:** rescaled equivalent ReLU MLPs with corresponding writable atoms; require matching diagnosed behavior and compare old held-out accuracy after both lifts. **Likely tie:** natural gradients or ordinary invariant subspace projection.
20. **Cross-version refutation transport — moonshot · primitive:** let a negative certificate survive a base-model migration by tracking the row/feature map it needs. Recheck the transported annihilation and separation margin before admitting the refutation in the new version; don't transport by weight resemblance alone. **First test:** permute and then perturb a frozen feature map; compare full re-solving and ABI/linker approaches and check the protected holdout on both bases. **Likely tie:** proof translation or warm-start verification.
21. **Train on the compiler's refusals — moonshot · primitive:** supervise the next-obligation proposer on verified missing access, not scalar failure. Model-proposed obligations carry independent acceptance and retention contracts; feedback distinguishes unsatisfiable, fixable by an extension, and unknown so the proposer cannot succeed by making the task trivial. **First test:** stream of toy classification failures; compare failure-only sampling and active curricula; audit independent new-goal coverage and old held-out accuracy. **Likely tie:** counterexample-guided curriculum with richer labels.
22. **Obligation price certificate — ambitious but doable · improvement:** certify a resource tradeoff rather than invent a new write. For each branch, bound minimum edit norm at different retention floors and take the lower envelope; do not infer forgetting directly from a large norm. **First test:** exact quadratic head with two branches of different costs; compare norm and covariance heuristics and check if the prices forecast independent old-set accuracy at matched scale. **Likely tie:** standard Pareto optimization or parametric QP.
23. **Certified write-direction exchange — moonshot · primitive:** schedule a swap of write access under a fixed rank budget. Retire an atom only after proving the residual family can preserve active old obligations and install a replacement with a checked witness on the new disjunction. Unlike expanding adapters or a Gramian reserve proxy, the move is a simultaneous revoke/grant with a retention contract. **First test:** three-task affine stream at rank two; compare greedy add-and-prune and exact subset search; test old held-out anchors after every swap and at recurrence. **Likely tie:** dynamic basis maintenance or sparse dictionary replacement.
24. **Closest realizable obligation — ambitious but doable · primitive:** when the write family is fixed, return a certified semantic renegotiation instead of quietly relaxing a threshold. Search a priced menu of permitted edits to the spec (latency cap, preference, allowed branch), with old invariants immutable, and prove a lower bound on what must change. **First test:** finite routing spec with differently priced changes; compare MaxSAT repair and slack penalties; verify all old workflows on held-out traces after accepting a renegotiated new goal. **Likely tie:** weighted MaxSAT; the added value would be checked, reusable negotiation between verifier and writer.

## Ranked deeper sub-questions

1. **Can a pulled-back dual predict the smallest retention-safe rank-one extension that actually works in a nonlinear model?** Highest upside: it turns a refusal into a new writable operation. Compare against equal-budget direct extension search and separately verify the deployed edit; surrogate feasibility is insufficient.
2. **Can proof-derived cuts become a replay substitute across a stream of obligations?** This would make certificates a memory form, not metadata. Find a family where cut reuse survives edits and old holdouts at equal bytes, and characterize when it expires.
3. **Does realizability have a useful depth, and can a local refutation predict the required layer coupling?** Distinguish nonlinear cooperation from mere budget or rank increases; a verified need for joint access would change the unit of plasticity.
4. **Can a weight refutation compile a residual into another store with one joint certificate?** A weight/context/tool compiler would decide where learning can occur, not just route a fallback. Compare to a single solver over the same mixed menu and check cross-store retention.
5. **When can one convex solve decide a softmax-mass obligation without committing to a target?** Seek a verifiable tightness condition, and exhibit a gap case. Useful if it substantially changes the reachable scale, but most likely an optimization improvement rather than a primitive.
