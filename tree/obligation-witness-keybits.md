# Obligation witness keybits: when is one keep bit enough?

Tree path: [discrete backprop through a learned tool loop (PR #52)](https://github.com/manojbajaj95/cl/pull/52/files) → [obligation identifiability (PR #73)](https://github.com/manojbajaj95/cl/pull/73/files) → **obligation witness keybits**. Related: [witness sets (PR #81)](https://github.com/manojbajaj95/cl/pull/81/files) and [obligation inverse certificates (PR #83)](https://github.com/manojbajaj95/cl/pull/83/files). Ideation only; all tests below are proposals, not results.

## Why the parent approach fails as a general guarantee

**Root cause: the learner can synthesize evidence of what a write changes, but that does not tell it what the user or task spec permits it to change. A keep bit constrains one such obligation. It does not grant permission anywhere else, even where the same rival loses.** PR #73 correctly locates a blind spot in PR #52: target-only replay left 3 / 2 / 1 minimal repairs across the three cases, five anchors reduced each to one, and removing just the aliased anchor restored 3 / 2 / 1. That is evidence for a decisive anchor in that setup, not for a one-bit or logarithmic bound. In particular, the parent goes from pairwise disagreements between candidate outputs to the minimum feedback needed to *certify an admissible action*. Those are different objects.

Let `C` be the currently allowed target-fixing writes, `X` the old-task situations (including context when relevant), and `A_w = {x : w changes the old behavior at x}`. The old model gives the comparator, not its authority. A possible world `k` is an externally meaningful keep map on `X`; let `W` contain the maps still compatible with the evidence. In the parent's hard-retention semantics, `k(x)=1` requires the old behavior at `x`, while `k(x)=0` only removes this requirement; it neither requires a change nor labels the replacement. The safe writes in world `k` are `S(k) = {w in C : A_w ∩ {x : k(x)=1} = ∅}`. A transcript certifies a write exactly when the intersection of `S(k)` over surviving worlds is nonempty. It may leave many maps and many writes indistinguishable.

- **Wrong coverage.** Pairwise disagreement is neither the full affected set nor a reliable measure of it. Suppose both target fixes change a shared old case `z`, and they differ on `x`. Even if `x` is released, the same disagreement transcript is compatible with both fixes being safe (release `z`) or neither being safe (keep `z`). Conversely, if both fixes agree with the old model everywhere, no bit is needed even if the underlying parameters differ. Complete pointwise feedback on the affected union would decide the finite problem; complete feedback on pairwise disagreements need not.
- **Wrong unit for a logarithm.** Consider `n ≥ 2` target fixes, each changing just its own old case `x_i`. Suppose public side information guarantees exactly one case is released. Each world has one safe write. Arbitrary balanced yes/no questions about the released index would take `ceil(log2 n)` in the worst case. But a legal point question only tests whether one specific index is released. An adversary can answer keep until `n−1` queries have been asked; the last index is then deducible. All these cases are pairwise witnesses. The gap is the geometry of legal questions, not a failure of input search or binary counting. In the opposite direction one common safe action can make the cost zero for arbitrarily many worlds.
- **Wrong authority and scope.** A pre-edit model can synthesize convincing witnesses and still miss reachable old cases, conflate two contexts with opposite keep decisions, or confidently self-label stale behavior. A deterministic synthesis step given the same learner state and external transcript adds no information about which compatible world is true. A bit can imply a regional decision only by shared constraints, an explicitly scoped oracle answer, or accounted-for external evidence; neither model confidence nor repeated paraphrases supply that implication. Later writes can also reach cases not covered by a previous certificate, as the witness-sets sibling warns. This node is about what the feedback authorizes, not about making a learned representation remember the label.

**What “near minimum” should mean.** Fix admissible queries `Q`, their semantics and side information, and the required output (a safe target-fixing write, or a sound no-write certificate). For a small finite problem the worst-case point-bit optimum is the minimum-depth adaptive decision tree over `Q`: at a terminal node either one write is safe in all surviving worlds or all surviving worlds have no safe write. Otherwise pick the question minimizing one plus the greater depth of its nonempty answer branches; if no question can split the remaining worlds, that branch is uncertifiable. Free abstention would make the objective trivial; report unresolved abstentions separately. With unrestricted binary predicates, each leaf may cover a group of worlds sharing an action (or a no-write verdict), so counting *mutually incompatible actions* gives a lower bound, not counting candidate parameters, witness points or all policy maps. Expected bits under a prior and noisy feedback are different problems; report them separately from worst-case exact safety.

| Closest baseline | What must differ here |
|---|---|
| Teaching dimension / recursive teaching dimension (Goldman & Kearns; Zilles et al.) | A cooperative teacher who knows the target can encode information in *which* example is sent. Here the learner poses the question, and need only certify an action. If a teacher chooses a witness, charge that choice too. |
| CAL / query by committee / generalized binary search | With the same safe-action stopping rule these are real controls, not strawmen. A different acquisition score alone is an improvement; a new feedback object must change what a transcript can certify or cost. |
| Sample compression (Littlestone & Warmuth) | A small reconstruction set is not a small oracle transcript. Count sample identities, side information and any scope rules not already shared; distinguish communication from retained bytes. |
| CEGIS and the parent's costed active diagnosis | A verifier can find counterexamples because it already has the spec, and a witness identity may carry more than one bit. Compare against exact diagnosis on the same query language and against CEGIS only where its oracle is available, with its richer response cost itemized. |

## Raw ideas (unfiltered)

Default first test: PR #52's retrying width-six tables, with exhaustive replay of the 90 single-cell edits for scoring, plus the smallest hand-built keep-map families needed to break a claim. Fix target success, query language, shared policy assumptions and oracle access across like-for-like arms. Compare to exact point-bit diagnosis and to cost-matched greedy diagnosis, random anchors and all-keep self-labels as applicable. For richer languages compare to exact diagnosis *in that language* too, and report returned bits, transmitted query/scope description, verifier work, generation work and stored bytes separately. Old-task checks use defended old cases outside the queried set (and outside any training anchors), with stale/released cases and target success scored separately. No replay or exact enumeration used for scoring should leak into a mechanism's selector.

1. **Old-self dummy write.** *Mechanism:* include the unedited model as a witness-generation rival, not as an eligible target fix; synthesize points against it to surface unanimous damage. *Why new:* corrects PR #73's pairwise witness menu rather than changing the committee score; likely an improvement, not a primitive. *First test:* plant one unanimous veto beyond two pairwise witnesses and ask whether the correct safety verdict changes. *Retention:* evaluate held-out old pairs that use the same aliased cell and pairs that avoid it.

2. **Release-cover certificate.** *Mechanism:* attach to a proposed write a proof that its entire affected region is contained in the union of released regions; the proof may combine overlapping grants. *Why new:* CEGIS normally checks a candidate against a fixed spec; here a separate checker validates a spec assembled from scoped replies. *First test:* cover three intersecting table regions with two grants and plant a one-case hole. *Retention:* test the hole and untouched old pairs, withholding them from acquisition.

3. **Action-conflict hyperedges.** *Mechanism:* store minimal groups of worlds with no common safe action as the objects a query must break. *Why new:* pairwise CAL/committee separation misses triples such as safe sets {a,b}, {b,c}, {a,c}. A hyperedge captures why the whole group must be separated even though all pairs overlap. *First test:* compare exact point-bit depth with a selector built from the triples and a pairwise greedy selector. *Retention:* score held-out keep pairs under the terminal action of each branch.

4. **Two-channel impossibility receipt.** *Mechanism:* return surviving worlds with the same answers for every legal query and an empty common safe-action set, plus a proof of indistinguishability under the witness generator. *Why new:* extends PR #73's ambiguous world pair to a certificate about a *particular communication interface*; a triple can be necessary. *First test:* mask the shared veto from the generator, then unmask it and verify that the receipt stops applying. *Retention:* on unmasked runs test old veto cases and ordinary old goals; on masked runs score whether the system withheld unsafe commits.

5. **Obligation quotient with proof.** *Mechanism:* collapse situations only when they have both the same effect signature across allowed writes and provably equal keep status across compatible worlds. *Why new:* behavioral clustering or sample compression alone gives no authority to share an answer. *First test:* put identical signatures in two policy contexts and show whether dropping the second criterion permits a wrong commit. *Retention:* test unqueried members of both contexts, including the rare one.

6. **Transportable implication receipt.** *Mechanism:* cache a keep/release answer with the policy assumptions under which it implies another obligation; migrate it across edits only by rechecking those assumptions and the scope mapping. *Why new:* PR #73 caches witness inputs that probe a write subspace; this caches an inference licensed by the oracle. *First test:* a table refactor preserves old behavior but one context changes policy; compare stale-grant leakage to input caching. *Retention:* score old goals in preserved and newly protected contexts after the second edit.

7. **Quantified veto query.** *Mechanism:* ask whether a specified effect region contains *any* must-keep situation. A no is a release proof for that region; a yes supplies no counterexample identity. *Why new:* contrasts point queries with a CEGIS verifier that sends a counterexample; it is a one-bit universal release on a query-defined domain. *First test:* split a simple affected block and compare to point bits and a counterexample-returning oracle, charging all scope checks. *Retention:* test unqueried old situations at the block boundary and in unaffected blocks.

8. **Budgeted omission ticket.** *Mechanism:* ask whether a declared write's impact on an old-task distribution is within a public loss budget, instead of asking for full release of every affected case. Keep hard vetoes separate. *Why new:* CABA audits fixed anchors; the ticket is permission over a declared effect and budget, not a sampled pass rate. *First test:* use two equal-size effects with unequal old-goal mass; compare to point diagnosis under the same risk contract. *Retention:* report held-out old average and worst protected-group success, including rare hard vetoes.

9. **Paired causal permission.** *Mechanism:* make the question whether behavior must survive only under a named intervention (e.g. retry with tool mode clamped), not on the raw prompt alone. *Why new:* the keep decision is indexed by an intervention semantics, whereas parent contrast probes compare observations. *First test:* one visible input under two clamped modes with opposite policies; compare to logging the mode and asking ordinary point bits. *Retention:* test old rollouts for both interventions and their natural mixture.

10. **Frame-rule grant.** *Mechanism:* bind release to a footprint and require a check that the edit cannot change behavior outside that footprint; disjoint grants can then compose. *Why new:* separation logic supplies the frame rule, but the object being framed here is signed-off behavioral change, not heap state. *First test:* compose two disjoint-cell grants, then introduce cross-call aliasing that invalidates the frame. *Retention:* test held-out cross-call goals as well as old single-cell goals.

11. **Permission circuit with queried leaves.** *Mechanism:* publish a policy circuit with unresolved Boolean leaves; point decisions are outputs, and asking a leaf can resolve many outputs. *Why new:* generalized binary search ranks questions given a language; a shared policy circuit defines a new interface and makes dependencies inspectable. *First test:* compare point and leaf queries on circuits with shared versus independent leaves, charging circuit publication if not public. *Retention:* test two unqueried old goal families sharing a leaf and a family with an exception gate.

12. **Countermodel-guided query-language refinement.** *Mechanism:* start with points; use residual indistinguishable worlds to propose a bounded grammar extension (scope, mode, or predicate), with the user explicitly accepting its meaning. *Why new:* CEGIS refines a program for a given spec; this refines what the parties can ask each other. *First test:* hide one policy dimension and compare to costed logging and a fixed richer grammar. *Retention:* test unseen old goals along the added dimension and on unchanged dimensions.

13. **Admissibility-checked parity.** *Mechanism:* on publicly indexed, prevalidated policy bits, ask a parity check so one response can eliminate many worlds without transmitting a witness identity. *Why new:* coding is known; unlike ledger group-testing merges this applies only to structured authority bits, not pooled model evaluations, and wins only when a trusted oracle can compute parity cheaply. *First test:* the singleton-release table with exact point and parity decision trees, counting reads required to compute a parity. *Retention:* score unqueried must-keep old goals and ordinary old goals separately; a shorter transcript alone is not a win.

14. **Confusable-transcript code.** *Mechanism:* spend redundancy only to separate worlds whose safe action sets cannot share a final commit under a bounded answer-error model. *Why new:* classical error correction reconstructs a message; the proposed code certifies an action without recovering the keep map. *First test:* one flipped answer on a small policy family; compare with repetition and full-map coding at equal bits. *Retention:* measure exact safe old-goal commits under every allowed flip and report target completion, not just error detection.

15. **Permission-sensitive compression decoder.** *Mechanism:* reconstruct releases from a bounded set of bits plus explicit scope witnesses, with a decoder that rejects any reconstruction unsupported by its side-information assumptions. *Why new:* standard sample compression reconstructs a predictor; here the decoder reconstructs only permissions needed by candidate effects and may prove others unknown. *First test:* two policy families with the same compressed points but different authority assumptions; compare full transmitted length to a scope-list baseline. *Retention:* test old exceptions deliberately absent from the compressed set.

16. **Teacher-choice accounting harness.** *Mechanism:* give learner and teacher a fixed scope dictionary; allow the teacher to choose one scope to answer, but send its prefix code and answer explicitly. *Why new:* teaching dimension treats example selection as part of teaching; this prices that side channel for safe-action certification. *First test:* randomize the scope dictionary and compare teacher choice against teacher-blind fixed ordering and unrestricted binary queries. *Retention:* test held-out old goals not indexed by the chosen scope and old goals in a rival scope.

17. **Policy-authorized orbit grant.** *Mechanism:* ask once on an orbit representative only after proving the effect and permission semantics equivariant under a named transformation. *Why new:* data augmentation transports labels; this transports the authority to change, including a way to reject a known broken symmetry. *First test:* permute table symbols but pin one exceptional symbol; compare to augmentation without the policy premise and to point queries. *Retention:* check unseen orbit members and exceptional-symbol old goals.

18. **Cross-edit grant amortization.** *Mechanism:* plan queries over a menu of anticipated future effects; buy a scope grant now only when its proof can constrain multiple distinct writes. *Why new:* witness caching reuses discriminator inputs, whereas these grants act like reusable permission facts; compare to ordinary cache reuse, not to restarting every time. *First test:* three stages with shifting candidate sets and one common region, then remove cross-stage overlap. *Retention:* score unseen old-task pairs after every stage, with a separate score for old behaviors introduced midstream.

19. **Split-only policy audit.** *Mechanism:* when an independently logged counterexample invalidates a keep-policy region, split that region and invalidate only answers whose proof depended on the old equivalence. *Why new:* unlike the ledger's killed split-only retrieval hierarchy, the split changes which commitments are legally supported, not which paths resolve. *First test:* change one policy attribute and compare to expiry, full requery and targeted invalidation without proofs. *Retention:* test both sides with unqueried old cases, including after the next write.

20. **Scope-symmetric rollback.** *Mechanism:* make the fallback the last authorized behavior only on the affected scope, and require rollback and both resulting routes to satisfy the target before serving. *Why new:* parent disagreement routing privileges the old model inside disagreement; this asks whether permission can be localized without silently undoing the target. *First test:* one old and one new route share a table cell; compare with full snapshot restore and PR #73's router. *Retention:* exercise unqueried retry sequences that traverse the boundary in both directions.

21. **Future-effect escrow.** *Mechanism:* admit a write only with a budgeted commitment to check which of its permission proofs a named class of later writes could invalidate; stop at invalidation, not on every later disagreement. *Why new:* PR #73's obligation tokens cache assumptions lazily; escrow explicitly constrains future write compositions and prices the deferred check. *First test:* two edits are separately harmless but their composition changes an old retry path; compare to a regression token and full re-audit. *Retention:* test old goals after both stages, including the hidden composed path.

22. **Action-specific selective abstention.** *Mechanism:* when no global commit is certifiable, prove exactly which old/new modes can be served by a partial write and explicitly decline the others. *Why new:* selective prediction abstains on uncertain outputs; this computes where an *edit* can be deployed given the same authority transcript. *First test:* require a fixed minimum target coverage and compare with no-write, old-model routing and universal deployment. *Retention:* report held-out old-goal success and coverage jointly so rejecting difficult old goals cannot look like retention.

23. **Multi-authority keybits.** *Mechanism:* scope an answer by authority as well as case; issue a certificate that the required release rule (e.g. two independent owners must both release) is satisfied. *Why new:* the ledger's multi-user-memory social choice was already covered; the narrow question here is whether proof-aware queries can avoid asking a party whose answer cannot change the admissible action. *First test:* two authorities and three writes with one publicly delegated region; compare to costed active diagnosis that knows the same rule. *Retention:* report held-out old goals for each owner and for the shared veto slice.

24. **Minimal failure triad.** *Mechanism:* distinguish three reasons for no commit by attaching a different certificate: an impossibility proof over the write menu, query-equivalent worlds with incompatible actions, or a reachable effect missed by the generator. Return “unresolved” if none can be checked. *Why new:* complements the sibling inverse-certificate question (what can the port repair?) and extends the parent's two-world output to a diagnosis of where to spend the next unit of effort. *First test:* construct three tiny tables with identical observed replies and different planted causes; compare explanations with and without an independent reachability checker. *Retention:* for each corrected cause, recheck unqueried old goals after the eventual commit; for unresolved cases separately record commits withheld.

## Ranked deeper sub-questions

1. **Can a reply be a scoped release rather than a point label?** (2, 7, 10, 17) Highest chance of a new primitive: a locally checkable grant that composes with a write's effect proof. The main falsifier is paying as much to specify and verify scopes as exact diagnosis or direct checking would have cost.
2. **What is the action-certification complexity of a constrained question language?** (3, 4, 12, 14) A useful result would give lower-bound or impossibility receipts for action overlap and show when legal syntax, not search compute, dominates. If exact costed active diagnosis already gives the same useful object and bounds, keep it as a baseline, not a renamed primitive.
3. **Which bits survive a change of write, context or policy?** (5, 6, 18, 19, 21) A permission proof with narrow invalidation semantics would be new persistent CL state. The falsifier is tying same-byte cached witnesses plus direct re-audit after both matched and shifted policy stages.
4. **Can structured authority make richer bits cheap without hiding the bill?** (11, 13, 15, 16, 23) Compare policy-leaf, parity, and teacher-selected queries to exact point queries at equal oracle effort and equal side information. This is lower-ranked because off-the-shelf coding or stronger oracle access could explain the whole advantage.
