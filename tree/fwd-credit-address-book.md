# Can a learned credit address book grow with genuinely new skills?

Parent: [PR #50, forward-only](https://github.com/manojbajaj95/cl/pull/50), deeper node 3 ("allocatable, portable write addresses"). Ideation only: no experiments were run for this node.

A **credit address book** is a persistent set of addresses `a_i = (where, which direction, under what condition)`, plus a rule that turns forward evidence (score differences, activations, A/B bits) into coefficients on those addresses. The parent's version learned keys from error signatures and let an editor mint new addresses. This node asks what stops such a book from *growing* when a skill needs a direction that no entry covers, rather than re-weighting a fixed low-rank basis.

## What current approaches do, and where each stops

| Family | Evidence | Why it cannot grow with a genuinely new skill |
| --- | --- | --- |
| Static shared bases | [Universal Weight Subspace (2512.05117)](https://arxiv.org/abs/2512.05117): 1,100+ models, including 500 Mistral-7B LoRAs, share a few principal directions. [Pretraining induces a reusable spectral basis (2605.07302)](https://arxiv.org/abs/2605.07302): leading singular vectors stay fixed under fine-tuning, and tuning only spectral coefficients is competitive on GLUE at 0.2% parameters. EigenLoRAx [2502.04700](https://arxiv.org/abs/2502.04700), LoRASpace [2610.27444](https://arxiv.org/abs/2610.27444). | These results are evidence that *familiar* tasks live in the basis. They are measured on tasks the pretraining distribution already supports, so the basis is a prior over the reachable set, not a growth mechanism. |
| Maintained ZO subspaces | SubZero (2410.08989), AdaSub-ZO learns projections from finite differences ([2610.15225](https://arxiv.org/abs/2610.15225)), AIM-ZO folds forward activations into an evolving subspace ([2609.35257](https://arxiv.org/abs/2609.35257)), ZO-Act [2607.01125](https://arxiv.org/abs/2607.01125), PAMS [2611.28476](https://arxiv.org/abs/2611.28476). | The subspace tracks the *current* task's descent directions and is overwritten when the task changes. ## Root cause

**A credit address book is spanned by what the model already computes, and nothing in a forward-only loop can tell that a skill lies outside that span or create the missing coordinate.** Four specific gaps:

1. **No span-membership test.** Existing books mint a new entry on input novelty (a new prototype, task id or slot activation) or never mint at all. No method asks the question that matters for credit: *is the score residual after the best write in the current book still larger than a null?* Without that test, a book cannot tell "learn coefficients" from "grow", so it either never grows (static basis) or grows on every distribution shift (libraries).
2. **Candidate addresses come from current activations.** Every forward-observable address is built from existing quantities: outer products of current activations (AIM-ZO, ZO-Act, PAMS), pretrained singular vectors (2605.07302), existing slots (SMF) or random directions (SubZero, MeZO). A first-order write `ΔW = u xᵀ` can only read features `x` the layer already has. A genuinely new skill that needs a new hidden feature (a conjunction, a new partition of input space, a new variable binding) has *no* single-layer address in the span, and random directions find it at the rates the PR #50 probe already measured for high-rank B.
3. **No ownership, so growth and retention are decoupled.** Subspace ZO methods overwrite their basis per task; libraries isolate per task but need the boundary. No book records which skills redeem credit through an address, so a forward-only learner cannot decide whether to reuse, split or protect it. That decision is the retention mechanism.
4. **A learned minting rule is a learned optimizer.** If the address map is meta-learned on a task distribution, minting itself goes out of distribution exactly when the skill is genuinely new (learned-optimizer evidence), so a learned book is only as general as its meta-training.

A book that grows needs all four: **(a)** a calibrated residual-credit test, **(b)** a generator of out-of-span candidates that does not reduce to random search in ambient dimension, **(c)** ownership and allocation so new entries don't overwrite old ones, and **(d)** a portability check (the address still works after later writes and paraphrases). Current methods have at most one or two: ZO subspaces have a weak (b), libraries have (c) with backprop, READ/RASP have (c) with task ids, and no method has (a).

**What would falsify this:** a static learned basis at equal state and compute matches a growing book on a stream of skills that are out of span by construction (verified by an oracle projection), or random minting matches residual-triggered minting at equal growth budget.

## Raw ideas (no self-filtering)

Each idea gives the mechanism, why it is new, and the cheapest first test with a retention check. Unless noted, controls are: a static learned basis at equal persistent state, AdaSub-ZO/AIM-ZO-style maintained subspaces at equal forward budget, CaLLM-style prototype minting, random minting at the same growth rate, and oracle backprop. P = primitive, I = improvement; these are proposer labels, not verified novelty. The common testbed is the PR #50 probe extended with a hidden layer, so that some tasks are out of span by construction (an oracle projection tells which).

1. **Residual-credit minting test — P (span-membership oracle).** Regress per-question score differences from antithetic perturbations onto the book's addresses, then compare the unexplained score variance with a null from sign-shuffled perturbations of the same norm. Mint only when the residual is significant. *New:* minting triggered by credit that the book cannot explain, not by input novelty. *First test:* a stream mixing in-span and out-of-span tasks; report mint precision/recall against the oracle, then retention of A after B. Control: input-prototype minting with the same total mint count.
2. **Multiplicative address birth — P (feature creation without gradients).** Propose a new hidden unit whose input is a gated product of two existing high-credit addresses' activations (`x_i ⊙ σ(x_j)`), giving a quadratic feature absent from the activation span, then score it forward-only. *New:* candidates outside the span, generated combinatorially from the book rather than drawn at random. *First test:* a new XOR-of-features rule on top of a frozen toy MLP; compare AIM-ZO activation candidates and random new units at equal evaluations; retention on the original task with the new unit gated.
3. **Credit-sign mitosis — P (growth by conflict).** When the sign of an address's credit differs across inputs (per-question score deltas disagree), split it into two children with context-gated keys and give the conflicting inputs to the child that wins. *New:* the split trigger is credit-sign conflict inside one address; MoE splits on load and libraries split on task. *First test:* two tasks that share a direction with opposite signs only on diagnostic pairs. Compare rank+1 static growth and a random split, and measure old-task loss at matched B gain.
4. **Circuit addresses — P (two-layer address unit).** An address is a joint pair of rank-1 writes in layers l and l+k, tested for interaction: a positive score for the joint pair while each half alone scores null. *New:* the address unit is a minimal circuit, and identification uses interaction effects that a single-layer book cannot see. *First test:* a two-layer toy where the new skill needs a new hidden feature; single-layer books fail by construction. Retention is measured on A probes routed through the same layers.
5. **Kink addresses — P (move where a unit fires).** Grow addresses that shift ReLU or gate biases on existing units, carving new input partitions without new directions; the search runs over thresholds, a 1-D variable per unit. *New:* the address names a partition change, not a direction. *First test:* a new piecewise rule over old features; compare direction-only books; measure A damage from bias shifts.
6. **Credit-gated Hebbian address drift — P (two-timescale book).** Coefficients learn fast from ZO scores, while address directions drift slowly by an Oja rule on activations that co-occur with positive credit (a three-factor local rule, no reverse pass). *New:* the addresses themselves learn from forward credit, which forward versions of two-timescale fine-tuning (2609.34667) lack. *First test:* the m+1-feature teacher of 2609.34667 with one new feature; check whether the slow addresses recover it, and how much the m old features erode.
7. **ICL-delta span check — P/I.** Use the activation difference between in-context and zero-shot runs as a candidate address, and add it only if it fails the span test against the book. *New vs WSP-writes-ICL (2611.26841):* ICL is the generator, and the book grows only on its out-of-span residual. *First test:* nonce rules, half expressible by old addresses; count mints and measure retention of earlier nonce rules.
8. **Code-distance allocation — P (retention as code distance).** Each skill is a sparse codeword over addresses. A new skill gets the codeword that maximizes its minimum distance to old codewords, and the book grows when the required distance can't be met (a Gilbert–Varshamov-style trigger). *New:* a growth law tied to an interference guarantee. *First test:* 50 synthetic skills; predicted vs observed forgetting as distance shrinks, compared against a book grown by a fixed schedule.
9. **Holographic address algebra — P (compositional keys).** Keys bind by circular convolution (HRR), so a composite skill's address is predicted as `key(A) ⊛ key(B)`, and only the residual that composition can't explain mints a new address. *New:* compositional skills should cost zero new addresses. *First test:* permutation tasks, holding out compositions and their order reversals; count mints on held-out compositions (target ~0) vs new primitives (target ≥1); retention of the constituents.
10. **Behavioral late-bound addresses — P (address = contrast set).** Store each address as the smallest set of probe pairs whose outputs it flips, and re-resolve it to weights by forward search whenever the model has moved. *New:* this answers drift (2606.10929) by making the address a behavior, not a direction. *Risk:* overlap with the P19 ABI and transport work. *First test:* rotate the hidden basis after writes; compare re-resolution cost and old-skill recovery with frozen-direction addresses.
11. **Credit-hole adversary — P (anticipatory growth).** A generator searches for inputs where the best write in the book still fails, and those holes seed addresses before a task arrives. *New:* the book grows from coverage holes, not demand. *First test:* held-out compositions; steps to learn a new skill with and without anticipatory addresses; A retention when the anticipatory addresses go unused.
12. **Forward Krylov expansion — P.** Grow the book with curvature-address products `H a_i` estimated by forward finite differences on the new task's score, building a Krylov subspace from the old book toward the new task. *New:* static and maintained bases never expand along the new task's curvature. *First test:* a quadratic probe with B in the Krylov span of A's addresses; compare random growth on steps to the halfway point and on A damage.
13. **Blank-unit reserve gated by residual credit — I.** Keep zeroed neurons with zero output weights as blank addresses. Their output weights open only after they pass the residual test (idea 1) and an old-probe null. *New vs Net2Net/neurogenesis:* birth is credit-triggered and protected until verified. *First test:* a stream of rank-growing tasks; retention vs dense growth.
14. **Superposed sparse book — I.** Keep more addresses than dimensions, each nearly orthogonal and random, with k-sparse activation per input, so the compressed-sensing interference bound sets capacity. *First test:* capacity curve (skills held at 90%) vs a dense basis at equal bytes. *Risk:* this is memory layers / SMF again.
15. **Typed growth — P (key, value or route).** Three forward probes decide whether a new skill needs a new key (input distinction), a new value (output) or a new route (composition of existing entries), and only that part grows. *New:* a type system for growth. *First test:* three families of new tasks with known types; accuracy of the type classifier, and retention per type.
16. **Negative book — P (forbidden directions from failed accepts).** Directions whose acceptance hurt old probes are kept as a book of anti-addresses, and new candidates are projected away from them. *New vs OGD:* the protected subspace comes from forward accept/reject history, not old-task gradients. *First test:* rotated hidden old subspace; how many rejections it takes to beat random projection and replay at equal old-query budget.
17. **Address provenance ledger — P (ownership).** Each address records which skills redeemed credit through it, and writes to an address shared by several skills need consent probes from those skills. *Risk:* overlap with PR #50's write-nullspace negotiation, made per address. *First test:* A,B,C stream with shared addresses; retention vs unowned books.
18. **MDL minting price — I.** Mint when the bits needed to encode the skill's coefficients under the current book exceed the bits for a new address plus its coefficients. *First test:* compare against idea 1's significance threshold on the same stream; mint count, A retention.
19. **Credit-collinear fusion — I (bounded book).** Merge addresses whose credit series stay collinear across skills, paired with mitosis (idea 3), so the book breathes at fixed size. *First test:* long stream at a fixed budget; retention vs LRU eviction.
20. **Book-level evolution — P.** Evolve a population of address books, each with different minted entries, selected on acquisition × retention; weights move only through each book's coefficients. *New:* ES over the credit interface rather than over weights. *First test:* 16 books on the probe; compare weight-level ES at equal forward evaluations.
21. **Seed-addressed book — P/I.** Store addresses as (PRNG seed, layer, scale), 8 bytes each, kept from perturbations that won; the book is a compressed, replayable basis that persists across tasks. *Risk:* check differentiation from SM1 (self-readable seed log, flood top 3): here seeds are a basis that later tasks reuse, not a history log. *First test:* bytes per retained skill vs low-rank basis storage.
22. **Certified entries — I.** An address enters the book only with a randomized-sign certificate: its intended sign moves new probes, and both signs leave old probes inside their noise floor. *First test:* the share of certified entries that later cause forgetting vs uncertified ones.
23. **Address teleportation via function-preserving rescale — P.** Before minting, apply a function-preserving reparameterization that moves old skills' sensitive directions away from the candidate's coordinates, so the new address lands in a region old skills don't use. *New:* uses the gauge dependence that the model-guided-edits node flagged as a problem. *First test:* the same out-of-span task with and without a pre-mint rescale; A damage at matched B gain.
24. **Self-naming failure classes — P.** The base model sorts its own failure transcripts into named classes; a class that recurs and isn't covered by any address's credit mints one, and the name becomes the key. *Risk:* the parent's editor-mints variant. *First test:* nonce-rule stream; agreement of the classes with ground-truth rule identity, and mints per genuinely new rule.
25. **Address half-life from redemption — I.** Each address decays at a rate set by how often credit is redeemed through it, and is revived from a tombstone key when its skill returns. *First test:* an A,B,A,C,B stream; return speed vs a static book and LRU.

## Deeper sub-questions, ranked by how likely each leads to a new primitive

1. **Can a forward-only learner certify that a skill is outside its address span?** (ideas 1, 18, 22). The residual-credit test is the missing piece in every family above, it is cheap, and it is falsifiable with an oracle projection. If it works, it becomes the trigger every growing book needs.
2. **Can forward-only search create a coordinate that is not in the activation span, at cost below random search in ambient dimension?** (ideas 2, 4, 5, 6, 12). This is the hard core: without it, "growth" only re-weights features the model already has. Multiplicative, circuit and kink addresses are three concrete generators to test against random new units.
3. **Can address algebra make compositions free, so the book grows only with genuinely new rules?** (ideas 9, 15). This separates new skills from recombinations and gives a measurable growth law: zero mints on held-out compositions, at least one on new primitives.
4. **Can growth by conflict (mitosis plus fusion) replace task IDs and keep retention at a fixed book size?** (ideas 3, 17, 19). This is the allocation side; it is likely to produce a strong improvement, and a primitive only if credit-sign conflict turns out to be a reliable boundary signal.
5. **Does a learned minting rule generalize, or does it learn surface tags?** (ideas 11, 20, 24). Learned-optimizer evidence predicts failure; worth asking only after 1 and 2 produce a book worth learning.

**Shared decisive setup for every sub-question:** the PR #50 probe plus a hidden layer and an oracle span projection, a stream with in-span, out-of-span and compositional tasks, returns to old tasks, and a forward-evaluation budget matched across arms. Report acquisition at fixed retention per forward evaluation and per byte of book state.
