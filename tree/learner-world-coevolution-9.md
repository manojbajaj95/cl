Child node (depth 8) of [PR #371](https://github.com/manojbajaj95/cl/pull/371) (`L8W01` + `L8W12`) · 26 concrete mechanism cards · Ideas only; no experiments run

**Parent triage.** In `reviews/flood-triage.md` (row 514, PR #371 / `tree/learner-world-coevolution-8.md`), two score-3 mechanisms survived while pointer/eviction variants were pruned:
1. **`L8W01` — rebuild from the live guard as an oracle:** weights hold a small, fixed-size seed for a boundary-probe generator; waking queries the live guard on generated probes to rebuild the skill in one step, so *pointer size stays constant $O(1)$ as rule complexity grows* while stored rule text grows with it.

## A · Live-Guard Oracle Reconstruction (`L8W01` deepened)

### L9W01 · Active boundary-bisection probe seed (hard-label hyperplane recovery)
- **Mechanism:** Static probe batches waste queries in interior regions far from $G(x)$'s decision facets. Store a constant-size seed $z_F \in \mathbb{R}^m$ that generates $K_0$ opposing-label anchor pairs $(x_i^+, x_i^-)$ and runs $T$ rounds of binary-search bisection along connecting rays—adapting hard-label cryptanalytic sign recovery ([2609.21941](https://arxiv.org/abs/2609.21941)) to locate exact boundary facets of a black-box guard $G$ in $O(d \log(1/\epsilon))$ queries before a single distilled wake step.
- **Nearest prior / gap:** [Drag-and-Drop LLMs](https://arxiv.org/abs/2506.16406) and random probing are non-adaptive; [2609.21941](https://arxiv.org/abs/2609.21941) targets adversarial model stealing rather than continual-learning self-recovery from a compact seed.
- **Cheapest first test:** Synthetic piecewise-linear guard sweeping clause count $C \in \{4, 16, 64, 256\}$ at fixed $m=32$ float seed and fixed query cap $Q$. Compare equal-byte replay, equal-byte rule-text retrieval, Drag-and-Drop from $Q$ static probes, random probes, and bisection `L9W01`. Kill if static Drag-and-Drop or random probes match `L9W01` post-wake accuracy at $C=64, 256$.
- **Old-task retention:** Measure post-wake accuracy on all $C$-clause guards and retention of dense tasks $A, B$ after 1-step wake.

### L9W02 · Contrastive-witness query probing (exploiting structured guard diagnostics)
- **Mechanism:** Real external guards (linters, schema validators, AST checks, policy engines) return *structured violation reasons* (failing clause ID, offending field/token), not 1-bit booleans. Inspired by contrastive membership queries ([2609.32820](https://arxiv.org/abs/2609.32820)), $z_F$ seeds a mutator that perturbs one candidate feature/clause at a time and parses the guard's contrastive witness—reconstructing a $C$-clause conjunctive/disjunctive rule in $O(C)$ queries instead of $O(2^C)$ black-box queries, while keeping $z_F$ size $O(1)$.
- **Nearest prior / gap:** [2609.32820](https://arxiv.org/abs/2609.32820) studies contrastive queries for formal shuffle ideals; neither Text-to-LoRA ([2506.06105](https://arxiv.org/abs/2506.06105)) nor standard active learning exploits structured validator error traces for 1-step weight reconstruction.
- **Cheapest first test:** 20-rule JSON/AST validator suite ($C \in \{4, 16, 64\}$) where $G(x)$ returns `(pass/fail, failed_clause_span)`. Compare 1-bit oracle `L8W01`, Text-to-LoRA on equal-byte truncated rule text, Drag-and-Drop, random probes, and contrastive `L9W02`. Kill if 1-bit `L8W01` or equal-byte rule-text matches `L9W02` at $Q = 2C$ queries.
- **Old-task retention:** Verify post-wake accuracy across all 20 validators and zero regression on unrelated tasks $A, B$.

### L9W03 · Two-round active query-to-LoRA refinement (beating one-shot Drag-and-Drop)
- **Mechanism:** One-shot hypernetworks ([Drag-and-Drop](https://arxiv.org/abs/2506.16406), [SHINE](https://arxiv.org/abs/2602.06358)) map a fixed batch of $Q$ examples to a LoRA adapter in one pass, missing narrow high-complexity rule corners. Split the query budget $Q = Q_1 + Q_2$: round 1 emits coarse adapter $\Delta \theta^{(1)}$ from $z_F$'s initial $Q_1$ probes; round 2 synthesizes $Q_2$ *maximum-uncertainty / boundary-disagreement* probes using $\theta + \Delta \theta^{(1)}$, queries $G$, and updates $\Delta \theta^{(1)} \to \Delta \theta^{(2)}$—strictly beating one-shot Drag-and-Drop at identical total query count $Q$.
- **Nearest prior / gap:** [2506.16406](https://arxiv.org/abs/2506.16406) and [2602.06358](https://arxiv.org/abs/2602.06358) are strictly feed-forward over static prompt sets; they do not close an active query loop against a live oracle.
- **Cheapest first test:** Rule-complexity sweep ($C \in \{8, 32, 128\}$) at fixed total budget $Q=64$. Compare one-shot Drag-and-Drop ($Q=64$), random probes, equal-byte replay, and 2-round active `L9W03` ($Q_1=32, Q_2=32$). Kill if one-shot Drag-and-Drop matches `L9W03` post-wake F1 at $C=128$.
- **Old-task retention:** Verify post-wake F1 on all complex rules and unchanged accuracy on retained tasks $A, B$.

### L9W04 · Backbone-quotient probe generation (dimension-independent query complexity)
- **Mechanism:** Probing in raw input space $\mathbb{R}^D$ requires $\Omega(D)$ queries even when the guard depends only on a $k$-dimensional semantic subspace ($k \ll D$). Parameterize the probe seed $z_F$ to sample perturbations inside the frozen/slow backbone's top-$k$ invariant feature coordinates $\phi(x)$ and project back to valid inputs via a lightweight decoder/template—reducing oracle query complexity from $O(D)$ to $O(k)$ while keeping pointer size $O(1)$.
- **Nearest prior / gap:** Membership-query active learning ([2609.27241](https://arxiv.org/abs/2609.27241)) suffers from out-of-distribution synthetic queries in high-dimensional raw spaces; quotient-space probing keeps queries on the valid input manifold.
- **Cheapest first test:** High-dimensional input world ($D=512$, intrinsic rule rank $k=8$) sweeping $C \in \{4, 32, 128\}$. Compare raw-space probing, random probes, Drag-and-Drop, equal-byte replay, and quotient-space `L9W04` at $Q=32$. Kill if raw-space probing or random probes match `L9W04`.
- **Old-task retention:** Verify post-wake retention on $F$ and zero drift in the shared backbone $\phi$ for tasks $A, B$.

### L9W05 · Stateful guard wake via $\Lambda^*_M$-seeded distinguishing suffixes
- **Mechanism:** Single-input probes cannot reconstruct *stateful* external guards (multi-turn policy monitors, rate limiters, sequence-order validators). Store a constant-size seed $z_F$ encoding a minimal set of *state-access prefixes* and *distinguishing suffixes* for symbolic Mealy-automaton active learning ($\Lambda^*_M$, [2509.14694](https://arxiv.org/abs/2509.14694); Moore-machine extraction, [2410.06045](https://arxiv.org/abs/2410.06045)); on wake, query the live guard on prefix+suffix sequences to recover its transition table and distill it into the learner's recurrent/attention weights in 1 step.
- **Nearest prior / gap:** [2509.14694](https://arxiv.org/abs/2509.14694) and [2410.06045](https://arxiv.org/abs/2410.06045) extract automata for offline inspection; using a compact suffix seed to wake a stateful continual-learning skill from a live environment guard is new.
- **Cheapest first test:** 10 stateful finite-automaton guards (sweeping state count $S \in \{3, 8, 20\}$). Compare stateless `L8W01`, Text-to-LoRA at equal bytes, equal-byte replay, random sequence probes, and $\Lambda^*_M$-seeded `L9W05`. Kill if stateless probes or equal-byte replay match `L9W05` at $S=20$.
- **Old-task retention:** Measure multi-step sequence accuracy on all 10 stateful guards after wake and retention of prior sequence tasks $A, B$.

### L9W06 · Zero-disruption passive-log + dry-run probe scheduler (`WMX6`-accounted oracle waking)
- **Mechanism:** Querying a live production guard consumes external compute/queue load (`WMX6`). Before issuing synthetic probes from $z_F$, first score the guard's *passive organic boundary log* (recent inputs already evaluated by $G$) using $z_F$'s information-gain selector, and issue synthetic probes *only* for uncovered facets via a read-only dry-run endpoint under a strict query cap $Q_{\max}$—charging every synthetic query in the equal-byte/equal-cost comparison.
- **Nearest prior / gap:** Standard membership-query active learning ([2609.27241](https://arxiv.org/abs/2609.27241)) assumes free, side-effect-free oracles; `L9W06` enforces `WMX6`'s full external-work accounting by hybridizing passive logs with minimal dry-run queries.
- **Cheapest first test:** Simulated guard with explicit per-query latency/cost $c_q$ and organic traffic stream. Compare purely synthetic `L8W01`, purely passive replay at equal bytes, Drag-and-Drop on passive logs, and hybrid `L9W06`. Kill if purely passive replay beats `L9W06` on total cost-adjusted retention.
- **Old-task retention:** Verify post-wake retention of rare boundary clauses that organic traffic missed, plus zero degradation on $A, B$.

### L9W07 · Input-schema-anchored probe seeds (invariance to arbitrary backbone rotation)
- **Mechanism:** If $z_F$ generates probes in hidden-layer coordinates $\phi_t(x)$, 20 subsequent tasks $C_1 \dots C_{20}$ rotate $\phi_t$ and break the pointer. Anchor $z_F$ directly in the *guard's stable input schema* (canonical parameter ranges, AST grammar productions, or fixed input-space prototypes) rather than internal hidden activations—guaranteeing that $z_F$ still hits $G$'s true boundary even after 100% backbone weight rotation or base-model swaps.
- **Nearest prior / gap:** Weight-space pointers (`L7W04`/`L8W07`) require continual Procrustes tracking across feature drift; schema-anchored probe seeds are representation-free and survive arbitrary drift with zero maintenance.
- **Cheapest first test:** Train 20 sequential tasks $C_1 \dots C_{20}$ with deliberate random orthogonal rotation of hidden layers every 5 tasks. Compare hidden-space `L8W01`, Procrustes-tracked `L8W07`, Drag-and-Drop, and schema-anchored `L9W07`. Kill if hidden-space `L8W01` survives rotation or if schema-anchored `L9W07` loses >5% post-wake accuracy.
- **Old-task retention:** Verify post-wake accuracy on all 20 guards after full backbone rotation and unimpaired $C_{20}$ accuracy.

### L9W08 · Distributional conservative wake under partial oracle query budgets
- **Mechanism:** When rule complexity $C$ exceeds what the query budget $Q$ can fully identify, a deterministic 1-step update overfits the queried clauses and makes silent errors on unprobed corners. Use a distributional weight-update predictor ([2610.01934](https://arxiv.org/abs/2610.01934)) conditioned on $z_F$'s $Q$ oracle responses to sample an ensemble of $M$ plausible patches and emit a *conservative* policy that flags/defers on high-variance unprobed inputs until more queries are granted.
- **Nearest prior / gap:** [2610.01934](https://arxiv.org/abs/2610.01934) predicts update distributions for test-time adaptation; applying it to under-determined oracle probing prevents silent extrapolation failures when $Q \ll C$.
- **Cheapest first test:** Under-budgeted regime ($C=128$ clauses, $Q=16$ queries). Compare deterministic 1-step `L8W01`, Drag-and-Drop, equal-byte replay, and conservative distributional `L9W08`. Kill if deterministic `L8W01` achieves equal selective-risk / silent-failure rate at $Q=16$.
- **Old-task retention:** Measure silent violation rate on unprobed clauses, accuracy on probed clauses, and retention of $A, B$.

### L9W09 · Complexity-adaptive pointer-vs-text crossover router ($O(1)$ seed vs. Text-to-LoRA)
- **Mechanism:** At low rule complexity ($C \le C^*$), storing compact rule text and running [Text-to-LoRA](https://arxiv.org/abs/2506.06105) / [Doc-to-LoRA](https://arxiv.org/abs/2602.15902) uses fewer total resources than issuing live oracle queries; at high complexity ($C > C^*$), rule text overflows the byte cap and exhibits distractor interference ([2611.30825](https://arxiv.org/abs/2611.30825)), whereas `L8W01`'s $O(1)$ seed still recovers $G$. Measure the exact crossover $C^*$ from `(byte_budget, query_cost)` and store rule text below $C^*$ but an oracle probe seed above $C^*$.
- **Nearest prior / gap:** [2506.06105](https://arxiv.org/abs/2506.06105) and [2602.15902](https://arxiv.org/abs/2602.15902) assume all rules fit in text context; `L9W09` explicitly maps and exploits the crossover where oracle probing dominates text-to-weights.
- **Cheapest first test:** Mixed-complexity 20-rule stream ($C \in \{2, 8, 32, 128, 512\}$) under fixed byte budget + `WMX6` query cost. Compare pure Text-to-LoRA, pure `L8W01`, equal-byte replay, and crossover router `L9W09`. Kill if pure Text-to-LoRA or pure `L8W01` dominates across the entire complexity spectrum.
- **Old-task retention:** Verify post-wake accuracy across both low-$C$ and high-$C$ rules and new-task speed on $C_1 \dots C_{20}$.

## B · Compilability-Regularized Skill Training (`L8W12` deepened)

### L9W10 · Differentiable linear-region count penalty on new rule sub-networks
- **Mechanism:** Any ReLU sub-network is mathematically equivalent to a decision tree ([2210.05189](https://arxiv.org/abs/2210.05189), [2506.05834](https://arxiv.org/abs/2506.05834)), but an unregularized MLP fractures input space into $10^4+$ tiny linear regions, making exact extraction blow up. Attach a differentiable **boundary-crossing penalty** $\mathcal{L}_{\text{reg}} = \sum_{j} \mathbb{E}_{x_1, x_2 \sim \mathcal{B}}[\sigma(\beta(h_j(x_1) \cdot h_j(x_2) < 0))]$ *only* to the newly added rule sub-network $f_F$—minimizing distinct activation patterns so exact piecewise-linear extraction produces a tiny, high-fidelity deterministic check while the backbone stays dense.
- **Nearest prior / gap:** Post-hoc [NN2Rules](https://arxiv.org/abs/2207.12271) and [2111.12628](https://arxiv.org/abs/2111.12628) struggle with tangled unregularized regions; [2504.14356](https://arxiv.org/abs/2504.14356) uses slow MIP solvers on whole nets. Local region-count regularization makes exact tree extraction cheap without touching the dense backbone.
- **Cheapest first test:** 15 crisp tabular/symbolic prevention rules learned sequentially on a dense backbone. Compare no regularizer + `NN2Rules`, whole-network crystallization ([2609.33028](https://arxiv.org/abs/2609.33028)), `L7W07` alone, and region-penalized `L9W10`. Kill if `NN2Rules` without the regularizer achieves equal extracted fidelity/AST size, or if `L9W10` drops new-task accuracy >2%.
- **Old-task retention:** Measure extracted check fidelity, AST node count, new-task accuracy, and backbone retention on dense tasks $A, B$.

### L9W11 · Hard-concrete $L_0$ input-sparsity for axis-aligned / 2-variable code predicates
- **Mechanism:** Even a low-region ReLU sub-network yields dense oblique hyperplanes $\sum_{i=1}^D w_i x_i > b$ that compile to brittle, opaque expressions. Attach differentiable $L_0$ / hard-concrete feature gates *only* to the first layer of each new rule sub-network $f_F$, penalizing fan-in $> 2$ per hidden unit—forcing every learned neuron boundary to compile directly into a human-auditable 1- or 2-variable predicate (`x_i > t` or `x_i - x_j > t`) before eviction.
- **Nearest prior / gap:** Standard [NN2Rules](https://arxiv.org/abs/2207.12271) extracts dense oblique inequalities or loses fidelity when approximating them with axis-aligned splits; training-time fan-in sparsity aligns the neural boundary with deterministic code syntax from the start.
- **Cheapest first test:** 15 rules (mix of axis-aligned and pairwise-comparison guards). Compare unregularized `NN2Rules`, whole-network $L_1$, and fan-in-sparse `L9W11`. Kill if `NN2Rules` matches `L9W11`'s extracted fidelity at equal code length (AST tokens).
- **Old-task retention:** Verify 100% dense backbone retention on $A, B$, <1% accuracy cost on new rules, and strictly smaller/higher-fidelity extracted checks.

### L9W12 · Differentiable logic-gate sidecar sub-networks (`DLGN` / `DLN` heads on a dense backbone)
- **Mechanism:** Rather than coercing an MLP head into logic via soft penalties, instantiate each newly learned crisp rule sub-network $f_F$ directly as a small *Differentiable Logic Gate Network* ([2210.08277](https://arxiv.org/abs/2210.08277), [2407.04168](https://arxiv.org/abs/2407.04168)) with thresholded input predicates, sitting beside the dense backbone. At compile time, apply task-aware discretization ([2609.33747](https://arxiv.org/abs/2609.33747)) to export $f_F$ as an exact Boolean circuit with **zero extraction fidelity gap**, then delete the sidecar to reclaim 100% of its parameter budget.
- **Nearest prior / gap:** [2210.08277](https://arxiv.org/abs/2210.08277) and [2407.04168](https://arxiv.org/abs/2407.04168) replace the *entire* model with logic gates (hurting dense perceptual tasks); using DLGN strictly as an evictable *new-skill sidecar* preserves full dense backbone capability while giving lossless compilation.
- **Cheapest first test:** Mixed stream of 10 dense perceptual tasks + 15 crisp rule skills. Compare unregularized MLP + `NN2Rules`, whole-network DLGN (fails dense tasks!), `L8W12` ReLU regularizer, and DLGN sidecar `L9W12`. Kill if whole-network DLGN matches dense-task accuracy or if `NN2Rules` matches `L9W12`'s zero-gap fidelity.
- **Old-task retention:** Verify zero degradation on the 10 dense tasks, 100% fidelity on the 15 compiled circuits, and full parameter-budget recovery.

### L9W13 · Two-phase dense-to-crisp temperature annealing (eliminating the `L8W12` accuracy tax)
- **Mechanism:** Applying a strong piecewise-linear / sparsity regularizer from step 0 traps $f_F$ in poor local minima, paying the exact *new-task accuracy cost* row 514 warns about. Train $f_F$ unregularized for phase 1 until training loss plateaus, then run phase 2: smoothly anneal activation sharpness $\tau \to 0$ and region-count weight $\lambda \to \lambda_{\max}$ while tracking held-out accuracy, halting annealing at the Pareto knee ($\le 0.5\%$ accuracy drop) before running code extraction.
- **Nearest prior / gap:** Static regularization (`L8W12` baseline) and whole-network crystallization ([2609.33028](https://arxiv.org/abs/2609.33028)) trade off learning accuracy against extractability; two-phase annealing gets dense optimization dynamics during acquisition and crisp structure right before eviction.
- **Cheapest first test:** Sweep regularizer strength $\lambda$ on 15 multi-clause rules comparing static `L8W12` (from step 0), `NN2Rules` (no regularizer), and annealed `L9W13`. Kill if static `L8W12` achieves the same accuracy-vs-AST-size Pareto frontier as `L9W13`.
- **Old-task retention:** Verify new-rule accuracy matches unregularized baseline while extracted check size shrinks by $\ge 5\times$ and dense tasks $A, B$ stay intact.

### L9W14 · Observable-predicate bottleneck with training-only backbone hints (standalone executable extraction)
- **Mechanism:** If $f_F$ reads evolving backbone hidden states $\phi_t(x)$, the compiled external check $A_F$ breaks as soon as $\phi_t$ changes on future tasks. Constrain $f_F$'s input layer to read *only* observable raw/schema features (making $A_F$ 100% standalone), while letting the dense backbone supply *training-only* auxiliary gradient/distillation hints that are detached and annealed to zero before extraction—gaining backbone transfer during learning without coupling the compiled artifact to backbone weights.
- **Nearest prior / gap:** Standard neural rule extraction ([2312.12878](https://arxiv.org/abs/2312.12878)) extracts rules over internal embeddings that break under continual drift, or forfeits backbone transfer entirely; training-only hint annealing gives both.
- **Cheapest first test:** 15 rules trained on a drifting backbone over 20 forward tasks $C_1 \dots C_{20}$. Compare hidden-state-dependent extraction (breaks on $C_{20}$), standalone no-hint training (slower learning), and hint-annealed `L9W14`. Kill if no-hint training matches `L9W14` learning speed or if hidden-state extraction survives $C_{20}$ drift.
- **Old-task retention:** Verify 100% standalone validity of all 15 compiled checks after $C_{20}$ and full dense-backbone plasticity.

### L9W15 · Compilability-probe router (auto-sorting crisp vs. fuzzy skills before regularization)
- **Mechanism:** Applying `L8W12` blindly to fuzzy/perceptual skills destroys their accuracy and wastes compilation effort. For every incoming skill $F$, run a cheap 2-epoch *compilability probe*: measure validation-loss sensitivity $\Delta \mathcal{L}_{\text{val}}$ when toggling the piecewise-linear regularizer (`L9W10`). Route low-sensitivity skills ($\Delta \mathcal{L}_{\text{val}} < \delta$) to a compilable sub-network destined for extraction+eviction, and high-sensitivity fuzzy skills directly to standard dense weights.
- **Nearest prior / gap:** `L8W12` assumes the caller already knows which skills are crisp; `L9W15` automates the crisp-vs-fuzzy boundary per skill at negligible probe cost.
- **Cheapest first test:** Unlabeled mixed stream of 10 crisp symbolic rules + 10 fuzzy perceptual tasks. Compare always-regularize (`L8W12` everywhere), never-regularize (`NN2Rules`), and probe-routed `L9W15`. Kill if always-regularize matches `L9W15` on fuzzy-task accuracy or never-regularize matches on crisp-rule extraction size.
- **Old-task retention:** Verify high accuracy across all 10 fuzzy tasks, clean compilation+eviction of all 10 crisp rules, and faster task-20 learning.

### L9W16 · Monotonic lattice regularization for statically verifiable extracted guards
- **Mechanism:** Extracted code checks for safety/prevention rules often need formal guarantees (e.g., larger threshold violations must never flip a guard from reject to accept). Regularize $f_F$ toward a *min-max lattice / partially monotonic piecewise-linear function* ([2506.05834](https://arxiv.org/abs/2506.05834)) by penalizing negative input-gradient signs on monotonic risk dimensions—so the extracted deterministic check is both compact and *verifiably monotonic* by syntactic inspection alone.
- **Nearest prior / gap:** [2506.05834](https://arxiv.org/abs/2506.05834) characterizes lattice representations of neural networks; using lattice regularization selectively on evictable prevention sub-networks guarantees safety invariants survive compilation without expensive SMT verification.
- **Cheapest first test:** 10 monotonic safety-threshold rules with noisy training labels. Compare unconstrained `NN2Rules`, `L8W12` without monotonicity, and lattice-regularized `L9W16`. Kill if unconstrained `L8W12` produces zero monotonicity violations under adversarial boundary testing.
- **Old-task retention:** Verify 0% monotonicity violations on all 10 extracted checks, high rule accuracy, and zero impact on non-monotonic dense tasks $A, B$.

### L9W17 · Periodic extraction-in-the-loop fidelity co-training
- **Mechanism:** Sparsity regularizers are only an *indirect* proxy for extractability—a sparse net can still disagree with its extracted rule list on critical corner cases. Every $E$ epochs during $f_F$'s training, run fast decompositional extraction (`NN2Rules` [2207.12271] or local search [2201.06863]) to produce candidate code $\hat{A}_F$, find high-disagreement inputs $x_{\text{diff}}$, and add a **fidelity-alignment loss** $\mathcal{L}_{\text{fid}}(f_F(x_{\text{diff}}), \hat{A}_F(x_{\text{diff}}))$—explicitly training $f_F$ toward functions that lie *exactly* in the image of the compiler.
- **Nearest prior / gap:** [2201.06863](https://arxiv.org/abs/2201.06863) extracts programmatic policies post-hoc; putting the extractor *inside* the training loop closes the neural-to-symbolic fidelity gap directly.
- **Cheapest first test:** 15 complex branching rules comparing post-hoc `NN2Rules`, static `L8W12` regularizer, and extraction-in-the-loop `L9W17`. Kill if static `L8W12` matches `L9W17`'s extracted-vs-neural fidelity gap (<0.5%) at equal AST size.
- **Old-task retention:** Verify <0.5% extraction gap across all 15 rules, preserved dense-task accuracy on $A, B$, and clean plasticity recovery after eviction.

### L9W18 · Isolated sub-network excision (exact capacity reclamation without unlearning collapse)
- **Mechanism:** Evicting a compiled skill from shared weights via gradient ascent causes plasticity collapse ([2608.29513](https://arxiv.org/abs/2608.29513)) and risks damaging retained tasks. Because `L8W12` trains each compilable rule inside a dedicated, sparsely-coupled sub-network $f_F$ gated onto the dense backbone, eviction after compilation is simply **structural excision**: delete $f_F$'s weights and recycle its exact parameter slot for the next incoming skill—achieving 100% plasticity recovery with *zero* gradient-based unlearning damage to $A, B$.
- **Nearest prior / gap:** Continual machine unlearning ([2608.29513](https://arxiv.org/abs/2608.29513)) fights entanglement after the fact; `L8W12`'s isolated compilable sub-networks turn eviction into exact slot recycling, beating LATM/Voyager (which leave dead weight traces behind) and gradient-ascent unlearning.
- **Cheapest first test:** Fixed-parameter-budget MLP+sidecar stream of 20 compilable rules + 20 forward tasks. Compare LATM/Voyager (compile without excision), gradient-ascent unlearning eviction, `L7W07` null-space reinit, and isolated excision `L9W18`. Kill if LATM without eviction or gradient-ascent unlearning matches `L9W18` on task-20 learning speed and $A/B$ retention.
- **Old-task retention:** Verify 0.0% degradation on dense tasks $A, B$, 100% rule retention via compiled checks, and constant learning speed through task 20.

## C · Coupled `L8W01 × L8W12` Mechanisms (Compilable Skills ↔ Constant-Size Oracle Probes)

### L9W19 · Joint facet-minimal training of compilable sub-networks and oracle probe seeds
- **Mechanism:** A skill compiled from `L8W12` has only $R$ active decision facets—which simultaneously bounds both its extracted code size *and* the exact number of live-guard oracle queries `L8W01` needs to reconstruct it! Co-train the compilable sub-network $f_F$ and its constant-size probe seed $z_F$ so $z_F$ targets $f_F$'s $R$ active linear-region boundaries while `L9W10` minimizes $R$—jointly shrinking both extracted check size and wake query count $Q$.
- **Nearest prior / gap:** `L8W01` alone probes an arbitrarily tangled guard; `L8W12` alone shrinks code size without optimizing oracle recoverability. Joint training couples the two objectives through the shared facet count $R$.
- **Cheapest first test:** 20-rule stream with simulated mid-stream artifact-loss wake events. Compare uncoupled `L8W01` + `L8W12`, Drag-and-Drop, `NN2Rules` + random probes, and jointly trained `L9W19`. Kill if uncoupled `L8W01` + `L8W12` achieves the same wake query count $Q$ and AST size.
- **Old-task retention:** Verify post-wake retention on all 20 rules at minimal $Q$, compact AST size, and unimpaired task-20 plasticity.

### L9W20 · Static AST-to-probe-seed synthesis at compile time (zero-meta-learning `L8W01` pointers)
- **Mechanism:** Once `L8W12` compiles $f_F$ into a compact deterministic AST/decision tree $A_F$ with $L$ leaves, we do *not* need meta-learning to build `L8W01`'s probe seed! Statically compute 2 opposing boundary witnesses per internal split node of $A_F$, hash/compress their generator parameters into a constant-size seed $z_F$, and evict $f_F$ (`L9W18`)—producing an exact, guaranteed-coverage oracle probe schedule with zero extra training cost.
- **Nearest prior / gap:** `L8W01` and [Drag-and-Drop](https://arxiv.org/abs/2506.16406) require training a separate probe/weight generator; compiling via `L8W12` exposes the exact symbolic splits needed to synthesize $z_F$ analytically.
- **Cheapest first test:** 20 compiled rules comparing meta-learned `L8W01` probe seed, random probes, Drag-and-Drop, and statically synthesized `L9W20` at equal query count $Q$. Kill if meta-learned `L8W01` or random probes match `L9W20` wake accuracy at $Q = 2L$.
- **Old-task retention:** Verify post-wake accuracy across all 20 rules after eviction and zero extra training overhead on $A, B$.

### L9W21 · Compilability-regularized 1-step wake (re-compilable recovery after guard outage)
- **Mechanism:** If an external guard $G$ is temporarily lost and `L8W01` wakes $F$ into weights via standard unconstrained distillation, the woken skill lands in entangled dense weights that can no longer be cleanly re-compiled or re-evicted. Apply `L8W12`'s sparse piecewise-linear regularizer *during the 1-step oracle wake* into an isolated sidecar slot (`L9W18`)—so even woken skills remain cleanly re-compilable into a replacement external check $A'_F$ and immediately re-evictable once coverage is restored.
- **Nearest prior / gap:** Standard 1-step wake (`L5W03`/`L8W01`) restores behavior into dense weights, re-introducing entanglement on every outage; compilability-regularized waking keeps the full lifecycle closed.
- **Cheapest first test:** 5 repeated guard-outage → wake → re-compile → re-evict cycles across 10 rules. Compare unconstrained wake + `NN2Rules` re-extraction vs. compilability-regularized wake `L9W21`. Kill if unconstrained wake maintains equal AST size and plasticity after 5 cycles.
- **Old-task retention:** Verify stable AST size, <1% fidelity drift, and constant new-task learning speed across all 5 wake/re-evict cycles.

### L9W22 · Probe-discrepancy detector for compilability-breaking human edits
- **Mechanism:** When humans edit a compiled external check $A_F \to A'_F$ (adding exceptions or fuzzy heuristics), `L8W01`'s probe seed $z_F$ detects prediction disagreement against $A'_F$. Run a quick `L9W15` compilability test on the disagreement slice: if $A'_F$ remains low-region piecewise-linear, update $z_F$ in place; if human edits made the guard non-compilable/fuzzy, re-absorb the fuzzy delta into dense weights while keeping the crisp core external.
- **Nearest prior / gap:** Extends `WMX3` (verify real guard changes before rebuilding pointers) by distinguishing *compilable* rule revisions from *non-compilable* drift.
- **Cheapest first test:** 10 compiled guards subjected to 5 crisp human edits (threshold/clause changes) and 5 fuzzy edits (semantic/noisy exceptions). Compare blind pointer rebuild, never rebuild, and discrepancy-routed `L9W22`. Kill if blind pointer rebuild matches `L9W22` on both edit types.
- **Old-task retention:** Verify retention on all 10 edited guards and zero collateral damage to unchanged skills $A, B$.

### L9W23 · Shared predicate-basis bank across $K$ skills (amortizing both code size and wake queries)
- **Mechanism:** Across $K=20$ compiled prevention rules, independent sub-networks repeatedly re-learn and re-probe the same atomic predicates (e.g., schema fields, range checks). Maintain a small shared bank of $P$ reusable atomic predicates: `L8W12` compiles each skill as a sparse Boolean/piecewise-linear formula over the shared bank, and `L8W01` queries the live guard *only* to identify which bank predicates are active—shrinking both per-skill AST size and wake query count by $O(\log K)$ at constant pointer bytes.
- **Nearest prior / gap:** Independent [NN2Rules](https://arxiv.org/abs/2207.12271) or `L8W01` extractions pay redundant per-skill feature discovery; a shared predicate bank amortizes both compilation (`L8W12`) and oracle probing (`L8W01`) across the skill library.
- **Cheapest first test:** 20 rules drawn from a shared 32-predicate vocabulary. Compare independent `L8W12`+`L8W01`, Text-to-LoRA, equal-byte replay, and shared-bank `L9W23`. Kill if independent `L8W12`+`L8W01` matches `L9W23` in total AST tokens and wake queries across $K=20$.
- **Old-task retention:** Verify 100% accuracy across all 20 rules, no destructive edits to shared predicates used by older rules, and faster acquisition of rules 11–20.

### L9W24 · Authorized-domain-bounded oracle probing (separating self-recovery from model extraction)
- **Mechanism:** Cryptanalytic hard-label probing ([2609.21941](https://arxiv.org/abs/2609.21941)) can reconstruct secret guard parameters using out-of-distribution synthetic queries, creating a security/privacy risk against external policy guards. Pair `L8W12` (which compiles only *publicly authorized behavioral invariants* via `WMX5`) with an explicit domain-projection constraint on `L8W01`'s probe seed $z_F$, restricting all wake queries to valid, authorized input distributions and logging every probe for audit.
- **Nearest prior / gap:** Bridges model-extraction security ([2609.21941](https://arxiv.org/abs/2609.21941)) with `L8W01` oracle waking so constant-size pointers remain safe in multi-party/regulated deployments.
- **Cheapest first test:** Guard containing both an authorized behavioral rule and a hidden secret threshold outside the valid domain. Compare unconstrained `L9W01` vs. domain-projected `L9W24`. Kill if domain projection causes >2% drop in authorized-rule wake accuracy.
- **Old-task retention:** Verify full post-wake retention on authorized inputs, 0% leakage on restricted probe queries, and unchanged $A, B$ accuracy.

### L9W25 · Disjoint-support multi-guard wake (interference-free simultaneous recovery)
- **Mechanism:** Under correlated outages where $k$ external guards fail at once (`HWX4`), waking $k$ dense skills simultaneously causes severe gradient interference. Because `L8W12` (`L9W11`/`L9W12`) constrains each rule sub-network to sparse predicate supports and isolated sidecar slots (`L9W18`), `L8W01` can wake all $k$ guards in parallel into disjoint sparse sub-networks—achieving zero cross-skill wake interference while keeping total memory overhead linear in the *active* outage count $k$ rather than total skill count $K$.
- **Nearest prior / gap:** Solves `HWX4`'s simultaneous-outage bottleneck structurally via `L8W12`'s sparsity rather than fragile orthogonal gradient projection (`L6W13`).
- **Cheapest first test:** Correlated outage of $k \in \{1, 3, 5, 10\}$ guards out of $K=20$. Compare dense simultaneous `L8W01`, orthogonal simplex `L6W13`, equal-byte replay, and disjoint-sparse `L9W25`. Kill if dense `L8W01` or `L6W13` matches `L9W25` wake accuracy at $k=5, 10$.
- **Old-task retention:** Verify simultaneous post-wake accuracy across all $k$ woken guards and zero regression on dense tasks $A, B$.
