# Obligation identifiability: the smallest observation that makes a retention-safe write unique

Parent: [`tree/harness-discrete-backprop.md`, PR #52](https://github.com/manojbajaj95/cl/pull/52/files) · Depth 3

**Root cause: every current method treats preservation evidence as a write-agnostic sample fixed before the candidate writes are known, but the observation that separates a safe write from an unsafe one is write-conditional. It lives exactly where the candidate repairs disagree. Passive anchors, replay and self-probes hit that region only by luck. No current learner computes the region from its own candidate set, though it has everything it needs to do so.**

The parent node found this in a finite form. Target-only replay left 3 / 2 / 1 minimal edits. Five old anchors cut each to one, and removing only the *aliased* anchor restored 3 / 2 / 1 even with the other four present. The localization came from one distinguishing observation, not from backward computation. This node asks what that observation is in general, how small it can be, and whether the learner can produce it itself.

Two observations make the question sharper than "active learning for CL":

1. **For retention, labels are almost free.** The target for "keep old behavior at x" is the pre-update model's own output at x. The only thing the learner cannot get from itself is whether old behavior at x *should* be kept (it may be stale or wrong). So the missing observation can shrink from a label to one **keep bit** per synthesized input.
2. **Identifying the write is not the goal.** A write that is safe in every world still compatible with the evidence needs no identification. The observation is needed only when no such *consensus write* exists. Active learning and version-space methods spend their queries on identifying the target function. That is the wrong objective, and it costs more queries.

### What current approaches establish

| Work | What it gives | Why it does not make the write identifiable |
|---|---|---|
| CABA, certified held-out anchors ([2610.40740](https://arxiv.org/abs/2610.40740)) | Post-update gate: largest interpolation whose worst-anchor KL stays under budget; off-anchor guarantee under coverage + Lipschitz assumptions | Anchors are fixed and reserved in advance. It certifies *given* coverage but never says which anchor is missing. An aliased input outside the anchors passes the gate. |
| CPLUS, self-probe gradients ([2609.32771](https://arxiv.org/abs/2609.32771)) | Frozen model generates inputs near retained samples and labels them itself; the gradients scale down conflicting updates | Probes are generated around *past samples*, not around the *disagreement between candidate writes*, so they are write-agnostic. Self-labeling assumes the old behavior should all be kept: no keep bit. |
| Task-Bank self-preservation ([2610.12602](https://arxiv.org/abs/2610.12602)) | Model picks which tasks to replay, using the incoming task; helps at 4B, not at smaller sizes | Selection is at task granularity and uses the incoming *data*, not the candidate *update*. The preservation set still covers "only part of what the model knows". |
| TTA identifiability ([2609.11235](https://arxiv.org/abs/2609.11235)) | Shows that an observation channel can make the oracle action unidentifiable even with a perfect selector; richer evidence helps only if it resolves the relevant ambiguity | Diagnoses the problem; does not construct the resolving observation or let the learner request it. Closest statement of our root cause, for TTA action selection. |
| Counterexample-supplemented sketches ([2607.15854](https://arxiv.org/abs/2607.15854)) | Coding agent stops and asks a clarification question when permission is ambiguous; anchors must survive each change | The question is unstructured and needs a human operator; no minimality and no synthesis of the distinguishing case. |
| Update admission auditing ([2609.10873](https://arxiv.org/abs/2609.10873)), STABLE, harness proposal/commit split | Gate or reject updates on validation evidence | They are acceptance tests over a fixed evidence pool, so they inherit its blind spots. |
| Disagreement-based active learning (CAL, version-space / QBC), CEGIS, A-CEGIS [2609.02892](https://arxiv.org/abs/2609.02892) | Query where the hypotheses disagree; counterexamples prune programs | They identify the *target concept*, not a write that is safe across worlds. They query labels where the old model already supplies them. A-CEGIS needs an executable spec. |
| Collaborative-parameter learning (CPL), GPM/OGD null-space methods | Protect parameters or subspaces indicated by past gradients | Protection is computed from the past data, with no reference to the specific alternative writes. |

**Strongest null.** Costed active diagnosis over the existing query menu: compute the version space of minimal repairs, ask the cheapest separating question, and repeat. On a finite deterministic model this already solves the problem (PR #52 notes the same for CEGIS / weakest preconditions). Any idea here must beat it on the number of *external* bits requested. The way to beat it is to (a) get labels from the old self, (b) stop when a consensus write exists, and (c) synthesize the separating input instead of picking it from a menu. A second null is CPLUS-style self-probes at equal count. A third is random anchors at equal count.

**What would disconfirm the node.** On realistic edits, either the disagreement region between candidate writes is so broad that witnesses cost as much as replay, or keep bits are nearly always "keep", so plain old-self distillation on synthesized witnesses already matches the method.

## Finite formulation (for the reviewer)

Let C be the set of minimal candidate writes consistent with the target fix. For two writes w, w' in C, let D(w, w') be the set of inputs where their outputs differ. Each input x in D gets the old output y_old(x), which is free, and an unknown keep bit k(x).

A write w is retention-safe if it agrees with y_old wherever k = 1. Any write is safe whenever all of D has k = 0, and the consensus write exists when some w agrees with y_old on the union of D. The **obligation number** of C is the minimum number of keep bits needed until a safe write is unique up to protected-behavior equivalence. That count, not |C| and not the version-space size, is the quantity the ideas below try to make small and computable.

## Raw mechanisms for the reviewer

Unfiltered. Each has a mechanism, why it is new against the table above, and a cheapest first test with a retention check. Unless stated, the testbed is PR #52's three width-six tables with 90 single-cell writes (finite, exact replay), or a toy MLP with rank-1 ROME-style edits (as in `tree/model-guided-edits.md`). "Retention" means held-out old input/output pairs not used for selection.

1. **Disagreement-witness synthesis.** *Mechanism:* for each pair of candidate writes, optimize or search an input x that maximizes the divergence between the two edited models, label it with the old model, and add it as an anchor. *Why new:* the anchors are a function of the candidate set, not of past data. CPLUS probes past samples; CABA reserves fixed anchors. *First test:* in the PR #52 tables, compare witness anchors vs random vs self-probe anchors at equal count (1–5). Measure minimal-edit count left and held-out old success.

2. **The keep bit as the only external query.** *Mechanism:* the learner never asks for labels. It asks a single bit per witness ("should the old behavior here survive?") and takes y_old from itself. *Why new:* it splits retention supervision into a free self-label and a one-bit staleness flag. Active-learning query costs assume full labels. *First test:* plant k = 0 on 20% of old pairs (stale facts). Count external bits to a unique safe write vs label queries under disagreement-based active learning. Retention is measured on k = 1 held-out pairs.

3. **Consensus write before query.** *Mechanism:* before asking anything, search C for a write that agrees with y_old on the whole disagreement union, and commit it if one exists. *Why new:* the objective is safety in all compatible worlds, not identification. Version-space methods always try to collapse the space. *First test:* the fraction of the parent's 90-write defects where a consensus write exists with zero queries, and its held-out old success vs the identified write.

4. **Obligation-number estimator.** *Mechanism:* from a diff of the candidate writes alone, predict how many keep bits a write will need (the log of the number of protected-behavior equivalence classes in C), and budget or abstain on that number. *Why new:* it prices identifiability before spending queries. Pre-edit capacity forecasts (killed) predicted collapse, not query cost. *First test:* the rank correlation between predicted and actual queries used, over all parent defects. The constant-budget control is required (see the killed N* idea).

5. **Write-conditional anchors from ΔW's input directions.** *Mechanism:* take the top input singular directions of each candidate ΔW, project them onto the data manifold (nearest real or generated inputs), and use those as anchors. *Why new:* the anchors are read off the write, not off the data. *First test:* toy MLP with rank-1 edits. Compare ΔW-key anchors vs random vs CPLUS probes at equal count, measuring retention on held-out old inputs.

6. **Non-identifiability witness as an output.** *Mechanism:* when no safe write is identifiable from what the learner can observe, it returns a certificate: two worlds that agree on all logged evidence but need opposite writes, plus the missing variable. *Why new:* the parent's "ask/abstain" becomes a checkable object. The TTA identifiability paper proves such pairs exist but does not emit them. *First test:* the parent's unlogged-tool-mode case. Measure precision and recall of emitted certificate pairs vs ground-truth ambiguous defects.

7. **Instrumentation requests instead of data requests.** *Mechanism:* when the ambiguity comes from a latent state (such as a hidden tool mode), the learner asks the harness to *log one more variable* rather than asking for more examples, choosing the variable that splits the certificate pair. *Why new:* observation design over the agent's own telemetry, not over inputs. *First test:* a toy with three candidate hidden variables. Measure the variable chosen vs the oracle and retention after the write.

8. **Two-sided interferometry (±Δ).** *Mechanism:* apply +Δ and −Δ of a candidate write in forks. Inputs whose response is odd in Δ are coupled to the write, and inputs with even or zero response are not. The odd set is the witness pool. *Why new:* a cheap disagreement detector that needs no second candidate. *First test:* toy MLP. Compare the recall of truly affected old inputs from the odd set vs a one-sided KL ranking at equal forward passes.

9. **Dual prices as value of information.** *Mechanism:* solve the write as a constrained problem over protected behaviors. The Lagrange multiplier on each tentative constraint says how much that constraint shapes the write, and the learner queries the keep bit of the highest-priced constraint first. *Why new:* query selection from the write optimizer's own duals rather than from model uncertainty. *First test:* a linear-head write. Compare queries to a safe write for dual ordering vs uncertainty ordering vs random.

10. **Minimum hitting set of disagreement regions.** *Mechanism:* treat each pair of candidates as a set (its disagreement region) and pick the smallest set of inputs that hits all of them, a greedy log(k) approximation. *Why new:* it makes "the smallest extra observation" a combinatorial object the learner computes. *First test:* parent tables. Compare greedy hitting-set size vs the true minimum (by enumeration) vs random anchors needed for uniqueness.

11. **Gradient-alias detector.** *Mechanism:* inputs whose loss gradient on the edited parameters is collinear with the target's gradient are the aliased ones, so synthesize inputs that maximize that cosine and label them with the old model. *Why new:* it searches for exactly the inputs the update cannot tell apart from the target. CPLUS uses probe gradients to scale updates, not to find aliases. *First test:* toy MLP, the alias-cosine probes vs CPLUS probes at equal count, measured by retention on held-out old pairs.

12. **Old-self labels on new-policy visitation.** *Mechanism:* for agents, a write changes which states get visited. Roll out the *candidate-edited* policy, then label those states with the *old* policy, so anchors sit where the new policy actually goes. *Why new:* write-conditional anchors in state space. Replay draws anchors from the old visitation. *First test:* the parent's retrying tool loop. Compare old success on held-out goals with these anchors vs old-visitation anchors.

13. **Contrast-pair request.** *Mechanism:* the one external query is a minimal pair (x, x') with near-identical surface and different correct outputs, which pins the boundary the write must not cross. *Why new:* one structured query replaces several labels and targets locality directly. *First test:* rank-1 factual edits on the toy MLP. Count contrast pairs vs single labels to a unique safe write, then check retention.

14. **Self-play witness game.** *Mechanism:* two copies of the learner each commit a different candidate write and search inputs where the *other* breaks old behavior. A game value of zero means the write is identifiable, and the winning inputs are the witnesses. *Why new:* adversarial witness generation between writes, not between a model and a data distribution. *First test:* the parent tables, comparing the witnesses found per round to the hitting-set optimum.

15. **Write-menu enrichment instead of observation.** *Mechanism:* sometimes no observation helps because no write in the menu is safe. The learner then requests a new write primitive (such as a gate variable) instead of a query. It decides between "ask" and "grow the menu" from the certificate. *Why new:* it makes observation vs capacity an explicit, decidable choice. *First test:* the parent menu with the gate cell removed. Measure whether the learner correctly reports "no safe write exists" and whether the gate restores retention.

16. **Invariance under requested interventions.** *Mechanism:* the learner requests environment perturbations (context shuffles, tool latency, distractors) and keeps only candidate writes whose effect is invariant across them. The safe write is the invariant one. *Why new:* the observation is an intervention the learner designs, IRM-style, for selecting a write. *First test:* a toy with a spurious upstream cue. Compare the invariant write vs the minimal write on held-out old success.

17. **Deferred commitment with a waiting-time price.** *Mechanism:* keep the candidate set alive, estimate the expected stream time until a natural input lands in the disagreement region, and query only if waiting costs more. *Why new:* free observations from the stream are priced against a query. This overlaps D1 deferred-commitment weights, which do not compute the disagreement region. *First test:* simulated stream over parent tables. Measure queries saved vs regret while waiting, with retention at the end.

18. **Disagreement-region router.** *Mechanism:* commit both candidate writes behind a learned detector of their disagreement region; inside that region, route to the old model. Each routed hit becomes a keep-bit request. *Why new:* the request queue builds itself as a side effect of serving. *First test:* toy MLP. Measure retention of routed inputs, new-task accuracy, and the bits requested per 1k inputs.

19. **Activation-patching query.** *Mechanism:* the extra observation is internal. One patching experiment on the target input tells an upstream fix from a downstream compensation (PR #52's core ambiguity) at the cost of a forward pass. *Why new:* an internal observation used to choose the write address. *First test:* a 3-stage toy network with planted upstream and downstream defects. Measure patching-chosen vs minimal-edit localization accuracy and retention.

20. **Failure-trace mutation boundary.** *Mechanism:* minimally mutate the failing trace until its repair set changes; the boundary traces are the witnesses. *Why new:* it builds witnesses from the failure, not from old data. *First test:* parent tables. Compare boundary-trace anchors vs random old anchors at equal count.

21. **Learner-written killing tests.** *Mechanism:* for each pair of candidate writes, the learner writes a test (an input plus an old-self expected output) that passes on one and fails on the other. The tests persist as a regression set. *Why new:* mutation testing aimed at the learner's own candidate writes. Mutant verifiers (RL-on-OOD #15) mutate the verifier, not the write. *First test:* an LLM-written harness edit with two candidate patches. Measure kill rate and held-out old task success after the chosen patch.

22. **Obligation tokens.** *Mechanism:* every committed write carries a short emitted note of what it assumed must not change (its witness set), checked lazily when later writes arrive. *Why new:* obligations become attached, inspectable state of the write. *First test:* a sequence of 20 toy edits. Measure the detection rate of a later write that violates an earlier write's obligation tokens vs a global replay check.

23. **Reusable witness certificates across writes.** *Mechanism:* witnesses that separated one pair of candidates are cached by the subspace or cell they probe, and reused when a later candidate set touches the same place. *Why new:* it amortizes identifiability, which is PR #52's remaining bet of "smaller reusable certificates", applied to observations. *First test:* 50 sequential parent-table defects. Measure the external bits per defect over time and retention on all earlier fixes.

24. **Bit-budget scaling law.** *Mechanism:* conjecture that the keep bits needed scale with the number of protected-behavior equivalence classes among candidate writes, not with model size or the anchor count CABA needs for coverage. Test it on edits of growing model width. *Why new:* a law for observation cost, not for forgetting. *First test:* toy MLPs at widths 16–256 with rank-1 edits, plotting bits to a safe write vs width against the predicted class count.

25. **Self-asked staleness.** *Mechanism:* before asking the user the keep bit, the learner asks itself (in context, given the new evidence) whether old behavior at the witness is now stale, and escalates only when its answer is unsure. *Why new:* a self-filter on the one remaining external bit. *First test:* small LLM, factual edits with planted stale neighbors. Measure external bits saved and the error rate on keep decisions against retention.

## Ranked next nodes

Ranked by how likely each leads to a new primitive:

1. **Is one keep bit per self-synthesized disagreement witness sufficient and close to minimal?** Can retention-safe writes be identified with about log(obligation number) external bits, with every label coming free from the old model (ideas 1, 2, 4, 10)? A yes makes "witness + keep bit" a primitive, and it is the direct answer to this node.
2. **When does a consensus write exist, and can the learner tell before asking?** Can the learner certify "safe in all compatible worlds" without identification (ideas 3, 6, 15)? This turns abstention into a decision procedure.
3. **Can disagreement witnesses be synthesized on-manifold in LLM weight space?** Does input search between two edited models find realistic aliased inputs that CPLUS-style probes miss (ideas 1, 5, 11, 14)? This is the scale-up risk for the whole node.
4. **When the missing observation is latent state, what is the minimal variable to instrument?** Can the learner request it (ideas 6, 7, 19)? This is the agent-harness version.
5. **Do witnesses transfer?** Can one write's obligation certificates be reused by later writes, so the external bits per write fall over a stream (ideas 22, 23)?
