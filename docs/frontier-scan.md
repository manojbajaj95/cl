# Continual learning: frontier scan

This scan prioritizes mechanisms outside on-policy self-distillation, weight-space programming, and agent workflow learning. The common question is **what should a bounded learner change when the stream changes, and how can we tell whether it changed the right thing?** Papers below are linked to inspected arXiv records; results are author-reported, not independent replications. This is a targeted scan through November 2026, not a systematic novelty clearance.

## Ranked research bets

### 1. Probe before writing: identify the shift, then update only the affected mechanism

**Hypothesis.** When an observation remapping and a physical change give the same evidence under the ordinary policy, a few diagnostic actions can distinguish them and make the right learned encoder or dynamics module reusable. In recurring, unmarked streams, target **≥25% less integrated excess rollout error relative to a regime-oracle predictor** vs. the best equal-budget non-oracle baseline, with **≤2 percentage points** degradation on invariant probes relative to pre-stream performance. Normalize rollout error by fixed per-environment state scales and define the invariant metric as the fraction of rollouts within a fixed tolerance. Count queries, control energy, and all update steps.

**Sanity check, not novelty evidence.** Let a scalar plant have known stable coefficient `a`, output `y = s*x`, and two actuators. Compare a sign flip in `s` to a sign flip in actuator 2's gain, assuming actuator 1's sign is stable and the initial state and process noise are symmetric. When ordinary actions never use actuator 1, both worlds have identical observation laws, even if actuator 2 is used. A pulse of known strength through actuator 1 separates them: residual `y[t+1] - a*y[t]` has mean `±g` after accounting for actuator 2. For `k` independent pulses with Gaussian innovation standard deviation `σ` and equal priors, optimal accuracy is `Φ(g√k/σ)`. At `g/σ = 0.5`, a seed-20261124 CPU check sampled the residual model with 20,000 balanced trials per setting: accuracy was 0.5000 with no pulses, 0.8364 with four (theory 0.8413), and 0.9756 with sixteen (theory 0.9772). With no stable anchor, do not claim identifiability.

**Pilot.** Build a controlled two-actuator simulator, then a DM Control cart-pole stream with remapped observations, actuator gain/dynamics changes, mixtures and recurrences. Fit a 0.1–2M parameter modular encoder/transition model. Hold out **combinations** of previously observed modules and include ambiguous, easy, and no-anchor controls; the learner receives no regime or shift labels. Probe when expected evidence could change the update decision; defer irreversible writes otherwise. Compare to frozen, full online adaptation plus replay, a VCD-style passive modular model, identical modules with equal-energy random probes, and active Bayesian diagnosis over a library of known modes with the same actions and a generic adaptation fallback. Include a label-oracle ceiling. Also report shift attribution, revision latency, and probe cost separately. **Budget:** <2 CPU-hours for the toy, ~16–40 single-GPU hours for the learned pilot.

**Publication bar.** The scalar separation is standard active diagnosis, not a contribution. The result would need conditions (and counterexamples) for identifying and reusing **learned, composable** mechanisms under recurrent shifts, plus a measured retention benefit on unseen combinations. [Safe active diagnosis](https://arxiv.org/abs/2606.19590) already handles sensor/actuator faults given candidate models, [PhysiCalWorld](https://arxiv.org/abs/2610.30125) already uses exploration to calibrate physics in context, and [continual WM reuse](https://arxiv.org/abs/2610.41041) already identifies observation-dependent reuse. If a known-mode filter or an in-context descriptor with the same probes matches the learned update policy on held-out combinations, do not scale.

### 2. Counterfactual rollback of learned sparse writes

**Hypothesis.** Explicitly bounding the dependencies of learned memory writes enables source retraction with **≤ half the replay compute** of full chronological rebuild, **exact state equivalence** on deterministic pilots, and **≤2 points** loss on retained multi-hop QA vs. unrestricted sparse memory at the same state/log budget (both trained without the withdrawn source for this comparison).

**Pilot.** Freeze a Qwen2.5-0.5B backbone and use a small writable memory with deterministic, event-keyed routing. Each update performs a local learned write from declared inputs, logging read/write dependencies on slot versions (including the prior state/optimizer of overwritten slots). Make routing and update admission independent of mutable state in the exact variant. When a source is withdrawn, recompute only its transitive descendants in event order, with per-event seeds and unchanged schedule. Audit the claim against a fresh chronological run with the source omitted and no schedule renumbering: inductively, a clean write sees identical inputs; dirty writes recover the counterfactual version once their dependencies are repaired. This only holds if **all** dependencies are logged or immutable; adaptive routers, negative retrieval matches, shared optimizer state, and cross-slot normalization can invalidate it. Use synthetic entity–relation streams with novel multi-hop queries, clean branches, revisions and source withdrawals. Split by graph and templates. Sweep dependency fan-out and retraction age. Compare direct slot undo, exact full replay, sharded PEFT/SISA-style replay, an unrestricted sparse memory model, and versioned graph retrieval. State agreement, retained/withdrawn fact accuracy (including descendants), and replay FLOPs plus log bytes are mandatory. **Budget:** ~12–36 single-GPU hours.

**Publication bar.** [Dependency-guided repair](https://arxiv.org/abs/2608.10502) already replays affected agent memory operations, and TANSAR already performs exact additive deletion. A result worth submitting would characterize when bounded-dependency **nonlinear learned updates** preserve compositional utility while admitting exact sublinear replay, and show where dense dependencies erase the advantage. This is source-event rollback, **not** proof of data removal from the frozen backbone or independent sources. If plain graph RAG or sharding matches the frontier, stop.

### 3. Diagnose which state has lost plasticity before resetting it

**Hypothesis.** A matched short-run fork from one checkpoint can predict whether clearing optimizer state, changing trainable representations, or doing nothing will improve the next segment under a retention constraint. Target **≥10% lower cumulative new-segment excess loss relative to a fresh-start reference** than the best fixed intervention, at **≤2 points** loss on invariant anchor accuracy and matched total backward passes. Compare the intervention selected by the fork with the best intervention measured on a disjoint continuation; the latter is an oracle, not training data.

**Pilot.** Use a 4-layer ~1M parameter classifier on recurrent Split CIFAR-100 streams with held-out corruption sequences, then verify any signal on a 0.5B LLM with sequential knowledge/reasoning slices. Fork at unsupervised loss-change triggers (loss on the current training batch, not hidden task IDs), using identical examples and RNG. Cross fresh vs. carried Adam state on untouched parameters with no reset vs. a fixed-size selective unit reset (clear moments of reset units in both arms). Score each fork on the next labeled training observations reserved for selection plus a capped historical anchor buffer; evaluate on disjoint data and count all forks' compute. Compare continued training/replay, periodic optimizer reset, selective reset, an equal-cost larger replay run, a cheap curvature/gradient proxy, and the oracle arm. Report adaptation AUC, retention, and intervention regret per shift type, including long no-shift controls. **Budget:** ~8–20 single-GPU hours on vision; ~20–60 more for the text check only if the diagnostic transfers across held-out vision streams.

**Publication bar.** [Optimizer resets](https://arxiv.org/abs/2306.17833), [adaptive/selective resets](https://arxiv.org/abs/2603.03796), and [predicting optimization readiness](https://arxiv.org/abs/2605.09044) are existing work. The contribution would be evidence for a reproducible crossover between optimizer-state and representation bottlenecks, a predictive intervention rule, and a characterization of failure under recurrence. A modest gain from spending more backward passes would not qualify.

**Recommendation:** prototype #1 first. It offers a cheap way to falsify the mechanism without an LLM or a cluster and a strong known-mode baseline that can rule out an incremental result. #2 is the fallback if active identification delivers diagnosis but no additional mechanism reuse. The pilots and publication claims above have not been demonstrated.
