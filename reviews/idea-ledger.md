# Idea ledger

Every idea the reviewer has judged, with its verdict, the reason, and (for survivors) the control it must beat and the pilot outcome. Full reasoning is in [batches-1-3-and-pr4.md](batches-1-3-and-pr4.md). One row per idea; update the row when a pilot result lands.

Status values:
- **QUEUED**: accepted for later; not started, no experiments run.
- **PILOTING**: passed review, pilot running.
- **GATED on X**: passed review; launch only if pilot X survives.
- **KILLED**: stop.
- **KILLED (at proposal)**: dropped by the proposer before review.
- **KILLED (fix)**: dead as written; can be resubmitted with the named fix.
- **SURVIVED / FALSIFIED**: the pilot outcome. A FALSIFIED row ends with **What we learned**, a negative result proposers can build on.

## Grading rules (from 2026-11-24, Manoj and Albert)
The reviewer grades cards instead of killing them:
- **AMBITIOUS BUT DOABLE**: ambitious and testable now. The verdict gives the smallest first test and the strongest control.
- **MOONSHOT**: ambitious but not testable yet. It goes on the [Moonshot shelf](#moonshot-shelf) with what would unlock it.
- **KILLED**: only for cards that make no sense or are already done (prior art). A pilot can still FALSIFY a card; that is recorded as a result, not as a review kill.
- **Primitive or improvement**: every card is also labelled PRIMITIVE (a new object or operation that a family of methods could build on) or IMPROVEMENT (a better existing method), with one line why. See the patterns section.
- **Volume over verification (Manoj, Albert).** Proposers optimize for many more and crazier ideas (the flood pool lives in `ideas/flood/`). The reviewer ranks the whole pool head to head on novelty only, runs prior-art checks only on the top 10, and picks a top 3 for deep work. No pilots on ideas rated IMPROVEMENT. Full verification happens at pilot time, not at review.
- **Retention check in every first test (Albert, Manoj).** Every smallest first test written for a top idea must show the model or agent still does its normal old tasks after learning the new thing.

## Patterns in the kills

- **Lesson-value claims must beat a temperature-matched no-lesson arm.** In G1/Q2 an entropy-matched temperature reproduced ~95% of per-start lesson effects (PR #27). Split-half reliability over unbalanced start sets measures the start mix, not noise. Counterexample: M2's outcome-trained salience beat the entropy control by 13.3 pp ([PR #35](https://github.com/manojbajaj95/cl/pull/35)), so the control is a required floor, not an assumed tie.
- **Anomaly mining:** an idea mined from a pilot surprise must first replicate that surprise at ≥ 10 seeds. Q1 (from PR #12) and P1 (from PR #11) both died at that gate.

- **Noisy ground truth:** when truth comes from fresh rollouts, report its split-half reliability first; G1's truth (ρ 0.16 with exact success) made the test unpassable.

- **Margin confound:** in any claim about which items are forgotten first, match per-item margin before attributing the order to a mechanism (reverse grokking, cooldown facts).

- **Ties a simple baseline at equal budget:** replay, append + retrieve, save/restore. This is how PR #1 died.
- **True by construction:** exact restore, flat reacquisition, a threshold built into the simulator.
- **Already in 2026 papers:** found by alphaXiv but missed by the HF papers search.
- **Merge cards must beat the union of their parts' baselines.** The strongest control for a merged idea is the best simple baseline of each part, stacked together at the same compute and tokens (for example leave-one-out plus recency plus the entropy control). A merge passes only if its mechanism has an interaction those stacked baselines can't reproduce, with a smallest test that isolates that interaction. Reusing a partial win from a kill must cite the result it rests on.
- **Primitive-or-improvement gate (every card, from 2026-11-24).** A primitive introduces a new object or operation that a family of methods could be built on (the bar is set by weight-space programming). An improvement makes an existing method better, cheaper or better understood. Each card's verdict states which, with one line why. Improvements need an unusually large effect to pass; primitives still face the usual controls and falsifiers.
