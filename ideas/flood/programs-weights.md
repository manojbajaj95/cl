# Flood: weights, activations and agents as programs

Raw, unfiltered continual-learning ideas built on treating weights, activations or agents as programs (compilers, type systems, version control, linkers, interpreters, model surgery). Nothing here is pre-killed; the reviewer ranks the pool. Known nearby prior art to screen against: weight-space programming for CL repair (2611.25613, Self-WSP 2611.28833, 2611.26841), circuit condensation (2608.27254), Library of Layers (2611.03526), edited-weight persistence (2511.05852, 2512.14741, 2610.07510, 2608.24988).

Each entry: **mechanism**, *why new*, **first test**.

## Compilers and intermediate representations

**P1. Skill compiler with a weight-space IR.** Each new skill is learned as a LoRA, then "compiled": lowered into a small typed IR (a sequence of rank-1 read/write ops on named residual-stream subspaces, recovered by sparse dictionary fitting of ΔW), optimized (dead-op elimination, constant folding of ops that never fire on the skill's inputs), and re-emitted as a smaller delta. Continual learning is then repeated compile-link of IR modules instead of gradient accumulation. *New:* treats a fine-tune as source code with an optimizer pass between learning and deployment; existing work prunes or merges deltas but has no IR. **First test:** GPT-2 small, 5 sequential synthetic tasks; compile each LoRA to ≤k rank-1 ops by greedy activation-weighted fitting; measure retention and size vs. raw LoRA stacking and vs. TIES merge at equal parameter count.

**P2. Dead-code elimination for forgetting.** Run "liveness analysis" over a network: a unit/direction is live for task t if ablating it changes task-t outputs. Before learning a new task, mark directions dead for every stored task and route the new task's update only into dead code (the free register file). *New:* a compiler liveness pass as the write allocator, computed from functional ablation, not Fisher or gradient magnitude. **First test:** MLP on split-MNIST/permuted-MNIST; liveness by per-neuron ablation on a 256-example buffer per task; compare forgetting vs. EWC and vs. gradient projection (GPM) at equal memory.

**P3. Just-in-time specialization of the base model.** Keep a frozen generalist; at deployment, profile which inputs arrive and JIT-specialize the network for the hot path (prune heads/neurons that are cold for current traffic, re-spend their capacity on a LoRA for the hot distribution), with a deoptimization guard that falls back to the generalist when an input hits a pruned path (guard = activation norm on the removed subspace). *New:* JIT + deopt guards as a CL mechanism: plasticity on the hot path, exact generalist fallback elsewhere. **First test:** Pythia-160M, stream of 3 domains; guard fires → generalist; measure in-domain gain and out-of-domain exactness vs. plain LoRA.

**P4. Profile-guided optimization of where updates go.** Log activation traces for the deployed distribution; use them like PGO to choose which layers/columns get the next update (hot code gets optimized, cold code is frozen). *New:* the traffic profile, not the training loss, decides write placement. **First test:** compare LoRA placed in the top-k most-activated-by-traffic layers vs. top-k by gradient norm vs. uniform, on a 2-domain continual stream, at equal rank.

**P5. Superoptimizing a delta.** Given a learned ΔW for a task, search for the smallest program (fewest nonzero rank-1 terms or fewest touched rows) that is input-output equivalent on the task's probe set, using a stochastic superoptimizer (STOKE-style MCMC over sparse deltas). Smaller deltas interfere less with later tasks. *New:* equivalence-preserving search over deltas, not magnitude pruning. **First test:** take 5 LoRAs on GPT-2; superoptimize to 25% nonzeros at matched probe accuracy; measure interference when stacking vs. magnitude-pruned deltas at equal sparsity.

**P6. Decompile-recompile across model versions.** When the base model is upgraded, decompile each skill delta into activation-level behavior (a probe dataset of (input, residual edit) pairs on named features), then recompile it onto the new model by solving for the delta that reproduces the same feature-level edits. *New:* skills survive base upgrades without the original training data, via a feature-level bytecode. **First test:** Pythia-70M → Pythia-160M; 3 skill LoRAs; transfer via SAE-feature-matched recompilation vs. re-finetuning on generated data from the old model.

## Type systems and contracts

**P7. Typed residual stream.** Assign each residual subspace a "type" (e.g., syntax, entity, number, task-id) learned by a probe; an update is type-checked before commit: a ΔW for a math skill may write only to number-typed subspaces. Ill-typed writes are projected away. *New:* static typing of weight edits; forgetting becomes a type error caught at write time. **First test:** GPT-2 with linear-probe types for 4 feature families; sequential fine-tunes with/without type projection; forgetting and plasticity vs. orthogonal-gradient baselines.

**P8. Refinement types as retention contracts.** Each stored skill exports a contract: a set of input regions with output constraints (e.g., logit margin ≥ m on probes). New updates are trained with the contract as a hard constraint via an SMT-like linearized check (interval bound propagation on the delta). *New:* certified non-regression of old skills per update, as a typechecker, not a penalty. **First test:** small MLP, 5 tasks, IBP-certified contract on 200 probes each; fraction of contracts held vs. EWC and replay.

**P9. Effect types for agent memories.** Every lesson in an agent's memory is annotated with an effect signature (which tools it reads/writes, which state it assumes). A new lesson whose effects conflict with an existing lesson's is rejected or forced to declare precedence. *New:* algebraic-effect typing of agent knowledge; interference becomes checkable statically. **First test:** synthetic tool world with 30 lessons; auto-infer effects from traces with an LLM; measure conflicting-lesson harm with vs. without effect checking, against a plain retrieval-dedup baseline.

**P10. Gradual typing of plasticity.** Parameters start "dynamically typed" (fully plastic); when a skill's contract stabilizes, its supporting parameters are progressively "statically typed" (frozen into a declared interface with checked boundaries). Casts between typed and untyped regions are runtime checks (activation-range assertions) that trigger relearning if violated. *New:* a stability schedule driven by interface stability, not time or importance. **First test:** compare on split-CIFAR-100 with ResNet-18 vs. progressive freezing by Fisher.

## Version control

**P11. git for weights with semantic three-way merge.** Store every update as a commit (delta + probe set). Merging two branches uses a common ancestor and resolves conflicts where both deltas change the same feature-level behavior in opposite directions; conflicts are surfaced as explicit "merge conflicts" that a small resolution fine-tune on both probe sets fixes. *New:* three-way (ancestor-aware), behavior-level conflict detection; task arithmetic is two-way and blind. **First test:** fork GPT-2 into two task branches from a shared mid-checkpoint; three-way merge vs. TIES / task arithmetic at equal compute.

**P12. git bisect for forgetting.** When a skill regresses after many updates, binary-search over the commit history of deltas (revert halves, test probe) to find the culprit update, then revert or rebase only it. *New:* O(log n) causal localization of forgetting in a delta history; most CL work looks only at the current weights. **First test:** 32 sequential LoRA commits on GPT-2 with one injected harmful commit; bisect cost and success vs. influence-function ranking.

**P13. Rebase instead of replay.** To keep old skill A after learning B, "rebase" A's delta onto the new base: re-solve A's delta on the post-B weights using only A's stored probe I/O pairs (no data). *New:* replaces replay with a rebase operation on a delta object; data-free. **First test:** 5-task sequence; rebase each old delta after each new task vs. replay with equal probe count.

**P14. Cherry-pick across models.** Lift a single commit (one learned skill delta) from model X's history and apply it to sibling model Y fine-tuned differently from the same base, with a "patch fuzz" step that aligns via permutation/feature matching. *New:* skill transfer as patch application with fuzz, between divergent descendants. **First test:** two GPT-2 descendants fine-tuned on different domains; cherry-pick a third skill's delta from one into the other; success vs. naive add.

**P15. Blame for outputs.** For any output token, compute `git blame`: which commit's delta contributed most to its logit (linear attribution through the delta history). Use blame to auto-revert commits that cause bad outputs observed in deployment. *New:* online delta-history attribution as a CL feedback loop. **First test:** 20 commits, 3 poisoned; blame-guided revert vs. random/most-recent revert for restoring a held-out metric.

**P16. Feature branches that never merge (copy-on-write weights).** Each user/task gets a copy-on-write fork where only touched rows are materialized; the base keeps serving. Garbage collection merges branches whose deltas coincide. *New:* COW + dedup GC as the memory model of a continually learning fleet. **First test:** 50 user forks of a small LM on synthetic personal facts; storage and accuracy vs. per-user LoRA.

## Linkers, loaders and ABIs

**P17. Weight-space linker with symbol tables.** Each skill module exports symbols (named residual directions it writes) and imports symbols (directions it reads). A linker resolves imports to exports across modules, inserting small adapter "relocations" when the bases differ. *New:* modular CL where composition is resolved by symbol linking, not by routing or averaging. **First test:** 3 composable skills (parse, compute, format) learned as separate LoRAs; link them to solve composite tasks vs. merging and vs. MoE routing.

**P18. Dynamic loading of skill libraries.** Skills live as shared objects (deltas) loaded on demand by a loader triggered by an activation-space "PLT stub": a frozen detector feature that, when it fires, swaps in the delta for the next k tokens. *New:* lazy binding of weights inside a forward pass, keyed by internal state, not by an external router. **First test:** 10 skill deltas on Pythia-160M, detectors from linear probes; accuracy and interference vs. always-on merge and vs. LoRA-switch by prompt classifier.

**P19. Stable ABI across base-model upgrades.** Define an ABI: a fixed set of anchor directions (calling convention) that every base version must preserve (enforced by an alignment loss during base upgrades). Skill deltas written against the ABI survive upgrades unchanged. *New:* ABI stability as a training-time constraint for future compatibility. **First test:** continue-pretrain Pythia-70M with and without an ABI loss on 64 anchors; old skill deltas' accuracy after the upgrade.

**P20. Position-independent skills.** Train skill deltas to be "position independent" (work when inserted at any of several layers) by randomizing insertion depth during training; then a linker can place them wherever capacity is free. *New:* PIC for weights; placement becomes a deploy-time choice. **First test:** train a LoRA with random-layer insertion vs. fixed; accuracy across insertion depths and interference when co-placed.

## Interpreters, VMs and activations as programs

**P21. The residual stream as a register machine.** Learn a small instruction set of rank-1 ops (read feature, write feature, gate) that the model executes; new skills are written as programs over this ISA by a meta-network (a "compiler" from demonstrations to op sequences) and installed as tiny deltas. *New:* continual learning by program synthesis in a learned ISA of the model's own weights. **First test:** toy transformer trained on a few arithmetic ops; learn the ISA by sparse dictionary over task deltas; synthesize a new task's delta from 10 demos vs. fine-tuning from 10 demos.

**P22. Activation patches as hot-fix bytecode.** Store corrections not as weight changes but as conditional activation patches (if feature f > τ at layer l, add v), executed by a tiny interpreter hook. Periodically "compile" frequently executed patches into weights. *New:* a two-tier interpreted/compiled memory with a promotion policy. **First test:** 100 factual corrections on GPT-2; patch interpreter vs. MEMIT vs. ROME at sequential scale; then compile hot patches and track collapse.

**P23. Tail-call optimization for agent loops.** Agent trajectories that repeat a sub-plan are detected as recursive calls; the agent "compiles" the recursion into a learned macro-action whose weights (a LoRA) execute the whole sub-plan in one step. *New:* CL for agents as automatic macro compilation from traces into weights. **First test:** gridworld/text-game agent with repeated sub-tasks; macro LoRA vs. skill library prompts on steps-to-solve and drift.

**P24. Partial evaluation of the model on a user.** Given a fixed user context (preferences, codebase), partially evaluate the network: fold the context's KV into the weights (Futamura-style specialization) so the context is no longer needed, and continue to learn on top. *New:* context distillation framed and done as exact partial evaluation (solve for weights reproducing the context-conditioned activations layer by layer, closed-form per layer). **First test:** fold a 512-token system prompt into GPT-2 layer-wise by least squares; match vs. context distillation by gradient descent at equal compute.

**P25. Abstract interpretation of updates.** Before applying a gradient update, run abstract interpretation over the delta (interval/zonotope bounds) to compute the set of probe behaviors it could change; refuse or shrink updates whose abstract footprint touches protected skills. *New:* sound pre-commit impact analysis. **First test:** MLP, protected probes, zonotope bound; forgetting vs. GPM at equal plasticity.

## Model surgery and live patching

**P26. Hot-swappable layers with live migration.** Replace one layer of a running model with an upgraded one, using a short "state migration" fit (map old layer outputs to new layer inputs for downstream compatibility) so downstream layers need no retraining. *New:* live migration of a single component in a deep stack as a CL primitive. **First test:** swap GPT-2 layer 6 with a version fine-tuned on code; with and without a linear migration shim; perplexity on both domains.

**P27. Organ transplant between models.** Transplant a circuit (heads + MLP rows) responsible for a skill from model A to model B, with alignment by activation matching and a small "immunosuppression" fine-tune to stop B's later training from rejecting it. *New:* skill acquisition by transplant; rejection dynamics as a measurable phenomenon. **First test:** transplant an induction-ish or IOI circuit between two Pythia seeds; skill retention over 1k steps of further training vs. distillation.

**P28. Surgical scar tissue.** After every model edit, add a thin protective layer (a frozen low-rank "scar") that projects later gradients away from the edit's subspace; scars accumulate and are periodically reabsorbed. *New:* local, per-edit gradient shielding that expires. **First test:** sequential MEMIT edits with and without scars; edit survival and general capability after 1000 edits.

**P29. Weight-space unit tests in CI.** Every update must pass a test suite (probe I/O pairs from every stored skill) in a CI loop; failing updates get automatically repaired by a minimal-norm correction that fixes failing tests (solve least-squares over the delta). *New:* a CI gate plus automatic program repair for weights. **First test:** 10-task stream; CI-repair vs. replay of the same probe set as training data.

**P30. Fuzzing for latent regressions.** Generate adversarial inputs (gradient-based fuzzing) that maximize behavior change between consecutive model versions; add found regressions to the test suite. *New:* differential fuzzing between model versions as the replay-set builder. **First test:** fuzz-found probes vs. random old data as replay buffer at equal size.

## Agents as programs

**P31. Agent as a source repo that edits itself under a type checker.** The agent's policy is a program (prompts + tools + small weights) stored in a repo; it proposes diffs to itself, which must pass a type checker over tool contracts and a test suite of past episodes before merge. *New:* self-modification gated by static checks and regression tests, unified across code and weights. **First test:** small coding agent on a stream of tool API changes; self-diff with checks vs. reflection memory.

**P32. Agent knowledge as a Datalog program.** Lessons are compiled into Datalog rules; contradictions are detected by the solver; the LM queries the program rather than reading free text. *New:* lessons as executable logic with consistency maintenance. **First test:** 50 lessons in a tool world; Datalog-backed vs. text-lesson agent on conflicting-lesson cases.

**P33. Garbage collection for agent memory by reachability.** Treat memories as heap objects and the agent's typical query traces as roots; mark-and-sweep removes lessons unreachable from any recent trace. *New:* reachability, not recency or score, decides eviction. **First test:** compare vs. LRU and utility eviction on a drifting task stream at equal memory budget.

**P34. Linker errors as curiosity.** When an agent's plan references a skill it does not have (unresolved symbol), it triggers targeted learning for exactly that symbol. *New:* curriculum from unresolved references in plans. **First test:** text-game agent with skill library; learn-on-unresolved vs. learn-on-failure on sample efficiency.

## Weight-space programming proper

**P35. Weight-space macros.** Define parametric ΔW templates (macros) by fitting a hypernetwork over many task deltas; a new task is learned by fitting macro arguments (a few scalars) rather than a LoRA, leaving the rest of the space untouched. *New:* CL in a low-dimensional macro argument space with built-in non-interference. **First test:** 20 task LoRAs on GPT-2 → hypernet macro; new-task accuracy and forgetting vs. full LoRA.

**P36. Weight-space control flow.** Implement if/else in weights: a learned gate direction routes each input into one of two delta branches inside a single layer; new tasks add branches conditioned on input features, never overwriting existing branches. *New:* branching as an explicit weight-space construct. **First test:** 5-task stream, 1 branch per task inside a GPT-2 MLP; compare with MoE-LoRA.

**P37. Weight-space loops for algorithmic generalization.** Learned skills are compiled into a weight-tied loop (one layer applied k times) so length generalization and new task variants come from changing k, not new weights. *New:* loop unrolling as a CL axis. **First test:** addition task; looped LoRA vs. standard LoRA on new lengths.

**P38. Weight-space exceptions.** A skill raises an "exception" (a dedicated output feature) when it is outside its domain; the handler (base model) takes over. *New:* calibrated domain exceptions as the CL safety net. **First test:** exception head trained with OOD negatives; harm on OOD inputs vs. no-exception LoRA.
