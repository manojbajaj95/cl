Raw proposals for harmless synthetic populations.

**PCX1. Teach a new fork the meaning of an update code rather than its donor’s coordinates.** Parts: PL4-01 effect-trained inverse, PL4-02 adaptive rank, PL4-03 permutation-aware decoder, PL4-06 newcomer boot map, PL4-07 transport after decoder drift, PL4-09 separating fixtures, PL3-01 shared update coordinates, T5-01 matched items. *Mechanism:* Define a code by signed changes on shared approved fixtures. Bootstrap each new fork with small local trials, then check whether old codes still denote the same effects after reparameterization or a decoder upgrade. When two codes agree on the anchor set but disagree on a later example, add an approved separating fixture before transporting either. *New:* A code can remain portable across model shapes and decoder versions without treating anchor agreement as proof of semantic equivalence. *First test:* Use small synthetic learners of different widths with a midstream neuron permutation and two lessons that collide on anchors. Compare direct patch transfer, fixed-rank decoding and fixture-checked transport.

**PCX2. Negotiate the part of a shared update each fork can realize without losing its next correction.** Parts: PL4-04 code-to-optimizer, PL4-08 private refusal, PL4-10 discrete write tokens, PL4-11 depth allocation, PL4-12 next-step metric, PL4-13 missing feature training, PL2-14 future-plasticity witness, D4-24 native next-update test. *Mechanism:* Decode a code incrementally in scratch state. Use the real next-step behavior on an approved branch-local lesson to compare fixed patches, local update rules and learning a missing input feature. Commit the supported portion only, recording the refused effect without borrowing the other fork’s local choice. *New:* A code can carry a common intent even if one receiver can realize only part of it or needs a different learning route. *First test:* Give two toy forks different feature access and later incompatible exceptions. Compare copying, fixed patch decoding and budgeted partial decoding on transferred gain, later editability and cost.

**PCX3. Compress a sequence of codes only after checking order and a later amendment.** Parts: PL4-05 ordered response correction, PL4-14 canceling superpositions, PL2-12 coalition witness, TT34 joint sandbox, D5-26 retained teaching response. *Mechanism:* Compare the ordered sequence, its proposed reduced code and a no-op on each receiving fork’s scratch state. Check the effects separately and jointly, including a new authorized amendment. Keep the original sequence if apparent cancellation depends on order or hides a lost teaching path. *New:* Zero net change on the anchor bank is not enough to justify deleting an update history. *First test:* Use synthetic paired forks where two codes cancel on anchors but have ordering-dependent effects on a third lesson. Compare additive compression and jointly verified reduction.

**PCX4. Trace teaching dependence through the machinery that still runs after retirement.** Parts: PL4-15 subset routing, PL4-16 attention normalization, PL4-17 running moments, PL4-21 order-sensitive detachment, PL4-22 routing gradients, PL4-23 growth decisions, PL4-25 fresh features, PL4-27 supervision selection, PL3-15 detachable residuals, PL3-27 optimizer-state split. *Mechanism:* In a synthetic learner with declared sources, keep detachable contributions and track dependencies through normalization, routing, feature growth and example selection as well as weights. After simulated retirement, compare removal orders and run an additional allowed update. Withhold claims of independence if retained behavior still depends on shared state influenced by the removed source. *New:* Detachment can fail through a state update or training-data selector even when the removed residual is no longer evaluated. *First test:* Compare weight-only detachment, source-aware state separation and allowed-only retraining in a toy stream with shared routing and a source-dependent curriculum.

**PCX5. Replace lost synergy only where independent evidence supports the new interaction.** Parts: PL4-18 protect main effects, PL4-19 inherited interaction factors, PL4-20 independent operand replacement, PL4-24 coalition-edge training, PL4-26 redundancy subtraction, PL4-28 fresh allowed interaction, PL3-28 abstaining replacement, D3-13 compatible histories, CR29 current-version relearning. *Mechanism:* Test each allowed main effect and the joint behavior under supported source subsets. Try a replacement operand or fresh interaction trained only on current approved fixtures, checking that redundant support is not counted twice. Where the evidence cannot distinguish plausible joint rules, keep the unsupported case separate rather than rebuilding it from stale predictions. *New:* A replacement can retain lawful cooperation without smuggling back a retired teacher through either double-counted main effects or an unverified cross-term. *First test:* Build harmless toy tasks with overlapping main effects and an interaction that only some allowed fixtures identify. Compare residual deletion, full allowed-only retraining and checked interaction replacement.

**PCX6. Make update codes portable without making teaching dependencies permanent.** Parts: PL4-01 effect-trained inverse, PL4-02 adaptive rank, PL4-03 permutation-aware decoder, PL4-06 newcomer boot map, PL4-07 transport after decoder drift, PL4-09 separating fixtures, PL3-01 shared update coordinates, T5-01 matched items, PL4-04 code-to-optimizer, PL4-08 private refusal, PL4-10 discrete write tokens, PL4-11 depth allocation, PL4-12 next-step metric, PL4-13 missing feature training, PL2-14 future-plasticity witness, D4-24 native next-update test, PL4-05 ordered response correction, PL4-14 canceling superpositions, PL2-12 coalition witness, TT34 joint sandbox, D5-26 retained teaching response, PL4-15 subset routing, PL4-16 attention normalization, PL4-17 running moments, PL4-21 order-sensitive detachment, PL4-22 routing gradients, PL4-23 growth decisions, PL4-25 fresh features, PL4-27 supervision selection, PL3-15 detachable residuals, PL3-27 optimizer-state split, PL4-18 protect main effects, PL4-19 inherited interaction factors, PL4-20 independent operand replacement, PL4-24 coalition-edge training, PL4-26 redundancy subtraction, PL4-28 fresh allowed interaction, PL3-28 abstaining replacement, D3-13 compatible histories, CR29 current-version relearning. *Mechanism:* Verify common effects and future learning on each receiving fork before accepting or compressing a code. Track which sources support later computation and updates, then retire a source in scratch state and revalidate independent behavior. Replace interactions only where current evidence is sufficient. *New:* The learner can separate a portable improvement from the local machinery that realizes it, and distinguish removing a patch from actually removing dependence on its teacher. *First test:* Cross synthetic learners of different shapes with ordered writes, later local amendments and detachable teaching interactions. Compare patch sharing, code sharing without checks and verified code transfer with source-aware removal at matched work.
