**RIR1. Pay for a shared fold with the old batch that restores a lost swap.** Parts: RS01 unnecessary route distinction, RS08 unknown arrivals, IN01 lawful substitution, IN06 idle clocks, RM01 shared fold, CL04 clock tracking. *Mechanism:* Within the frozen menu of interchangeable due records, choose a batch that returns the entire drifted landing tube to the opposite opener's fixed set and makes one route's continuation distinctions sufficient for the others. Keep the swap right inactive until both native transition checks pass; charge any displaced record still owed. *New:* A recovery batch could restore an executable right and make its alternate routes cheaper to remember. *First test:* Compare separately optimized recovery and compression on blind idle clocks, including a recovered swap with a surviving rare-reader distinction.

**RIR2. Delete a route exception only after the no-show branch really settles.** Parts: RS09 last exception, RS10 selective deletion, IN09 own-queue precondition, IN12 last blocker, IS09 forward settlement, WM11 verified release. *Mechanism:* At timeout revoke the swap ticket and use due old service to prepare the residual. A genuinely later useful record from the opener's own queue must settle the still-live effect. Delete a fold exception only after the remaining suffix cannot distinguish it and actual reuse leaves old floors intact. *New:* A timeout could earn memory through real learning rather than through declaring a failed partner irrelevant. *First test:* Withhold or replace the later record; compare rollback-free cleanup plus a separate fold and check old reads along every live branch.

**RIR3. Share a proof between two completions without sharing their consent.** Parts: RS11 shared residual, RS14 every request variant, IN17 two completions, IN21 minimal decision evidence, RR09 joint grant, CC19 joint frontier, RN01 narrowed executable cone, RN03 provenance quorum. *Mechanism:* Keep one continuation representation for the recovered partner branch and same-queue settlement only where it preserves the distinctions either may make. Let independent partial evidence erase disallowed effects from both representations, but require separate full consent before serving any nonzero effect. Advertise separate backed grants or one jointly feasible bundle; sharing a state abstractor grants neither right by itself. *New:* One expensive residual may support two useful options without accidentally selling both to the same capacity. *First test:* Compare disjoint certificates and exact joint admission, including two separately valid paths that compete for the same reserve.

**RIR4. Make two due batches earn alignment only in a lawful order.** Parts: RS04 order sensitivity, RS06 complementary batches, IN05 public exchange, IN07 independent witness, GR11 downstream sequence, UO11 window consumption. *Mechanism:* Freeze the actual due-record menu and check both compositions at the reached weights. Publish a supported order only if it preserves all prefixes, leaves an independent old read available and repairs a joint continuation distinction by the original deadline. Preserve a backed stop if one record never arrives. *New:* Partial scheduling freedom could remain even where one composition earns a fold and the reverse breaks it. *First test:* Cross exact scheduling and matched unordered training with a late required record and a branch that matches output but fails a later native update.

**RIR5. Borrow a temporary interpretation and return it through ordinary old work.** Parts: RS05 lasting alignment, RS12 tag-free carrier, IN03 repay coverage, IN14 reader's actual state, BF02 old update law, CS05 handoff state, SN01 selective momentum, SN09 open neutral region. *Mechanism:* Require real old-task work to move a shared carrier into a common interpretation while preserving due reads; charge any deferred diversity. Copy only the moment components visible to either future job; reconstruct the rest from allowed inputs, and check that the resulting native update lands the signed payment in the neutral region opened by useful work. Hand back the original update behavior, not just predictions, before returning memory, and let blind successor work verify it. *New:* Learning can remove a route tag by making one carrier useful for both routes rather than hiding selection in its private state. *First test:* Compare a fixed shared basis, separate carriers and an output-only handback on blind receiver changes and rare old gradients.

**RIR6. Sell partial sharing with an executable next move.** Parts: RS03 finest reader, RS16 bounded common state, RS17 partial sharing, IN10 unseen record types, IN11 supported arrivals, RM02 explicit lease. *Mechanism:* Freeze allowed arrival classes and form the joint continuation partition on reached states. Carry a bounded exception only for classes still distinguished; back its expiry by genuine forward settlement or an already certified renewal. Do not sell unknown arrivals against a smaller summary. *New:* Incomplete alignment can buy useful reuse early while preserving a verifiable contract for exceptions. *First test:* Compare full sharing, separate route state and exact finite accounting with one surprise arrival near lease expiry and an old reader that still needs the exception.

**RIR7. Move a verified fold to a new scheduler without transferring hidden history.** Parts: RS15 reassignment, RS19 finite arithmetic, IN19 second scheduler, IN13 who is next, SH01 atomic transfer, WG18 successor order, SN04 clock sensitivity, SN18 rederivation error, UN04 path-specific memory. *Mechanism:* Pass the remaining obligation, original cut and native continuation proof atomically. Rebuild the reachable envelope for the receiving scheduler's actual record orders and clocks. Test clock-skew-sensitive directions jointly with the reader-neutral corridor; matching outputs after handover is not enough. Transfer only when every newly offered path preserves old reads and the same narrow contract; preserve a scoped exception otherwise. *New:* Reuse of a fold can follow exact behavioral boundaries rather than one scheduler's implementation. *First test:* Compare full replay and unchanged receipt transfer at equal costs on a scheduler with the same margins but a new legal interleaving.

**RIR8. Price all coverage displaced by a cheaper narrow state.** Parts: RS07 cheaper joint fold, RS13 confusion graph, IN20 exchange rate, IN08 competing queue, WM01 posted price, PG19 release condition, UN10 edit-funded release, UN16 spendable width, RN19 eliminate a path. *Mechanism:* At a posted tariff, charge paid and displaced records, live bytes and proof cost. Preserve a joint budget for old coverage and backed queue work; if a competing queue spends shared slack, recompute the relevant proof before granting the release. Debit an occupancy only once the earlier edit survives on its replacement path and the later editor uses the returned direction for an incompatible write. Validate the refund by a distinct later write. *New:* A smaller fold can be compared honestly against the old service it asks someone else to deliver. *First test:* Compare fixed per-queue budgets and direct full-state continuation with matched realized service and a later claimant using supposedly refunded bytes.

**RIR9. Use realized progress to distinguish missing supply from missing information.** Parts: RS02 restrict reachability, RS18 joint proof, IN04 verifier ambiguity, IN16 exhausted arrivals, UB13 unresolved evidence, PX08 missing edge, RN12 native-step null, RN20 disarm. *Mechanism:* Return different witnesses for no lawful batch that reaches a settlement region, an existing batch that cannot be chosen from public observations, and an overbroad approximation that only fails to certify. Disarm a pending relation when justified narrowing removes its final clean realization; a nominal null with no useful authorized effect cannot count. Use actual required work to narrow reachability where possible; never treat an unexplained refusal as proof. *New:* The next proposer can target genuinely missing training capability instead of paying for more proof or storage indiscriminately. *First test:* Plant each kind of obstruction and a valid but conservatively rejected fold; compare exact reachability and generic refusal while reading old tasks.

**RIR10. Earn a shared carrier through recurring swaps, defaults and reuse.** Parts: RS05 lasting alignment, RS20 later writer, IN17 contingent options, IN18 hidden partner, DP20 renewable reserve, BP04 returned capacity, UN01 opposing pair, UN06 cancelling partner switch. *Mechanism:* Co-train one public carrier for a fixed recovery menu and a useful own-queue exit. Certify the same offered write across all reachable aliases by opposing native dependencies, including a partner change at an activation seam. Verify that alternating ordinary successes and defaults do not repopulate deleted distinctions; reuse the returned block for a blind writer before checking the following pair, including hidden partner identity and due readers. *New:* Recurring recovery might make future memory cheaper instead of accumulating route-specific state at each default. *First test:* Compare two independent recovery lanes and repeated tag compression under multiple defaults, a concurrent ordinary arrival and actual reuse.
