**SAR1. Grow a rendezvous only for the cases a replayed swap cannot settle.** Parts: SD2-01 reorder guard, SD2-06 directed prerequisite, SD2-07 scoped repair, SMA07 synchronize collisions, SMA15 commute redundant rounds, OS19 executable order. *Mechanism:* Rehearse both orders of two toy module updates under matched disturbances. Route only observable conflict cases through a rendezvous; preserve the directed prerequisite if one path is illegal. Let genuinely unknown cases take a predeclared fallback instead of inventing a safe order. *New:* Replay could teach when synchronizing is worth the delay without requiring a global scheduler. *First test:* Use finite inventory tasks with reversible and irreversible examples. Compare always locking, pairwise order tests and context-scoped rendezvous at equal work.

**SAR2. Retire a shared producer only when each recipient gets its real continuation.** Parts: SD2-02 named reader, SD2-09 separating suffix, SMA09 distribute state, SMA18 residual commitments, ER4-21 typed group cutover, VD24 adverse receipt. *Mechanism:* Give each recipient just the projected producer state it needs. Shadow replay the same pending messages on each path and preserve an adverse suffix as a regression witness. If any due consumer still needs the producer, keep a compatibility path until that consumer's obligations can transfer together. *New:* Architecture retirement could preserve reader-specific obligations without copying a whole module into each successor. *First test:* Test a toy shared producer with two consumers, one delayed result and one failed request. Compare full copies, immediate removal and targeted projection.

**SAR3. Reopen an update path only when a recipient can exhibit a missing distinction.** Parts: SD2-13 late refinement, SD2-19 relearnable distinction, SD2-23 share query, SMA13 keep forward path, SMA19 counterexample edge, BM4-26 smallest separator. *Mechanism:* Keep the forward operation while removing a costly update edge. Preserve a lawful witness query rather than its answer; if a later recipient demonstrates that aliased histories require different choices, grow the smallest local correction path that resolves them before the deadline. *New:* An architecture could stop storing an update rule while retaining the ability to relearn it from fresh evidence. *First test:* Make a toy readout lose adaptation but not accuracy and compare a permanently open edge, an equal-byte replay buffer and witness-triggered regrowth.

**SAR4. Keep a swap certificate conditional across two blind architecture edits.** Parts: SD2-05 third-edit blocker, SD2-24 certificate with a hole, SD2-25 unresolved square, SMA20 translate legal operations, SMA24 joint cut, ER2-27 noncommuting edits. *Mechanism:* Translate editable operations across two joint consumer migrations. Carry the short third-edit prefix that could invalidate an existing swap and leave the certificate unfilled until a new lawful observation resolves it. Require the translated schedules to preserve old reads, not merely share current outputs. *New:* A reusable order relation could survive changes of implementation without treating a once-valid swap as permanent. *First test:* Place a known order counterexample behind the second reader migration in a small automaton. Compare cached pairwise certificates, full reverification and a scoped unresolved witness.

**SAR5. Spend delayed feedback on the successor that can still act on it.** Parts: SD2-11 encode a continuation, SD2-15 shared observation budget, SD2-22 observable divergence, SMA17 logical cut, SMA23 delayed credit, ER4-13 reader deadline, SD22 in-flight rehearsal. *Mechanism:* Replay delayed outcomes across a logical architecture cut without sorting by arrival time. Use operation provenance to route feedback to the successor that can still implement the corresponding correction, and choose the first observable divergence only if it can change an action before that successor's deadline. *New:* A rewrite might retain useful credit assignment without retaining the predecessor or duplicating every feedback record. *First test:* Simulate one split with delayed and reordered feedback. Compare arrival routing, old-module replay and provenance-based continuation using equal queue space.

**SAR6. Teach a joint rule only after separate corrections fail in the same reachable case.** Parts: SD2-03 admissible couplings, SD2-04 aligned noise, SD2-10 separate safety target, SMA25 typed feedback, SMA29 joint correction, RB12 joint certificate. *Mechanism:* Replay paired evidence messages under aligned draws. Compare both isolated edits and a joint rule consuming typed observations in one realizable history; keep separate rules when they safely agree. Export a scoped inseparability witness rather than fusing every update. *New:* Shared training could synthesize a new operation only where one legal sequence cannot satisfy both corrections. *First test:* Cross independent and correlated nuisance effects on two toy corrections. Compare averaging, permanent fusion and exact context-dependent joint planning.

**SAR7. Freeze a common prefix that two later readers can specialize without taking each other's work.** Parts: SD2-12 adaptation program, SD2-17 two return ports, SD2-18 worst recoverable setting, SMA08 common prefix, SMA21 joint roles, LE5-20 compact interface, ER3-15 reader partitions. *Mechanism:* Commit a small shared carrier and a local adaptation program before revealing the returning settings. Assign roles only from lawful observed context. Price both short-lived views and preserve their pending deadlines under interleaving; expose a losing slice when no affordable carrier supports both. *New:* A shared representation could buy useful later adaptation without owning or overwriting either reader's private continuation. *First test:* Withhold two return settings and interleave their requests at fixed memory. Compare separate copies, one static adapter and a shared prefix with executable refinements.

**SAR8. Grow a new state split only where a rehearsal identifies a distinct next action.** Parts: SD2-14 rebind first guess, SD2-20 impossible recovery, SD2-21 exception basis, SMA01 continuation counterexample, SMA14 history quotient, BM4-26 separating observation, ER3-13 joint cue loss. *Mechanism:* Match two histories with identical present observations and find a short lawful suffix that demands different next actions. Grow the new state distinction at the first boundary that can observe it; if no cue arrives in time, retain a backed safe common action or mark that slice infeasible. *New:* A rewrite could allocate state for consequential order exceptions instead of replaying all old histories. *First test:* Plant two redundant carriers and one late cue in a finite scheduler. Compare automatic state growth, exact refinement and scoped counterexample-triggered growth.

**SAR9. Run real useful work under an independently chosen replacement and then replace it again using only the overlap where legal operations translate. Keep unsupported directions visible and payable rather than forcing a full bidirectional map. *New:* A portable operation relation could be bought without locking the next trainer into the translator's own feature convention. *First test:* Test three consecutive toy module compositions with incompatible internal coordinates and matched local observations; compare fixed translations, duplicate experts and tested partial operation maps.
