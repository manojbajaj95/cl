# Cross-pool merges, round 19

Focal sources: `tree/conservative-extension.md` (PR #122, CE#) and `tree/function-matched-twins.md` (PR #123, FT#). Crosses with counterfactual shadows (F2-5, SM34 in PR #43), B22 stateless twins (PR #48), RL3 verifier twins (PR #51), N34 Liskov memory (PR #41), adapter contracts (PR #117, AC#), and earlier cross-pool rounds. Preservation over a declared legacy interface is distinct from matching today's predictions and from surviving later learning. A sampled twin match is not global function equality. These are raw and unfiltered.

**CT1. Qualify an extension twice: as a program and as a learner.** Parts: CE1 eliminable definitions, CE9 sealed distinguishing contexts, FT1 ordinary-history twins, FT3 mismatch dose, GP3, N34 Liskov (PR #41). *Mechanism:* Check that each new symbol expands into an old-language program with unchanged observations. Then compare the extension with an output-matched isolated namespace under the same future minibatches. Treat an observed difference in future retention as a separate trainability finding, not a counterexample to the static proof. *New:* A certificate can say that old calls still mean the same thing without claiming that subsequent learning will preserve them equally well. *First test:* Compile two implementations in a tiny typed interpreter with a trainable dispatcher. Exhaust old terms at launch, then run matched updates and compare held-out service to isolated routing, full rechecking and injected launch-mismatch controls.

**CT2. Make a shadow twin that isolates an edit from the habits it arrived with.** Parts: CE8 merged admission, CE12 formal versus live failure, FT4 reset-and-swap, FT11 gauge audit, F2-5, SM34 (PR #43). *Mechanism:* Run shadows that cross two histories with edit present or absent on identical serving and training inputs. Use independently reset or swapped optimizer slots to distinguish an edit interaction from carryover, and compare simple function-preserving reparameterizations before attributing the interaction to learned protection. *New:* A twin-based rollback can respond to the edit's interaction with history rather than punishing any change that appears after installation. *First test:* In a typed agent with a trainable router, plant a bad edit, a momentum-only artifact and a history-specific interaction. Compare attribution and false rollbacks to one no-edit shadow and comparing end scores alone.

**CT3. Give an adapter a compatibility test for its next lesson, not just its current answer.** Parts: CE15 independent client observations, FT12 gate crossing, FT21 future response transfer, AC1 finite response and AC7 trainability (PR #117), FP6. *Mechanism:* Register a bounded client write contract and run matched public adaptation jobs on shadow copies of old and updated bases. Check complete logits and actual one-step effects before buying longer forks. On a failed future-service check, test whether a small transport can restore the downstream response without changing the caller contract. *New:* A static ABI pass and a dynamic learning pass can be routed separately, so a base need not freeze all client features to admit an upgrade. *First test:* Add a gating-boundary shift to the PR #117 tiny adapter world. Compare the two-stage gate with activation-only compatibility, finite-response matching and same-call per-adapter distillation.

**CT4. Learn a distinction from the caller, not from twin histories that only the benchmark knows.** Parts: CE2 missing context, CE11 unknown meaning, CE16 scoped revisions, FT13 history/future crossover, RL3 verifier twins (PR #51), N34 Liskov (PR #41). *Mechanism:* Use ambiguous old/new calls with counterbalanced contexts to ask which public caller field legitimately distinguishes the contracts. For continuations that reverse which twin is safer, do not treat hidden training history as a usable context bit; retain the old route on unsupported calls. Bound permitted context queries separately from proof work. *New:* Separates a semantic conflict that needs caller information from a dynamic risk that needs a safer implementation. *First test:* Build a tiny overloaded language where one field is truly discriminative and another is only correlated with launch order. Compare against global version tags, history-conditioned routing and always asking.

**CT5. Retire a state representation only when an old caller can still wake it up.** Parts: CE5 inductive simulation, CE13 retraction, CE21 implementation reclamation, FT7 exchange modules, FT18 finite-depth matching, Q5, GP8. *Mechanism:* Migrate states with a checked retraction for legacy observations. Probe histories with matched visible outputs but different carried state using identical public continuation prefixes. If the transferred state fails at a later old-context read, extend the relation only with the missing observable dependency or keep a scoped fallback. *New:* A migration can preserve state needed after several calls without saving every private field or inferring complete equality from snapshots. *First test:* Enumerate finite agent states with a delayed dependency two calls away. Compare retraction plus continuation tests against serializer round trips, output distillation and exhaustive state retention.

**CT6. Make a verifier twin challenge the certificate's observer.** Parts: CE17 partition proof, CE20 audit escalation, CE22 weak observers, FT3 mismatch dose, FT15 separating bank, RL3 verifier twins (PR #51), Q7. *Mechanism:* Construct pairs of old contexts that agree under the registered observer but differ under an independently executable caller check. Buy the next challenge based on which observation ambiguity could change admission. Reuse the resulting counterexample to refine the scope; a passing empirical probe never silently upgrades a bounded proof. *New:* A twin is a test of the admission language itself, not only of the candidate edit or of the learner's retention. *First test:* Use a typed workflow with an old return value and hidden ordering requirement. Match oracle calls against random context audits, full rechecking and checking the candidate with no observer revision.

**CT7. Distinguish a bad service contract from a queue the extension made disappear.** Parts: CE12 formal/live witnesses, CE14 contention, CE19 world variation, FT16 path versus clock, B22 stateless twin (PR #48), BR7. *Mechanism:* Pair a stateless traffic twin with the deployed learner and evaluate the same old calls under fixed arrivals and policy-induced arrivals. Track completion, abstention, selection and learning progress separately. Permit a safe-looking new tool only if it keeps the declared old service floor, including queue delays, or explicitly narrows its scope. *New:* A service regression can come from the extension changing access to work, even when completed old calls still satisfy the same semantics. *First test:* Add shared budget and return traffic to a finite agent. Compare detection and new-task service against semantic-only admission, aggregate accuracy checks and an always-frozen route.

**CT8. Consolidate the better future of two equivalent implementations, not their mean.** Parts: CE8 joint admission, CE15 independent observation maps, FT19 protection backup, FT22 safe merge, POP13 path witnesses (PR #116), AC16 composition (PR #117), FP12. *Mechanism:* Search for a merged candidate whose old observations match both compatible contracts and whose bounded future shocks preserve each protected skill. Check the actual combined write and all relevant serving paths instead of independently certifying two components. Refuse to claim a best-of-both result if the protections cannot coexist under the deployment budget. *New:* A merge can target complementary future service without requiring identical internal specialization or hiding trade-offs behind a mean score. *First test:* Train two tiny specialists that match current service but fail on opposite shared updates. Compare merged coverage with weight averages, routed replicas and finite-response matching alone at equal capacity.

**CT9. Invalidate a proof only when a change can reach the thing it protects.** Parts: CE6 proof dependencies, CE9 sealed contexts, FT5 liability clock, FT9 targeted contraction, SM34 (PR #43), GP10. *Mechanism:* Keep static proof dependencies separate from empirical future-service witnesses. Use an edit's read and write set to recheck reachable proof clauses, and use a short common continuation to remeasure dynamic liabilities after a changed optimizer or curriculum. Retire monitors only when independent controls show they are redundant for the declared horizon. *New:* Proof reuse and training-response reuse have different invalidation rules; neither needs indiscriminate refresh. *First test:* In a tiny tool language plus trainable dispatcher, plant one harmless refactor and one future-only change. Compare verification cost and missed regressions with full rechecking, purely syntactic invalidation and fixed re-audit intervals.

**CT10. Ship the invariant to the new host and let the host choose how to preserve it.** Parts: CE10 missing write access, CE18 portable contracts, FT10 transport protection, FT21 future traces, P6 recompilation (PR #39), N1 round trip (PR #41), F2-5, BR4. *Mechanism:* Export a public old-observation contract and a fixed bank of legal future challenges, not a donor delta. Let the target choose a native intervention under that contract and compare paired with/without-transfer shadows; if it cannot preserve old service and learn the new task, expose the missing controllable port rather than quietly relaxing the contract. *New:* A host can inherit a testable protection rule even when donor coordinates or learning dynamics cannot be mapped. *First test:* Move a defended typed skill between a linear dispatcher and a tiny ReLU dispatcher with different ports. Compare behavior, future retention and acquisition against direct weight transfer, ordinary distillation and isolated version routing.

**CT11. An extension that proves what old calls mean and tests what later training will do to them.** Parts: CE1 definitions, CE2 context, CE5 simulation, CE6 dependencies, CE8 merged admission, CE9 sealed contexts, CE12 service, CE13 retraction, CE14 contention, CE15 multi-client maps, CE17 partitions, CE18 portability, CE20 escalation, CE22 observer challenge, FT1 ordinary history, FT3 mismatch, FT4 swaps, FT5 relaxation, FT6 finite matching, FT9 contraction, FT11 gauge, FT13 crossover, FT15 challenge bank, FT16 matched progress, FT19 fallback, FT21 transfer, FT22 merge, F2-5, SM34, B22, RL3, N34, AC1, AC7, GP3, GP8. *Mechanism:* Admit an extension only when it serves the new task and preserves old observations over a declared context scope. Separately put admitted versions through function-matched shadow futures with common batches and untouched old probes; isolate optimizer, launch mismatch and one-step shortcuts before buying a longer probe. When a violation is found, distinguish missing caller context, a changed consumer, a service bottleneck and future-only liability, and spend repair work on the implicated surface. *New:* Static conservativity and empirical robustness to later learning become separate release conditions with different evidence and remedies. *First test:* Combine the PR #122 typed language and shared-budget agent with the PR #123 common-future twin protocol. Plant an overload conflict, a downstream adapter change and a future-only retention gap. Compare frozen version routing, exact in-scope rechecking, matched same-input logits and first-update controls, and an equal-budget stack of standalone guards. Report new-task uptake, false admissions, proof scope, and worst old service at matched progress.
