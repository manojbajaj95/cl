# Flood: multi-agent continual learning

64 raw proposals. A player can be a task's probe generator, an optimizer head, an adapter owner, or a separately deployed agent; it needn't be another LLM. The aim is to find new objects or operations that other continual-learning methods could build on. Near neighbors are starting points for review, not verdicts. Screened against the [ledger and triage in PR #6](https://github.com/manojbajaj95/cl/pull/6) and adjacent floods, especially [econ-society](https://github.com/manojbajaj95/cl/pull/45).

All first tests are CPU toys unless noted. Score old tasks on held-out examples, not settlement or training probes; report the worst old-task change from its pre-switch score as well as new-task learning. Match the named control on relevant storage, probes, training/evaluation compute, and inference calls; charge the mechanism for trial updates and market settlement. Compare retention at matched new-task accuracy where possible (otherwise show both axes). No experiments have been run.

## A. Property rights over updates

**M1. Auction the right to write first.** Task proxies bid numbers of their future SGD steps for positions in a write order on one nonlinear block; the earliest writers surrender those steps to displaced tasks, and the winner order is applied without extra updates. **Why it might be new:** the lot is precedence between noncommuting writes, not examples or rank (cf. gradient surgery and scheduling auctions). **First test:** train three alternating XOR MLP heads sharing their first layer; retention: first two XOR variants after the third. **Tie control:** greedy order from measured pairwise interference using the same trial steps and per-task update counts.

**M2. Sell the cross term.** Each task proposes a rank-one step; a clearinghouse estimates the two-write interaction by subtracting each isolated loss change from their joint change. Buy compatible write bundles and use the interaction surplus to fund replay for any loser, then commit the bundle. **Why it might be new:** credit attaches to joint interference rather than gradient externalities (cf. E15 VCG gradient taxes, combinatorial auctions). **First test:** rank-one updates on a three-task factorized linear net with a rank bottleneck; retention: both old regressions after the last stream. **Tie control:** greedy selection using the same joint-loss probes, splitting replay uniformly.

**M3. Conserved write currency, depreciating monopolies.** Tasks mint write tokens only by donating adaptation batches that measurably help another task. Unspent tokens lose value whenever their owners occupy many frequently written coordinates; spend tokens to unlock partial writes to those coordinates. **Why it might be new:** cooperative transfer creates spendable permission to interfere, rather than rent charged for gradient demand (cf. E1, demurrage). **First test:** alternate related and unrelated linear tasks with disjoint rare features; retention: rare features on the original two tasks after frequent tasks dominate. **Tie control:** importance masking with the same write sparsity and transfer-gain probes.

**M4. Trade maintenance across layers.** An incumbent offers to protect another task's bottom-layer feature directions if that task maintains its top-layer calibration; the accepted matching defines which task-specific loss is backpropagated into which layer, not which task owns the whole model. **Why it might be new:** exchangeable duties are layer-targeted backward passes (cf. barter matching, layerwise replay). **First test:** two old tasks share low-level image features but not decision boundaries; learn a third shifted task. Retention: old feature shifts and calibration on held-out digits. **Tie control:** optimize the best fixed layerwise loss routing on the same trials.

**M5. Rights to an invariance, not coordinates.** Old tasks sell write easements that let new optimizers use any parameters so long as they keep a task-owned behavioral relation (e.g., flip equivariance) within a purchased tolerance; a violated easement redirects the next update to repair the relation. **Why it might be new:** tradable rights specify what models may change under transformations, not what cells are frozen (cf. constrained CL and property easements). **First test:** sequential synthetic image attributes with competing rotations/flips; retention: old attribute accuracy on fresh transformed examples. **Tie control:** fixed invariance regularization with equal batches and the same transforms.

**M6. Pay-to-fork a shared feature.** If tasks disagree on a feature update, they pool bids for a split and repay its extra bytes by compressing their own heads; after splitting, gate the corresponding channels by task. **Why it might be new:** a split is a negotiated redistribution along the entire model, not automatic progressive expansion (cf. DEN and public-good provision). **First test:** a tiny MLP where a shared hidden feature becomes harmful to one of three tasks; retention: first two tasks after the split and compression. **Tie control:** loss-triggered expansion with the same final width and head sizes.

**M7. Clearinghouse for the write echo.** Each writer must post a candidate follow-up delta in case the next little batch amplifies its current damage; the next task can clear the echo jointly with its own update, or decline and buy ordinary rehearsal instead. **Why it might be new:** a jointly exercisable repair proposal is the object, not a stored inverse update or a loss debt (cf. E9, extragradient). **First test:** alternate cyclic spiral streams on a 2-layer MLP; retention: longest-absent spiral after each switch. **Tie control:** lookahead replay with the same number of trial and committed steps.

**M8. Negative-space capacity auction.** An incoming task bids for a direction along which old proxies agree they will *not* rehearse; fit that direction on the old proxies' null-space sketches, then train in it for a short lease. Proxies can pool their vetoes across individually safe directions that together threaten them. **Why it might be new:** the purchase is a coordinated commitment not to counterwrite (cf. OGD and bundle auctions). **First test:** multi-output regressions with overlapping approximate null spaces; retention: original tasks after two concurrent tenants. **Tie control:** joint Jacobian projection with the same sketch bytes and projected-rank budget.

## B. Prediction and truthful memory writes

**M9. Market on which lesson to pair, not which to keep.** Memory readers forecast how a lesson pair changes a fixed downstream decision relative to both singletons. A randomized paired audit pays proper scores; clear only complementary pairs into two-slot memory. **Why it might be new:** the priced object is interaction under joint retrieval, not an endorsement, portable lift, or a forgetting forecast (cf. combinatorial prediction markets). **First test:** grid instructions combining exception and default rules over three maps. Retention: original maps after later exceptions enter memory. **Tie control:** pairwise empirical lift ranking with the same four-arm audits and prompt tokens.

**M10. Exclusion market.** Memory writers issue probability distributions over the kinds of inputs on which *their own* advice would hurt relative to abstention. Proper scores on a random no-write/challenger split train a soft exclusion mask for each lesson, including currently unused lessons. **Why it might be new:** wagers pay for calibrated failure boundaries whether or not the lesson is accepted (cf. selective prediction and counterexample-guided preconditions). **First test:** synthetic symbolic repair rules with changing applicability. Retention: previously learned repairs after two conflicting rules arrive. **Tie control:** supervised applicability masks using the same labeled audits and mask bytes.

**M11. Buy information instead of buying memories.** Several readers price alternative unknown outcomes of an unlabeled old query; the same scoring budget pays whoever reduces posterior disagreement on other queries after the one purchased label settles. Write only the selected labeled examples into rehearsal memory. **Why it might be new:** what circulates is the external value of an audit to other predictions, not lesson popularity (cf. Bayesian active learning and information markets). **First test:** drifting contextual bandits with correlated old contexts; retention: held-out regret on the first two bandits. **Tie control:** expected information gain with the same queried labels and model heads.

**M12. Prediction market for disagreements about outcomes.** Two writers publish rival memories with identical prescriptions but different outcome models. A reader buys one outcome forecast to plan exploration; settle randomly on a held-out transition, and route the memory to the better calibrated forecast for that state. **Why it might be new:** identical actions need not imply interchangeable memories; the market preserves predictive alternatives (cf. successor representations and mixture-of-experts). **First test:** tiny gridworlds where the same action opens different doors in old and new regimes. Retention: planning success in original regimes after regime three. **Tie control:** likelihood-gated mixture with identical transition observations and state size.

**M13. Sworn evidence, competing explanations.** An experience owner submits a minimal trajectory claim; a distinct interpreter supplies a rule backed by that claim. If a random audit vindicates the trace but not the rule, only the rule bond burns and only that memory edge is pruned. **Why it might be new:** split liability lets observation outlive its wrong lesson (cf. factored provenance and principal–agent contracting). **First test:** text-free crafting rules learned from traces with incidental cues; retention: early recipes after a rule shift. **Tie control:** keep traces and rules separately, prune by independent audit accuracy at the same byte and audit budget.

**M14. Deliberately make memory writers uncertain about their audience.** Writer agents submit (scope, payload) offers before recipient identities are sampled; test a concealed mix of new and old recipients, pay on disclosed scope accuracy, and distill only successful recipient–payload pairs into a retrieval policy. **Why it might be new:** buyer identity is a mechanism lever against writing to proxy quirks, distinct from testing a lesson on another model (cf. mechanism design behind a veil of ignorance, domain generalization). **First test:** three small retrieval agents with swapped spurious cues. Retention: original agents' decisions on fresh old inputs after adding two recipients. **Tie control:** pooled multi-recipient validation with the same audits and policy size.

**M15. Market for absence proofs.** Competing auditors predict whether deleting a memory leaves a sampled set of task families unchanged; those families have different randomized inclusion rates, published before trading. Settle with an actual knockout; evict the entry only after a profitable unchanged bet and spend freed bytes on a fresh entry. **Why it might be new:** claims concern redundancy relative to a live catalog, not popularity or recency (cf. E38 fence audit and decision markets). **First test:** compositional policies with duplicate and unique rules. Retention: early-rule execution after repeated evictions. **Tie control:** direct knockout estimates with identical stratified samples and admission policy.

**M16. Reveal when you learned it.** Writers may submit a memory now or wait and submit it with one confirming episode; a posted menu trades scope of initial routing for verifiable evidence and claws it back on failure. Train a separate reader gate for each evidence tier. **Why it might be new:** evidence timing is a strategic variable the memory protocol can price, rather than fixed delayed verification (cf. dynamic screening and kinetic proofreading). **First test:** symbolic tool choice with transient successes and persistent rules; retention: previously valid tool choices during false new trends. **Tie control:** fixed early provisional slot plus confirmation using the same examples, audits, and slots.

## C. Replay coalitions, bargaining, and appeals

**M17. Shapley replay across time, not records.** Task players contribute replay *appointments*; estimate a task's marginal improvement over permutations of appointments spanning two switches, then reassign slots according to those credits. **Why it might be new:** a contribution is a scheduled intervention that can synergize with another switch's rehearsal (cf. Data Shapley and spaced replay). **First test:** three related permuted-digit tasks with short returns. Retention: both first tasks after the final switch. **Tie control:** greedy marginal gain from the same replay rollouts, dropping permutation averaging.

**M18. VCG with rival replay plans.** Old-task proxies submit alternative batches requesting different numbers of replay slots; select a winning bundle by predicted held-out gains. Re-solve without each winner, deduct its foregone surplus from next-window slot credits, and train on the current bundle. **Why it might be new:** a VCG pivot is applied to rationed replay plans rather than taxing destructive gradients (cf. E15, weighted coresets; truthfulness not assumed with learned valuations). **First test:** four classifier tasks with overlapping exemplar needs and induced inflated bids. Retention: per-old-class recall after the last two waves. **Tie control:** greedy unique-coverage replay with the same proposals and audit budget.

**M19. Credible-threat bargaining.** The incoming task and an incumbent each compute what they could learn if assigned the block alone, starting from current weights. Compute a Nash bargain over mixed updates using those disagreement values; if no deal clears, spend the window on separate heads instead. **Why it might be new:** attainable alternatives, not fixed per-task reference losses, determine who concedes shared capacity (cf. Nash-MTL and bargaining with endogenous outside options). **First test:** conflicting clustered regressions with one task gaining access to a shortcut halfway through. Retention: early regressions on non-shortcut inputs. **Tie control:** Nash-MTL with fixed disagreement and the same head reserves, gradients, and trial evaluations.

**M20. Contingent truce over an unlabeled region.** Old and new task agents agree to apply a shared update on confident examples but assign a small bypass to a disputed region until a random query there is labeled; settle by folding the bypass into the preferred update or retaining separate routing. **Why it might be new:** bargaining can leave a named subdomain unresolved without suspending the whole update (cf. deferral and domain adaptation). **First test:** checkerboard classifiers with a delayed label in one quadrant. Retention: old performance both inside and outside that quadrant after settlement. **Tie control:** entropy-gated separate head with identical delayed queries and head size.

**M21. Right of appeal after consolidation.** Each losing task receives one challenge to spend on a counterexample cluster. An accepted cluster forces a rollback decision on the next proposed low-rank consolidation, using aggregate candidate updates rather than restoring an earlier model. **Why it might be new:** a scarce appeal changes a future decision, rather than becoming another hard-replay sample (cf. CEGAR and algorithmic recourse). **First test:** learn sequential shape rules with rare exceptions. Retention: held-out variants of the first two exceptions after the next consolidation. **Tie control:** automatic worst-cluster gating with the same probes and retry budget.

**M22. Replay jury drawn from tasks with no stake.** A coalition disputes how to repair an old failure; task proxies unaffected in the initial audit are selected by lot, and their trial changes decide which repair to apply. **Why it might be new:** the deciding signal is predicted spillover to nominal outsiders, not votes on shared memory or worst-task priority (cf. sortition and held-out validation). **First test:** five interacting binary classification rules, with two competing repairs for one old class. Retention: original disputants plus old outsider tasks after several repairs. **Tie control:** select by total held-out loss with the same audited proxies and steps.

**M23. Coalitions buy complementary replay bottlenecks.** A task that retains examples but lacks labels joins one with a reusable decoder but few examples; a matching market pays only when the proposed decode-and-replay pair passes third-party probes, then consumes the pair in one update. **Why it might be new:** the constituent contributions are unlike goods, not competing labeled records (cf. co-training and matching markets). **First test:** synthetic sequences, previous-wave aliases, and a shared inverse grammar. Retention: early sequence transduction after new aliases arrive. **Tie control:** nearest-compatible decoder assignment with the same labels, examples, and verification calls.

**M24. Nonpunitive amnesty rounds.** A task proxy can confidentially admit its historical replay requests no longer improve its score; in return it gets a one-window audit guaranteed against deletion, and freed slots go to claimants that actually help. Keep the compact policy only if it passes the audit. **Why it might be new:** incentives separate disclosure of redundancy from a loss of future protection (cf. contract amnesty and replay pruning). **First test:** proxies with a synthetic reason to hoard slots across alternating regression tasks. Retention: old tasks that relinquish slots, especially after a long gap. **Tie control:** utilization-based pruning with equal grace windows and audits.

## D. Leagues and no-regret learning

**M25. PSRO over write policies.** Build a payoff table whose rows are recent learners and columns are historical *writers* capable of continuing training on a short task schedule. Approximate best responses train against a meta-solver's mixture of these destructive continuations; deploy one learner, not the historical ensemble. **Why it might be new:** the league game is about surviving someone else's weight update, not beating its acting policy (cf. PSRO and learned optimizers). **First test:** 3 writers cycling through directional gradient subspaces on four overlapping regressions. Retention: old regressions after an unseen two-write continuation. **Tie control:** uniform meta-training on the same writers and inner steps.

**M26. League of former collaborators.** Keep fixed partner policies from prior waves, not the learner's old copies. A meta-solver assigns partner pairings that expose worst cross-play deficits, and new weights are trained on those matches. **Why it might be new:** continuity becomes compatibility with the history of collaborators rather than old-task labels (cf. FCP and PSRO; test the temporal compatibility claim). **First test:** two-player referential games with evolving partner conventions. Retention: success with early partners on fresh referents after the final entrant. **Tie control:** uniform partner replay with identical policies, games, and optimizer steps.

**M27. Reciprocity as a memory carrier.** In a repeated coordination league, an incumbent rewards a newcomer for preserving another incumbent's convention by switching to the newcomer's higher-value convention when context permits. Train the newcomer with the resulting contingent rewards, then remove the league. **Why it might be new:** a reciprocal response policy can transmit maintenance norms without explicit old-task reward (cf. indirect reciprocity and multi-agent self-play). **First test:** two-context signaling game with three generations. Retention: latest agent's old-code success with an unaware original partner. **Tie control:** equally frequent old-code partners without contingent switching, matching rewards in expectation.

**M28. Swap regret over update operators.** Record regret for replacing a chosen optimizer action (freeze, project, rehearse, append) with each other action only when that original action would have been selected. Fit a contextual swap-regret policy and apply its recommended updates. **Why it might be new:** retention can be an equilibrium property of conditional deviations in learning decisions (cf. internal-regret minimization, not merely task reweighting). **First test:** cyclic sparse feature tasks with a budget of one step per round. Retention: early classifiers after the last regime. **Tie control:** external-regret operator selection with identical estimates and trial calls.

**M29. Correlated equilibrium of write masks.** A common random signal recommends coordinated sparse masks to task optimizer heads. Each learns only from regret against unilateral mask deviations; execute the resulting correlated sparse updates on a shared model. **Why it might be new:** shared correlation can preserve compatible write pairs that independent routing misses (cf. correlated equilibrium and gradient masking). **First test:** three nonlinear MLP tasks with updates that conflict only when applied to the same units. Retention: early tasks after synchronized arrivals. **Tie control:** independent mask policies with the same marginals, sparsity, and reward observations.

**M30. Sleeping experts who remember their own opportunity cost.** A dormant skill keeps one small accumulator for the regret it would incur if replaced by a shared fallback when it wakes. On recurrence, update only the adapters belonging to experts with largest sleeping regret. **Why it might be new:** regret compares an explicit migration to a fallback on awake rounds, instead of training every rare expert or broadcasting an old score (cf. sleeping experts/ specialist aggregation). **First test:** heavy-tailed arrivals of old symbolic translators. Retention: same-wave first-attempt accuracy on waking up after long gaps. **Tie control:** frequency-and-loss prioritized adapters with the same activations and updates.

**M31. Continual play under regret to the never-forgotten policy.** Low-rank task heads compete against a streaming comparator allowed to spend at most the learner's total replay budget but allowed to shift it retroactively across switches. Minimum predicted regret to that comparator determines the next rehearsal batch. **Why it might be new:** comparator hindsight prices *when* an intervention would have mattered, rather than just whether an old task loses now (cf. shifting regret and budgeted online learning). **First test:** exact small comparator on two recurrent linear tasks and one distractor. Retention: both old test sets at each return. **Tie control:** worst-loss replay with identical lookahead and audit budget.

**M32. Rectified retention league.** Keep adversary policies that impersonate old partner protocols. Train each new specialist only against archived opponents it can beat but against which the current common model regressed; distill the specialists' *action advantages* into the common model. **Why it might be new:** rectification uncovers lost competencies via disagreement between current learner and live specialists, rather than finding new niches (cf. rectified PSRO and policy distillation). **First test:** iterated tiny coordination games with three partner rules. Retention: average and worst original-partner success after rule four. **Tie control:** error-prioritized uniform specialist distillation with equal teacher matches.

## E. Financial derivatives on capabilities

**M33. Call option on a learning direction.** An old task buys, before going dormant, the right to veto one dimension of a future write if an audited capability drops below strike; exercise by removing the step's component along a stored low-rank direction. **Why it might be new:** contingent ownership concerns a particular future gradient direction and locally modifies execution (cf. options and importance protection, not insurance-funded replay). **First test:** sequential low-rank regressions with rotating feature bases. Retention: old task after a rare overlapping write plus two harmless ones. **Tie control:** fixed per-direction protection tuned to average intervention frequency, same sketches and probes.

**M34. Sell a forward on a repair bundle.** Current and future training rounds share a schedule: a writer gets extra bandwidth now only by posting two repair examples and a future window in which its proxy promises to inject them. Precommit resource exchange and discard the bundle when delivery passes its audit. **Why it might be new:** enforceable reserved scheduling is the primitive, not betting on loss or posting bare replay debt (cf. E7, E9, forward delivery). **First test:** periodic task returns with bursty compute availability and two-window repair deadlines. Retention: first-task accuracy before and after each delivery. **Tie control:** periodic replay with matched timing information and total steps.

**M35. Capability swaps between deployments.** Two deployments exchange commitments to maintain each other's lowest-coverage task; both train on the partner's probes and periodically return only learned query-conditioned corrections, not weights. **Why it might be new:** exchange is of future maintenance exposure, not static specialization or merging (cf. E39, swap contracts). **First test:** two tiny agents get anticorrelated periods of rare-task access. Retention: early rare-task success on each deployment after three access switches without live partner calls. **Tie control:** periodic reciprocal distillation with the same correction bytes and partner probes.

**M36. Parametric insurance that ships a decoder.** Before any drop, underwriters offer alternative tiny decoders for an old capability, each triggered by an observable state transition (e.g. interface rename), not by a measured failure. If triggered, attach the purchased decoder without replay. **Why it might be new:** payout is a pre-priced functional patch, rather than reimbursement in updates (cf. E10 and contingency adapters). **First test:** symbolic converters with occasional feature renames and false triggers. Retention: accuracy on original semantics after new schemas arrive. **Tie control:** install the same-size patch on first audited failure, matched probes and patch construction.

**M37. Reinsurance by failure correlation.** Underwriter agents pool small residual repairs and negotiate which combinations can jointly insure task pairs. Store a shared repair basis for low-tail-dependence groups; activate it only on a verified joint shock, and dissolve the pool if shocks become correlated too often. **Why it might be new:** joint tail dependence decides factorization and contingent use, not static representational similarity (cf. reinsurance tranches and shared-basis LoRA). **First test:** low-rank classification tasks whose failure covariance flips halfway through. Retention: worst original two tasks after the flip and next shock. **Tie control:** cluster by observed gradient similarity with equal repair rank, audits, and activation rate.

**M38. Bankruptcy as a reverse auction for witnesses.** When a task adapter cannot be maintained cheaply, liquidate its ranks; remaining modules bid how few demonstrations they need to reconstruct a held-out witness behavior, and the winner gets those demonstrations and part of the freed rank. **Why it might be new:** liquidation transfers reconstructible fragments, not first-priority claims on a replacement model (cf. E12, auction-based compression). **First test:** retire one of four polynomial experts and reuse its budget on a new task. Retention: other early tasks plus retired expert witness generalization. **Tie control:** distill the retired adapter into its closest neighbor at identical bytes and evaluation budget.

**M39. Short sellers of “permanent” consolidation.** A challenger can borrow one rehearsal slot by supplying a counter-batch that trains well on a new task but breaks a nominated consolidated skill. If tests show the break generalizes, replace one of the skill's anchors with the challenger's crafted example pair. **Why it might be new:** the bet concerns a falsifiable *training attack surface* and pays in the right to repair it (cf. hard-example mining and E25; test only on toy supervised distributions). **First test:** sequential synthetic arithmetic rules; retention: challenged early rule under a later independently drawn update. **Tie control:** adversarial replay generation with the same counter-batches and trials, selecting anchors directly by loss.

**M40. Exchange-rate tax at optimizer boundaries.** Two tasks quote how many old-task calibration points a unit of their standardized step buys. Spend a fraction of the converted step to align the *specific* interface where these rates diverge before training across it; update the swap rates on shared audits. **Why it might be new:** cross-task optimizer units affect interface repair allocation, rather than global logit inflation or a learning-rate rule (cf. E2, adaptive loss balancing). **First test:** two-branch MLP with deliberately changing input scales and downstream labels. Retention: early tasks tested on both original and rescaled inputs after new-task training. **Tie control:** GradNorm plus interface rehearsal with identical gradient samples and repair steps.

## F. Adapter coalitions and evolutionary games

**M41. Core-stable adapter ownership.** Task heads value candidate low-rank partitions by audited accuracy. Move singular directions among adapter coalitions until no sampled subset can do better by leaving together at its share of total rank. **Why it might be new:** collective exit is an admissible model edit, not simple gradient similarity clustering (cf. core stability and AdapterFusion). **First test:** four linear tasks with one profitable three-task coalition but bad pairwise overlaps. Retention: early tasks after a fourth changes the partition. **Tie control:** agglomerative adapter clustering with access to the same scores and ranks.

**M42. Mutualism requires repayment in a different layer.** Adapter A borrows a feature from B, while B gets a guaranteed backward pass through an A-owned projection on demand. Store the two-way edge and prune a pair only when both borrowed services cease to help. **Why it might be new:** forward and backward dependencies become different sides of enforceable inter-module ownership (cf. symbiotic coevolution and cross-stitch nets). **First test:** two shallow feature adapters learning related then conflicting binary tasks. Retention: held-out tasks that initially benefited from mutualism after the conflict. **Tie control:** learned bidirectional cross-stitch links at equal rank and backward compute.

**M43. Slow replicator for weights, fast replicator for access.** Adapter owners compete for two budgets with different feedback: new-task successes change routing quickly; rare old-task successes shift rank reproduction slowly. Shrink one factor and expand another whenever rank shares change. **Why it might be new:** the deployed population and its capacity distribution can evolve separately (cf. replicator dynamics, load-balancing MoE, and population-based training). **First test:** three toy specialists, one under heavy short bursts. Retention: long-dormant original tasks after the burst. **Tie control:** frequency-smoothed rank pruning plus a separately trained router with identical capacity.

**M44. Partner choice can veto homogenization.** Each adapter can refuse to combine with others if recent compensation did not cover its own task's loss; train the router against mutual acceptance instead of independent utility. **Why it might be new:** composition depends on bilateral acceptance and experienced harm (cf. stable matching and MoE routing). **First test:** sequential regressions whose strongest independent adapters interfere in pairs. Retention: originals served by refused combinations before and after the latest task. **Tie control:** pairwise gating on measured joint errors with equal route samples and adapter calls.

**M45. Adaptive species boundaries from failed matings.** Mate two adapter factors by alternating their columns. If offspring gains new accuracy but damages both parents' niches, evolve a *do-not-cross* relation and enforce it only at reproduction, not inference. **Why it might be new:** reusable incompatibility lives between lineages and constrains future writes, unlike diversity-preserving routing or E21 recombination itself (cf. NEAT speciation). **First test:** three related rank-two mapping families and repeated toy crosses. Retention: both parent families in selected descendants. **Tie control:** similarity-based speciation with the same archived factors and mating trials.

**M46. Rock–paper–scissors with module antidotes.** Train tiny repair adapters in a nontransitive game: each learns to restore a task the next adapter's update harms. Keep a cycle chosen by payoff, and distill its repair steps into the common base. **Why it might be new:** coexistence preserves repair operators because each defeats a different form of interference, not because each solves a different end task (cf. nontransitive games and quality diversity). **First test:** three cyclic overlapping linear rules with a shared bottleneck. Retention: all original rules after two fresh writes by a held-out writer. **Tie control:** disjoint per-task repair experts with the same ranks, audits, and distillation steps.

**M47. Hostile takeover without weight merging.** Challenger modules acquire an incumbent's routing rights only by offering another module reliable specialized service that replaces some of the incumbent's calls; transfer route probabilities by observed service share, then retrain on displaced tasks. **Why it might be new:** replacement can proceed through reassigned call edges, not test-and-replace a whole module (cf. E41, mixture-of-experts distillation). **First test:** toy three-stage calculator where a new primitive overlaps a legacy one. Retention: old multi-step calculations after takeover. **Tie control:** gradual score-based router reassignment with the same calls, parameters, and training.

**M48. Cultural veto on adapter cloning.** An adapter can reproduce only if a newly paired apprentice, which observes its activations but cannot copy its weights, can demonstrate the parent's long-tail behaviors. The cloned rank goes to the apprentice's hardest reproducible behavior. **Why it might be new:** reproductive fitness includes teachability under a bandwidth constraint, not only task payoff (cf. iterated distillation and evolutionary teaching). **First test:** small language-game policies with one idiosyncratic early convention. Retention: descendants play that convention with an original partner after four generations. **Tie control:** select clones by direct rare-case return with the same apprentice rollout and rank budgets.

## G. Transmission, gossip, and consensus without weight merges

**M49. Two-person memory: transmit the question, not the answer.** One generation sends an apprentice the minimal queries that would disambiguate an old rule; an unrelated partner or environment answers them. The apprentice fits the old rule from that dialogue and repeats the cycle. **Why it might be new:** query curricula, not compressed answers or dialogue codes, are inherited (cf. iterated learning and teaching dimension). **First test:** infer symbolic rules across five transmission bottlenecks, each with access to a noisy answer oracle. Retention: accuracy of the original rules on fresh examples after four handoffs and two new rules. **Tie control:** transmit exemplars with the same bits and same oracle calls.

**M50. Teach to a wrong apprentice on purpose.** Each generation learns two explanations of the same behavior: a compact default and a correction for an apprentice assigned a known plausible misconception. Pass both on, and let the receiving agent repair its own interpretation before storing the result. **Why it might be new:** a memory unit includes a repair targeted at a known reader bias rather than formal redundancy or error-correcting meter (cf. E32, pedagogical reasoning). **First test:** iterated transmission of toy physical rules with changing learner priors. Retention: original rules on novel compositions after multiple hops. **Tie control:** transmit twice as many informative example bits under the same simulation and message budget.

**M51. Push-sum over function differences.** Fleet members gossip paired predictions on rotating public probes: one prediction before applying a local lesson and one afterward. Push-sum estimates the average signed function change across uneven network degree; peers fit small local residuals to only supported changes. **Why it might be new:** a learned update is communicated as a local before/after relation even when agents disagree on starting predictions, without merging weights (cf. push-sum and federated distillation). **First test:** three heterogeneous MLPs on a moving directed graph. Retention: their first local tasks after an isolated agent returns. **Tie control:** push-sum on ordinary logits with the same total numbers communicated and distillation steps.

**M52. Consensus commits a distinction, not an answer.** Peers propose pairs of old inputs whose outputs must stay distinguishable. Reach quorum on which distinctions are actionable, store the relation with confidence, and enforce it as a contrastive constraint during local new training. **Why it might be new:** consensus over behavioral inequalities can survive incompatible labels and model families (cf. ordinal distillation and consensus memory, not endorsement of lessons). **First test:** agents classify three differently labeled renditions of old shapes. Retention: original per-agent rewards and distinguishability after two new shapes. **Tie control:** distill local hard pseudo-labels with the same probe pairs and message volume.

**M53. Quorum on an observation window.** A fleet requests agreement on a *past observation window* before canonizing the resulting input–output summary. If messages arrive out of order, postpone the write until it can be trained on comparable observations; no weights are versioned or reconstructed. **Why it might be new:** the protocol coordinates temporal comparability of memories, not merging parameters or replaying named checkpoints (cf. snapshot algorithms and asynchronous distillation). **First test:** disconnected agents see early and late observations of a seasonal cyclic bandit. Retention: decision reward in the first season on its third return. **Tie control:** timestamp-binned distillation with the same messages, examples, and synchronization delays.

**M54. Cultural relay with contrasting teachers.** Each entrant learns an old skill by observing two teachers, one of whom uses a deliberately misleading shortcut. Teachers score the novice on new contexts; store the tested distinctions as only the examples worth relaying. **Why it might be new:** an explicit wrong cultural lineage is a teaching resource, not noise to average out (cf. contrastive teaching, not contrastive decoding). **First test:** four-hop shape-rule learning with reversed spurious color features. Retention: original rules on held-out shapes and flipped colors after later rules enter. **Tie control:** single-teacher relay using the same number of counterexamples and demonstrations.

**M55. Gossip a repair demand instead of a lesson.** Copies send a nonce query and a checksum of their historical output without sending a solution. Neighbors that can still reproduce it supply useful intermediate activations, which recipients use for local rehearsal before deleting the message. **Why it might be new:** peer discovery is driven by verifiable recall requests rather than pushed content or static transactive routing (cf. pull gossip and feature distillation). **First test:** agents with explicitly matched intermediate width solving different tiny sequence tasks, each losing a different early entry. Retention: all earlier tasks under fresh sequence paraphrases after dropout and new learning. **Tie control:** direct answer requests and output distillation with the same messages, oracle accesses, and total bits.

**M56. Negative consensus during network partition.** Separated subfleets may agree to *temporarily suppress* incompatible rules in shared contexts while continuing local learning; when reunited, only those suppressed rules are tested across both prior distributions and selectively re-enabled. **Why it might be new:** escrowed disagreement preserves private memories without copying or merging conflicting answers (cf. conflict-free replication, but no learned-state merge, and selective abstention). **First test:** two populations acquire opposed conventions during a split. Retention: each origin's pre-split conventions on held-out partners after reunion. **Tie control:** retain both rules behind a provenance router with equal metadata, route calls, and audits.

## H. Institutions that learn how to keep learning

**M57. Constitutional convention with staggered evidence, not members.** Old task proxies pick a selector for which probes may count in future model-write audits; incoming proxies can amend it only if their proposal generalizes on a frozen sample drawn after they commit. Retrain the selector, not the task heads. **Why it might be new:** the evolving constitution governs evidence admission rather than aggregating lesson votes (cf. social choice for memory and reusable holdouts). **First test:** classifiers whose visible audit distribution becomes gameable as new task proposers arrive. Retention: original tasks on an independent test after two amendments. **Tie control:** validation on stratified rotating samples with equal fixed holdout draws and audit steps.

**M58. Long-horizon franchise contracts for compressed skills.** A task delegates maintenance to an apprentice that earns future adapter capacity only if it can absorb a specified fresh variation *without* more forgetting than its incumbent. Move the reserved rank only after the paired forward-transfer and retention test. **Why it might be new:** the asset transferred is a right earned by safe adaptation, not a distillation exam for current behavior (cf. E18 and succession by distillation). **First test:** tiny spelling transducers evaluated on one novel affix before a change of maintainer. Retention: old affix families after the apprentice learns a later unrelated task. **Tie control:** select an apprentice by current performance with the same test cases, adaptation FLOPs, and final rank.

**M59. A cartel of useless replay.** Regularly give each replay bidder one privately randomized audit reward so colluding proxies cannot reliably share fake credit. Measure payoff synchronization before and after randomization and downweight coordinated bidders' future *slot requests*, leaving their examples eligible. **Why it might be new:** private test randomness addresses coalitional exaggeration without assuming any proxy is individually unreliable (cf. collusion-resistant mechanisms and data valuation). **First test:** competing replay agents inflate rewards for overlapping templates in a class stream. Retention: distinct early classes after template drift. **Tie control:** cap correlated or duplicate replay batches using the same audit and replay counts.

**M60. Jurisdiction for conflicting old-task revisions.** An agent learning a revised rule offers separate single-context and cross-context patches. Route the right to adjudicate failures to the smallest group of old contexts that was actually affected; only that group can approve promoting the repair to a shared adapter. **Why it might be new:** update authority is inferred from blast radius, not linked to a fixed task ID or type-level certificate (cf. subsidiarity and hierarchical gating). **First test:** toy calendar arithmetic with a local convention change and global boundary conditions. Retention: both changed and unchanged historical calendar translations after the next revision. **Tie control:** affected-domain loss gating using the same jurisdiction probes and patch sizes.

**M61. Anonymous borrowing from a capability commons.** A new task can rent an old feature without revealing its own inputs. A broker sends only binned feature statistics, and the old task offers a maintenance contract keyed to how much shared activation drift it will tolerate; train within the accepted bounds. **Why it might be new:** a learning agreement can depend on reported statistical exposure without sharing examples or behavior (cf. federated feature alignment and adverse-selection screening). **First test:** sites with synthetic private linear tasks and distribution skew. Retention: old site's accuracy after two renters with different exposure profiles. **Tie control:** batch-statistic alignment with equal bytes, feature limits, and updates.

**M62. Pension rights for obsolete proxy heads.** Retire old task proxies by letting them pay a share of their final replay allowance into a successor head that predicts *when they would reappear*. The successor can spend only when surprise at recurrence beats a precommitted statistic; use the payout for immediate adaptation. **Why it might be new:** succession transfers a dormant right to reactivate instead of predictions, old rank, or probe examples (cf. change-point detection and E10; test cold-start performance separately). **First test:** seasonal sequence tasks with missing cycles. Retention: first-attempt and ten-step accuracy on the oldest revived sequence. **Tie control:** periodic plus change-triggered replay with the same summary bytes and step budget.

**M63. Tradable dissents over *why* an update was accepted.** Losing tasks may spend one audit credit storing a dissent of the form “this update wins only if context C persists.” New task proxies purchase which dissents to test with their update budget; a falsified assumption sends gradients to a scoped correction, without reverting the original step. **Why it might be new:** decision rationales are executable contingent claims, not a seed log or explanation transcript (cf. assumption-based truth maintenance and market for tests). **First test:** old symbolic rules whose shortcut correlations recur and reverse. Retention: early rule transfer on contexts named by dissents and on independent holdouts. **Tie control:** store discovered brittle contexts as prioritized replay triggers with the same bytes and test calls.

**M64. Mechanism inheritance after proxy extinction.** A failing task proxy bequeaths a small scoring rule to the training scheduler rather than its model or examples. Later proxies can acquire those rules if they find tasks for which the rules rank plausible repairs well; use acquired rules to choose shared updates. **Why it might be new:** inheritance carries rules for allocating learning, not weights, optimizer momentum, or habits (cf. iterated institutional evolution and meta-learned losses). **First test:** a stream of small regression families with a missing proxy for the oldest family. Retention: score that family's fixed test only at evaluation after later proxies inherit the rule. **Tie control:** freeze a fixed meta-learned repair scorer with equal parameters, candidate updates, and proxy evaluations.
