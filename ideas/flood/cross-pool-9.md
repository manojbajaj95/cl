# Cross-pool merges, round 9

Focal sources: `tree/obligation-witness-keybits.md` (PR #93, OK#), `tree/set-valued-edit-certs.md` (PR #98, SE#), `tree/harness-shared-isa.md` (PR #100, ISA#), `pilots/toolbox-drift/` (PR #101, TD), and `pilots/defect-transmission/` (PR #37, DT). TD detected breaking drift earlier with tools but did not establish faster recovery; on silent drift, both tested arms detected immediately and diagnosis remained hard. ISA's null LoRA preserves an identity contract only on its training scope: it suppresses the existing text instruction in the mixed-substrate probe. DT is a kept CPU signal for planted-signature inheritance, not a demonstrated epidemic or an independent per-note rate. These are raw and unfiltered.

**V1. An alarm that compiles its own next experiment.** Parts: TD silent-drift recovery bottleneck, OK9 paired causal permission, SE14 future meets, N31 exception handlers (PR #41), U6. *Mechanism:* Replace a failed test's generic error message with a compact relation over plausible changed API transforms and permitted repairs. Ask the next probe that separates transforms requiring different repairs, not merely the one most likely to fail. Keep a single candidate repair only when it passes the full retry trajectory under the measured transform. *New:* The alarm supplies a decision problem whose shortest path ends at a safe repair, not a higher-confidence detection event. *First test:* Replay the PR #101 silent transforms in its deterministic simulator with detection fixed at first use; compare detection-to-stable-recovery calls against the existing repairer and budget-matched random failing tests.

**V2. One-edit diffs versus version-seam repairs.** Parts: TD tool/test recovery, SE7 edit-parametric retry powers, SE24 proof repair, FA8 continuation seams (PR #99), R1. *Mechanism:* Learn a compact seam relation for a block of retries that carries the same repair variable through every copy. A drifted endpoint invalidates just the algebraic steps that read its interface. Rebuild that slice and join it to the untouched relation to propose a patch that works on a previously unseen horizon. *New:* The reusable recovery artifact is a chunk of a proof over candidate edits, not a stored patch or an old trace that used a fixed patch. *First test:* Extend the PR #101 simulator with a two-call dependency and unseen retry lengths; compare recovery latency and false accepts with full exact rebuilding, per-step patching and cached whole patches.

**V3. The adapter that promises to leave instructions writable.** Parts: ISA1 behavioral footprints, ISA2 swap consistency, OK10 scoped frame grants, SW3 ABI-stable training (PR #53), MX1. *Mechanism:* Add instruction-toggle contrasts to an adapter's footprint so a candidate must preserve which instructions can still change the answer, not just the answer without instructions. Train on sampled live directives and certify only a declared scope; a null adapter that loses a usable toggle fails as a write even when nominal task accuracy stays high. *New:* The protected object is a reader's future control surface rather than its ordinary output distribution. *First test:* In the PR #100 swap matrix, add a held-out instruction whose effect cannot be implemented by a postprocessor alone; compare matched-gain adapter training with nominal distillation, zero-delta and null-LoRA controls, plus same-length filler and entropy-matched no-instruction controls.

**V4. A typed escape hatch instead of a best-effort prompt.** Parts: ISA6 substrate lattice, TD documented versus silent drift, OK22 scoped abstention, N12 escape analysis (PR #41), U4. *Mechanism:* Upon a tool alarm, move only the region with a verified declarative equivalent to an alternate substrate. For regions needing latent inference, keep a separately authorized old route or abstain until a targeted probe certifies a common write; promote temporary edits out of the local frame only after verification across protected behaviors. *New:* Failover is a partial, typed migration of a behavior rather than a global fallback to another substrate or a code-only rule. *First test:* Mix pure format transformations with context-dependent procedure actions in a small PR #101-derived world; compare time to partially restored service, stable full recovery and unaffected-task errors against whole-procedure lesson fallback, with filler and entropy-matched no-memory controls.

**V5. A relay firewall that still learns from a failed helper.** Parts: DT planted-signature inheritance, OK2 release cover, SE6 lossless joins, LP12 truth maintenance (PR #59), Z4. *Mechanism:* When a new helper is learned from retrieved notes, record the small set of output predicates whose values branch when each note is toggled. Before downstream reuse, send inherited predicates through a join with provenance and scoped authorizations, making the unresolved predicate switch read-only while leaving independently verified results available. *New:* Containment tracks which behavioral claim may have been inherited, instead of excluding a whole note or mistaking all defects for propagation. *First test:* In the PR #37 held-out family setup, place one bad note among sound notes and test selective quarantine against note filtering and uniform gating. Measure planted-signature transmission and correct transfer with matched retrieval depth, same-length filler and source-fitted entropy-matched no-note arms.

**V6. A negative scope that travels farther than a failed patch.** Parts: DT local single-bad-note contrast, ISA16 matched-gain disagreement, OK6 implication receipts, RS10 disqualifying examples (PR #90), R2. *Mechanism:* When two substrate implementations reach the same gain but only one inherits a planted defect, distill the nearest negative boundary as a predicate on calls. Transfer that predicate to another reader only after a paired contrast establishes that the implication still holds; do not copy the suspect helper or its note. *New:* A failure can improve another learner without relaying the exact behavior that caused it. *First test:* Run PR #37-style note families against text and a tiny executable procedure; hold out one reader and a scope shift, and compare signature-specific suppression and correct reuse against copying tests or suppressing entire notes, with both note controls.

**V7. Future repair capacity as part of a tool purchase.** Parts: SE22 reserve a continuation, OK18 grant amortization, TD recovery tie, NC9 escrow (PR #67), CD13 small gain (PR #74). *Mechanism:* When selecting a tool implementation, reserve at least one checked repair move for declared future drift families before committing. Reuse a scope grant across several future transforms only where its affected-region proof covers all of them; otherwise keep a reversible slow fallback and track its call cost. *New:* A replacement is evaluated by what it can still repair after tomorrow's drift, not solely its current latency or regression tests. *First test:* Give the PR #101 simulator two consecutive changes such that all candidate first repairs pass but only some permit a safe second repair. Compare recovery after the second change against the cheapest current fix and byte-matched rollback caching.

**V8. Test a note in the substrate it will actually inhabit.** Parts: ISA9 substrate dropout, DT distinct depth backgrounds, OK19 split-only policy audit, EC03 factorial licensing (PR #94), T11. *Mechanism:* Construct licensing rectangles by crossing one note toggle with one live substrate swap while holding the rest of the retrieval stack fixed. Store only the observed safe scopes and explicitly split a previously licensed cell if a new adapter changes the effect. An all-bad stress test remains separate from the local one-bad contrast. *New:* A lesson license is conditional on the reader path that implements it, so text-to-weights migration cannot inherit a safety claim for free. *First test:* Cross a null adapter with one swapped note in mostly sound and all-filler stacks on a small held-out PR #37 slice; compare calibrated harm flags against depth-only and adapter-presence gates with same-length filler and source-fitted temperature.

**V9. A shared ISA that can distinguish permission failure from missing capability.** Parts: OK24 failure triad, SE16 suffix-based refutation, SE17 extension, ISA11 differential fuzzing, CA1 credit-span minting (PR #78), T6. *Mechanism:* When a repair cannot be dispatched, require the compiler to distinguish an empty safe-edit set from indistinguishable permission worlds and from a footprint that merged states with different continuations. The corresponding output is a failed-write witness, a scoped question, or a substrate contrast that tests a new port. *New:* Recovery errors become typed operations for refining the substrate boundary rather than retries with a stronger model. *First test:* Enumerate toy repairs across text, code and a two-parameter model; independently vary unavailable permissions, aliasing and absence of a write handle. Compare correct routing of next actions against confidence thresholds and same-budget brute proposals.

**V10. A canary whose positive result unlocks a recovery transition.** Parts: TD alarms without recovery, ISA15 behavior content addressing, SE21 checked edit migration, FA17 paired cross-version bridges (PR #99), U1. *Mechanism:* Index a canary by the smallest callable footprint needed to decide a transition between old and replacement implementations. On drift, run the same two boundary calls in both versions; use a successful bridge only to unlock the specific recovery transition it distinguishes. Preserve a separate drift alarm when no bridge licenses a move. *New:* A test can take the learner from one repair state to another without touching unrelated behaviors; detection and transition certification are separate outputs. *First test:* Run a two-version PR #101 API stream with documented changes and silent transforms; hold the detector fixed and compare stable recovery per call with generic regeneration and a best-effort fixed mapping.

**V11. A bilingual recovery loop with evidence and authority built in.** Parts: OK2 release cover, OK6 implication receipt, OK9 causal permission, OK18 grant amortization, OK19 split audit, OK22 abstention, OK24 failure triad, SE6 lossless joins, SE7 retry powers, SE14 future meets, SE16 suffix refutations, SE17 write-family expansion, SE21 checked migration, SE22 next-write reserve, SE24 proof repair, ISA1 footprints, ISA2 swap consistency, ISA9 substrate dropout, ISA11 differential fuzzing, ISA15 content addresses, ISA16 matched-gain disagreement, TD matched detectors, TD silent-transform bottleneck, DT signature readout, DT local-depth contrast, N31 recovery dispatch, EC03 licensing, FA17 seam bridges, U10. *Mechanism:* A drift alarm produces a set of plausible shared repairs and one contrast that can shrink it. A compiler chooses a substrate only when its live footprint still allows old directives to act, keeps one future repair in reserve, and routes unresolved regions to a verified fallback. Its receipts distinguish permission from evidence and attach inherited-claim provenance to new helpers so a fast fix cannot silently reproduce the same defect downstream. *New:* The durable unit is a recovery transition with a checked affected scope, a preserved control surface, and a portable reason to reuse it after drift. *First test:* Build a tiny three-port retry stream with one silent transform, one null-adapter insertion and one inherited functional bug. Hold initial detection fixed; compare episode-to-stable-recovery, retained instruction effects and next-helper planted defects against stacked test-driven repair, independent footprint checks and note filtering, with both note controls.
