# Idea flood: self-modifying agents and models

Raw, unfiltered proposals about models and agents that change themselves: on-policy self-distillation (OPSD), self-edited weights, prompts and code, recursive self-improvement, and models that train their successors. Nothing here was pre-killed; the reviewer ranks the pool on novelty. Each card gives the mechanism, why it would be new (nearest work I know of), and the cheapest first test.

Checked only against `reviews/idea-ledger.md` (PR #6) for exact repeats. Nearby prior art seen in one alphaXiv pass (2026-11-24): WSP ([Sparks of WSP](https://www.alphaxiv.org/abs/2611.weight-space-programming), [Self-WSP 2611.28833](https://arxiv.org/abs/2611.28833), [LMs Can Rewrite Their Own Weights 2611.21885](https://arxiv.org/abs/2611.21885), [Recursive Self-Editing 2611.29513](https://arxiv.org/abs/2611.29513), [WSP writes ICL 2611.26841](https://arxiv.org/abs/2611.26841), [WeightLoop 2611.07319](https://arxiv.org/abs/2611.07319)), OPSD variants ([teacher evolution 2610.38637](https://arxiv.org/abs/2610.38637), [no supervision 2608.06296](https://arxiv.org/abs/2608.06296), [SR-OPSD 2608.09745](https://arxiv.org/abs/2608.09745), [privileged context as drift 2610.07842](https://arxiv.org/abs/2610.07842)), RSI ([RSI-Prime 2611.23138](https://arxiv.org/abs/2611.23138), [SwarmRSI 2610.20431](https://arxiv.org/abs/2610.20431), [Third Eye 2611.12988](https://arxiv.org/abs/2611.12988)), self-adapting/hypernetwork LoRA ([SEAL 2506.10943](https://arxiv.org/abs/2506.10943), [Text-to-LoRA 2506.06105](https://arxiv.org/abs/2506.06105), [Doc-to-LoRA 2602.15902](https://arxiv.org/abs/2602.15902)), Gödel-machine agents ([DGM 2505.22954](https://arxiv.org/abs/2505.22954), [Red Queen GM 2606.26294](https://arxiv.org/abs/2606.26294)), and model collapse across generations ([2611.06022](https://arxiv.org/abs/2611.06022), [2609.25721](https://arxiv.org/abs/2609.25721)).

## A. Self-edit representations (what a self-modification *is*)

**SM1. Seed-log autobiography.** Restrict every self-update to a seed-based zeroth-order step (MeZO-style: a PRNG seed plus one scalar), so the model's entire learned history is a short text log of `(seed, scale, reason)` lines. Put that log in the model's own context: it can read, cite, reorder, drop or re-scale any past update by name, and continual learning becomes editing a readable autobiography that regenerates the weights exactly. *New:* seed-based updates are used for memory-cheap training, never as a self-readable, self-editable record of what the model learned. *First test:* 0.1–0.5B model, two-task stream with MeZO seeds; ask the model to delete the updates tied to task B by reading the log, and measure how close the result lands to the task-A-only checkpoint vs. naive reversal of the last k steps.

**SM2. Weight ISA.** Define a tiny instruction set for self-edits (`WRITE_RANK1 layer k v`, `SWAP_NEURON`, `TRANSPLANT_HEAD`, `SCALE_SUBSPACE`, `FREEZE`), with an interpreter. The model emits short programs in the ISA instead of raw numbers (WSP) or gradients. The ISA is the primitive: edits become diffable, composable, statically checkable, and transferable across models that share the ISA. *New:* WSP papers write raw weights or code that writes weights; nobody fixes a weight-level assembly language and studies its learnability and composition. *First test:* frontier LLM via API writes ISA programs to fix a planted bug in a 2-layer MLP; compare success and program length to free-form WSP code on the same bugs.

**SM3. Weight quines.** Train a small net so that on a reserved prompt it outputs a compact description that regenerates its own most recent adapter. After later fine-tuning damages the adapter, the model runs its quine prompt and re-applies what it emits: memory that self-repairs by self-reproduction. *New:* persistence of edits under fine-tuning is studied (ledger), but not edits that carry their own regeneration recipe inside the network. *First test:* MLP + hypernetwork head that emits its own LoRA; damage by fine-tuning on a conflicting task; measure recovered old-task accuracy vs. a stored-adapter restore of equal bytes.

**SM4. Weight malloc.** The model keeps an explicit free-list of dormant neurons and allocates them to new skills through an allocator API (`alloc(n)`, `free`, `gc` by usage counts). Continual learning writes only into allocated blocks; garbage collection reclaims unused ones. *New:* dynamic architectures grow capacity, but none expose an allocator with free/gc semantics the model itself calls. *First test:* MLP on Permuted-MNIST-style stream, allocator vs. random sparse masks vs. PackNet at equal capacity.

**SM5. Typed edits.** Every self-edit declares an interface: the input subspace it reads and the output behaviour it changes. A type checker refuses to compose two edits whose interfaces overlap without an explicit merge. Interference becomes a type error caught before deployment. *New:* edit-interference prediction exists numerically, not as a declared, checked contract the editor must write. *First test:* 200 MEMIT edits with declared key subspaces; does "type error" at compose time predict pairwise forgetting better than key cosine?

**SM6. Write tokens.** Special vocabulary tokens that, when emitted mid-generation, perform a rank-1 update to the model's own MLP from the current hidden state, persisted across episodes. The model learns *when* to write itself during ordinary decoding. *New:* fast weights reset per sequence; 2611.21885 rewrites weights via a separate procedure, not as an in-decoding action. Nearest risk: 2611.21885. *First test:* 2-layer transformer on a key-value stream where facts recur across episodes; RL or supervised write-token placement vs. always-write fast weights.

**SM7. Neutral-drift reserve.** Reserve a slice of parameters that random-walk under a neutral-drift process that keeps the function unchanged (moves along loss-flat directions), occasionally recruited when a new task arrives. Borrowed from neutral networks in evolution: drift keeps the reserve "fresh" without touching behaviour. *New:* plasticity-loss fixes reset or perturb; none drift along function-preserving directions to stay plastic. *First test:* MLP plasticity benchmark (Slowly-Changing Regression), drifting reserve vs. frozen reserve vs. shrink-and-perturb.

**SM8. Undo-in-weights.** Each self-edit writes its own inverse into an orthogonal subspace, gated by a text trigger ("revert edit 17"). The model can undo itself without an external checkpoint store. *New:* reverts use stored diffs outside the model; here the undo is a capability of the model. Risk: ledger's return-point adapters (exact by construction). *First test:* 50 rank-1 edits with paired gated inverses in a 0.5B model; revert-by-prompt fidelity vs. bytes used.

## B. On-policy self-distillation variants

**SM9. Era-routed OPSD.** Keep the model's past selves (checkpoints along the stream) as candidate teachers; per token, the teacher is whichever past self is most confident on that token. Old tasks are taught by the era that knew them, new ones by the current self. *New:* OPSD teachers are one current/EMA model (2610.38637); per-token routing across time-indexed selves is not done. *First test:* SmolLM-class model is too weak (ledger), so use Qwen2.5-1.5B on GPU or a toy transformer on a 3-task stream; era routing vs. EMA teacher vs. replay.

**SM10. Disagreement-frontier OPSD.** The student samples prefixes, and training concentrates on tokens where hinted and unhinted versions of itself disagree most (max information from the hint). A curriculum discovered by the model's own self-disagreement. *New:* OPSD weights tokens uniformly or by teacher entropy; using the hint's marginal effect as the selection signal is new. *First test:* existing OPSD setup, top-20% hint-effect tokens vs. all tokens at equal token budget.

**SM11. Censored-self unlearning.** Teacher = the same model conditioned on "you have never heard of X"; on-policy distill into the student. Forgetting by self-distillation from an imagined ignorant self, keeping everything the instruction doesn't touch. *New:* unlearning uses gradient ascent or refusal data; self-distillation from a counterfactual-ignorance prompt is untested. *First test:* TOFU-style forget set on a 1B model; forget quality and retain utility vs. gradient-difference unlearning.

**SM12. Diff-as-privilege OPSD.** Render the model's last weight update as text (WSP-style reading or the SM1 seed log) and give it as privileged context to the teacher; the student distills "knowing what changed in me". Self-knowledge of edits gets internalised. *New:* privileged info in OPSD is task hints, never the model's own weight diff. *First test:* after a known edit, does diff-privileged OPSD reduce collateral damage versus plain OPSD on the same edit?

**SM13. Hindsight-self teacher.** Teacher is the model conditioned on its *own* completed rollout and outcome ("you will end up at X"), distilled back onto the prefix. The privileged context is the model's future self. *New:* hindsight relabelling exists for goals; as an OPSD teacher signal for CL, using the model's own continuation and outcome as privilege seems unused. *First test:* math reasoning stream, hindsight-self OPSD vs. outcome-reward RL at equal samples.

**SM14. Mirror OPSD.** One set of weights in two modes (base and base+adapter); each mode teaches the other on the domain where it is more confident, alternating. Two-way self-distillation inside one parameter set holds the old task in one mode and the new in the other, then folds them. *New:* deep mutual learning uses two separate nets; a mode-swapping single net for CL is not studied. *First test:* two-domain stream, LoRA on/off modes, mirror OPSD vs. LoRA merge.

**SM15. Ontogeny distillation.** The successor is distilled from the parent's *checkpoint sequence* in order, so it re-lives the parent's development instead of copying the end state. Hypothesis: it inherits the parent's plasticity, not just its knowledge. *New:* distillation uses the final teacher; developmental replay of past checkpoints as a teacher curriculum is unexplored. *First test:* small LM, distill from 10 checkpoints in order vs. final teacher at equal tokens; then measure how fast each successor learns a new task.

## C. Prompts, code and harness changing themselves

**SM16. JIT-compiled lessons.** Treat in-context lessons like code in a tiered JIT: a lesson that stays unedited and keeps firing is "hot" and gets compiled to a LoRA via context distillation; when a failure contradicts it, it is de-optimised back to text. Knowledge moves between tiers by usage. *New:* context distillation is a one-way move; a tiered compile/deopt cycle with hotness is new. *First test:* G1 router, tiered lessons vs. all-text vs. all-weights on a stream with a mid-stream rule flip.

**SM17. Decompile–recompile cycle.** Periodically the agent decompiles what is in its weights (self-explanation of a LoRA's behaviour) into text, edits the text, and recompiles. Knowledge in weights becomes editable by the same agent that wrote it. *New:* weight-to-text explanation and text-to-LoRA exist separately; using the round trip as the editing loop is new. *First test:* decompile a LoRA trained on a rule, change one clause in text, recompile; compare to direct LoRA fine-tuning on the changed rule.

**SM18. Sampler-as-memory.** Given A3 (lessons act mostly like temperature), the agent stores memory as code it writes for its own logit processor: per-task masks, biases, temperature schedules. Memory lives in the decoder, not the prompt. *New:* decoding-time steering exists, but agent-authored, persistent sampler programs as the memory store do not. *First test:* G1 router, LLM-written logit processors vs. text lessons vs. entropy-matched temperature.

**SM19. Loss-as-memory.** Each round the model writes the code of its own next training loss (token weights, which examples to drop, auxiliary terms) from its failure log. What it learned about *how to learn* persists as loss code. *New:* learned losses are meta-learned offline; an LLM rewriting its own loss online for CL is not done. *First test:* 0.5B SFT stream, frontier LLM or the model itself writes token-weighting rules per round vs. uniform loss.

**SM20. Generational test immunity.** Every self-edit of an agent's code must pass tests written by its *past* versions against the new one, and each version adds adversarial tests aimed at its successor. Tests accumulate into an immune memory across generations. *New:* DGM-style agents use fixed benchmarks; Red Queen GM co-evolves evaluators, but not past-self-authored tests aimed at successors. *First test:* small coding-agent harness with 10 self-edit generations; regressions caught vs. fixed suite.

**SM21. Tokenizer as mutable memory.** The agent adds, merges and deletes its own tokens (with embeddings set from averaging or a small fit) as frequent macros come and go; vocabulary churn tracks the stream. *New:* the ledger killed grown vocabularies with a frozen backbone; adding *deletion and merging* as a forgetting channel is the twist. *First test:* code stream with API renames; churned vocab vs. frozen vocab, measuring context length and accuracy.

**SM22. Self-chosen growth.** When failing, the model inspects its own gradient statistics and decides where to add capacity (which layer, how many neurons) via net2net-style function-preserving growth. *New:* growth heuristics are fixed rules; letting the model's introspection choose growth is new. *First test:* MLP stream, introspective growth vs. uniform widening vs. no growth at matched final size.

## D. Successors and lineages

**SM23. Curated inheritance.** Before training its successor, the parent writes a dataset and explicitly withholds its own known misconceptions (found by self-checking against a verifier). The lineage forgets its errors on purpose. *New:* model-collapse remedies add outside data (2611.06022); selective parental withholding is untested. *First test:* small parent with planted wrong facts; successor trained on curated vs. raw parent samples; error inheritance rate.

**SM24. Budding and fusion.** Under drift the agent buds small specialised offspring (adapters or small models) per subdomain, lets them learn on their slice, and later fuses them back (merge or distil). A life cycle: bud, specialise, fuse. *New:* MoE and merging exist separately; the timed bud/fuse lifecycle driven by the model's own drift detection is new. *First test:* 4-domain stream, bud/fuse vs. single LoRA vs. always-separate adapters.

**SM25. Lamarckian optimizer state.** The parent passes its optimizer state (Adam moments, a learned preconditioner) to a fresh successor of a different architecture through a mapping, so the successor inherits *how to learn*, not what was learned. *New:* weight inheritance and distillation are common; optimizer-state inheritance across architectures is not. *First test:* MLP width 256 → 512, mapped Adam moments vs. fresh optimizer on the next task's learning speed.

**SM26. Leash adapter.** The parent trains its successor to keep a small adapter slot that only the parent can write, so the parent can correct the successor after release. A designed correction channel across generations. *New:* successor training has no reserved interface for later parental edits. *First test:* successor with leash slot; parent writes 20 corrections; compare to fine-tuning the successor directly.

**SM27. Hint inheritance ladder.** Generation n's OPSD teacher uses hints written by generation n−1, and generation n writes hints for n+1. Does hint quality compound or collapse along the ladder? *New:* OPSD hints are fixed or human; a lineage of model-written hints is new. *First test:* 5 generations of a 1.5B model on a math stream; hint usefulness per generation.

## E. Recursive self-improvement mechanics

**SM28. Invariant-preserving self-edits.** A self-improvement loop where each edit must keep a declared invariant exact (probe-set logits), enforced by projecting the edit, like a loop invariant in program verification. Capability can grow while the invariant cannot drift. *New:* RSI work gates edits by benchmarks; a hard invariant subspace as a projection is new for RSI. *First test:* toy LM, 20 self-edits, probe KL with vs. without the projection, and capability gain.

**SM29. Path certificates.** Accept a self-edit only if the whole linear path from old to new weights is non-worse on probes, not just the endpoint. The model stays in one connected basin, so every past self can be reached by interpolation. *New:* mode-connectivity studies exist, but path-gating as an acceptance rule in self-improvement is new. *First test:* CL stream with endpoint-only vs. path-gated acceptance; forgetting and later revert quality.

**SM30. Verbal self-forecast.** Before training on an example, the model writes in text how its answers will change; it is then trained to make those forecasts accurate. It learns a self-model of its own plasticity and uses it to choose training data. *New:* forecasting forgetting is done with external first-order tools (ledger #16); the model forecasting its own update in language is new. *First test:* 1B model, forecast accuracy on held-out probes after single-example updates; does forecast-based data choice beat loss-based choice?

**SM31. Plasticity market.** LoRA experts bid credit to be updated on each example; credit is earned when an expert's output is used downstream. Plasticity is allocated by an internal economy instead of a router. *New:* MoE routing allocates compute, not who gets to learn. *First test:* MoE-LoRA on a 4-task stream, auction vs. gradient routing on forgetting.

**SM32. Self-debugger surgery.** The model reads SAE features that fire on its own failures and writes steering or ablation edits on those features. Self-debugging at the feature level. *New:* Self-WSP edits weights; feature-level self-surgery from failure logs is not done. *First test:* small model with an off-the-shelf SAE; failure-feature ablations chosen by the model vs. random feature ablations.

**SM33. Weight-reading metacognition.** Give the model a tool that returns its own weight rows as tokens and ask "do you know X?" via weight inspection. Knowledge-of-knowledge from reading, not from activations. *New:* WSP reads other networks; reading one's own weights for self-knowledge is new. *First test:* MEMIT-edited facts; does reading the edited rows predict knowledge better than verbal confidence?

**SM34. Counterfactual twin.** Run a shadow copy with the last N self-edits removed, on the same live inputs, to estimate each edit's causal value online. Edits that do not beat their twin are rolled back. *New:* the ledger's offline A/B (G1) failed; online shadow twins avoid off-policy correction. *First test:* G1 router stream; twin-gated edits vs. accept-all vs. offline IS ranking.

**SM35. Voluntary forgetting tokens.** The model emits "forget" tokens naming a subspace it wants decayed, choosing what to forget. *New:* forgetting is scheduled externally (decay, pruning); here the model picks. *First test:* model chooses which LoRA components to drop from text descriptions; compare to magnitude pruning on later retention.

**SM36. Weight dreaming.** In idle time a hypernetwork generates synthetic adapters for imagined tasks and trains on them, so the generator keeps its coverage. Sleep in weight space instead of data space. *New:* generative replay works in data space; adapter-space replay is rare (von Oswald hypernet CL regularises outputs, not dreamed weights). *First test:* hypernetwork CL on Split-CIFAR-like task embeddings, dreamed-adapter replay vs. output regularisation.

**SM37. Capability/value split RSI.** Treat recursive self-improvement as a dynamical system: improvers must be contractive on a value subspace and expanding on capability. Choose improvers by measured contraction rates. *New:* RSI work measures gains, not the stability of its own fixed point. *First test:* 10-step self-edit loop on a toy LM; contraction of value probes vs. capability gain per step.

**SM38. Prompt–weight swap.** Periodically swap what is in weights and prompt: weights are decompiled into prompt text, and the prompt is compiled into weights. A garbage-collection cycle that exposes everything to editing. *New:* context distillation goes one way; a full swap cycle is new. *First test:* G1 router with periodic swap vs. no swap on rule-flip recovery.
