# Flood: ideas from continual-learning-bench submissions

Raw, unfiltered continual-learning ideas inspired by the open PRs and code of [pgasawa/continual-learning-bench](https://github.com/pgasawa/continual-learning-bench) (CL-Bench, arXiv 2606.05661). Nothing is pre-killed; the reviewer ranks the pool on novelty. Screened by title against `reviews/idea-ledger.md` (PR #6) and the other flood files to avoid exact repeats; where an idea sits near a ledger entry, the difference is stated.

## What the bench PRs show (the inspiration)

- **Logbook (#35):** a short Python program per task, written by Opus from the task brief *before any run* and never revised, keeps a typed record and prepends ≤4k chars. ICL+Logbook scored 0.274 (sales 0.72) but went negative on cohort (−0.23).
- **Causal reflection (#34):** stock ICL against a model API that keeps a session causal graph, runs a counterfactual check before each graph update, and resets the graph for the baseline. It scored 0.42 normalized reward for $2.32, vs $14–$441 for the other entries.
- **Learner 1.0 (#32):** learns only in weights. After every instance a teacher LLM writes examples *from states the learner actually reached*, one update per example, no replay. Normalized gain was 0.23.
- **Mubit (#12–#19), Kaleidoscope (#23), knowledge_cards (#11):** memory stores lift weak models most (Gemini 3.1 Pro went from −0.076 with ICL to 0.23). Kaleidoscope *loses* to plain ICL on database_exploration (0.41 vs 0.62), the task with a schema migration at question 20. knowledge_cards clears cards on a drift NOTICE.
- **Ouroboros (#10):** autonomous harness with self-review: poker gain −176 while other tasks rose.
- **Leak fixes (#24, #25, #26):** agents learned through unintended channels: container files outside `/app`, shared test patches, and `git log` of future commits (a published Opus 4.7 trace applies the fix commit from history).
- **Task structure:** cohort_studies gives no reward, only more biased studies, and its in-tool KL is a known overfitting trap. BSM gives an ack only, and transmitters go silent for many scans. Poker switches opponents. Sales loses old data exports, so `/app` is the only institutional memory. codebase switches repos (tablib→tenacity).

Each entry: **mechanism**, *why new*, **cheapest first test** (CPU unless noted) with a retention check and the same-budget control most likely to tie it.

## A. Memory as a program (from Logbook)

**B1. Memory schema migrations with up/down functions.** Treat what an agent remembers as a typed database whose *schema* is the learnable object. When feedback contradicts the schema (a new field, a changed encoding), the agent writes a migration: an `up` function that converts every stored record to the new schema and a `down` function that recovers the old view. Old knowledge is transformed rather than dropped or duplicated. *Why new:* memory systems add, edit or delete notes; none version the schema and migrate old contents, and Logbook's schema is frozen at write time. **First test:** synthetic database_exploration clone with 2 migrations (cents→dollars, epoch→ISO); Qwen2.5-1.5B writer of migrations vs edit-notes. Retention: accuracy on pre-migration-style questions asked after both migrations. Tie control: append-only notes with a "superseded" tag.

**B2. Logbook compiled into weights (a persistent latent register).** Distill a Logbook program's state-update rule into a small recurrent state vector that the model carries across instances, reading and writing it inside its own forward pass, so the "notes" become a learned register file rather than text. *Why new:* this is weight-space programming of a *stateful* program, with recurrence across episodes, where existing work compiles stateless functions. **First test:** tiny transformer trained to emulate a hand-written poker-opponent logbook on synthetic hands; then run it on a new opponent sequence. Retention: return against the first opponent after two switches. Tie control: same-size text summary prepended.

**B3. Inverse Logbook (memory programs synthesized from trajectories).** After N instances, search for the smallest program whose state, replayed over the logs, would have predicted every successful action. Then use that program as the memory going forward and re-synthesize it when its predictions fail. *Why new:* Logbook writes the program a priori; agent memories are text. This makes the memory a program induced from experience with an MDL objective over logs. (MDL lesson scoring in the ledger scores text lessons, not programs.) **First test:** LLM-guided program search (Nemotron, batched) over 40 database_exploration-like logs; compare to the a-priori logbook. Retention: old-group questions after the switch. Tie control: an a-priori logbook given the same tokens.

**B4. Spec-to-schema meta-learning (what to remember, decided before experience).** Learn the map from a task brief to a memory schema across many tasks, so a new task gets its memory layout zero-shot, as Logbook does by hand. *Why new:* this makes "what is worth remembering" a transferable learned prior instead of an emergent property of a reflection prompt. **First test:** leave-one-task-out over the 6 bench tasks (offline, from their briefs and released traces): does a schema written from 5 tasks' briefs+outcomes beat a schema written from the brief alone on the 6th? Retention: score on early-instance questions after the schedule ends. Tie control: generic key-value notes.

**B5. Logbook markets.** Several competing memory programs run in parallel on the same stream. Each bids its confidence on the next answer, and the agent trades on the logarithmic-scoring-rule winner. Programs that keep losing go bankrupt and are replaced by mutated survivors. *Why new:* this puts competition and selection on the memory *representation* during deployment, with a proper scoring rule as the selection signal. **First test:** 8 hand-varied logbooks on synthetic poker with opponent switches. Retention: pnl on a returning opponent. Tie control: the single best logbook chosen in hindsight.

## B. Causal state as memory (from causal reflection)

**B6. Edge-addressable weights.** Each causal edge the agent believes in is written as its own rank-1 LoRA component, trained only on episodes that exercise that edge. A graph edit then maps to weight algebra: deleting an edge subtracts its component, and reversing one swaps in a different component. *Why new:* this joins causal-graph memory (#34, text/API side) with weight-space programming, so weights carry an explicit, editable causal structure. **First test:** synthetic 6-variable SCM QA with a 1.5B model; learn 8 edges as components, then delete 2. Retention: accuracy on queries using only the untouched edges. Tie control: one LoRA retrained on the edited data.

**B7. Counterfactual-gated weight writes.** Before committing an update learned from an episode, replay the episode with the hypothesized cause perturbed. Write only if the model's predicted outcome moves the way the hypothesis says. Otherwise park the update as "correlational". *Why new:* #34 gates *graph* updates with a counterfactual check; no weight-update rule gates on interventional consistency. **First test:** sales-like synthetic stream with spurious price/store correlations that flip midway; small MLP or 0.5B LoRA. Retention: error on the pre-flip regime. Tie control: same updates gated by loss decrease alone.

**B8. Active intervention budgeting.** In cohort_studies the agent has 20 actions and no reward, so it should learn across studies *which queries resolve the most graph uncertainty*. It keeps a memory of query→information-gain outcomes and chooses probes by expected graph-entropy reduction. *Why new:* this applies continual learning to the agent's *experiment design*, not its answers. **First test:** synthetic cohort generator, 12 studies, a GPT-free scripted planner vs one with learned probe values. Retention: KL on early-region cohorts after late studies. Tie control: a fixed probe order tuned on study 1.

**B9. Graph diffing as a drift detector.** Keep the causal graph from the previous regime. On each instance, score the evidence against both the old graph and a minimally edited one, and declare drift only when an edit wins by a Bayes factor. Only the edited edges get rewritten. *Why new:* knowledge_cards clears all cards on drift, and Kaleidoscope degrades on drift. This rewrites only the changed edges by construction. **First test:** database_exploration-like synthetic migration affecting 2 of 10 schema facts. Retention: accuracy on the 8 unaffected facts after migration. Tie control: clear-all on NOTICE (knowledge_cards behaviour).

**B10. Server-side learning state as a separable object.** #34 showed the whole gain can live behind the model API, with the harness unchanged. So define a portable "learning state" (graph plus KV-prefix) that can be exported, merged across rollouts and imported into a different model. *Why new:* the state that carries learning becomes a first-class artifact, separate from weights, harness text or model identity. **First test:** export a graph learned by Qwen 1.5B on 3 synthetic tasks and import it into Qwen 0.5B. Retention: task-1 accuracy after the import plus task 4. Tie control: transfer the transcript text instead.

## C. Learning only in weights (from Learner 1.0)

**B11. Reachability-preserving updates.** Learner 1.0's teacher writes examples *from states the learner reached*. Generalize this into a retention constraint: after an update, the set of states the old policy could reach must stay reachable, estimated by rollouts. Outputs are free to change. *Why new:* retention is defined on behavioural support (what the agent can still get to), not on outputs or parameters. **First test:** gridworld with 3 sequential goal tasks, small policy net. Retention: success on task 1 after 3. Tie control: KL-to-old-policy regularizer at equal strength.

**B12. Teacher retirement schedule.** The teacher that writes training examples is phased out as the learner's own examples start to match the teacher's (judged by a held-out verifier), so the learner becomes its own teacher on the states it now handles. *Why new:* this makes the *source* of supervision a learned, retiring quantity in continual learning. Different from OPSD teacher-refresh (ledger): here the teacher is replaced by the student per state region. **First test:** 0.5B on arithmetic-format stream with a 1.5B teacher; retire per format once agreement exceeds 90%. Retention: old formats after 5 more. Tie control: fixed teacher throughout.

**B13. Dual-written procedures as a forgetting alarm.** Every procedure is written both as text (notes) and into weights. At use time, the disagreement between weight-only behaviour and notes-conditioned behaviour on the same state is a label-free forgetting signal that triggers targeted rehearsal. *Why new:* the redundancy across substrates is used as a *sensor*, not as a double dose (ledger M3 tested dosing, not disagreement). **First test:** Qwen 0.5B, 10 synthetic procedures, LoRA plus notes. Check whether disagreement predicts which procedure fails after 10 more updates (AUROC). Tie control: weight-only loss on stored examples.

**B14. One example, one update, a canonical ledger.** With single-example updates in arrival order, store the ordered example ledger. Learn a "consolidation compiler" that periodically retrains from the ledger in a learned canonical order, chosen to minimize interference, and swaps the result in. *Why new:* the training order becomes an optimizable compile step over a ledger, offline, between deployments. (O2 in learning-primitives asks for commutativity of the operator itself.) **First test:** 0.5B LoRA, 60 facts in 3 domains; arrival order vs greedy canonical order vs random. Retention: domain-1 facts. Tie control: shuffled replay at equal steps.

## D. Unintended channels as a resource (from the leak-fix PRs)

**B15. Stigmergic memory.** Agents deliberately write into the environment (files, comments, git notes) in a learned code, and later instances read that state back. Partial resets test robustness. *Why new:* the bench treats this channel as a leak to close. Here it is a designed substrate with a learned codec and an erasure model. **First test:** sales-like container, agent may write only into a 2 kB area that is randomly half-erased between instances; learned redundancy vs plain notes. Retention: year-1 cluster growth rates recalled in year 5. Tie control: plain notes with the same erasure.

**B16. Channel attribution of learning gains.** Ablate each possible carrier (context, store, files, git, weights, API state) one at a time over the same rollout. This gives a decomposition of a system's gain by channel, a *ledger of where learning lives*, which becomes the target for routing future writes. *Why new:* the bench reports one gain number, and PR #26 found by hand a gain carried by a forbidden channel. **First test:** replay the published ICL and Kaleidoscope traces with channel masks on 2 tasks (offline). Retention: gain on the first 5 instances re-asked at the end. Tie control: none needed for the measurement; for routing, write to every channel.

**B17. Past-history distillation for codebases.** Legitimately use the git history *before* `base_commit` to learn the repo's evolution operator: train to predict the next real commit from the previous ones, then solve the issue. *Why new:* the leak shows that future history solves tasks. The past history is a free, repo-specific curriculum that continual-learning systems ignore. **First test:** tablib history up to each base commit; 0.5B code LoRA on next-commit prediction, then pass@1 on the 9 tablib tasks. Retention: tablib pass rate after training on tenacity history. Tie control: LoRA on repo source files at equal tokens.

## E. Drift and stale memory (database migration, Kaleidoscope vs ICL)

**B18. Executable facts.** Every memory is a pair: a claim and a cheap verification probe (a SQL query, a unit test, a scan check). At retrieval the probe runs, and failed probes mark the claim stale and trigger re-exploration only for that fact. *Why new:* this turns "staleness" from a heuristic (recency, NOTICE) into a per-fact runtime check with a cost budget. **First test:** synthetic migration DB, 1.5B model, 40 questions. Retention: correct use of unaffected facts after the migration. Tie control: clear-all on drift.

**B19. Evidence-retaining notes with lazy re-derivation.** Hypothesis: Kaleidoscope loses to ICL on the migration task because distilled notes throw away the raw evidence needed to notice the change. Notes keep pointers to the raw observations that produced them and are recompiled from those when contradicted. *Why new:* this makes provenance part of the memory's update rule, not only an audit trail. **First test:** offline on the released database_exploration traces: replay with notes-only vs notes plus evidence pointers (a 1.5B reader). Retention: pre-migration groups after the migration. Tie control: raw transcript ICL.

**B20. Environment-version transport for memories.** Learn an operator that maps memories written under environment version v to version v+1 (e.g. old schema → new schema), learned from a few paired probes, and apply it to the whole store. *Why new:* the ledger covers task-vector transport across *model* versions; this transports the *agent's knowledge* across *world* versions. **First test:** 3 synthetic migrations; fit the operator from 3 probe pairs each. Retention: transported old memories answer old-type questions correctly in the new schema. Tie control: re-explore from scratch at equal query budget.

## F. Opponent switches and harmful learning (poker, Ouroboros)

**B21. Kelly-sized memory reliance.** Treat each stored exploit as a bet with an estimated edge and a variance. The agent sizes how much it acts on a memory with a Kelly fraction that shrinks automatically when recent evidence weakens the memory. *Why new:* this is a capital-allocation rule for *using* memories, not for writing them, so one stale exploit cannot cause unbounded loss. **First test:** simulated poker with 4 scripted opponents and switches, a tabular exploit memory. Retention: pnl when an old opponent returns. Tie control: a fixed confidence threshold.

**B22. Always-on stateless twin.** Run a cheap stateless shadow policy on every instance and score both with the same scorer when feedback arrives. Memory use is gated per region of state by whether the stateful policy is beating its own twin. *Why new:* the benchmark's baseline becomes an online control signal against negative transfer such as Ouroboros' −176 poker gain. **First test:** offline on published poker traces: would gating on twin-vs-stateful running reward have avoided the drop? Retention: final gain on early opponents. Tie control: memory decay at a matched rate.

**B23. Simulator memories.** Store small executable models of *other agents or environments* (one per opponent, store or repo). At each instance, retrieve by the likelihood of recent observations under each simulator, and plan inside the retrieved simulator. *Why new:* the memory unit is a generative world model scored by likelihood, not a fact or a lesson. **First test:** poker with 4 opponent programs, LLM-written simulators, retrieval by action likelihood. Retention: detection speed and pnl on a returning opponent. Tie control: notes describing each opponent.

## G. Learning with no reward or only an ack (cohort, BSM)

**B24. Memory of the sampling process.** In cohort_studies each study is a biased sample. The agent remembers, per study, an estimate of the *selection mechanism* (who got enrolled) and pools all studies by inverse-selection weighting. *Why new:* continual learning usually stores knowledge about the world; this stores knowledge about *how the data reached it*, which is what makes a non-iid stream poolable. **First test:** cohort-like synthetic generator, 12 studies, logistic selection. Retention: KL on early-region cohorts after all studies. Tie control: naive pooled KM.

**B25. Goodhart memory.** Learn, across instances, calibration curves between in-tool proxy metrics (the in-study KL) and the delayed true score, and store them as memory so the agent stops optimizing proxies that diverge. *Why new:* this remembers *how reliable the agent's own instruments are*. **First test:** synthetic tasks with a proxy that correlates 0.9 early and 0.2 later; agent with vs without proxy-calibration memory. Retention: correct proxy trust on early-type tasks. Tie control: always use a fixed proxy weight.

**B26. Self-predictive registries.** BSM gives only an ack. The memory (transmitter registry) is trained to predict the *next scan's peaks*, and its prediction error is the only learning signal. Items whose predictions keep failing are revised. *Why new:* this is a label-free continual-learning loop in which the memory is a forecaster of observations, not a store of answers. **First test:** BSM-like simulator, registry as an explicit list updated by a scripted or 1.5B writer. Retention: inactive transmitters still listed after 30 silent scans. Tie control: a frequency-threshold registry.

**B27. Learned survival functions for memories.** Each memory item carries a hazard function fit to how long *things of its kind* stay true in this world (BSM: transmitters silent for many scans still exist), rather than a usage-based decay. *Why new:* forgetting is matched to the world's persistence statistics, learned per item type. The ledger's "programmable half-life" is set by the writer, while here half-lives are estimated from the stream. **First test:** BSM-like simulator with 3 transmitter classes of different duty cycles. Retention: silent-class recall after long gaps. Tie control: one global decay tuned on validation.

**B28. Generator memories (lattice registry).** Mubit's BSM run stored a fitted frequency lattice, not a list. Generalize: memory compresses observations into the smallest parametric generator that reproduces them, and retrieval samples from or queries the generator. *Why new:* the memory unit is a generative hypothesis with parameters, and inconsistent new data triggers re-fitting of the generator, not note edits. **First test:** BSM-like data on a hidden lattice plus off-lattice outliers; list registry vs generator registry. Retention: recall of early-seen channels. Tie control: list with dedup.

## H. Workspaces, cost and models (sales, leaderboard patterns)

**B29. The file system as a weight space.** In sales the persistent `/app` is the agent's only institutional memory. Treat its scripts and data files as parameters: after each year's feedback, propose edits to the workspace, accept them by validation on all past years' feedback, and track forgetting as failing re-runs. *Why new:* this applies optimizer and retention machinery (acceptance tests, regression checks) to an agent-written code base as the learned object. **First test:** sales-like simulator, 1.5B agent, 6 years. Retention: forecast error on year-1 clusters after year 6. Tie control: notes-only memory.

**B30. Posterior artifacts.** The agent maintains a probabilistic program plus its posterior (e.g. growth rates and price elasticities per cluster) as memory, and each year updates the posterior exactly rather than rewriting notes. *Why new:* memory is a sufficient statistic with exact incremental updates, so retention is guaranteed by conjugacy instead of being hoped for. **First test:** the same sales simulator, LLM-written model updated by code. Retention: year-1 parameter recovery. Tie control: an LLM that rewrites a summary each year.

**B31. Memory as a model upgrade.** Memory stores lift weak models most (Gemini 3.1 Pro: −0.076 → 0.23). Measure an exchange rate between memory items and model scale: give memory written by a strong model to a weak reader, and find how much memory equals one model size. Then train writers that maximize weak-reader gain. *Why new:* this treats memory as a transferable capability patch across models, with a reader-aware writer objective. **First test:** Qwen 1.5B writes and 0.5B reads, vs 0.5B writing for itself, on the G1 router (with filler and temperature arms per the A3 gotcha). Retention: early-lesson tasks after 30 more lessons. Tie control: the strong writer's raw transcript.

**B32. Reasoning amortization with invalidation.** #34 got top scores for $2.32. Cache the *results of expensive reasoning* (derived facts, solved sub-plans) as cheap memory, with invalidation tied to the inputs each result depended on. Learning then becomes the conversion of thinking into lookups. *Why new:* this makes cost per learned gain the objective, with dependency-tracked invalidation (a build system for thoughts). **First test:** database_exploration-like synthetic, 1.5B: tokens to reach equal accuracy with vs without the cache, through a migration. Retention: post-migration accuracy on cached-but-unaffected facts. Tie control: a plain answer cache without invalidation.

## I. Resets and orders (benchmark protocol)

**B33. Learned partial resets.** The bench compares full memory against `reset()`. Learn a reset gate that decides which memory subsets to wipe at each instance boundary, trained on the counterfactual gain of each subset. The training signal comes from the benchmark's own stateless baseline. *Why new:* reset becomes a learned, item-level operation, positioned between "keep all" and the baseline. **First test:** poker and database synthetics, 4 memory partitions, oracle-gain labels from offline ablations. Retention: gain on returning regimes. Tie control: a recency window.

**B34. Memory as a pure function of the evidence set.** Each run uses 5 permuted orders, so order effects are part of the score. After every instance, rebuild the memory from scratch from *all* raw logs in a canonical order (a deterministic compile), so the memory depends on the set of evidence, not its order. Compare it with incremental memory. *Why new:* this makes order invariance a structural property of the memory pipeline rather than a regularization target. (The killed memory-loop Lyapunov work only predicted order dependence.) **First test:** synthetic database stream, 5 orders. Measure the across-order variance of final accuracy. Retention: early-instance re-asks. Tie control: incremental memory with a fixed summarizer seed.

**B35. Cross-task schedule interference.** run-all runs 6 tasks with separate memories. Run one shared memory across all six tasks in sequence and measure positive and negative transfer between the tasks' memories. *Why new:* this turns the bench into a task-incremental, multi-domain continual-learning test of agent memory, which no submission tried. **First test:** 3 synthetic task clones (db, poker, sales) with a 1.5B agent, sequential with a shared store. Retention: task-1 score after tasks 2–3. Tie control: separate stores.

**B36. Refusal-free schema adaptation.** #35 found Sonnet 5.5 refusing on schema fields named `thinking` or `thought`. A continual learner should learn the *interface* it is allowed to use: it keeps a memory of output schemas that fail (refusal, parse errors) and rewrites its own output protocol. *Why new:* this applies continual learning to the I/O contract between agent and environment, not to the task content. **First test:** a 1.5B agent with injected schema rejections on 3 field names; count recovery instances. Retention: original fields still used where they are allowed. Tie control: a fixed retry ladder (as in #19).
