# Cross-pool merges, round 33

Focal sources: `tree/unregistered-dependence.md` (PR #150, UD#) and `tree/stored-slack.md` (PR #151, SS#). Crosses with learned invalidation (PR #148, LI#), minimal wake anchors (PR #149, WA#), fact–skill entanglement (PR #140, FE#), behavior footprints (PR #102, BF#), footprint counterfeits (PR #107, FC#), adapter contracts (PR #117, AC#), redundant skill populations (PR #116, POP#), X1/Y1 override budgets, rented constraints (PR #145, RC#), Y6 plasticity economy, and earlier rounds 1–32. These are raw proposals. Separate specified reads, actual model reads and effects of an allowed writer. Report false-safe slack, premature guards and undiscovered edges separately; measure slack in fact units, not logits. For each stored counter, charge where and how it is updated; compare computed slack, an equal-byte external table and exact recomputation. Separate finite audits from proofs under declared assumptions and compare old service at matched attained B progress.

**USR1. Let two leased writers spend the same safety reserve only if their effects really cancel.** Parts: UD4 jointly harmful writes, UD15 finite safe regions, UD16 composition, SS4 escrowed slack, SS20 multi-hop slack, RC7 sub-leases, Y6 plasticity rent, ECR3 joint windows. *Mechanism:* Track each writer's proposed effect in fact units in an external joint ledger. Credit offsetting edits only when the shared consumer stays within its declared region at every observable prefix, or when the writer can publish both changes atomically. Reserve an explicit share for unresolved downstream effects. *New:* Two writes that each fit their own slack can fail together; two writes that are rejected individually may be safe in a verified joint commit. *First test:* Compare independent quotas, a joint region and a fixed projection in a two-toll learner. Cross reinforcing and canceling moves with both write orders, charging ledger updates and failed commits.

**USR2. Challenge a footprint with moves that spend no visible answer margin.** Parts: UD2 writer-specific registries, UD5 relabeling invariance, UD23 targeted verification, SS3 value–threshold–slack triangle, SS9 local writes, SS22 boundary brackets, BF#, FC#, W1 expiring behavioral identity. *Mechanism:* Start with replacements that give identical answers and report the same reads. Apply permitted small fact moves without crossing either claimed boundary, then use a held-out bracketing move to test whether each replacement tracked the accumulated change and whether it spuriously touched a neighbor. External counters are tied to the writer version, so copied footprint declarations do not reproduce the measured trajectories by fiat. *New:* A counterfeit can match the old contract and pass a single edit yet spend a different amount of slack on the way there. *First test:* Compare cache, reader and shared-writer implementations on same-endpoint paths with different prefixes. Test whether trajectories detect incompatibilities earlier than matched one-shot probes.

**USR3. Give an adapter a fact-unit lease on both sides of its interface.** Parts: UD1 producer–consumer pair, UD9 joint migration, UD11 feature refactors, SS10 re-anchoring, SS18 base-invariant slack, AC#, FP7 caller-side enforcement, FE6 shared writer. *Mechanism:* Before a base upgrade, negotiate which fact changes may consume slack and how the downstream consumer is expected to interpret the adapter's write. Store brackets and units outside the base; transplant them only after a verified rebind re-establishes the same boundary under the new downstream semantics. If the producer and consumer cannot migrate together, keep an old route or fall back. *New:* An adapter can keep exactly the same input activations and outputs today while its permissible future writes have become narrower. *First test:* Compare activation matching, output matching and paired boundary probes across a permuted base and a same-output changed interpreter. Count re-anchoring and test a later unrelated lesson.

**USR4. Count backup skills by the slack they do not share.** Parts: UD8 reachable routes, UD21 shared cuts, SS13 stale slack, SS16 slack floors, SS19 read versus memorize, POP#, FP4 shared-risk reserves, RC22 joint wake. *Mechanism:* Keep a versioned external boundary sketch for each reachable holder and label known shared dependencies and failure intervals. Rent an active holder's constraint only if an independently reachable alternative stays within its own audited region or a fixed public wake can restore the active one. Two copies with the same exhausted consumer boundary do not buy a second unit of cover. *New:* Redundancy can disappear gradually in a fleet long before the first request fails. *First test:* Compare staggered specialists, copies sharing the same writer, and equal-byte replay under common and independent perturbations. Measure survivor reachability, worst request latency and B after wake.

**USR5. Give an absent exception a finite safety boundary.** Parts: UD7 negative lookups, UD8 close newly reachable routes, UD12 independent audits, SS5 evidential slack, SS11 learned expiry, LI18 completeness, WA9 active disagreement, LWA4 missing-edge probes. *Mechanism:* On a declared query region, keep conservative external bounds on how close an excluded entry is to changing a fallback or top-k decision. A new writer that can create entries cannot inherit a bound that covered only old candidates. Spend an independent audit on a disagreement revealed by an insertion or a scope change before reusing the cached fallback. *New:* A lookup can depend on a fact that was not present when the dependency registry was built. *First test:* Add exception keys to a small retrieval learner while holding scores for existing keys fixed. Compare positive-edge tracking, invalidate-all and bounded fallback, charging both index updates and missed exceptions.

**USR6. Keep two override budgets: how much a fact may move, and how much a writer may distort the rule.** Parts: UD14 original-contract budget, UD17 reachable histories, UD20 authorized edits, SS12 slack erosion, SS17 fossil beliefs, X1 typed overrides, Y1 hysteresis, ECR6 scoped permits. *Mechanism:* Record baseline constraints outside shared serving weights. Apply approved fact deltas to the current-premise ledger; debit residual writer-induced changes in boundary behavior against the original rule, not against yesterday's already-drifted model. Do not let rebasing the counter forgive cumulative damage without independent evidence. *New:* The right to change a value need not include the right to change the threshold or erase a still-valid exception. *First test:* Alternate authorized toll changes with small B writes and reversals. Compare rolling resets, a single norm budget and dual accounting at matched direct edit efficacy and B progress; score supplied-premise skill separately.

**USR7. Reserve the anchor for the first boundary a wake can no longer justify.** Parts: UD3 induced forgetting, UD6 cheap registered reads, SS12 latent erosion, SS15 replay triggers, WA3 drift loans, WA6 change-frontier labels, RC4 lease term, LWA1 anchor renewal. *Mechanism:* Maintain an external interval for each tested wake-dependent boundary and refresh from fixed public probes. If slack erodes near a known branch point, first run the frozen wake on a shadow; spend priced side information only when candidate completions disagree at a current separating case. An ambiguous anchor or untested route suspends renewal rather than licensing longer leases. *New:* A learner can trigger intervention before a stored answer fails without storing a labelled recovery hint for every sub-threshold move. *First test:* Randomize lease dose and version changes across opposite private worlds. Compare calendar refresh, output-error-triggered replay and slack-triggered wake at equal state and audit budgets, with stale-version and kept-B checks.

**USR8. Charge a registry for the writes needed to keep its own counters honest.** Parts: UD21 factored cuts, UD24 replay break-even, SS2 stored versus computed, SS8 counter location, SS14 precision budget, LI21 two-level cache, Y6 plasticity economy, KT1 upkeep. *Mechanism:* Put frequently used counters in a small external tier and recompute the long tail, with an isolated-adapter arm to measure what happens if tracking itself writes model state. Charge each writer's share of registry updates, validation, read amplification and collateral, including fact moves that flip nothing. Spend released capacity on B only when the full maintenance bill still improves. *New:* A memory can save live output writes while becoming worse at continual learning because its own bookkeeping writes are too expensive. *First test:* Cross hot and cold consumers with small-step drift and burst revisions. Compare exact external slack tables, sensitivity-based computation and write-on-change at matched bytes and measured service cost.

**USR9. Return the smallest conflict that a new writer cannot avoid.** Parts: UD13 bypass tests, UD18 impossibility witnesses, UD19 replacement cuts, SS1 weighted dependency graph, SS4 joint slack, SS23 false-safe certification, BF# footprint envelopes, FC# footprint counterfeits, ECR4 repair charges. *Mechanism:* In a finite host, identify an admitted B goal and old requests for which no candidate write meets both contracts. Show whether the conflict comes from a real shared dependency, a falsely generous stored boundary, or the chosen writer family. Price a replacement cut, an external route or a smaller target instead of treating a veto as evidence of universal impossibility. *New:* A failure receipt can tell the writer whether to buy information about the boundary, buy a new interface, or give up part of the requested progress. *First test:* Enumerate legal writes to a tiny rule graph, then use paired probes to propose conflicts in an unpartitioned host. Compare exact finite receipts, simple norm vetoes and rank-matched protection.

**USR10. Let a correction cross its own boundary without spending another consumer's.** Parts: UD10 retire a read by replacement, UD20 authorized change versus forgetting, UD22 steer around a cut, SS7 crossing triggers, SS9 local writes, SS17 slack surgery, FE#, LI#, FF#, FER10 consumer scheduling. *Mechanism:* Use external counters to propose where a current binding should change answers. Verify a direct rebind and independently test procedure use with supplied held-out premises; allow the authorized flips, then guard unrelated boundaries and still-current old exceptions. Retire an old path only after a replacement demonstrates both required propagation and preservation under the allowed writer. *New:* An edit can intentionally spend all slack on one edge while protecting the procedure that lets a different caller use the same fact. *First test:* In a two-hop rule learner, vary which recipients should change and which share an internal feature but not an obligation. Compare graph-scoped writes, activation protection and exact-store routing at matched new-fact recall.

**USR11. Lease plasticity against a ledger of what reads can still tolerate.** Parts: UD1 producer–consumer protection, UD2 writer-specific registries, UD4 joint clauses, UD5 invariance, UD7 negative reads, UD8 route closure, UD9 joint migration, UD10 read retirement, UD11 transport, UD12 independent audits, UD13 bypass checks, UD14 anchored budgets, UD15 finite regions, UD16 composition, UD18 impossibility receipts, UD19 replacement cuts, UD20 authorized changes, UD21 shared cuts, UD22 steered writes, UD24 replay break-even, SS1 weighted edges, SS2 computed versus stored, SS3 slack triangle, SS4 escrow, SS5 evidential slack, SS7 crossing triggers, SS8 counter placement, SS10 re-anchoring, SS12 latent erosion, SS13 stale slack, SS14 precision, SS15 replay triggers, SS16 slack floors, SS17 fossils, SS18 base-invariant contracts, SS19 cache tiers, SS20 multi-hop propagation, SS22 bracketing, SS23 false-safe audits, LI#, WA#, FE#, BF#, FC#, AC#, POP#, X1, Y1, RC#, Y6, ECR4, LWA4. *Mechanism:* Register what a skill ought to read, what it actually reads, and what each allowed writer can change. Carry versioned external slack or recompute it as cost dictates; reserve regions for joint writes and sample outside the graph for missing dependencies. Spend bounded slack on new learning only while protected consumers have an audited route or a declared recovery option. After an edit, debit accumulated residuals, renew anchors where necessary, and separate authorized change from collateral and stale revival. *New:* The learner can lend not just space or rank, but the measured distance between a proposed write and each old service's next failure, with explicit limits on how much of that distance it actually knows. *First test:* Use an enumerable routing world with rare fallback exceptions, aliased adapters, drift-only fact moves, overlapping leases and a shared wake. Compare tuned projection, replay, an exact priced graph-plus-slack cache and budgeted learned registries. Report first break, worst prefix, false-safe and missing boundaries, counter and anchor costs, and matched post-wake B progress.
