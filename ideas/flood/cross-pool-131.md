## Merge proposals

**ABY1. Grade the writer by the placements that transfer to unseen effects.** Parts: HL01 benchmark, HL02 placement-only track, HL03 values-only track, HL04 gain-per-rank curve, HL05 truncation audit, HL24 causal localization, HL25 description-based placement, HL26 budget frontier, HL27 placement map, PL5-10 held-out effect family. *Mechanism:* Cross placement chosen by the writer or a gradient-based selector with handwritten or trained values at each parameter budget. Reserve entire task-effect families from placement development. Log the gain lost when a full edit is truncated separately from failure to pick the right module. *New:* A placement is evidence of reusable knowledge if it helps a different value finder on a task family the writer has not already tuned for. *First test:* On synthetic symbol and formatting tasks compare all four arms, with equal budgets within each arm's comparison; report target gain and untouched-task retention.

**ABY2. Carry the reasons for a patch through a base upgrade and a later correction.** Parts: HL06 annotated rank-one writes, HL14 decompile and recompile, HL21 base migration, HL22 cross-size compilation, L3-03 amendment transport, TT14 editable decompilation, NP4-13 response to future evidence. *Mechanism:* Store component claims with independent behavior probes plus a withheld correction described in observable terms. Rebuild from that spec without the old factors; apply the correction after rebuilding. Compare against carrying over numbers or reconstructing only present behavior. *New:* Two migrated adapters can pass the same current tests yet disagree on what changes when a later correction arrives; preservation of that response is a separate migration target. *First test:* Compile a synthetic rule and later amend a single exception on a new base. Compare spec-only recompilation, a claims-shuffled control, applicable numerical transfer and equal-data retraining; test the amendment and untouched rules.

**ABY3. Repair collateral damage only when the component explanation survives ablation.** Parts: HL07 component blame, HL09 declared protected behavior, HL13 handwritten initialization, HL15 spillover repair, HL16 component veto, HL17 exceptions, TT03 protected updates, NP5-26 future-revealed interference. *Mechanism:* Before allowing a repair, compare component and joint ablations against a low-rank correction fitted on the same evidence. If damage is diffuse, do not pretend a single direction caused it. Protect the stated old behavior now and after a fixed menu of benign later updates. *New:* A repair should remove the observed spillover without leaving a concealed regression that appears after the next ordinary adaptation. *First test:* Train on one toy spatial rule, withhold a neighboring rule, then repair and apply a later benign update. Compare matched-rank retraining, a static protected projection and the claim-guided repair on both rules.

**ABY4. Admit adapter sets against stated contracts and independent regression tests.** Parts: HL08 declared read sets, HL10 conditional components, HL11 claim-based merging, HL12 composition checks, HL18 shared component bank, HL19 local revision, HL20 retained regression tests, HL23 sequential edit capacity, HL30 defensive admission audit, NP4-21 common-ancestor composition. *Mechanism:* For approved uses on synthetic data, record shared component ancestry and declared domains. Use read/write checks only as a screening heuristic; require independent behavior tests on the actual composed set, including benign domain overlaps. After a revision recheck affected sets and retain the retired component's regression tests. *New:* A set that passes today must not inherit approval blindly after one member changes; the admission artifact includes the conditions and tests that justify reuse. *First test:* Compose six toy domain adapters and compare all subsets against separate and pairwise checks. After one benign rule revision, compare selective rechecking against full rechecking and plain factor merging; measure missed regressions and evaluation cost.

**ABY5. Charge for search, not just for the final adapter.** Parts: HL28 gate overfitting, HL29 matched controls, HL31 description and unlabelled-input track, HL32 cost ledger, HL33 edit-ready bases, PL5-10 held-out effect family. *Mechanism:* Give each writer or control the same information and evaluation-call budget, and seal test tasks by effect family. Charge edit-ready preparation separately and amortize it across a published number of subsequent tasks. *New:* A claimed handwriting advantage must survive transfer to new effects after all up-front and per-task selection costs are counted. *First test:* Run a proposed description-only synthetic benchmark with trained adapters given the same generated or supplied labels in each comparable arm, plus norm-matched random search. Plot held-out gains and retention against tokens, evaluations and training compute.

**ABY6. Keep an editable adapter contract across authoring, repair, composition and migration.** Parts: HL01 benchmark, HL02 placement-only track, HL03 values-only track, HL04 gain-per-rank curve, HL05 truncation audit, HL24 causal localization, HL25 description-based placement, HL26 budget frontier, HL27 placement map, PL5-10 held-out effect family, HL06 annotated rank-one writes, HL14 decompile and recompile, HL21 base migration, HL22 cross-size compilation, L3-03 amendment transport, TT14 editable decompilation, NP4-13 response to future evidence, HL07 component blame, HL09 declared protected behavior, HL13 handwritten initialization, HL15 spillover repair, HL16 component veto, HL17 exceptions, TT03 protected updates, NP5-26 future-revealed interference, HL08 declared read sets, HL10 conditional components, HL11 claim-based merging, HL12 composition checks, HL18 shared component bank, HL19 local revision, HL20 retained regression tests, HL23 sequential edit capacity, HL30 defensive admission audit, NP4-21 common-ancestor composition, HL28 gate overfitting, HL29 matched controls, HL31 description and unlabelled-input track, HL32 cost ledger, HL33 edit-ready bases. *Mechanism:* Store behavioral claims, independently held-out tests, component ancestry and an amendment interface separately from the numerical factors. At each stage require the contract to predict an operation that a performance-matched adapter alone may not preserve. If claims fail to predict behavior, fall back to ordinary training and revalidation. *New:* An adapter's durable object would be the contract that still governs a later revision on a new base, not the old weights or an explanation written after a score improved. *First test:* On a fixed synthetic rule stream, author, compose, revise and migrate adapters before issuing a withheld amendment. Compare numerical merging and transfer, and trained adapters with an equally strong external regression suite. Match access and budgets; report retention, amendment accuracy and cost at each stage.

## LoRA prior-art check: PR #400

This is a targeted comparison with published baselines, not a novelty verdict. [Self-WSP](https://arxiv.org/abs/2611.28833) reports that random search sometimes matches its edits; [Writing Weights or Training Them?](https://arxiv.org/abs/2611.27089) reports that trained rank-one LoRA wins on the tested spatial targets but damages neighboring tasks. So ABY1 and ABY5 are assays, and ABY3 must beat equal-information trained repair as well as matched search. [Text-to-LoRA](https://arxiv.org/abs/2506.06105) already generates adapter weights from descriptions, [Trans-LoRA](https://arxiv.org/abs/2405.17258) transfers with synthetic data, and [LoRA-X](https://arxiv.org/abs/2501.16559) transfers compatible subspaces without training in its demonstrated setting. For ABY2, test the response to a later amendment, not description-to-adapter generation or porting alone. [S-LoRA](https://arxiv.org/abs/2311.03285) supports serving many adapters, and [TIES-Merging](https://arxiv.org/abs/2306.01708) addresses parameter interference in merging; ABY4 instead asks whether explicit, versioned behavioral checks predict which sets remain compatible after a revision.
