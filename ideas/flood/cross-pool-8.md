# Cross-pool merges, round 8: deep cross

Deep cross: established sources revisited in new combinations: `ideas/flood/nooa.md` (PR #41, N#), `ideas/flood/physics-math.md` (PR #44, PH#), `tree/model-forward-only.md` (PR #50, FO#), `tree/harness-discrete-backprop.md` (PR #52, DB#), `ideas/flood/hardware.md` (PR #66, H##), `ideas/flood/control-dynamics.md` (PR #74, CD#), and `ideas/flood/wildcard.md` (PR #82, WC##). The first nine cards join distant source pairs or triples; the last combines their parts. These are raw and unfiltered.

**U1. Escape velocity for learned state.** Parts: N12 escape analysis, PH2 critical slowing, FO15 adaptive one-bit microscope. *Mechanism:* Let a method's temporary discovery live in a disposable copy of `self`. When the agent starts to depend on it, test recovery from tiny removals at multiple lags; spend extra A/B comparisons only where recovery is ambiguous. Promote a value out of local scope only when the forward trace predicts a lasting dependency and an independent follow-up confirms reuse. *New:* Memory promotion is based on whether the agent recovers from removing a discovery, rather than a persistence flag or a prediction from salience alone. *First test:* In a typed maze harness, give repeat and one-shot facts identical initial utility; compare survival of repeat facts per stored byte against store-all and immediate leave-one-out.

**U2. Exception handlers that carry a write-shape signature.** Parts: N31 learned exception handlers, PH26 winding bits, FO7 local proofs of correction. *Mechanism:* Give each handler a finite ordered family of counterfactual boundary calls. Encode accept/recover/pass-through by a small loop of two-dimensional responses and decode a nonzero winding only when the local assertions pass. A handler may be fine-tuned across tasks without rewriting dispatch as long as the loop retains clearance and fidelity on the boundary calls. *New:* Recovery dispatch is checked by an invariant over permitted failure interventions, not saved exception strings or a single output logit. *First test:* Use synthetic shifting exceptions and compare two equal-size dispatch heads (winding versus ordinary logits) after unrelated learning, with held-out boundary calls and deliberately under-sampled loops.

**U3. A learning tide for typed sibling methods.** Parts: N28 signature evolution, PH5 Koopman modes, FO12 checkpoint distillation. *Mechanism:* Track the forward effects of inserting or masking each proposed argument field across sequential versions. Separate stable change modes from task-local ones; promote only stable fields into a shared type and distill their features from trial methods into the common implementation, leaving transient fields in the child's schema. *New:* Schema growth is guided by the persistence of an intervention's learned effect, not just whether the field improves current prediction. *First test:* In a CPU typed function learner, interleave persistent and spurious fields and compare promoted-field precision and held-out-task adaptation against static schemas and a mean-effect threshold.

**U4. Avalanches that cross a program boundary only with a receipt.** Parts: N40 learned metaclasses, PH9 local toppling, DB1 repair wires. *Mechanism:* Have a learned metaclass assign a small request buffer to each writable field. A successful local repair can top up neighbors, but a threshold crossing across methods must emit its candidate write and affected retained obligation before propagating. The chosen graph makes broad refactors possible without silently treating co-activation as permission to change another field. *New:* The size of a code-repair cascade emerges from local evidence and typed write boundaries rather than a hand-set global patch size. *First test:* Plant coupled and isolated defects in a finite method graph; compare repair success, write count and unrelated regressions against fixed-radius and global repair with the same verifier.

**U5. An adaptive scheduler that phase-locks credit, not work.** Parts: N30 asynchronous credit, PH48 phase multiplexing, H14 spike collisions. *Mechanism:* Let each concurrently running subroutine emit a short phase tag when producing a partial result. Verified downstream outcomes update the write eligibility only of tags that align under a learned timing offset; the actual work still runs under a conventional scheduler. Give overlapping tags a phase-separation objective so shared return times alone do not grant shared credit. *New:* Asynchronous feedback can select a persistent write by synchronization without changing execution ordering or relying only on call IDs. *First test:* In a delayed-feedback worker harness, vary lags and overlapping completions; compare update credit recovery against time windows, eligibility traces and an exact-ID oracle when one result has multiple contributors.

**U6. Pair subtrees before paying for a new contrast.** Parts: N32 subtree replay, PH16 response asymmetry, FO5 compositional A/B codebook. *Mechanism:* Treat paired edit directions as diagnostic experiments over replayable calls. When A affects B more than the reverse, split the fault hypotheses by retesting one condition subtree and one return subtree; only buy a fresh full rollout if neither contrast distinguishes asymmetric routing from a stale witness. *New:* Reciprocity failures choose the replay granularity and the next diagnostic codeword, not a global similarity score. *First test:* Use a four-method toy with truly directional interference and symmetric controls; compare repair-selection accuracy per tool call against whole-trace replay and random subtrees.

**U7. Learn which family of typed outputs needs a forbidden hole.** Parts: N9 contract tightening, PH30 persistent skill holes, WC02 coupled views. *Mechanism:* Embed known successful procedure/context pairs using forward effects, and find a stable hole surrounded by validated returns. Generate paired tasks from opposite views of that hole before tightening the output contract: install a prohibition only if both views identify the same excluded latent case, otherwise preserve the missing case as an unanswered guard. *New:* The shape of observed competence triggers a contrast that decides whether to write an exception or request evidence, not just which task to practice. *First test:* On a tiny multi-view shape generator with one genuine forbidden region and one unexplored region, compare incorrect exclusions and past return validity against uncertainty sampling and fixed contract tightening.

**U8. Reciprocal repair maps with a frequency split.** Parts: PH14 work asymmetry, DB17 reserve of future repairs, CD6 frequency-division plasticity. *Mechanism:* Record forward and return trajectories when trying opposite edits in a fork, and use their measured asymmetry to decide whether the system may write the fast branch or must preserve a slow route for reversal. Treat work gaps as empirical quantities, not thermodynamic identities. *New:* The timescale of placement depends on how much future repair latitude the present edit would consume. *First test:* In a two-timescale linear learner with controllably irreversible interference, compare later selective repair cost at matched initial gain with a fixed crossover and a loss-only reserve.

**U9. Type-indexed sublevel guards with replaceable retention budget.** Parts: PH44 region-preserving updates, N6 signature hashing, FO18 replaceable constraints. *Mechanism:* A method signature names a family of old probes; keep only the boundary facets needed to preserve feasible return regions for that type. A new method competes for facet storage by demonstrating that dropping a facet changes a feasible correction elsewhere, not merely that a probe's internal activation moved. *New:* Retention compression operates on the decision relevance of typed geometric constraints, rather than on examples or uniformly frozen activation regions. *First test:* In a small ReLU function library with shared and independent return types, compare old-region slips, behavior and new-task gain against full activation-region freezing and equal-byte random facet eviction.

**U10. A forward-only workshop that can change its own rules.** Parts: N6 signature hashing, N9 tightening, N12 escape analysis, N28 signature evolution, N30 async credit, N31 handlers, N32 subtree replay, N40 learned metaclasses, PH2 recovery lag, PH5 slow modes, PH9 toppling, PH14 asymmetric work, PH16 reciprocity, PH26 winding, PH30 skill holes, PH44 region guards, PH48 phase alignment, FO5 A/B codebook, FO7 local proofs, FO12 distillation, FO15 adaptive probing, FO18 retiring constraints, DB1 repair wires, DB17 reserve, H14 credit apertures, CD6 crossover, WC02 coupled views. *Mechanism:* Run a workshop of typed methods that promotes transient state only after measured dependence, grows shared schemas from slowly varying interventions, and propagates validated repairs through its own metaclass. An asynchronous credit bus decides which tentative repairs can harden; local boundary tests and measured return costs preserve detachable recovery routes when methods compose. *New:* The durable learner state includes which rules may rewrite future rules and which local forward tests can certify that rewrite. *First test:* Start with a four-method synthetic workflow: mask a local discovery, inject one coupled failure, and swap the order of delayed outcomes. Compare modular retention and adaptation per forward against the same components with a fixed metaclass and separate, nonshared retention budgets.
