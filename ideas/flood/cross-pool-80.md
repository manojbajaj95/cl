## Reviewer-requested merge: synonymous mutability × gauge-orbit tags

**ORM1. Put the edit preference in the orbit rather than in a decoded tag.** Parts: NNL01 synonymous mutability, GO08 permutation tags, GN12 gauge relocation, SM02 directed escape, IP25 causal receipt. *Mechanism:* Use exact hidden-unit permutations of a tiny software MLP to preserve predictions while placing units under different parts of a frozen, address-sensitive editor. Keep total edit exposure fixed and change which useful next behaviors its edits reach. The editor does not decode a tag. If the editor is fully permutation-equivariant, orbit selection alone should have no effect; use that as a null, not a weakness to hide. *New:* The orbit would carry an operational edit preference rather than a message a second component has to read and enforce. *First test:* Enumerate all permutations of a two-unit model on a finite grid; compare native, swapped and sham representatives under one fixed editor and an equivariant control. **Strongest stacked baseline:** same-bit explicit header plus an edit mask, with edit-triggered gauge relocation given the same search, storage and write budget.

**ORM2. Keep an orbit-borne protection policy through real editor changes.** Parts: NNL01 synonymous mutability, GO08 stable gauge tag, GH10 projected header, SM06 protection across editors, SM13 canonicalization, SM15 closed representative set. *Mechanism:* Search for a set of function-equivalent representatives that stays safe under both declared editors and the real normalization pass, but has a bounded useful escape for a maintenance write. Keep a decoded checksum only as a diagnostic, not as proof of protection. If normalization collapses the orbit, report the carrier unavailable; if active projection is required, charge it separately. *New:* Surviving bits and surviving directional protection become independently testable; a readable tag alone would not imply continued mutability control. *First test:* Use a tiny two-layer model with two ordinary perturbation operators and a deterministic canonical sort. Check read equality, subsequent write outcomes, and a rare old case after each operation. **Strongest stacked baseline:** actively projected gauge header plus explicit importance/freeze masks and function-preserving relocation, charged for refresh work and retained bytes.

**ORM3. Make a protected clause cold to one blind editor but teachable by another.** Parts: NNL01 synonymous hot and cold forms, GO08 edit-address metadata, GN12 protection by relocation, GH10 maintenance control, SM03 coordinated edits, SM10 writer-specific edits, CR22 substitute teacher, LE5-09 preserved response. *Mechanism:* Choose a read-equivalent orbit representative that steers one fixed software editor away from a linked old invariant while a second fixed editor can still make a useful coherent repair. Test an independently chosen follow-up teacher on the state after the first real update; never equate frozen outputs with preserved teachability. *New:* A single representation could separate two future edit distributions without either editor consulting a policy table. *First test:* Enumerate a three-clause toy rule puzzle and label the legal co-edits in advance. Compare both editor orders and a canonicalized null. **Strongest stacked baseline:** same-budget per-editor masks or explicit tags, plus gauge relocation and a constrained repair search preserving the same old contract.

## New tree crossings

**ORM4. Route the same delivered service through paths with different future correction effects.** Parts: FA03 temporal route, FA07 write-distinct flow, FA06 bounded lifetime, SD2-02 named reader, IP07 reachable locality. *Mechanism:* In a finite software routing fixture match delivered items and per-edge totals, then choose a lawful event order that sends a bounded correction only to timed reachable edges. Check the downstream old reader at its deadline, not just the endpoint deliveries. *New:* A scheduler may carry a future edit preference in event order without changing current service. *First test:* Hold edge totals and costs equal on two temporal graphs and compare static reachability, explicit routing tags and exact timed planning.

**ORM5. Preserve the delayed outcome when the route that earned it is removed.** Parts: FA02 return-flow credit, FA10 shift-tolerant delivery, SMA23 delayed credit, BM4-03 unsettled loss, ER4-21 typed cutover. *Mechanism:* Route a real delayed outcome by a verified operation mapping at cutover. When real return traffic no longer reaches a valid recipient in time, record an unresolved obligation rather than giving another edge credit. Test local correction after a second reroute. *New:* Time-respecting credit transport could survive topology changes without keeping a full old path. *First test:* Use a small synthetic queue whose return route changes midway; compare forward-path replay, actual return only and receipt-aware rerouting.

**ORM6. Require two independent arrivals before a shared route can consume capacity.** Parts: FA05 local budget, FA08 coincident inputs, FA09 feedback cap, CR18 single-origin receipt, IP09 distinct observations, SMA07 rendezvous. *Mechanism:* At a software junction reserve a share floor for due old traffic. Permit a new shared correction only after compatible independent observations meet at the same legal step; duplicate delivery cannot provide the second observation. Limit repeated capacity gain while retaining passage for needed feedback. *New:* Two useful flows could teach a new route without letting a single reinforced path crowd out old work. *First test:* Cross duplicated receipts, late arrivals and repeated gains in a finite graph with fixed total capacity; compare independent gating and exact joint scheduling.

**ORM7. Export a bounded counterexample when recoding cannot protect a rare read.** Parts: SM07 blast radius, SM12 reuse proof, SM14 rare behavior abstention, SM16 protected consequence, BM4-26 separating observation, SD2-09 refuting suffix. *Mechanism:* Compile a bounded proof of the protected consequence across reachable next edits. When the rare prefix is outside the proof, keep an executable fallback and export the earliest lawful separating suffix. Reuse only the proof fragment whose scope survives a second edit. *New:* A cheap equivalence proof could guide selective coding without substituting ordinary cases for a rare old guarantee. *First test:* Compare exhaustive enumeration, cached proof reuse and scoped abstention on a finite rule set with one deliberately omitted late consequence.

**ORM8. Price mobile edit protection against the work a second teacher can really do.** Parts: SM01 move protection, SM05 fixed-size recoding, SM08 thaw cost, SM09 anticipated collisions, SM11 neutral drift, LE5-24 consumed directions, CR32 observed use. *Mechanism:* Select a read-equivalent code under a fixed memory budget and measure legal thawing after an ordinary first edit. Distinguish neutral representation drift from real new evidence, and pay for the recoding only if an independent teacher completes the second use more cheaply at the same old-service floor. *New:* The learner could buy movable protection instead of permanently renting spare capacity. *First test:* In a small synthetic rule stream, cross harmless normalization with genuine target change and compare matched replay, masks and finite recoding search.
