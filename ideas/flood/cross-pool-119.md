Raw proposals for harmless synthetic environments.

**PGX1. Spend capacity on dormancy only if the recovery route survives new learning.** Parts: OE4-01 revival lookahead, OE4-02 revival-null directions, OE4-03 dormancy exchange rate, OE4-04 target revival, OE4-05 separable expression, OE4-26 key stability, OE3-12 protected relearning, L8W17 update-matched plasticity, D4-24 future teaching gradient. *Mechanism:* Use a one-step surrogate to propose writes that can change outputs, then test full recovery on scratch copies after later learning. Track separate targets for protected, untouched and retired toy skills. Count only verified dormant skills in the exchange rate, after charging for the expression layer, keys and test work. *New:* Directions that preserve one recovery step may still break later recovery; measure extra capacity only where the whole recovery route holds. *First test:* Compare output protection, key-stability training and no protection on a harmless rule stream. Match write budgets and report the new skills learned, dormant skills restored and protected skills damaged.

**PGX2. Price keys by how long they work on checkpoints they have never seen.** Parts: OE4-06 weight-conditioned updates, OE4-07 future-weight distribution, OE4-08 planted keys, OE4-09 minting at mastery, OE4-16 sibling transfer, OE4-18 transition keys, OE3-10 synthetic stored lessons, OE2-15 portable rewards, OE2-21 regrowth pricing, PL5-10 held-out effects. *Mechanism:* Compare keys planted during acquisition and keys minted on simulated lapses. Test both on later checkpoints and sibling models with held-out changes to behavior, not just held-out seeds. Price local adaptation, revival work and fallback storage against fixed deltas and stored objectives. *New:* A key that generates a checkpoint-specific delta earns its storage cost only if it handles sufficiently different later writes better than a cheaper fixed payload. *First test:* Across harmless branching learners and toy control worlds, measure recovery half-life at matched bytes and steps for fixed deltas, synthetic keys, transition batches and objective programs.

**PGX3. Compress keys by sharing what revives together, not by reusing a format everywhere.** Parts: OE4-11 key superposition, OE4-12 coarse and fine keys, OE4-13 generated keys, OE4-14 discrete keys, OE4-15 latent keys, OE4-25 key proposer, OE3-02 revival modes, OE08 counterfactual frontier, D5-26 retained teaching responses. *Mechanism:* Let a proposer try shared coarse keys plus per-skill residuals in text, generated and latent forms. Promote a combined key only when independent probes show which skills it restores and whether it preserves the response to a fresh lesson. Account for generators and interface decoders as well as payloads. *New:* A cheap key code must preserve the differences that matter to the next lesson, not just pass today's skill checks. *First test:* Compare separate keys, one flat combined key and coarse-plus-residual keys as toy competence clusters increasingly overlap; include a tokenizer or feature-basis change.

**PGX4. Page incompatible skills only when both switch directions are checked.** Parts: OE4-10 reversible toggles, OE4-19 expressed working set, OE4-20 time-multiplexing, OE4-21 direct dormancy writes, OE3-03 signed revival, TT28 no-update shadow, L8W22 round-trip reversibility. *Mechanism:* Hold a bounded active set of toy skills. Before replacing one member, compare scratch switching with just cueing the desired skill in context, and check that the outgoing skill can still be restored without damaging unaffected skills. Admit directly dormant skills only after a successful scratch retrieval. *New:* Paging is a trade of switching cost for capacity, not an unbounded store; asymmetric interference can make a slot reusable in one direction only. *First test:* Use alternating toy rule families with known interference and varying demand bursts. Compare permanent expression, context routing and checked paging on switching latency, capacity and repeated round-trip errors.

**PGX5. Preserve recoverable branch versions without letting old answers become current.** Parts: OE4-17 checkpoint keys, OE4-22 dormant merge, OE4-23 dormant versioned edits, OE4-24 dormant distillation, OE3-17 reset insurance, PL02 preserve disagreements, PL03 successor stress test, CR29 versioned relearning. *Mechanism:* Merge or distill a set of harmless rule forks with version-tagged keys for archived behaviors. Restore them on isolated copies and score authorized continuations as well as present outputs. Distinguish behavioral recovery over the tested repertoire from exact checkpoint rollback, and keep a checkpoint when the weaker guarantee is insufficient. *New:* Two successors can look identical today while one has lost a branch's recoverability or can no longer keep retired answers out of current behavior. *First test:* Compare output-only distillation, separate checkpoints and dormant keys on contradictory toy revisions. Test recovery in isolation, current-version routing and how cheaply each restored branch learns its next correction.

**PGX6. Build a checked skill pager that pays for each recovery guarantee.** Parts: OE4-01 revival lookahead, OE4-02 revival-null directions, OE4-03 dormancy exchange rate, OE4-04 target revival, OE4-05 separable expression, OE4-26 key stability, OE3-12 protected relearning, L8W17 update-matched plasticity, D4-24 future teaching gradient, OE4-06 weight-conditioned updates, OE4-07 future-weight distribution, OE4-08 planted keys, OE4-09 minting at mastery, OE4-16 sibling transfer, OE4-18 transition keys, OE3-10 synthetic stored lessons, OE2-15 portable rewards, OE2-21 regrowth pricing, PL5-10 held-out effects, OE4-11 key superposition, OE4-12 coarse and fine keys, OE4-13 generated keys, OE4-14 discrete keys, OE4-15 latent keys, OE4-25 key proposer, OE3-02 revival modes, OE08 counterfactual frontier, D5-26 retained teaching responses, OE4-10 reversible toggles, OE4-19 expressed working set, OE4-20 time-multiplexing, OE4-21 direct dormancy writes, OE3-03 signed revival, TT28 no-update shadow, L8W22 round-trip reversibility, OE4-17 checkpoint keys, OE4-22 dormant merge, OE4-23 dormant versioned edits, OE4-24 dormant distillation, OE3-17 reset insurance, PL02 preserve disagreements, PL03 successor stress test, CR29 versioned relearning. *Mechanism:* Protect a bounded working set and test candidate eviction and replacement on scratch copies. Store dormant skills under versioned keys selected by measured recovery across later writes, preserve separate branch continuations, and charge switching, generation and verification against the claimed capacity gain. *New:* The same learner can allocate expression, dormancy or a stronger fallback according to what it can actually restore at the next checkpoint. *First test:* Cross harmless synthetic rule families with bursty demand, conflicting versions and drifting representations. Compare all-active replay, context routing, checkpoint storage and checked paging at matched bytes and work.
