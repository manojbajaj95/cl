Raw proposals for harmless synthetic rules and independently verified safeguards.

**CPX1. Distinguish a short recovery key from a hidden copy of the rule.** Parts: L8W01 executable-oracle queries, L8W04 rank-one key, L8W06 boundary-targeted probes, L8W09 byte crossover, L7W04 external payload, D5-13 update versus read. *Mechanism:* At matched information budgets, use an authorized synthetic rule oracle to choose queries that distinguish candidate rules, then test whether the resulting native update beats reading the same answers without updating. Evaluate cold loss of the oracle separately: a key that requires a live oracle is not an outage fallback. *New:* The comparison can show whether executable access saves internal bytes or just shifts rule storage and recovery work elsewhere. *First test:* Sweep rule description length and query budget for small generated grammars. Compare byte-matched static text, exemplar replay and a key with live oracle access; include an oracle-unavailable arm.

**CPX2. Translate recovery keys by their held-out behavior, not by their geometry alone.** Parts: L8W02 recovery alignment, L8W03 shared delta decoder, L8W07 key rotation, L6W12 co-rotated wake, D4-04 native update metric, D3-09 witness identity. *Mechanism:* Rebase a key on validated matched predictions after representation drift. Compare an alignment map and a shared delta decoder as candidate generators, then verify the actual optimizer response and collateral effects. Reject keys that match coordinates but restore the wrong exception. *New:* A compact key can be portable even when the learner's features rotate, provided the recovery it authorizes is independently checked. *First test:* In a tiny learner compare pure feature rotation with a lossy remap that matches anchor scores. Test static keys, geometric transport and behavior-checked decoding at equal work.

**CPX3. Compile only the part of a learned skill the external checker can actually own.** Parts: L8W05 deterministic core and residual, L8W11 equivalence gate, L8W12 compilable training, L8W13 partial extraction, L8W14 shared-feature partition, L7W07 compile and evict, D3-12 dependency frame. *Mechanism:* Extract a deterministic candidate with a declared input domain and an explicit unknown outcome. Keep neural exceptions and shared features until independent tests establish equivalence on the declared core and no dependency on the portion being removed. Outside that scope, preserve verified coverage or abstain. *New:* A hybrid skill can free some trainable capacity without treating every unchecked case as equivalent to the compiled rule. *First test:* Use a generated grammar with one provable core, rare exceptions and a shared feature used by another task. Compare whole-rule extraction, no eviction and scoped extraction and deletion.

**CPX4. Batch removals only when they free usable learning directions together.** Parts: L8W08 combined recovery keys, L8W10 subspace reinitialization, L8W15 interference-based scheduling, L8W17 update-matched audit, L8W23 joint removal, L4W10 cost in effective dimensions, L6W13 joint recovery. *Mechanism:* Group candidates by measured overlap with the next task's native update. Simulate joint removal and joint recovery before committing either; match reset magnitude and compute in controls. Count capacity regained only if a held-out new task learns faster without losing old service or a required joint recovery. *New:* A drop in parameter rank may not create useful plasticity, especially when recovery directions collide. *First test:* Use a finite learner with matched-size removals of overlapping and orthogonal skills. Compare sequential removal, matched random resets and composition-aware batch removal.

**CPX5. Emit the recovery test with the compiled check and require a round trip.** Parts: L8W19 compile-evict cycle, L8W20 compiler-emitted keys, L8W22 scratch round trip, L4W21 release after verification, LM26 capability handshake, D5-26 response sketch. *Mechanism:* Have the compiler emit candidate keys and independent boundary probes. On a scratch copy match service before and after removal, then rebuild using only the proposed recovery materials. Test with the checker available and with it withdrawn: keep independent coverage where the latter fails and keep the old capacity until acceptance. *New:* Compilation can produce both an executable obligation and an explicit account of which recovery claims depend on the checker surviving. *First test:* Compare eviction without recovery, a skill library without eviction, and a verified compiler-driven round trip on synthetic rules with a complete and an incomplete artifact.

**CPX6. Reconcile checker edits without restoring a stale rule or hiding its maintenance cost.** Parts: L8W16 factored check registry, L8W18 shifted-input recovery, L8W21 inadvertent re-learning, L8W24 description-length gate, L8W25 human-edited check resync, L8W26 falsification suite, L7W05 version coherence, LW10 interface contracts, CR29 versioned recovery. *Mechanism:* Version the checker and key together, and require independently approved behavior changes before syncing a key. Audit shifted cases and incidental relearning without masking new valid requirements. Factor verified overlapping checks, charging upkeep and duplicated coverage; refuse automatic key reuse after an incompatible edit. *New:* Compiled skills become maintainable after human edits rather than silently drifting into stale code, duplicate weights or both. *First test:* Run a harmless sequence of schema revisions, independent rule corrections and new tasks. Compare append-only checks, static replay and checked resynchronization at matched service, internal bytes and external maintenance.

**CPX7. Move a verified rule out of the learner without giving up the ability to correct or recover it.** Parts: L8W01 executable-oracle queries, L8W04 rank-one key, L8W06 boundary-targeted probes, L8W09 byte crossover, L7W04 external payload, D5-13 update versus read, L8W02 recovery alignment, L8W03 shared delta decoder, L8W07 key rotation, L6W12 co-rotated wake, D4-04 native update metric, D3-09 witness identity, L8W05 deterministic core and residual, L8W11 equivalence gate, L8W12 compilable training, L8W13 partial extraction, L8W14 shared-feature partition, L7W07 compile and evict, D3-12 dependency frame, L8W08 combined recovery keys, L8W10 subspace reinitialization, L8W15 interference-based scheduling, L8W17 update-matched audit, L8W23 joint removal, L4W10 cost in effective dimensions, L6W13 joint recovery, L8W19 compile-evict cycle, L8W20 compiler-emitted keys, L8W22 scratch round trip, L4W21 release after verification, LM26 capability handshake, D5-26 response sketch, L8W16 factored check registry, L8W18 shifted-input recovery, L8W21 inadvertent re-learning, L8W24 description-length gate, L8W25 human-edited check resync, L8W26 falsification suite, L7W05 version coherence, LW10 interface contracts, CR29 versioned recovery. *Mechanism:* Compile supported behavior into versioned external checks, retain a bounded recovery key, and verify both true plasticity gains and old obligations after eviction. Distinguish live-oracle rebuilding from independent outage recovery. Recheck scope after rule edits and restore only what is valid in the current world. *New:* A cross-pool compile-and-evict cycle can price external maintenance, recovery dependencies and editability instead of counting offloaded weights as a free gain. *First test:* Use harmless synthetic rule streams with varying rule entropy, partial compilability, representation drift and checker outages. Compare byte-matched replay, stored rule text, tool-library creation without eviction and eviction without a tool, measuring both retention and later learning.
