# Flood: continual-learning primitives (new objects and operations on learning itself)

Raw, unfiltered ideas. Bar: each one is a new object or operation that a family of methods could be built on, the way weight-space programming made weights a data type. Nothing is pre-killed; each entry is marked *ambitious but doable* by default, and lists the nearest prior art I found so the reviewer can rank on novelty. Screened against `reviews/idea-ledger.md` (PR #6) and `ideas/flood/programs-weights.md`; where an idea touches a killed one, the difference is stated.

Already-covered directions found while screening (not re-proposed here): task-vector transport across base versions (2602.12952, 2510.09658, 2605.28444, 2503.20110, 2610.32581), CRDT model merging (2605.19373, MELD 2608.16357), LoRA-to-text decompiling (2611.09454, DIT 2510.05092), reversible/exact-forgetting CL (2603.11239, 2505.12239, 2610.07197), write-time update covariance (2611.write-time-covariance…).

Each entry: **mechanism**, *why new*, **cheapest first test** (CPU unless noted). Memory or lesson tests carry the filler and temperature-matched arms by default.

## A. Time and versions as data types

**L1. Prompt-addressable checkpoints (a git log inside one set of weights).** Every update is trained with a version tag token (v1, v2, …) prefixed to its data, plus a light "as-of" consistency loss: under tag v_k, outputs on a probe set match the stored logits of checkpoint k. The deployed model then answers "as of v_k" by prompt, reproducing any past self without storing checkpoints; rollback, diff and bisect become prompt operations. *Why new:* temporal LMs tag facts with dates; this tags the whole model state, so version control is a capability of the model, not of the storage system. **Test:** GPT-2 small, 5 sequential tasks; KL(model | tag v_k, checkpoint k) on held-out inputs vs. untagged model and vs. a same-length random-tag control. Kill if as-of KL is not < 50% of untagged KL, or old-task accuracy under the past tag < 80% of checkpoint k's.

**L2. Weight bisect.** Given a regression in the current model, find the earliest update responsible by binary search over L1 tags (or over stored low-rank deltas) with only log2(N) evaluations, then revert just that update's subspace. *Why new:* `git bisect` for learned behavior; data attribution answers "which examples", bisect answers "which update", at O(log N) probes. **Test:** 32 sequential LoRA updates on GPT-2, plant one regression; bisect finds it in ≤ 5 evals, and reverting its delta recovers ≥ 90% of the lost behavior with < 1 pp damage to later updates, vs. TracIn-style attribution at equal compute.

**L3. Learning branches with fast-forward merges.** Maintain branches as tag-conditioned behaviors in one model (L1), and define merge as training the trunk tag to match branch outputs only on the branch's diff region (inputs where branch and trunk disagree). *Why new:* merge is defined on behavioral diffs, not weights, and conflicts are explicit as inputs where two branches disagree. **Test:** two branches from one trunk (two domains); diff-region merge vs. TIES and vs. distillation on all inputs at equal tokens; count conflicts surfaced vs. ground truth.

**L4. Undo log of opcodes.** Restrict every write to a library of invertible weight operations (rank-1 Householder reflections, invertible scalings of a column) so each update is a group element with an exact inverse; the model's history is a word in the group, and any update can be removed by conjugation even out of order. *Why new:* exact-unlearning work stores data or shards; here learning itself is restricted to a group so undo is algebraic. Differs from return-point adapters (killed: save/restore stack) because no state is saved. **Test:** MLP, 10 sequential tasks with Householder-only updates; capacity vs. ordinary SGD at equal steps, and error after removing task 3 out of order. Kill if Householder learning reaches < 80% of SGD accuracy.

**L5. Time-reversal symmetric training.** Train so that running the optimizer backward on the same data stream exactly recovers earlier weights (reversible integrators such as leapfrog with exact fixed-point arithmetic, Maclaurin 2015), making "unlearn the last day" an exact, data-free operation. *Why new:* reversible SGD was used for hypergradients, never as a CL undo primitive. **Test:** small MLP, fixed-point leapfrog SGD with momentum; reverse 1,000 steps and compare weights bitwise; cost overhead vs. checkpointing.

## B. Deferred, conditional and hypothetical learning

**D1. Deferred-commitment weights (learning before you know the label).** For ambiguous data, train K hypothesis branches into one model, each addressed by a branch code (a learned key vector), sharing all other parameters. When the delayed label arrives, a 1-bit "collapse" selects the branch: the winning branch code is folded into the base and the losers are deleted, with no retraining. *Why new:* superposition of models (1902.05522) and supermasks store tasks; label-delay CL waits. This stores competing hypotheses about the same data and resolves them later. **Test:** synthetic fact stream where 30% of facts arrive with 2-way ambiguous labels resolved 200 steps later; compare to storing the raw examples and training after resolution (same final compute). Kill if collapse accuracy is < 90% of train-after-resolution or storage is not ≤ 20% of the raw buffer.

**D2. Gradient IOUs.** For an unlabeled or delayed example, store a compressed gradient for each candidate label (a K-way gradient table, sketched to r dims); when the label arrives, apply the right column, corrected to the current weights by a stored Jacobian-vector sketch. *Why new:* an IOU is a promise of a future update with its own staleness correction; label-delay methods replay data instead. **Test:** split-MNIST stream with labels delayed 500 steps; IOU apply vs. replay of stored inputs at matched bytes.

**D3. Hypothetical fine-tuning as a query.** A trained "update simulator" head answers: "if I were fine-tuned on X, what would my answer to Y be?" without performing the update; trained on (X, Y, post-update answer) triples generated by actually fine-tuning a small proxy. *Why new:* makes the counterfactual update a queryable operation for planning what to learn. Forecast-forgetting (killed #16) predicted aggregate forgetting from first-order math; this learns the post-update function directly. **Test:** GPT-2 small, 500 tiny fine-tunes; simulator accuracy on held-out (X, Y) vs. first-order influence and vs. in-context "pretend you learned X".

**D4. Conditional updates (if-then weights) triggered by internal state.** An update is stored as (trigger direction in the residual stream, delta) and fires only when the trigger activates; the trigger is learned as the minimal-description condition that separates the update's inputs. Programs over weights get branching. *Why new:* GRACE/WISE route by key matching on inputs; here the condition is a learned internal predicate that can be composed (AND/OR of triggers). **Test:** 20 facts with overlapping conditions on GPT-2; composed trigger accuracy vs. GRACE codebook at equal parameters.

**D5. Learning with a safe word.** Each update is trained jointly with an anti-update: a second delta that, when added, restores pre-update behavior on the update's footprint. Anti-updates are tiny (they only cancel the footprint) and can be shipped to revoke a skill. *Why new:* revocable skills without retraining or storing checkpoints. **Test:** 10 LoRA skills; anti-update size and revocation fidelity vs. task negation (−ΔW) at equal rank.

## C. Moving learning between substrates

**S1. Memory relocation (virtual memory for learned behavior).** One address space spans context text, layer-k LoRA, and a tool; a "move" op relocates a learned behavior between addresses while holding its effect fixed (matched absorption), so a system can page lessons in and out. Builds on MX1 (PASS): if the route sets in-context overridability, relocation becomes the knob that makes a lesson editable (move shallow) or locked (move deep). *Why new:* context distillation and LoRA-to-text are one-way conversions; this is a relocation op with an invariance guarantee and a side effect it predicts. **Test:** MX1's world; relocate 10 lessons layer 8 → last blocks → text and back; behavior drift < 2 pp and directive shift follows the destination as MX1 measured. Kill if a round trip loses > 5 pp.

**S2. Carrier data (send a skill through innocuous text).** Given a skill delta ΔW in a teacher, search for a carrier dataset drawn from unrelated text whose fine-tuning gradient on a student with shared init reproduces ΔW (subliminal learning 2507.14805 shows traits transmit; this makes it a designed channel). Uses: replay without storing old data, private skill transfer. *Why new:* subliminal transmission was observed as a risk; here it is an encoding operation with a measurable rate (bits of skill per token). Differs from counter-gradient data (#10 killed) by requiring the carrier to be unrelated text. **Test:** GPT-2 small, a toy skill; greedy carrier selection from WikiText by gradient alignment vs. GradMatch on skill data. Kill if carriers transmit < 30% of the skill at 10× the tokens.

**S3. Skill rate-distortion curves as an object.** For any learned skill, measure the curve of retained behavior vs. bits of storage across substrates (text, KV, LoRA rank r, carrier data). The curve, not the skill, is what systems trade, enabling a "memory market" that buys the cheapest substrate for a target fidelity. *Why new:* an exchange rate between memory substrates. **Test:** 10 skills × 4 substrates on Qwen 0.5B; are curves consistent across skills (ranking stable)? Kill if per-skill rankings are no better than random.

**S4. Lesson ↔ weight round-trip invariants.** Define a lesson's canonical form as the fixed point of text → LoRA → text (distill, then decompile with 2611.09454-style recovery). Lessons that are not fixed points are lossy; their round-trip residue says what text cannot carry. *Why new:* a fixed-point definition of "what a lesson is". **Test:** 20 lessons; iterate the round trip 3 times; measure convergence of behavior; residue vs. lesson length control.

**S5. Activation cassettes.** Store an episode as the residual-stream deltas it induced at a few layers (a "cassette"); replay = injecting the cassette during training on unrelated inputs to restore the skill, with no tokens stored. *Why new:* replay in activation space keyed to the model's own representation; generative replay replays inputs. **Test:** split tasks on GPT-2; cassette replay vs. raw replay at matched bytes.

## D. Learning operators with algebraic structure

**O1. Idempotent learning (learn(x) ∘ learn(x) = learn(x)).** Train a write operator (a small hypernetwork from data to delta) with an idempotence loss, so seeing the same lesson twice changes nothing the second time. Fleet sync and double dosing become safe by construction. *Why new:* double dosing failed to oscillate in pilot, but idempotence as a designed property of the learner (not of merge) is untested. **Test:** fact stream with 30% repeats; idempotent writer vs. plain fine-tune on repeat-induced drift and over-confidence, vs. dedup-by-hash.

**O2. Commutative learning operators.** Train the write operator so learn(a) then learn(b) equals learn(b) then learn(a) on a probe set (commutator loss on pairs). Order invariance makes distributed, asynchronous CL exact. *Why new:* bounded-delay scheduling (killed) reordered within a window; this learns an operator whose commutator is near zero globally. **Test:** hypernetwork writer on a synthetic fact world; commutator norm and accuracy vs. ordinary SGD and vs. gradient accumulation.

**O3. Learning-operator inverses (a learned "unlearner" paired to every learner).** Train a pair (write, erase) so erase(write(θ, x), x) = θ on behavior, then erase works on new x zero-shot. *Why new:* unlearning methods are separate optimizations per request; here erase is a trained operator, the algebraic inverse of the learner. **Test:** 500 synthetic facts; erase on held-out facts; relearning-attack resistance vs. gradient ascent.

**O4. Update kernels (learning as convolution).** Characterize a model by its response to a canonical micro-update at every location (a learning impulse response); any update's effect is predicted by convolving its gradient with the response. Then nonlinear deviations from this kernel are the object of study. *Why new:* a linear-response "transfer function" of the learner as a per-model artifact. Reviewer warning: the linear part is first-order; the claim to test is that the nonlinear residual is low-dimensional and predicts interference. **Test:** MLP; is the residual of the kernel prediction captured by ≤ 5 components across 100 updates? Kill if not.

**O5. Update hashing and deduplication.** A locality-sensitive hash of updates in function space (sign pattern of the update's effect on a fixed probe set) lets a fleet detect "I already learned this" before applying it. *Why new:* content-addressed learning, like git object hashes for skills. **Test:** 200 LoRAs (some near-duplicates); hash recall of duplicates vs. weight cosine.

**O6. Interference as a measurable inner product, exposed as an API.** Every stored skill exposes a function `interfere(Δ)` returning predicted damage, computed by the skill itself from a stored second-order sketch; the scheduler negotiates updates with skills. *Why new:* skills as active agents that veto updates. **Test:** 10 skills; veto policy vs. GEM on forgetting at equal compute.

## E. Weights that carry metadata

**M1. Provenance channels.** Train with an auxiliary output head that predicts, for any generated token, which update (or data source) produced the behavior; training labels come from L1-style tags. At inference, every answer carries its provenance. *Why new:* attribution is usually post hoc and expensive; here it is a trained capability. **Test:** 5 sources fine-tuned sequentially into GPT-2; provenance-head accuracy vs. TracIn at 1/1000 the cost.

**M2. Confidence ledgers in weights.** Each update writes a calibrated confidence alongside its content (an extra scalar head per update), so the model can later say "I learned this from one example" and down-weight it. *Why new:* uncertainty about what was learned, not about the input. **Test:** facts learned from 1 vs. 10 examples; does the ledger head separate them (AUC ≥ 0.8) vs. output entropy?

**M3. Plasticity tokens.** Data carries learned control tokens (<keep>, <draft>, <volatile>) that the model has been meta-trained to obey during later fine-tuning: <volatile> examples change weights only in a fast-decaying subspace. *Why new:* learning metadata expressed in the data itself and honored by the learner, so the data owner controls retention. **Test:** meta-train on GPT-2 small; does <volatile> content decay ≥ 3× faster under later training than <keep> content at matched initial accuracy?

**M4. Self-describing deltas.** Every LoRA is trained to also emit, when given a reserved prompt, a natural-language description and a test set for itself (the delta carries its own manifest). Library management becomes reading manifests. *Why new:* the manifest lives in the delta, not in an external registry, so it survives merging and transport. **Test:** 20 LoRAs; manifest accuracy (tests pass on own delta, fail on others) vs. external DIT-style describer.

## F. Agents and fleets

**A1. Experience as a tradeable asset with a price.** Agents in a fleet post lessons to an internal market; price = measured lift on the buyer's own tasks (paid in compute budget). Prices aggregate distributed evidence about lesson value. *Why new:* surprisingly-popular voting (killed) asked agents to predict; a market makes them pay for wrong lessons. **Test:** 10 agents, 40 lessons, synthetic tasks; does price rank correlate with true lift (Spearman ≥ 0.6) vs. upvote counts at equal evaluations?

**A2. Testaments for successors.** Before a model upgrade, the old agent writes an artifact (lessons, tests, hard cases) optimized for how fast the successor learns from it, measured on a proxy successor. *Why new:* transfer artifact optimized for the learner, not the content. **Test:** Qwen 0.5B → 1.5B on a rule world; optimized testament vs. dump of all lessons at equal tokens.

**A3. Self-play with past selves as a curriculum (frozen-ancestor opponents for forgetting).** The agent continually plays against its own L1-tagged past versions on old tasks; losing to an ancestor is a forgetting alarm and a training signal. *Why new:* uses the ancestor as an adversary rather than a distillation teacher. **Test:** synthetic game with drift; ancestor-play vs. replay at equal episodes on old-regime win rate.

**A4. Memory immune system.** Lessons carry antigen signatures (failure fingerprints); an immune memory of past bad lessons rejects new lessons with similar signatures. *Why new:* negative memory of bad lessons, rather than positive memory of good ones. **Test:** inject 20% harmful lessons in a stream; rejection precision vs. a judge LLM at equal calls.

**A5. Forkable agents with merge-back.** An agent forks into K variants with different memory policies for a window, then merges back by keeping the memory of the fork whose behavior was best on a shared probe set (branch and bound over memory policies at deployment). *Why new:* evolutionary search over the memory state itself during deployment. **Test:** 3 forks × 5 windows; vs. single agent at equal episodes.

## G. Wild cards

**W1. Dream-erase.** Between tasks, sample the model's own high-temperature "dreams" and apply small gradient ascent on them (Crick–Mitchison unlearning) to remove spurious attractors and free capacity for new facts. Hopfield results show capacity gains (2603.09384); untested in LMs. **Test:** GPT-2 small fact stream; dream-ascent vs. random-text ascent and vs. weight decay at equal steps on new-fact capacity and old retention.

**W2. Forgetting curves as a fingerprint of the training data.** The shape of a model's forgetting curve under a standard perturbation identifies what it was trained on, enabling detection of unseen fine-tunes. *Test:* 20 fine-tunes; classify source domain from forgetting curves vs. weight-diff features.

**W3. Learning-rate schedules as messages.** Two models share a skill by exchanging only an LR schedule over a shared public data stream: the receiver's schedule makes it learn the sender's skill from public data. *Test:* shared init, public WikiText stream; per-step LR search reproduces a skill delta at what fraction?

**W4. Negative examples from the future.** Train on data the model will see later, with gradient sign flipped, to pre-reserve capacity (an "inoculation slot") so later learning of that data lands in a protected subspace. *Test:* split tasks; pre-inoculated subspace vs. random pre-allocation on later forgetting.

**W5. Weight tides.** Make all weights oscillate slowly (a global periodic modulation of LoRA gains) and store tasks at different phases, reading a task by choosing the phase. Superposition by phase (1902.05522 uses fixed keys; this uses a continuous phase that drifts, so old tasks come back on schedule, like spaced repetition built into the weights). *Test:* 10 tasks; retention vs. superposition-with-keys at equal parameters.

**W6. Learning with a body double.** Keep a tiny proxy model whose learning dynamics are fit to the big model's (matched per-update behavior change on probes); trial-run every candidate update on the double first. Different from forecast forgetting (killed) because the double is itself trained to match post-update behavior, not computed from first-order math. *Test:* GPT-2 small as big, 2-layer as double; does the double rank 50 candidate updates by real forgetting at ρ ≥ 0.6?
