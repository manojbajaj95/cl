**LCX1. Renew an opposed witness through a real learner step.** Parts: D4-01 differential trunk drift, D4-04 optimizer-metric pivot, D4-05 ordinary lesson initialization, D4-07 retained teaching gradient, D3-01 certified pivot, IP20 changed optimizer. *Mechanism:* When a trunk change erases one representation of an admissible world, fit a small candidate correction to the difference between the two worlds' observed effects. Validate it by taking the actual optimizer step on fresh authorized evidence in scratch state. Check both signs and old constraints; if repair fails, report lost representation rather than treating the opposite world as proven. *New:* A repair object preserves how to relearn a side under the native update, not a snapshot of its previous head or a Euclidean direction. *First test:* Use matched frozen and online trunks in a finite ReLU fit, swap optimizer preconditioning, and give both the same permitted examples. Compare exact refit, cached gradients, and a verified actual-step repair.

**LCX2. Reopen a feature only when its learned response restores the missing sign.** Parts: D4-02 activation boundary, D4-03 repair dictionary, D4-06 functionally matched feature, D4-08 one-factor unsharing, D4-09 conditional gradient variance, L4-12 input-factor repair, D2-11 opposed worlds. *Mechanism:* Use held-out interventions to decide whether a dormant unit, an existing dictionary atom or one unshared factor restores a missing response to the next authorized example. Compare current service at equal outputs; a variance-derived direction counts only if its realized updates repeatedly satisfy the old evidence and response floors. *New:* A feature can be retained for a useful future update even when its current activation contributes nothing to the service score. *First test:* Enumerate a quantized low-rank toy with an inactive unit, matched answers, and zero mean but unequal conditional repair success. Compare a best signed spare, full factor split and constrained dictionary reuse.

**LCX3. Treat optimizer state and normalization as real writers in a joint update.** Parts: D4-11 mixed update term, D4-12 second-moment collision, D4-17 normalization as writer, IP19 multi-writer response, SD2-05 third-edit blocker, L3-22 jointly callable ports. *Mechanism:* Execute each training request separately and jointly in scratch state, preserving the actual update order and state. Isolate a mixed term by selectively substituting moment or normalization state for diagnosis, then test whether a lawful repair preserves both new effects and a third old correction. Do not approve from a state reset alone. *New:* Two writers may be safe on the weight surface but collide in state that matters only to the next lesson. *First test:* Construct equal final weights with distinct moment or normalization trajectories. Match old scores and new-task gain; compare weight-only checks, state interventions, and exact prospective joint simulation.

**LCX4. Block only the pair that teaches away the deciding report.** Parts: D4-13 router coalescence, D4-14 shared nuisance feature, D4-15 report saturation, D4-18 student compression, D3-15 joint blocker, DF28 diagnostic blind spot. *Mechanism:* Track paired reports through actual router and student retraining. Require that either writer alone preserves an informative observable contrast, while training them together collapses it through a verified component. Include a teacher or frozen export that retains all routes to rule out a purely static conflict. *New:* A learned joint blocker can expose a diagnostic lost to shared compression even when the nominal reporting actions remain available. *First test:* Use matched teachers with a shared latent bottleneck, plus an equal-loss student that keeps both reports. Compare frozen route checks, held-out pair testing, and full joint retraining.

**LCX5. Keep a second source of evidence when training changes what will be seen.** Parts: D4-16 training distribution cycle, D4-19 capacity reallocation, D4-20 next example becomes uninformative, CE4-23 exposure denominators, D3-18 diagnostic slack, DF16 migration bridge. *Mechanism:* Check how one writer changes the other's sampler and available features. Require a permitted comparison that remains observable and produces distinguishable native updates after both writes. Record lost access and uninformative access separately; propose an alternative only where it has independent support. *New:* A report may still be elicitable but no longer teach opposite corrections once the jointly trained representation consumes its distinguishing coordinates. *First test:* In a synthetic two-writer stream vary exposure and pruning independently. Compare fixed replay, route preservation without a gradient check, and actual next-example utility, with a matched static export.

**LCX6. Distinguish new evidence from a change in what the model can express.** Parts: D4-10 evidence versus learning death, D4-21 pivot releases blocker, D4-22 replacement report feature, D4-23 same-scope cross-version evidence, D3-22 shared failure trace, CE3-17 exercise assumptions. *Mechanism:* Cross evidence-only and update-only interventions. If the evidence still permits both worlds, try a verified pivot and train the smallest report feature that distinguishes their revised predictions. Check legality again after another version change on the same scope; never infer transport to another user from version stability. *New:* One local witness repair can also restore a joint diagnostic without pretending the valid world set changed with the representation. *First test:* Run a two-by-two exact toy with evidence refutation versus representational loss and route failure versus survival. Compare full re-solving, a static witness repair, and paired native-update repairs with the same budget.

**LCX7. Keep a counterexample that prevents an overbroad veto on future writers.** Parts: D4-24 actual peer update transport, D4-25 shared plastic subspace, D4-26 counterexample to blocker, L4-25 preserve a failure witness, D3-19 checked abstraction, CR24 bounded impossibility. *Mechanism:* Propagate candidate repairs through the peer's actual update and test the space that remains plastic under both requests. If no repair exists, name the bounded update and observation class actually ruled out. *New:* An admission contract can learn when static similarity hides safe training, reducing repeated unnecessary vetoes. *First test:* Use two equal-score peer edits that move features identically on today's cases but have different next gradients. Compare exact paired training, static effect filters and a counterexample-refined policy.
