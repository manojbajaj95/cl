# Cross-pool merges, round 15

Focal sources: `tree/breadth-outside-edit-theory.md` (PR #115, BI#) and `tree/differential-fork-registers.md` (PR #114, DF#). Main crossings are with programs and weights (#39, P#), NOOA (#41, N#), learning primitives (#42, M#), self-modification (#43, SM#), physics and math (#44, PH#), economics (#45, E#), neuro-inspired learning (#46, NB#), CL-bench (#48, B#), forward-only and RL (#50–51, FO#/RL#), coding (#56, IC#), control (#74, CD#), composable forks (#79, CF#), and rounds 1–8. The interface can change in four places: symbols, architecture, population, and the source of training evidence. Fixed fork probes can measure learning responses, but they do not establish a new read channel unless matched forward and one-step controls fail. These are raw and unfiltered.

**BR1. Make a new token prove it is a cache, not a new meaning.** Parts: BI1 partition conservation, BI2 segmentation anchors, BI3 memoized computation, P19 stable ABI (PR #39), N6 signature hashing (PR #41), Q5. *Mechanism:* Expose the tokenizer as a compiler with an executable byte-level reference. Add a merged token first as an optional fast path, then admit it only if paired segmentations preserve next-byte probabilities and the old command on protected contexts. Reserve or rebalance the added output mass separately so matching internal states cannot hide a changed softmax. *New:* Vocabulary growth can accelerate computation without silently changing either the language contract or the confidence on old strings. *First test:* In the PR #115 softmax toy, add short byte strings with two legal parses. Compare a cache plus partition guard against frozen rows, a separate head, and either guard alone at matched new-token accuracy.

**BR2. Grow a circuit that has to pass a driving test after the next lesson.** Parts: BI6 gradient-preserving growth, BI7 probationary coupling, DF3 train-versus-apply, CD4 input shaping (PR #74), NB03 compartment veto (PR #46), Q7. *Mechanism:* Install an output-neutral branch on probation. Run two fixed payload-blind lesson sequences on copies: actual updates and matched cached steps. Permit backward coupling only if the branch survives the real continuation and the old branch retains its control response. Re-test after changing the loss, where an insertion-time Jacobian tie need not hold. *New:* Growth has a qualification for how it learns, not just a function-preserving initializer or a check on the first gradient. *First test:* Widen a two-layer MLP with cancelling clones; vary lesson order. Compare retention and new-task progress against Net2Net-style growth, fixed probation and an insertion-only NTK match.

**BR3. Split a word only when its two meanings learn differently.** Parts: BI4 token mitosis, BI5 tombstones, DF6 public-example substitution, P8 refinement types (PR #39), N9 contract tightening (PR #41), SM21 mutable tokenizer (PR #43). *Mechanism:* For a shared token with conflicting roles, construct fixed, held-out public curricula by use type and split the token only when the resulting learning responses disagree persistently. Preserve the unsplit byte-level meaning for ambiguous contexts and train the routing rule separately from the new token rows. *New:* Uses future response to decide which interface symbol to create; a cluster in the current embedding is not enough. *First test:* Generate a grammar where two senses share spelling and some contexts, plus a frequency-only bimodal control. Compare split decisions, next-byte accuracy, and old usage against gradient clustering, frequency splitting and a fixed tokenizer.

**BR4. Let a new architecture inherit a contract it can re-derive, not a transcript it can mimic.** Parts: BI8 birth depth, BI10 succession contracts, DF5 matched forward limit, DF11 cross-bank copy, E18 succession exams (PR #45), N1 round-trip consolidation (PR #41), X10. *Mechanism:* Expose each old skill through an executable reference and a small public curriculum bank. A successor can replace an old depth exit with a new implementation only if both its current answers and its response to held-out rule variations match the contract; compare against a same-input forward transcript before claiming extra fork value. *New:* A migration test can catch a successor that distilled an old answer but learns the wrong generalization when that skill is revised. *First test:* Move a tiny stack-language interpreter from an MLP to a recurrent reader. Compare transcript distillation, executable refitting, and the combined gate on old programs and revisions drawn from a held-out grammar.

**BR5. Route a skill to the fleet that can cover it after a shared failure.** Parts: BI11 adapter ABI, BI12 population erasure codes, BI15 contagion tracing, IC2 fountain-coded skills (PR #56), E10 insurance pools (PR #45), CF3 coupling sketches (PR #79), X8. *Mechanism:* Register private adapter ports and keep redundancy across clients selected for failure diversity under common base updates. Route by a charged, current availability check. If one update disables all holders through the same port, count one correlated failure mode and fund an independent carrier rather than more replicas on that port. *New:* Population retention is a joint coverage problem under shared training shocks; copies with the same weakness need not buy reliability. *First test:* Simulate a trunk with six private readers and planted correlated failures. Compare routed retention and memory to uniform replication, an independent full base, and marginal-failure allocation.

**BR6. Trade base-update headroom without making small clients invisible.** Parts: BI11 adapter ABI, BI15 contagion tracing, BI24 interface budgets, E14 commons governance (PR #45), E15 gradient taxes (PR #45), B16 channel attribution (PR #48), Q6. *Mechanism:* Give deployed adapters individually testable activation contracts. Have base-update proposals declare which protected ports they would spend, and require paired client-local measurements to settle the charge. Reallocate unused slack, but block transfers that leave a client below its non-tradable floor. *New:* A shared-base update can pay for verified interference instead of treating a small adapter's regression as negligible in fleet averages. *First test:* In a three-client affine trunk, plant a small client uniquely sensitive to one direction. Compare protected clients, new-task gain and audit cost against mean-distillation, worst-client projection and a uniform per-client cap.

**BR7. Distinguish a model that forgot from a model that stopped receiving questions.** Parts: BI16 propensity ledger, BI17 silence, BI18 retention exploration, B8 intervention budgets (PR #48), B22 stateless twin (PR #48), RL3 verifier twins (PR #51), Z9. *Mechanism:* Use a controlled exposure stream that leaves a small, logged probability of seeing underrepresented contexts and compare its outcomes with an exogenous stateless twin. Split silent regions into known skill loss, lack of evidence, and exogenous disappearance. Where support is zero, buy a legal observation or abstain; no weighting can recover the missing labels. *New:* Exposure is an experimental instrument for model-caused forgetting, not just a covariate in a replay sampler. *First test:* Extend the PR #115 user-return simulator with an exogenously vanishing region and a region that vanishes only under a bad deployed answer. Match the label budget against random coverage, inverse propensity alone, and a fixed audit.

**BR8. Learn from the user's correction without training on your own echo.** Parts: BI20 echo accounting, BI16 propensity ledger, M1 provenance (PR #42), SM10 disagreement frontier (PR #43), RL2 teacher as experimenter (PR #51), CF1 clause-indexed forks (PR #79). *Mechanism:* Trace which pieces of returned traffic quote the model and which supply new evidence. Run paired public continuations that hold the quote fixed while varying the independently verified correction; update only the verifier clauses whose improvement depends on the correction. Keep explicit uncertainty about paraphrases without reliable ancestry. *New:* Separates genuine correction from apparent confirmation inside feedback the learner helped generate. *First test:* Simulate dialogues with copied answers, paraphrases and verified corrections. Match training examples against deduplication, all-traffic self-training and correction-only learning without clause attribution.

**BR9. Make a longer context window prove where its new evidence starts.** Parts: BI21 context extension, BI23 modality conservation, DF20 semantic collisions, FO3 orthogonal question barcodes (PR #50), N7 contract replay (PR #41), CD20 reference governor (PR #74). *Mechanism:* Pair every extension-relevant probe with a second probe in which the added context or modality is rigorously uninformative. Gate learning from the extension on selective gain in the informative twin and stable decisions on its short reference. Generate withheld twins after installation so a writer cannot rely on a fixed canary list. *New:* Distinguishes a genuinely useful extra input from confidence changes or a brittle shortcut caused by having a new input port. *First test:* Give a small sequence classifier long-range hints that are sometimes useful and sometimes random. Compare twin gating with short-logit matching, a separate route, and ordinary mixed-length training.

**BR10. Use deployment replicas as experimental arms, not just spare teachers.** Parts: BI13 staggered replicas, BI14 diversity reservoir, BI17 silence, DF19 transplant calibration, PH3 objective continuation (PR #44), E16 staggered committees (PR #45), RL1 executable fork tapes (PR #51), Y5. *Mechanism:* Choose lags and public exposure probes before deployment. Use replica disagreement after a shared update to test which of two explanations fits: the new environment invalidated an old rule, or the rollout itself suppressed its data. Route a skill to an old replica only when a public check supports the latter and the current world still accepts its answer. *New:* Staggering buys comparable evidence across rollout stages rather than an automatic preference for an older model. *First test:* In a synthetic returning-user fleet, introduce one global rule change and one regression driven by the newest agent. Compare diagnosis and service against latest-only, oldest-as-teacher and randomly staggered copies.

**BR11. An interface-change compiler for a learner that no longer lives in one model.** Parts: BI1 output mass, BI2 segmentation, BI3 token caches, BI6 gradient-preserving growth, BI7 probation, BI10 succession, BI11 adapter ABI, BI12 population coverage, BI13 staggered replicas, BI15 interference tracing, BI16 exposure, BI18 exploration, BI20 echoes, BI21 context, BI23 modalities, BI24 interface budgets, DF3 train/apply, DF5 forward null, DF6 substitutions, DF11 response copying, P19 stable ABI, N7 contract replay, N9 tightening, NB03 branch veto, E10 pooling, E14 common budgets, IC2 coded skills, FO3 barcodes, RL2 experimental teachers, CF3 couplings, CD4 shaping, Q5, Q6, X8. *Mechanism:* Before a migration, name the conserved quantity separately for each interface: old-context output mass, response to future updates, client activation contracts, and continued opportunity to observe old slices. Test old and proposed interfaces on paired data and fixed payload-blind curricula; isolate unsupported changes on probation. When a local contract cannot be preserved, use a costed compatible route or declare a coverage gap rather than averaging it away. *New:* One migration protocol spans changing symbols, trainable capacity, populations and endogenous data without pretending that a single retention score covers them all. *First test:* Start with the separate PR #115 probes, then combine two interventions at a time: add a token and widen a network, or update a shared base and change traffic. Compare against the strongest individual guard and their equal-budget stack; isolate whether the combined gate finds failures neither guard alone exposes.
