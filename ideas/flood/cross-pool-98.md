Raw proposals for synthetic coupled systems and isolated tests.

**RCX1. Tell prevention apart from failures that disappeared from the report.** Parts: L2W01 matched shadow relaxation, L2W05 causal extinction, L2W07 avoidance censoring, L2W10 rehearsal leakage, LW29 frozen-world anchor, DF03 recommendation versus survey effect. *Mechanism:* Replay matched prefixes in an isolated copy with the old and new preventer, tracing abstention and rerouting separately from prevented outcomes. Require independent upstream evidence before retiring a failure family; mark unavailable counterfactuals unresolved, and never relax live safeguards for this comparison. *New:* The rehearsal ledger can distinguish reduced demand for recovery from lost observation without treating absence of reports as causal evidence. *First test:* Use a synthetic routing task with equal observed incident counts produced by prevention, deferral and upstream removal. Compare live frequency, unpaired replay and matched isolated contrasts.

**RCX2. Compress recovery drills only where the same lesson still repairs the failure.** Parts: L2W02 prevention-recovery interference, L2W03 near-miss boundaries, L2W04 recovery decay, L2W06 downstream starvation, L2W08 leak-through shifts, L2W09 shared recovery templates, LW02 prevention amnesia, D5-18 equivalent lesson, CE4-24 diagnostic power. *Mechanism:* Generate bounded simulated breach cases from near-misses at each relevant stage. Pool drills only after a held-out update demonstrates the same recovery without weakening prevention. Allocate rehearsal by measured recovery decay and check the post-prevention breach distribution, not just historic failures. *New:* An upstream improvement could make downstream rehearsal more selective without quietly removing the recovery directions it still needs. *First test:* Use a finite cascaded service simulator with two superficially similar recoveries and rare bypass events. Compare uniform replay, template compression and decay-aware drills at equal memory and update work.

**RCX3. Compare rollback and forward repair on the same reachable world.** Parts: L2W11 world-weight mismatch audit, L2W12 minimal assumption witness, L2W13 three-way repair choice, L2W14 reversible world diff, L2W15 read-only dry run, LW03 hysteretic rollback, D3-20 observable return. *Mechanism:* Record the observable tool and state assumptions required by the old model. In a shadow copy compare plain restore, a compatible world shim, and forward repair, charging each for actual service and recovery. Mark unobserved consequences and irreversible changes explicitly rather than granting rollback from a successful dry run alone. *New:* The old checkpoint is a candidate for the current world, not an automatic return to past safety. *First test:* Build a mock interface migration with an irreversible capability change and a reversible wrapper edit. Compare full state restore, stored assumptions alone and verified three-way triage.

**RCX4. Restore a narrow slice without undoing what the world now relies on.** Parts: L2W16 multi-step shims, L2W18 selective rollback, L2W19 rebound after reversal, L2W20 failure tombstones, L4-27 scoped readmission, SD2-05 later edit breaks a swap. *Mechanism:* Enumerate admissible orders for the narrow rollback and its dependent shims. Test preserved slices through a declared world response delay, and retain a versioned witness for the failed update so it is not immediately relearned. Reject a shim pair if each is safe alone but together loses a current dependency. *New:* A local rollback can preserve a useful adaptation and its users' resulting expectations without turning the original failure into a global or permanent veto. *First test:* Use a toy workflow with three changes and delayed responses, where reverting one output can break an unrelated route. Compare global revert, slice-only revert and verified shim plus tombstone.

**RCX5. Keep old safeguards in place until loss of the new preventer is manageable.** Parts: L2W17 two-phase world commit, L2W21 unsuppression shock, L2W22 withdrawn external guards, L2W26 suppression-aware probation, CE4-13 preserve another actor's opportunity, D5-03 verified reopening window. *Mechanism:* Before allowing dependent changes during probation, test preventer loss with and without the old external guards on an isolated model of current operations. Track who can restore each guard and whether that can occur before failure propagation. Defer guard retirement until a checked replacement or recovery is available. *New:* An update that reduces immediate failures would not be approved on the assumption that an independently supplied fallback will remain in place. *First test:* Simulate success-induced guard removal and an independent failure of the preventer. Compare fixed probation, checkpoint-only rollback and guard-aware staged admission.

**RCX6. Use one probe budget to route a failure to the right kind of recovery.** Parts: L2W23 current-world drills, L2W24 shared probe budget, L2W25 guided forward recovery, L2W27 crossed failure attribution, L2W28 unified admission gate, L3-27 feed failures into rehearsal, D3-26 separate obstruction types, CR24 scoped impossibility. *Mechanism:* Cross old and current conditions with policies that vary in recovery competence while holding service demands fixed. Use probes that distinguish world incompatibility from lost recovery, then test a forward repair that preserves prevention where rollback is blocked. If evidence is insufficient, name the untested assumption rather than allocating every remaining probe to the same candidate. *New:* A failure after rollback can teach the next simulator which dependency changed, without treating all such failures as proof that recovery was forgotten. *First test:* Enumerate a finite four-cell case with changed world assumptions and degraded recovery varied independently. Compare separate audit budgets, exhaustive tests and decision-sensitive allocation.

**RCX7. Prove that prevention leaves an effective recovery route in the world it changes.** Parts: L2W01 matched shadow relaxation, L2W05 causal extinction, L2W07 avoidance censoring, L2W10 rehearsal leakage, LW29 frozen-world anchor, DF03 recommendation versus survey effect, L2W02 prevention-recovery interference, L2W03 near-miss boundaries, L2W04 recovery decay, L2W06 downstream starvation, L2W08 leak-through shifts, L2W09 shared recovery templates, LW02 prevention amnesia, D5-18 equivalent lesson, CE4-24 diagnostic power, L2W11 world-weight mismatch audit, L2W12 minimal assumption witness, L2W13 three-way repair choice, L2W14 reversible world diff, L2W15 read-only dry run, LW03 hysteretic rollback, D3-20 observable return, L2W16 multi-step shims, L2W18 selective rollback, L2W19 rebound after reversal, L2W20 failure tombstones, L4-27 scoped readmission, SD2-05 later edit breaks a swap, L2W17 two-phase world commit, L2W21 unsuppression shock, L2W22 withdrawn external guards, L2W26 suppression-aware probation, CE4-13 preserve another actor's opportunity, D5-03 verified reopening window, L2W23 current-world drills, L2W24 shared probe budget, L2W25 guided forward recovery, L2W27 crossed failure attribution, L2W28 unified admission gate, L3-27 feed failures into rehearsal, D3-26 separate obstruction types, CR24 scoped impossibility. *Mechanism:* Maintain a causal suppression ledger and a checked current-world rollback certificate. Preserve recovery exercises for returning cases, test whether dropped safeguards make rollback unsafe, and compare scoped revert, compatible shims and forward repair before disturbing protected service. Reuse failure evidence only where the original causal premises still hold. *New:* Prevention and rollback become a joint obligation: improvements must not silently consume the recovery option they appear to make unnecessary. *First test:* Run bounded synthetic coupled systems with delayed guard withdrawal, selective censoring, hidden recovery decay and tool migration. Compare isolated replay plus ordinary rollback, independent audits and the joint policy at matched service and compute; score false retirements, failed recoveries and validation work.
