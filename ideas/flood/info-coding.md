# Flood: continual-learning ideas from information theory and coding

Raw pool for the novelty reviewer: 64 ideas, unfiltered and not literature-checked. Each gives the mechanism, why it might be new, and the cheapest first test with a retention check (old tasks still work). Near neighbours and ledger kills ([reviews/idea-ledger.md, PR #6](https://github.com/manojbajaj95/cl/pull/6)) are named in one clause where known, so the reviewer can judge the distance. Killed ideas on this angle that these try not to repeat: functional syndromes (coded key→value checks), coded/redundant memory fragments, MDL lesson scoring, the Landauer erasure budget, coded merge interference, and private memory shorthand (on the Moonshot shelf). Forward-only #3 (orthogonal question barcodes) is the nearest pool idea to the multiplexing section.

"Retention check" always means: re-score the old tasks after the new learning step, against the same model trained by plain fine-tuning (and replay where named) at equal compute.

## A. Weights as a channel code

**1. Weights as a systematic code with parity layers.** Split the network into "systematic" weights (the ones that compute) and "parity" weights that never run in the forward pass but are trained to satisfy linear constraints with the systematic ones (Hw = 0 over a learned sparse H). After a new-task update damages systematic weights, run belief-propagation decoding on H to restore the old-task component, treating new-task change as signal to keep and off-subspace change as noise. New because CL protects weights by penalty or freezing; here old knowledge is recoverable after damage by a decoder. Near: functional syndromes (killed, but those checked function outputs on MEMIT keys, not weight-space parity). First test: MLP on task A, add parity rows for one layer, fine-tune on B, decode, then briefly re-tune on B; retention = A accuracy versus EWC at equal parameter overhead.

**2. Erasure-coded skills across layers (fountain-coded adapters).** Store each skill as k LoRA "source blocks" encoded into n > k LT/Raptor-style droplets spread across layers; any k recovered droplets rebuild the skill. When later training overwrites some layers, the skill still decodes from the untouched ones. New because adapter libraries store each skill once in one place. First test: 4 skills on a small transformer, overwrite a random 30% of layers with new-task training, decode each skill from surviving droplets; retention versus storing 4 plain LoRAs at equal total rank.

**3. Interleaving against burst forgetting.** Forgetting is bursty: one new task hits a contiguous block of parameters (a layer, a head). Channel coding handles bursts with interleavers. Permute each skill's parameters across the network with a fixed interleaver so a burst hit on any layer becomes scattered small errors in every skill, which are then correctable (by idea 1, or by plain robustness). New because no CL method deliberately spreads one skill over many weights to convert bursts into random errors. First test: compare localized versus interleaved storage of a skill delta under a layer-local new task; retention of the old skill.

**4. Unequal error protection by task value.** Allocate redundancy (parity rank, replication, coding rate) per task in proportion to its measured value or query frequency, like UEP for video headers versus pixels. Forgetting becomes a rate-allocation problem with a solvable optimum. New because CL regularizers protect by sensitivity (Fisher), not by declared value. First test: 3 old tasks with weights 1:2:4, same parity budget, UEP versus uniform; retention weighted by value.

**5. Rateless skill memory.** The model keeps emitting more parity for important old skills over time, "rateless" style, whenever spare capacity appears (e.g. dormant units). Retention improves continuously with idle capacity, with no fixed protection decision. New because protection in CL is set at learning time. First test: allocate dormant units to parity for task A as they appear during B, C; retention curve versus fixed allocation.

**6. Weight-space LDPC with learned Tanner graph.** Learn H jointly with the weights so that the code's check nodes align with function-relevant directions, i.e. a code whose distance is measured in loss, not Hamming. New because codes are designed for symbol errors; here distance is functional. First test: two-layer net, learn H with a "decodes back to low old loss" objective; compare against random H.

**7. Fisher-weighted soft-decision decoding.** Use per-parameter Fisher information as the channel's log-likelihood ratios: high-Fisher weights are "reliable symbols". A decoder repairs low-reliability symbols from high-reliability ones after drift. New because Fisher is used only as a penalty weight (EWC), never as decoder soft information. First test: with idea 1's parity, compare hard versus Fisher-LLR decoding after fine-tuning; retention.

**8. Repetition code with majority vote across seeds (ensembled memory).** Keep three cheap low-rank copies of a skill in different subspaces; at inference take a median of their contributions. A new task corrupting one copy is outvoted. New mostly in the claim that a 3-copy repetition code beats one 3x-rank copy for retention. First test: equal-rank comparison under sequential tasks; retention.

## B. Rate-distortion and capacity

**9. Forgetting as an optimal rate-distortion operating point.** Treat the model as a channel with fixed capacity C bits; the stream asks for more. Choose what to forget by solving rate-distortion with a distortion = expected future-query loss, using a reverse water-filling over task "variances" (how often each task is queried). Prediction: tasks below the water level are forgotten entirely, not partially. New because CL treats forgetting as uniform erosion; this predicts a sharp all-or-nothing pattern and a level. First test: 10 tasks on a small MLP with a hard parameter budget, measure per-task retention and test whether a water level fits.

**10. Measured capacity of a model in "skill bits" with a channel-coding converse.** Define skill bits as the mutual information between task identity and outputs on a probe set, and measure how many bits a fine-tune adds and erases. Then check a converse: no method can hold more skill bits than the measured capacity. New as a capacity law per model, not per parameter count. Near: residual skill bits (killed for mask dependence; this uses output MI, which needs no mask). First test: GPT-2 small, N synthetic tasks, plot skill-bits held versus N for fine-tune, replay and LoRA; retention is the y-axis.

**11. Information bottleneck in update space.** Constrain each update ΔW so that I(ΔW; new data) is high but I(ΔW; old function) is low, estimated with a variational bound on probe outputs. New because IB is applied to representations, not to updates. First test: penalize KL between old and new output distribution conditional on a learned compression of ΔW; retention versus LwF.

**12. Successive refinement memory.** Store knowledge so it is "successively refinable": a coarse version in a small subspace and refinements in larger ones. Under capacity pressure the model drops refinements, keeping the coarse version of every old task instead of losing whole tasks. New because CL either keeps or loses a task; this makes graceful degradation a designed property (the opposite of idea 9's all-or-nothing; the pair is a test). First test: nested-rank LoRA (Matryoshka style) per task, then shrink rank under a new task; retention by rank.

**13. Lossy compression of the past with task-aware distortion (semantic replay codec).** Train a codec that compresses old training data to a tiny bitrate under a distortion defined by the model's own loss gradient, not pixels or tokens; replay decoded samples. New because generative replay reconstructs data; this reconstructs only what moves the weights. Near: dataset distillation and gradient matching. First test: 100 bytes per task codec versus random coreset of equal bytes; retention.

**14. Water-filling learning rates.** Give each eigendirection of the old-task Hessian a learning rate by water-filling: directions with low old-task curvature get more "power" for the new task. New in the explicit power allocation picture; near K-FAC projection methods. First test: spectral LR allocation versus OGD on two-task MLP; retention and new-task loss.

**15. Capacity-achieving order of tasks.** Ask which task order maximizes total stored bits, by analogy to successive interference cancellation, where decode order matters. Predict that learning the "strongest" task first and the weakest last maximizes the total. First test: 3 tasks, all 6 orders, measure total retained accuracy; check the predicted ranking.

## C. Source coding of experience (agents and models)

**16. Huffman-coded lesson stores.** Give each agent lesson a context-length budget inversely proportional to how often it fires (frequent lessons short, rare ones long), so expected prompt cost is minimized at fixed recall. New because lesson stores use uniform length or summarization. Must beat same-length filler and temperature-matched arms (ledger rule). First test: G1 router, 30 lessons, compute firing frequency, rewrite to Huffman-like lengths; retention = accuracy on old regimes at equal mean tokens.

**17. Arithmetic-coded memory in the model's own probabilities.** Store agent memory as an arithmetic-coded bitstream using the model's own next-token distribution as the probability model; decoding replays the text. Memory cost in bits equals the model's surprise, so updates to the model change memory cost (and can corrupt it). New because nobody measures agent memory in the model's own bits, and the coupling makes "model update breaks memory decode" a concrete CL failure. First test: encode 50 lessons with Qwen 0.5B, fine-tune the model on a new domain, decode with the new model; retention = exact decode rate; fix by storing a model version tag.

**18. Self-readable seed log as a compressed code (link to SM1).** Treat SM1's (seed, scale, reason) log as a source code for the weights and measure its rate: bits of log per bit of skill. New as a rate measurement for the top-3 candidate; gives SM1 a kill line (if the log needs as many bits as a LoRA, it is not a compression). First test: 1k seeded rank-1 steps on a small model versus LoRA of equal skill gain; count bits; retention after replaying the log on a newer base.

**19. Lempel-Ziv skill dictionary.** Grow a skill library like LZ78: each new skill is stored as a pointer to the longest existing skill prefix plus one new component. Old skills are never rewritten, only referenced. New because skill libraries store flat entries or trees by hand; LZ parsing gives an automatic, compression-optimal composition structure. First test: agent tool-macro library built LZ-style versus flat over a 100-task stream; retention = old-task success, plus library size.

**20. Universal-code prior over lessons (Solomonoff-weighted memory).** Weight each memory by 2^(−length of its shortest description under the current model). As the model improves, some lessons become short (absorbed) and drop weight automatically. Near: MDL lesson scoring (killed at proposal as covered), but here the code length is re-evaluated by every new model version, so it is a CL obsolescence signal. First test: measure lesson NLL under 0.5B then 1.5B; test whether low-NLL-under-new-model lessons are the ones whose removal costs nothing (retention).

**21. Distributed source coding for fleets (Slepian-Wolf memory).** Agents in a fleet hold correlated experience. Each sends only syndrome bits of its lessons; a receiver with its own correlated memory decodes the full lesson. Fleet memory sync then costs the conditional entropy, not the full entropy. New because fleet memory sharing sends full texts or embeddings. First test: two agents with overlapping lesson sets; syndromes from a learned hash; decode accuracy versus bits; retention of each agent's own lessons after merging.

**22. Wyner-Ziv consolidation.** Consolidating context into weights is "compression with decoder side information": the decoder (the model) already knows most of the lesson. Train the consolidation target to encode only what the model cannot predict (high-surprise tokens) and drop the rest. New because consolidation distills the full lesson. First test: LoRA consolidation of lessons with full-sequence loss versus surprise-only loss at equal steps; retention of old capabilities (lower risk since fewer tokens are trained).

**23. Entropy-coded replay buffer.** Keep replay data at a fixed byte budget compressed by the current model (as in idea 17). As the model learns, the same examples cost fewer bits, so the buffer grows automatically for well-learned tasks and shrinks for novel ones. Prediction: buffer composition tracks what the model already knows, so it should be biased toward hard examples when you pick by bits. First test: fixed-byte buffer with model-compressed storage versus raw; count stored examples and retention.

**24. Kolmogorov sufficient statistic of a task.** Split each task's data into a "structure" part (a short program/lesson) and a "noise" part (incompressible residual), Kolmogorov-structure-function style; consolidate only the structure into weights and store the noise externally. New as an explicit split rule for what goes in weights versus memory. First test: synthetic tasks with rule + exceptions; consolidate rule only; retention of old tasks and accuracy on exceptions via retrieval.

## D. Codes on activations and prompts (addressing and multiplexing)

**25. CDMA task multiplexing.** Give each task a spreading code (a ±1 sign pattern over hidden units); train the task by multiplying activations by its code. Tasks share every weight but are near-orthogonal in code space, and inference "despreads" with the task's code. New because superposition methods (PSP, Cheung 2019) use random rotations of weights; CDMA uses activation codes with known cross-correlation bounds (Gold codes), so interference is bounded in advance. First test: 10 permuted-MNIST tasks with Gold-code masks versus PSP; retention.

**26. Prompt-addressable checkpoints as a codebook (link to L1).** Make L1's tags codewords of an error-correcting code over tokens, so a slightly wrong or partial tag still retrieves the right past self, and the number of storable selves follows a sphere-packing bound. New: gives L1 a capacity law. First test: 16 checkpoints addressed by tags with Hamming distance 3 versus random tags; retrieval under 1-token corruption; retention of each past self.

**27. OFDM learning: frequency-division of tasks in the input spectrum.** Assign each task a band of input positional or spectral features; train with band-limited filters so updates for task B cannot touch task A's band. New because CL never separates tasks by signal frequency. First test: tasks defined on sinusoidal inputs in disjoint bands; band-restricted versus free MLP; retention. Then try token-position bands in a transformer.

**28. Spread-spectrum watermark lessons.** Encode a lesson as a low-amplitude spread-spectrum perturbation of the input embeddings across many tokens, decoded by the model's correlation with a key. Survives truncation and paraphrase of the prompt. New as a memory carrier robust to context editing. Near: soft prompts. First test: lesson as key-correlated embedding noise versus soft prompt; robustness to dropping 50% of tokens; retention.

**29. Superimposed codes for compositional skill calls.** Use a superimposed (Kautz-Singleton) code so that any OR of up to d skill codewords is uniquely decodable; activating several skills at once in one prompt token becomes unambiguous. New because skill routing picks one or uses soft mixtures without uniqueness guarantees. First test: 20 skills, 2-of-20 combinations via superimposed tags versus learned soft prompt mixture; accuracy and retention of single skills.

**30. Group-testing for "which memory broke."** After a model update, find which of N stored lessons or edits fail using O(d log N) pooled tests (prompts containing subsets), not N tests. Near: coded merge interference (killed: BOCS). Difference: this localizes post-update damage to individual memories, not merge interactions. First test: 200 edits, update, 40 pooled tests versus 200 single tests; localization accuracy; then repair only flagged edits and measure retention.

**31. Polar-coded attention heads.** Polarization makes some synthetic channels perfect and others useless. Apply a polar transform across attention heads during training so that some heads become "frozen bits" (perfectly reliable, used for old knowledge) and others become noisy (used for plastic learning). New: a principled reason for head specialization into stable and plastic sets. First test: small transformer with butterfly mixing across heads; measure head reliability split; freeze reliable heads after task A; retention.

**32. Lattice-quantized skill deltas.** Snap each skill update onto a lattice (E8 / Leech) in a low-dim subspace. Later updates add lattice-quantized deltas; drift smaller than half the packing radius is corrected by re-quantization. New because quantization in CL is for memory size, not error correction. First test: quantize LoRA A/B in 8-dim blocks to E8; add Gaussian drift from later training; re-snap; retention versus unquantized.

**33. Orthogonal tasks via Hadamard routing.** Use rows of a Hadamard matrix as per-task gain vectors on each layer's channels; exact orthogonality means the cross-talk between tasks' linear parts is zero. Near: idea 25 and PSP; difference is deterministic exact orthogonality and a hard limit of n tasks per n channels. First test: n = 64 channels, 8 tasks; retention versus random masks.

## E. Feedback, channels with memory, and ARQ

**34. ARQ for consolidation.** Consolidating a lesson into weights is a noisy transmission. After each consolidation, probe; if the lesson failed to "arrive" (probe fails), retransmit only that lesson (hybrid ARQ with incremental redundancy: paraphrases). New: retransmission with incremental redundancy as the consolidation loop, rather than fixed epochs. First test: 20 lessons consolidated by LoRA with ARQ versus fixed epochs at equal total steps; arrival rate and old-task retention.

**35. Feedback channel capacity: learner tells the teacher what it already knows.** With feedback, a sender can code more efficiently (Schalkwijk-Kailath). Let the student report its current posterior on a probe after each batch; the teacher sends only the residual (what the student got wrong, scaled). Prediction: error falls doubly exponentially in rounds instead of exponentially. New as a quantitative rate prediction for teacher-student CL. Near: active learning, OPSD. First test: linear regression student-teacher with posterior feedback versus without; then a tiny LM; retention of old regression tasks.

**36. Channels with memory: model update as a Gilbert-Elliott channel.** Model the effect of fine-tuning on stored knowledge as a two-state (good/bad) Markov channel over steps; estimate transition rates from probes and switch protection (replay rate) on when the hidden state is "bad". New because replay schedules are fixed or loss-triggered; this filters a hidden channel state. First test: estimate HMM on probe errors during a task stream; HMM-triggered replay versus fixed replay at equal replay count; retention.

**37. Interference alignment across tasks.** In multi-user channels, interference alignment packs all interference into half the dimensions at every receiver. Train new tasks so that their gradients' projection onto every old task's sensitive subspace falls into one shared "junk" subspace, leaving half the space interference-free for each old task. New because projection methods remove interference per old task, consuming dimensions linearly with tasks; alignment would consume half the space regardless of task count. First test: K tasks, linear model, compare capacity (tasks storable before failure) of OGD versus an alignment constraint.

**38. Dirty-paper coding for new tasks.** When the "interference" (old weights) is known to the encoder, Costa showed capacity equals that of no interference. Precode the new task's update with knowledge of the old weights so it lives "around" them rather than against them. Concretely: learn ΔW in a nested-lattice coordinate system defined by the old weights. New as a capacity statement: known old knowledge costs no capacity in principle. First test: linear toy with nested lattice precoding versus plain fine-tune; retention and new-task error.

**39. Broadcast-channel superposition coding for multi-skill adapters.** One adapter, two receivers: a "cloud" component decodable by all downstream tasks plus a "satellite" component only one task decodes. Learn the split by a superposition-coding loss. New: explicit common/private split with rate guarantees. Near: shared-private multitask. First test: two related tasks; cloud+satellite LoRA versus separate LoRAs at equal rank; retention of task A after task C uses only cloud.

## F. Hashing, sketches, and checksums

**40. Merkle-tree model state.** Hash each block's weights and each block's function on a probe set into a Merkle tree. After any update, comparing roots finds exactly which blocks changed function in O(log n) comparisons. Enables "content-addressed weights": a skill is identified by its function hash, so two training runs that learn the same skill dedupe. New as functional hashing (not byte hashing) for model state. First test: probe-function hashes with LSH tolerance on a small transformer; detect which layers changed after fine-tune; dedupe identical skills learned twice; retention unaffected (diagnostic).

**41. Count-min sketch of usage for forgetting decisions.** Keep a sketch of which hidden features fire for which inputs over the whole stream (constant memory). Forget (reinitialize) only features whose sketch count is low, like dormant-neuron reset but by long-run usage frequency instead of recent activation. Near: ReDo, continual backprop. First test: sketch-guided resets versus continual backprop on a plasticity benchmark; retention of old tasks.

**42. Bloom-filter "have I learned this?" gate.** Before writing a lesson or doing an update, check a Bloom filter of hashed semantic signatures of everything already learned; skip exact or near duplicates. Prevents double-dosing (ledger M3 killed for no overshoot, but duplication cost remains). First test: stream with 30% duplicates; Bloom gate versus none; retention and compute.

**43. Locality-sensitive hashing of gradients as task identity.** Hash each batch's gradient with SimHash; a change in hash bucket distribution signals a task boundary, enabling boundary-aware CL without labels. Near: task-free CL change detectors. First test: SimHash bucket drift as boundary detector on split-CIFAR; boundary F1, then use boundaries to trigger EWC consolidation; retention.

**44. CRC on behaviours.** Store a small set of "checksum prompts" whose outputs are a deterministic function (e.g. parity) of many stored facts; any single corrupted fact flips the checksum. Cheaper than testing every fact. Near: functional syndromes (killed). Difference: checksums are behavioural prompts for agents and LLM facts, not linear checks on keys; detection only. First test: 100 facts, 10 checksum prompts that require multi-fact reasoning; detection rate of single-fact corruption; retention diagnostic.

## G. Information measures as learning signals

**45. Mutual information budget per update (bits-per-step learning rate).** Set the step size so each update carries a fixed number of bits about the batch, measured as KL between the predictive distributions before and after on the batch. Large-surprise batches get capped. Prediction: retention is a function of total bits written, regardless of step count or LR. New because it gives a universal x-axis for forgetting. First test: vary LR and steps on a fine-tune; plot old-task loss versus bits written; test collapse onto one curve.

**46. Bits-back consolidation.** In bits-back coding, auxiliary random bits are "returned" for free. During consolidation, sample LoRA weights from a posterior and get bits back from the randomness: the consolidated model is a posterior sample whose free bits encode another (old) skill. New: a second skill stored in the randomness of the first. Crazy. First test: a toy VAE-like weight posterior where the noise seed carries skill B bits; decode B; retention of A.

**47. Directed information for credit assignment in agents.** Measure directed information from each memory entry to later actions (Massey), not correlation; keep memories with high directed info into success. Near: G1 off-policy evaluation (killed) and leave-one-out. First test: estimate DI from logs with a plug-in estimator, compare against LOO on the G1 router; retention of returning-regime accuracy.

**48. Information-geometric "parallel transport" of skills across updates.** When the base model updates, transport each stored skill along the Fisher-Rao geodesic between old and new base, instead of re-applying the same ΔW. Near: task-vector transport (prior art listed in memory: 2602.12952 etc.). Difference: Fisher-Rao transport, not permutation or linear maps; risk of overlap high. First test: two GPT-2 checkpoints, transport LoRA with Fisher-weighted connection versus naive; retention of skill.

**49. Redundancy-synergy decomposition of the model (PID) as a forgetting map.** Partial information decomposition splits what units carry into unique, redundant and synergistic parts. Prediction: synergistic information is forgotten first (it needs many units intact), redundant last. Protect synergy specifically. New as a prediction plus a protection target. First test: small MLP on XOR-like tasks (pure synergy) versus copy tasks (redundant); compare forgetting rates; then PID-weighted penalty; retention.

**50. Typicality-based replay selection.** Replay atypical examples (those whose per-token log-loss falls outside the typical set of the old task under the current model), since typical ones are implied by the bulk. New as a selection rule from the AEP. Near: hard-example replay. First test: replay buffer chosen by atypicality versus random versus loss-based at equal size; retention.

**51. Entropy-production rate as a novelty meter.** Track the cross-entropy rate of the incoming stream under the model; when it exceeds the model's own entropy rate by more than a threshold, the stream is novel and learning switches on; otherwise the model stays frozen. "Learn only when surprised" with an information-theoretic threshold. Near: surprise-gated learning. First test: stream alternating old and new tasks; gated versus always-on; retention and compute.

## H. Network coding, fleets, and distributed memory

**52. Network-coded fleet learning.** Agents exchange linear combinations of their adapters (random linear network coding) instead of raw adapters; any agent receiving enough independent combinations can decode every other agent's skill. Fleet knowledge spreads at max-flow rate and survives agent loss. New because federated CL averages (losing individual skills) or ships each adapter. First test: 5 agents, 5 LoRAs, gossip coded combinations; decode at each agent; retention of each skill and robustness to dropping 2 agents.

**53. Secret-sharing of skills.** Split a skill delta into n shares (Shamir over reals, or additive shares) so any k shares reconstruct it; fewer reveal nothing. Gives forgetting by deleting shares and controlled unlearning by revoking k−1. New as a CL control primitive (provable deactivation by share deletion). Near: exact-forgetting CL prior art. First test: 3-of-5 shares of a LoRA; reconstruct; verify that 2 shares give chance-level skill; retention of base.

**54. Coded computation for robust inference with partial weights.** If parts of the model are lost or offloaded, coded computation (MDS-coded matmul) lets the remaining parts still compute old skills exactly. Enables "model shrinkage without forgetting" for edge agents. First test: MDS-code one FFN into 5 shards of which 4 suffice; drop a shard; retention of all tasks.

**55. Gossip with erasure: rumor-spreading bounds on fleet lesson propagation.** Predict, from rumor-spreading theory, the time for a correct lesson to reach all agents and how many corrupt copies survive under copy errors; design the copy protocol (push-pull with checksums) to hit the bound. Near: E32 metered lessons, E31 Tasmania. First test: simulated fleet of 50 LLM agents with paraphrase copying; measure spread time and lesson drift against the bound.

## I. Strange and moonshot

**56. Error-correcting output codes for continual class growth.** New classes get new codewords from a code with large minimum distance; old classes' codewords never change. The output layer learns bits, not one-hot classes, so adding a class only adds a codeword. Near: ECOC (Dietterich 1995) in CL is partly explored. First test: split-CIFAR class-incremental with ECOC heads versus linear head; retention of old classes.

**57. Writing on memory with stuck-at defects.** Information theory handles memories with cells stuck at known values (Kuznetsov-Tsybakov): you can still write at full rate if the encoder knows the stuck positions. Treat frozen/protected old-task weights as "stuck cells" and encode the new task's information around them at full rate, with a known decoding map. New: a capacity result saying protection by freezing need not cost new-task capacity. First test: freeze 50% of weights for task A, train task B with a stuck-at code versus plain masked training; new-task accuracy and retention.

**58. Write-once memory codes for plastic weights (WOM codes).** Flash memory can be rewritten several times without erasing by using WOM codes whose cells only move one way. Constrain weight updates to be monotone (only increase a magnitude) under a WOM code, so k later tasks can be written without erasing earlier ones. New: a code that gives multiple writes of the same parameters with no interference by construction. First test: binary-ish weights in a small net with a 2-write WOM code; two tasks; retention.

**59. Zero-error capacity of a model (confusability graph of skills).** Build a graph where two skills are adjacent if a single update can confuse them; the Lovász theta of this graph bounds how many skills can be kept perfectly. Measure it on a real model. New as a zero-error capacity estimate for CL. First test: 20 skills, measure pairwise confusion under fine-tune, compute theta, compare to the number kept by the best method found.

**60. Adversarial channel view: worst-case future tasks.** Treat future fine-tuning as an adversarial (arbitrarily varying) channel; train old knowledge with a code that survives any update of bounded norm (list decoding, AVC capacity). Near: fine-tune-robust pretraining (prior art per memory). Difference: a coding guarantee with a computed radius. First test: certify a radius for task A under ‖ΔW‖ ≤ r using parity (idea 1); check empirically with adversarial fine-tunes; retention.

**61. Model weights as a steganographic channel for their own history.** Embed a compressed log of training history (data hashes, LRs, task order) into low-significance bits of the weights, readable by the model itself via a learned probe. Lets a model later "remember how it learned" and undo specific steps. Near: SM1 seed log, which stores it outside. First test: embed 1 KB in LSBs of fp16 weights, fine-tune, read back; bit error rate and retention (LSB noise must not hurt tasks).

**62. Learned code between consecutive model versions (version-to-version channel).** Train each new base version with an extra objective that the old version's lessons (in context) still decode correctly, i.e. the model update itself is coded to preserve a channel to old memories. Near: P19 stable ABI. Difference: framed as maximizing mutual information between old-memory inputs and behaviour across versions, measurable in bits. First test: two fine-tune stages of a 0.5B model with and without a memory-channel MI term on 50 lessons; retention = lesson effect after update (must beat temperature arm).

**63. Turbo learning: iterative decoding between weights and memory.** Two "decoders": weights and context memory each produce a posterior on the answer; exchange extrinsic information (what each adds beyond the other) for a few rounds, like turbo decoding. New because hybrid memory systems just concatenate retrieval with weights. Prediction: double dosing (ledger M3) arises from passing intrinsic not extrinsic information, and turbo exchange removes it. First test: question set where both weights and memory partly know answers; turbo-style logit combination versus concatenation; retention of weight-only answers.

**64. Gaussian-channel learning-rate law ("Shannon-Hartley SGD").** Treat each step as transmission through a noisy channel where signal = batch gradient and noise = gradient noise; the bits learned per step are 0.5·log(1+SNR). Predict forgetting as noise power the old task receives. Prediction: retention depends on SNR integrated over training, not LR or batch size individually. First test: vary batch size and LR at matched integrated SNR; test collapse of old-task loss curves.
