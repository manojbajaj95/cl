# Cross-pool merges, round 1

These merge ideas from different flood files into bigger primitives. Sources: `programs-weights.md` (PR #39, P#), `nooa.md` (PR #41, N#), `learning-primitives.md` (PR #42, L/D/S/O/M/A/W#), and the merged-proposer files in PR #36 (MX/MY/MZ, F1-#/F2-# = `proposer-batch-1/2.md`). They are raw and unfiltered; each has a mechanism, why it's new, and the cheapest first test.

**X1. Override-typed weights: a type system whose types are override budgets.** Parts: P7 typed residual stream, P10 gradual typing of plasticity, MZ3 trust dial, MX1 route-dependent correctability (passed review), M2 confidence ledgers, N27 types as compressed lessons. *Mechanism:* every stored behavior gets a type that says how large a contradicting directive must be to override it ("frozen", "editable", "draft"). The type is enforced by which route the write uses: a mid-layer LoRA for frozen, a readout adapter for editable, context for draft. A gradual-typing pass promotes a behavior from draft to frozen once its contract stabilizes. *New:* MX1 is the measured fact that the route sets correctability; this makes the route a declared, checkable type, so editability becomes a static property instead of an accident. *First test:* M3 world, 3 types × 50 lessons. Check that the measured follow index orders frozen < editable < draft at matched absorption, and that promotion keeps retention.

**X2. Weight-space git with override-aware merges.** Parts: P11 semantic three-way merge, P12/L2 bisect, P15 blame, L1 prompt-addressable checkpoints, M1 provenance channels, F1-25 provenance rollback, F2-19, MX1. *Mechanism:* each update is a commit tagged with a version token (L1) and its route (MX1). Merge conflicts are detected as overlapping functional drops, and resolved by giving the side with the larger override budget priority. Regressions are bisected by tag prompts instead of by reverting weights. *New:* it combines version semantics, inside one set of weights, with a conflict rule taken from the margin and override data. *First test:* GPT-2-XL #24 harness; two branch updates and one merge. Measure retention vs task arithmetic and TIES at equal parameters, and how often bisect finds the right commit.

**X3. Learning operators with algebra, compiled from correctability.** Parts: O1 idempotent, O2 commutative, O3 paired unlearner, D5 safe-word anti-update, L4 invertible opcodes, F2-30 reversible LoRA, F1-26 order-invariance regularizer, F2-35 order-averaged consolidation. *Mechanism:* one write operator, a hypernetwork from data to a delta, trained so that writes are idempotent and commute on probe sets and come with an exact inverse. The two-order comparator (PR #11/#17, ρ = 1.0) is the training signal for commutativity. *New:* a single operator with the full algebra (idempotence, commutativity, inverse), checked by an order-sensitivity measurement the ledger already validated. *First test:* synthetic regression tasks, comparing a hypernet write op with and without the algebra losses. Measure the comparator distance and the exactness of erase.

**X4. Contract-carrying memory with Popperian retirement.** Parts: N18 Popperian memory, N19 counterexample objects, N33 mutation testing, N37 self-written tests, P8 refinement-type contracts, P29 weight CI, M4 self-describing deltas, F1-34 self-written probes, MZ1 vaccination. *Mechanism:* every memory, whether in context, weights or code, is stored with an executable predicate and tests. It is falsified when its predicate fails on live observations, and mutation-tested to measure its causal effect. Memories whose mutation changes nothing are deleted, falsified ones are retired, and vaccination trains the reader on mutated (defective) copies. *New:* one lifecycle for memories in every substrate, driven by falsification. Memories fail loudly, which turns the Toolbox result (lessons fail silently) into a design rule. *First test:* G1 router lessons with predicates: falsification retirement vs LOO vs recency. Measure regret and defect transmission.

**X5. Virtual memory for learned behavior, paged by margin.** Parts: S1 memory relocation, S5 activation cassettes, P18 dynamic loading, MX2 margin-gated visibility, MY2 flippable mass, F2-6 bidirectional consolidation, F2-8 sink memory, N29 pass-by-reference. *Mechanism:* one address space spans context text, KV cassettes, LoRA pages and tools. A page is loaded into the fast tier only for states whose margin is below its directive shift, and evicted to a slower tier when its flippable mass drops. *New:* the paging policy is the margin law, the one quantity the ledger found that predicts when a memory can change behavior. *First test:* M2/N1 harness with 3 tiers; margin paging vs LRU vs always-on at equal context tokens. Report returning-regime accuracy.

**X6. Agents as typed object graphs with weight inheritance and Liskov retention.** Parts: N2 inheritance-shaped adapters, N5 refactor-as-surgery, N34 Liskov memory, N15 MRO retrieval, N16 diamond conflicts, P17 linker symbol tables, P19 stable ABI, P36 weight-space control flow. *Mechanism:* skills are classes, and each class owns a LoRA residual. A subclass's weights are the sum along its MRO. Forgetting is defined as a Liskov violation (a subclass update breaks parent-typed calls) and is tested in CI. Upgrades keep an ABI of anchor directions. *New:* forgetting gets a formal, checkable definition from behavioral subtyping, and the weight-sharing structure comes from the agent's own class tree. *First test:* synthetic skill hierarchy, 4 classes on 0.5B. MRO-summed LoRAs vs independent vs a single LoRA; Liskov-violation rate and retention.

**X7. Counterfactual futures as a training object.** Parts: D3 hypothetical fine-tuning query, D1 deferred-commitment branches, D2 gradient IOUs, W4 negative examples from the future, F2-5 counterfactual twin, MY1 fragility forecast, F2-32 forecasts as a service, P25 abstract interpretation. *Mechanism:* the model carries an update simulator head that answers "what would I answer to Q after training on X" (D3). Calibrated on margin plus overridability (MY1), it gates updates: commit, defer as a gradient IOU, or branch. *New:* learning decisions are made against predicted futures rather than observed losses, and the simulator's features come from the ledger's margin findings. *First test:* #24 harness. Train the simulator on 20 fine-tunes and predict per-fact drops on 5 held-out ones. Spearman vs the first-order bound.

**X8. Fleet economy with testaments and immune memory.** Parts: A1 market, A2 testaments, A4 immune system, A5 fork/merge-back, MZ4 lesson market, N38 cross-agent import, F1-24 disagreement teacher, contamination law R (PR #4). *Mechanism:* agents trade lessons and methods priced by verified lift. A shared immune memory keeps the fingerprints of lessons that caused contagion, and retiring agents write testaments that are priced by their successors' lift. *New:* an economy whose epidemic threshold R is set by prices and immunity, with a law that predicts when it is stable. *First test:* challenge world + fleet_sp with 8 agents; market+immune vs uniform sharing. Measure fitted R and fleet gain.

**X9. Sleep as compilation.** Parts: P1 skill compiler IR, P5 superoptimize deltas, P2 dead-code elimination, N23 GC pauses as sleep, N22 dormant-method resets, MZ2 boundary dreaming, W1 dream-erase, F2-29 sleep debt. *Mechanism:* sleep is triggered when the memory heap is full (GC). It compiles the day's lessons into deltas trained on boundary dreams, superoptimizes them to the fewest rank-1 terms, removes directions with no live effect, and resets dormant ones to restore plasticity. *New:* one offline pass that consolidates, compresses and restores plasticity, built from compiler passes. *First test:* M3 world; compile-sleep vs plain LoRA sleep. Measure retention, rank used and next-task gain.

**X10. Ellipsis-annealed code↔weight round trip.** Parts: N1 round-trip consolidation, N4 `...` frontier after an upgrade, N36 ellipsis density as a knob, S4 round-trip invariants, P6 decompile-recompile, A2 testaments, MY4 format is a route. *Mechanism:* agent knowledge cycles between code (methods), weights (LoRA) and `...` stubs. The fraction of stubs is annealed like temperature, and a method's canonical form is the fixed point of code → weights → code. After a base-model upgrade, methods whose round trip diverges are reset to `...`. *New:* a substrate-cycling continual learner whose fixed points define what has been learned. *First test:* 20 helper methods on 0.5B: round-trip divergence vs test pass rate, and the post-upgrade reset vs keep-all.

**X11. Plasticity control plane.** Parts: M3 plasticity tokens, F2-15 plasticity budget tokens, MX3/MY3 correctability meter, P4 profile-guided update placement, F1-21 targeted plasticity injection, F2-26 damage-aware LR, W6 body-double proxy. *Mechanism:* a small proxy model (W6) fit to the big model's update dynamics predicts the correctability meter and the functional damage of a planned update. It then sets plasticity tokens and per-layer LR (as in PGO) before the write. *New:* closed-loop plasticity control through a cheap proxy, with the meter as the controlled variable. *First test:* fit a 0.5B proxy to the 1.5B M3 runs and test whether its predicted damage ranks the real damage (ρ > 0.5).

**X12. The 20-way umbrella: one law of learned behavior.** Parts: X1–X11 + MX4. *Claim:* every operation above (write, type, merge, page, retire, trade, compile) is governed by one state variable per behavior, its override budget b = directive shift − margin, with a route term. A single fitted σ(a·b + c_route) predicts follow, fragility, contagion and plasticity across substrates. *First test:* pool every measured (b, outcome) pair from the first tests of MX1, MY1, MY2, X1 and X5, and compare one global fit with per-operation fits by held-out log-likelihood.
