# Long-run agent memory, batch 1: self-sealing lessons, difficulty-confounded writes, double-dosed consolidation

Angle: how agent memory changes over hundreds to thousands of episodes (consolidation, forgetting, drift, compression, write/read policies). Checked against the ledger (PR #6) and the agent batches (PR #7). Prior art via alphaXiv, 2026-11-24.

## M1. Self-sealing lessons: feedback pruning selects for wrong prohibitions, so they dominate the wrong lessons that survive a long run

**Mechanism.** Every outcome-based curator (ACE helpful/harmful counters, utility eviction, falsification gates, randomized block curation) can only remove a wrong lesson when the agent acts on it and sees a bad outcome. A wrong *prescription* ("always pass X") gets acted on and refuted. A wrong *prohibition* ("never call tool T", "don't paginate past 5") stops the agent from ever producing the evidence that would refute it: the avoidance-learning paradox (Mowrer; Solomon & Wynne), where avoidance responses resist extinction because the feared outcome is never sampled. Pruning is therefore a selection process: wrong prescriptions decay at a rate set by how often they fire, wrong prohibitions decay only through incidental violations. Prediction (long-run only): the share of prohibitions among *wrong surviving* lessons rises with horizon toward 1, even when the writer produces prohibitions and prescriptions at equal rates and equal error. Early in a run the two are indistinguishable, so short pilots miss it. Consequence: late-run memory harm is concentrated in a lesson class that no current curator ever tests. Fix: spend the exploration budget on prohibitions, in proportion to how long each has gone untested (violation count since write), instead of uniformly.

**Closest prior art.** Randomized block curation (RBC, [2610.18427](https://arxiv.org/abs/2610.18427)) includes every block at random on practice tasks, uniformly, with no account of which lessons can't produce counter-evidence. Lessons from Luck ([2610.33029](https://arxiv.org/abs/2610.33029)) measures noise carried into lessons, one step. Experience Rot ([2611.20922](https://arxiv.org/abs/2611.20922)) and evidence-linked memory ([2611.14320](https://arxiv.org/abs/2611.14320)) document memory-induced harm without a selection mechanism. No paper found on survivorship of untestable lessons under pruning.

**Strongest control.** RBC-style uniform random lesson suspension at the same exploration budget (same number of episodes with some lesson suspended). Also: ACE counters alone; an LLM judge asked to flag doubtful lessons at equal calls.

**Smallest falsifying test.** Synthetic tool-API world (scripted environment, Qwen2.5-1.5B writer/actor on CPU, or a scripted writer that emits lessons with a controlled error rate to isolate the curator). Writer emits prescriptions and prohibitions at a 1:1 rate with equal 30% error. Run 1,000 episodes × 3 seeds under ACE counters + utility eviction. Measure (a) prohibition share among wrong surviving lessons at episodes 50, 200, 1,000; (b) wrong-lesson discovery rate of targeted vs uniform suspension at equal budget.
**Kill line:** prohibition share among wrong survivors at 1,000 episodes is not ≥ 2× its share at write time (i.e. < ~0.75 from 0.5 baseline-adjusted), or targeted suspension does not find wrong lessons ≥ 2× faster than uniform suspension at equal budget (CI excluding 1), or the task-success gain over uniform is within the seed CI.

## M2. Memory without a baseline: success-filtered lesson writing is confounded by task difficulty, and the bias compounds as the agent improves

**Mechanism.** Most self-evolving memories write lessons from outcomes: keep what co-occurred with success (ExpeL insights, ReasoningBank, ACE reflections). With heterogeneous task difficulty, any behaviour the agent shows more often on easy tasks co-occurs with success whatever its effect, so the writer infers "do X" from P(success | X) without controlling for difficulty. This is REINFORCE with no baseline, except here it is bias, not just variance, because the writer conditions on the agent's own difficulty-dependent behaviour. Long-run dynamics: once a confounded lesson is written, the agent applies X everywhere, including hard tasks where X hurts; success on hard tasks falls, those failures are rarer than easy-task successes, so the lesson keeps net-positive evidence. Prediction: under success-filtered writing, hard-task accuracy first rises then declines after a few hundred episodes while easy-task accuracy keeps rising (a difficulty-split divergence), and the share of lessons whose measured effect is negative on hard tasks grows with horizon. Fix: write from advantage, not reward. The baseline V(task) is the agent's own memory-free success probability, read exactly from the model as P("yes" | "Will this task succeed?", task) or from a cheap verbalized estimate, and the writer only sees episodes labelled "better than expected" / "worse than expected".

**Closest prior art.** Lessons from Luck ([2610.33029](https://arxiv.org/abs/2610.33029)) is outcome noise on one decision, not difficulty confounding over a run. Experience selection for continual agents ([2611.27159](https://arxiv.org/abs/2611.27159)) selects training records by gradient/NLL, not by advantage for text memory. Disentangling task difficulty from run-level failure ([2610.05572](https://arxiv.org/abs/2610.05572)) is failure prediction, not memory writing. Failure-trace value ([2611.11342](https://arxiv.org/abs/2611.11342)) adds failures but does not baseline them.

**Strongest control.** Write from both successes and failures with similarity retrieval (ReasoningBank style), at equal writer calls and context. Second: tell the writer each task's difficulty bucket in text (same information as the baseline, no reweighting). Third (ceiling): ExpeL-style same-task success/failure contrast using retries (costs extra episodes).

**Smallest falsifying test.** Synthetic tool world with two difficulty tiers (easy 80%, hard 20%) and one planted spurious behaviour X that the base policy shows mostly on easy tasks and that hurts on hard tasks. Qwen2.5-1.5B, 1,000 episodes × 3 seeds, global playbook (no per-task retrieval). Arms: success-filtered, success+failure, difficulty-in-text, advantage-labelled. Report hard-task accuracy curve and confounded-lesson share over time.
**Kill line:** success-filtered writing shows no hard-task decline after its peak and no growth in confounded-lesson share (i.e. the phenomenon doesn't exist), or advantage writing does not beat both success+failure and difficulty-in-text on hard-task accuracy at 1,000 episodes by ≥ 5 points beyond the seed CI.

## M3. Double dosing: after consolidation into weights, a lesson still in context is applied twice, and long runs oscillate

**Mechanism.** Hybrid memories move lessons from context into weights (OPCD, Cortex, ENGRAM, sleep-style consolidation). Two policies are in use: evict a lesson once consolidated, or keep the notes. For graded behavioural lessons ("be more cautious with deletes", "ask fewer clarifying questions", "prefer the cheaper tool"), the in-context effect is a shift in log-odds, and if the weight update moved the same direction, the two shifts add: the agent overshoots. In a closed loop the agent then writes a corrective lesson, which is consolidated and kept, and the policy oscillates around the target with growing amplitude when the loop gain (context effect + absorbed fraction) exceeds 1, a classic overcorrection instability that only shows after several consolidation cycles. Evict-on-consolidate fails the other way: consolidation is partial (E1 in PR #7 assumes exactly this), so the unabsorbed part is lost. Fix: residual memory. After each consolidation, re-measure every consolidated lesson's in-context effect under the new weights from log-probs on its own probe states, and keep, shrink ("slightly more cautious"), negate or evict it so the context carries only target minus weights.

**Closest prior art.** Cortex ([2610.20399](https://arxiv.org/abs/2610.20399)), ENGRAM ([2611.09472](https://arxiv.org/abs/2611.09472)), Instant Weight-Space Consolidation ([2611.20759](https://arxiv.org/abs/2611.20759)), selective parametric consolidation ([2606.26806](https://arxiv.org/abs/2606.26806)) and context distillation as latent memory management ([2605.28889](https://arxiv.org/abs/2605.28889)) decide what to consolidate; none measures whether context and weight effects add after consolidation or what the context should hold afterwards. Ledger E1 predicts absorption before training; M3 is about the interaction after it and its multi-cycle dynamics.

**Strongest control.** Evict-on-consolidate and keep-all, both at equal consolidation compute. Third: re-derive the context from scratch after each consolidation with the new model writing lessons (same number of writer calls as the residual pass).

**Smallest falsifying test.** Qwen2.5-0.5B + rank-16 LoRA, 40 graded lessons with a scalar behavioural target each (e.g. clarifying-question rate, tool-cost preference) on synthetic tasks. Step 1 (cheap, decisive): distil each lesson by OPCD, then measure the behaviour under weights only, context only, and weights+context. Step 2: 6 consolidation cycles × 3 seeds in a closed loop where the agent writes corrective lessons from its deviation from target.
**Kill line:** in step 1, weights+context shift is < 1.2× the larger single shift for ≥ 80% of lessons (effects saturate, so keep-all is safe and M3 is dead); or in step 2, residual memory does not beat the better of evict-all and keep-all on mean |behaviour − target| over cycles 3–6 by ≥ 25% relative, beyond the seed CI.
