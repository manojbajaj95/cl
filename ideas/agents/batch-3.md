## C1. Learn tools backwards: inverse tool models adapt to tool drift from unlabeled deployment traces
**Claim.** When a tool changes (renamed argument, new units, changed defaults), the deployed agent's failed traces still contain correct (output, call) pairs: whatever the tool returned is a true consequence of the call that was made. Training an *inverse* model, call ← (goal, observed output), on these traces relabels every failure as a success for a different goal (hindsight relabelling through the tool). A forward model trained on the same traces only sees failures. Prediction: after a tool drifts, an inverse-trained LoRA recovers the new interface from far fewer traces than forward SFT, and recovers from failed traces alone, with no success signal.
**Control that could tie, and why it should fail.** Forward SFT on the same traces at equal tokens, and in-context "here are recent tool outputs" with the same traces. Forward SFT cannot use a failed trace as positive evidence. In-context traces tie at a handful of drifts, but they cost context on every call and should fall behind as drifts accumulate across many tools.
**Pilot.** Qwen2.5-0.5B with a LoRA on 30 synthetic APIs. Apply 1–3 drifts per API (argument rename, unit change, default flip). Collect 50–500 deployment traces per drift with the pre-drift policy, mostly failures. Arms: forward SFT on successes, inverse/hindsight-relabelled SFT on all traces, in-context traces, and AT-AT-style doc rewriting (2610.34679). Measure post-drift call accuracy vs. number of traces, and pre-drift retention. **Kill** if inverse training does not reach forward-SFT accuracy with ≤½ the traces, or does not beat in-context traces once ≥10 APIs have drifted.
**Closest.** Robust Function Calling Under Interface Drift (2610.23342) and AT-AT/DOCSCHISEL fix descriptions, not the policy. Hindsight relabelling (HER) and inverse dynamics (VPT) exist in RL, but I found none applied to tool interfaces in LLM agents.

## C2. Hysteresis in self-improving agents: predict order dependence from the memory loop's contraction rate
**Claim.** A memory self-update loop M_{t+1} = U(M_t, episode_t) is a random dynamical system. If U is contracting on average (Lyapunov exponent λ < 0), the final memory forgets its history and is order-invariant; if λ ≥ 0, the loop shows hysteresis: the same tasks in a different order give a different stable memory and different downstream skill. λ can be estimated from the first ~20 updates by running two nearby memories (one lesson perturbed) through the same episodes and measuring how their behavioural distance grows. Prediction: the λ sign forecasts which agent designs (update prompt, memory size, curation rule) are order-dependent, before the order-dependence is measured.
**Control that could tie, and why it should fail.** Running the full loop under two task orders and comparing outcomes directly is the ceiling, not a competitor, since it costs the whole run. Cheap competitors are memory-growth rate, edit rate, and the self-modification convergence signals in 2611.01304. These measure whether the memory *settles*, not whether it *forgets initial conditions*: a loop can settle to an order-specific attractor. That is where they should fail.
**Pilot.** Qwen2.5-1.5B with ACE-style and Dynamic-Cheatsheet-style update rules plus 4 curation variants (8 designs). Rule-induction stream of 200 episodes, 6 orders × 3 seeds each. Estimate λ from the first 20 updates. Measure the end-of-stream accuracy spread across orders. **Kill** if the λ estimate's rank correlation with order spread across the 8 designs is not above the best cheap competitor by ≥0.3, or if all designs have the same λ sign (no spread to explain).
**Closest.** When LLMs Modify Themselves (2611.01304) studies convergence of self-modifying prompts. Attractor states in multi-turn conversations (2606.30571) studies text dynamics. Neither estimates sensitivity to initial conditions or predicts order dependence of agent memory.
