## G1. Test a memory edit on yesterday's logs: exact-likelihood off-policy evaluation for agent memory, with an effective horizon of a few tokens
**Claim.** Memory systems validate a candidate lesson by running new episodes (ACE, falsification gates, randomized playbook experiments). For an LLM agent the behaviour policy is known *exactly*, because every logged action has its token log-probabilities under the old memory. Re-scoring the same logged tokens with the candidate memory in context gives exact importance ratios π_new/π_old. Long-horizon importance sampling is normally unusable because ratio products explode. The structural claim here is that a memory edit changes the action distribution on only a few *memory-sensitive* tokens (argument values, tool choices), and the ratio is ≈1 everywhere else. So the effective horizon of per-decision IS equals the number of sensitive decisions, not the trajectory length, and variance stays bounded. Prediction: per-decision weighted IS plus doubly robust correction over logs ranks candidate lessons as well as running fresh episodes, at zero new environment interactions. Accuracy degrades exactly as the edit's number of sensitive decisions grows.
**Control that could tie, and why it should fail.** An LLM judge reading the logs and the candidate lesson ("would this have helped?"), and a learned uplift model (UpliftMem 2609.36805) at the same compute. Both guess at counterfactual behaviour. OPE measures it from the model's own probabilities, so it should win where the judge's intuition about what the model will do is wrong (lessons the model ignores, or over-applies). Running fresh episodes is the ceiling, not a competitor.
**Pilot.** Qwen2.5-1.5B (HF, CPU for log-prob rescoring) on ALFWorld-text or synthetic API tasks. Log 2,000 episodes under memory M. Generate 40 candidate edits, then get ground-truth value per edit from 100 fresh episodes each. Compute per-decision WIS and DR estimates from logs, plus the effective sample size and the count of sensitive tokens (|log ratio| > 0.1). **Kill** if OPE's rank correlation with ground truth is < 0.6, or not ≥0.15 above the LLM judge, or ESS collapses below 5% for typical edits. The last would mean the sparse-sensitivity claim is false, which is itself worth reporting.
**Closest.** Amortized OPE for LLMs (2610.10848) and OTROPE (2609.36264) evaluate whole models or responses, and the world-model OPE for agents (2606.05558) simulates environments. Memory-edit validation everywhere else uses fresh rollouts. I found no exact-likelihood OPE for memory or prompt edits in agents, and no sparse-sensitivity account of why it would work.
